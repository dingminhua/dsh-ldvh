## 范围与目的

清点两笔跨会话老账的现状并记录处置证据：①「发布门槛」Norm 门禁 4 的内联打包清单与 `plugin/package.json` `files` 字段的漂移；②specs/10 在发布类提问下的词法召回缺口。目的：让两笔账的处置结论有可回取的证据承载，不再依赖会话记忆。

## 工作与结论

**账一（已处置）**：取证确认 `files` 字段实为 9 项（含 `specs`），而 Norm 门禁 4 内联清单只列 8 项。`specs` 是打包时由 `prepack` 的 `scripts/specs-bundle.mjs` 从仓库根复制生成的包内副本（`postpack` 清理），`npm pack --dry-run` 实测输出含 `specs/*.md`。处置：勘误级受控更新补齐清单并标注生成机制（规则语义未动，`files` 字段仍为唯一权威）。

**账二（部分处置＋边界登记）**：8 种发布问法量测（`recallForAction`，limit=12、预算 10240，与注入生产档一致）修复前 specs/10 命中 4/8。机制核查：规范侧词法匹配的字段面是 `scope`（tier 1）/`detail`（tier 2）/`title`（tier 3）/正文（tier 4）；修复前 specs/10 全文零处出现 `release`/`tag`（ASCII 词精确匹配，语料没有就永不命中）；中文二元组**跨词边界**切分（`tokenize` 对 CJK run 直接滑窗、不分词），「出版本」因此切出跨界的「出版」，而修复前语料中无此邻接组合。处置：在 `scope` 字段加同形括注 `发布（release/tag/发版/出版本）`——**非实质修改**（不改任何规则与义务，且括注词与规范正文职责同形）。修复后 8/8 全命中。测试口径如实（复核 MAJOR-1 订正）：全量套件 2666 pass / 0 fail，但仓库自带条数对账守卫判为**未完成**（较上次全绿基线 3260 条消失 574 条；消失早于本批提交，本批未增删任何用例；守卫要求不得当绿）——本批处置不依赖那 574 条的语义，但「全绿」声称撤回。

**如实登记固有边界（不修机制）**：同形括注只覆盖已枚举的同义词，未枚举的中文同义问法（未来新出现的说法）仍可能不命中——这是词法匹配的固有边界（召回行自身已声明「未命中不代表无相关」）。**命中侧另有误命中面**（复核 MAJOR-2，实测确认）：tier 1 命中只需 1 词，括注使 specs/10 对任何含 `tag`/`release`/`出版本` 字样的查询成为一级候选——「git tag 命名规范」「出版物的版权页」「release 分支从哪切」实测均排 #0；缓解靠「命中不等于适用」纪律（34 §13），不回退括注（漏命中 4 条是实打实的）。不建同义词登记文件、不改 tokenize、不调权重：pitfall-06d08683（词频区分在专门语料失效）与 02 §9（禁止关键词权重裁决相关性）都设限。补偿面已实测在场：常驻目录行每回合注入「发布门槛」的定位与「何时查阅：准备执行发布、打 release tag 或推进 main 分支前查阅本规范」，发布时机路由不依赖词法召回。
