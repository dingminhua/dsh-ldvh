# 逐字比对统一归一化口径

## 摘要

五处同类比对各自为政：有的只折叠空白、有的连折叠都没有，一律做字节级子串相等。材料是带 Markdown 的正文，于是引证与结论只要跨过加粗或行内代码定界符就被判成「内容不实」。本单抽一个共享归一化模块，把五处统一为「归一化后再子串判定」，并把归一化能做什么、不能做什么钉成闭集。

### 五处调用点
`plugin/lib/friction-window.js` 的 `verifyQuotation`（只折叠空白，且 `:303` 把归一化后的字符串作为 `value.quote` 落库）；`plugin/lib/workcase-tools.js` 的 record_review（`:727`）与 record_audit（`:841`，均为裸 `includes()`）；`plugin/lib/research-session.js:286` 的行内引证核对（裸 `includes()`）；`plugin/lib/commit-validation.js:609` 的删除依据核对（只折叠空白）。

### 归一化闭集
允许：剥离成对出现的 Markdown 强调定界符（`**`、`__`、`*`、`_`）与行内代码定界符（反引号），折叠连续空白为单空格，去首尾空白。禁止：删除标点、全半角转换、大小写折叠、字符集或字形归一。理由是任何超出定界符剥离的操作都会把「改写过的转述」与「原文」的差别一起抹掉，而本项要担保的正是这两者不同。

### 落库语义的决定
`value.quote` 落库保留**执行体提交的原文**（仅去首尾空白），不落归一化形态。执行体交的文本与材料原文可以不同，改写它会掩盖这个差异；而「确在材料内」这一结论已在当时机械判定，不依赖落库文本复现。

### 判据可判定性
不采用「全仓 grep 命中数为 0」一类判据：`plan[].step` 须逐字重复在正文「计划」节，而本对象载体本身就在仓库内，这类字面量判据结构性不可达。改用「逐处改接 + 测试用例覆盖」的证据。

## 结果

- cancellation:
  - **理由**：本单的核心前提经第二轮建前独立审核推翻——统一归一化实为**放宽受理面**，与规范相悖。`specs/36-闲时辅助系统规范.md` §11 原文要求「执行体的判断须逐字引证该交付材料中的原文；引证不在交付材料内者，该判断不成立……不得以相似度或模糊匹配替代」；`specs/21-WorkCase 工单.md` §14 要求 record_audit 的 summary 为「子代理捕获结论的逐字子串」；`specs/09-受控提交与机械守护规范.md` §5.3 第 7 项要求引用「逐字存在」。而两侧同时剥离字符会使「删字即通过」成立（材料 `snake_case` 与引证 `snakecase` 同归一后相等），恰好拆掉该条款要担保的东西，故本单 scope 首句「不动任何判据强度」不能成立。第二轮审核另判：plan 第 1 步写「五个文件」而五处分布在四个文件，判据不可满足；plan 第 3 步要求比照 `friction-window.js:299` 输出原文，而该支输出的 `q` 已归一化，与第 2 步落库语义互斥；做什么第 4 项与明确不做什么第 2 项在同段内正反互斥。据此本单不再修订，予以撤销。
  - **未发生的范围**：全部计划步骤 1–3 均未实施，`plugin/lib` 下无任何共享归一化模块、无任何调用点改接、无新增测试；`value.quote` 落库语义未改动；`discovery/quote_too_short` 分支的拒绝理由未改动；本单未获得 Gate 1 批准，attempt 未启用。原拟随本单办理的「陈旧引注清扫」与「执行体契约要求逐字复制材料原文」两项，均未由本单实施，须另办。
