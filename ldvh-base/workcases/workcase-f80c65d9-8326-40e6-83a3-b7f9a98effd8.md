# 闲时摩擦发现机制规范修订

## 摘要

闲时摩擦发现机制的规范修订：把已定方向落成 26 号与 32 号的条文修订，并产出宿主侧实现设计。

### 现状核实

闲时摩擦发现机制此前只有两份 Research 提供外部依据（research-cf315013 闲时机制可吸收形态、research-fa0cff9c 的 F19–F23 增补），规范侧 32 号 §10 与 26 号留有多处条件式缺口：32 §10.2 声称「DSH 无 cron 与独立定时设施」与实际存在的 schedule 包矛盾；26 号缺重复计数的可枚举字段；deferred 语义与本地层 buffer 重叠；入账门为事前批准，与 00 §1「盯守会疲劳」的判断冲突。

### 已定方向（Human 裁定）

1. 摩擦**入账**改为默认拒绝 + 事后否决，窄口径自动入账，不走事前 Human Gate；
2. 归纳、计数、记录现状属第一层，可自动执行；状态流转、impact 变更、销账仍属 Human Gate；
3. deferred 重新定位为「留观」——语义从「明确暂缓但保留账面」改为「已入账、尚未攒够，只记录被看见的事实，不承诺修复」；
4. 新增 `voided` 作废终态，使事后否决权有落点；
5. 机械通道：创建 `observing` 与 `count ≥ N` 阈值触发的流转不属授权缺失；值得修评估、暂缓、销账、作废、impact 变更仍属 Human Gate；
6. 归因允许先为自由文本（不必指向已存在对象），另设可选 `attribution_ref`；
7. 本机制属辅助机制，语义查重环节按 04 §8.4 登记为 gap、不主张机械保障；
8. Code 侧同步由另立工单承接，本工单不含任何插件代码修改。
