# 运行实例陈旧模块可核

## 摘要

现状：DSH 宿主不热重载 `plugin/lib`，运行中的进程持有的模块代码是其首次 import 那一刻的版本。已有的陈旧检测不在别处，正是 `plugin/lib/module-freshness.js`（2026-10-28 建立，源自 friction 账目 `fbd65401`）：它按「文件 mtime 晚于进程启动时刻」判定必然陈旧，三个边界已在该模块头注如实声明（mtime 未变检不出、不判陈旧方向、读不到不判陈旧）。但它的覆盖面只有两个文件——`VALIDATOR_MODULE_FILES` 仅含 `commit-validation.js` 与 `ldvh-tools.js`（`module-freshness.js:86`），且唯一消费者是 precheck：`ldvh-tools.js` 用它把 `failed` 降级为 `unverifiable`。于是 `plugin/lib` 其余 93 个 `.js` 的陈旧无人可见。另有两个既存「版本」也不覆盖本问题：`commit-validation.js:66` 的 `SOURCE_FINGERPRINT` 是字面量 `sha256("dsh-ldvh-git-gate-v1")`，与源码内容无关；`hook-manager.js` 的 `bundleVersion` 只管磁盘上的 Hook 脚本。08 §163 所说的「版本守卫」是写入原子性守卫，不是加载版本守卫。

### 查重
