# 提请弹窗 200 字符上限落到接缝

## 摘要

把 ADR「提请弹窗 question 上限 200 字符」（adr-7ceaf7fc）确立的上界落到实现侧：LDVH 经 ctx.userQuestions.ask 发出的提请弹窗，其 question 文本须 ≤ 200 字符，超出部分改由 question.detail 承载。

### 现状核实
已实测确认缺陷两侧：LDVH 接缝（plugin/lib/host-seams.js 的 requestWorkcaseRouting 与 requestSparkConsent）对组装后的 question 无长度上界；宿主侧对 question 长度零校验零截断。渲染上 question 位于 flex-shrink:0 的标题区，而 detail 与 options 同处可滚动 body——超长 question 顶高卡片后把选项挤出可视范围，Human 无从作答。实测后果：三次 Spark 创建提请 fail-closed。

### 处置方向
在 host-seams.js 内建立单一的有界组装：question 只放短标题与关键字段，长呈报整体移入 detail。detail 渲染于可滚动 body 内，且经 ask 链路原样透传，是宿主已提供的现成承载位。

### 边界
不改授权语义与 fail-closed 行为，不改选项标签，不为宿主侧增加校验，也不主张宿主已提供机械保障。登记接缝单行模板 85 字符，已在界内，不动。

## 授权范围

做什么：
- 在 plugin/lib/host-seams.js 建立有界组装，使 requestSparkConsent 与 requestWorkcaseRouting 传入宿主时 question ≤ 200 字符，长呈报改由 question.detail 承载。
- 更新断言 question 文本的现有测试，使其断言新契约。

明确不做什么：
- 不改 requestRegistrationConsent（单行模板已在界内）。
- 不改 Human Gate 的授权语义、选项标签与 fail-closed 行为；不新增或放宽任何标签接受面。
- 不为宿主侧增加长度校验，不主张宿主已提供机械保障。
- 不改任何规范源文本。

## 计划

1. 在 plugin/lib/host-seams.js 实现有界组装并对两处接缝生效
   - 完成判据：requestSparkConsent 与 requestWorkcaseRouting 组装后传入宿主的 question，其 .length 均 ≤ 200，且原呈报正文逐字出现在该次请求的 detail 中（由测试断言）
2. 更新断言 question 文本的现有测试至新契约
   - 完成判据：plugin/test 中断言 question 含呈报原文的用例改为断言 detail 承载，并断言 question 长度 ≤ 200
3. 运行插件测试套件确认无回归
   - 完成判据：在 plugin/ 下运行 node --test test/*.test.mjs，输出零失败
