gist: 把复核独立性变成工单关闭的硬性前置：关闭前必须有一条来自独立会话或子代理的结论记录，低风险工单也不例外；为此建立由代码托管的会话身份，使主控自查无法冒充。
serves: SG-3
summary: |-
  ### 把复核的独立性从规范义务升级为关闭侧硬门禁
  凡 WorkCase 关闭，必须至少存在一条由独立于实施者的会话/子代理产出的结论记录，低风险工单不豁免（依 Human 2026-09-19 裁定）。

  ### 现状核实（2026-09-19，逐文件回读）
  reviews 的 provider/model 由 Code 托管（workcase-writer.js:1039 stampReviewEntries），但其值取自会话**路由**记录（session-signature.js 尾读 model/selection|request/context），非会话身份——同 provider/model 的两个会话盖出完全相同的署名，故现有字段无法支撑「记录者 ≠ 实施者」的机械比对；attempt.controller 是 AI 自填自由文本（workcase-tools.js:359 仅校验非空），同样不能作身份；Code 侧可观测的会话身份（agent.id / session.header.id，child.js:45-49 已可读）当前无任何字段承载。

  ### 另
  受管辖子代理当前不注册 ldvh_* 工具（lifecycle.js:161-163 子代理走 installChild 后即返回；child.js「Tools… stay OFF」），结论无法由该执行体自身写入，须经 Code 观测的通道回传。

  ### 本单落实
  ①在 attempt 与 reviews 上建立由 Code 从 DSH 会话记录托管的会话身份锚点；②关闭侧新增身份比对校验，要求至少一条 reviews 条目的会话身份与实施 attempt 的会话身份不同，缺失、相同或不可得即 fail-closed 拒绝关闭并报告具体原因；③为隔离执行体提供结论回传通道，且不因此赋予其其它受控写能力；④同步 21 §8/§14/§15.1，并显式处置 02 §15「按风险选择最小充分视角」与本硬门禁的张力。

  ### 诚实边界
  机械层只能证明「记录该结论的会话身份 ≠ 记录该实施尝试的会话身份」，不证明视角实质独立、内容正确或结论成立；「子代理完成 ≠ 主控完成、同一主控编排的结论 ≠ 视角独立」的语义判断仍归 AI/Human（02 §15）。

  ### 查重记录（21 §6.2）
  既有 draft 4005b67b「关闭侧授权与复核门禁（承 C2 缺口）」覆盖「授权指纹未比对」与「cancel 不校验 reviews（rebatch→cancel 绕过）」两项，并明确声明「不新增对象字段」；本单承接「reviews 独立性从无比对」且必须新增字段，范围与前置声明均不重叠，故不并入、另立本单。

# WorkCase 关闭侧身份比对硬门禁

## 摘要

### 把复核的独立性从规范义务升级为关闭侧硬门禁
凡 WorkCase 关闭，必须至少存在一条由独立于实施者的会话/子代理产出的结论记录，低风险工单不豁免（依 Human 2026-09-19 裁定）。

### 现状核实（2026-09-19，逐文件回读）
reviews 的 provider/model 由 Code 托管（workcase-writer.js:1039 stampReviewEntries），但其值取自会话**路由**记录（session-signature.js 尾读 model/selection|request/context），非会话身份——同 provider/model 的两个会话盖出完全相同的署名，故现有字段无法支撑「记录者 ≠ 实施者」的机械比对；attempt.controller 是 AI 自填自由文本（workcase-tools.js:359 仅校验非空），同样不能作身份；Code 侧可观测的会话身份（agent.id / session.header.id，child.js:45-49 已可读）当前无任何字段承载。

### 另
受管辖子代理当前不注册 ldvh_* 工具（lifecycle.js:161-163 子代理走 installChild 后即返回；child.js「Tools… stay OFF」），结论无法由该执行体自身写入，须经 Code 观测的通道回传。

### 本单落实
①在 attempt 与 reviews 上建立由 Code 从 DSH 会话记录托管的会话身份锚点；②关闭侧新增身份比对校验，要求至少一条 reviews 条目的会话身份与实施 attempt 的会话身份不同，缺失、相同或不可得即 fail-closed 拒绝关闭并报告具体原因；③为隔离执行体提供结论回传通道，且不因此赋予其其它受控写能力；④同步 21 §8/§14/§15.1，并显式处置 02 §15「按风险选择最小充分视角」与本硬门禁的张力。

### 诚实边界
机械层只能证明「记录该结论的会话身份 ≠ 记录该实施尝试的会话身份」，不证明视角实质独立、内容正确或结论成立；「子代理完成 ≠ 主控完成、同一主控编排的结论 ≠ 视角独立」的语义判断仍归 AI/Human（02 §15）。

### 查重记录（21 §6.2）
既有 draft 4005b67b「关闭侧授权与复核门禁（承 C2 缺口）」覆盖「授权指纹未比对」与「cancel 不校验 reviews（rebatch→cancel 绕过）」两项，并明确声明「不新增对象字段」；本单承接「reviews 独立性从无比对」且必须新增字段，范围与前置声明均不重叠，故不并入、另立本单。

## 授权范围

做什么：(A) 在 attempt 与 reviews 上建立 Code 托管的会话身份锚点（来源为 DSH 会话记录中的 agent.id / session.header.id，不经 AI 自填）；(B) 在关闭侧实现身份比对校验——至少一条 reviews 条目的会话身份由 Code 托管取得且与实施 attempt 的会话身份不同时才允许关闭；不满足即 fail-closed 拒绝关闭并报告具体原因；低风险工单不豁免（Human 2026-09-19 裁定）；(C) 打通隔离执行体的结论回传通道，使受管辖子代理（或另一受管辖根会话）能将其结论经该通道落为 reviews 条目，且不因此赋予其其它受控写能力；(D) 补行为测试：伪装路径（同会话自填、复用旧条目、以正文自述替代、无独立结论）被机械拒绝，合法路径通过，含负向控制；(E) 同步规范 21 §8 字段闭集、§14 受控操作与关闭前置、§15.1 类型特有验证及验证表的保证边界，并处置 02 §15「按风险选择最小充分视角」与本硬门禁的张力（对齐或按 01 §9 程序修订，二者择一并记入修订依据）。明确不做什么：不修改 §10.3 的 C2 授权钉扎与 cancel 旁路（归既有 draft 4005b67b，边界见查重记录）；不实现 25 §11 的 goal-changed 级联标记；不改 03/05/06/07/08/09 号规范；不新增取代既有 action 的 ldvh_* 受控工具（若确需新入口，先停下报告并提请裁定）；不处置存量 closed 工单的记录补录（be30b5f7 不可重开，按 21 §18）；不声称机械层能证明视角的实质独立。

### 插件重载后的追加执行（2026-09-19 第二轮）

#### 一、补上 scope (C) 承诺但实际走不通的通道：受管辖子代理的复核回传

**发现的缺口**：子代理**不注册任何 ldvh_* 工具**——实测由真实隔离子代理（324d8a5a-…，origin=subagent、depth=1）逐个核对其 56 项工具名单，无一以 ldvh_ 开头；代码侧对应 lifecycle.js 对 origin === "subagent" 走 installChild 后即返回。而本轮为堵「shell 身份可伪造」把复核身份收紧为只接受 source="host"。两者相加的后果：「开启代理做独立审核」在机械上走不通——正是 scope (C) 明文承诺要打通的通道。

**处置**：新增「父会话代子代理回传」路径（record_review 的 reviewer_child_agent_id）。身份与结论文本**都取自宿主子代理登记表**（lifecycle.js 的 lookupChild，Code 亲观测）：身份取 child.sessionId → source="host"；结论文本取子代理真实产出（DelegatedChildRecord.setConclusion 于 turn-end 捕获）。父会话不得替换。用例锁定四条拒绝路径：未知子代理 id、无已捕获结论、概要非逐字子串（防代述）、宿主未暴露登记表时 fail-closed。

#### 二、修正回传通道的自造死结：长结论与 600 字符上限冲突

**实测发现**：子代理 captured conclusion 是最终正文全文，而 reviews[].summary 有 ≤600 上限（21 §8「复核详情不入对象」）。一份真实七要素结论实测 672 字符即被拒 → 通道对真实复核不可用。

**处置**（不放宽上限，而与 §8 分工一致）：超 600 时须提供**逐字子串**作为概要（校验 conclusion.includes(summary)），全文留在 transcript；未提供且首段超限则拒绝并说明，不静默截断。

#### 三、存量对象来源补齐

**发现**：本锚点之前的 attempt 有 session_id 却无 session_source，而关闭门禁要求条目两端来源俱为 "host" → 这类对象永远关不掉。

#### 四、来源洗白封堵（本单自审发现的严重缺陷，已修）

**发现**：来源若按「继承性补齐」，任何一条**无来源**的条目都会被随后一次宿主写入洗白成 source="host"，从而计入判据——等于把「shell 身份可伪造」的缺口从后门放回。实测复现：注入无来源条目 → 攻击者一次宿主写入 → 该条目变成 session_source="host" 并被采纳。

**处置**：来源改为**不继承补齐**——既有条目一律保留原值，缺失即缺失（null 亦改为一律省略，因「值不明」与「字段未存在」语义不同）。有专门用例锁定。
