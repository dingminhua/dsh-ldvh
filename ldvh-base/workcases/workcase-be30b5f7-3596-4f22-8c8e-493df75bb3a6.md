# WorkCase tab 增加 SG 筛选

## 摘要

在 WorkCase tab 增加 SG（serves 子目标锚点）筛选，学习 spark tab 的做法。现状核实（2026-09-16）：ServesSgFilter 组件、前端过滤（item.serves === activeServesSg）、?serves= URL 参数、选项源（goal 的 sub_goals）与计数均已通用；唯一开关是 ObjectList 的 supportsServesSgNavigation = currentType === 'spark'（729 行），组件注释与契约测试 spark-serves-filter-contract.test.ts 亦为 spark 专用表述。

## 授权范围

做什么：把 ObjectList 的 supportsServesSgNavigation 从「仅 spark」放开到 spark 与 workcase；泛化 ServesSgFilter 的注释与文案（不再写「Spark 的 serves_sg」）；明确其与 workcase lifecycle 五档筛选的叠加规则（两维度并存、计数口径一致）并实现；扩展契约测试覆盖 workcase 侧 SG 筛选（选项源/过滤/计数/URL 参数）。明确不做什么：不改 serves 字段语义（20 §8 与 21 §8 各自为其类型的唯一权威）；不改 goal 修订级联行为（25 §11 对 WorkCase 生效、对 Spark 豁免——筛选只读 serves 值，不涉级联）；不改后端 API（该筛选是前端过滤，Spark 侧亦无后端参数）；不改其它类型 tab 的筛选面；dist 重建、受控提交与验证三件套不列为计划步骤（归 06 §6.7 与 09 §7）。

## 计划

- 放开开关与文案泛化：判据——workcase tab 出现 SG 筛选且选项源跟随 goal 子目标；组件与注释不再限定 spark
