# 闲时摩擦发现接通子代理派生

## 摘要

机械层已具备，缺的是语义判断的承载者。

### 现状核实
上一单（提交 ae0ae9b）已落盘三个模块：`pending-queue.js`（04 §8.3 队列六条契约）、`friction-discovery.js`（§8.4 闭集机械部分，含 N=3 固定内嵌与精确回读）、`idle-checkpoint.js`（32 §10.2 预算轮换与 §8.3 fail-closed 收口）。`triggers.js` 已把 §8.4 的两步触发落成两个钩子，`lifecycle.js` 已挂 agent/status 监听并注入编排回调。全套 1140/1140 通过。

### 当前实际行为
触发链会走到 `runIdleCheckpoint`，但因没有语义判断提供者（`discover` 缺席），它返回 `skipped`——不创建任何账目。这是刻意的：§8.4 第 1 项的语义查重是规范明文登记的 gap，机械层不得代为判断，否则就是伪造一个机械校验冒充语义判断。

### 处置方向
用宿主的 `subagents.startContinuable` 派生受管辖隔离子代理，把机械前提（阈值 3、候选账本）交给它，收回其关于「哪条候选同题 / 是否为新阻碍」的判断，再由 `friction-discovery.js` 的闭集落地。必须在真实会话中实跑一轮并取得观察证据——04 §8.5 条件式要求「已写代码」不能代替「已跑通」。

### 边界
子代理的判断质量（把不同阻碍误判为同题会虚增 count 并把不该转 open 的账目推过阈值）无机械保障——§8.4 第 2 项的反向护栏把它列为已知失效面，处置是事后撤销误判递增（26 §17 第 6 项）。本单不消除该风险，也不得被引为已消除；子代理产出不取得授权或完成效力（§8.2 第 4 条），不得产生需要 Human 决定的结论（§8.2 第 2 条）。

## 授权范围

做什么：
- 用 subagents.startContinuable 派生一个受管辖隔离子代理，承载 04 §8.4 第 1 项的语义查重与入账判断
- 设计并落盘该子代理的提示词：输入为阈值 N=3 与既有 open/observing 候选（title/phenomenon），输出为结构化判断
- 把子代理的结构化判断接进 idle-checkpoint.js 的 discover 参数，由 friction-discovery.js 的闭集机械落地
- 验证 SubagentProvider.inheritsParentContext 对本地 provider 的实际取值，以及上下文继承是否真的生效
- 在真实受管辖会话中实跑一轮闲置检查点，取得完整链条的观察证据（触发→派生→判断→落盘→回读）
- 为新增链路补测试，遵守「测试失败须报告而非改写断言」纪律

明确不做什么：
- 不修改 04/26/32 号规范源（阈值 N 已由上一单固定为 3，本单不重开）
- 不实现容量维护与记忆健康体检两个任务（现如实报 not-implemented，保持原状）
- 不为语义查重建立任何相似度阈值式的机械判据冒充语义判断
- 不主张机制已运行——是否具备按 §8.5 由观察取得
- 不删除或改写既有 friction 账目
- 不自行撤销误判递增（属 26 §17 第 6 项的反向护栏，须独立核对）

## 计划

- 读清宿主 subagents 服务的 ContinuableStartSpec 契约，确认派生所需字段与 provider 名称解析路径
  - 完成判据：给出该服务在本仓可用 provider 名的实测输出，以及派生一次所需的最小字段清单；不可用时如实报告而不造字段
- 实测 SubagentProvider.inheritsParentContext 对本地 provider 的实际取值
  - 完成判据：给出实测输出（provider 名 + inheritsParentContext 布尔值），以及该值的来源（宿主注册处）；取不到即报告 unavailable，不从签名推断
- 设计并落盘子代理提示词与其结构化输出的契约（输入：阈值与候选清单；输出：判断结果）
  - 完成判据：提示词与输出契约成为仓内可回读的承载；输出契约明确「同题命中 / 新阻碍 / 无新发现」三态与各自必填字段
- 把 discover 接进 idle-checkpoint.js 并接通派生链路
  - 完成判据：新链路有测试覆盖，且测试断言的是「判断结果被机械落地」与「派生失败时按 §8.3 入队」，全套测试通过数不少于接单前的基线
- 在真实受管辖会话中实跑一轮闲置检查点，取得端到端观察证据
  - 完成判据：给出真实运行的观察输出（检查点确认→派生→判断→落盘或 skipped→回读），并如实标注哪些环节未能观察到
- 按 04 §8.5 如实报告机制是否已具备，并列出未验证范围
  - 完成判据：交还文本明确区分「已观察到」与「未验证」，且不含「机制已运行」这类超出观察的声明
