# 受控写入拒绝的机械留痕

## 摘要

给受控写入的机械拒绝补一条可累积的痕迹：`toolDescriptor.execute` 是所有 LDVH 工具的唯一包装点，在它返回非成功 envelope 时，把「工具名 + 原因码 + 时刻」追加到一个独立的非事实载体；既有闲时任务读出并按原因码聚合，作为语义判断的输入材料。

### 为什么接在 toolDescriptor 而不是各 writer
`plugin/lib/ldvh-tools.js:1839` 的 `toolDescriptor(operationKey, operation, handler)` 是统一包装：`ctx.tools.register(toolDescriptor(...))` 无例外地包裹每一个 LDVH 工具，成功与失败都经它的 `execute` 返回。各 writer 层（`workcase-writer.js`、`spark-writer.js` 等十余个模块）各有自己的 `failure()`，逐个接入既易漏又不可枚举；接在包装点则一处覆盖全部。

### 三项不可越过的边界
1. 不得写 11 §9 的摩擦观察缓冲（§12bis.1 写入者被穷举为两个）
2. 不得产出 `group`／`attribution`／`title`／`basis`（`11` 明写为执行体的语义判断产物）
3. 不得挤进 runlog（50 条环形已被诊断占满，且 `readTimerEvidence` 依赖它）

### 已实证的问题规模
修复诊断页多帧 zstd 缺陷后首次取得真实分布：604 次 LDVH 调用中 166 次失败，其中 `workcase/frontmatter_invalid` 16 次、`workcase/coherence_invalid` 10 次。同一类错误早已远超 N=3，缺的不是证据而是累积。

## 授权范围

做什么：
- 新增拒绝痕迹载体模块（`~/.dsh/ldvh/` 下，非事实源、按项目分区、带上限）
- 在 `toolDescriptor` 的统一 `execute` 出口处，对 `outcome` 非 `completed` 的结果追加一条痕迹
- 提供读取侧：按「工具名 + 原因码」聚合出「出现 N 次」的材料形态
- 补齐单元测试（含「成功不记」「聚合不跨原因码合并」「同项目隔离」三类断言）

明确不做什么：
- 不修改 `11`、`26`、`02`、`09` 任何规范条文
- 不写 Friction 账本（`ldvh-base/frictions/`）
- 不写摩擦观察缓冲（不 import `friction-observation-buffer.js` 的写入路径）
- 不产出 `group`、`attribution`、`title`、`basis` 任何语义字段
- 不改 `idle-runlog.js` 的容量、不向 `idle-checkpoint-runs.json` 写入
- 不新增阈值常量，不做「达 N 次自动入账」
- 不改 Web 呈现层

## 计划

1. 新增拒绝痕迹载体模块（写入 + 读取 + 聚合），落 `~/.dsh/ldvh/`，按项目分区、带上限
   - 完成判据：模块导出写入与读取函数，可被单测直接调用；同一 `dshHomePath` 下不同项目写入互不可见；超出上限时最旧条目被丢弃且文件大小有硬上界
2. 在 `toolDescriptor` 的统一出口接入痕迹写入
   - 完成判据：构造一次返回非 `completed` outcome 的工具调用，断言痕迹里出现一条含该工具名与原因码的记录；构造一次 `completed` 调用，断言痕迹条目数不增
3. 实现按「工具名 + 原因码」聚合的读取形态
   - 完成判据：写入分属两个不同原因码的同工具记录各 3 条，聚合结果返回两条独立分组、各自计数为 3，不发生跨原因码合并
4. 补齐单元测试并做变异验证
   - 完成判据：每条边界各有一条直接触发它的用例；对「成功也记录」「跨原因码合并」「跨项目串写」三处分别做变异，各被至少一条用例捕获（变异后失败、还原后通过）

## 结果

- 取消记录：
  - **理由**：建前独立审核（`21 §14`）三维全部判「不符」，结论 `needs_revision`；主控逐条复核原文属实，核心是**本工单的前提事实错误**，非措辞问题。三条致命项：① 「`toolDescriptor` 是唯一包装点」为假——`plugin/lib/ldvh-tools.js:1845` 的 `toolDescriptor` 只被本文件 `:1938` 的循环调用，遍历 `OPERATIONS` 的 12 项；十个类型模块各自 `export function toolDescriptorFor` 并在各自 `registerXxxTools` 内注册（`workcase-tools.js:1616`／`spark-tools.js:869`／`friction-tools.js:617`／`adr-tools.js:582`／`devlog-tools.js:638`／`goal-tools.js:307`／`norm-tools.js:558`／`pitfall-tools.js:486`／`research-tools.js:1052`／`subgoal-tools.js:659`），另有 `subagent-result.js:107` 内联；全仓无任何模块 import 该 `toolDescriptor`。故按现文实施，新载体对它所引的 16+10 次 `workcase/*` 拒绝覆盖率为 0。② 「`outcome` 非 `completed` 即被拒绝」不成立——`05 §8` 六值闭集区分 `unavailable`（前提不足）、`invalid_request`（形状不可解析、零副作用）、`rejected`（输入足够但被机械拒绝）、`partial`、`execution_error`；把四类混作一账会造出假摩擦，而这正是来源 Spark 自己列为待回答的第 4 个核心问题，本单未承接。③ 「拒绝返回即消失、同类错多次与一次同形」与事实不符——`plugin/web/api/services/runtimeDiagnostics.ts` 的 `extractToolOutcomes` 与聚合段早已按原因码跨会话累积（`byTool`／`byCategory`／`byCode` 三层），本单引用的 604/166/16/10 正是该报告的输出；以一份已聚合的报告证明没有聚合，逻辑上自相矛盾。另有可行性与 scope 项共九条必须修改项（`descriptor` 取不到 `dshHomePath`、写入落在同一 `try` 内会把 `completed` 翻成 `execution_error`、原因码在 envelope 无结构化字段、步骤 2 判据不能证伪、读取侧无调用者触 `02 §6.1` 唯一消费者、scope 内「不新增阈值常量」与「带上限 + 淘汰」自相冲突、「不 import 写入路径」不能阻止 fs 直写等），逐条见该次 `pre_reviews` 记录。
  - **未发生的范围**：未执行任何 `plan` 步骤（`draft` → `closed`，未经 Gate 1）；未触碰 `plugin/lib`、`plugin/test`、`specs/` 任何文件；未产生 Friction 账目或摩擦观察缓冲条目；四项 `done_criteria` 全部未开始。
