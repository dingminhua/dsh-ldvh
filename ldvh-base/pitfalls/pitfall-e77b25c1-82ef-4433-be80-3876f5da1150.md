# 准入判定下沉到可替换层致入口不短路

## 症状
为工具补写的单测转红：工具层读取开关之后仍然把请求交给了 seam，期望的「不调用下游」没有发生，因为开关判定被放在 seam 内部。逐字引证：

```
测试暴露了一个真实的设计缺陷：开关判定被委托给了 seam，导致任何 seam 实现都可能忽略它。
来源：本材料 turn 4 assistant 段（「最后为工具本身补一个测试」之后）：『测试抓到了一个真实缺陷：工具层读取开关后，**仍然把请求交给了 seam**，因为开关判定放在了 seam 内部。应该让工具层自己短路』；同一轮稍后又写『测试暴露了一个真实的设计缺陷：开关判定被委托给了 seam，导致任何 seam 实现都可能忽略它』。
```

识别信号：一条新补的单测转红，且失败原因指向「请求仍被交给了下游」——被守护的短路行为从未发生。

## 触发条件
把「是否放行」这类准入判定放进下层的可替换实现（seam）里，而不是放在工具入口自己做：工具入口读到开关后仍照常把请求交给 seam，判定结果完全取决于 seam 实现是否自觉短路。

## 根因
seam 是可替换实现，其契约里没有「必须短路」这条义务，把准入判定委托给它等于把守卫交给一个可以不履约的一方；工具入口又只负责读取开关而不据其自行拒绝，于是任何忽略该判定的 seam 实现都会让准入静默失效。覆盖面：lint 与既有检查都不覆盖这一层（它们不检查「判定发生在哪一层」），唯一能把它检出来的是一条直接针对短路行为的单测。

## 解决
该轮给出的处置是把短路搬回工具层：工具入口自己读开关并自行短路，不再把被拒绝的请求交给 seam（材料原文：「应该让工具层自己短路」）。成功信号：那条针对短路行为的单测由红转绿。必要边界：seam 仍可作为实现细节保留，但判定与拒绝动作必须发生在不可被替换的一侧（工具入口）。

## 规避
1. 准入/开关判定一律放在工具入口，不下沉到可替换实现；
2. 为「应当被拒绝／短路」这条路径补一条直接单测，断言下游未被调用；
3. 新增 seam 实现时，把「短路义务」写给调用方，而不是依赖实现自觉。
例外：判定所需信息只由 seam 掌握时，可由 seam 返回判定结果，但执行拒绝的动作仍由入口承担。

```

来源：本材料 turn 4 assistant 段（「最后为工具本身补一个测试」之后）：『测试抓到了一个真实缺陷：工具层读取开关后，**仍然把请求交给了 seam**，因为开关判定放在了 seam 内部。应该让工具层自己短路』；同一轮稍后又写『测试暴露了一个真实的设计缺陷：开关判定被委托给了 seam，导致任何 seam 实现都可能忽略它』。
```
