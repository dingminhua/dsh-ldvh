# 终态守卫无条件失败致终态更正被阻断

## 症状
对已处于 `retired` 终态的对象发起受控写入时，写入被失败返回阻断：实现层无条件返回 `failure("adr/status_terminal", ...)`，使「对终态对象的终态更正」这类按规范本应允许的动作无法落盘。逐字引证：`plugin/lib/adr-writer.js:585`：`if (prevStatus === "retired")` → 无条件 `failure("adr/status_terminal", "...the object i… 来源：主控会话 turn 13 · user 行 · 「双源召回 · 行动前候选」事实源清单中 spark/open 条目 spark-6317a233-90e9-443c-be06-5bc87ed54a5a.md（ldvh-base/sparks/spark-6317a233-90e9-443c-be06-5bc87ed54a5a.md）的摘要行；本材料未给出会话 id，故以 turn 号与行内位置回指。

## 触发条件
同时满足两点即触发：(1) 对象已处于终态（本次为 `prevStatus === "retired"`）；(2) 本次写入动作是规范允许的终态更正（内容更正、状态不变），而非状态推进。守卫条件只读对象的现态，不读本次动作的类型，于是两类动作被同一条件一并拒绝。

## 根因
终态守卫的判据覆盖面宽于契约意图：规范把「终态不可重开」限定在状态不可变这一面，而内容更正仍是合法动作；实现却把条件写成对「对象已处于终态」的无条件 `failure`，把契约中「状态不变即合法」的那一面一并挡下。即「对象已终态」被当成了「本次写入非法」，动作维度在判据中缺失。逐字引证：`plugin/lib/adr-writer.js:585`：`if (prevStatus === "retired")` → 无条件 `failure("adr/status_terminal", "...the object i… 来源：主控会话 turn 13 · user 行 · 「双源召回 · 行动前候选」事实源清单中 spark/open 条目 spark-6317a233-90e9-443c-be06-5bc87ed54a5a.md（ldvh-base/sparks/spark-6317a233-90e9-443c-be06-5bc87ed54a5a.md）的摘要行；本材料未给出会话 id，故以 turn 号与行内位置回指。

## 解决
把守卫条件从「对象已终态」收窄为「本次动作试图改变终态对象的 status」：对只改内容、不改 status 的终态更正走允许路径并正常写入；对试图把终态对象重新推进到其它状态的请求保留 `failure("adr/status_terminal", ...)` 拒绝。成功信号：终态更正落盘并可回读，同时状态推进仍被拒。

## 规避
实现终态守卫时按「本次写入动作改变了什么」分判，而不是按「对象现在处于什么状态」单判：终态对象的 status 变更一律拒绝，内容更正不得被同一条件连带阻断。核对条件：新增或复用 `failure(".../status_terminal", ...)` 类拒绝时，须确认它只覆盖状态推进路径。例外：若某载体规范明确要求终态对象整体不可写，则该载体按其规范执行。

## 影响与适用范围
适用于受控写入层以「对象当前是否已处于终态」单一条件判定写入合法性的场景；也适用于任何把「状态不可重开」扩张为「对象不可写」的终态守卫（本次为 ADR 写入器）。何时可能踩到：在终态对象上做内容更正时；本条引证「无条件 `failure("adr/status_terminal", ...)`」即该形态。经验何时可信：只要终态守卫仍以对象现态单判写入合法性，本条即适用；若守卫已按动作类型分判，则不构成约束。
