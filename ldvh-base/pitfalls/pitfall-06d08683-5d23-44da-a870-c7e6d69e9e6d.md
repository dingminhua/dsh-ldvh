# 以词频区分泛词与主题词在专门语料失效

## 症状

召回精确率长期停在个位数到十几个百分点，返回条目大量靠「相关」「已有」「结论」「影响」这类泛词命中；每次优化（扩虚字表、加类型点名层、加窄面判据、加 df 过滤、加主题词门槛、加全弱证据闸）都只换来 0～1 个百分点改善，或干脆把命中数一起打掉。

最锐利的识别信号：**在同一套门槛下，「该排除的泛词」比「必须保住的主题词」频率更低。**

## 触发条件

- 语料是专门领域（本仓为 284 份规范与事实载体），主题高度集中；
- 判据只使用词法统计（文档频率、停用词表、手工词表）；
- 系统期望用**同一个门槛**同时决定两件事——排除泛词、保住主题词。

三条同时成立即会触发。

## 根因

**在主题集中的语料里，主题词本身就是高频词，频率轴无法把「泛」与「主题」分开。**

实测（本仓 284 docs，df 为该词出现在多少份载体中）：

| 词 | df | 性质 |
|---|---|---|
| `相关` | 35% | 泛词 |
| `已有` | 25% | 泛词 |
| `仓库` | 32% | 泛词 |
| `结论` | 68% | 泛词 |
| `影响` | 59% | 泛词 |
| **`提交`** | **65%** | **主题词（查询核心）** |
| **`校验`** | **51%** | **主题词** |
| `排序` | 10% | 主题词 |
| `召回` | 22% | 主题词 |
| `门禁` | 23% | 主题词 |

`相关`（35%）比 `提交`（65%）还稀有。任何单向阈值都无法同时保住「提交/校验」又排除「相关/已有」——**不是词表不够大，而是判据在数学上不成立**。

已观察：六次尝试均失败或仅 0～1pp。
未知：是否存在某种非线性组合能在这条轴上分开两个群体——未穷举，但 df 分布重叠已使高收益希望很低。

## 解决

接受该方向不可解，转向两条正交路径：

1. **碎片（跨词二元组）可用 PMI 修**。实测门槛取 6 时质量基线 10.8% → 11.7%，返回行 65 → 60，命中数不变（7/8）。收益小（+0.9pp）但零召回损失；建表约 394ms，需按语料指纹缓存。
2. **语义判别**才是真正剩下的手段：需要词性、句法角色或向量相似度，超出纯词法能力。`34 §6` 的三态判据设计本就把裁决交给 AI 语义消费。

成功信号：明确写下「不再尝试扩词表／加 df 门槛」，把精力导向碎片与语义两条线。

## 规避

核对条件：当有人（包括 AI 自己）提出「加一个停用词表／把某词放进泛词集／提高 df 门槛来提高精确率」时。

动作：**先量候选词的 df，看「要排除的」是否真的比「要保住的」频率更高**。若两者重叠（如 35% 对 65%），立即停手，不要写代码。

例外：若语料改为通用领域文本（主题词不再天然高频），或已引入词性／句法信息，则本判定不再适用，可以重试。

## 验证

已观察：本仓 284 份载体上的 df 实测值；六次失败尝试的历史；PMI 门槛 6/5/4/3.5 四档实测（11.7%／11.1%／8.0%／8.0%）。

来源：`research-0b3471af`（DSH 记忆家族横向调研）、`research-f8b248ce`（F4 回声陷阱：相似度 ≠ 必要性），以及本轮新增的 Lucene／IK／PMI 三处外部证据。

未覆盖：未验证「主题词高频」在多大规模语料上开始成立；未穷举所有非线性判据；PMI 碎片过滤仅做过实验，**已撤销，尚未落地**。

## 影响与适用范围

适用于用词法统计（文档频率、停用词表、词表扩充）判断「某个词是否构成检索主题」的召回排序与注入决策；在主题词本身即高频的专门领域语料上必然失效。

展开：**何时可能踩到**——专门领域知识库的词法召回、任何想用停用词表调精确率的场景。
**何时可信**——语料主题集中、判据仅用词频。语料一旦通用化或引入语义特征，本经验不再可信。

## 证据

- Lucene `CJKBigramFilter`：二元组建在分词器切出的 script run 上，无相邻字时才退为 unigram——二元组本身是召回导向的近似边界。
- `elasticsearch-analysis-ik` README：`ik_max_word` 最细粒度适合 Term Query，`ik_smart` 最粗粒度适合 Phrase Query——工业做法是双粒度，细粒度供召回、粗粒度供精度。
- Wikipedia `Pointwise mutual information`：明载 PMI 偏向低频事件，并另设 `pmi^k` 变体专纠此偏差——与「idf 奖励稀有的跨词碎片」同构。
