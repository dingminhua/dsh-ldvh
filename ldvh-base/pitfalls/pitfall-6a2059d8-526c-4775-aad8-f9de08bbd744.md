# 契约语言要求只落成一个字面量致其余描述失守

## 症状
一条全英文的提交通过了 Git Gate 与提交预检，没有任何机械判据把它拦下。该提交仍然带着中文字面量 `关键变更:`，所以全部格式类判据都通过，英文只出现在 header 描述与正文散文这些判据触及不到的位置。事后补检查时，在历史 1341 笔里量到同类命中 2 笔（`2c476bd8` 本身与 `de701ec`），未豁免时量测值为 2/1229。

## 触发条件
契约里同时存在两项同语义要求：一项是硬性字面量要求（`关键变更:` 必须逐字节相等），另一项是只对自然语言描述成立的默认要求（描述部分用中文）。判据是按「当前代码里可机械匹配的字面量」逐条枚举写出来的，于是默认要求只落成对那一个字面量的检查，其余同语境的字段没有任何判据。

## 根因
`plugin/lib/commit-validation.js` 的 `validateMessage` 用严格相等承载中文要求：`const keyIndexes = lines.flatMap((line, index) => (line === "关键变更:" ? [index] : []));`。判据覆盖面因此恰好等于这一个字面量 token——它能证明这套契约默认中文，却不能证明 header 描述用了中文。覆盖面窄于契约意图的那部分就静默失守：不是判错了，是根本没有判。

## 解决
在已有的 `GATE_RULES` 里登记 `validation/header_not_chinese`（severity: blocking），并在 `validateMessage` 的 header 校验之后加入辅助函数 `isHeaderDescriptionNonChinese`：取出 `type(scope): ` 之后的描述部分，描述非空且不含 `[\u4e00-\u9fff]` 范围内字符时产出一条 finding。同步在测试的预期规则清单中登记新规则并补用例，把两处以英文占位作描述的夹具改为中文（这两处考的是 type/scope 结构，与语言无关），并对两笔历史提交走豁免登记。

## 规避
枚举判据时按「契约声称要求什么」列，而不是按「代码里现在写了哪几条规则」列；一旦发现已有判据强制逐字节写出某个中文标识符，就把它当作「本契约默认中文」的一等证据，去核对契约里还有哪些字段同属中文语境却没有判据。不要因为搜索代码没命中中文/语言类关键词就判定契约没有该要求——命中缺席不等于要求不存在。

## 验证
已观察：新判据针对性用例 84 pass / 0 fail；全量历史回放 1341 笔零命中（其中 2 笔已登记豁免，未豁免时量测为 2/1229）；去掉本次改动后完整套件仍出现同样的 2 个失败，说明这 2 个失败与本次改动无关。未覆盖：改动后完整套件的最终差分在观察结束时仍未落地；判据落在共用的 `validateMessage` 上、声明同时作用于 Gate 与 precheck，但 pre-commit hook 路径的实际拦截未被观察；判据只要求「至少一个汉字」，因此只含极少中文的描述是否会被拦、以及 `\u4e00-\u9fff` 之外的扩展区汉字是否被计入，均未观察。

**入档复核（2026-10-19）**：转正前对修复面做了机械核对——修复已由提交 `3937abb` 入库：`plugin/lib/commit-validation.js:77` 登记 `validation/header_not_chinese`（blocking），`:115` 为 `isHeaderDescriptionNonChinese`，`:144` 在 header 校验之后调用并产出 finding，与本条「解决」段逐条对应；`:61-64` 的 `HEADER_LANGUAGE_EXEMPTIONS` 逐字登记 `fix(injection): stop re-injecting the governance block on adjacent turns`（`2c476bd`）与 `fix(client): ctx.get→ctx.inject for betterSidebar tab registration`（`de701ec`）两笔，与本条所述「两笔历史提交走豁免登记」一致。与 pitfall-daed4856（新增判据未量测可分辨力致零检测力）的关系须声明：两者源自同一次修复，但机制不同——daed4856 记的是「判据选取前未量测可分辨力」，本条记的是「契约的同语义要求只落成一个字面量、其余无判据」，前者是方法学教训、后者是实现覆盖面缺口，故分别承载、互不替代。原文「未覆盖」三项（最终差分、pre-commit hook 路径、扩展区汉字）维持原样。

## 影响与适用范围
LDVH 插件侧提交校验链（`plugin/lib/commit-validation.js` 的 `validateMessage` 及其调用方 Git Gate 子进程、提交预检与 commit-msg hook），以及任何以字节精确字面量承载契约要求、而契约其余同语义部分没有对应机械判据的场景。
