# 无基址构建致 SPA 白屏

## 症状

构建命令返回成功（vite 输出 `✓ built in N s`），无任何错误或警告指向资源路径；浏览器打开 SPA 挂载路径时整页空白。开发者工具网络面板可见 JS/CSS 请求指向宿主根路径而非 SPA 前缀路径，拿到的不是该 SPA 的产物。

**识别信号**：页面空白但构建日志无异常；`dist/index.html` 中 `src`/`href` 以 `/assets/...` 开头，而非 `/<prefix>/assets/...`。该信号可在不打开浏览器的情况下直接检查产物得出。

## 触发条件

同时满足以下条件时触发：

1. SPA 通过宿主挂载在非根前缀（如 `/ldvh`），且与宿主共享同一端口；
2. 构建时未指定该前缀——即直接调用底层 `vite build`，缺少 `--base=/<prefix>/`（构建工具 `base` 默认为 `/`）；
3. 构建产物目录不作为版本控制内文件被比对或校验（dsh-ldvh 的 `dist/` 属 `.gitignore`），因此错误产物不会被提交差异暴露。

## 根因

构建工具的 `base` 默认值为 `/`，产物据此生成绝对资产引用。该引用相对于**浏览器地址栏的站点根**解析，而非相对于页面所在的前缀路径；前缀挂载下引用必然落空。宿主对未知路径的兜底行为（本实例返回 200 的宿主页面而非 404）使症状表现为「整页空白」而非「资源 404」，进一步掩盖了真实原因。

**已观察**：`--base` 缺失是直接原因，且为充分原因——同一次源码，仅切换构建命令的基址参数即可复现与消除。

**未知**：宿主兜底路由策略不同的部署下症状形态是否一致；其它构建体系（webpack/rollup 直接配置）的等价配置未验证。

## 解决

改用带基址的项目构建脚本，不直接调用底层构建命令：

- dsh-ldvh：`pnpm build:dsh`（= `tsc -b && vite build --base=/ldvh/ && node scripts/gzip-dist.mjs`）；
- 反例（会白屏）：`npx vite build`。

**成功信号**：`dist/index.html` 的资产引用以 `/ldvh/` 开头；`GET /ldvh` 与 `GET /ldvh/assets/<hash>.js` 均返回 200 且 `Content-Type` 为 `text/javascript`。

**必要边界**：仅重新正确构建即可恢复，无需修改源码；若错误产物已被分发（如随包发布），需重新分发，仅重建本地目录不足以修复已分发副本。

## 规避

1. **核对条件**：任何 Web 构建之后，检查 `dist/index.html` 的 `src`/`href` 是否全部以挂载前缀开头。
2. **动作**：一律使用带基址的项目脚本；不以「构建成功」作为「页面可用」的证据——二者在本机制下不相关。
3. **机械拦截**：`plugin/web/tests/api/spa-asset-base-contract.test.ts` 在产物存在时校验前缀，违规即失败并打印修复命令；已接入 CI（`.github/workflows/ci.yml` 的 web job 先 `build:dsh` 再跑契约测试），使该拦截在持续集成中生效。
4. **例外**：若该 SPA 改为独立端口或根路径挂载，前缀约束不再适用；若构建脚本自身改为在配置中固定 `base`，则命令行参数不再是必要条件，但仍应保留产物校验。

## 验证

**已观察**：

1. 以裸 `npx vite build` 复现白屏——产物引用为 `/assets/index-*.js`，与实际服务的 `/ldvh` 前缀不符；
2. 守卫测试在该错误产物下确实失败，并输出含修复命令的失败信息（非静默通过）；
3. 以 `pnpm build:dsh` 重建后，`/ldvh` 与资产引用均恢复正确，实测 `GET /ldvh` = 200；
4. 在全新 clone（无 `dist/`）中复验完整 CI 序列（install → type-check → build → test）通过，269/269。

**未覆盖**：

1. GitHub Actions 实际运行环境未验证，仅在本地模拟同等步骤；
2. 其它构建工具的同类基址语义未验证；
3. 宿主兜底路由策略不同的部署未验证。

## 影响与适用范围

适用于「SPA 以非根路径前缀挂载、与宿主共享同一端口」的构建与验证：构建产物引用未挂该前缀时，页面在浏览器中整页空白，而构建过程本身成功且不报错。已验证实例：dsh-ldvh 的 plugin/web（/ldvh 前缀，pnpm build:dsh 与裸 vite build 的差异）。

**何时可能踩到**：任何「非根前缀挂载 + 共享端口」的 Web 前端构建；尤其当构建产物不入库、且构建成功不校验资源路径时——此时错误既不被版本控制暴露，也不被构建过程暴露，只在浏览器中显现。

**何时可信**：在 Vite 及 `base` 语义相同的构建工具下可信；换用其它构建体系时应重新验证等价配置。若本项目改为独立端口或根路径挂载，本经验的前提消失。
