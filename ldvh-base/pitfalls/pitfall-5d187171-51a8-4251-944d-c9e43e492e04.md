# 读取已删字段得undefined致诊断整体失败

## 症状
调用运行时诊断工具时，整个调用失败并回显 `value is not lossless JSON`，而不是返回部分结果。逐字引证：value is not lossless JSON。来源：主控会话 [turn 76] assistant 段：诊断工具报错回显（原样）value is not lossless JSON，另见同段「**但我漏了一处**：诊断工具还在读 `settings.review.model`，而该字段已被我删掉 → 读到 `undefined` → 工具返回值不是合法 JSON → 整个诊断报错：」

## 触发条件
同时满足两点即触发：(1) 诊断工具组装返回值时读取某个可选字段；(2) 该字段此前已被删除（或从未存在于当前配置），读取结果为 `undefined`。此类读取没有出现在返回值组装处的显式缺省处理里，缺陷只在序列化时才显形。

## 根因
诊断工具还在读 `settings.review.model`，而该字段已被我删掉 → 读到 `undefined` → 工具返回值不是合法 JSON → 整个诊断报错。即：读取侧对已删除字段没有失效判据，`undefined` 被原样带入工具返回值；返回值组装层又没有统一的合法性保证（序列化前的兜底或校验），于是一个字段缺失被放大成整次诊断调用失败。逐字引证：value is not lossless JSON。来源：主控会话 [turn 76] assistant 段：诊断工具报错回显（原样）value is not lossless JSON，另见同段「**但我漏了一处**：诊断工具还在读 `settings.review.model`，而该字段已被我删掉 → 读到 `undefined` → 工具返回值不是合法 JSON → 整个诊断报错：」

## 解决
按同段自述定位到漏掉的那一处读取并加以修正：「**但我漏了一处**：诊断工具还在读 `settings.review.model`，而该字段已被我删掉」——修正方向是让该读取不再取已删除的字段，或对其取值做缺省兜底，使返回值重新成为合法 JSON。成功信号：诊断工具调用不再回显 `value is not lossless JSON`。

## 规避
组装工具返回值时，对所有可能缺省或已被删除的可选字段一律先做缺省兜底，并在序列化前对整个返回值做一次合法性校验（确保其为合法 JSON），不让单个字段的 `undefined` 传播为整次调用失败；删除配置字段时，须同步核对并清理全部读取侧引用点。核对条件：新增或改动诊断类工具的返回值字段时，确认每一项都有「取不到时取什么」的显式约定。例外：确实允许缺失且已有外层兜底的字段可不重复兜底。

## 影响与适用范围
适用于宿主侧运行时诊断类工具在组装返回值时读取可能已被删除或缺省的可选字段的场景；也适用于任何把外部读取结果直接放进工具返回值、且无序列化前兜底或合法性校验的调用。何时可能踩到：删除某个配置字段后未清理读取侧、或让可选字段以 `undefined` 进入工具返回值时；本条引证「读到 `undefined` → 工具返回值不是合法 JSON」即该形态。经验何时可信：只要工具返回值仍可能携带未兜底的缺省字段，本条即适用；若返回值组装层已具备统一的序列化前校验与兜底，则不构成约束。
