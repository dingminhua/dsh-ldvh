# 中间载体路径缺项目维度致材料混装

## 症状
同一个中间载体里混着多个管辖项目的观察材料：诊断页列出的条目中，属于本项目的与属于其他项目的混在一起，按项目筛选无法得到干净结果。

## 触发条件
中间载体的路径不含项目维度，取路径的函数只接受 `dshHomePath` 一类全局参数。任何「多个管辖项目共用一份运行状态」的实现（观察缓冲、待处置队列、水位文件等同型）在第一个项目之外产生材料的项目上触发。初期只有一个项目时不会暴露，第二个项目一接入即出现。

## 根因
写入位置的维度少于材料的维度。材料按项目产生，但载体按宿主产生——两处维度不一致，材料就只能落到同一个文件里。此时再想区分项目，只剩「给每条记录加 project 字段」一条路，而那会越出该类型的字段闭集（经验条目的闭集本就比摩擦条目少一项，没有 project 位）。

## 解决
载体改为按项目分文件：`<项目 id>.jsonl`，与相邻类型的同类载体并列而分立。项目 id 在全部分区入口改为必填，缺失时明确拒绝（`*/project_missing`）；另加源码级护栏扫描，覆盖全部缓冲调用点，防止将来新增调用点时漏传。

## 规避
把「载体路径函数的参数是否含取舍维度」作为新建任何中间载体时的必答项：材料的区分维度有哪些，载体路径就必须带哪些。不要指望事后给记录加字段补救——字段闭集是事先定的，事后加字段要么越界，要么改动全部消费方。

## 验证
本项目实测：改造后两个项目各自的诊断页只列本项目条目，按项目筛选结果与直接读该项目的载体文件逐条一致。护栏扫描在新增调用点漏传 `projectId` 时报错。守卫用例 `plugin/test/buffer-project-partition.test.mjs` 15 pass；两个上层入口在缺项目时分别返回 `capture/project_missing` 与 `observation_review/project_missing`。

### 独立复现验证（2026-11-02）

**复现主体与独立性边界**：主控委派的独立子代理（受管辖隔离子代理，上下文不外泄给本候选），模型与主控相同（deepseek-v4.1-flash），派生于同一会话但上下文隔离；按 01 §12.2 读作「同模型 + 上下文隔离」，不是异模型独立验证。

**复现做法**：直接对缓冲层调用 `appendBufferEntry` / `readBufferEntries`，分别在不传 `projectId`、传两个不同 `projectId` 三种情形下写入并读回；再经 `landCaptureVerdict`、`reviewPendingEntries` 两个上层入口试缺项目写入；最后跑 `plugin/test/buffer-project-partition.test.mjs`。

**观察结果**：`bufferEntryPath(home)` 在不给项目时仍回落到旧的全局载体 `…/ldvh/observation-buffer.jsonl`；两处不带 `projectId` 的写入**都成功**并各自读回，读出的 item 上没有 project 字段；分别传项目 id 时各自隔离、互不串扰。上层两个入口已拒绝：`landCaptureVerdict` → `capture/project_missing`，`reviewPendingEntries` → `observation_review/project_missing`。分区守卫用例 15 pass。

**判定**：**部分复现**。材料的「写入维度少于材料维度」确凿，上层入口的明确拒绝与分区隔离也已落地；但候选「解决」段所称「各写入入口改为必填、不静默回落到旧全局载体」在缓冲层本身**不成立**——`appendBufferEntry` / `readBufferEntries` 仍静默回落（用例注释逐字写着「空串 = 未传：落到旧 global carrier（向后兼容）」）。入档前应把该句限定为「分区入口」而非「各写入入口」，或另行决定是否收掉缓冲层的回落。

**未覆盖**：诊断页按项目筛选的界面呈现；候选症状段引用的历史数字「47 条观察中混有他项目材料」未能复核（当时现场未留存）。

## 影响与适用范围
适用于一切把「多个管辖项目的运行状态」落到同一载体的实现：观察缓冲、待处置队列、水位与检查点文件、运行痕迹日志。不适用于载体本身就以项目为单位的形态（如每项目一个目录）。边界：本条的解法要求写入维度与材料维度一致；若某类材料天然跨项目（如宿主机级事件），须在该载体上另行说明其归属判据，不能套用本条。

展开——何时可能踩到：新建任何按宿主而非按项目落盘的中间载体时（观察缓冲、待处置队列、水位与检查点、运行痕迹日志），在第二个管辖项目接入那一刻就会暴露；第一版只有单项目时完全看不出来，因此不能以「现在单项目跑得好」作为不需要项目维度的证据。经验何时可信：材料确按项目产生、而载体路径的形参里没有项目维度时，本条的判据与解法成立；反过来说，若载体本身就以项目为单位（每项目一个目录或一个文件），本条不适用。另外须记住本条在「验证」段记下的准确边界——分层拒绝只落在分区入口上，底层缓冲的 append/read 仍保留向后兼容的静默回落，因此不能把本条读成「所有写入入口都必填」；若要收掉那层回落，属另一次决定，不在本条范围内。
