# 按存档整文件恢复致带回他人在途改动

## 症状
从本地存档整文件恢复自己的改动后，工作树中的文件带回了并非自己写入的内容：`spark-tools.js` 出现别人的 `objectRef` 用法却没有对应 import（会报错），恢复出的测试文件里多出一条自己不存在的用例 `collect tool: resolves a child that finished BEFORE the rebuild` 并因此失败。这些外来内容无法用「这是我改的」解释，只能逐文件重新甄别。

## 触发条件
同一工作树上还有其他执行线同时在途改动；自己把改动以整文件粒度存入本地存档；随后工作树回到某个基线（HEAD），再按存档做整文件恢复。

## 根因
存档快照的基线与恢复时的 HEAD 不属于同一条时间线：快照基于较早的提交（`8ca87ab`），其上 HEAD 已有更新的逻辑；同时取快照时工作树里已经存在其他执行线未提交的改动。整文件恢复把这两项一并作用到工作树上——旧版整文件内容覆盖了 HEAD 上更新的部分，别人的在途改动也随文件一起被带回。

## 解决
恢复后逐文件与 HEAD 比对，把内容分成三部分：自己新增的 hunk、HEAD 已有而存档版本更旧的 hunk、他人未完成的在途改动；然后按 HEAD 重建文件、只保留自己的 hunk，并把自己不拥有的测试用例从恢复出的测试文件中排除。

## 规避
保存时记录基线提交号，以及当时工作树里是否存在他人在途改动；恢复前先确认存档基线与当前 HEAD 的先后关系；恢复后对每个文件逐一核对「本文件是否只含我的 hunk」，通过后再进入 lint 与测试。

## 验证
按 HEAD 重建并排除外来用例后，观察到：lint 干净；相关 49 项测试全部通过；全量测试中剩余 8 个失败经「暂停自己的改动后重跑」确认在未应用自己改动时同样失败，属既有失败；提交 `2c476bd` 经 Git Gate 通过，暂存区不含外来内容。未覆盖的部分：被排除的他人在途 `objectRef` 改动与那条测试用例是否仍完整保留在其原有载体上，本次未观察；多轮存档/恢复下的重复验证也未做。

**入档复核（2026-10-19）**：转正前对修复面做了机械核对——提交 `2c476bd`（fix(injection): stop re-injecting the governance block on adjacent turns，2026-10-19 03:30）确存在，其 `关键变更:` 恰含 `plugin/lib/spark-tools.js`、`plugin/lib/workcase-tools.js` 等条目，与本案涉及的载体一致；当前 `plugin/lib/spark-tools.js:35` 已有 `import { objectRef, objectRefOf } from "./object-reference.js";`，即症状所述「有用法无 import」已消失，`node --check` 通过；该文件 `:659`、`:683`、`:686` 的 `objectRef`/`objectRefOf` 用法与本条所述外来 `objectRef` 用法对应。本条自述的「未覆盖」之一（被排除的他人改动是否仍完整保留在其原有载体上）本轮仍未观察，维持原样——**不能据上述核对声称他人的在途改动未在任何环节丢失**，该段核对只证明自己的提交干净。
