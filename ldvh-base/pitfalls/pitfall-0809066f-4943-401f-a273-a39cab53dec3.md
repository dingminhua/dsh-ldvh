# dsh-ui 根容器形态错致围栏整段无效重发

## 症状

助手发出的一处 dsh-ui 围栏中，根级 `items` 字段被写成对象而非数组，渲染层判定为 `invalid_json` 并拒绝渲染，要求重发修正版；该回复的结构整体未渲染出来。逐字引证：

```
"items":{"type":"text","content":"你已明确要求提交全部在途改动，我照办
来源：主控会话 turn 26：assistant 段的 dsh-ui 围栏「提交前核实」JSON（items 为对象），及其后说明「我的上一个围栏 JSON 无效（渲染失败）。重发修正版，并先验证。」；对应 user 段的 genui-fence-repair #13a318819055（status=render_failed，error=invalid_json，repair=failed，next=resend_corrected_fence_only）。
```

识别信号：宿主回执形态是 `status=render_failed` + `error=invalid_json` + `next=resend_corrected_fence_only`（整段拒收），而不是节点级的 `invalid_spec` 逐项诊断；围栏根级 `items` 的值是一个带 `type` 的对象而非数组。

## 触发条件

手写 dsh-ui 围栏时把根级 `items`（节点数组）写成单个节点对象，且发出前未调用机械校验（`validate_dsh_ui`）。与同族形态错位的差异：table 节点的 rows 形状错由宿主判 `invalid_spec`（节点级回执，可逐项定位），根级容器形态错则落在 `invalid_json`（整段围栏拒收），代价是整段重发。

## 根因

手写 dsh-ui 围栏在发出前没有机械校验位：宿主侧的形状校验只在提交之后生效，写作侧没有把「根级 `items` 必须是数组」这类结构性约束在发出前核一遍，于是结构性错误只能等渲染失败后才被回执发现，成本从「自查一次」升级为「整段重发」。这类错误与内容质量无关——文字无误、语义通顺，唯一错处是容器形态，因此任何只读正文、不查结构的人工复核都看不出它；可用的机械入口（`validate_dsh_ui`）本可拦截（pitfall-4ac5ebb6 已实测该入口对 rows 形状错会给 `invalid_spec` 诊断），只是本轮未在发出前调用。

## 解决

已实际采用的处置是重发修正版并先验证：「我的上一个围栏 JSON 无效（渲染失败）。重发修正版，并先验证。」；对应回执为 genui-fence-repair #13a318819055（`status=render_failed`、`error=invalid_json`、`repair=failed`、`next=resend_corrected_fence_only`）。成功信号：修正版围栏不再触发围栏修复回执。必要边界：这纠正了这一次围栏，未在写作侧建立发出前的强制校验位，同型错误仍只能靠宿主回执发现。

## 规避

1. 核对条件：根级 `items` 恒为数组（节点列表），不得写成单个节点对象——`{"type":"text","content":...}` 这类只能出现在数组元素位置。
2. 动作：发出前用机械校验入口（`validate_dsh_ui`）先验一次 JSON 与节点结构，把 `invalid_json`／`invalid_spec` 挡在提交之前，而不是靠渲染回执发现（pitfall-4ac5ebb6 已实测该入口对 rows 形状错会给出诊断）。
3. 动作：收到 `render_failed`／genui-fence-repair 回执时，按回执整段重发修正版并重验，不做局部补丁式重发（局部重发往往带着同型错误再失败一次）。
4. 例外：经 `render_ui` 工具面提交时按工具自身 schema 构造根容器，不手写根级 `items` 字面量。

## 验证

已观察：turn 26 的 dsh-ui 围栏根级 `items` 为对象，宿主回执 `status=render_failed`、`error=invalid_json`、`repair=failed`、`next=resend_corrected_fence_only`；助手在同一轮说明「重发修正版，并先验证。」。逐字引证：

```
"items":{"type":"text","content":"你已明确要求提交全部在途改动，我照办
来源：主控会话 turn 26：assistant 段的 dsh-ui 围栏「提交前核实」JSON（items 为对象），及其后说明「我的上一个围栏 JSON 无效（渲染失败）。重发修正版，并先验证。」；对应 user 段的 genui-fence-repair #13a318819055（status=render_failed，error=invalid_json，repair=failed，next=resend_corrected_fence_only）。
```

未覆盖：修正版围栏是否渲染通过（材料未给出后续回执）；`validate_dsh_ui` 对「根级 items 为对象」这一形态是否直接给出诊断未实测（只实测过其对 rows 形状错的诊断）；同批回复中其它围栏是否也有根容器形态问题未逐一核。

## 影响与适用范围

适用于一切手写 dsh-ui 围栏（含 `render_ui`）的提交场合：根级 `items` 写成对象时，宿主判 `invalid_json` 整段拒收并要求重发，回复面上一条结构都不渲染。何时可能踩到：一次回复里要发多块结构化内容、根级节点数组较长时（本条引证的「提交前核实」块即该形态）；手写围栏 JSON 而不经 `render_ui` 工具面时风险更高。何时可信：只要根级容器形态仍靠宿主回执才发现，本条即适用；若发出前每次都过一遍机械校验，则不构成约束。本条不覆盖 table 节点 rows 逐行形态（见 pitfall-df2ce84d）与非白名单 `type` 被静默丢弃（见 pitfall-4ac5ebb6）——那两类的失效面分别是节点级拒收与节点静默消失，与本条的整段拒收不同。
