# 新工作树缺依赖致验证失败

## 症状
在新创建的工作树中直接运行需要第三方依赖的验证命令时失败，而同一条命令在主仓工作目录能通过。逐字引证：失败原因是新工作树缺 `node_modules`，不是规范问题。识别信号是失败与本次改动内容无关、且失败发生在工作树刚创建之后；同一命令在主仓执行正常。

## 触发条件
三个条件同时成立时触发：① 工作树是新建的（`git worktree add` 或 create_worktree 工具），依赖目录按设计不在版本控制中；② 未先安装依赖就运行验证命令（规范解析、测试、构建、类型检查）；③ 命令的模块解析落在工作树自身而不是主仓。逐字引证：失败原因是新工作树缺 `node_modules`，不是规范问题。

## 根因
工作树创建与依赖准备之间没有时序契约：新建工作树只带受版本控制的文件，`node_modules` 不在其中；验证入口不检查依赖是否就绪，失败只以通用命令错误出现，调用方须自行判断是环境缺失还是验证内容失败。逐字引证：失败原因是新工作树缺 `node_modules`，不是规范问题。已观察的是本次失败与安装依赖后重跑通过；尚未观察验证入口内置依赖预检的形态。

## 解决
本次实际采用：在新建工作树中安装依赖（本仓用 pnpm 安装），随后重跑同一条验证命令，命令通过。成功信号：安装依赖后同一验证返回成功、不再报缺依赖。必要边界：这只补齐环境，未改变验证内容——逐字引证：失败原因是新工作树缺 `node_modules`，不是规范问题。

## 规避
新建工作树后按「创建 → 安装依赖 → 运行验证」三步执行；不要用主仓的依赖或主仓工作目录代替，否则还会掩盖工作树内的改动（另见验证目录沿用的既有经验）。核对条件：工作树刚创建、且验证失败指向缺包或模块解析时，先确认工作树内依赖目录是否存在。逐字引证：失败原因是新工作树缺 `node_modules`，不是规范问题。

## 验证
已观察（本次）：在新建的 dev-v6 工作树中运行规范解析验证失败，失败原因是新工作树缺 `node_modules`，不是规范问题；安装依赖后重跑同一条命令通过。未覆盖：其它工作树与其它包管理器是否同形、离线或无网络环境的处置、验证入口是否应内置依赖预检（未实现，故未观察）。

## 影响与适用范围
适用于在新建 git 工作树中运行依赖验证命令（规范解析、测试、构建、类型检查等）的场合：新建工作树不含 node_modules 等依赖目录，未先安装依赖即运行验证会失败。经验可信的边界是「依赖不在版本库、验证命令需要已安装依赖」这一组合；若验证入口自带依赖预置或依赖已随工作树分发，本条前提消失。

展开——何时可能踩到：新建工作树、克隆后首次运行、或在隔离副本上做验证时。何时可信：依赖不在版本库且验证命令需要已安装依赖时；若依赖已随工作树分发或验证入口自带预置，本条前提消失。
