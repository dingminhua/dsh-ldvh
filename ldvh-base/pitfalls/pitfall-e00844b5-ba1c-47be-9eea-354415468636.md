# 会话header读取位置与宿主不符致复核记录恒不可写

## 症状
复核通道看似已接通，但 `record_review` 始终写不进 `reviews`：任何已结束的复核者都被判成「不是本代理」，机械校验反复拒绝写入，工单在 Gate 2 收口处反复卡死。

## 触发条件
会话 header 由宿主放在 handle 属性上，而读取代码按约定去 events 数组里找那一行。

## 根因
代码与宿主实际的 header 存放位置不一致——宿主把会话 header 放在 handle 属性上，代码却去 events 数组里找那一行，因而永远找不到，`reviews` 字段写不进去。

## 解决
修改读取实现使其按宿主实际位置取 header（提交 `b8caddb`），并把更正提交进仓以免再被并发会话的 `git stash` 收走。

## 规避
对接宿主会话结构前先确证 header 的真实存放位置，不按文档或事件流的约定位置直接实现读取。

## 验证
重启会话后修复生效：四条真实复核记录全部解析成功，`record_review` 写入成功，第 11 轮复核记录已写入 `reviews`（结论 needs_revision）。未覆盖：本次观察未见对四条记录之外其它来源、以及 handle 属性缺失场景的取证。

## 影响与适用范围
适用于任何以会话 header 做身份判定、并据此写入受控载体的场景；读写位置不一致时症状表现为「字段恒不可写」而非报错，易被误判为权限或前置条件未满足。
