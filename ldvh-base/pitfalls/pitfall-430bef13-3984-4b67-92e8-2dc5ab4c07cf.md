# 标识符正则未覆盖CJK致路径截断误判

## 症状

提交前的引用检查把一条指向确实存在、但路径中含 CJK 字符的 docs 文件引用报成「悬空引用」，报出的 token 是被截断的 ASCII 前缀（如 `docs/workcase-996e207a-指称形态候选-2026-10-18.md` 被截成 `docs/workcase-996e207a-`）。主控据此认为「Git Gate 要求移除该引用」，准备对载体文本做最小化改写以让门禁放行——即判据误报会把人推向改写语义内容。

## 触发条件

校验正则用 `\w`／`[A-Za-z0-9]` 一类字符界定路径或标识符边界，未启用 Unicode 属性转义与 `u` 标志；被检文本中存在 CJK 字符时，匹配在首个非 ASCII 字符处停止，只截到前缀。前缀当然无法在仓库中解析为真实路径，于是被判成悬空。

## 根因

正则的字符类没有覆盖 Unicode 字母／数字／组合记号（`\p{L}` / `\p{N}` / `\p{M}`），也没有 `u` 标志，于是「能匹配到的 ASCII 前缀」被当成了完整的标识符：判据把形式当成了语义，把截断产物当成了被检对象本身。截断点恰好落在 CJK 起始处，因此只在含中文的路径上暴露，纯 ASCII 路径不受影响，回归用例若不含 CJK 形状就测不出来。

## 解决

把 `commit-validation.js` 中的路径／标识符字符类改为 `[\p{L}\p{N}\p{M}._/-]` 并加 `u` 标志，使其覆盖 CJK 字母、数字与组合记号；同时补一条覆盖该形状的回归用例，防止退回窄字符类。该模式与用例已落在提交 9262710。

## 规避

见到「引用被判悬空但报出的 token 明显只是某条更长路径或标识符的前缀」时，先判定是不是匹配被截断，而不是先把引用改写掉——改写会掩盖判据缺陷并损失语义。所有以 `\w` 或 ASCII 字符类界定路径／标识符边界的校验器，改用 Unicode 属性转义（`\p{L}`／`\p{N}`／`\p{M}`）并加 `u` 标志；新增此类判据时，回归用例里放一条含 CJK 的样本。

## 验证

已观察：`git diff` 在两个相关文件上为空，本次改动无残留；模式与回归用例均在 HEAD:297；全套 1688 pass / 0 fail / 1 skipped，fail 计数为 0；用仓库中已修的代码对暂存内容重跑检查后 Gate 通过（E 组以 96076f2 落地）。
未覆盖：除本仓库该处引用检查外，其它校验器（commit message 的其它判据、其它插件的路径匹配）是否同样使用窄字符类未逐一验证；CJK 与组合记号混排、emoji、非拉丁文字的边界未专门测；预检服务端旧模块导致该判据修复后仍报旧 token，属另一条已入账的阻碍，本次未解决。

独立复现验证（2026-10-28，入档前置）：复现主体为隔离子代理（独立上下文 session 59751938-eb68-42da-a4ee-f2102f9fd730），未参与本候选形成；独立性边界为与形成者同模型（dsh-opencode-go/deepseek-v4.1-flash）、上下文隔离。复现做法：取 `9262710^` 的旧 `commit-validation.js`，对真实存在的中文 docs 路径调用 `checkDocsReferences`；再在 /tmp 副本把现行实现尾类换回 `[A-Za-z0-9._/-]` 跑 `test/commit-validation.test.mjs`。

观察结果：旧实现对 `docs/workcase-996e207a-指称形态候选-2026-10-18.md` 报 `validation/docs_reference_dangling`，token 截断为 `docs/workcase-996e207a-`（症状与根因均成立）；现行实现对同一句提取出完整路径，`commit-validation.test.mjs` 在 HEAD 91/91 通过；把尾类改回旧值后 CJK 用例转红、actual 逐字为截断前缀。修复提交 `9262710` 同时改实现与加用例。复现未覆盖：候选所记「全套 1688 pass」未复核（按纪律不跑全量套件）；「均在 HEAD:297」的行号已漂移到 308；现行尾类实为 `[\p{L}\p{N}\p{M}._/-]*[A-Za-z0-9_-]`，以 CJK 收尾的 docs 路径仍不被提取，属残留缺口。


**机械化承载（2026-10-28 盘点）**：`plugin/lib/commit-validation.js:307-308` 的 `_FLAGS = "gu"` 与 `_SOURCE` 的 Unicode 尾类，配合 `plugin/test/commit-validation.test.mjs:623`（CJK 中段 + ASCII 收尾整条提取）与 `:643`（重建丢 u 标志即失效）已把本条的规避实现为机械判据：含 CJK 的 docs 路径不得被截成 ASCII 前缀。覆盖边界：`_SOURCE` 尾类仍要求 ASCII 收尾，以 CJK 收尾的引用要么被截成 ASCII 前缀并误报 dangling，要么整条提取为空（实测两种形态均如此，此处不复写字面路径以免本身被同一判据误报）；用例只覆盖 ASCII 收尾的样本，其它校验器未审计。

## 影响与适用范围

凡用 `\w`／ASCII 字符类界定路径或标识符边界的提交前校验器（本次在 commit-validation.js 的 docs 引用检查上实际观察），仓库含 CJK 文件名或 CJK 引用文本时适用；其它校验器未覆盖。
