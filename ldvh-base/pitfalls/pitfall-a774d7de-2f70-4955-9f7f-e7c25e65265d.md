# 校验假定形式与语义一一对应

## 症状

为「写法/命名/编号」类纪律设计了机械校验或守卫测试，它**看起来正在管这件事**，但实测出现两类同时发生的失效：

**漏检**：目标错误的**真实写法**根本没被拦住。实测本例——WorkCase「执行」节记账纪律要求「计划步骤 N」（N 以当前 plan 为界），据此设计的越界校验（拒 N 超过 plan 长度）对错误写法「步骤 7」「步骤 8」**全部放行**：该校验函数体内**从不出现「执行」**（实测计数 0），它压根没看执行节。

**误报**：合法载体被拒。同一校验把含「引述他对象编号」的摘要判为越界（`超出当前 plan 长度 6`），于是那张**记录该缺陷的工单**自己写不进去——修复工具被自己的修复挡住。

**守卫只到形态级**：独立对抗审核实施变异 ⑥（把被回退的校验改名 `checkLedgerNumbers`、改文案、保留全部语义，接入写入路径），7 项守卫测试**全部通过**，而该门禁实测确实会拒绝写入。

## 触发条件

两个条件同时成立时触发：一、被约束对象是**自然语言正文**而非结构化字段；二、校验以**形式特征**（数字、编号、「步骤」字样、行首前缀）近似「该写法合规」这一语义判断。

组合条件：**形式与语义非一一对应** + **以形式特征代替语义判定**——两者同时成立即触发，与具体语言、项目、实现无关。

## 根因

**形式到语义的映射不构成一一对应，而机械校验只能看见形式。**

「步骤 7」与「计划步骤 7」在语义上是同一件事的两种写法，但形式上不同；反过来，同一串数字既可能指目标集合的元素，也可能指叙述者自身的序号，两种指代在字形上无别。校验器只能匹配字形，因此它在两个方向上同时出错：该拦的写法不在它的匹配面内（漏检），不该拦的写法落在了匹配面内（误报）。

**误报的代价被低估**：误报不是「多拦一次」，而是**制造反激励**——谁想按规范修正，就得先把这条守卫弄绿，于是修复被推回去保留缺陷（本例即如此：那张工单自己写不进去）。

## 解决

已实际采用（2026-09-18，LDVH 仓库 `21 §8` 执行节记账纪律，本仓库 WC-1c6afa19）：**回退该机械校验**，改以不含任何拒绝规则的「弱约束」承担同一目标——

- 规范给出**唯一合法写法**（「计划步骤 N」），不给替代写法留空间；
- 弱约束的判断依据由实现侧在该纪律所约束操作的时点**提示给调用方**（而非由机械校验拒绝）；
- 弱约束不具强制力，**不得据其声称已获保障**。该声明已写入守卫测试头部，并有一条守卫断言该声明存在。

三条核对条件（**加校验前做「变异三连」**，每次变异后必须还原）保留如下，作为识别本机制的方法：

1. **目标错误形态能否被捕获**：把该校验声称要防的那个错误**按它的真实写法**注入，观察是否被拒。若原错误写法与校验识别形式不同形，此项必失败——这正是本例的发现方式。
2. **合法形态是否被误伤**：注入合法写法（含各种等价变体：全/半角、缩进、引号、CRLF），观察是否被误拒。
3. **语义等价改名是否逃逸**：把校验函数改名、错误文案改写、但保留全部语义，观察守卫是否仍能捕获。若守卫仍全绿而该门禁实测生效，则守卫只具备形态级保证——**如实登记该边界，不得宣称语义级防护。**

**例外**：当被校验对象是**结构化字段**（YAML/JSON 的枚举、类型、必填性、闭集）而非自然语言正文时，形式与语义通常一一对应（`status: open` 就是那个枚举值，不存在等价的另一种写法），机械校验在此**有效且应当使用**。本经验不构成「不要加校验」的通用主张——它只否定「形式与语义非一一对应的场合仍强行加校验」。

## 规避

**已被规范源吸收（2026-10-28，Human 决定废止）**：上述三条核对条件与变异三连已由 `specs/06` §5 承载——「新增校验前须以变异验证其三向有效性：目标错误的**真实写法**可被捕获、合法写法的等价变体不被误伤、把被守卫实现**改名改措辞但保留语义**后仍被捕获」，以及「被区分对象在形式上不可分时（同一字形承载不同语义），不得以机械校验强制执行」。自该条款生效起，本条不再独立承担约束，仅作为该规则的来源引用保留（`specs/23` §6.3、`specs/35` §8.6 第 3 项）。**引用时请以条文标题与章节号定位**：`specs/06` 行号随改动漂移，本仓已发生过多起废止对象裸行号失准的情形（本条自身原引的 `:103`／`:105` 即已于 2026-10-28 更正——两处现在分别落在 `06` §4「适用范围」与 §5 的变异三向段，均非原指条文）。

以下为废止前的原始规避记录，保留为历史基线：

**核对条件**（加校验前逐条自问，对应 `specs/06` §5 的变异三向）：

1. 被校验对象在**形式上是否可分**？同一字形是否承载不同语义（「步骤 7」既可能指计划元素也可能指叙述序号）？形式上不可分时，不得以机械校验强制执行。
2. 合法写法是否存在**等价变体**（全/半角、缩进、引号、CRLF）？存在时须先归一化，再验证不被误伤。
3. 把被守卫实现**改名改措辞但保留语义**后，守卫是否仍能捕获？不能则守卫只到形态级，须如实登记该边界，不得宣称语义级防护。

**动作**：三项逐条做变异验证，每次变异后还原；任一不成立时，不得以收紧匹配或增加文本断言加以掩盖。

## 验证

已观察（2026-09-18，LDVH 仓库）：

- **漏检**：以 2 步 `plan` 的 WorkCase 载体实测，向「执行」节写入纯「步骤 7」「步骤 8」——现有 `validateCarrierCoherence`（`plugin/lib/workcase-writer.js`，只校验摘要/授权范围/计划三节）返回通过，错误正常落盘。该校验函数体内**从不出现「执行」**（实测计数 0）。
- **误报**：为同一载体加上「识别显式形式」的校验后，含「引述他对象编号错误」的摘要被拒（`超出当前 plan 长度 6`），导致该对象无法再写入——该误报发生时对象正是「记录该缺陷」的那张工单。
- **守卫形态级**：独立对抗审核实施变异 ⑥（语义等价、改名改文案的越界门禁 `checkLedgerNumbers` 接入写入路径），7 项守卫全部通过且该门禁实测确实拒绝写入；本次由实现者独立复现确认。
- **回退后**：web 测试 274/274、plugin 测试 824/824 全绿；本单工单（摘要含该引述）可正常写入。

**后续复核（2026-10-14，LDVH 仓库）**：触发信号第 1 项（守卫从源码文本断言改为**行为断言**）**部分命中**——2026-09-27（commit 389c575）新增 `plugin/test/workcase-plan-step-reference.test.mjs`（3 项行为断言：注册真实工具、断言调用方实际收到的信封），原有的 7 项源码文本守卫（`plugin/web/tests/api/workcase-execution-ledger-contract.test.ts`）原样保留、其头部关于保证边界的声明亦在。新增行为层的直接原因是**本机制在同一纪律上的第三次实证**：全部源码文本守卫对该值的形态断言全绿，而 `plan_step_reference` 在工具边界被一个**六键白名单**重新投影时被**静默丢弃**，调用方根本看不到权威编号清单（新增测试头部的原文记述：`every source-text guard was green while no caller could see the list`）。⇒ 本条的机制判断据此再次成立，且比创建时更明确：源码文本断言把「某形态存在」当作「某语义生效」，**当形态未变而语义在后续投影中丢失时，守卫全绿与防护失效可以并存**。边界须一并记明：行为断言能覆盖这类缺口，但**不能反推源码文本断言有害**——后者仍承担「防止已知形态被误删或被随手复原」的作用；两者并存才是当前的实际防线。

未覆盖：

- **弱约束的实际降低复发率未验证**——只有本会话一例样本，且规范与工具层提示的真实遵守效果需跨会话观察。
- **同类校验未普查**——本仓库其它类型（20/22/24/26/27）的正文纪律是否存在同根因设计，本经验未逐项核对。
- **变异三连第 3 项的通用性未验证**——「语义等价改名逃逸」在本例由独立审核的变异 ⑥ 实证，但其它项目的源码文本断言是否同样脆弱，需按其实际实现核对，不得仅凭症状相似即认定同因。

## 影响与适用范围

为「写法/命名/编号」类纪律设计机械校验或守卫测试的场合——特别是校验需要区分「X 引用自己」与「X 引述他人」、或需要以源码文本断言代替行为断言时，校验必然同时漏检与误报。已验证实例：LDVH `specs/21` §8 执行节记账纪律的越界校验（已回退）及其 7 项守卫测试。

具体而言：

- **何时可能踩到**：为自然语言正文的写法纪律新增机械校验时；把结构化字段的校验经验平移到正文纪律时（前者形式-语义一一对应、后者不然，平移即引入本机制）；用源码文本断言守卫「某实现不得复活」时。本例的触发场景是：AI 在一次执行记录里自创编号、与 plan 的位置序号混同，修复者据此设计「越界即拒绝」的校验——设计动机完全正当，失效源于**形式不可分**而非动机错误。
- **经验何时可信**：本经验的机制判断（形式-语义非一一对应时，机械校验必然漏检+误报，且误报制造反激励）在自然语言正文范围内稳定成立，与具体语言、项目、实现无关。但**具体到其它校验，是否同样不可分须按「核对条件」第 1 条实测**——先做变异三连，不得仅凭症状相似即认定同因，也不得因本经验存在就放弃所有正文校验。
- **与既有经验的分界**：`96fb3199`（首行比较式校验漏掉多余H1）的根因是判定单位选错，**可修**；本条的根因是形式-语义映射不可判定，**不可修**，只能改为弱约束或不设校验。二者症状相似（都表现为校验失效），**根因不同，故各自成对象**（23 §6.2：不同机制的相似症状不合并）。
