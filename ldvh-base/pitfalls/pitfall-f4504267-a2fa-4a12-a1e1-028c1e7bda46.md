# 否定式守卫用例缺正控制致假通过

## 症状

一条以「只断言不命中」为主的守卫用例，在被守护的实现整体失效（返回空集）之后仍然全绿：否定断言在空结果上全部成立，用例看起来守住了行为，其实对实现的整体失效零检测。

识别信号：把被守护实现改成 `if (true) return [];` 后该用例通过；用例里找不到任何一条断言「正确输入应当命中」的正控制。

## 触发条件

为「不命中／拒绝」类行为补守卫用例时，断言全部写成否定式（不该命中 X、不该返回 Y），且被守护的实现以返回空集表示失败而非抛错。此时实现整体失效只会让结果更「空」，否定断言反而更容易成立。

## 根因

否定断言只能区分「错误地命中了」与「没命中」，无法区分「正确地没命中」与「实现根本没工作」。当失效方向恰好是「什么都不返回」时，否定断言的预期值与被破坏后的实际值一致，于是用例通过。缺的不是断言数量，而是一条正方向的控制项：证明这条链在被破坏之外的情形下确实能工作。

## 解决

在同一用例里补正控制断言：先用一个必须命中的正确输入，断言结构层确实命中，再跑否定断言。正控制失败时的信息应直接说明判读方法——本项目写的是「对照：正确的短指称须命中。此项失败说明结构层整体失效，下面的否定断言无意义」，使失败信息本身即可判断题面。

## 规避

给「不命中／拒绝」类行为补守卫用例时，先写正控制、再写否定断言；验收手段是变异：把被守护实现改成恒返回空集，用例必须转红，若不红即缺正控制。例外：实现失效时抛错而非返回空集时，否定断言会因异常失败，本条不直接适用；或套件内另有正控制用例覆盖同一路径时，可不必重复。

## 验证

已观察：结构层 `if (true) return []` → 该用例仍绿；加了正控制后才转红，说明此前该用例对被守护实现的整体失效零检测。

### 独立复现验证（2026-11-02）

**复现主体与独立性边界**：主控委派的独立子代理（受管辖隔离子代理，上下文不外泄给本候选），模型与主控相同（deepseek-v4.1-flash），派生于同一会话但上下文隔离；按 01 §12.2 读作「同模型 + 上下文隔离」，不是异模型独立验证。

**复现做法**：给 `plugin/lib/source-recall.js` 的 `structuralHits()`（:1692）注入 `if (true) return [];`，然后跑 `plugin/test/source-recall.test.mjs:2616` 起的那条守卫用例，分两版：①删去正控制后仅保留否定断言；②保留正控制（在 :2628–2634）。

**观察结果**：①删去正控制的版本仍全绿（pass 1 / fail 0）——即结构层整体失效而否定断言全过；②保留正控制的版本转红，报 `AssertionError: 对照：正确的短指称须命中。此项失败说明结构层整体失效，下面的否定断言无意义`。正控制措辞本身就把判读方法写进了失败信息。

**判定**：复现成功，且当前 HEAD 该用例已带正控制（`a3525fc` 之后入库），即候选「解决」段的落地在版本上可核。

**未覆盖**：同批其它否定式用例未逐条做同样的变异检查；变异只覆盖「整体失效返回空集」一种形态，逐字段错误、边界值错误等局部变异是否可检出未验证；全量套件（116 个测试文件）未跑。

## 影响与适用范围

适用于以「只断言不命中」的否定式用例守护某一层实现的回归测试：当被守护实现整体失效并返回空结果时，否定断言全部成立而用例假通过。不适用于同一条用例已含正控制断言、或实现失效时抛错而非返回空集的情形。展开——何时可能踩到：为「不命中/拒绝」类行为补守卫用例时，尤其被守护实现以返回空集表示失败而非抛错时；只跑一遍用例看到全绿就认为守卫已成立时。经验何时可信：材料能指出该用例的断言全为否定式、被守护实现被整体改坏（返回空集）后用例仍绿、补正控制后转红时，可据此判定缺口在缺正控制断言；若实现失效时抛错（否定断言会因异常而失败），或套件内另有正控制用例覆盖同一路径，则本条不直接适用。
