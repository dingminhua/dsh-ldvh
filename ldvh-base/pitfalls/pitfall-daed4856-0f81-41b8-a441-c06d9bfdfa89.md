# 新增判据未量测可分辨力致零检测力

## 症状
在提交 message 语言的修复方案中新增了一条机械判据（要求整条 message 必须含中文）。该判据被当作对本次事故的防护写进方案，实际上一次也不会触发：凡满足既有规则的消息必然同时满足它。审核者指出后实测确认，全部提交 1230 笔中含字面量 `关键变更:` 的有 1229 笔，判据被现有规则完全蕴含，检测力为 0——它看起来做了防护，实际什么都没拦，并会被后续复核读成「该方向已闭环」。

## 触发条件
未先取真实历史作基线量测，就把一条「读起来像防护」的机械判据写入修复方案；当该判据的成立条件恰好已被既有规则蕴含时，缺陷在复核之前不会被任何环节察觉。

## 根因
判据按「形式上像防护」而非「在真实数据上能独立触发」来选取。既有规则已强制 commit message 含中文字面量 `关键变更:`，新增判据只是该规则的真子集，不提供任何增量拦截力；检测力为零的判据仍被计入方案覆盖面，制造了已闭环的假象。

## 解决
撤下该判据，不作修饰保留。方案中只保留能独立触发的那一条表述（header 描述部分须含汉字），并在采纳前先在真实历史上量测其误伤：conventional 形状 1229 笔中仅 2 笔误伤（`2c476bd`、`de701ec` = 0.16%），事故前历史仅 1 笔，据此确认成本可数、不是不可承受。

## 规避

**已被规范源吸收并修正（2026-10-28，Human 决定废止）**：本段规避已由 `specs/04` §6.3「新增机械判据须先判定它与既有规则有无增量」承载。**该条同时修正了本条的方法**：原文主张「取全部历史提交作基线量测，单独触发数为 0 时不纳入方案」——而历史提交按构造几乎全部满足既有规则，故任何新判据在该语料上的独立触发数**恒为 0**，按字面会禁止一切新增机械判据（`04` 条文审核第 1 轮所指出）。现行条文改为「**集合蕴含**」判据：先按「该判据要约束的对象」划定同领域**已在机械面落地且会实际阻断**的检查的并集（只产诊断/提示的检查不计入），再判新判据的触发集合是否被该并集覆盖；被蕴含 ⇒ 无增量、**不得据此声称已防住或已闭环**（但可以加，其价值只记可诊断性等其它项）；不被蕴含 ⇒ 在既有语料上量测误伤并写明语料范围；判不出逐条差别时按「未被蕴含」处理。强制落点为 `04` 第 10 节「验证与证据边界」表中「新增机械判据与既有规则的关系」行。自该条款生效起，本条不再独立承担约束，仅作为该规则的来源引用保留（`specs/23` §6.3、`specs/35` §8.6 第 3 项）。**引用时请以条文标题与章节号定位**：`04` 行号随改动漂移，本仓已发生过多起废止对象裸行号失准的情形。

以下为废止前的原始规避记录，保留为历史基线（其量测方法已被上述条文取代，不得按字面执行）：

新增任何机械判据前，先取全部历史提交作基线，量测两项：该判据单独可触发的比例（确认检测力非零），以及它与既有规则重合造成的零增量比例。单独触发数为 0 时不纳入方案，即便其描述听上去像防护；纳入前须同时给出误伤率，用以判断取舍是否值得。

## 验证
已观察：全部提交 1230 笔中含 `关键变更:` 的 1229 笔，确认旧判据被现有规则完全蕴含；替换判据在 1229 笔 conventional 形状上误伤 2 笔（0.16%），事故前历史 1 笔。未覆盖：替换判据尚未进入规范、仍在等待 Human 决定是否修订 §5.1，其在后续真实提交上的实际拦截表现、对新提交形状的误伤率均未观察到；0.16% 只在既有历史样本上测得，不能外推到未来形状。

**入档复核（2026-10-19）**：转正前对修复面做了机械核对——替换判据已由提交 `3937abb`（fix(gate): header 描述须含中文，闭合全拉丁标题的放行缺口）入库：`plugin/lib/commit-validation.js:77` 登记 `validation/header_not_chinese`（severity: blocking），`:115` 为 `isHeaderDescriptionNonChinese`，`:144` 在 header 校验后产出 finding；豁免表 `HEADER_LANGUAGE_EXEMPTIONS`（`:61-64`）逐字登记两笔既有拉丁标题，与本条「2 笔误伤已登记豁免」对应。量测口径复核：本条所记「全部提交 1230 笔、含 `关键变更:` 1229 笔」为当时基线；按当前仓库复算为总提交 1342、含 `关键变更:` 1232 笔，差值来自此后新增提交（`3937abb`、`8955e2a`、`945a78c` 等），比例结论（近乎全部提交都含该字面量，故「整条消息须含中文」为真子集）不变。原文「未覆盖」三项（规范是否修订 §5.1、后续真实提交的拦截表现、新形状误伤率）维持原样。

**规范补写进展（2026-10-28）**：已在 `specs/04` §6.3 新增「新增机械判据须先判定它与既有规则有无增量」——先按「该判据要约束的对象」划定同领域**已在机械面落地且会实际阻断**的检查的**并集**（只产诊断/提示的检查不计入），再判新判据的触发集合是否被该并集覆盖；被蕴含 ⇒ 无增量、**不得据此声称已防住或已闭环**（但可以加，其价值只记可诊断性等其它项）；不被蕴含 ⇒ 在既有语料上量测误伤并写明语料范围，该领域无既有语料时量测义务不成立、须把「未测误伤」登记为未覆盖；判不出逐条差别时按「未被蕴含」处理。§10 补验证行，§1 补负担 (d) 与风险 (d)。

该处经**三轮代理独立审核**（隔离子代理），**终审判定 `pass`**。三轮轨迹：
- 第 1 轮 3 blocking。最重的是作者原稿写「单独可触发数为 0 时不得纳入方案」——而历史提交按构造几乎全部满足既有规则（本仓 1533 笔提交中几乎全含 `关键变更:`），故任何新判据在该语料上的独立触发数**恒为 0**，按字面会**禁止一切新增机械判据**；同时针对尚未出现的新形状的判据必然为 0，也被一律拒收。作者据此把判定从「样本计数」改为「集合蕴含」。
- 第 2 轮：前轮 B2/B3 已解决；B1 未解决并新发现两项——①「所属领域」无定义、判定量词（并集/逐条）未定，两种读法在「新判据触发集 = A∪B、既有 A、B 各覆盖一半」时结论相反；②「被蕴含 ⇒ 已被拦住」未限定既有检查须为**拦截型**，把只产诊断的检查算作覆盖会把真实增量误判为零。
- 第 3 轮（终审）：判定 `pass`。前轮三项全部已解决，9 项新发现均为 non-blocking。作者随后按审核建议修了其中最优先的两项（§10「可证明范围」补「不证明增量判断实质正确」、未满足处理补「有语料但未量测误伤即声称覆盖」这一档）与三项小项（「生效」限定为已在机械面落地、§1 出口改回指、对象描述须取实际读取的载体）。

**遗留（按 01 §12.4 登记；终审已 pass，但下列改进项未做）**：
1. **量测的时点与前提**：§10 行写「提出新增机械判据时」，但「运行它量测」须先有实现；正文未写明量测可在实现之后补做。
2. **领域粒度的残余空间**：领域由提案方对「该判据要约束的对象」的描述决定，虽有「须取判据实际读取的载体」兜底，仍存在收窄描述以缩小既有规则并集的空间；残余由「既有规则清单」交审核方核对承担。
3. **与 Code 侧变异三向的证据合并口径未写**（对象不同、不构成重复展开，但合并使用时如何陈述未规定）。
4. **「被蕴含」的方向在 6 处使用**，单读 §10 行或 §1 时方向可能读反，宜在术语处点明。

## 影响与适用范围

适用于向机械校验新增提交类判据时的取舍与复核环节。**引用时须知其规避已被规范修正**：原文的「样本计数」判据（单独触发数为 0 即不纳入）在既有规则近乎全覆盖的语料上会退化为「禁止一切新增判据」，现行条文以「集合蕴含」取代之；本条作为该修正的来源保留。
