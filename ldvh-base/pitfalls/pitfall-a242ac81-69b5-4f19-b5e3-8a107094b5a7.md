# 运行期载体跨载体引用致校验失败

## 症状

在 dsh-ldvh 仓库执行 `npm --prefix plugin test`，`test/runtime-carrier-validator.test.mjs:1264` 用例「the real plugin-specs corpus has no errors, hints or gaps」失败，实际 {errors:2, hints:0, gaps:0, verdict:'fail'}，期望 errors=0 / verdict='pass'；全量 2613 项中 2594 通过、1 失败、19 跳过。

## 触发条件

在 `plugin-specs/*.yaml` 的 `ldvh_spec.requirements[].text` 正文里写 `§` 条款号引用（如「（00 §4.5）」），或写另一个运行期载体的 spec_key 引用（如「（ldvh-root 的 proxy-auxiliary-failure）」）。本例由提交 c6d7406b 在 `plugin-specs/pitfall-fact-type.yaml` 的 `delegate-draft` 条目（requirements[8].text）引入。

## 根因

运行期载体写作契约禁止跨载体引用。`validateRuntimeCarrierCorpus` 逐字扫描 text 字段：「00 §4.5」命中 `prohibited/section_reference`（matched "§"）；「ldvh-root 的 proxy-auxiliary-failure」命中 `prohibited/other_runtime_carrier`（matched "ldvh-root"，matchedForm spec_key）。两处都在 doc 正文里，不在载体头部；该校验对正文同样生效。

## 解决

把两处括号指针删掉、改为自足表述，规则语义原样保留（「也不因落笔取得规则效力或完成结论。」与「由主控如实转告。」）；落地提交 dcfca02f。

## 规避

写运行期载体正文时不写 § 条款号与 spec_key 跨载体指针；需要指向别处时改写成自足的规则陈述（被删的只是指路，规则本体仍写在正文里）；改完运行 `npm --prefix plugin test` 核对语料校验用例，或用 `validateRuntimeCarrierCorpus` 只读求值看 errorCount 是否归零。

## 验证

已观察——`npm --prefix plugin ci` 退出 0；修复后 `npm --prefix plugin test` 全绿（2613 项、2594 通过、0 失败、19 跳过）；校验器 HEAD 版 errorCount=2 / verdict=fail，工作区版 errorCount=0 / verdict=pass；独立审核确认全语料 `grep -rn "§" plugin-specs/` 无命中、无同类跨载体引用残留。未覆盖——仅实测 § 与 spec_key 两种禁止形态，未穷尽其他禁止写法；未在其他宿主/项目验证；未验证未来校验器规则变更后的形态。
