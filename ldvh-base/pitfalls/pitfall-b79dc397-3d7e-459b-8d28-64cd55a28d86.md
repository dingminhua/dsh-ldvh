# 新增防护无直接用例致变异零检出

## 症状

首次变异验证时，M4 变异没有被测出来：登记查重这条防护没有被测试覆盖住，整套测试在变异生效后仍然全绿，没有任何用例因该变异转红。

逐字引证（缓冲条目 944aecd9-03e2-4416-a26b-2410037d1a05 的 evidence，原文复制）：

```
M4 没有被测出来：登记查重这条防护没有被测试覆盖住。补一条直接覆盖它的测试。
来源：本次会话 turn 115 助手正文（材料窗口内 assistant 段落）
```

识别信号：变异体改变了一条新增防护的行为，跑完整套测试却零失败；被变异的那条防护在用例集中找不到一条以它为断言对象的用例。

## 触发条件

一次改动新增了防护或拒绝路径（本例为登记查重这条防护），而测试用例是按既有行为构造的，没有一条用例的输入真正落到该防护的拒绝分支；随后以变异验证检验覆盖度时触发。材料记录的是「首次变异验证」。若已有用例直接触发并断言该防护，或变异不改变任何可观察行为，则不属于本形态。

## 根因

变异验证的检出条件是「有用例在该变异生效时失败」。新增防护只被既有用例间接经过、没有用例把输入构造到它的拒绝分支，于是变异改变了防护行为却不改变任何被断言的可观察结果，M4 便存活下来。材料对此的判断是「登记查重这条防护没有被测试覆盖住」——覆盖的判据不是防护代码被执行过，而是有断言能观察到该防护的行为差异。已观察：M4 没有被测出来，且材料把原因归为登记查重防护没有测试覆盖。未确证：既有用例是完全没执行该分支，还是执行了却未断言其结果，材料未区分。

## 解决

为登记查重这条防护补一条直接覆盖它的测试：让该用例的输入真正落到防护的拒绝分支，并把断言钉在该防护的行为结果上，使变异一旦破坏防护，这条用例就转红。成功信号（材料记载）：补一条直接覆盖它的测试之后，该防护才被测出。必要边界：补用例后重跑变异验证的输出未留在材料中，故「M4 已转红」在本条中属预期而非已观察（见验证段）。

## 规避

新增防护或拒绝路径时，同时补一条直接覆盖它的测试，把「只该防护能拦住」的输入固定下来；在变异验证里以「删改该防护后这条用例是否转红」作为覆盖验收，而不是以「既有用例全绿」推断新防护已被覆盖。对本例而言，为登记查重这条防护补一条直接覆盖它的测试，即把零检出的变异变成可检出。例外：防护无法从外部触发、或变异与原型行为等价时，不以变异存活判定覆盖缺失，须另找可观察信号。

## 验证

已观察：首次变异验证中 M4 没有被测出来，材料明言登记查重这条防护没有被测试覆盖住；处置是补一条直接覆盖它的测试。未覆盖：补用例后重跑变异验证的具体输出（M4 是否转红）未留在材料中；其余变异体的检出情况未出现；「新增防护无直接用例即零检出」在其它防护路径上的可复现性未验证。

## 影响与适用范围

适用于以变异验证检验新增防护或拒绝路径覆盖度的场景：当新增的防护分支没有一条直接触发它的用例时，变异体不会被任何用例捕获而存活；本例为登记查重这条防护与 M4 变异。不适用于已有用例直接断言该分支、或变异不改变可观察行为的场合。

展开——何时可能踩到：改动新增了防护或拒绝分支，而用例主要覆盖正常路径；或把「全套测试全绿」当成新增防护已被覆盖的证据时。经验何时可信：材料能指出该防护没有一条直接触发它的用例、且变异改变的是该防护的可观察行为时，可据此判定变异零检出源于覆盖缺失，本例的登记查重这条防护即因缺少直接用例而未被测出；若防护不可从外部观察，或变异与原型行为等价，则本条不适用。
