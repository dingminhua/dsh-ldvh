# 破坏性 mv 以未确认的 glob 作目标致目录并入

## 症状

在 `ldvh-base/` 下做恢复性质的移动，事后六个同级目录整体出现在 `ldvh-base/workcases/` 里，而 `ldvh-base/` 下这六个目录同时消失：目录结构被破坏，实际被搬动的路径数量远多于操作者以为的「移动一个文件」，且命令本身没有任何报错。

逐字引证（缓冲条目 bcccb5ca-3eb0-4f78-aabd-607bb58ac191 的 evidence，原文复制）：

```
我把六个目录整体移动到了 `workcases/` 里。原因是 `mv "$f" ldvh-base/*/` 中的 glob 展开了多个目录，`mv` 会把最后一个当目标目录，前面全当源。
来源：会话主控材料 turn 97（assistant 段落中「我在排查中犯的错误」一节，dsh-ldvh 仓库 ldvh-base/ 目录）
```

识别信号：命令只写了一个源路径和一个 glob 目标，目标目录事后多出成组目录、源位置成批缺失。

## 触发条件

三个条件同时成立时才会发生：① 通配符写在命令的**目标**位置，例如 `mv "$f" ldvh-base/*/` 里的 `ldvh-base/*/`，而源是单个 `"$f"`；② 该模式在当前目录下匹配到多于一个目录（`ldvh-base/` 下并列多个子目录时成立）；③ 执行前没有先确认展开结果，直接执行这条破坏性移动。只匹配到一个目录时 `mv` 只得到一个目标，不会发生并入；已打印确认过展开结果并看到多候选的，属于配置错误而非本条机制。

## 根因

shell 在 `mv` 启动前完成路径名展开：`ldvh-base/*/` 被替换成一串目录路径，`mv` 于是收到多个操作数，并按「最后一个操作数是目标目录、前面全是源」的语义执行——最后一个匹配目录成了目的地，`"$f"` 和其余目录一起被并入它。认知上的错位在于：操作者把通配符当成「一个确定的目录」，shell 却把它变成了一个路径列表，而命令文本里没有任何提示或确认点标出这个转换。故失败方向由匹配结果决定（最后一个才是目标），与「我以为目标是那个目录」的意图无关；这也解释了为什么命令不报错：对 `mv` 而言这是一条完全合法的多源移动。

## 解决

识别后按原路径把被并入 `ldvh-base/workcases/` 的六个目录移回 `ldvh-base/` 原位，恢复目录结构；恢复与之后的搬移一律把目标写成精确的单一路径，不再让通配符出现在目标位置。

必要边界：材料逐字记录的是误移本身与根因自述，恢复动作的具体命令与回读结果未被逐字记录，本条不据记忆补写这些细节（见验证段）。

## 规避

在写下任何会一次移动或删除多个路径的破坏性命令前，加一道「展开结果核对」，三步即可：① 核对条件——命令的目标参数含通配符（如 `mv "$f" ldvh-base/*/` 里的 `ldvh-base/*/`），或源参数可能匹配多个路径；② 动作——先把同一模式交给 `printf '%s\n' ldvh-base/*/` 或 `ls -d` 打印，确认恰好一个候选再执行，目标一律写精确路径，需要批量移动时用 `mv -t <dir>` 明确指定目标；③ 例外——确实要把多个源移进一个目录时，目标必须是显式写出的单一目录，不得靠 glob 的最后一个匹配充当目标。

## 验证

已观察：误移的方向与规模（六个目录整体进入 `workcases/`）与根因（转述自引证原句：原因是 `mv "$f" ldvh-base/*/` 中的 glob 展开了多个目录，`mv` 会把最后一个当目标目录，前面全当源），均由操作者在同一段落的错误复盘里自述确认；引证与来源已原文复制于症状段。未覆盖：恢复动作的命令形态与回读结果、`"$f"` 与其余五个目录各自最终落点、以及其他 shell 与 `mv` 实现（含 `-t` 语义差异）下的表现；本条只有一次材料观察，不主张在所有破坏性命令上普遍成立。

## 影响与适用范围

适用于把 shell 通配符写在破坏性文件操作的目标位置（`mv`、`cp -r`、`rm -r` 等）、从而一次搬移或删除多个路径的场景；不适用于目标已写成精确路径、或执行前已打印确认过展开结果、只有单一候选的命令。

展开——何时可能踩到：整理目录、批量恢复被误移的文件、清理构建产物这类「用一条命令挪一堆东西」的操作，只要目标位置写成通配符就会踩到，`ldvh-base/*/` 这次即实例。经验何时可信：失败表现为「目标目录里多出成组目录、源位置成批缺失」且命令目标含通配符时，本条可信；若失败命令的目标是精确路径，或已先打印确认过展开结果仍出错，则应另找机制，不套用本条。
