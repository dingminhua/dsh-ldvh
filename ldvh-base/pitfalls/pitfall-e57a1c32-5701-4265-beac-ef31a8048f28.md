# 镜像未同步占位版致插件安装误报缺组合包

## 症状

从 DSH 插件管理页选择「中国大陆镜像源」安装 dsh-ldvh 时，安装失败并提示「这个包没有声明组合包，无法作为插件安装：dsh-ldvh declares no dsh.bundle」。同一时刻官方 registry 的 latest 为 1.0.0，其 manifest 明确含 dsh.bundle，用官方源取到的 tarball 内 bundle 声明齐全。

## 触发条件

插件发布后、镜像同步完成前的窗口内，用户从插件管理页选择中国大陆镜像源安装。该窗口不固定为「几小时」：本例正式版 1.0.0 于 17:01Z 发布、距占位版 0.0.0-stage 仅晚 4 分钟，而同步日志显示 delay: 53703176ms（约 14.9 小时），即发布后约 15 小时镜像仍只给占位版；故不得以发布时长排除本因，须先看 packument 实际状态。

## 根因

npmmirror（registry.npmmirror.com）对 npm 新发布版本的同步存在滞后：占位版 0.0.0-stage 已同步，而正式版 1.0.0 长时间未同步，镜像的 dist-tags.latest 仍指向占位版。占位版 manifest 的 dsh 字段为 null，没有 bundle 声明；插件管理页按所选安装源解析 spec，取到占位版后据此判定「没有声明组合包」。报错文案只带包名、不带安装源与版本，容易被误读成「包本身坏了」。

## 解决

先触发镜像同步：`PUT https://registry.npmmirror.com/-/package/dsh-ldvh/syncs`（body 为 `{}`；本例响应为 `{"ok":true,"id":"6afffd22cd986b27faa8f74b","type":"sync_package","state":"waiting"}`）。待同步日志出现 `Synced version 1.0.0 success` 与 tag 变更行 `🟢 Synced 1 tags: [{"action":"change","tag":"latest","version":"1.0.0"}]` 后重试安装；同步完成后 CDN 与 packument 刷新本例约 2–4 分钟（15:58:27 packument 仍为旧值、16:00:16 出现 1.0.0），以 packument 实际出现目标版本为准。也可临时把安装源切到官方 registry 直接安装。

## 规避

遇到「declares no dsh.bundle / 没有声明组合包」且该包发布不久（窗口可达十余小时，见触发条件），先 curl 对比官方与镜像的 packument（versions 与 dist-tags），再决定是等镜像同步还是换安装源。不要先怀疑或改动包本身。

## 验证

2026-11-20 主控完成如下验证链（来源：主控会话当日各时点实测，及 npmmirror 同步日志 https://registry.npmmirror.com/-/package/dsh-ldvh/syncs/6afffd22cd986b27faa8f74b/log）：

- 镜像 packument（15:54 实测）：versions 仅 `['0.0.0-stage']`、dist-tags.latest=0.0.0-stage、该 manifest `dsh=null`、description='Temporary package placeholder for staged publishing'
- 官方 packument（同时点）：dist-tags.latest=1.0.0、manifest `dsh.bundle={patch:'./cordis.patch.yml'}`
- `npm pack dsh-ldvh@1.0.0`（官方源）tarball 内 package.json 的 dsh.bundle 齐全
- 同步发起响应 `{"ok":true,"id":"6afffd22cd986b27faa8f74b","type":"sync_package","state":"waiting"}`；同步日志出现 'Synced version 1.0.0 success' 与 'Synced 1 tags: [{"action":"change","tag":"latest","version":"1.0.0"}]'
- 同步后镜像 packument versions=['0.0.0-stage','1.0.0']、latest=1.0.0；`npm view --registry=镜像` 返回 1.0.0
- 临时目录执行 `npm i dsh-ldvh@1.0.0 --registry=https://registry.npmmirror.com` 成功，装到 1.0.0 且 dsh.bundle 与 cordis.patch.yml 均在包内

未覆盖（与「验证过什么」同样必答）：

- 未在真实插件页复现「declares no dsh.bundle」报错，依据仅为用户提供的报错截图
- 未记录失败时所在的 profile/实例；desktop profile 已安装 dsh-ldvh（dev link），按插件管理器 inspect 流程应先报 already-installed，故截图中的失败大概率来自另一个未安装该包的 profile/实例，未核实
- 「同步前 versions 仅 ['0.0.0-stage']」现已无法复测，依据为 15:54–15:58 实测与同步日志 'versions 1 => 2' 的反推

## 影响与适用范围

本经验适用于任何 npm 已发布 DSH 插件在发布后短时间内经中国大陆镜像源安装的场景；若官方源同样报出「declares no dsh.bundle」，则不适用本经验，那说明包本身确实缺少 dsh.bundle 声明。此类误报不影响包的实际质量，按上述同步或换源即可正常安装。
