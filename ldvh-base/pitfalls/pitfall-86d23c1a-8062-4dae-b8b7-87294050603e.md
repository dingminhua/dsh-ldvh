# Git Gate 双向路径覆盖拦截

## 症状

git commit 时 commit-msg 钩子拒绝提交，报错形如 `validation/staged_path_uncovered: staged path "plugin/package.json" is not covered by any 关键变更 item`；预检工具 ldvh_precheck_git_commit 却可能先行通过（预检只校验「每个关键变更项匹配某个暂存路径」的半边，双向覆盖是 Git Gate 的完整规则）。

## 触发条件

提交消息的「关键变更:」小节中存在未包含任何暂存路径词的条目，同时暂存区包含未被任何条目覆盖的文件——典型场景：按语义分组写变更项（如「工具链落地」）而未点名 package.json/package-lock.json 等具体文件；或新增了与既有条目路径无关的暂存文件。

## 根因

K1 双向覆盖校验（并行线落地于 commit 07b9c25）：specs/06 §6.2 的提交契约要求关键变更项与暂存 diff **互相**覆盖——不仅每项要能机械对应到路径，每个暂存路径也要被某项覆盖。匹配规则（commit-validation.js 的 itemMatchesPath）：项含完整路径、文件名、去扩展名 stem、或无数字路径段（如 plugin/lib/spark-tools 的段 spark-tools）。

## 解决

在「关键变更:」对应条目中补入暂存路径的 stem 或路径段后重新提交；本例在工具链条目点名 package.json/package-lock.json 后通过。

## 规避

写提交消息时先 `git status --short` 列出全部暂存文件，逐文件核对是否已被某个「关键变更」项的路径词覆盖；多文件提交按文件域分组写条目并逐项点名 stem，不写无路径词的纯语义条目。

## 验证

修复后本仓库全部受控提交（19dcd7f 之后十余次）均通过 Git Gate；「路径词缺失→拦截→补词→通过」因果链在 2026-09-09 当日两次复现确认。未验证范围：非本仓库的其他 Git Gate 部署。

## 影响与适用范围

适用于本仓库全部经 Git Gate 的受控提交的提交消息撰写。
