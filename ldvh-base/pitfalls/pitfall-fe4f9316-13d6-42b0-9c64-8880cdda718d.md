# 正文自写 H1 与生成 H1 冲突致写入被拒

## 症状
向 spark 对象写入补记正文时，调用被拒，报错为 `spark/body_invalid: expected exactly 1 H1 heading, found 2`。去掉多写的 H1 后重试即通过，回读成功。

## 触发条件
按常规文档直觉给正文加了一个 `# 摩擦与经验的分诊边界与重复治理` 一级标题（与对象 title 同名），而该载体的 H1 由 Code 从 title 自动生成，正文必须从 H2 起，于是正文中出现第二个 H1。

## 根因
受控写入的载体结构校验按「正文恰好含 1 个 H1」判定，而 title 字段已被 Code 用于生成该 H1；撰写侧默认正文自带 H1，撰写侧与写入侧对 H1 归属的理解不一致，属于载体契约与撰写习惯的错位，而非偶发输入错误。

## 解决
删除正文中手写的 `#` 一级标题，把原本挂在该标题下的内容改挂在既有 H2 之下作为 H3 补记，重写后写入通过。

## 规避
向载体写入前先确认该载体的正文起始层级：H1 由 title 生成则正文一律从 H2 起；标题层级与 title 重复时改为引用式小节标题而非同名 H1。

## 验证
已观察：重写后的写入被接受，回读通过，正文呈 H2 段落 + 其下 H3 补记的结构；原文称「去掉 H1 后通过」且「回读通过」。未覆盖：同一载体再次写入时是否复现此拒绝、其它同类载体（norm/adr/工单）是否有相同的 H1 归属契约，本次材料未涉及。

## 影响与适用范围
影响与适用范围：仅见于 spark 载体的受控写入路径，触发面为「正文自写与 title 同名的一级标题」这一写法；当前观测样本为单次单载体，不足以判断其它载体类型是否同构。
