# 正文自写 H1 与生成 H1 冲突致写入被拒

## 症状
向 spark 对象写入补记正文时，调用被拒，报错为 `spark/body_invalid: expected exactly 1 H1 heading, found 2`。去掉多写的 H1 后重试即通过，回读成功。

## 触发条件
按常规文档直觉给正文加了一个 `# 摩擦与经验的分诊边界与重复治理` 一级标题（与对象 title 同名），而该载体的 H1 由 Code 从 title 自动生成，正文必须从 H2 起，于是正文中出现第二个 H1。

## 根因
受控写入的载体结构校验按「正文恰好含 1 个 H1」判定，而 title 字段已被 Code 用于生成该 H1；撰写侧默认正文自带 H1，撰写侧与写入侧对 H1 归属的理解不一致，属于载体契约与撰写习惯的错位，而非偶发输入错误。

## 解决
删除正文中手写的 `#` 一级标题，把原本挂在该标题下的内容改挂在既有 H2 之下作为 H3 补记，重写后写入通过。

## 规避
向载体写入前先确认该载体的正文起始层级：H1 由 title 生成则正文一律从 H2 起；标题层级与 title 重复时改为引用式小节标题而非同名 H1。

**已被规范源吸收（2026-10-28，Human 决定废止）**：本条规避已由 `specs/20` §8 承载——`:140`「正文结构（H1「# 标题」由 Code 从 title 生成、位于围栏后首行且恰好一个，正文自 H2 起……）」，强制落点在 §15 验证表 `:322`「H1 恰好一个且与 title 一致、正文自 H2 起……→ 拒绝创建/更新；修复后重走」。自该条款生效起，本条不再独立承担约束，仅作为该规则的来源引用保留（23 §6.3、35 §8.6 第 3 项）。

## 验证
已观察：重写后的写入被接受，回读通过，正文呈 H2 段落 + 其下 H3 补记的结构；原文称「去掉 H1 后通过」且「回读通过」。未覆盖：同一载体再次写入时是否复现此拒绝、其它同类载体（norm/adr/工单）是否有相同的 H1 归属契约，本次材料未涉及。

独立复现验证（2026-10-28，入档前置）：复现主体为隔离子代理（独立上下文，未参与本候选形成）；独立性边界为与形成者非同一执行主体、上下文隔离。复现做法与观察结果：在 /tmp 的插件副本上以单文件定向用例驱动真实工具面（`ldvh_spark_write`，action=update）——先以「`body_markdown_after` 自带与 title 同名的一级标题」写入，被拒且回显 `body: expected exactly 1 H1 heading, found 2`（实际 envelope 把候选所记的单串拆成两行 gaps），载体零写入；再以「H2 段落 + 其下 H3 补记」重写，写入通过、落盘文件仅 1 个 H1 且含 H3。复现未覆盖：同一载体再次写入是否复现该拒绝未观察；其它载体类型未实跑——静态核对显示 `plugin/lib/pitfall-writer.js`、`workcase-writer.js`、`goal-writer.js` 的写入侧同属「H1 由 title 生成、正文自 H2 起」契约，故本条 scope 的「仅见于 spark」只覆盖实跑观测样本，适用面是否更宽尚无实跑证据。


**机械化承载（2026-10-28 盘点）**：`plugin/lib/spark-writer.js:523-526` 的载体结构校验分支（正文 H1 计数必须恰为 1，否则报「body: expected exactly 1 H1 heading, found N」）＋ `plugin/test/spark-writer.test.mjs:1082/1104` 已把本条的规避实现为机械判据：多写一个同名 H1 即写入被拒且零落盘（去掉该计数分支后两例转红）。覆盖边界：同形分支在 `norm-writer.js:189`、`adr-writer.js:355`、`workcase-writer.js:1401` 上没有任何用例守护（去掉后相应套件仍全绿）。

## 影响与适用范围
影响与适用范围：仅见于 spark 载体的受控写入路径，触发面为「正文自写与 title 同名的一级标题」这一写法；当前观测样本为单次单载体，不足以判断其它载体类型是否同构。
