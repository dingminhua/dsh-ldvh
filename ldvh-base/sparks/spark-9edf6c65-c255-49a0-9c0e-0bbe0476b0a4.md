# 并行会话引导进入独立 worktree

## 当前理解

Human 2026-11-19 提出并行会话引导进独立 worktree、面向所有管辖项目。只读调研 report-e8112a5c 确认宿主 worktrees/create_worktree 为原生隔离能力；三坎未消：不复制在途改动、worktree 内 git 提交需沙箱授权、事实源分叉合并未定义。下一步先做受控可行性实验，不直接实现。

初始直觉"提醒建分支"经机制核实发现无效：普通 git branch 只换 HEAD、不隔离工作树。宿主实际提供的是会话级 Git worktree——`ctx.worktrees.create` 建独立 checkout 并经 `workingDirectory.set` 把会话 cwd 切进去（一手证据见 report-e8112a5c，refs 指向它）。三道坎展开：① worktree 从本地 commit 建、不复制 staged/unstaged/untracked/ignored 文件，而并发摩擦主形态恰是"在途未提交改动"，触发时机须早于改动产生且有残余边界；② workspace-write 下 worktree 内不能直接 git add/commit（Git 目录在 linked worktree 之外），须沙箱显式授权，否则隔离后无法受控提交；③ 多 worktree 各持一份 ldvh-base，事实源分叉合并/销账归属未定义，且分支载体纪律要求 main 树不含事实对象、worktree 须从 dev 建。

## 调查问题

对面向所有管辖项目的 LDVH，是否应在检测到多会话并行于同一工作树时引导会话进入独立 Git worktree，以及触发时机、隔离边界与事实源分叉的合并规则应如何界定？

## 调查边界

判明该隔离引导是否成立、触发时机与残余边界、worktree 内受控提交与管辖判定能否跑通、事实源分叉合并规则即停止；不含直接编码实现，也不在本 Spark 内判定该机制一定优于现有并发守卫（concurrent-write-guard 等）。
