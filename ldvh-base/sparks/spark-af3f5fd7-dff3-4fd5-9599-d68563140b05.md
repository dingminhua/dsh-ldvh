### 2026-11-02 重核（只读）：五缝清单已定且已逐缝消费，缺的是「能力面清单」这一产物形态

> 本节给出**当前**证据；上文是 2026-09-15 记录，未改写。

**`scope_boundary` 三要件逐项核**：

**①「绑定能力面清单确定」——已确定，且已入规范**。`specs/10` §6「宿主缝的消费义务」下有一张**五缝表**（第 168–172 行），逐缝写明「LVH 须做什么才算消费」与「未消费时不得主张什么」：

| 宿主缝 | 规范要求 |
|---|---|
| `ctx.tools.register` | 经该入口注册操作并接受参数校验 |
| `ctx.tools.guard` | 经该入口注册单调守卫；守卫**只能拒绝、不得放行** |
| `ctx.invariants.register` | 经该入口部署运行时不变量断言；违规经其 `fail` 通道报告 |
| `fs/observed` 读观察 | **两半都要**：读侧记录并发出观察；写侧经 `fs/write-intent`／`fs/edit-intent` 挂版本守卫 |
| `ctx.userQuestions.ask` | 经该入口承载 Human Gate 提请；须有**实际调用点**，未获肯定答复 fail-closed |

这张表就是「绑定能力面清单」的规范形态——它比上文所记的 `dsh-plugin-binding-plan.md` 那份 471 行候选更权威（后者已随 docs/ 删除），且**已生效**（`specs/10` 是现行规范）。

**②「各能力已落地或已明确不采用」——五缝全部有实现**：`grep -rl` 于 `plugin/lib/*.js` 得 `ctx.tools.register` 13 个文件、`ctx.tools.guard` 1 个、`invariants.register` 1 个、`fs/observed` 2 个、`ctx.userQuestions.ask` 8 个。`plugin/lib/host-seams.js:11-15` 的注释逐条列出这五缝并说明各自的契约形态（`tools.guard` 是同步 `(execution) => string | undefined`、`fs/observed` 是 emit 事件、观察侧记录监听侧镜像 `:197`）。即**五缝没有一条是「未采用」**。

**③「与当前实现一致」——一致，且规范明文把「现状」交给读取时观察**。`specs/10` 第 173 行：「各缝的**实际消费现状**按 01 §7.2 由读取时的观察与实现核对取得，本节不陈述其当前状态」——这是一条刻意的设计：规范不写「现在消费了哪几缝」（那会随实现漂移而失真），只写「消费的判据」。故「与当前实现一致」这一要件在规范层**无法也不应**被写成静态结论。

**故本条实质上已经达成，且是以比原设想更好的形态**：上文设想的产物是「一份绑定能力面清单文档」（`dsh-plugin-binding-plan.md`），而实际落地的是**规范条文 + 逐缝消费判据 + 实现对照**三件——清单被写进了 10 号而不是写进一份 docs 文档。这恰好符合 00 §3.2「docs/ 不是权威」的纪律。

**唯一仍需核的一处**：上文所记「§10 剩余未答项（Q1–Q4 的 Tab/Sidebar 注册冲突、Q7 热重载、Q8–Q10 Client/Host 边界、Q11–Q13 多 profile、Q16–Q17 发布）是否仍开放未逐项核」。这份 `investigation-report-dsh-subagent-default-model.md` 已随 `ec19ba6` 删除，**其 Q1–Q17 的原文已不可回查**；而 `plugin/` 结构（`CHANGELOG.md`／`LICENSE`／`README.en.md`／`README.md`／`cordis.patch.yml`／`eslint.config.js`／`icons`／`lib`／`package.json`／`scripts`／`test`／`web`）已完整，说明发布工程那几问（Q16–Q17）事实上已被实现回答。剩余 Q1–Q4／Q7–Q13 因原文不可回查，**无法逐项判定是否仍开放**——这一残留不影响「五缝已绑定」这一结论，但属凭据链断裂的如实登记。
