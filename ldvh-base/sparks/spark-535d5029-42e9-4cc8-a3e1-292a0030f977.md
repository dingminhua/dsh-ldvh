# 生命周期验证的 Windows 覆盖

## 当前理解

Windows 侧范围与验证已补齐：10 项生命周期验证真机全过（windows-lifecycle-verification.test.mjs），ACL 判据由无条件 fail-closed 改为 Get-Acl 真核验，结果写入 docs/governed-project-lifecycle-verification.md；UNC/junction/NTFS 占用等未覆盖项如实登记。

**收束依据（两轮，均为实测而非读码推断）**：

1. **范围侧已完整**：`specs/08` 有四段 Windows 条款（用户配置根须经宿主 API 解析、
   `path` 持久化的盘符/UNC 语义、ACL 继承与不可核验即 fail-closed、
   不硬编码三平台系统用户目录）。此判断在 2026-11-02 的重核中已立。
2. **验证侧已补齐**：10 项生命周期验证在 Windows 真机逐项执行并通过，承载用例
   `plugin/test/windows-lifecycle-verification.test.mjs`（`node --test` 可重复运行），
   结果逐项写入 `docs/governed-project-lifecycle-verification.md` 的「Windows 验证」节。
3. **顺带修出一处功能性缺陷**：`evaluateRegistrationEntry` 原在 `win32` 上**无条件**
   fail-closed，理由是「本实现没有 ACL 核验器」。该前提不成立——ACL 可读。其后果是
   CLI 登记入口在 Windows 上永久不可用，与 `specs/08 §5.6`「Windows 目标文件占用导致
   replace 失败时明确返回失败」（即预期可写）冲突。现已改为真核验。

**过程中被推翻的两个结论（如实保留，不抹去）**：

- 2026-09-12 记「Windows 范围章节未完成」——被 2026-11-02 重核推翻：范围其实已补齐，
  缺的只是验证。
- 2026-11-02 记「缺的是验证，须 Human 定『真机补跑』或『明确声明不做』」——2026-11-10
  真机补跑已完成，两个出口中走了前者，后者不再需要。

**该缺陷的第二轮修订**：首版用 `icacls` 文本解析 + 黑名单，经独立审核实测出四类问题，
其中「路径含空格」一种是 **fail-open**（`Everyone` 越界被放行，而 DSH 用户配置根位于
`C:\Users\<用户名>\AppData\Roaming`，用户名含空格即触发）。已重写为 `Get-Acl` 结构化
读取 + 白名单 + 目录/文件双检，四类从根消除，并补了行为级守卫与冻结工作区的变异检验。

**本单关闭过程本身的一处教训（2026-11-10，如实登记）**：首次尝试关闭时校验器只报
`summary` 超 200 字符，我却两次误归因——先断言「`recall_digest` 是规范未定义的非法
字段」（错：`spark-writer.js:90` 的闭集里明确列着它），再断言「宿主加载了旧代码」
（错：15:48 启动时点的版本同样含该字段）。两次都是拿**间接证据**替代**直接验证**——
一次是读规范正文而非代码闭集，一次是读进程启动时间而非跑一次校验。本地直接调用
`validateSparkFrontmatter` 后显示 ok:true、0 issues，证明代码侧并无问题；受控写入
一侧仍报同一 gap，属宿主模块与磁盘源码不一致，**重启宿主后消失**（本单最终得以关闭
即其证据）。教训：报错文本给定后就按它定位，不要绕过它去猜上游原因；若本地与宿主
结论冲突，先怀疑运行实例而非源码。

### 2026-11-02 重核（只读）：Windows 侧已有**明确的 fail-closed 处置**，但仍未写进验证记录

> 本节给出**当时**证据；上文已按 2026-11-10 的实测更新，本节保留为历史。

**实现侧已有 Windows 分支，且是有意的 fail-closed 而非静默通过**。`plugin/lib/governed-projects.js:469` 起：

```js
if (process.platform === "win32") {
  // 07 §5.6 Windows clause: inherit the DSH user-config ACL, never fake POSIX
  // mode; when the ACL cannot be verified the high-risk write must
  // fail-closed. This implementation has no ACL verifier, so the honest
  // outcome is `registration_permission_unverified` — NOT a silent pass.
  return unavailable(REGISTRATION_UNAVAILABLE_CODES.PERMISSION_UNVERIFIED, ...);
}
```

该分支注释明确引「08 §6 forbids」——即它是有意识地对规范条文的执行，不是遗漏。`PERMISSION_UNVERIFIED` 在 `:29` 登记为 `registration_permission_unverified`，Unix 侧另有 `:489` 的 `0700` 宽权限拒绝，两侧同构。

**规范侧已有 Windows 条款，共四段**：`specs/08` 第 90 行（用户配置根须经宿主 API 解析，macOS/Windows/Linux 均消费实际根目录）、第 123 行（`path` 持久化语义，**Windows 盘符与 UNC 路径允许 `C:/...`、`//server/share/...`，比较须遵循实际文件系统语义并解析 junction/symlink，不得用简单 lowercase 冒充规范化**）、第 163 行（**Windows 继承 DSH 用户配置目录 ACL，不伪造 POSIX mode、不扩大到其它用户，ACL 无法核验时高风险写入 fail-closed**；另记「Windows 目标文件占用导致 replace 失败时明确返回失败」）、第 275 行（不在实现中硬编码三平台系统用户目录）。

**当时的结论**：范围已补齐（四段条文），缺的是验证；`plugin/test/` 下没有任何 Windows 平台专属用例，且 `governed-projects.js:469` 的 win32 分支在 macOS 上不可达。完成度约 1.5/2。

### 2026-11-10 收束：验证已补齐（本节为终态依据）

- **10 项生命周期验证**在 Windows 真机全部通过，逐项结果见
  `docs/governed-project-lifecycle-verification.md`「Windows 验证」节的表格。
- **权限判据**已从「无条件拒绝」改为真核验，判据、边界与未覆盖项均在该文件内登记。
- **未覆盖项如实保留**：UNC 共享上的真实核验、junction、NTFS 占用竞争、ACL 读不到的
  构造场景、域环境主体。这些**不**构成收束的阻碍（`scope_boundary` 要求的是「范围明确
  且验证补齐或明确不覆盖」，两者均已达成），但**不得**据本条宣称 Windows 已完整验收。
