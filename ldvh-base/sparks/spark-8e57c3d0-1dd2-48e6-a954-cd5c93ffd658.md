# lint 结果未纳入机械守门

## 当前理解

受控提交的两个机械入口（precheck 与 Git Gate）与 CI 均不消费 lint——三处的 run 步骤与实现均无 eslint 调用，已逐一核实。2026-10-16 核对发现本条的初判需收窄：06 §5 第 118 行已规定「ESLint 统一配置，提交前必须通过静态分析」，§9.1 第 1 项更把「Lint 检查未通过」列为必停情形，该要求随 50bcf27（2026-10-09）落盘，早于本条创建（2026-10-14）5 天。故「lint 是否该纳入机械入口」在规范侧已有要求，缺的是承载而非依据；本条的问题因此由「纳入门禁／只作提示／不做入口 三选一」收窄为「已有要求由哪个入口承载」。仍成立的原始事实：判据面（plugin/eslint.config.js 的 files 面，即 lib/**/*.js、test/**/*.mjs、lib/bin.js）曾自带 6 处 eslint 错而无人发现，已由 15faa2a 清除（7 个文件全在 lib/ 下），现测该面 exit 0；另有 14 处落在配置面之外（scripts/backfill-spark-priority.mjs，13 no-undef + 1 no-unused-vars，因 files 未覆盖 scripts/**/*.mjs 且缺 node 全局），属覆盖面问题而非代码问题。**范围澄清**：web 面不在本条判据面内（该 config 第 21 行显式 ignores web/**），web 曾有的 18 处 lint 错已于 915208f 清除，与本条无关。

**核实方法（只读，未改动任何规范与实现）**：读取 06 §5 第 118 行、§9.1 第 1 项的原文；以 `git log -S` 定位该要求的落盘提交与日期；比对 `.github/workflows/ci.yml` 两个 job 的 run 步骤；只读核对 `plugin/lib/git-gate-runner.js` 与 `plugin/lib/commit-validation.js` 是否引用 eslint；实跑 `npx eslint lib test lib/bin.js`（exit 0）与 `npx eslint scripts/ -f json`（14 处）。

## 调查问题

06 §5 已规定「提交前必须通过静态分析」，该要求应由哪个机械入口承载，scripts/**/*.mjs 是否纳入其覆盖面？

**当前已答／未答**：已答——规范侧对「lint 必须通过」早有要求，故原问的三选一（纳入门禁／只作提示／不做入口）中「只作提示」与「不做入口」两选项已与 06 §5 及 §9.1 冲突，不再是开放选项；问题实质收窄为承载入口的选定。未答——该要求落到 precheck、Git Gate 还是 CI（三者当前均不消费 lint），以及 scripts/**/*.mjs 是否纳入覆盖面（现测该处 14 处未受检）。

## 调查边界

当「已有 lint 要求由哪个机械入口承载、其覆盖面是否含 scripts/」有结论时停止——本条不承接具体 eslint 规则的增删，也不承接历史 lint 债的清理（那部分已由 15faa2a 清完判据面），亦不承接 scripts/ 之外的工具链覆盖面扩张。

**本条的边界不含**：为落地该要求而实施的入口改造（属实现动作，方向定后另行处置）；也不含 web 面 lint 状况的跟踪（web 不在本条判据面内，见上）。

## 演变

- **2026-10-16**：按 06 §5／§9.1 的既有要求收窄问题焦点。原问「lint 是否该纳入机械入口（纳入门禁／只作提示／不做入口 三选一）」的前提不成立——规范侧早有「提交前必须通过静态分析」的要求（50bcf27，2026-10-09，早于本条创建 5 天），故问题收窄为「已有要求由哪个入口承载」；scripts/ 覆盖面一问保留。原 scope_boundary 的停止条件随之改写，非目标项（规则增删、历史债清理、scripts/ 之外的覆盖面扩张）不变。
