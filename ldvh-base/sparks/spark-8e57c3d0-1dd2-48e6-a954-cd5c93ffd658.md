# lint 结果未纳入机械守门

## 当前理解

已完成承载入口与覆盖面的判定。结论：06 §5「提交前必须通过静态分析」应由 Git Gate 承载——三候选中只有 commit-msg 阶段具备拒绝提交的出口，与 §10 验证表「未通过不提交」同构；CI 作兜底，因本地 hook 可被 --no-verify 绕过；precheck 不承载，其 06 §6.2 语义为只读预检，纳入 lint 会抬高每次预检成本却不产出「能否提交」的判定。scripts/**/*.mjs 应纳入且已纳入：plugin/eslint.config.js 的 files 面已含 scripts/**/*.mjs 并引入 node 全局，实测 eslint . 覆盖 138 个文件（scripts/ 3 个）、0 error 0 warning，本条曾经的 14 处已清零。本条不落实现改造，也不决定 lint 接入的工程细节（本地二进制、退出码判据、CI 同步、web 覆盖面）——那些属另立的实现事项。

**核实依据（只读实跑）**：读取 06 §5 第 118 行、§9.1 第 1 项、§10 静态分析验证行的原文；实测 plugin/eslint.config.js 的 files 面与实际受检文件集；实测三个候选入口的源码均无 eslint 调用（commit-validation.js 无引用、git-gate-runner.js 仅支持 git-commit-msg 一个命令、.github/workflows/ci.yml 两个 job 均无 lint 步骤）。

**边界外但已识别**：web/ 面被 eslint.config.js 第 21 行显式 ignores，故 web 代码不进本条判据面——若要求严格度覆盖前端，需另立覆盖面扩张事项。

## 调查问题

06 §5 已规定「提交前必须通过静态分析」，该要求应由哪个机械入口承载，scripts/**/*.mjs 是否纳入其覆盖面？

## 调查边界

当「已有 lint 要求由哪个机械入口承载、其覆盖面是否含 scripts/」有结论时停止——本条不承接具体 eslint 规则的增删，也不承接历史 lint 债的清理（那部分已由 15faa2a 清完判据面），亦不承接 scripts/ 之外的工具链覆盖面扩张。

## 演变

- **2026-10-16**：按 06 §5／§9.1 的既有要求收窄问题焦点。原问「lint 是否该纳入机械入口（纳入门禁／只作提示／不做入口 三选一）」的前提不成立——规范侧早有「提交前必须通过静态分析」的要求（50bcf27，2026-10-09，早于本条创建 5 天），故问题收窄为「已有要求由哪个入口承载」；scripts/ 覆盖面一问保留。原 scope_boundary 的停止条件随之改写，非目标项（规则增删、历史债清理、scripts/ 之外的覆盖面扩张）不变。
