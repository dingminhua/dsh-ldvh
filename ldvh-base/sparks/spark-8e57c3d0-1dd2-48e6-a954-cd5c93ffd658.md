# lint 结果未纳入机械守门

## 当前理解
受控提交的两个机械入口（precheck 与 Git Gate）只校验提交消息与候选 Index 的一致性，不跑 lint；因此 HEAD 曾自带 6 处 eslint 错（判据面 eslint.config.js 的 files 范围内）而无人发现。另有 14 处落在配置面之外（scripts/backfill-spark-priority.mjs 的 no-undef，因 files 未覆盖 scripts/**/*.mjs、缺 node 全局），属覆盖面问题而非代码问题。本条要问的是：lint 结果该由哪个机械入口消费、覆盖面该落到哪里。
