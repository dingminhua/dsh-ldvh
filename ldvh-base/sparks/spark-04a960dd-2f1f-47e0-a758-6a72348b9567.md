# 经验与摩擦代理分工按新定义修正

## 当前理解

现行定义（00 §4.5 代理辅助任务）：主控派生零上下文代理，只做三件事——判定出现了该记的东西、整理交出上下文材料、接收一行回执；判断责任不由主控承担、由机械校验保障。

- 经验侧：`pitfall-fact-type` 的 `delegate-draft` 明写代理「只起草，不写入经验目录、不取得授权或完成效力」；`entry-channels` 要求主控在同一动作内受控写入并写后精确回读；`context-supply` 要求材料全部由主控交付。
- 摩擦侧：`friction-settlement-system-foundation` 的 `discovery-trigger` 由主控当场发起并交出材料；`discovery-context` 界定材料；`discovery-closed-set` 规定一次派发内的动作（读账本判同源、写观察、攒三条晋升、补充级更新、写后回读、失败留痕）——读与写观察由发现段做，晋升与补充在同一次派发内机械收尾。

Human 2026-11-23 新定义：
- 经验：主控整理好上下文给代理 → 代理直接判断并落笔 → 是否成功告诉主控 → 主控转告 Human。
- 摩擦：主控整理好上下文给代理 → 代理操作、判断、落笔 → 是否成功告诉主控（→ 主控转告 Human）。

共同点：落笔权从主控移到代理，代理承担判断与写入，主控退化为「交材料 + 接收结果 + 转告 Human」。

## 调查问题

经验与摩擦两类辅助记录中，代理的职责边界与落笔权应如何按 Human 新定义修正？
