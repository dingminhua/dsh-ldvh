# federation 与 api 的 v4 残留收敛

## 当前理解

本议题已于 2026-10-18 查全并收敛。全部命中位置及实际后果：① federation.ts:142 的 activeWorkCases 原以 status === 'blocked' 计数——v5 状态闭集无该值，判据恒假，行为碰巧等于只数 open，但依据错误；② federation.ts:143 的 pendingDecisions 原以 phase ∈ {human_plan_confirming, human_closure_confirming} 判定——v5 对象无 phase 字段，恒为 0，两个 Human Gate 永不入账，是真实失真；③ cognition.ts:44 的 InboxKind 含 blocked_resolution，而 deriveInboxKind 无法产出该值是不可达分支；④ api.ts:483 收件箱类型与 CognitionCenter.tsx:93,122 同步残留，locales.ts 两条同源词条无人引用；⑤ api.ts:67 的 WorkCaseV5View 与 api.ts:438 的 ObjectDetail.summary 仍声明 phase?: string；⑥ locales.ts:311 的 source_phase 与 locales.ts:410 的 phase 词条是 v4 概念。

收敛方向（已落地）：v5 的生命周期位置唯一来源是 facts.ts 经 deriveWorkCaseV5View 派生的 group（pending_gate1 / awaiting_gate2 / executing / closed），
读取方不得按字段名自行重算——重算即第二套判据（09 §5 一致性纪律），这也正是原判据的病因。
影响面：联邦卡「推进中」「待决定」两个计数由恒值转为真实值；认知中心收件箱不再有不可达类型；api.ts 与词条表不再承认 v4 字段。
