# 过程引导的规则供给：三通道与漏判证据

## 当前理解

**方向（2026-11-22 Human 裁定后）**：运行期规则**只**来自运行时机制载体（`plugin-specs/`）；`specs/` **全面退为需求文档**（根决定），只承担需求记录，**不做格式检查、不走严格审核与机械校验**；L0–L4 分层读取入口一并撤除。严格性集中在载体侧：形态、条目可判定、体量、误伤量测、逐条变异取证、准入与独立审核。

**价值链四层**：价值层（对齐 Vibe ＋ 协调 Coding，`00 §1`）→ 动作层（七项业务系统，`00 §2.6`）→ 痕迹层（事实对象，`00 §2.4.2`）→ 供给层（规则文本，AI 据以判断）。

**三通道**：A 机器强制（能被代码检查的规则）｜B 常驻判断辅助（每回合注入）｜C 按需查证（工具按需读）。两条腿都要在：过程引导（当场行为）＋ 产出物治理（事后可核对）。

**【两类文本】**

| | 装什么 | 约束谁 | 地位 |

| **开发规范**（`specs/`，Markdown） | 需求与设计记录 | 人与开发中的 AI | 一般文档；不强制、不审 |
