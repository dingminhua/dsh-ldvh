# 启动引导对 specs/ 的悬空假定

## 当前理解

启动引导（governed 会话的规则读取指引）与三个读取入口此前硬性假定受辖项目根存在 `specs/`，而安装事务（specs/10 §6）只创建 `ldvh-base/` 与 Git hook，从不创建 `specs/`——受辖但非 LDVH 仓库的项目因此完全读不到规范语料：`read-specification-candidates/content` 报 unavailable，`discover-ldvh-capabilities` 因解析不到声明表而全量误报「不可用」。

已消解：specs/01 §10.3 修订为三级回退（项目根 `specs/` → 插件开发布局源仓库根 `specs/`，以根规范载体辨认 → 插件包内 `specs/`，prepack 复制），link 安装读源仓库目录、npm 安装读包内副本；信封 sources 如实标注实际应答方，membership evidence 对回退语料按「不适用」报告。规范修订见 commit 1f1b276，实现见 commit 8b9005b（测试 1534/1534、lint 干净、pack 实证 30 个语料文件入包且开发树无残留）。
