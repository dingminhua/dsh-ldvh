# 关键变更路径覆盖的宽松匹配

## 当前理解

Git Gate 的 K1 双向路径覆盖校验中，反向半边（每个非豁免暂存路径须被某条「关键变更」项覆盖）的匹配函数对路径做目录段回退：只要消息项含路径的任一目录段（如 plugin、web），该路径即算被覆盖。源码注释自认此为 known limitation，测试固化其为有意设计（为兼容 diffstat 式区域命名）。代价是同一目录下的范围外污染——典型为并行会话的 git add 落入共享 Index——不被拦下，实际已发生一次（32 个 plugin/web 文件被随同提交）。已确认的判断：①该回退是有意设计而非缺陷，故处置不是修 bug，而是权衡「收紧规则」与「如实登记代价」；②收紧会破坏 diffstat 式区域命名的既有用法与对应测试，代价收益尚未计算；③防御侧经验（Pitfall 86d23c1a）已记「提交时显式 pathspec」为必需措施，但那只降低发生率，不能使校验本身可依赖。未决：收紧到何种粒度（精确路径级匹配，或目录段词须整段匹配并排除通用词）；是否须在 specs/09 §5.3 或 specs/10 §6 如实登记该已知边界与代价；是否与同门议题 64754323（precheck 与 Git Gate 检查覆盖不一致）合并处置。

**为什么保留**：这是防自欺锚点（「关键变更」逐路径对应）在反向半边上的可绕过口子，已导致一次范围外内容被静默提交；且该隐患于 2026-09-10 已被记录，却在归档时被误判为已由 Spark 承载，至今无人承接。后续方向：判定「收紧匹配」与「如实登记代价」何者成本相当，并决定是否与同门议题 64754323 合并处置。

1. **收紧**——把匹配规则改为路径级判定（或保留目录段回退但限定为整段匹配并排除通用词），并相应更新测试与既有提交消息撰写惯例。**须同时更新两处诊断文案**（见机制细节末条），否则口径与实现再次分叉。
2. **登记**——不改正向行为，转而在规范侧（候选落点 `specs/09` §5.3 或 `specs/10` §6）如实登记该已知边界与代价，使「校验能覆盖什么、不能覆盖什么」不被过度主张。
3. **不适用**——经 Human 判定该类宽松匹配对本管辖区不构成须处置的问题，给出理由后停止。
