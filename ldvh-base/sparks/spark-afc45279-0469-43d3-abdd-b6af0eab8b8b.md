# docs 过程文档的时效纪律

## 当前理解

docs/ 过程文档治理已成熟：法律地位已定论（01 §9.1 候选路径不含 docs/、01 §4 明文排除；00 §3.2 未经受控写入不成为稳定事实），分类表以「效力」为轴（A review-* 43 份为 01 §12 规范效力溯源证据必须保留、B/C 唯一记录、E 类 15 份唯一建议归档），三轮归档全部 git mv 零删除。**缺口：分类轴无「时效」维**——只答「该不该留」，未答「引用对象是否仍存在」。本轮撞到三处：① RELEASING.md 要求核对「Python 核心」但仓库已无 .py；② 同文件要求核对 plugin/screenshots.json 但该文件不存在；③ ldvh-plugin-implementation-plan.md 引用 docs/dsh-current-version-and-market-gap.md 但该文已归档。归档处理「已被取代」，本缺口处理「引用落空」，现行机制只能人工事后发现。外部实践（AI-first 项目拆 docs 路由、RFC→ADR、控制 spec 长度）多在「怎么组织」层，LDVH 已到「效力归属」层，但未覆盖引用时效性。

补充细节（承上）：

**现有治理的四份产物**：`docs-cleanup-assessment.md`（法律地位与分层原则）、`docs-cleanup-retention-table.md`（逐份 A–G 对照表）、`archive/README.md`（原 docs 目录，已随 `ec19ba6` 清除、可自该提交回取）（三轮归档索引与纪律）、`docs-to-spark-census.md`（过程文档 → Spark 转入普查）。规模：根约 75 份 + `archive/` 约 52 份。

**规范地位的两条依据**：`01 §9.1` 候选路径只含 `specs/` 与 `specs/attachments/`；`01 §4` 明写「本规范不把 `docs/`、`archive/`、Code、tests、缓存、索引、聊天、评审结论或工具输出转化为规范源」。故 `docs/` 无规范效力，清理不触犯受保护内容程序，也不走规范退出流程。

**分类轴是「效力」而非「重要性」**：A 类 `review-*`（43 份）必须保留的理由不是「有用」，而是它们是 `01 §12` 规范独立对抗审核的效力溯源证据——「规范经过审核」这一事实只能由报告承载，删则溯源断裂（同 `00 §5.6` 防自欺逻辑）。

**三处实例的性质**：① 与 ③ 是「引用落空」（指向不存在的对象）；② 是「引用悬空」（对象尚未建立）。三者与「已被取代」的归档不同——归档时对象仍在，只是过时。

**查重结论**：对照全部 33 个 Spark（含 open 与终态），无同主题对象。最近邻 `351a0b17`（ADR → Norm 转向）与本对象相邻——都涉「对象退出后的引用处理」，但前者管 ADR 退休的规范闭合，后者管 `docs/` 文档引用的时效失真，主语与责任面不同。

### 2026-11-02 重核（只读）：规模已实测（真·落空仅 6 处），且「引用落空」已有机械门禁

> 本节给出**当前**证据；上文是 2026-10-28 记录，未改写。

**待决问题 1「规模」——已实测，答案是「极小」**。`docs/` 现状（2026-11-02）：根 7 个文件（6 份 markdown + `workcase-996e207a-census.py`）、`archived/` 4 份 markdown，**合计 10 份 md**。用正则提取全部反引号包裹的代码/文档路径引用得 **75 处**；逐处核对存在性（先按原路径、再按 `docs/` 前缀、最后按全仓 basename 回退——后者用于排除「路径写法不精确但对象确实存在」的假阳性）后，**真·落空引用仅 6 处、去重后 4 个目标**：

| 落空目标 | 出处 |
|---|---|

**「引用落空」这一半其实已有机械门禁，且已生效**。`specs/09` §5.3 第 5 项（Human 指示 2026-10-12）已落为规则 `validation/docs_reference_dangling`（`plugin/lib/commit-validation.js:87` 登记，`severity: "blocking"`），实现函数 `checkDocsReferences(carriers, { exists })` 在 `plugin/lib/commit-validation.js:367`。它做的事正是本条所问的「引用落空」检测：

```js
const preexisting = new Set(extractDocsReferences(carrier.baseline));
for (const ref of extractDocsReferences(carrier.content)) {
  if (preexisting.has(ref)) continue; // old reference: cleaned up gradually
  if (resolveExists(ref)) continue;   // live target: not a violation
  issues.push(newFinding("validation/docs_reference_dangling", ...));
}
```

**但它有三条边界，恰好把本条问的情形排除在外**：① **只查新增**（`preexisting` 命中即跳过），`specs/09` 第 133 行明文「本项只阻止**新增**引用，不追溯存量」；② **只查规范载体与事实载体**（`isSpecOrFactCarrierPath`，即 `specs/**`、`ldvh-base/**` 与根 `README.md`），**`docs/` 自身内的载体互引不检**（`specs/09` 第 126 行明写「该目录本就是临时的」）；③ 不查「引用悬空」（对象尚未建立）。

**故本条的缺口性质要据实修正**：上文说「现行机制只能人工事后发现」，现在**不准确**——规范载体与事实载体中的**新增**落空引用会被机械阻断；真正无机械承载的是 **`docs/` 内部互引的落空**（本次实测的 6 处全部属此类），以及**存量**落空。这两类恰好都是 `specs/09` 刻意排除的（理由：该目录本就是临时的，其内部互引不构成权威主张）。

**待决问题 2「分类轴」——规模已给出答案**。`scope_boundary` 末尾明文允许：「扫描结论若显示规模极小（如仅本轮这三处），正确结论可能是「不值得立规则，补一条惯例即可」——本对象允许以「不成体系、不立规范」为落点」。实测 6 处（去重 4 个目标）与「本轮这三处」同一量级，且全部落在 `docs/` 内部互引——一个**已被 09 号明文声明为不检**的范围内。故按本条自身预设的判据，**正确结论倾向「不成体系、不立规范」**。

**仍须 Human 定的两点**：① 是否接受「`docs/` 内部互引落空不设机械门禁」——若接受，本条可按 `scope_boundary` 的「不成体系」出口收束；② 若判「仍要一条惯例」，其承载只能是原 docs 归档子目录 README 的既有纪律追加一条（不新增规范章），因为规模不支持新立章节。两点都是取向判断，AI 不代定。

## 调查问题

docs/ 过程文档引用了已不存在或从未存在的对象时，应采用何种纪律发现、标注与处置？

**待决的具体问题**：

1. **规模**——这类失效引用在 `docs/`（根 + archive 合计约 127 份）中实际有多少处？未扫描前不得假设其规模。
2. **分类轴**——是否需要在现有「效力」轴之外增设「时效」轴，形成二维分类？还是仅在 `archive/README.md`（原 docs 目录，已随 `ec19ba6` 清除、可自该提交回取） 的既有纪律上追加一条？
3. **承载形态**——该纪律应走 Norm（`8` 或 `7` 方向）、并入既有 `docs/` 治理文档、还是作为一条惯例先试运行？
4. **发现机制**——能否机械化？「被引用的路径是否存在」可机械核查；但「被引用的语义是否仍成立」不能。
5. **与归档的关系**——归档后引用的处置是「就地改指向 archive 路径」还是「标注为已归档」？两者对读者含义不同。
6. **失效与失实是否同题**——「引用落空」（指向不存在的对象）与「内容失实」（对象存在但说法已错，如「Python 核心」）是同一纪律还是两条？本轮三处实例中二者各占其半，须先判是否合并。

## 调查边界

完成一次 docs/（根 + archive）失效引用的真实扫描并得出规模，且就「是否成体系、应走何种承载、发现机制可机械化到何种程度」形成结论并交 Human 裁定后停止。不含 docs/ 物理重组、不含既有 A–G 分类表重裁、不含 specs/ 内部引用一致性、不含归档动作执行。

边界说明：本对象边界是「**纪律的确立与否**」，不是「完成清理」——`docs/` 物理重组（如改分目录路由）的收益与迁移成本须另行判定；`specs/` 内部的引用一致性属元规范维护；归档动作本身的执行不在本对象内。扫描结论若显示规模极小（如仅本轮这三处），正确结论可能是「不值得立规则，补一条惯例即可」——本对象允许以「不成体系、不立规范」为落点，不得为交付而制造规范（`27 §5` 成体系判据、`01 §11.4` 来源先行）。
