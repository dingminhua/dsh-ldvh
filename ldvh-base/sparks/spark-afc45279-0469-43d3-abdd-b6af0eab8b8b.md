# docs 过程文档的时效纪律

## 当前理解

docs/ 过程文档治理已成熟：法律地位已定论（01 §9.1 候选路径不含 docs/、§84 明文排除；00 §3.3 未经受控写入不成为稳定事实），分类表以「效力」为轴（A review-* 43 份为 01 §12 规范效力溯源证据必须保留、B/C 唯一记录、E 类 15 份唯一建议归档），三轮归档全部 git mv 零删除。**缺口：分类轴无「时效」维**——只答「该不该留」，未答「引用对象是否仍存在」。本轮撞到三处：① RELEASING.md 要求核对「Python 核心」但仓库已无 .py；② 同文件要求核对 plugin/screenshots.json 但该文件不存在；③ ldvh-plugin-implementation-plan.md 引用 docs/dsh-current-version-and-market-gap.md 但该文已归档。归档处理「已被取代」，本缺口处理「引用落空」，现行机制只能人工事后发现。外部实践（AI-first 项目拆 docs 路由、RFC→ADR、控制 spec 长度）多在「怎么组织」层，LDVH 已到「效力归属」层，但未覆盖引用时效性。

补充细节（承上）：

**现有治理的四份产物**：`docs-cleanup-assessment.md`（法律地位与分层原则）、`docs-cleanup-retention-table.md`（逐份 A–G 对照表）、`docs/archive/README.md`（三轮归档索引与纪律）、`docs-to-spark-census.md`（过程文档 → Spark 转入普查）。规模：根约 75 份 + `archive/` 约 52 份。

**规范地位的两条依据**：`01 §9.1` 候选路径只含 `specs/` 与 `specs/attachments/`；`01 §84` 明写「本规范不把 `docs/`、`archive/`、Code、tests、缓存、索引、聊天、评审结论或工具输出转化为规范源」。故 `docs/` 无规范效力，清理不触犯受保护内容程序，也不走规范退出流程。

**分类轴是「效力」而非「重要性」**：A 类 `review-*`（43 份）必须保留的理由不是「有用」，而是它们是 `01 §12` 规范独立对抗审核的效力溯源证据——「规范经过审核」这一事实只能由报告承载，删则溯源断裂（同 `00 §7.1` 防自欺逻辑）。

**三处实例的性质**：① 与 ③ 是「引用落空」（指向不存在的对象）；② 是「引用悬空」（对象尚未建立）。三者与「已被取代」的归档不同——归档时对象仍在，只是过时。

**查重结论**：对照全部 33 个 Spark（含 open 与终态），无同主题对象。最近邻 `351a0b17`（ADR → Norm 转向）与本对象相邻——都涉「对象退出后的引用处理」，但前者管 ADR 退休的规范闭合，后者管 `docs/` 文档引用的时效失真，主语与责任面不同。

## 调查问题

docs/ 过程文档引用了已不存在或从未存在的对象时，应采用何种纪律发现、标注与处置？

**待决的具体问题**：

1. **规模**——这类失效引用在 `docs/`（根 + archive 合计约 127 份）中实际有多少处？未扫描前不得假设其规模。
2. **分类轴**——是否需要在现有「效力」轴之外增设「时效」轴，形成二维分类？还是仅在 `docs/archive/README.md` 的既有纪律上追加一条？
3. **承载形态**——该纪律应走 Norm（`8` 或 `7` 方向）、并入既有 `docs/` 治理文档、还是作为一条惯例先试运行？
4. **发现机制**——能否机械化？「被引用的路径是否存在」可机械核查；但「被引用的语义是否仍成立」不能。
5. **与归档的关系**——归档后引用的处置是「就地改指向 archive 路径」还是「标注为已归档」？两者对读者含义不同。
6. **失效与失实是否同题**——「引用落空」（指向不存在的对象）与「内容失实」（对象存在但说法已错，如「Python 核心」）是同一纪律还是两条？本轮三处实例中二者各占其半，须先判是否合并。

## 调查边界

完成一次 docs/（根 + archive）失效引用的真实扫描并得出规模，且就「是否成体系、应走何种承载、发现机制可机械化到何种程度」形成结论并交 Human 裁定后停止。不含 docs/ 物理重组、不含既有 A–G 分类表重裁、不含 specs/ 内部引用一致性、不含归档动作执行。

边界说明：本对象边界是「**纪律的确立与否**」，不是「完成清理」——`docs/` 物理重组（如改分目录路由）的收益与迁移成本须另行判定；`specs/` 内部的引用一致性属元规范维护；归档动作本身的执行不在本对象内。扫描结论若显示规模极小（如仅本轮这三处），正确结论可能是「不值得立规则，补一条惯例即可」——本对象允许以「不成体系、不立规范」为落点，不得为交付而制造规范（`27 §5` 成体系判据、`01 §11.4` 来源先行）。
