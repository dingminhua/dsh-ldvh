## 当前理解

五项归宿已全部经 Human 决定（2026-11-04 第二轮裁定）：①先例回流与④提交↔记录联动拒绝；②影响闸门与⑤量化治理习惯拒绝（接受现状、不额外要求——② 不增设影响面机械闸门，⑤ 不改 00 §5.6，因 §5.6 既有「声明超过依据支持范围本身即不允许」已覆盖「宣称改善却无实测」，未测而称改善按现行条文已属违规）；③丢弃可数化要做，范围限受控写入的拒绝，四条验收判据已备，待经建单路由取得 Human 选择后建 WorkCase 实施。至此五项均有归宿，本条按 20 §9.1「已把后续责任交给 WorkCase」转 implemented。

### 原始记录（2026-09-15，照录不改）

Utopia 调研（research-6ba53f52）核对 LDVH 现状后确认五个机制吸收候选：①先例回流——人工纠正 AI 提案的理由进本地层记忆并成为同类提案的装配召回义务（落 35 号修订评审）；②影响闸门——受控写入前机械计算影响面（supersede 对象数、被引用关系数、受保护文档触碰），超线自动升级 Human 确认（落 00/03）；③丢弃可数化——Git Gate 预检与受控写入的拒绝按原因码累积计数，攒到阈值自动生成摩擦入账提议，为 26 号账本补上机械出生传感器（衔接 35 号 §10.3）；④提交↔记录联动——提交 message 关联 object_uid 并机械同步 ADR 状态行，顺带解决 35 号附录 A.5 消费信号开放问题（落 06/22）；⑤量化治理习惯——规范实质修订附执行基线前后对比（落 00 §7 防自欺实践）。另有六项判定为已等价或不适用（双时态、三态证据、写入时闸门、叙事化命名、两阶段 ready、推理物化），不重开。

五项候选展开（依据均为调研对象的发现单元与 utopia 决策记录，Human 已确认逐步吸收，各条独立可承接）：

**① 先例回流**（utopia 0025/0026；调研 F8）
- utopia 做法：人工裁决的 rationale 从每个决定路径入台账，治理任务把先例拉进裁决 prompt；模型自己的 why 保留在机器决策旁；README「decisions people make there are recorded and used to tune the agent, closing the loop」。
- LDVH 现状：35 号有双路召回与反思机制（生命周期事件触发的修订意见），无「Human 纠正 AI 提案的理由 → 同类提案强制召回」闭环。
- 落点：35 号修订评审——拒绝/修改理由进本地层记忆（新类别或既有类别扩展）+ 提案装配时召回义务。成本最高（跨记忆语义 + 装配义务）；与 open Spark b8cd2268（LDVH 记忆系统）同向，承接时先对齐。

**② 影响闸门**（utopia 0027/0028；调研 F8）
- utopia 做法：自动合并前问 execution_gate——会开一致性矛盾、有推导依赖、被答案引用过的，一律升级人工（escalate_impact），无视置信度；裁决者先带 consequences 工具查后果再看（0028）。
- LDVH 现状：Human Gate 按 00 §4.2 重大取舍清单定性触发，无影响面机械计算。
- 落点：00/03 受控写入——预检增加机械影响面信号（本次写入将 supersede 几个对象、被几条关系引用、是否触碰受保护文档），超阈值自动升级 Human 确认。成本中：CLI/Code 扩展 + 00 §4.2 清单的具体化。

**③ 丢弃可数化**（utopia extraction_drops；调研 F4）
- utopia 做法：11 类抽取丢弃原因全部落表、UI 可数可看（「attr_domain_mismatch 最昂贵」这类失败模式成为可趋势化数据）。
- LDVH 现状：26 号定义了摩擦账本但出生路径宿主机制留白（26 §3.2）；35 号 §10.3 空闲评审有摩擦入账提议（语义判断）；Git Gate 预检与受控写入的拒绝目前即时报错、不累积。
- 落点：拒绝原因码计数台账 → 阈值触发自动摩擦入账提议，与 35 号 §10.3 空闲评审提议路衔接。成本低-中：机械计数器 + 接线。

**④ 提交↔记录联动**（utopia decisions README；调研 F6）
- utopia 做法：「The PR that implements a record updates its status line」——从三次状态行滞后于代码的教训长出。
- LDVH 现状：ADR 语义变更已走新对象替代（22 号，等价半边）；提交与 ADR/事实对象状态行无机械联动；35 号附录 A.5 已登记「Git 提交 message 引用 object_uid 作为消费信号」开放问题。
- 落点：06 Git Gate 消息模板加「关联对象」字段 + 状态行同步机械校验；同一改动顺带解决 A.5 消费信号来源。成本低：Git Gate 扩展；与 open Spark cdc8bf7d（关系机制：证据与消费召回）相接，承接时对齐。

**⑤ 量化治理习惯**（utopia 0012；调研 F5）
- utopia 做法：每轮治理改动都带实测数字（签名违规率 57%→35%→4%、真反转 39→0），bench 每次全新库防污染。
- LDVH 现状：规范修订不附执行基线。
- 落点：00 §7 防自欺的实践具体化——规范实质修订时对执行指标前后各测一次（如 precheck 拒绝率、Stop Condition 触发率）。成本最低：习惯层，不强改规范。

**不吸收（已等价/不适用，防为吸收而吸收）**：双时态 facts（↔ CAS+change_log+retired，载体不同）、三态证据与空值显式（↔ confirmed/uncertain/gaps）、写入时签名闸门（↔ 受控写入+Git Gate；utopia 57%→4% 为此路线的量化旁证）、叙事化命名与迁移即文档（↔ 规范命名+Pitfall）、两阶段 ready（LDVH 无长流水线场景）、本体推理物化与 Ontology2SQL（产品能力非治理机制）。重开条件：仅当后续新证据出现。

**号位注记（2026-10-14，批次 G 号位对照）**：本节全部为 2026-09-15 的时点记录，照录不改；其号位按现行对照读：①「35 号」（记忆与反思系统）现为 `specs/32-记忆存取系统规范.md`；②、③中「00 §7 防自欺」的对应条款现为 `specs/00-理念与构成.md` §5.6「据实声明」；④「06 Git Gate 消息模板」的对应契约现为 `specs/09-受控提交与机械守护规范.md` §5（受控提交契约）与 §5.5（Git Gate）；「落 00/03」「00/03 议程」中的 03 号（事实模型）现为 `specs/02-事实源与事实模型基础规范.md`；⑤「00 §4.2 重大取舍清单」现行有效（Human Gate 与根决定清单）。26/22 号位与调研对象号未随重构变动。

**③ 丢弃可数化——建议吸收，落点重定（新落点优于原定）**。原落点（35 §10.3 / 附录 A.5）已不存在，但 `26 §3.2` 明文把「摩擦发现的宿主机制」划归 **11 号 §9 摩擦发现**（2026-10-28 边界澄清），而 `11 §9` 的双层机制（发现层写缓冲、审核层按 `group` 相等比较达 N=3 晋升）**完全依赖语义查重**——这正是 `26 §3.2` 风险登记里的「阈值误判：语义查重的误判会虚增计数」。③ 的价值是补一条**纯机械、可复算、无学习参数**的出生传感器，与语义查重**互补而非替代**，满足 `02 §9` 确定性红线。实现可行性比原判断更乐观：原因码**已存在且结构良好**（`invalid_request` 出现 110 处、`friction/frontmatter_invalid`、`specs/header_invalid`、`facts/carrier_uid_duplicate` 等，形态为「类型/具体原因」，天然可聚合），缺的只是**累加器**。**三条必须写进承接对象的边界**：(a) **机械计数不得直接写 Friction 账本**——`26 §9.2` 明文「机械通道只作用于观察缓冲与『缓冲晋升为 open』，不作用于任何已存在的账目状态」；正确形态是「计数攒够 → 写一条 `pending` 缓冲条目 → 走 11 §9 既有晋升路径」，接现成管道、不新增写入面；(b) **阈值沿用既有的 N=3，不得另定**——`11 §9` 已把 N 固定内嵌，风险登记写明「阈值 N 固定为 3 后，判定的敏感度随该常量确定」；引入第二个阈值会造成两套攒账口径互相矛盾；(c) **`attribution` 必须随条目写入**——`11 §7.1` 把 `attribution`／`attribution_ref` 纳入账本投影的理由原文是「执行体拿不到归因，按根源查重在机制上不可执行」，且 `26 §6.2` 的查重锚是「归因 + 机制模式」而非字面相似。

**④ 提交↔记录联动——建议两半均拒绝，理由不同**。(a) **提交 message 关联 object_uid**：`09 §5.1` 末段现行原文「这一面只作软约定、不作强制条款——本节不因它新增任何可拒收的 message 约束，`precheck-git-commit` 与 Git Gate 也**不校验**指称形态」，且 `02 §9.3` 第 6 项写明该面「没有可判定的判据」；这是 **Human 2026-10-18 决定二 C** 的明确裁定，改成强制等于推翻它，不能由本条候选自动推进。(b) **状态行机械同步**：utopia 场景是「PR 实现记录 → 改状态行」，而 LDVH 的 `22` 号规定 ADR 语义变更**走新对象替代**（`superseded-by`），旧对象转 `retired` 是终态只读——结构上不可能出现「代码改了但状态行还旧」，故 ④b **在 LDVH 里没有独立可吸收的内核**，照搬会造出一个不存在的动作。建议在 disposition 写「已由 22 §9 的对象替代语义在结构上覆盖」。

**⑤ 量化治理习惯——建议吸收（最该做的一项）**。落点存活：原「00 §7 防自欺」现为 `00 §5.6 据实声明`，其现有表述「有几分证据，说几分话」「声明超过依据支持范围本身即不允许」**已是纪律但缺「量化」这一层**。**建议的窄形态**：在 `00 §5.6` 补一句——规范实质修订时，若该规范有可观察的执行指标（拒绝率、触发率、误判率），须附修订前后对比；无可观察指标时须声明「本条无可量化执行指标」。三条优点：(a) 零机械成本，纯书写纪律；(b) 直接服务 §5.6 既有目标（防「声称改进但无证据」）；(c) 边界自带——无指标时声明即可，不逼人伪造数字。**真实成本在流程不在分析**：`00` 是**受保护文档**（`00 §4.3`），改它须「先展示现有内容与准确候选、说明差异与原因、经过独立审核并取得 Human 明确同意，且形成只包含相应受保护文档的独立提交」；`09 §5.6` 另规定「在实现与验证实际完成之前，触及受保护文档的 Merge 必须暂停，不得声称 Merge 闭环成立」。

**建议处置顺序（按归宿明确度 × 成本）**：1) **⑤ 吸收**（零成本但走受保护文档流程，收益最直接）；2) **① ④ 拒绝**（论证已足、不需实现——两项一拒，未决项从 5 降到 2）；3) **③ 吸收**（成本低-中，落点已重定清楚，注意上述三条边界）；4) **② 保留待承接**（须 Human 先定阈值，是唯一真正需要新决策的一项）。按此处置，本条可在 ② 有归宿后转 `implemented`。

**本节未核实的范围（据实声明）**：(a) utopia 侧证据**全部转引**——本文所有 utopia 依据引自 `research-6ba53f52` 的既有结论，未回 GitHub 复核，该调研自身已登记「治理链与 chat runner 实现细节未逐行验证」；(b) ③ 的原因码分布是**静态统计**——`invalid_request` 110 处等数字是 `grep` 数出的**出现处数**，不等于**运行期拒绝次数**，真实频率需埋点；(c) ② 的**实现成本未评估**——只核了数据源存在，未核在 `02 §10.1` 增加披露段的具体改动量；(d) **三个阈值一律未定**——③ 的计数阈值、② 的影响面阈值均未给数值，那属 Human 决定，不属分析结论。

**③ 的验收判据（拟用于 WorkCase 的 done_criteria，四项均可机械判定）**：

1. 构造同一「类型前缀 + 原因码」的三次连续拒绝，断言缓冲内产生**一条** `pending` 条目、其 `pending_count` 为 3、且该条目携带 `attribution`；

3. 断言全程**零** Friction 账本写入（以账目总数不变为判据，不得以「计数器已有值」代替）；
4. 断言该 `pending` 条目可被 `11 §9` 既有晋升路径消费——即它不是一条 `group` 无法匹配、永远晋升不了的孤立条目。

**③ 的一处语义陷阱（须写进承接对象，否则计错）**：受控写入的拒绝中，`invalid_request` 占绝对多数（静态统计 110 处），而它混装了**十几种语义完全不同**的失败。此类拒绝未必是「摩擦」——它是「调用方传错参数、改一下再传」。若把整族 `invalid_request` 笼统并入一个 `group`，会把无关失败攒成一笔账。故 `group` 键**必须细到「类型前缀 + 具体原因码」**，且 `invalid_request` 一族在聚合前须逐个审视其语义边界；本机制**不得**以「全部 `invalid_request` 归一个 group」实现。
