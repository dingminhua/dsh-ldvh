# 主控未主动发起经验/摩擦的成因诊断

## 当前理解

取证出主控未主动发起的四层成因：①触发是语义判断、无机械提示位，全靠当次自觉；②主控把scope收敛为完成字面要求，三次时机全由Human点破；③被触发后挑材料仍弱（摩擦归因污染）；④00 §4.5刻意不让主控为记漏负责，机械层只保执行链、不保发起。与spark-78a0b250同源不同焦点，用refs关联。

四层成因逐条展开（现场取证，均可回指）：

1. **直接原因**：触发是语义判断、没有机械提示位。每回合的引导（guidance-text.js 第 56 行）只写「主控在当次行动中发现…时」，「发现」完全靠自觉；spark-78a0b250 也记着「触发靠主控当场自觉、无机械提示位，产物稀疏」。本次会话主控从未自主做出过「出现了该记的东西」这个判断。
2. **判断层**：主控把每轮 scope 收敛成「完成用户字面要求」（第1轮测试→仿真，第2轮讲概念→讲概念，第3轮派代理→才真派），从没退一步问「这轮有没有值得留的经验/摩擦」。三次可触发时机（仿真冒充实测、经验/摩擦概念混淆、并发改动干扰提交）全由用户先点破。
3. **执行层**：即便被指令触发，主控挑选材料那一步仍弱——给摩擦代理的材料把第 2 轮「概念区分」误算进「交付不匹配」的同源证据（归因污染），正是 25 §13 登记的「主控挑材料能力直接决定记录质量」代价的现场复现。
4. **设计边界**：00 §4.5 把这两类动作定义为判断责任不由主控承担的「代理辅助任务」，并明确故意不让主控为「记漏」负责（记漏取决于当次是否恰好察觉，不可穷举、也不可事后核对）。故没有机械兜底，可靠性全压在「当次自觉」这个软约束上；机械层只保障执行链（授权、署名、回读、阈值晋升），不保障「会不会发起」。

与 spark-78a0b250 同源但不同焦点：后者问触发机制如何稳定/可观测且不落入定时驱动（前瞻的机制设计），本条问失效成因（回溯诊断），用 refs 关联以免断链。用户已表示本方向后续由自己处理。
