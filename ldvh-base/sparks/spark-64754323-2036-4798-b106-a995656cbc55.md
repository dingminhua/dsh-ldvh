# Git Gate 的 fail-open 通路

## 当前理解

`restructure-decision-list` §1 硬事实 #5：precheck 跑 `validateMessage + checkKeyChangesAgainstDiff + checkSignatureAgainstRoute`（三值 `passed/failed/unverifiable`）；`git-gate-runner.js` 只跑前两者（exit 0/1），**不查签名取值来源**。而 `06 §6.1` 要求「precheck 与 Git Gate 机械检查两行 trailer 的存在、**取值来源**和候选一致性」→ 存在 **fail-open 通路**。硬事实 #6：`06 §6.3` 原文「不含上述内容的普通提交在 hook 中直接放行」，即规范按内容分派，而实现无分派、检查全部提交。核验位置：plugin/lib/ldvh-tools.js:352-374、git-gate-runner.js:29-38。**并入项**：`restructure-decision-list` §2 已定项 A 的「修复事实 #5 的 fail-open」。

（来源：docs/restructure-decision-list-2026-09-10.md §1 #5/#6、§2 定项 A）

## 调查问题

precheck 与 Git Gate 的检查覆盖不一致（签名取值来源未查）应如何闭合？

## 调查边界

实现与 `06 §6.1/§6.3` 契约一致、fail-open 通路闭合、有机械校验覆盖时停止。
