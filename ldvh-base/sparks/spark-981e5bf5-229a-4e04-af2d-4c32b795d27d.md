# 摩擦与经验的重复与边界

## 当前理解

本次账本体检（2026-10-19）在 94 条 Friction、40 条 Pitfall 中共识别出 6 组高置信重复与 3 组疑似重复，分两层：层一为 Friction 与 Pitfall 之间的跨类型重复（至少 4 组，典型如「夹具同步化致断言恒真」friction-287d656c 与 pitfall-3ee591bc、「首行比较式校验漏检多余H1」friction-f647c6b5 与 pitfall-96fb3199 且两条都仍在活跃状态）；层二为各类型内部重复（Pitfall 侧「重复注入」被登记 4 次：friction-41a43496 已 resolved、pitfall-ef791457 与 pitfall-194381e1 已 discarded、pitfall-4f33d264 仍 active；Friction 侧「入队返回值被丢弃致登记静默失败」被记为 friction-09ff06a3 与 friction-56a9f9a8 两条）。可直接观察到的根因有二：其一，friction-4ea2c026 已记录 count 字段装不下结构性重复，补填值与实测不可分，导致后续执行体无法从账目上看出「这个机制已被观察过几次」；其二，20 号 §6.2 的查重口径只要求比对同类 open Spark，26 号 §9 的自动动作闭集中第 1 项账目比对的比对范围未界定为跨类型。二者共同造成「记下了但互相看不见」。处理次序建议先层二（机制可改，不动规范边界）再层一（须裁定 Friction/Pitfall 的区分线，涉及 26 §1 与 23 §1 的规范修订）。

### 已识别的重复组

层一（跨类型）：

- 夹具同步化致断言恒真：friction-287d656c [observing] 与 pitfall-3ee591bc [discarded]
- 来路不明的证据被转正：friction-aa6815a0 [observing] 与 pitfall-055a5a96 [discarded]
- 首行比较式校验漏检多余 H1：friction-f647c6b5 [observing] 与 pitfall-96fb3199 [active]
- 重复注入：friction-41a43496 [resolved]、pitfall-ef791457 [discarded]、pitfall-4f33d264 [active]、pitfall-194381e1 [discarded]（同机制跨类型且跨状态共 4 条）
- 疑似：幻影复现（编造执行记录）friction-16ded549 [observing] 与 pitfall-fa36d461 [active]

层二（同类型内部）：

- 相位闭集缺 complete 致吞错：pitfall-b011ff88 [active] 与 pitfall-9d3740a6 [discarded]
- 入队返回值被丢弃致登记静默失败：friction-09ff06a3 [observing] 与 friction-56a9f9a8 [observing]
- 提交引用未提交文件致纯净检出即崩：friction-77462e8b [observing] 与 pitfall-2d8463ef [draft]（此条亦为跨类型）

### 两条层的处置性质不同

层一应归为规范边界问题：26 §1「Pitfall 是规避导向，Friction 是改进导向」的区分线是「改什么」，但同一机制往往既能修掉也能避开，边界因此重叠。层二应归为查重机制问题：账目之间不可见，执行体创建新账目时看不到既有同类账目。

### 并入去向（2026-10-19）

本 Spark 的层一结论（Friction 与 Pitfall 的边界重叠）已并入「经验与摩擦边界重划」规范修订的后续推进，转 `implemented`，不再作为并行悬置项。

**并入的判断依据**：本 Spark 的调查问题与停止条件，与边界重划修订所处理的正是同一件事——层一是「边界怎么画」，层二是「画清之后的查重怎么落实」。二者不可割裂推进：只补查重机制而不重画边界，等于在错误的坐标上加强去重；只重画边界而不补查重判据，则停止条件的后半段无人承接。

**本 Spark 为修订提供的具体输入**：上列 6 组高置信重复与 3 组疑似重复构成边界重划的验证判据——修订后的判别轴须使这些重复组各自有唯一落点，否则即为未达成。

## 调查问题

Friction 与 Pitfall 之间、以及各自内部的重复入账，应通过明确两者边界还是补强查重机制来消除？

## 调查边界

当账本中已识别的重复组全部完成「合并/废弃/保留」处置，且查重机制具备可机械验证的判据时停止——不以账目总数下降为停止条件。

### 非本 Spark 范围

- 闲时触发机制改为按轮触发（独立议题，服务 §6.1 进入契约）
- 账本的 count 字段能否承载结构性重复（已由 friction-4ea2c026 单独立账）
- 超出本次已识别重复组的新重复发现
