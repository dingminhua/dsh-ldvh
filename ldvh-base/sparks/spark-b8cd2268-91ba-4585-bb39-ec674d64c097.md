# LDVH 记忆系统

## 当前理解

记忆系统设计已定稿（2026-09-10 Human 多轮拍板）：两层架构（本地层 storageDomain 轻治理 + git 层事实源全治理 + Human 拍板晋升，独占记忆职责）；信息分诊受众判据（三道门+默认本地）；本地层五类十三字段、三路记录触发+四操作比对+矛盾检测、零依赖启发式检索、无举证义务、400 条/按类 TTL；git 层 V1 落既有六类+关系图+预检召回集中+沉淀制度一章；Web 主管理面+会话双入口；V1 参数已批（三页三命令/摩擦阈值 3/评审默认开）。设计全文 memory-system-design-prompt.md（原 docs 目录，已随 ec19ba6 清除、可自该提交回取）（其 §六开放问题已完整落在本 Spark 待决子问题 1–7，docs→Spark 普查 A-09 并入不新建）。待决七项交对抗审查：空闲触发、效用审计、V1 验收、分诊机械化、晋升转换、git 效用信号、影子联动。类型系统同日定形：Spark 方向主线（20 号修订）、ADR 法定效力（22 号修订）；设计内容将随记忆规范起草收敛进条款（规范即法，不预落 ADR）。

分层展开（正文为快照的展开叙述，frontmatter summary 为唯一权威索引）：

**两层架构与独占职责**：本地层存 $DSH_HOME/storages（DSH 原生 storageDomain，单 key 聚合——agent-memory 先例），跨项目共享但条目带 scope（global / project:<仓库名>）分区；git 层为 ldvh-base 事实源（受控写入+Git Gate+类型准入全治理）。用户装了 LDVH 不需要第二个记忆系统（mnemon 的 USER.md/MEMORY.md/Documents/Memory Spaces 四大职能被两层完整替代）——Trae/WorkBuddy 实证：复述规范的记忆必静默过时，无晋升通道的教训永远停在记忆层。

**信息分诊受众判据**（什么进 git、什么不进的核心判据）："这条信息错了或丢了，伤害的是谁？"——伤害项目→门 1 进 git（按性质路由：坑→Pitfall、决定→ADR、外部结论→Research、议题→Spark、任务→WorkCase、系统性摩擦→Friction）；只伤害自己→门 2 留本地（五类）；谁都不伤害→门 0 不记（可重新发现的、AI 自身断言与推断偏好、单会话状态——状态不记，靠 DSH 会话历史+Output Envelope 承载）。不确定时默认本地：宁可漏进 git（本地可晋升），不可错进 git（错入需退休流程）。

**本地层设计**：五类（preference 工作偏好 / pattern 跨项目个人模式 / fact 环境与工具事实 / buffer 候选认识缓冲晋升主力 / note 杂项桶）；十三字段（id/type/title/tags/scope/project/confidence/importance/source/origin user|agent/created/updated/expires/locked 人锁 AI 只读/promoted 影子指向 git 对象）；三路记录触发（主控随手记过 Helper 格式校验 + 空闲评审代理保守回顾默认不变更 + 容量维护代理只整理不新增）+ 写入前四操作比对（新增/修正/矛盾/重复——Mem0 四操作的人工闸门版）+ 矛盾时提示替换或并存（sgme 先例）+ 重复摩擦 3 次提示记 lesson（agent-memory 先例，提示不自动写）；检索零依赖启发式（tokenize CJK 单字双字 + Jaccard + 评分 base×importance×recency×access）+ scope 过滤 + 每次注入附命中依据（noema explain 先例，与 git 侧 F2 对称）；热集常驻 + pre-step 动态召回；协议文本进系统提示、易变内容进消息流（mnemon 防缓存失效切法）；无举证义务（不保留原始对话、弱 source、删无审计——举证归 git 层，宽进轻出不对称治理）；治理参数：400 条上限、importance-3 淘汰保护、Jaccard≥0.7 合并、按类 TTL（preference/fact 180 天、pattern/note 90 天、buffer 30 天，可显式覆盖）；不上向量（远期唯一批准升级路径 sqlite-vec）/图/量化（六项目实证：插件级千条量级全在启发式端，图增益仅 ~2%，量化零使用）。

**git 层设计**：V1 不新建记忆类型（buffer 晋升按性质落既有六类——03 §9.3「按其沉淀环节分流」原义）；关系图（Web 呈现：对象/类型目录/标签三类节点 + Federation 全景图 + ObjectDetail 邻域图 + 确定性哈希布局——数据全在 frontmatter relations，零建边成本，待 07 号扩展立项）；预检式召回集中定义于记忆规范（做决定前查 ADR 防矛盾决定、动手前查 Pitfall 防重蹈覆辙、调研前查 Research 防重复调研——记忆是主动防线非被动仓库）；沉淀制度作为记忆规范一章（四系统独立规范结构下不另立文档）；与 21（WorkCase）/22（ADR）规范并行起草互为输入。

**管理面**：Web 主管理面（记忆列表 type/scope/importance 过滤+accessCount 冷热+TTL 预警、详情含命中依据与 locked 开关、晋升确认卡=Human 拍板 UI 化、审计视图四失败模式体检+摩擦检测历史、对话内回合尾记忆活动条）+ 会话内问询双入口（即时提议即时决——主面不等于唯一面）；人命令 list/show/edit/delete/promote + export/import 迁移（换机器场景，不做自动云同步）；Web 写操作与 AI 工具写操作过同一道 Helper 格式校验（单一闸门不因入口分叉）。

**设计原则**（压倒一切技术选型的三条第一性原理）：可追溯压倒可检索（宁检索弱不可溯源断）；消费压倒积累（KPI 是被用了多少次不是存了多少条，accessCount 是效用审计地基）；Human 闸门压倒自动化（跨界动作二元化：轻到无伤害或重到 Human 拍板，无中间态自动写公共区）。

**V1 参数（Human 批准默认值 2026-09-10）**：三页（记忆列表/详情/晋升确认）+ 三命令（记/查/删）；摩擦检测阈值 3（可配）；空闲评审代理默认开、可关。

**调研依据链**：业界通用层（research-fd133f0d——Agentic RAG survey/GraphRAG/Mem0/Letta/Anthropic/LoCoMo/LongMemEval/BEAM 十二源）、Letta 技术实现层（research-7b939142——三仓库代码级取证：Constitution 条款/MemFS git hook 闸门/约束配置/fail-closed 沙箱/三类子代理）、DSH 生态横向（R3 mnemon 深研/R7 记忆家族/R6 上下文插件）、Trae 与 WorkBuddy 实证分析（docs/ 两篇——镜像问题、无晋升教训流失、V4 记忆过时漂移；即 docs→Spark 普查的 B-03 条目，其内容已为本段所载，不另立对象）、本地层审核代理报告（对照 agent-memory/noema/sgme 源码八维度核验）。
