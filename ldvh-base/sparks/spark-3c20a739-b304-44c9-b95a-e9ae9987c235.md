# 02 章序与 00 列举序不一致

## 当前理解

`02` 六系统章序为 `9记忆与反思/10调研/11讨论/12工作执行/13规则遵守/14目标与蓝图`，与 `00 §3.1` 列举序（调研→讨论→工作执行→规则遵守→目标与蓝图→记忆与反思）不一致，与 `01 §8.1` 号位表（30–35 同 00 序）亦不一致。集合相同、仅次序不同，非缺漏。原登记于 `docs/pending-human-decisions-2026-09-11.md` 非阻塞待办 N-1，判为「既有状态、非本批缺陷」，是否调整待 Human 定。

同时 `01 §8.1` 的业务系统号位表（`30` 调研 / `31` 讨论 / `32` 工作执行 / `33` 规则遵守 / `34` 目标与蓝图 / `35` 记忆与反思）与 00 列举序一致，故 02 的章序与号位表也不一致。

该不一致在 `docs/pending-human-decisions-2026-09-11.md` 附「两项非阻塞待办」中登记为 **N-1**，当时审核判为「既有状态，非本批缺陷」，是否调整留由 Human 定。本对象即该项的独立承载。

**处置（已落实）**：Human 裁定「调整 02 章序，00 是根规范，下位规范必须对齐上位规范」。`02` 六业务系统章序已重排为 `00 §3.1` 列举序——现为 `§9 调研 / §10 讨论 / §11 工作执行 / §12 规则遵守 / §13 目标与蓝图 / §14 记忆与反思`，与 `01 §8.1` 号位表（30–35）同序。同步范围（均已机械核对）：(1) 02 章序重排，六章正文逐字未改、仅章号与次序变化（经 `git show HEAD` 逐章比对，六个正文块字节相同）；(2) 因章号位移，15 份规范共 51 处 `02 §N` 引用同步更新（旧 §10 调研→§9、§11 讨论→§10、§12 工作执行→§11、§13 规则遵守→§12、§14 目标与蓝图→§13、§9 记忆与反思→§14），已逐条核对引用处正文所述系统与新章号一致；(3) 02 §20 验证表原「工作模型根一致性」行含豁免陈述「00 §3.1 按系统列举，不规定本文的章节编号顺序……故章节序不构成对 00 列举序的偏离」，该陈述为旧状态而设、与本次裁定相悖，已改为要求名称、根职责**与列举次序**一致；(4) 02 §16 自引用原引「本节与 §9」（指记忆与反思）已随章号变为 `§14`。

**范围边界（如实限定）**：本改动**不涉及** `01 §8.1` 号位表本身的变更（该表本已与 00 同序，属另一事项）；不改变任何业务系统的名称或根职责内容。`docs/` 下带日期的审计与复核报告（如 `docs/review-round2-00-01-02.md`、`docs/review-00-protected-change.md`）仍含旧章号引用，但它们是时点性审计记录（多份明示「仅只读 + 仅写本文件」的操作边界），按 06 §5「Git 历史即溯源记录」不应回溯改写，故保持原样。
