# 事实对象关联五环节

## 当前理解

`docs/dev-memo.md` §5 待定项 **#11「事实对象内部关联五环节必决清单」**：ADR 0/8、Pitfall 0/8 声明关系；谱系类关联在 v4 曾被踢出、关系也曾被禁止承载证据。自述「02 起草前**必须**逐项形成候选方案、层级归属与待 Human 决定项」。**环节 1 声明**：把公共 `relations` 形状、关系条目最小信息、定位符形态、类型关系闭集、应声明/可选关系、互斥/基数/方向约束列为待决问题，分别记录哪些属 02 公共层、哪些应下沉 20–24；创建入口应要求声明或确认哪些关系也须形成候选方案。**环节 2 证据**：评估 v5 关系指向证据的方案（相对 v4 05 曾禁止关系承载证据的方向反转）；列出证据形态、定位符、关系—证据绑定、机械存在性校验、AI 语义复核及边界。**环节 3 谱系/承接**：分别检查拆分谱系、共同线索、跨对象承接中哪些必须成为可机械消费的关系、哪些只保留在事实正文或演变内容；`routed-to`、`contributed-to`、`informs` 等仅作待审查的关系家族候选。**环节 4 消费与召回**：明确关系边如何服务 F0–F4 事实召回（不与 L0–L4 规范读取分层混用），边展开容量、分页/深度/方向限制、超预算交还列为跨层分工问题。**环节 5 机械校验与服务**：relation-key 闭集、目标完整性、方向/基数/互斥、证据定位存在性、关系变更与失效观察、正向/反向检索列为候选契约。**分工纪律**：`02` 负责公共事实关系语义与受控写入边界，`20–24` 负责各类型关系闭集和类型条件，`05` 负责检索/校验服务契约，`10` 负责 Web 消费与呈现；四者不得互相越权或把实现投影反写成语义规则。**v4 实证与对治**：声明率 ADR 0/8、Pitfall 0/8、Spark 77/103、WorkCase 94/152、Study 17/51；稀疏既来自缺规则也来自声明摩擦高（吸收账「零摩擦链接文化」）。
