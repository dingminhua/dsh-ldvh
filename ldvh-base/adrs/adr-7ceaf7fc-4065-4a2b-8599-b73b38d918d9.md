# 提请弹窗 question 上限 200 字符

## 决策背景

LDVH 插件经 `ctx.userQuestions.ask` 发出的提请弹窗，其 `question` 文本没有长度上界；宿主侧也不施加任何校验或截断，超限不会被拒绝，只会让提请变得无法作答。

### 缺陷实测

三次 Spark 创建提请（`plugin/lib/host-seams.js:516` 的 `requestSparkConsent`）因 Human 无法作答而 fail-closed，失败理由串为：

- `spark consent request failed: the user cancelled ask_user_question`
- `human did not confirm the Spark 创建 (answer: null)`

实际传入的呈报正文约 3000 字符，全部落在 `question` 字段，选项被挤出可视范围。

### 渲染侧成因

`question` 渲染为 `h2.title`（`dsh-client-ui-user-questions/lib/client.js:613-614`），CSS `.QOsGLa_title{margin:0;font-size:16px;font-weight:500;line-height:22px}` 无截断、无行数上限、无滚动；卡片 `.QOsGLa_card{max-height:min(60vh,520px);overflow:hidden}`，而只有 `.QOsGLa_body{overflow-y:auto}`（位于 title 之后，`client.js:642-648`）可滚动。超长 `question` 顶高卡片后 options 被推出可视范围，且用户无法滚动到它。

宿主侧无兜底：`dsh-user-questions/lib/index.js` 的 `ask` 只校验 `questions.length===0`（`EMPTY_QUESTIONS`）、`agent` 是否为注册表中的活跃实例（`CALLER_NOT_LIVE`／`DELEGATED_CALLER`）与 `intent` 命中（`BAD_INTENT`），对 `question` 长度零校验零截断。对照 `dsh-client-ui-approval` 有 `.gtAFBG_title{text-overflow:ellipsis}` 与 `.gtAFBG_description{-webkit-line-clamp:2}`，问询卡片没有对应机制。

### 三处接缝实测

| 接缝 | 位置 | 现状 |
| --- | --- | --- |
| 登记确认 | `plugin/lib/host-seams.js:380` | 单行模板 85 字符，天然有界 |
| 工单路由确认 | `plugin/lib/host-seams.js:443` | 字段数 × 字段长双向无界 |
| Spark 确认 | `plugin/lib/host-seams.js:516` | 外壳开销 53 字符；终态门因 `disposition` 上界 200 字符（20 §8）使组装后 `question` 至少 227 字符，压缩无法解决 |

## 决定

LDVH 提请弹窗的 question 文本不超过 200 字符，超出该上界的呈报内容由 question.detail 承载。

## 备选与理由

- 只约束调用方传入的 `summary` ≤ 200 而不约束组装结果——否决：外壳（「Spark 创建确认（20 §16 Human Gate）」29 +「对象：…」21 + 空行 2 = 53 字符）仍使组装后超限，缺陷仍在。
- 要求宿主为问询卡片加截断或滚动——否决：宿主不是 LDVH 的规则对象（00 §3.3 规范源边界），把修复寄托于外部变更等于不修复。
- 不设数值上界，仅在规范中要求「呈报宜简短」——否决：不可机械核验、不可独立违背，正是当前缺陷的成因。
- 选定：约束组装后传入宿主的 `question` 字符串 ≤ 200 字符，超出的呈报内容改由 `question.detail` 承载。

选定理由：`question.detail` 渲染于可滚动 body 内（`client.js:644-648`），且经 `ask` 链路原样透传无字段过滤（`client.js:844` 的 `answerQuestion` 构造 `new PendingQuestion(sessionId, request.questions, request.signal)`），是宿主已提供的、可承载长文本的现成位置。

## 后果

正面：选项区恢复可见，20 §16（Spark）、21 §6.3（路由）、07 §5.6（登记）的提请恢复「可作答」，Human Gate 不再因载体缺陷空转。

代价：终态门的呈报（`disposition` 上界 200 字符）无法再整体塞进 `question`，必须改走 `detail`——`plugin/lib/host-seams.js` 三处接缝的文本组装需相应调整，属实现侧后续工作。

已知限制：宿主侧不施加任何长度校验，超限不会被拒绝，本上界只能靠 LDVH 消费侧自查；本条不主张宿主已提供机械保障。

## 适用范围

适用于 LDVH 插件经 ctx.userQuestions.ask 发出的全部提请弹窗，约束其中每个 questions[i].question 的文本长度；不约束 question.detail、options[].label 与 options[].description，也不改变各 Human Gate 规范对呈报内容完整性、去向与授权的要求。
