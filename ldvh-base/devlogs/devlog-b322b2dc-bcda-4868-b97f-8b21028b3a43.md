# 结构维度召回改造：可达性提升，排序质量未动

## 背景

源文档「结构维度召回改造（2026-10-29）」全篇（§一～§九）。改造前召回是带类型分桶的词法召回：类型只当过滤器、排序档位与排除名单用，类型专属字段几乎全未消费——全库 272 个对象、40 个 frontmatter 字段中 22 个零消费，而 `02 §9.1` F2 原文已要求「按类型、状态、稳定引用、关系、locator 或类型允许字段」命中。缺口不是「设计不够」，是既有条文未落。

约束：不得越 `02 §9` 的确定性红线（禁相似度、embedding、关键词权重或 AI 输出自动裁决相关性）；`34 §8.2` 命中依据须可复算；`34 §12` 三态与未检查范围须逐类披露；不新增依赖。

## 做法

1. **事实源改用 YAML 结构化解析**：`loadFacts` 从行式解析切到 `yaml` 包的 `parseObjectFrontmatter`（已是插件直接依赖）。解析失败时退回行式解析器并置 `yamlError` 由调用方披露——不让一个坏载体使整个召回不可用，也不假装读到了。
2. **新增结构命中层**：`structuralHits()` + `STRUCTURAL_MATCH_FIELDS`，判据是**整值相等（大小写无关）、不认子串**（`SG-1` 不命中 `SG-10`、`P1` 不命中 `P10`）。整值相等是可复算的确定性事实，与既有 tier 0（`spec_id` 整词命中）同一形态，故不越红线；字段之间不分高下，不设人为权重。
3. **新增 7 个 facet 收窄参数**：`objectUid`、`serves`、`priority`、`impact`、`directionKey`、`relationKey`、`attributionRef`，一律单值（闭集多值收窄等价于不筛）。被筛掉者进 `uncheckedRange.excludedByFacet` 并带其在 facet 上的实际取值。
4. **候选卡承载类型专属短字段**：`serves`/`priority`/`impact`/`directionKey`/`occurrenceCount`/`relationKeys`/`gate1`；长文本不进卡面。`estimateLineBytes` 同步，否则预算算少、注入超 `10:241`。
5. **纯指称与带主题分流（§六bis 修复）**：初版结构命中无条件取 `tier: 0`，导致查询里顺带出现结构值时，恰好 priority=P1/serves=SG-1 的对象压过真正相关条目（4 条探针中 3/4 被淹没）。修法——实义词 ≤ `STRUCTURAL_BARE_QUERY_MAX_TOKENS = 2` 视为纯指称，结构值即主题占 tier 0；否则降为 `STRUCTURAL_DEFERRED_TIER = 5`，仍构成候选且在命中理由里写明「不占优先位」。

## 实测

- 结构命中（改造前 → 改造后）：完整 `object_uid` 0→1；`P1` 0→16（15 条结构命中）；`SG-1` 3→26（含 1 条误命中消失）；`informs` 0→45；`release-gate` 正文蹭→1 条结构命中；`heavy`（open 池）1→1 且仍靠正文命中——库内 10 条 `impact=heavy` 全部已 resolved/voided，而 F2 默认只含 `open`，故这是正确结果，不是缺陷。
- 块标量解析缺陷的真实受害者是 WorkCase 的 `scope`：可命中 tier1 的从 14/38 升到 38/38。上一轮「friction/research 命中不了 tier1 是块标量所致」的因果判断**经实测证伪**——那两类规范里本就没有 `scope` 字段。
- 解析失败 0/272；新增 9 条用例全通过。
- 召回质量基线（`recall-quality.test.mjs`，limit=3）：6/65 = 9.2% → 6/65 = 9.2%，主题命中 6/8、无主题干净 1/5 均不变。
- 预算成本（同一查询，friction，limit=5）：2400 档 1944→2001 字节（+57），1200/800 两档 0 差值。
- 全量测试：2461 pass / 8 fail；8 条失败经 `git stash` 单文件回退验证均非本次引入。

## 结论与边界

结构维度（serves/priority/relation_key/direction_key/attributionRef 等类型专属字段）从「不可达」变为「可整值相等命中」，纯指称查询的命中数实测提升（uid 0→1、P1 0→16、SG-1 3→26、informs 0→45）；但召回质量基线在 limit=3 下保持 6/65 不变，故本次改造只证明可达性改善，不构成召回率提升，且结构命中只在查询为纯指称（实义词 ≤2）时占最高层，带主题查询降为 tier 5 不占优先位。

边界与已确认不成立的情形：

1. **不是质量提升**——9.2% 的中性结果为有意：本次补的是指称可达性，不是排序质量；把两者混谈会让「指标上升、质量下降」的误判重演。
2. **未做真实查询集评测**——数字来自自造探针与既有 16 条人工标注用例，不能当作召回率结论。
3. **带主题查询下结构命中不占优先位**（tier 5），这是修复回归后的取舍，不是遗漏。
4. **两项未验证**：同层内结构命中与文本强命中的排序次序未测；facet 未接入任何工具面（除已有 `ldvh_spark_list` 外其余 list 工具只有 `limit`/`status`）。
5. **一项既有缺陷只登记未修复**：预算 1200/800 两档下渲染文本超出预算 268/247 字节，改动前后数值一字不差，成因指向 `RENDER_FIXED_OVERHEAD_BYTES`（720）对小预算不够；修它要动 `10 §5.3` 预算档位，属 Human 决定面。
6. **`impact` facet 已随 2026-11-02 撤销影响分级一并删去**（26 §8）；本条做法与实测中与 `impact` 相关的部分属于当时的账本形态，不代表当前字段集。
