# 召回落实取证：交付的是候选，不是约束

## 背景

subgoal-a7accc55 的达成条件要求双源召回评估包记录六项材料。前一轮已交候选、未检查范围与遗漏截断三项（`recall-real-cases.mjs` + `devlog-9e6d6850`），本轮补缺失的适用判断、行动落实、材料进入判断的位置三项。

按 00 §2.6，双源召回的职责终点是「把识别结果落实为实际改变的行动」；34 §8.1 第 4 项把这条定死：识别结果不改变任何行动要素者不构成落实，并给出五类可观察形态。故本轮以真实会话日志为证据来源，测「落到底有没有发生」。

## 做法

1. **取证脚本** `plugin/scripts/recall-action-evidence.mjs`：从会话日志的事件流里切出「召回注入回合」，逐回合提取随后的工具调用与 reasoning。
2. **证据强度分档**：回指不等于落实。按工具性质分三档——write（受控写入/审批的参数承载了该候选）、read（按该标识精读，是落实的前置）、relay（转述进派发上下文）。按回合取最强行分类。
3. **判断位置**：看被注入候选的标识是否出现在该回合的 reasoning 里。这一项区分两种不同失败：候选没进判断（§8.3「有指向」不成立）与进了判断但未改行动（「有改变」缺失）。
4. **口径守卫** `plugin/test/recall-action-evidence.test.mjs`：钉住四条在本次实施中逐个踩到的口径错误。
5. **适用判断的可回读产出**：按 03 §7.2 公共格式对当次动作逐条判定，落于 `docs/recall-precheck-record-2026-11-11.md`。此前该能力只能声明「无产出」，现已有具体形态。

## 实测

扫描 200 个含注入的会话，627 个注入回合、3055 条被注入候选。

| 指标 | 读数 |
|---|---|
| 注入后发生工具调用 | 605/627（96.5%） |
| 调用参数回指到候选 | 51/627（8.1%），131 次 |
| 出现 Gate 类动作 | 81/627（12.9%） |
| **write 档（候选参与落盘或提请）** | **15/627（2.4%）** |
| read 档 | 20 |
| relay 档 | 16 |
| 无回指 | 576 |

判断位置：有 reasoning 的回合 607/627；reasoning 提及候选 124/627（19.8%）；**动手但未提及候选 481/627（76.7%）**。

## 结论与边界

**双源召回当前交付的是「看得见的候选」，不是「改变了行动的约束」。**三条独立口径同向：主题命中 17/21（不漏）但事实侧精确率 1.8%（不准）；write 档仅 2.4%；76.7% 的回合动手却不提任何候选。按 00 §2.6 与 34 §8.1 第 4 项，召回的职责终点当前没有被普遍达到——是结构性读数而非偶发失败。

**适用判断已有首个可回读产出，但它只证明「判断被作出并记录」，不证明判断正确**（34 §14），也不证明此后每回合都会这样判断。该记录最有信息量的部分是十条规范被判定「不适用」——它们进入候选仅因当次问句含「根据」「文档」「给出」等泛词，与之对应的动作本轮一个都没发生。这正是 `pitfall-06d08683`「以词频区分泛词与主题词在专门语料失效」的现场实例：若不逐条判定，「命中」会被当成「相关」。

**因果未验**：write 档 15 个回合只证明「候选标识出现在写入参数里」，不证明该候选改变了决策。语义判读属 AI/Human 核对，脚本不越界。

**本次实施踩到并修正的四条口径错误**（均由新增守卫钉住）：按字母序截断目录致样本被命名顺序决定（628 目录只取到 9 个）；注入事件自身被当回合致后续行动被丢弃（实测 0 次工具调用）；系统注入块被当回合边界致单会话 90 次注入只切出 1 回合；标题前 6 字子串匹配致 252 次回指里 116 次落在 `dsh-ui`／`Spark ` 等通用前缀。第四条修正后回指率由 13.1% 降至 8.1%。

**这构成一处 00 §5.3 价值冲突，本轮不裁定**：提高精确率（价值二）与保持召回宽度（价值一）直接对立，两侧负担与风险见评估包 §7.2，须 Human 决定。上一轮直接主张「优先处理精确率」是让价值二默认覆盖价值一，不合规，本轮更正。
