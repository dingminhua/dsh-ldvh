# 宿主 0.2.2-rc.2 子代理派发形状适配

## 背景

宿主升级到 0.2.2-rc.2 后，插件三处子代理派发调用仍按旧形状传参，导致三条子代理链路在第一跳即失败。原载体是一份 WorkCase（`workcase-316795ec`，open，serves 子目标「空闲积累与摩擦发现」）。

WorkCase 载体即将随类型删除而退役（2026-11-13 Human 根决定：WorkCase 正式从 LDVH 删除）。本条目承接该单的适配结论与两条残差。

## 做法

核实 rc.1→rc.2 区间消费条目的三态判定；修正三处 `startActivation` 调用形状；修测试替身并补形状守卫；推进基线登记值并留痕。

## 实测

**计划步骤 1 达成**：三态判定逐条完成，破坏面 1 条（`subagents.startActivation` 的 spec 形状）、须审面经核对判为对插件消费面无关、无关面逐项列明；依据已附入事实规范「本地开发工作流」的 change_log 与本区间差分结论段。

**计划步骤 2 达成**：三处调用点按 rc.2 平铺 spec 传参（`plugin/lib/workcase-auto-audit.js`、`plugin/lib/friction-discovery-provider.js`、`plugin/lib/experience-review-stage.js`）；按 `startActivation({` 的括号配平扫描 `plugin/lib` 全部调用点，残留内层 `request:` 传参 0 处。

**计划步骤 3 达成**：五处旧形状替身改为断言平铺形状，另补三条形状守卫用例；检测力经单项变异实测 4／1／7 例转红，独立复核以三处同时退回的方式复验亦全红；复核还查得摩擦发现模块两处仍把旧内层形状当作当前形状（模块头注释、报错文案），已改正；改后全量套件 3260 例通过（fail 0）。

**计划步骤 5 达成**：事实规范「本地开发工作流」的登记值经受控更新推进到 `0.2.2-rc.2`（四项实证本次独立取得），并落 DevLog `devlog-d1ae2885` 留痕。

**计划步骤 4 未达成**：修复前的真机痕迹已回查（runlog 四次 `stopped`，同一 TypeError 停在宿主 `dsh-subagent/lib/index.js:3024`，与待处置队列四条未结条目一一对应），根因在真机侧可回查；但**修复后的派发在运行中宿主上尚未发生**——闲时检查点需静默 ≥300 秒且无回合在飞（本次回合推进持续取消该计时），建前自动审核需一个建单载体而 Human 已选择直接执行（21 §6.3 不对象化）。

## 结论与边界

宿主 0.2.2-rc.2 把子代理派发接口的 spec 从「内层 request」拆平为「顶层平铺」，插件三处调用点已按平铺形状修正，全仓残留内层 `request:` 传参 0 处，并有形状守卫用例与变异复验兜住检测力；事实规范「本地开发工作流」的基线登记值已推进到 `0.2.2-rc.2`。

**边界**：**修复后的派发在真实运行中的宿主上尚未发生**——计划步骤 4 未达成。真机复验被两个条件卡住：闲时检查点需静默 ≥300 秒且无回合在飞（回合推进持续取消该计时），建前自动审核需一个建单载体而 Human 已选择直接执行（21 §6.3 不对象化）。故本条只证明**形状已修正且有守卫**，不证明**真机链路已跑通**。

**已确认的不成立**：不得据本条认为宿主 0.2.2-rc.2 的子代理派发链路已在真机验证通过——截至本条目写成时未发生过。

## 去向
