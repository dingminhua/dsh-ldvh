# 真实任务召回评测与上文改法对照

## 背景

spark-69b1de3f 记录了三步方向，第一步（核对并修正已返回／未返回集合）已于提交 `567a924a` 落实。本条目承接其后两步：建立接近真实任务的评测集，以及比较「利用有限当前话题」的检索改法。

既有评测集 `plugin/test/recall-quality-cases.mjs` 的 13 条是人工编的——查询按「这个问题该召回什么」反推，字面距离短、主题词几乎必然出现，只适合防倒退，系统性高估真实能力。

## 做法

1. **真实语料提取**：从 `~/.dsh/sessions/--Users-dmh2002-DshProject-dsh-ldvh--/` 下 628 个会话日志取 user 角色文本。关键实现细节：会话日志按追加写成多帧 zstd，`zstdDecompressSync` 只解第一帧（实测 18MB 文件只解出 212 字节头部），须用 `plugin/lib/zstd-compat.js` 的 `decompressZstdStream` 逐帧解压——否则会得出「会话日志是空的」这一错误结论。
2. **清洗**：剔除系统注入块（`<system-reminder>`／`Current runtime context.`／【双源召回】等）与子代理派发消息，只保留主控会话的 Human 原话。48 个主控会话去重后得 373 条。
3. **建评测集** `plugin/test/recall-real-cases.mjs`：32 条，分四类——topic 10（有明确主题）、ellipsis 13（连续追问，题干无主题）、noise 6（无主题短指令）、ref 3（精确引用式）。每条记 `basis`（标注依据）与 `context`（省略型的真实上文），可逐条复核。
4. **结构守卫** `plugin/test/recall-real-cases.test.mjs`：钉住四条会让评测集悄悄腐烂的约束（每条须有依据、ellipsis 须有上文、ref 须为空标注、kind 闭集且四类非空）。
5. **评测脚本** `plugin/scripts/recall-real-eval.mjs`：按 kind 报精确率、主题命中、规范侧／事实侧分开计数。
6. **对照实验** `plugin/scripts/recall-topic-context-ablation.mjs`：测量「把真实上一条消息并入查询」的效果与代价。**只测量不改实现**——该改法改变注入形式，按 `10 §9.1` 第 2 项属 Human Gate。

标注过程中修正了三处自身错误，均记在数据文件注释里：ellipsis 初版标成空答案且无上文（会让对照实验分母恒为 0）、ref 类初标了非空答案（把边界测试写反）、一条 ellipsis 误放进 topic 段。

## 结论与边界

**真实任务下召回不漏但严重不准**：主题命中 10/10，说明正确对象几乎总在注入面里；但事实侧精确率 1.8%（110 行只有 2 行对题），注入的绝大多数是无关经验。`noise`／`ref` 两类共 126 行全为无关注入——短指令与引用式提问会稳定换来一整屏噪声。这与人工编集的 5/8 命中、7.58% 精确率不可直接比较：两套集子的语料与问法都不同。

**「并入上一条消息」是净收益，但不足以据此改实现**：省略型相关行 8→14（+75%）、命中 7/11→9/11，代价是话题型相关行 −3、注入行 +51。净相关 +3。损伤机制已定位：上文稀释本回合短查询，把原本排在第 4–5 位的正确项挤出去（「清理一些无效的断言吧」单句命中 06 测试规范，拼接后丢失）。

**「实义词数 < N 才拼接」这条条件判据被证伪**：收益与实义词数无关——7 个实义词的「先把好处理的处理掉」仍受益，9 个的「清理一些无效的断言吧」反而受损。有条件方案只拿到 +2，无条件方案 +6，调阈值改善不了这一格局。

**样本与口径的边界**：本集只有本项目 48 个主控会话，不等于全部使用场景；13 对省略型样本量小，+6 的效应不足以支撑实现决策。真实流量下的召回率、AI 拿到候选后是否据此行动（34 §8.1 第 2 项）均未验证。

## 去向

- 评测集、结构守卫与两个脚本已落盘，可作为后续改动的可比基线。
- 「并入上文」的具体实现未做：它改变注入形式，属 `10 §9.1` 第 2 项 Human Gate 事项，须 Human 裁定后再动。本条只交付测量证据。
- 事实侧 1.8% 的精确率是比「并入上文」更值得处理的问题——注入的无关经验稀释了真正的信号。该方向未在本轮展开，留待下一轮。
