## 研究问题

对话任务闭环中的暂停、恢复、交还、Human Gate 与 AI 防自欺五个控制点，外部实践如何定义各自的判据与义务，其判据是否可机械核验

## 输入与边界

**输入**：00 §2 根方案第四条（五个控制点的义务与判据表述）、§7.1 防自欺、§7.2 Stop Conditions、§7.3 恢复与风险匹配、§7.4 交还与撤回、§4.2–§4.3 Human Gate；02 §18 协同与四层判断、§19 暂停接管与恢复、§20 交还。

**边界**：只调研判据与义务的外部依据，不调研具体实现；不修改 00 任何条文。

## 关键发现

### 外部共识认为 agent 循环应使用客观停止判据而非主观判据

Agent Loop Termination Pattern 列出四类停止判据：verifier done-checks、iteration caps、token/time budgets、no-progress detection；MindStudio 的分析进一步指出最好的 agent 循环用客观停止判据而非主观判据。限制：两者为行业分析与博客，非同行评议研究。

对 LDVH 的意义：§7.2 的停止条件宜保持为可核验触发，不宜退回主控主观判断。

溯源：https://www.agentnative.dev/patterns/agent-loop-termination-pattern（四类可枚举判据：verifier done-checks／iteration caps／token-time budgets／no-progress detection）

### 恢复的主流做法是重放持久日志而非重新推断

Checkpointing 的定义是工作流进度记录为持久日志、恢复意味着重放该日志而不是重新推断；Agent Patterns Catalog 的 agent-resumption 模式同样以持久化执行状态使长时运行能存活重启与断连，并指出天真地从头重试的问题；五种恢复策略中 State Persistence 居首。限制：agent-resumption 主要面向确定性工作流，LLM 场景的重放保真度未见系统性研究。

对 LDVH 的意义：§7.3 现未规定恢复的依据来源，宜补一条「恢复依据来自持久记录，不来自重新推断」。

溯源：https://dev.to/alex_aslam/agents-that-forget-where-they-are-will-repeat-work-forever-checkpointing-is-the-save-point-28p3（checkpointing 定义为进度记为持久日志、恢复靠重放而非重新推断）

### 外部主流交接做法是压缩式总结，而 LDVH 要求结构化七项

handoff skill 的做法是不把单次会话撑爆而是总结当前会话状态并移交；Context Compaction Pattern 指出压缩会留下沉积物并可能丢失信息。对 LDVH 的意义：压缩必然丢信息，支持 §7.4 必须含已证实与未证实范围；但主流是自由文本总结而 §7.4 要求七项结构化，这处加强需证据说明其优于总结式，是本次调研最需回答的问题。

溯源：https://www.aihero.dev/skills-handoff（handoff 通过总结当前会话状态移交而非撑爆单次会话）

### Human-in-the-Loop 审批关卡的设计难点集中在避免瓶颈与治理负担

HITL 审批关卡的定义是 agent 必须请求并获得人类决策，与 LDVH §4.2 一致；StackAI 与 BMC 的分析都把避免瓶颈、延迟、治理负担列为主要设计难点。对 LDVH 的意义：§4.3 要求提必须含八项要素，与「避免瓶颈」存在张力，需在 HV1 上验证其未损害 Human 决策速度。

溯源：https://www.stackai.com/insights/human-in-the-loop-ai-agents-how-to-design-approval-workflows-for-safe-and-scalable-automation（HITL 定义与瓶颈／延迟／治理负担为设计难点）

### calibration 研究已识别自改进引入自信度自偏的风险

Calibration 研究指出若自改进方法在自信度估计上引入自偏，会对 LLM 安全与可靠性构成重大威胁；Self-Calibration Prompting 提供了让模型评估自身输出的方法。对 LDVH 的意义：支持 §7.1 防自欺锚点的必要性，也提示主控自查存在自偏风险——与 Human 决定「不让主控自查充当兜底手段」方向一致。

溯源：https://arxiv.org/html/2504.02902v1（自信度自偏对 LLM 安全与可靠性构成重大威胁）

## 未证实与缺口

- **结构化交还是否优于压缩式总结**：未找到直接对比二者的实证研究。§7.4 的七项要求目前只有内部一致性推导，缺外部验证。
- **五项控制点是否完整**：未找到「对话任务闭环应有哪些控制点」的权威清单，五个控制点来自 LDVH 自身推导；是否遗漏升级、委派交接等未证实。
- **HITL 提请详细度与决策速度的量化关系**：未找到可靠数据。
- **checkpoint 日志在 LLM agent 上的可靠性**：agent-resumption 主要面向确定性工作流，LLM 场景下重放保真度未见系统性研究。

## 建议

1. §7.3 恢复宜补「恢复的依据来自持久记录，不来自重新推断」，与 checkpointing 主流做法对齐。
2. §7.4 的七项交还宜标注为 LDVH 的刻意加强而非直接沿用外部惯例，便于按 HV4 效用审计复核。
3. Human Gate 的八项提请要素需在 HV1「决策提请清晰可决」上验证其未损害 Human 决策速度。
4. 五个控制点的完整性作为开放问题保留，不在本次定论。

## 后续分流

- 结构化与总结式无实证 → 保留为开放问题。
