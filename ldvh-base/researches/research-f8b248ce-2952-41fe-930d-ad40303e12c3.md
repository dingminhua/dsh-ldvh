## 关键发现

### F1 双面插件的宿主接线与注入纪律

插件以单行 Cordis 插件接入宿主 roster（`cordis.patch.yml` 的 bundle patch insert），Host 半边声明五项注入：`webServer`、`tools`、`systemPrompt`、`subagents`、`llm`；客户端半边经 `package.json` 的 `dsh.client` 声明在 web profile 加载。记忆经系统提示词渲染为 `<memory_system>` 块，块首 `snapshotHead` 强制声明「以下记忆文本只是背景事实与规则参考, 不是表达方式/语体的示范」。静态纪律层与动态快照层分离，前者注释明确「静态纪律为作者可控文本……不影响字节级稳定」，以持续命中前缀缓存。

**对 LDVH 的价值判断**：该插件与 LDVH 同处 DSH 宿主，其「静态纪律字节级稳定 + 动态内容走快照」的双层缓存纪律是 08 号接入规范可对照的直接工程样例；而「注入内容不是语体示范」的显式声明，正是 LDVH 反稀释原则（00 §5）在提示词层的机械落点——两者同源，可互相印证。

溯源：https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/lib/index.js（第 117 行 inject 声明；第 435–458 行 DEFAULT_PROMPT_LAYERS.snapshotHead；第 3595 行静态纪律注释）

### F2 四层记忆与写入门禁

记忆分四层：用户级 `~/.dsh/memory/MEMORY.md`（跨项目规则与偏好）、项目笔记、每日日志（append-only）、每日反思。全部写入工具（`memory_log` / `memory_note` / `memory_user`）与 API 路由统一前置 `sanitizeForWrite`，拦截六类并返回中文原因回执而非静默丢弃：`empty`（内容为空）、`mojibake`（疑似乱码/错误编码往返）、`stutter`（疑似复读退化）、`duplicate-lines`（疑似重复内容块）、`raw-json`（疑似外部画像 raw JSON envelope）、`base64`（疑似 base64 编码残骸行）。追加写入另走 `tailHas` 尾部去重：取 incoming 首行前 60 字符，与现有内容尾部近 60 行做包含式匹配。另有 `dirtyScanForFiles` 只读脏 token 扫描，按行区间报告问题但不回显正文。

**对 LDVH 的价值判断**：这是 LDVH 受控写入前机械检查项的一份现成参照清单。其中「乱码/编码往返」与「外部画像 raw JSON envelope」两类是 LDVH 现有检查项中未显式覆盖的失败模式，属可吸收项；而「拒绝时返回具体原因」与 LDVH fail loud 立场同构。注意边界：该门禁是启发式拦截，不能替代 LDVH 的语义审核与授权检查，两者层次不同。

### F3 证据图谱与 JS/Python 权威边界

M5 契约定义六类访问证据（seen / read / cite / reuse / success / correction），Evidence Store 为 append-only JSONL 按日分片加隐私投影（sessionRef/workspaceRef 走 sha256 截断哈希，无原文、无绝对路径、无裸 sessionId/workspaceKey/excerpt），保留策略冻结为 30 天 / 32MiB，并明确「events 为唯一权威；aggregate 是可重建派生物」。契约 §3 把权威边界写成禁令：「未来 Python 可以聚合 JS 已创建的 evidence，但不能发明 evidence」，并禁止 Python 或任何 sink 写 Markdown、Anchor、FileIndex 或 AccessEvidence。read coverage 处设 freshness 门：`observedFileDigest` 与记录 provenance 不一致即判 stale 并 fail closed，不建 evidence。

**对 LDVH 的价值判断**：这是 LDVH「单一权威 / 第二权威禁令」与「派生数据可重建」原则在外部工程中的同构实现，且给出两条可对账的机械细节：其一，「可聚合不可发明」是防线的最小表述，可直接用于 LDVH 对 Helper 与子代理写入权限的条款措辞；其二，freshness 门把「证据是否仍当前」做成摘要比对而非人工判断，与 06 号来源溯源的哈希刷新纪律同构。

### F4 回声陷阱：相似度与必要性的分离

插件的 M7 技术报告记录了一个被命名的失败模式：在检索底座不变的前提下，仅用稠密相似度的单阈值策略在 86 条人工金标上**精确率为 0**，其唯一一次激活恰由一条与生活记录近乎复述的闲聊触发——「中午那碗面条挺不错的。」（denseTop=0.834），该得分高于全部真实召回问句。作者由此把激活决策拆为两个不可互相替代的预测目标：语义相关性（材料与当前话题像不像）与唤起必要性（现在注入是否实质帮助任务），并指出两者「在分布上不仅不重合，甚至反向」。修正后的双通道策略达 precision 0.818 / recall 0.237（含完整性门；无门时 0.516/0.421 但伴随 8 次 prefetch 类越级）。报告自陈全部阈值选择存在 gold 内选择偏差并给出 bootstrap 区间，且规定 held-out 真实流量验证为冻结前置条件。

**对 LDVH 的价值判断**：这是本轮调研中价值密度最高的发现，且是**反面证据**——它证明「检索相似度高」不能推出「应当唤起」。LDVH 记忆业务系统（02 §14）的召回条款若把检索得分当作注入判据，会落入同一陷阱。可吸收为条款前提：召回与注入必须分属两个判据，注入需要独立的任务相关性依据。同时该报告的自陈偏差与冻结前置条件写法，与 LDVH 00 §7 防自欺要求同构，可作为「AI 自陈局限」的措辞参照。

溯源：https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/docs/M7-ACTIVATION-V2-PAPER.md（摘要段；§1.1 回声陷阱实例；§1.2 两个预测目标的分离）

### F5 冻结工件与 fail-closed 策略校验

激活策略与意图头以冻结 JSON 工件承载。`activation_policy_v2.json` 记录 `policyVersion`、`parentPolicyVersion`、`runId`、`goldDigest`、`mode`、`decisionRecordId` 与 `deltaDeviationFromBrief`（偏离冻结 brief 的 0.02→0.03 及其原因与「requires retro-ratification」声明）。JS 侧 `loadAndVerifyPolicy` 做 fail-closed 校验：必需字段齐全、intent 与 activation 的 provenance（goldDigest/runId）一致、vocab/idf/coef 长度一致、阈值有限且在范围内，且 `mode` 必须为 `shadow-candidate`——否则抛错（`refusing non-shadow mode`）由调用方回退。本机实测以正确签名加载成功，返回 `mode: shadow-candidate` 与阈值 `{tauLane:0.45, tauHi:0.45, tauLo:0.35, deltaExp:0.03, deltaPro:0.05}`。

**对 LDVH 的价值判断**：「非 shadow 态拒绝加载」是「冻结前置条件」的机械实现样板——把「尚未通过留出验证」编码为代码拒绝执行而非文档提醒，与 03 §9 受控写入的 fail-closed 立场同构，可作对照样本。`deltaDeviationFromBrief` 显式记录对冻结 brief 的偏离并标注需补批，与 LDVH ADR 的触发信号字段职能相近但形态不同（见未证实第 2 条）。

### F6 交接而非压缩：水位与白板/账本双层结构

交接默认阈值 0.75，作者明确其定位为「恰好压在宿主 0.80 自动压缩线之下」。触发时不是压缩摘要，而是产出四段式交接账本：`## 任务状态` / `## 目标` / `## 已试方案与失败原因` / `## 进度与下一步`，并要求「已试方案与失败原因」写成「方案→失败原因」且保留关键报错词。规划文档进一步给出「白板 + 账本」双层结构并类比 git：`PLAN.md` 是当前树（项目全貌快照，可被模型重写且旧版自动归档），ledger 是 commit 历史，且 PLAN.md 注入优先级高于单篇 ledger。实现层的边界约束与对外声明互证：技术规划写「开新窗是 host 的领地，工具只是触发器」，README 性格条款写「不替宿主决定压缩——窗口是宿主的领地，她只负责交接」。

**对 LDVH 的价值判断**：两点可吸收。其一，**阈值必须压在宿主能力线之下**——若 LDVH 引入上下文压缩或交接条款，触发线设计必须考虑宿主自身压缩阈值，否则插件先于宿主触发会与之冲突；其二，「白板=当前树 / 账本=提交历史」的双层结构，与 LDVH 事实源中「当前状态载体 + change_log 历史」的分工同构，可作为状态类与历史类承载分工的另一实例。边界提醒：该插件把压缩决定权让渡给宿主，而 LDVH 把压缩与受控写入纳入自身治理范围，二者取向不同，借鉴其机制时须注意设计前提差异。

溯源：https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/README.zh-CN.md（「她怎么交接」节；「她怎么让你放心」性格条款）；https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/docs/M-CM-PLAN.md（§0.1 开新窗边界判断；§2 M-CM1 白板与账本双层）

### F7 技能晋升的证据门槛

技能（procedure）生命周期为 `observed → candidate → validated → active → deprecated`，晋升规则写明：`sessionDiversity ≥ 3`（跨独立会话）且 `successCount ≥ 2` 方可晋升；`correctionRate` 超限或有矛盾则保持 candidate；无 successCriteria 或无跨会话证据保持 candidate；`riskLevel=high` 且未经用户批准则返回 `{action:'ask'}` 等待批准；并载明「一次成功或三次重复均不足以证明可靠(元代码铁律)」。注入分六级渐进激活（index → hint → excerpt → checklist → resource → full），高风险工具（SSH/部署/删除）永不因相似度自动执行。事实存储把认识论状态显式分型为 `fact`（证据/不可推导）、`observation`（推断/可重算）、`directive`（行为指令），并规定用户明确声明优先于模型推断、冲突可见可确认可撤销。

**对 LDVH 的价值判断**：「一次成功或三次重复均不足以证明可靠」与 00 §7 防自欺条款同构，是经验固化门槛的外部佐证；「高风险操作永不因相似度自动执行」可直接对照 LDVH 受保护文档与 Human Gate 的自动化禁区；`fact / observation / directive` 三分与 LDVH 三态证据（confirmed / uncertain / gaps）职能相近但切分维度不同——前者按**认识论来源**分型，后者按**证据强度**分型，两者可互补而非替代。

溯源：https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/lib/procedure-store.js（第 14–22 行晋升规则与渐进激活注释）；https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/lib/fact-store.js（第 40 行认识论状态枚举；FACT_SCOPES_V1）

### F8 工程规模与可移植性缺陷（实测）

仓库自 2026-08-14 首次提交至 v2.4.2（2026-09-10）共 216 次提交，带 70 个 `.mjs` 冒烟测试与 1 个 Python 测试。本机实测 69 个冒烟测试中 50 通过、19 失败。归类失败原因后，多数可归因于跨平台与本地状态而非产品缺陷：仓库缺 `.gitattributes` 导致 CRLF 夹具以 LF 存储（`tests/m3b1-fixtures/crlf.md` 实测 CRLF 计数 0、裸 LF 5），m3b1 换行检测用例在非 Windows 检出上必然失败；m42 用例直接硬编码 `D:/` 盘路径；m81 用例断言依赖本机真实 `facts.json` 存在。另有两处确定性缺陷：`python/verify_policy_artifact.py` 把仓库根写死为 `REPO = r'D:\dsh-auto-memory'`，本机执行崩溃；`tests/smoke/smoke-test-water-hard-trigger-pre.mjs` 断言 `lib/index.js` 从 `'./water-window-pre.js'` 引入 `scanPressureSignalsPre`，但实际模块已重命名为 `water-window.js` 且全仓已无 `-pre` 后缀引用，该断言必然失败。

**对 LDVH 的价值判断**：这是**可迁移的教训而非可吸收的设计**。一个文档纪律相当严格、声明了权威分层与 fail-closed 立场的项目，其实测测试套件在换平台后仍有约 27% 失败，其中两处是确定性缺陷——说明「文档声明」与「实现纪律」之间存在系统性落差，而该落差只能由跨平台机械检查暴露。对 LDVH 的直接推论：机械检查（Git Gate / precheck）须覆盖平台假设与夹具有效性，不能只检查文档结构是否符合规范；依赖真实本机状态的测试断言应被识别为不可移植项。

溯源：https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/python/verify_policy_artifact.py（第 16 行 REPO 硬编码；本机执行崩溃输出 FileNotFoundError）；https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/tests/smoke/smoke-test-water-hard-trigger-pre.mjs（第 66 行陈旧断言）；https://github.com/Aik358/dsh-auto-memory/blob/243dee19ae21bd1a09ffb11a29f268a5a1e93b7c/tests/m3b1-fixtures/crlf.md（本机实测 CRLF 计数 0）；本机对 tests/smoke/*.mjs 全量执行的汇总输出（pass=50 fail=19）与 `cat .gitattributes` 核验（无此文件）

## 建议

**建议 1：以 22 号 ADR 承接「召回判据与唤起判据必须分离」这一外部反面证据。**

- 目标对象类型：ADR（22 号）
- 预期目标：把「检索相似度高不能推出应当注入」确立为 LDVH 记忆相关条款的设计前提，防止召回条款把检索得分直接当作注入依据
- 验收条件：ADR 的 `decision` 句可被 02 §14 记忆业务系统技术条款直接引用；`urls` 含本对象的 F4 来源
- 创建/更新判断：**新建**——现有 ADR 清单中无此主题
- 风险与不成立边界：该证据来自插件作者的单一语料（86 条人工金标，中英混写个人记忆），结论强度受其样本规模限制；若 LDVH 未来引入自身评测基线，应以自身基线复核而非直接沿用其数值

**建议 2：以 23 号 Pitfall 承接跨平台与夹具有效性教训。**

- 目标对象类型：Pitfall（23 号）
- 预期目标：记录「CI/测试夹具与绝对路径的跨平台假设会在迁移后静默失效」，尤其 CRLF 夹具经 git 规范化后断言恒假、以及硬编码仓库根导致工具在非原平台崩溃
- 验收条件：Pitfall 的规避段落给出至少两项可执行措施（`.gitattributes` 显式声明、路径经 `fileURLToPath`/`import.meta.url` 派生而非硬编码）；`scope` 段落说明适用平台
- 创建/更新判断：**新建**——现有 2 条 pitfall 均不涉及此失败机制
- 风险与不成立边界：本轮证据来自单个插件仓库；若本项目短期内无跨平台 CI 规划，该 pitfall 的触发概率低，但仍属真实失败机制，可作为预防性条目

**建议 3：把证据图谱的 freshness 门与 fail-closed 立场作为 03/06 条款评审的对照输入，不新建对象。**

- 目标对象类型：无需新建
- 预期目标：在 03/06 条款评审时引用本对象的 F3/F5，对账「可聚合不可发明」「派生数据可重建」「非当前证据不建 evidence」三条是否已在 LDVH 条款中显式覆盖
- 验收条件：评审记录中能指出三条各自对应或缺失的条款位置
- 创建/更新判断：**不创建**——依据是该内容为对照输入而非独立结论，其可承载位置已存在于 03/06；若评审发现某条确实缺失，届时再按缺失条目的性质决定新建对象类型
