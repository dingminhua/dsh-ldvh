## 研究问题

七个 DSH 社区上下文插件（openwolf/infinite-context/brain-compaction/context-compressor/session-surgeon/context-doctor/dsh-context）各自如何解决上下文负担问题——读维机制、写维闭环、宿主接入面、治理与反面教训——哪些对 LDVH 读/写双维有参考价值。

本调研支撑 LDVH 读/写双维（02 §6-7）与上下文负担控制设计：横向比较七个插件的读维机制、写维闭环、接入面与治理边界，为 LDVH 事实预热、上下文预算与受控操作提供外部依据与反面教材。基线：五个仓库已更新到远端最新（infinite-context 5362cce、context-compressor 3fa2699、session-surgeon 9a83b81、context-doctor 41d5c2e、dsh-context 30892c8/v0.47.0），openwolf 7a7ecc6 与 brain-compaction d40955a 无更新。

## 输入与边界

方法：七路子代理分仓只读取证（每仓一路）+ 主控第一手核验（关键结论均有 file:line 证据，子代理报告与主控核验交叉印证，冲突处以主控核验为准）。观察时点 2026-09-10。

对照框架：LDVH 读维判据（specs/02 §6）——取得当前工作所需且来源明确的信息，控制上下文负担；实际使用的信息可回指来源；候选/片段/完整来源/已读/未读可区分。写维判据（§7）——受控写入、授权、备份、回读、未验证可区分。

不覆盖：七个项目的 Web client 呈现层细节（除 dsh-context 与 context-doctor 的 slot 面外）、brain-compaction 引擎互斥仲裁的运行时实测、dsh-context 逐 patch 版本 diff。

## 关键发现

### F1 context-compressor 压缩非破坏性：最新优先回放 + 摘要注入新会话 + 原文保留

从 session.surface 节点 newest-first 回放到 maxInputChars(20000) 字符上限（超限丢最旧），保留会话自身 system+tools 前缀；SUMMARY_INSTRUCTION 要求压成 3~10 条每条一句话的中文要点；摘要作为第一条 user 消息注入新会话（摘要当已建立背景而非新指令）。源会话只读，原文保留侧边栏完整可回看。

溯源：https://github.com/qwert702/dsh-context-compressor/blob/3fa2699/lib/index.js（159-160, 13-14）

### F2 context-compressor 接入面：Web 按钮+HTTP 精确路由，additive slot

触发是会话标题栏「压缩」按钮 → fetch POST /api/dsh-context-compressor/compress；无 registerTool/ctx.on，仅 webServer 精确路由 + settings；client 注入 slot conversation.session.header.actions（priority 10），additive 不替换既有项。

溯源：https://github.com/qwert702/dsh-context-compressor/blob/3fa2699/lib/client.js（200-215）

### F3 context-compressor fail-closed 机械守护

状态码闭环：disabled(200 ok:false)/bad-request(400×2)/session-not-found(404)/open-turn busy(409)/压缩进行中(409)/空会话(422)/provider-error(502)；maxTokens 截断→MAX_TOKENS 错误；摘要无文本或含图→报错。

溯源：https://github.com/qwert702/dsh-context-compressor/blob/3fa2699/lib/index.js（199-215, 269-337）

### F4 infinite-context 读维工程：三层记忆 + 向量检索 + 动态 CTX + 四层预算

三层 short/mid/long 持久化（MemoryDoc 携带 tier 写 SQLite）；语义检索 query 嵌入后 VectorIndex.search(topK, floor)；动态 CTX 三源汇入 per-model registry（config→request-context→probe，probe 受 ceiling 约束只能缩小不能膨胀）；四层预算 short 10K/mid 20K/long 5K/retrieved 15K，TokenBudget.validate 断言 total ≤ maxTotal，headroomRatio 默认 0.25。

溯源：https://github.com/omdsh-dev/dsh-infinite-context/blob/5362cce/src/memory-context.ts（175-234）；types.ts（12）

### F5 infinite-context 破坏性压缩链（写维反面教材）

压缩后 oldMessages 从消息数组移除，替换为 [summaryMessage, ...keptMessages]；原文无备份/快照、无回滚；遗忘 sweep 直接 store.delete + index.remove 无确认；无 verbatim diff 审计工具。这是 LDVH 写维判据备份、回读、未验证可区分红线的反面样本。

溯源：https://github.com/omdsh-dev/dsh-infinite-context/blob/5362cce/src/memory-compaction.ts（559-566）

### F6 infinite-context 防失真工程

摘要不缩小即拒绝（saved<=0 → cooldown 或 throw）；extractBatch prompt 明确 PRESERVE verbatim（code snippets/file paths/function names）；防重入锁防 LLM 摘要调用重入治理；thinking guard 在窗口接近满时注入 overflow finish。

溯源：https://github.com/omdsh-dev/dsh-infinite-context/blob/5362cce/src/memory-compaction.ts（576-584, 752-758）

### F7 session-surgeon 写维闭环五重防护

默认 dry-run（所有写入口 dryRun=true，CLI 需 --apply、tool 需 apply=true）→ refuse 硬拒（header 不可解/版本不兼容/退役字段/中间帧损坏）→ 备份原子写（copyFile→fsync→O_EXCL .bak + atomicWrite .tmp+rename）→ 回读校验（decodeSessionBuffer→eventsSeqOk）→ seq 不连续 throw 拒绝二次损坏。

溯源：https://github.com/xiaoshenming/dsh-session-surgeon/blob/9a83b81/src/repair.mjs（applyRepair 273-288）

### F8 session-surgeon 字段化输出契约

planRepair 返回 {actions[], events, header, mustWrite, refuse}——actions 是机器可判别修复步骤、mustWrite=actions.length>0、refuse 存在即不可修复原因；applyRepair 返回 {dryRun, wrote, backup, plan, afterHealth}。与 LDVH 写维判据范围、身份、授权、基线、变化、回读、未验证可区分几乎一一对应。

溯源：https://github.com/xiaoshenming/dsh-session-surgeon/blob/9a83b81/src/repair.mjs（planRepair 70-271, applyRepair 281-288）

### F9 session-surgeon 接入面：三工具 + CLI 双入口 + loopback-only 路由 + 纯被动触发

session_scan/session_inspect/session_repair 三工具（plugin/index.mjs）；CLI 6 子命令（scan/inspect/repair/compact/export/index）；6 条 /api/session-surgeon/* 路由全部 loopback-only（403 非本机）；无事件监听，纯被动触发。

### F10 session-surgeon 治理：不修清单 + 版本门控

## 未证实与缺口

未证实：
- infinite-context 破坏性压缩是刻意取舍还是未及实现：仓库无设计决策文本，mergedFrom 保留 provenance 但无 re-derive 工具（U1）。
- openwolf digest 预算为估算非精确（char-ratio ~4chars/token 或 tokenMeter），±15% 偏差，大 STATUS 段可挤掉后置源，无校准数据（U2）。
- brain-compaction 引擎判定依赖 ctx.compaction 实例类名（constructor.name），类名是构建产物标识非稳定契约，本地未装子插件无法实测（U3）。
- dsh-context 63 spec 测试口径与仓库实测不符（实际 80 spec 文件 1529 用例），疑为旧统计或口径差异（U4）。
- context-doctor CJK 估算精度边界：启发式 1.5 字符/token 对不同分词/编码场景误差未知，无校准数据（U5）。
- context-compressor 长会话最旧部分缺席新会话：回放按字符上限最新优先，超限丢最旧，README 自认已知限制（U6）。

缺口：
- dsh-context 逐 patch 版本（0.41.1-3、0.46.1）与逐行 diff 未穷尽（G1, medium）。
- brain-compaction 引擎互斥仲裁运行时行为未实测（子插件未随包安装），协调层只判定+报告无自动停用执行（G2, medium）。
- 七个项目的 Web client 呈现层细节未逐一深审（除 dsh-context/context-doctor slot 面外），属呈现层不影响写维判据（G3, low）。
- rank shadow 检测只处理同名技能遮蔽，工具重名/指令覆盖等同类遮蔽形式未验证（G4, low）。

## 建议

A1 读维采纳索引指针 + 预算封顶摘要组合：索引不搬正文（openwolf）、预算封顶准入（openwolf digest）、渐进读取链（wolf_map→wolf_file→read offset/limit 对应 L0→L3）；验收条件：注入物是预算内指针而非正文，实际使用的信息可回指来源。判断依据：F13/F14/F16。可被 02 §6 读维与事实预热承接。
A2 写维采纳字段化输出契约 + dry-run 默认 + 备份回读闭环（session-surgeon 全链）：plan.actions[]+mustWrite+refuse+afterHealth+backup，所有写入口默认 dry-run、显式 apply 才写、写后回读校验；验收条件：写操作有明确计划字段、默认不写、写后回读验证、失败有备份可回退。判断依据：F7/F8/F10。可被 02 §7 写维与 Helper 受控操作承接。
A3 以 context-doctor 度量补 LDVH 读维缺口：注入面四段分类、CJK token 估算、rank shadow 检测可平移为 LDVH 规范源负担审计（specs 间重复/遮蔽检测）；验收条件：上下文负担可度量、重复/遮蔽可检测。判断依据：F19/F20。可被规范源负担审计承接。
A4 反面教材吸收：不学 infinite-context 的摘要替代原文破坏性链（压缩即删原文、无回滚无审计），学其防失真工程（摘要不缩小即拒绝、verbatim 清单）；验收条件：任何摘要/压缩操作不删原文、有回滚或原文可回看、防失真有机械校验。判断依据：F5/F6。可被事实对象与溯源红线承接。
A5 协调层模式（brain-compaction）：组装层不复制实现、零 import 运行时探测、引擎互斥仲裁只判定+指引不主动停用；验收条件：协调层与实现解耦，缺件降级不崩。判断依据：F11/F12。可被 02 技术支撑与插件交付形态承接。
A6 上下文可观测（dsh-context）：9 卡片仪表盘 + 基线门控（低版本走 fallback 零数据）+ 瘦头/按需 detail 双通道；验收条件：Human 可看清上下文构成与责任部分，低版本 harness 安全降级。判断依据：F17/F18。可被 Web 信息呈现承接。
