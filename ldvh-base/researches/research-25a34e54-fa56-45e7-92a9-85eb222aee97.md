## 研究问题

DSH 0.1.7-rc.2 宿主编排能力与兄弟编排插件生态的现状，对 LDVH 提出哪些同步跟进要求？

## 输入与边界

- **数据源**：本地 `deepseek-harness` @ `dsh-v0.1.7-rc.2`（git tag，只读差分与源码阅读）；8 个兄弟编排插件仓（2026-09-26 拉取至最新）；本仓 dsh-ldvh 规范与插件实现的对照面；运行中宿主（本会话工具面实测）。
- **方法**：两条子代理调研线（宿主能力线 / 兄弟插件线），关键结论经主控亲自核验（源码行级，核验清单见过程稿附录 A）。
- **边界**：不重复前两轮 DSH 升级调研（rc.1 契约面、rc.2 增量比对）已覆盖的内容，仅在编排能力语义与兄弟生态设计两条新轴上延展；不评审兄弟插件代码质量；本文不构成对任何规范修订的授权——修订须经各自 Gate。
- **过程稿**：`docs/dsh-orchestration-ecosystem-research-2026-09-26.md`（开发设计输入，非规范、非事实对象）。

## 关键发现

### 宿主原生子代理工具在 standard 预设下默认可用

standard 预设 `delegation` 组显式挂载 `tool-subagent`（spawn, continuable）、`tool-subagent-fork`、`tool-subagent-control`（send_message / interrupt_agent / list_agents）；host 平面同名行 `disabled: true` 避免双注册。子代理契约见 `packages/subagent/subagent/src/types.ts`（SubagentCapabilities：agentOptions / outputSchema / depthLimit / toolFilter / persona），生命周期与归档收容见 `lifecycle.ts` / `child-agent.ts` / `run-settlement.ts` / `archive-admission.ts`（`workspace/session-activity` 应答运行中后代 + `workspace/session-stop` 逐个 cancel，环状损坏链只访问一次）。对 LDVH 意味着：30 号调研线与 32 号执行/复核的委派承载面已就绪，无需自建编排设施。

溯源：https://github.com/deepseek-ai/deepseek-harness（packages/bundle/web-app/presets/standard.patch.yml delegation 组 @ dsh-v0.1.7-rc.2）

### subagent 默认限额为 maxDepth=1 与 maxActiveSubagents=8

`subagent/src/index.ts:202-203`（均 volatile）：`maxDepth` 默认 1（0 完全禁用、1 仅直子），`maxActiveSubagents` 默认 8（并行常驻/续接子，超限 `ACTIVATION_LIMIT_REACHED`）。本会话与 rc.1 调研 §3.6 双重实测 depth 2 被拒。对 LDVH 意味着两条硬约束：实施者为子代理时无法再派独立复核子代理（32 §12「独立子代理为默认优先形态」在该场景不可达，复核须回主控层发起）；30 号并行调研线（上轮 7 条）贴近 8 条上限——规范均未登记。

溯源：https://github.com/deepseek-ai/deepseek-harness（packages/subagent/subagent/src/index.ts:202-203 @ dsh-v0.1.7-rc.2）

### 宿主 workflow 编排工具为原生默认可用能力

`packages/workflow/tool-workflow` + `workflow-ptc`：脚本体钩子 `agent(prompt, opts)`（opts.schema 用 JSON Schema 子集校验子代理结果）、`pipeline`（无屏障逐项流水）、`parallel`（屏障汇合）、`phase` / `log`；caps 默认 total 1000 / items 4096 / sync 5000ms；会话日志不变量（`invariant.ts`，restored plugin data 不信任）与 job-ring 镜像（`record.ts`，settle 后迟到事件无害）。对 LDVH 意味着：大规模扇出调研多了一条原生形态可评估，但其消费方式待 08 编排契约章定义后才能登记。

溯源：https://github.com/deepseek-ai/deepseek-harness（packages/workflow/tool-workflow/src/record.ts 与 invariant.ts @ dsh-v0.1.7-rc.2）

### 08 §5.4 事件面登记落后实现两代

`specs/08` §5.4 仍列 `agent/session-start`（emit），核验标注停在 0.1.5-alpha.1（2026-09-10）；上游 0.1.7 已删除该事件、语义并入 `agent/created`（serial，`source: 'startup'|'resume'|'clear'|'compact'`，监听器返回 Promise 被串行 await、抛错回滚创建事务）；插件实现已迁移且 rc.2 调研 C15 证实 8 事件全在、mode 未变。对 LDVH 意味着：规范文本与实现矛盾——§5.4「已核验事件」清单是 08 §3.1 第 3 条职责的登记对象，登记失真直接违反档位诚实性，属必须修（A1）。

溯源：https://github.com/dingminhua/dsh-ldvh（specs/08-DSH环境接入与插件发布规范.md §5.4；plugin/lib/lifecycle.js:293-299）

### 规范链存在编排契约承接断点

02 §8「具体契约由 08 承接」、21 §3.2 与 §3.3「attempt 的宿主实现与锁语义指定由 08/09 承接」、32 §12「spawn/通信/中断回收的宿主机制归 08/09」三处指向，而 08 §3.1 六条职责（manifest/工具注册/引导事件/交互/登记/守护发布）无任何编排条目；21 §15.2 将 attempt 宿主实现列为未闭合依赖（未满足不得声称 V6/HV2 兑现），该依赖的承接方文本本身缺席。对 LDVH 意味着：SG-1「规范体系彼此互咬有效」存在一处实断点，08 需新增编排宿主契约章（B1）。

溯源：https://github.com/dingminhua/dsh-ldvh（specs/21-WorkCase-工单.md §3.2/§3.3/§15.2；specs/02-工作模型基础规范.md §8）

### Skill 管辖消费方未建立宿主缝

07 号把 Skill 列为管辖判定四消费方之一（执行前检查项目是否在管辖列表），但 08 §5 五类宿主缝不含 skill，`plugin/lib` grep `registerSkill|ctx.skills|sessionSkillCatalog` 零命中。宿主侧 skill 体系成熟（SkillRegistry 合并多 provider catalog、`<skill_content>` 直入会话、`agent/pre-step` 注入 catalog、digest 比对避免重发布）。对 LDVH 意味着：按 08 §5「未消费缝必须如实报告」纪律，须在补消费与如实标注之间做明确登记（B3）。

溯源：https://github.com/dingminhua/dsh-ldvh（specs/07-管辖范围规范.md §5.6 消费方表；specs/08-DSH环境接入与插件发布规范.md §5 宿主缝清单）

### LDVH 会话数据消费面对 v4 新载荷实测容忍

`event-stream.js:18` 仅按 turn/end 闭合 open turn；`child.js:146-148` 只读 `data.turn` 并回扫 assistant/message；`triggers.js:69` 只判事件类型——三处均不解析 reason 细分，v4 新增的 `reason.kind: 'forked'` 与补写的 `turn/end{interrupted}` 无害；`session-signature` 消费的 `model/selection` 与 `request/context` 事件两版均存在。对 LDVH 意味着：升级 rc.2 后无须为 turn 扫描做载荷适配，rc.1 调研的 ⚠️ 项可以销账。

溯源：https://github.com/dingminhua/dsh-ldvh（plugin/lib/event-stream.js:18；plugin/lib/child.js:146-148；plugin/lib/triggers.js:69）

### 兄弟编排项目普遍采用人工门禁与可审计流水

agent-teams（Approve & Run 计划冻结 + `docs/quality-gates.md` 机器可判定门禁 + 实现者不可自批 + repair-review 链）、dag-orchestrator（SQLite 哈希链事件日志 + `kind:"approval"` 门禁 + 默认防注入：任务子代理禁 dag_*/subagent*、上游输出置于数据标记间）、dsh_workflow（`approvalMode` 三级 + append-only `events.jsonl` + 不可变快照）、mnemon（不可变 View + provenance）、deep-research（acceptance 前置 + 对抗性审查）。对 LDVH 意味着：人工门禁与可审计流水的生态共性印证 LDVH 治理方向处于主流设计空间，而非孤例。

溯源：https://github.com/NanmiCoder/dsh-agent-teams（docs/quality-gates.md）

### LDVH 对兄弟项目治理原语已有语义等价物

Git 受控提交 + change_log 对应 append-only 流水；C2/Gate 1 授权钉扎对应计划冻结；21 §15.2 attempt 令牌对应 attempt_id 防篡改；00 §5 委托不转责 + 宿主 delegation statement + untrusted 标注对应防注入边界。对 LDVH 意味着：按反过度设计红线（21 §16/30 §21/31 §16/35 §20）不引入工程化原语、仅记录印证是正确取舍，避免第二套审计层。

溯源：https://github.com/dingminhua/dsh-ldvh（specs/21-WorkCase-工单.md §15.2 attempt 令牌；specs/06-事实源与信息溯源规范.md §6 受控提交契约）

### 当前会话的专家团工具来自第三方 Agency 插件

`summon_expert*` / `list_experts` / `get_expert_team` 在 deepseek-harness 全仓源码零命中；实为 `@michengai/dsh-agency-agents` v1.0.5（desktop profile 装载）。宿主另有 `experimental/agent-team` + `tool-agent-team`（spawn_teammate / team_task_* / 持久 mailbox + 共享任务 DAG），不在 standard 预设、默认不可用。对 LDVH 意味着：专家团产出的消费按第三方插件依赖对待，不归因宿主版本；宿主编排面升级不自动改变其行为。

溯源：https://github.com/MichengAI/dsh-agency-agents（cordis.patch.yml 工具注册面，v1.0.5）

### auto-review 三档模型终审为实验插件且默认关闭

`experimental/auto-review`：low 放行 / medium 需显式当前授权（点名动作 + 目标 + 范围）/ high 永拒（含显式请求）；歧义或超范围 fail-closed；审查请求五分区（REVIEW_POLICY / ENVIRONMENT / PROJECT_INSTRUCTIONS / FILTERED_HISTORY / PENDING_ACTION）；主代理 system/message 与 assistant 输出排除在外；风险与审查轨迹非 durable 状态；standard 预设不挂载。对 LDVH 意味着：若转正，宿主将原生具备行动前模型终审，与 LDVH 预检/门禁互补而非重叠（auto-review 管「这个动作能不能做」，LDVH 门禁管「这件事有没有被授权」）——列入上游吸收跟踪。

溯源：https://github.com/deepseek-ai/deepseek-harness（.agents/notes/implemented/feature/2026-08-28-auto-review.md @ dsh-v0.1.7-rc.2）

### mnemon 以「历史记忆永不凌驾当前指令」为铁律

dsh-mnemon v0.5.15（git 2026-09-26）将「历史记忆永不凌驾当前指令」列为记忆系统铁律，配合不可变 View 与 provenance 承载。`specs/35` 与 `specs/00` grep 无该显式表述（00 §4 Human 决定权可能隐含覆盖——属规范修订判断，非证据可决，见未证实 U1）。对 LDVH 意味着：35 号落地时可评估显式化该原则，作为防自欺的兜底表述。

溯源：https://github.com/omdsh-dev/dsh-mnemon（docs/en/development/architecture.md，v0.5.15）
