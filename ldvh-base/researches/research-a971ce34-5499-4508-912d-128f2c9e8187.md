## 关键发现

### F1 复核队列是治理中枢：按「出路不同」分档、徽标读服务端 COUNT、决策卡统一页脚

观察：Review.tsx 左栏为七档队列（pending 未上图记忆 / duplicates 重复对 / conflicts 时态新旧 / unconfirmed 新版未再提 / lowconf 低置信 / violations 公理违规 / defects 本体自相矛盾）加 agent 档（「七档问知识对不对，这档问机器替你办的对不对」）与台账/合并历史；violations 与 conflicts 分开的理由是「出路不同：可能答公理写错了」。档位徽标是服务端 COUNT 经 SSE 推送，不受分页影响；不带 ?queue= 进来默认落总览（「从前是第一个非空队列，那等于替人决定先看哪一档」）；深链 ?queue=&item= 落到档并 ring 点亮那张卡。决策卡统一 CARD_ACTIONS 页脚：动作左下沿卡片左缘对齐（一列卡纵向排齐、指针几乎不动）、危险动作最后、解释性内容放卡片上方在读决定之前读到（DESIGN.md 规矩 6）。
判断：分档哲学是「按出路」而非「按数据类型」，与我方认知中心收件箱四档（plan_confirmation/closure_confirmation/blocked_resolution/pitfall_confirmation，同样按待办出路）同向互证；CARD_ACTIONS 是「以决定结尾的卡」的成熟形状，可直接用于未来任何裁决面与收件箱卡的形态演进。
溯源：https://github.com/deeplethe/utopia/blob/dev/web/src/pages/Review.tsx（QUEUE_ORDER 与 Sel 类型、RailItem 计数、深链段、DuplicateCard 页脚 CARD_ACTIONS）

### F2 决策台账自包含：动作徽标＋快照＋人写的理由＋署名＋日期；AI 裁决单列且带先例与查询轨迹

观察：DecisionRow（台账行）= 动作 Chip（10 种 action 各配色）+ 决策时自包含快照（不 join 活数据）+ 人写的那句 why + confidence + 谁做的（actor_name ?? "AI"）+ 日期。AgentRow（AI 裁决）= 动作 Chip + 置信度 + 六态状态机（proposed/applied/accepted/overridden/reverted/superseded）+ defer 留下的问题正文 + 可展开先例列表（含人写的 why）与查询轨迹（「它查了什么，一行一次」）；人可带一句理由回答，走人的裁决路径、成为下一轮先例（决策 0026）；applied 的 merge 可 revert。理由输入框嵌在动作旁：单条卡一个、批量条一个，可空，写了跟决定进台账成先例。
判断：这是 32 号「复核判据七要素」与 35 号「理由回流」在 web 层的完整呈现形态——我方 WorkCase reviews 字段与 change_log 署名（provider/model 托管）已有等价数据，缺的是「读作一行裁决」的呈现与 AI/人 actor 维度的单列；属 A 层纯呈现层可直取（机制需求）。
溯源：https://github.com/deeplethe/utopia/blob/dev/web/src/pages/Review.tsx（DecisionRow、AgentRow、precedentText、DuplicateCard 批量理由段）

### F3 证据与缺席的呈现纪律：引用是落款且只列用到的、无引用明写、没日期要写出来、置信度只在低时说话

观察：Chat 引用等答案说完才出（「引用是答案的落款，不是过程的一部分」）、只列 citedSources（「检索到的不等于用到的」）、无引用时明写「未引用任何来源」（#547：缺席没人读得出来，得写出来）；Graph FactRow 没日期也要写一句「原文没写日期」；EvidenceList 证据卡不可点、不截断（证据是判断依据不是导航目标）、出处角标链到 doc?chunk、置信度只在 <0.75 时才说话；corrected 区间用一整句话说「是引擎对账闭合的」。
判断：与 10 号「如实降级、不用颜色单独承载状态」同向且更进一步——把「缺席」从默认空白升级为显式陈述；我方已有 field_issues/unparsed_structures 承接如实降级，可把「缺席要写出来」组件化为统一句式，并作为 10 号未来修订的候选条款（机制需求）。
溯源：https://github.com/deeplethe/utopia/blob/dev/web/src/pages/Chat.tsx（TurnView 引用段、citedSources、answeredWithoutSources）

### F4 URL 哲学与深链：「你在看什么」进 URL（深链可点亮目标卡），「你怎么看」不进

观察：router.tsx 注释明确 URL 哲学：搜索词、选中实体、时间轴时刻、复核档进 URL；节点档位、分页不进。库是容器不是筛选条件——进路径不进查询参数（没有 kbId 构造不出库内路由）。graph 的 entity/focus/at 用 replace 不 push（「点节点是浏览不是导航」），后退前进仍可用。
判断：我方路由 /objects/:type/:id 已含「看什么」，但筛选档位、收件箱选中态、ReadingPanel 打开态都是组件状态——不可分享、刷新即失、无法从会话深链进证据；此项是 F8 桥接方案的 web 侧前提，纯呈现层可直取。
溯源：https://github.com/deeplethe/utopia/blob/dev/web/src/router.tsx（L91-114 URL 哲学注释、KbRedirect）

### F5 空状态即引导：一句话＋至多一个动作，按优先级排序、按权限给按钮

观察：NextStep 把「这个库走到哪一步」收成一个判断四个页面共用：一句话状态 + 至多一个动作按钮（「状态一句话，动作在按钮上；原理属于文档」）；优先级排序（无模型 > 无文档 > 处理中 > 有失败未修）；权限不同动作不同（管理员见「去配模型」、普通用户只见「去找管理员」——「按钮亮着却点不动，等于让人猜自己有没有权限」）。
判断：10 §8 边缘条件「分项呈现原因而非合并为单一结论」的具体化范式；我方未初始化/未管辖/空联邦/空列表空态可直接套用（机制需求）。
溯源：https://github.com/deeplethe/utopia/blob/dev/web/src/pages/NextStep.tsx（nextStep 优先级分支、useReadiness、权限分档）

### F6 设计规范六规则由 style-guard 在 CI 强制：baseline 只能缩短、块注释豁免、token 从样式表反读

观察：DESIGN.md 六规则（字号五档/间距六档/圆角四档按角色命名/颜色只用 token/状态只在组件定义一次/面板是内容的槽）由 scripts/style-guard.mjs 的 12 条正则规则在 CI 强制（build 第一步跑 guard，违规不合并）；工程纪律三条：baseline 名单只能缩短不能加长、新文件永不豁免；块注释豁免（规矩可在被检文件里被引用）；字号与颜色 token 从 styles.css 正则反读——加 token 守卫自动认得。shadcn 供应层整体跳过（VENDOR）。
