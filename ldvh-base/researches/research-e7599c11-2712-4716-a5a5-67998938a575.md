## 研究问题

DSH 宿主（@deepseek-ai/dsh 0.1.2 系列）为第三方插件提供哪些 Service、Event、模型工具与 Slot/问询授权能力，各自的接入边界在哪

本调研支撑 LDVH 08 号《DSH 环境接入与插件发布规范》的当前性维护与 LDVH 插件绑定计划的能力依据判断。调研对象为 DSH 0.1.2-rc.1（本机生效版本与 npm dist-tags latest 一致；另存在 0.1.5-alpha.1 预发布，未纳入本轮基线）。问题分解为七面：Service 目录、Event 目录、模型工具层、问询/授权通道、Slot/主题、Web 接入面索引、子代理编排。

## 输入与边界

方法：五路只读调研子代理分面取证（Service 目录 / Event 目录 / 工具层+问询授权 / Slot+Web 索引 / 子代理编排，各带 scope、验收标准与三态输出要求）+ 主控第一手核验（关键结论逐条 file:line 抽验；三处子代理计数或证据误差由主控实测修正：Event mode 分布、guard 证据错位、slot 计数口径）+ 外部锚点核验（npm registry tarball 抽样 20/20 HTTP 200，本机安装物与 tarball 同版本）。证据形式：逐字摘录 + 包内 file:line 锚点 + npm tarball URL 长期锚点。版本基线：涉读 40 余包全部为 @deepseek-ai/*@0.1.2-rc.1。观察时点 2026-09-10。

不覆盖：dsh-workflow 内部实现及其与 subagents 的耦合细节（R5 专项调研承接）；前端 shell 消费 __DSH_BOOT__ 的细节与浏览器认证协议（R2 官方插件接入面调研承接）；chain kind slot 的 select 语义深挖；codex/claude-code SubagentProvider 的能力面（实现包不在本机安装树）。

## 关键发现

### F1 宿主经机器目录声明 68 个 Service 与 65 个 Event，与官方文档同源不可分叉

@deepseek-ai/dsh-tool-cordis 内嵌机器可读 API 目录：SERVICE_API 68 条（双口径计数：数组求值 68 与条目分隔符 68 一致）、EVENT_API 65 条（顶层 name 字段精确计数），由 scripts/gen-cordis-api.ts 从 TS 源码 AST 遍历生成（目录保留 abstract/泛型/@Remote 装饰器标记——只可能来自源码 AST，编译产物中已擦除）。目录经 Inspect Provider 对外暴露：listService 与 listEvents（HOST_EVENTS 过滤 6 个 cordis/ 前缀内部事件，实际对外 59 个宿主事件）。头注原文声明与渲染文档 "Produced by the same AST walk as docs/cordis-catalog, so this data and the rendered docs cannot diverge"。LDVH 会话日常使用的 cordis_inspect_list/cordis_inspect_query 工具背后正是这套目录。

**对 LDVH 的价值**：宿主能力事实的第一权威入口是 Inspect Provider（listService/listEvents），不是源码通读也不是手工盘点文档——08 号规范修订与 LDVH 插件设计应以机器目录为能力依据锚点，从根上消除文档腐化问题。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-tool-cordis/-/dsh-tool-cordis-0.1.2-rc.1.tgz（lib/index.js:5-13 头注；SERVICE_API 起于 19 行，EVENT_API 起于 4612 行，HOST_EVENTS 过滤于 8526 行）

### F2 目录是静态契约：服务可用性由 composition 挂载决定（base 组合 85 行）

SERVICE_API 是全量契约声明，queryServiceApi 只读静态常量、不检查运行时服务是否被 provide——"目录有 68 条"不等于"插件在任何组合下都能 ctx.get 到"。dsh-base 组合头注原文 "Row order carries no load semantics (activation is service-availability driven)"，默认挂载 85 个插件 row（timer、llm、session、settings、sandbox、approval、permission presets、各 tool-*、subagent 双后端、web 三件等）。目录中 e2b 与 lsp 两键在已安装包树无实现命中，印证目录声明与运行时可用是两层。

**对 LDVH 的价值**：LDVH 插件绑定计划必须以实际生效组合（base 85 行 + profile 叠加层）为运行时清单做依赖声明——硬依赖走 inject（缺失时插件进入 waiting），可选依赖走 ctx.get + undefined 检查；"目录里存在某服务"不构成接入依据。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-base/-/dsh-base-0.1.2-rc.1.tgz（cordis.patch.yml:3-7 头注与全部 85 个插件 row）

### F3 事件面四模式 emit 49/waterfall 14/serial 1/parallel 1，agent 系事件做作用域分发

65 个事件按监听模式分布：emit 49（单向通知）、waterfall 14（链式决策、返回值权威，如 agent/pre-step、system-prompt/assemble、tools/pre-execute、approval/request）、serial 1（agent/turn-stopping）、parallel 1（session/flush），四者求和恰为 65 与总数互证。agent 系事件经 @deepseek-ai/dsh-scope 的 invariant 提取函数做 agent-scoped 分发（如 agent/created 提取载荷首参数的 agent 字段），作用域内监听者只收自己 agent 的事件。

**对 LDVH 的价值**：LDVH 插件的事件监听设计有精确的模式分类依据：决策类需求（拦截 step、改写请求配置、审批）用 waterfall，观察类需求（会话创建、设置变更）用 emit；agent-scoped 语义意味着挂到 agent 作用域的监听器天然与 LDVH 单会话插件的生命周期对齐。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-tool-cordis/-/dsh-tool-cordis-0.1.2-rc.1.tgz（lib/index.js:4612-5388 EVENT_API 与 :8526 HOST_EVENTS 过滤；作用域分发 invariant 函数另见 dsh-scope tarball lib/invariant.js:10,19）

### F4 工具注册协议：register+defineTool 工厂，guard 单调守卫只能拒不能放行

插件向宿主注册模型工具的协议：ctx.tools.register(defineTool({name, description, parameters, output, execute}))，返回 disposer；参数经 JSON Schema 编译校验（违规抛 ToolArgsError）。守卫通道 ctx.tools.guard(guard) 注册单调守卫——文档原文 "Any matching guard may deny by returning a reason, while no guard can force-allow a call another guard denied"，plain-context 注册全局生效、经 agent.ctx 注册仅对该 agent 生效；guard 在 tools/pre-execute waterfall 之后执行。作用域收敛通道 restrict(filter) 做 allow/deny（要求 agent.ctx 作用域，与祖先链取交集）。执行链全序：pre-policy → guards → around-dispatch → post-policy → 内容终结 → 通知。

**对 LDVH 的价值**：LDVH Helper 确定性执行的机械闸门有了权威通道——guard 只能收紧不能放宽，恰与 00 §7 防自欺方向同构（dsh-sub-cli 第十七轮修复已实测此通道：0.1.2+ 的 ctx.tools.guard() + 谓词作用域收敛方案）。ldvh_* 工具族的注册走同一 register 协议。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-tools/-/dsh-tools-0.1.2-rc.1.tgz（lib/index.js:2807-2812 guard 文档、:837 defineTool、:2817-2822 实现）

### F6 问询通道强制精确存活调用者：子代理不能直接问人

userQuestions.ask 的边界由两个错误码钉死：CALLER_NOT_LIVE（要求精确的存活调用代理——agents.get 对该 id 返回值不等于传入代理即拒）与 DELEGATED_CALLER（调用代理被另一存活代理拥有时拒绝，原文 "human interaction is unavailable while the calling agent is owned by another live agent; include the unresolved question or decision in the child agent's final result"）。空问题列表抛 EMPTY_QUESTIONS。

**对 LDVH 的价值**：Human Gate 问询必须在主控（根代理）发起——这不是 LDVH 的纪律约定而是宿主的机械强制。LDVH 调研/讨论子代理的设计必须内置"未决问题带回父级结果"的协议，与 00 §4 Human 决定权的执行位置对齐。

### F7 审批通道与沙箱三档固化联动：ask/ask/never

approval.request() 须在开放回合内调用（回合外抛错，审计对 approval/asked 与 approval/decided 须回合闭合），经 approval/request waterfall 决策（UI 呈现 allow once/reject，策略 never 时直接 rejected）。沙箱三档 SANDBOX_MODES = read-only/workspace-write/danger-full-access，在 base 组合 permission presets 与 approval 行固化联动：三档分别对应审批 ask/ask/never；approval 行随 DSH_PERMISSION_MODE 环境切换（danger-full-access ⇒ never）。

### F8 子代理编排：spawn/fork 双 provider 与 one-shot/continuable 二分

ctx.subagents（SubagentRuntime）提供 start（一次性运行，返回 SubagentRun）与 startContinuable（常驻可续）双入口。内置双 provider：spawn（inheritsParentContext=false——"its own session, own system prompt, zero parent context"）与 fork（=true——seed 为父会话已完成回合前缀，进行中回合不含）。第三方经 registerProvider 接入：Provider 声明能力五布尔（agentOptions/outputSchema/depthLimit/toolFilter/persona），请求带未声明能力时 start 前即拒 UNSUPPORTED_CAPABILITY。工具层三态路由：continuable 后台直接 startContinuable 返回 subagentId、one-shot 后台经 jobs.start 返回 jobId（job_output/job_kill 收集）、前台 await start。

**对 LDVH 的价值**：02 §8 编排技术支撑的宿主基线确认——LDVH 调研子代理（spawn，自包含任务）与讨论子代理（可续协作）分别对位 one-shot 与 continuable 语义；CLI relay 子代理的接入点是 registerProvider（dsh-sub-cli 已实证）。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-subagent-spawn-in-process/-/dsh-subagent-spawn-in-process-0.1.2-rc.1.tgz（lib/index.js:30 inheritsParentContext = false；编排服务双入口与 provider 协议另见 dsh-subagent tarball lib/types/index.js:115 与 :419-432）

### F9 子代理策略委派：approval 钉死 never，权限声明段强制注入

captureDelegatedPolicyOverrides 只继承父的显式 sandbox override，approval 一律钉死 'never'。子代理组合强制注入固定权限声明段 SUBAGENT_DELEGATION_CONTEXT："your permission scope was fixed when you were started and cannot be widened from inside this session"。

**对 LDVH 的价值**：00 §5"委派不转责"在宿主层有机械保障——子代理越界动作必被沙箱拒绝而非弹出审批问询（问询还会被 DELEGATED_CALLER 拦截），越界信息只能以错误形式回流主控。LDVH 子代理的权限设计应按"只收窄"假设规划。

### F10 父子通信约束：send_message 仅相邻，interrupt 可达任意深度

send_message 服务层只允许相邻通信（父与直接 continuable 子）：非精确存活发送者 UNAUTHORIZED、非常驻 continuable 子发父 UNAUTHORIZED；缺席直接子可经 ctx.agents.resume 冷恢复（durable Session + 单 Activation + FIFO inbox 语义）。interrupt(targetSessionId, authority) 的 authority 两型（user/ancestor）：ancestor 须为精确存活祖先且在 activation.ancestry 链上——即可中断任意深度后代；目标缺席为接受的 no-op。toolFilter 以 ToolRestriction（allow/deny 数组）随 continuable descriptor 持久化支持冷恢复；委派深度 maxDepth 默认 3、单调不减。

**对 LDVH 的价值**：LDVH 编排的通信拓扑约束确认：跨级通信须逐级中继（与 ldvh_collect_subagent_results 的父级回收设计对齐）；中断能力全深可达，调研子代理的止损通道畅通。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-subagent/-/dsh-subagent-0.1.2-rc.1.tgz（lib/types/continuation.js:329,340 UNAUTHORIZED；:421-449 interrupt）

### F11 客户端 UI 面：52 个官方 slot 与 single-shadow 语义，theme 双层定制

slots 服务（SlotRegistry，服务名 "slots"）基于纯注册表 SlotCore（构造预置 root 种子位），register(options, component) 四类 kind（single/keyed/list/chain）带加载时校验、返回级联 disposer。官方 slot 目录 CLIENT_SLOT_API 计 52 个（主控三字段交叉计数：key=52/kind=52/scope=52；分布 27 single/17 list/6 keyed/2 chain），可经客户端 Inspect Provider Slots.listSubTree 实时查询。关键语义：single slot 的第二注册是 shadow 而非并列——root 的 doc 警告 "DO NOT register here … a second entry does not sit beside the frame — it shadows it, and a dynamically registered entry is assigned a lower priority than the shipped one, which makes it the winner"（动态条目优先级更低反而胜出，会顶掉整个 AppFrame），自建全屏浮层应注册 shell.overlay（list，加法语义）。theme 服务经 register（整主题：id+colorScheme+tokens）与 overrideTokens（token 到 light/dark 值对的覆盖层，seq 序后写胜，返回 disposer）双层定制，变更发 theme/change 事件。

**对 LDVH 的价值**：10 号 Web 呈现规范的挂载面确认：LDVH 主界面入口（Tab/面板）走 settings.plugins.tab 或独立 slot；浮层走 shell.overlay；品牌定制走 overrideTokens 不动全局调色板。single-shadow 语义是插件 UI 设计必须规避的陷阱。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-cordis-client-runner/-/dsh-cordis-client-runner-0.1.2-rc.1.tgz（lib/client.js:2135-4054 CLIENT_SLOT_API，root 条目 :3302-3310；slots 服务注册另见 dsh-client-ui-renderer tarball lib/client.js:995）

### F12 Web 接入面：webServer 四类路由席位 + dsh.client 声明式前端 + slot 即 Tab/Sidebar 接入面

webServer 服务（激活即 listen，port 可 OS 分配）提供四类路由席位：register({kind: exact/prefix, path, handler})、registerUpgrade（WebSocket）、registerFallback（唯一 fallback 席位，由 frontend-static 占用服务 dist 静态资源）、tapIndex（原始 HTML 变换）；index 注入两段式（结构化行 + 原始 tap，经 webserver/index-inject 事件收集）。插件前端资源经 package.json 的 dsh.client 字段声明（platform/inject/external/immediately + exports 指向浏览器 bundle），由 ClientModuleRegistry 组成 window.__DSH_BOOT__ 启动图并挂 /plugins 前缀路由。浏览器到宿主 RPC 走 /api 前缀（浏览器认证保护）。Tab 与 Sidebar 无独立注册服务——接入面就是 slot 系统（sidebar 单例及其子 slot、settings.plugins.tab 等 list slot）。

**对 LDVH 的价值**：LDVH 插件的 Web 服务（cognition 端点等）走 webServer exact/prefix 路由、前端资源走 dsh.client 声明、UI 入口走 slot——三条接入径路与 R2（官方插件接入面专项）形成精确衔接。

溯源：https://registry.npmjs.org/@deepseek-ai/dsh-host-webserver/-/dsh-host-webserver-0.1.2-rc.1.tgz（lib/index.js:157 服务注册、:205 registerFallback；前端资源声明另见 dsh-client-modules tarball lib/index.js:440-488）
