## 入账依据

## 处置

**不可清偿去向（不在本项目可动范围，Human 2026-11-20 裁定）**：账目主诉求是「接口在调用前机械告知必填字段及其形态约束（非空）」。本次核查确认该诉求依赖工具参数层支持非空校验原语，而宿主 `@deepseek-ai/dsh-tools` 的参数 spec 只接受 `description/title/default/examples` 与 `type/enum/const/oneOf/required`，**没有 `minLength` 校验**；本仓 [parameter-spec-adapter.js](plugin/lib/parameter-spec-adapter.js) 的 `DROPPED_KEYWORDS` 还刻意剥离 `minLength`，并有测试固化该行为。因此即便在本仓源 schema 写 `minLength: 1`，也会在适配时被剥掉、到不了模型侧——「非空」只能以散文 description 呈现，无法机械告知。该能力缺口在宿主工具格式层，不在本仓可动范围，按 36 §9.4 第 2 类接受。

**拒收侧已加固、部分证据已过期（如实登记）**：核查当前代码，各 writer 的非空守卫已就位——`createFrictionObject` 对 `bodyMarkdown` 空值返回 `invalid_request`（L529）、`body_markdown_after`/`change_summary` 等亦有非空守卫（L673/679 等），工具层返回带 actionable 消息的 `invalidRequest` gap；即账目所述「漏传被拒、须重试」是校验**在生效**，不是缺陷。账目 L56-58「空 `change_summary` 被七类写入器原样写入 `change_log[0].summary` 并成功」这条证据在本轮核查时已不成立：以 friction 写入器为例，create 路径把 summary 取为 `frontmatterDraft.change_summary ?? "受控创建 Friction 对象"`（L558-562）——`??` 对显式空串 `""` 原样保留（不回落到默认文案），但紧随其后的 `validateFrictionFrontmatter` 以 `change_log[i].summary.trim().length === 0` 守卫（L220-221）拒收空摘要，故当前代码不会让空摘要落盘。该支证据过期（如实声明，不据其扩大或缩小账目范围；此处只核到 friction 写入器，其余六类未逐一实测）。

**无残留窄口（如实登记）**：复核 L558-562 的 `??` 与 L220-221 的非空守卫后确认——显式空串虽经 `??` 原样保留为 `""`，但在写入前的 `validateFrictionFrontmatter` 校验中被 `change_log[i].summary` 非空守卫拦下，故 friction 写入器不存在「空摘要落盘」的残留通道。本条转 accepted 不因此扩大或缩小范围。

**复审触发**（自觉约束，非机械检测）：当宿主 `dsh-tools` 的参数 spec 增加非空/长度校验原语（或其等价的前置告知机制），使工具能在调用前机械告知必填与非空时，由 Human 按 26 §10 Human 入口新建 open 账目并在正文接续本 uid。

**配对复审**：`open → accepted` 不触发配对复审（36 §9.4）——本账目无 `paired-with` 边，债未清偿，规避经验仍按需要处理。
