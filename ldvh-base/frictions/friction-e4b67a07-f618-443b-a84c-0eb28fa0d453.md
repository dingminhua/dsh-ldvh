# 闲时派发按轮换与Human秒度全做设计相悖

## 现象
闲时派发当前按 rotation % 3 轮换、每次只派一个任务；而 Human 明确的设计意图是「勾选哪些就同时做哪些，上下文拼接在给代理的提示词里」，二者矛盾，需要改（32 §10.2「按预算轮换」为候选态）并删掉整套轮换相位。

## 入账依据
可归因性：材料中主控明确陈述当前实现为「pickEnabledAuxTask 按 rotation % 3 挑一个」，而 Human 的设计意图是「勾选即全做、上下文拼接」，二者直接矛盾，且主控要求为此改规范（32 §10.2 为「按预算轮换」候选态）。修了会更好：若按 Human 设计改为「一次派发做所有勾选任务」，rotation 相位逻辑整套可删、capacity-maintenance 从「永远轮不到」变为可达、每 3 次空转 1 次的浪费消除——这是机制层面的系统性建模错位，不是单次手误。

## 处置
解药为提交 `39e3623a7470e10c391840af3c965220ba76cf88`（整体删除任务轮换，改为「一次派发做多件事」）与 `15faa2a878757571988f0fa57137d542d178fc60`（清底：判据扫描发现的四处现行语态残留），依 02 §8.1 commit 形态进入 `informs`。

核验（2026-10-14，第 1 批）：

- **规范面**：`specs/32-记忆存取系统规范.md.draft` §10.2 现行文本为「**不设任务轮换，也不设用于决定「本次轮到谁」的派发预算。**」，并明定「本项只取消**派发次序**上的预算；各任务**自身**的作业限额不受影响」——与本账所记 Human 设计意图（勾选即全做、上下文拼接进提示词）一致。
- **实现面**：`plugin/lib/aux-task-registry.js` 落任务登记表（每任务自述 promptSection/outputSchema/validate 三部位）与 `buildCompositePrompt`（公共段一次 + 各任务段依次拼接）；复合 schema 使各任务占一个顶层字段以防同名字段静默覆盖；`validateCompositeOutput` 逐任务独立收口（任务级失败如实返回，不再抛错掀翻其余任务）；`plugin/lib/idle-settings.js` 的 `pickEnabledAuxTasks(settings)` 取**全部**已启用任务。即「一次派发做多件事」已成立，`rotation % 3` 与整套相位逻辑已删。
- **连带消除**：`capacity-maintenance` 从「永远轮不到」变为可达（39e3623 提交消息记载的护栏实测：撤掉 runlog 的 `tasks`/`unimplemented` → 3 条测试失败），即该可见性已被测试锁定；「每 3 次空转 1 次」的浪费随轮换删除消失。
- 判据面 eslint 0 错；plugin 全量测试 1447/1447 通过。

**据实声明**：本账现象段（「当前按 rotation % 3 轮换」）是入账时的陈述，现已与实现不符——本账正是记录该矛盾的载体，按 26 §8 不因解药落地而改写现象段；读者应据本处置段理解其现况。另：本条标题中的「Human秒度全做」为入账时的表述错误（应为「与 Human『勾选即全做』设计相悖」），本次流转不修改标题，仅在此如实登记，以免后来者据标题推断原意。
