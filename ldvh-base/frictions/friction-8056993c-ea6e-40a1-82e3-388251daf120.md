# fork 全量 seed 随会话增长致执行体成本失控

## 现象
宿主 fork provider 把会话日志最后一个 turn/end 之前的全部事件硬编码为执行体 seed，且 start/prepareContinuable 与 SubagentStartRequest 契约均不接受调用方收窄参数——执行体可见上下文随会话增长单调扩大，长会话下机制执行成本与失败率随之上升

## 入账依据
可归因性：fork 全量 seed 直接可归因于宿主 fork-in-process provider 的实现（completedTurnPrefix 硬编码取最后一个 turn/end 前全部事件），插件经 SubagentStartRequest 无任何收窄通道；修了会更好的预期：若改为插件自建受限 seed provider 或经 04 §8.4 修订允许受限继承，执行体成本不再随会话增长，长会话下机制可持续产出判断、水位可持续推进，失败率不再随会话规模上升
