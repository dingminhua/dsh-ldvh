# 以产物缺席作否定判据致连续错判

## 现象
本轮两次把「在所读产物中查不到某事件」直接当作「该事件从未发生」的判据，而两个产物（插件日志、会话文件）实际都不覆盖被判现象，两处均在事后被自证为不成立。

## 入账依据
可归因性：材料内同一轮出现两次同型误判且均被自纠。(a)「Zero probes — meaning `installChild` **never ran**. The guard already rejected the subagent.」紧接下一行即被「The log is stale (Sep 29) — not the running host's.」推翻——产物根本不覆盖当前进程。(b)「Confirmed: the trigger requires `agent/turn-stopping` + `agent/status idle`. The subagent session has **no `agent/status` events** — so it can't be from there.」被隔数轮后的「`agent/status` **不写进会话文件**」推翻——产物不记录被判事件本身。两次失效机制同一：所读产物未覆盖被判现象，而「查不到」被直接当成「未发生」。第二次的误判支撑了后续数轮排查方向，故不是偶发手误而是稳定复现的判据缺失。预期改善：若「未在产物中查到」与「未发生」之间必须先建立产物覆盖该现象的证据（日志时间戳对应当前进程、该事件类型确实落盘、该文件确含同类记录），则此类否定性判断在本地排查中不再依赖事后自纠回收，也不必等到下一轮才推翻已据以推进的中间结论。

补充观察（2026-10-14T05:48:38.426Z）：该句表明执行体把运行痕迹表里「0 次 create」（产物缺席）当作否定判据，据此错误地得出机械通道无产出，随后自我更正（「我把它误当成该机制的历史产出总量」）。这正是既有账目 1e589e75「以产物缺席作否定判据致连续错判」描述的同一种阻碍在本次材料中的一次实例——用产物缺席作否定判据导致错判。判定为 same-obstacle。另据实声明：本次材料被截断（turn 2 在 0ac049b5、2 处中断），仅就所见部分判断。

## 处置
解药为三笔 commit 级承载（解药走直提路径、无对应 ADR/WorkCase 事实对象，依 02 §8.1 commit 形态承载 informs）：

1. `74f885de34b82ea22d6087cea8512931949131e6`（docs(specs): 补写批量判定零值歧义的纪律，2026-10-28）——06 §5 立「『没有输出』与『输出为零』是两个结果」：取不到计数与取到零须输出为两个不同终态；**判断运行是否发生须用与结果无关的证据**（运行器报告存在，满足其一即可），进程退出状态不得单独充当该证据；终态须使整批结论不可用。这正是本账 2026-10-18 观察（变异脚本把缺席的 `ℹ fail` 行读作「接住数 0」、一次错判整批 11 处）所要求的前置证据。
2. `c57bf5b49c1444c0188d134d4946e52597dfc51b`（docs(specs): 补写检索未命中不可作为清空依据的纪律，2026-10-28）——06 §6 立「检索不能证明『没有』」：检索只给候选不能单独作「已清空」依据，归零判断须落到载体内容，样本自证只缩小需读范围不能替代读。这正是本账 2026-10-19 观察（检索零命中被升级为「该纪律无载体」）所封死的推论方向。该条经三轮独立审核，终审后「键形量词」「载体范围」两项概念层遗留按 23 §12 未覆盖口径登记在 pitfall-4f6b2f2d。
3. `dfde6ff1852a62fb23c8358ef001f4539be63f5d`（fix(test): 批量判定区分未运行与零结果，2026-10-28）——实现层收口：`plugin/lib/test-run-report.js` 新增三态判定唯一入口 `classifyTestRun`（reported／count_unavailable／not_run），`mutation-check.mjs` 与 `drift-check.mjs` 的两份 `failCount` 副本删除改走同一入口，不可用终态单列并使整批结论作废；新增 9 例锁三态可区分、退出码不作运行证据。这是 06 §5 原始失效点（`return m ? Number(m[1]) : 0` 把「没跑」并入「零失败」）的实际修复。

核验（2026-10-28）：① 06 §5 与 §6 条文均在 HEAD（`specs/06-Code 实践与测试规范.md`，§7 验证表「批量判定的零值歧义」「删除后的下游清理」两行同步在册）；② `classifyTestRun` 在 HEAD（`plugin/lib/test-run-report.js`），两脚本副本已删；③ `plugin/test/test-run-report.test.mjs` 九例与 `retired-params.test.mjs` 五例在 HEAD。

边界（如实声明）：本笔只主张本账**两次实测观察所落的形态**已被封死——(a) 批量判定脚本把「没跑」并入「零结果」，(b) 检索零命中被升级为「实体不存在」。不主张「一切否定性推论已被机械挡住」：产物覆盖性判定（日志时间戳对应当前进程、事件类型确实落盘）在一般排查场景仍靠 AI 自律，无通用机械门禁；06 §6 的「键形枚举由操作者认知决定」边界（想不到的写法不会进未覆盖登记）是该条自身登记的概念层遗留，不因本销账而消失。
