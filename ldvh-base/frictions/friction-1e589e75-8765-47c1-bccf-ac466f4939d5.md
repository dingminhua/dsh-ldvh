# 以产物缺席作否定判据致连续错判

## 现象
本轮两次把「在所读产物中查不到某事件」直接当作「该事件从未发生」的判据，而两个产物（插件日志、会话文件）实际都不覆盖被判现象，两处均在事后被自证为不成立。

## 入账依据
可归因性：材料内同一轮出现两次同型误判且均被自纠。(a)「Zero probes — meaning `installChild` **never ran**. The guard already rejected the subagent.」紧接下一行即被「The log is stale (Sep 29) — not the running host's.」推翻——产物根本不覆盖当前进程。(b)「Confirmed: the trigger requires `agent/turn-stopping` + `agent/status idle`. The subagent session has **no `agent/status` events** — so it can't be from there.」被隔数轮后的「`agent/status` **不写进会话文件**」推翻——产物不记录被判事件本身。两次失效机制同一：所读产物未覆盖被判现象，而「查不到」被直接当成「未发生」。第二次的误判支撑了后续数轮排查方向，故不是偶发手误而是稳定复现的判据缺失。预期改善：若「未在产物中查到」与「未发生」之间必须先建立产物覆盖该现象的证据（日志时间戳对应当前进程、该事件类型确实落盘、该文件确含同类记录），则此类否定性判断在本地排查中不再依赖事后自纠回收，也不必等到下一轮才推翻已据以推进的中间结论。
