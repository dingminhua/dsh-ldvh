# 子代理引文落在切片窗口外致运行空转

## 现象
子代理用 fork 继承主控上下文后，引文取自切片窗口之外的会话文本，落地侧引文校验据此连续三次判定不成立，10 次运行中 3 次空转。

## 入账依据
重复出现——本次材料中同一形态已发生三次（21:23:34、21:26:00、21:44:42），机制总账 10 次运行中 3 次因该形态 stopped，非单次卡顿；三次引文的出处经核查分别落在主控会话文本（42 次 / 21 次 / 28 次出现），而不在机械切片窗口内。可归因——根因在 provider 选型与 prompt 第 135 行的组合：fork 继承完整主控上下文，子代理据此判断「系统性」是设计意图，但同一上下文也使其无法区分「窗口内材料」与「已处理的更早内容」，于是引文取错处；落地侧 verifyQuotation 逐字核对只是把该失效如实暴露，它本身无误。修了会改善什么——若执行体只被授予切片窗口（spawn 而非 fork）并以显式清单交付候选账目的 phenomenon 供比对，则引文必然落在窗口内，3/10 的空转消失，且 same-obstacle 判定首次具备可发生的前提（本次窗口内该形态仍在持续，同一阻碍已被观察到两次以上却因落空而未累计）。本次材料存在长度截断，仅就 turn 47–48 所见部分作出本判断，未据此断言窗口外的运行情况。
