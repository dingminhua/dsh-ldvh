# 事实对象载体内聚校验后置

## 现象

写 Spark/Pitfall 等事实对象时首次提交被载体内聚与载体结构校验拒绝，需按规范原文重新对齐 frontmatter 与正文后才通过。本次会话内命中 5 次同一机制（Spark 3 次：正文重复 H1、`summary` 未在正文逐字出现、结构拒绝；Pitfall 2 次：无 `urls` 时多写「证据」段、`scope` 用中文引号与 frontmatter 不一致），均发生在首次受控写入，每次代价是一轮重写后才落盘。

## 入账依据

三条件逐项核对：

**重复出现**——本次会话内 5 次命中同一机制，非单次卡顿：Spark 受控更新被拒 3 次（`spark/body_invalid` 正文 H1 重复、`spark/coherence_invalid` 当前理解段未逐字含 `summary`、结构问题），Pitfall 受控创建被拒 2 次（`pitfall/body_invalid` 无 `urls` 却含「证据」段致 H2 段数不符、`pitfall/coherence_invalid` 影响与适用范围段未逐字含 `scope`）。五次拒绝均由同一类规则触发，属证据等价的重复性。

**可归因**——机械校验由 `20 §14.1`、`23 §14.1`、`26 §14.1` 的类型特有验证表定义，校验时机在写工具（`spark-write` / `pitfall-write`）的提交阶段；相关不变量（正文自 H2 起、H1 由 Code 从 title 生成、frontmatter 是唯一权威文本且对应段须逐字包含、条件段与 `urls` 共现）散居各类型 `§8` 字段契约与 `§14.1` 验证表，按 `01.Att.03 §4` 属 L3/L4 披露层，构造对象时通常不在视野。

**修了会更好**——若这些不变量在构造阶段前置可见（写工具 schema 声明，或创建提案模板列出核对项），首次通过率提高，重写轮次减少。**修复不改变任何机械校验的强度**——不是放松校验以换取通过，而是把同一组不变量提前告知。

## 处置

**缓议理由（2026-09-14，Human 判断）**：本账目的类型归属不成立——它记录的不是「实际工作流中的重复体验」（26 §10 摩擦来源定义），而是 LDVH 体系本身的结构缺口。规范 `§14.1` 的校验规则完备、正确、机械强度恰当，并不存在「待修的阻碍」；阻碍感来自规范暴露顺序与校验时机的错位，属**系统未完善**而非摩擦。据此本账目的**内容已就地更正**：入账依据第三项改以「构造阶段前置提示」为改善方向（原文曾表述为校验时机问题），并保留三条件核对的完整证据。
