# 预检分块错位致报错位置与文本结构不符

## 现象
校验器连续两次以「summary 每个块都必须由 ### 标签开场」同一规则拒绝，且报告指出的 block #3/#5/#7 与文本实际段落结构错位一整段，使按规则修正无法收敛。

## 入账依据
可归因性：报错位置由校验器自身的切块逻辑产生，与提交文本的段落结构不一一对应，属机械侧的定位失真，非文本内容问题（同一规则下按指示修改两次仍被拒）。修了会更好的预期：若分块与文本结构对齐，报错可定位到真实段落，修改即可收敛。

补充观察（2026-10-19T14:27:06.653Z）：材料明确指出「校验器与提交文本的块划分口径不一致」，并给出拒因 `block #3 / #5 ... every block after the first must open with a fixed head` 而提交文本只有 3 个块；这正是既有 friction-2c52306f「预检分块错位致报错位置与文本结构不符」的同一阻碍，非新条目。
