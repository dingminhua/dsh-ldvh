# 提交消息与内容严重不符，约110行实际变更未声明

## 现象
commit 473d670 对 Att.01 的提交消息只声明 4 类改动，但实际 diff（113+/104- ≈220 行）另含约 110 行未声明变更（新增术语行、章节号更替 §5.1→§6.1 与 §7.1→§8.1、承接方更正、整段重写等），提交消息与 diff 逐条不对应。

2026-10-13 复核追加：本条与 8e321438（跨组拆分提交时重建文件丢失既有改动）**根因相同而方向相反**——8e321438 是同一文件内的他组改动被**丢失**，本条是同一文件内的他组改动被**吸收**进一个以别事为主题的提交。两者共同指向「宿主对同一文件内跨组改动无机械分离保障」这一根因。经 26 §6.2 语义比对判定二者为**同根异现**（现象不同：丢失 vs 申报失实），故分立账目、互不替代，各自独立累积计数。

## 入账依据
提交消息列出的每个 - 列表项须与 diff 逐条对应、不得遗漏实际存在项（specs/09 §5），而该提交消息遗漏约 110 行实际变更；材料明确把本阻断归为 8e321438 的「同族」，但现象本质不同（8e321438 是重建文件丢失既有改动，本次是提交消息遗漏声明实际变更），属同根异现，账本尚未独立记录；修好消息/纪律可避免此类申报失实与其连带风险。

**为何机械校验未拦住（2026-10-13 复核补充）**：`validation/staged_path_uncovered` 的机械口径是**路径级**——只要 `关键变更:` 中有一条 `- ` 项提到某路径，该路径在候选 Index 中的**全部** diff 即算「已覆盖」（`plugin/lib/commit-validation.js` 的 `staged_path_uncovered`／`key_change_unmatched` 两条规则均以路径集合比对，不比对文件内变更项）。故本条「一条项声明了该文件十余类改动中的四类」在路径级校验下**必然通过**。这与 09 §5.1 的**条内**义务（「不得遗漏 diff 中实际存在的变更项」）之间存在粒度落差：规范要求逐条对应，机械校验只能到路径级。修了会更好的方向是补一层不依赖语义的机械信号（如按文件统计增删行数与项内声明规模的偏离告警），或明确该义务的机械不可达边界并交由独立审核承接。
