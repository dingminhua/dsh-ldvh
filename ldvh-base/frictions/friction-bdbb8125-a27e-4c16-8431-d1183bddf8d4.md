# 运行实例旧模块致注入读数不可判读

## 现象
经验 L0 索引在注入中报告「本项目当前无 active 经验（0 条）」，而同一语料实际有 68 条 active 经验。

（来源：109）
2. （2026-11-11T10:48:50.762Z，session-d6c30109-0084-4b8d-a0e2-6802815fccb8 @ 7）运行中的宿主还加载着旧模块，这一回合又走了纯读取路径，所以仍报 0
（来源：7）
3. （2026-11-11T12:01:13.255Z，session-d6c30109-0084-4b8d-a0e2-6802815fccb8 @ turn 5..7）你现在看到的「经验 · 0 条」就是那个缺陷本身：运行中的宿主还加载着旧模块
来源：本次材料 turn 7 assistant 回复（主控会话，会话 id 未在材料中给出）；同轮 user 注入的 L0 索引行「【经验 · active Pitfall（23 §12 按需索引）】本项目当前无 active 经验（0 条）。」

## 入账依据
运行中的宿主仍加载旧模块时，经验注入行会显示「本项目当前无 active 经验（0 条）」，而同一语料实际有 68 条 active 经验。该 0 来自计数接缝的 `?? 0` 兜底：经验已移出常驻枚举，找不到对应段就落到 0，于是「运行实例未装载新计数」与「本项目确实没有经验」在读数上完全同形。后果是每次在会话内验证经验索引的进展，都要先跨过一层无法判读的读数；不重启宿主就无法区分「修复未生效」与「本类为空」，而重启又不是会话内可完成的动作。同组已有两例同类观察，这是反复出现的系统性阻碍，不是单次卡顿。
