# 渲染层未注册新决策值致静默结果丢失

## 现象
把关请示的 renderEnvelope 只注册 review 与 skip 两个分支，新增的 silent 决策落进 else 被渲染成「未发起询问」，其 notice 从未出现在模型可见的输出里。

### 该阻碍的历次观察（3 次，逐字引证）
1. （2026-11-04T14:27:22.292Z，session-5d9e6f62-9b7b-4e36-b3c4-9397ca666a18 @ 16）工具调用成功，但只返回了一行摘要，checked、stale 等字段都消失了。
（来源：16）
2. （2026-11-12T22:27:21.104Z，session-72aa14f9-f7c1-4a6a-9f79-bb59e4f81d56 @ 18）确认：`renderEnvelope` 里**没有任何** `review-ask` 分支。
（来源：18）
3. （2026-11-13T14:38:43.581Z，session-d3e26128-b9f5-45d9-bf4a-4bca84a6ea87 @ 5）`renderEnvelope` 只处理 `review` 和 `skip`，`silent` 落进 else 被渲染成「未发起询问」，`notice` 从头到尾没有渲染。
（来源：5）

## 入账依据
可归因：缺口落在 review-ask 输出渲染接缝的 decision→分支绑定——新增档位时渲染层不报错、而是静默走 else 兜底，模型侧因此只看到错误的档位描述并丢掉 notice；修好（补分支并对 decision 取值做穷尽性校验）后，静默执行的痕迹才可能真实到达模型，否则「静默不等于无痕」在真实路径上无法执行。
