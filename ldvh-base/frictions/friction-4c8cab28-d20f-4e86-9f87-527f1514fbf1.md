# 子代理独立会话致冷却锚点分家

## 现象
冷却锚点与派发计数按 session id 分键存储，摩擦发现派生的子代理带有独立 session id，锚点因此分家：配置为 600 秒的最小间隔，在连续四次派发中实际只隔 172、67、1、63 秒，而运行痕迹每次均记 cooldown 通过。

## 入账依据
材料中两处同指一事且互为因果：「**根因找到了**：出现了**两个 session 键**。会话 id 变了，冷却锚点跟着分家」与「最小间隔设的是 600 秒，实际间隔只有 1–172 秒。冷却**根本没生效**」，故可归因于「按 session 分键的运行状态遇派生会话即分裂」这一形态，而非单次异常。与既有「重启割裂观察区间致累计计数失真」虽同属状态分家，但分裂主体（子代理会话 vs 进程重启）、受影响状态（冷却锚点与派发计数 vs 水位累积器）、可观察症状（最小间隔失效 vs 累计计数失真）三者均不同，修其一不防其二，故不判为同一阻碍。预期改善：若分键判据纳入对派生会话的排除，「约束未生效却在痕迹里显示生效」这一形态在本仓库其它按 session 分键的运行状态上不再重现。

补充观察（2026-10-11T06:13:07.322Z）：本次材料是「补 parentSession 判据」这一轮的取证与验证记录。其核心一行给出量化取证：本宿主 48 个会话（44 根 + 4 子代理）的 origin 全部为 null，故 install() 里 `origin === "subagent"` 的子代理识别恒为假——护栏从未生效；子代理因此被按根会话完整 install、挂上 idle 检查点触发器，并取得自己的会话键读写水位与冷却状态，冷却锚点随之分家。这与既有账目「子代理独立会话致冷却锚点分家」是同一阻碍：本次材料给出的是该阻碍的根因（判据字段在宿主上不存在）与修法（补 parentSession 判据）及其验证，属对同一阻碍的补充观察，不是新阻碍。另注：材料因长度上限被截断（assistant 段在 dsh-ui 围栏中途断于「parentS」），故判断仅就可见部分作出；截断发生在本次核心取证行之后，不影响上述取证的可核对性。
