# 决策基线在注入面缺席

## 现象
在预算 600–1199 字节档以及被判为纯读取／无主题词的回合里，整段 active ADR 决策基线完全不进入注入面（ADR 0 条且无任何痕迹），只由数据层承载。

### 该阻碍的历次观察（3 次，逐字引证）
1. （2026-10-31T17:45:15.240Z，session-9d57cb22-0d6e-42c0-a4b0-b9aa4e0f6b17 @ 15）固定文本随语料（基线 6→7 条 ADR）和披露行（名额行、摘录行）持续长大，2400 字节硬顶没动——这次被顶穿只是时间问题。
（来源：15）
2. （2026-11-02T20:17:04.879Z，session-583ff38c-5f35-449c-95e5-d93c27776023 @ 4）如果哪天有人把预算调到 800，2 条法定决策就会静默从注入面消失（数据层还在，但 AI 看不到了）
（来源：4）
3. （2026-11-02T21:11:50.317Z，session-583ff38c-5f35-449c-95e5-d93c27776023 @ 6）22 §12 要求「相关行动开始前必须召回并核对 active ADR」。此前有两个回合里它其实看不见：预算极小，或本回合被判为纯读取／无主题词。
（来源：6）

## 入账依据
22 §12 要求相关行动开始前必须召回并核对 active ADR；这些回合的注入面无任何基线痕迹，属可归因于注入装配面的系统性缺口，修好（补仅基线注入路径并并入既有披露行）会让该类回合重新可见，故可期待修后更好。

## 处置

解药 `8fab5aa808b32ca1bda30bbe51f8f1ef179294ca`（ADR 决策基线在极小预算与无词法候选回合下仍可见）。

**两处缺口分别怎么补的**：
1. **预算极小档（600–1199 字节）**：基线整段让位时不再静默。不新增行（新增必超预算），而是把痕迹**并入既有截断披露行**并改用紧凑措辞，使净字节不高于原行——模型侧看到「基线 N 条未展开」且回指 22 §12，数据层仍承载完整基线。让位不等于丢弃，但也不再无声。
2. **纯读取／`no_tokens` 回合**：新增只注入基线的路径 `baselineOnlyInjection`，与词法候选层解耦。22 §12 的义务召回属 02 §9.1 F1（枚举指定对象集合），本就不依赖词法命中；旧实现让整行注入随词法候选一起消失，等于把法定决策的可见性绑回当回合用词。归因由独立字段承载（`baselineOnlyCause`：`excluded-by-34-6` 与 `recall/no_tokens` 两值不混同）。

**核验（本轮实跑，非复述历史）**：
- 直接用 `buildRecallInjection` 打本仓真实语料：预算 600／800／1199 三档均 `inject: true`、`decisionBaseline.items.length = 2`、文本含「基线 N 条未展开」痕迹且回指 22 §12；1200／2400 档起段头「【决策基线 · active ADR」直接出现。
- 纯读取与无主题词两条：`看看这个文件`（cause=`excluded-by-34-6`）、`为什么这里不对`／`怎么办`（cause=`recall/no_tokens`）三例均 `inject: true`，渲染文本含「【决策基线」段头，基线条目逐条可见。
- `plugin/test/recall-injection.test.mjs` 83/83 通过，其中「22 §12：纯读取回合仍须带出决策基线」「22 §12：no_tokens 回合仍须带出决策基线」「22 §12：无可披露基线时不注入（不得退化为无条件注入）」三条正是本次判据。
- plugin 全量：2867 通过 / 0 失败。

**观察侧**：末次观察 `2026-11-02T21:11:50.317Z`，解药落地 `2026-11-03T05:05:00+08:00`（= 2026-11-02T21:05:00Z）——解药早于末次观察 6 分 50 秒，该次观察记录的是修复前状态（当轮注入仍走旧路径）。此后至今无同型观察。

**边界（如实声明）**：① 极小预算档补的是**痕迹**而非完整基线——「基线 N 条未展开」告诉模型基线存在且回指 22 §12，条目正文仍不可见，须自行 `ldvh_adr_list` 取；这是预算约束下的取舍，不声称等于完整可见。② 本单不改 `34 §6` 排除条件本身，也不改预算档位划分。③ 渲染字符上限与字节预算的换算关系未在本单复核，属另一条账（若将来再被顶穿应新开账）。
