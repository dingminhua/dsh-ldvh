## 0. 上位规范

`specs/00-理念与构成.md` 定义 Web 的价值、信息来源和 Human/AI 职责边界；`specs/05-事实模型基础规范.md` 定义当前事实源、精确读取、派生信息和受控写回边界；`specs/08-Web 呈现与交互规范.md` 是 Web 呈现、交互、来源回指与验证要求的直接规范；`specs/21-WorkCase-工作项.md` 唯一定义 WorkCase 当前字段、状态、阶段和派生投影边界。

本文只定义 `web/` 参考实现的页面级设计约束、组件风格、布局规则和交互细节，不替代上述规范、具体事实类型规范、行动模板或事实源对象契约。

当本文与当前 specs 或具体事实类型来源存在冲突或解释不一致时，以当前规则源为准；Web 页面、API、组件和 `web/docs/` 不得反向新增字段、状态、Human Gate、事实判断或机械契约。

## 1. 全局设计约束

### 1.1 技术栈

| 层 | 技术 |
|---|---|
| 框架 | React 18 + TypeScript |
| 样式 | Tailwind CSS（darkMode: class） |
| 构建 | Vite（端口 5173，strictPort: true） |
| 后端 | Express 4（端口 3001） |
| 路由 | React Router v6 |
| 图标 | lucide-react |
| Markdown | react-markdown + remark-gfm |
| 代码高亮 | react-syntax-highlighter（Prism + oneDark） |

### 1.2 主题系统

- 三态切换：system / light / dark
- CSS 变量使用 RGB 通道值（如 `248 249 251`），支持 Tailwind 透明度修饰符
- 所有颜色通过 `ldvh-*` 命名空间引用

### 1.2.1 当前确认边界

当前 Web 设计已确认对象页、提交页、ProjectFiles、扩展阅读、移动端抽屉、复制语义和 i18n 规则。最前面第一入口已确认可见名为“聚焦 / Focus”，内部概念和源码仍使用 Cognition Center；其余前置入口的最终名称、顺序和信息架构仍未完全确定。实现和文档可以沉淀它们必须遵守的通用组件、布局、复制和 i18n 契约，但不得把其余临时入口文案、顺序或信息架构写死成最终产品结论。

在其余入口未确认期间，任何相关设计或实现变更都应满足：

1. 不改变左侧主导航作为主导航的事实；
2. 不影响已确认的对象列表、对象详情、提交记录、ProjectFiles 和右侧扩展阅读规则；
3. 不新增事实源、状态机、对象类型、写入白名单或 Human Gate 结论；
4. 不用入口 tab 的临时文案反向定义 i18n key、路由语义或长期页面职责。

### 1.3 国际化

- React Context 轻量实现，localStorage 持久化
- 所有用户可见 UI 文案必须通过 `useI18n()` 的 `t()` 获取；组件内不得直接写中文或英文句子
- 状态文本必须通过 `getStatus()` 获取，不展示 raw status 值
- 标题必须通过 `getLocalizedTitle()` 获取（优先 title_en/title_zh，回退 title）
- 字段名必须通过 `FIELD_LABEL_LOCALES` 或全局 i18n key 映射，不展示 raw snake_case 字段名
- 类型标签必须通过 `TYPE_LOCALES` 或 `nav.*` 映射，不展示 raw type 值
- 枚举值必须通过语义映射本地化，例如 `priority`、WorkCase `phase`、进展分组、工作项状态、复核结论和关闭分类；具体闭集只来自对应类型当前契约。
- 字段和枚举映射必须遵守对应事实类型契约：`priority` 只适用于 WorkCase 和 Spark；ADR、Pitfall 和 Study 不得因 UI 信号标签需要而展示或补写 `priority`；任何当前类型都不得补写未登记的 `importance`
- `priority` 属于轻量信号语言，不属于流程状态或告警；列表和详情中应使用弱边框、透明背景、短文本或点状提示，不得使用大面积实心色块、强告警色或影响卡片主边框来表达普通优先级
- 空状态、加载失败、占位动作、按钮、tooltip、面板标题和辅助提示都必须有中英文版本
- 对象身份区只显示更新时间，统一使用 `formatDateTime()`，格式为 `YYYY-MM-DD HH:mm`；若最新更新流水具有完整 `signature.agent_id` 和 `signature.host_environment`，必须以提交同款圆点样式紧随其后显示，且不得从对象字段或不完整签名推断。WorkCase 的 `reviewed_at`、`approved_at` 等用于辨识具体复核或批准事件的来源时间，必须完整显示原始带时区 RFC 3339 值，不得截断到分钟或丢失偏移量。事实源中的 `datetime` 字段必须记录至少包含小时和分钟的 ISO 8601 时间戳，不得写 date-only 后由 Web 补出 `00:00`；相对时间由 API/i18n 提供，不在组件内拼接
- 对象详情页和右侧扩展阅读区的对象身份头部必须复用同一套字段顺序：`类型标签 + 状态标签 + object-id`、标题行、更新时间（可带更新流水署名）、右上复制入口；状态不得漂移到右上操作区或另起 MetaChip 行
- 允许例外：代码块、YAML 原文、文件路径、命令、ID、哈希、第三方 Markdown 内容和事实源正文；这些内容作为事实数据展示，不由 UI 翻译

**新增/修改页面的多语言检查清单：**

1. 切换到英文后，页面框架、按钮、筛选、状态、字段名、空状态、错误兜底和 tooltip 不得混入中文 UI 文案。
2. 切换到中文后，状态、枚举、分类和字段名不得展示 raw snake_case / raw enum；未知值可回退为原值，但必须使用元信息样式或 tooltip 保留诊断属性。
3. API 派生字段属于 UI 枚举时必须前端映射，例如 WorkCase `progress_group` 和 `progress_step`；映射不得改写事实源原值或成为第二字段契约。
4. API 事实正文属于证据内容时不翻译，例如校验器 message、文档标题、Git message、Markdown 正文、路径和命令输出。
5. 不允许在 JSX 中用 `locale === 'zh' ? '中文文案' : 'English copy'` 临时分支；语言名称、枚举映射等也必须进入 i18n key 或显式 mapping 表。
6. 新增字段、重命名字段或调整字段适用对象时，应同步检查 `web/src/utils/fieldFormats.ts`、`web/src/utils/objectSignals.ts`、`web/src/i18n/locales.ts` 和对应页面文档，不得用 Web 文案反向定义对象契约。

**事实正文不翻译边界：**

以下内容属于事实数据或审计材料，不进入 UI 翻译流程，也不得因当前语言切换而改写：Markdown 正文、YAML 原文、Git message、commit body、校验器 message、命令输出、文件路径、URL、对象 ID、commit hash、代码块、第三方 Markdown 内容和事实源英文索引标签。Web 可以翻译围绕这些事实数据的 UI 标签、节点标题、tooltip、空态、错误态和帮助说明，但不得翻译事实正文自身。

**英文长文案约束：**

英文环境下按钮、tab、状态、tooltip 和空态文案通常长于中文。所有新增布局必须允许英文换行或合理压缩，不得用只适配中文的固定宽度、固定按钮文案长度或不可换行标题。tab 与按钮可以限制最大宽度并使用 `truncate`，但主阅读标题、对象标题、提交描述和事实正文不得用截断替代阅读。

### 1.4 排版系统

所有页面必须使用语义排版类表达文本角色，不再在业务组件里临时选择字号。除特殊图表、代码高亮和第三方 Markdown 样式外，新增 UI 不允许直接使用 `text-[10px]`、`text-[11px]` 等任意字号。

| 页面说明 | `ldvh-page-subtitle` | 14px / 24px | 400 | 页面标题下方说明 |
| 区块标题 | `ldvh-section-title` | 14px / 20px | 600 | 页面大区块标题 |
| 卡片标题 | `ldvh-card-title` | 14px / 20px | 500 | 卡片、面板、列表项标题 |

| 卡片判断项标题 | `ldvh-card-decision-title` | 13px / 20px | 600 | 决策型 Card 内目标、覆盖、排除、成功标准等判断项标题 |

### 1.5 固定切换区

- 页面中承担视图切换、对象切换、返回、关闭、上一个/下一个等导航职责的顶部控制区，不得随长正文滚出当前滚动容器。
- 中间主内容区域如存在 `tablist`、对象详情身份区或同等切换入口，应使用当前主滚动容器内的 sticky 顶部区域；内容正文在其下方继续滚动。
- 右侧扩展阅读区和移动端底部阅读面板的头部控制区必须固定在面板顶部，面板正文使用独立滚动区域。
- sticky / fixed 控制区必须有不透明或半透明背景、合适的 `z-index` 和底部分隔线，避免滚动内容穿透或遮挡切换按钮。
- 移动端底部阅读面板不额外占用单独拖动把手行；标题区域本身承担拖动职责，导航按钮和关闭按钮保留在同一固定控制区。有标题时标题显示在可拖动区域内，无标题时该区域显示居中拖动把手。

**约束：**

1. 页面级标题只使用 `ldvh-page-title`，面板内标题不得使用页面级字号。
2. 卡片、列表、表格内文本默认使用 `ldvh-body` / `ldvh-body-muted`，不要在局部混用 `text-sm` 和 `text-xs` 表达同一语义。
3. 强调卡片标题只用于正文含多个独立判断区、需要维持“对象身份高于区块标题”层级的 Card；不能用于普通单行列表项，也不能代替页面或详情标题。
4. 卡片判断项标题和正文只用于 Card 的有限行数扫描窗口；详情页和阅读面板仍使用各自正文层级，不得随之缩小。判断项正文即使使用 12px，也仍是事实正文，不得改用弱色、mono 或辅助标签语义。
5. `ldvh-caption` 只用于辅助信息，不承载主要内容；如果用户需要阅读或点击，至少使用 `ldvh-body`，或在前述决策型 Card 扫描窗口中使用 `ldvh-card-decision-body`。
6. `ldvh-chip` 只用于短标签，不用于长句、按钮主文案或段落。
7. 筛选、视图切换和同层 tab 控件统一使用 `ldvh-tab-list`、`ldvh-tab-button`、`ldvh-tab-button-active` 和 `ldvh-tab-button-idle`；tab 内数量使用 `ldvh-tab-count` 并继承 tab 文字字体、字号和字重，不得在对象页、提交页或工具页局部发明胶囊、分段控件、计数间距、独立数字字体或其他 tab 外观。
8. 数字指标只允许使用 `text-xl` 或 `text-2xl`，并限定在 Metric/Stats 组件内。
9. Markdown 阅读区使用 `MarkdownPreview`，基于 `github-markdown-css`，正文基准为 14px；表格、代码块、引用块和任务列表样式由 `index.css` 中的 `.ldvh-markdown-preview` / `.ldvh-inline-markdown` 统一控制，不得在业务组件里手写 Markdown 标签样式。
10. 普通对象身份的绝对时间统一使用 `formatDateTime()`，显示为 `YYYY-MM-DD HH:mm`；WorkCase 的 `reviewed_at`、`approved_at` 等复核或批准事件时间除外，必须完整显示来源中的原始带时区 RFC 3339。date-only 只允许出现在字段契约明确为 `date` 的事实中，不能作为 `datetime` 字段的正常输入。
11. UI 字距保持默认 0，不使用 `tracking-*` 做装饰性字距。
12. 数字序号只表达来源已经成立的步骤、优先级、排名、依赖顺序或其它先后语义；没有先后关系的同级集合统一使用圆点。数组位置、稳定 ID、字段顺序或显示排序不能成为编号依据；来源 Markdown 已明确选择列表类型时忠实保留。

### 1.5 布局

- 单一 App Shell：左侧导航 + 中间主内容 + 右侧扩展阅读区。
- 主导航固定在左侧，不提供顶部导航、对象类型标签页或底部 Tab 作为替代主导航。
- 左侧导航在 `sm` 及以上默认展开，可折叠为 56px 图标 rail；折叠状态写入 `localStorage`。Compact（小于 `sm`）固定保留同一条 56px 图标 rail，不能因宽度移除全局导航，也不在该最小态另设展开控件。
- 折叠/展开控件位于左侧导航头部，不悬浮在主内容中线。
- 中间主内容使用 `ldvh-page-frame` 或等价页面框架，所有宽度统一使用 `p-6`。
- 右侧扩展阅读区属于 App Shell，不属于单个页面内部卡片；对象引用和文档引用优先在扩展区打开。
- 右侧扩展阅读区遵循同一内容点击切换规则：首次点击打开，点击不同内容切换预览，再次点击当前内容关闭扩展阅读。
- 右侧扩展阅读区的对象内容必须与对象详情页同源：同一对象的字段顺序、字段标签、字段过滤和字段渲染不得在 `ReadingPanel` 中另起一套摘要实现。
- 对象列表页 `/objects/:type` 是主选择面，不保留右侧扩展阅读；从详情页或跨类型详情返回列表页时，App Shell 必须主动关闭扩展阅读区。
- 右侧扩展阅读区会改变主内容可用宽度，仪表盘、卡片组、列表组不得只依赖 `lg:` / `xl:` 视口断点决定列数。
- 密集卡片布局优先使用 `auto-fit + minmax()` 或容器查询，让列数由容器实际宽度决定；统计卡最小宽度不低于 192px，主面板卡片最小宽度不低于 320px。
- 页面最小宽度：375px（StatCounter 2025-2026 数据：375×812 占 4.23%，是当前在售最低 CSS viewport，对应 iPhone SE 2/3）。
- 设计基准：390px（iPhone 12~16 主力）/ 393px（iPhone 14 Pro~16 Pro）/ 412px（Pixel/Samsung 主力）。

**滚动所有权：**

- App Shell 根节点唯一拥有视口高度并使用 `overflow-hidden`；`html`、`body`、`#root` 不形成第二个文档滚动层，`#root` 固定覆盖视口。
- 中间主内容是页面纵向滚动容器；左侧导航只在自身条目溢出时纵向滚动；扩展阅读正文在面板内部独立滚动。三者不得通过鼠标滚轮互相推动，也不得令整个 Shell 位移。
- 左侧导航继承 App Shell 的实际高度，不能再次声明一个独立视口高度；展开态、Compact 图标栏和底部工具区不得产生横向滚动条。
- 业务面板按真实内容高度收口，不能用 `min-height: 100vh`、剩余视口填充或隐形占位把页面延长；页面内容结束后不得仅因侧栏滚动或模块展开留下可继续滚动的大块空白。

**当前实现的硬约束：**

1. 不把主导航改回顶部 Tab；对象类型切换由左侧导航承载。
2. 不把右侧扩展阅读区改成对象列表；扩展区只保留上一个/下一个访问对象导航和当前内容阅读。
3. 不把右侧扩展阅读区做成只开不关的单向入口；同一入口再次点击必须关闭当前扩展阅读。
4. 不让对象列表页继承详情页留下的扩展阅读状态；回到列表页时必须收起右侧区域。
5. 不把对象详情页改成 YAML 查看器；由精确读取字段重建的 YAML 数据只作折叠辅助，不替代原始载体或主阅读。
6. 不在 `ReadingPanel` 里维护独立的对象字段顺序、字段 label map 或字段渲染器；扩展阅读只能复用详情页阅读布局或详情页字段组件。
7. 不在页面内部再创建一套浮动侧栏、二级全局导航或营销式首页。

### 1.6 移动端适配策略

采用一套页面，不做独立移动站，也不维护独立的移动端信息层级、字号、间距、字段排列或卡片样式。窄屏只允许两项 App Shell 级结构变化：

1. 小于 `sm` 时，左侧主导航自动收缩为 56px 图标栏；不增加底部主导航、顶部对象类型 Tab 或另一套展开入口。
2. 小于 640px 时，桌面右侧次级阅读切换为底部阅读抽屉；内容来源、字段顺序和阅读组件保持与详情页同源。

除此之外，页面和业务组件在所有宽度使用同一套基础样式。标题、弱信息、字段、操作与 Card 不因窄屏单独增高、缩小、隐藏、换序或改变密度。底部阅读抽屉为拖动和触摸保留的头部与按钮命中区属于抽屉壳层本身，是唯一允许的控件尺寸例外，不能传播到页面模块。通用 `flex-wrap`、`auto-fit + minmax()`、内容断行和滚动容器仍可依据真实可用宽度自然工作，它们用于防止溢出，不构成第二套手机版。`xl` 等宽屏工作台增强可以保留，但不得反向引入 Compact 专属呈现。

### 1.6.1 移动端已确认规则

移动端策略属于已确认设计基线，不随其余入口 / tab 的产品命名变化而变化：

1. 只有 `Layout` 的图标栏切换和 `ReadingPanel` 的底部抽屉切换可以使用 Compact 断点。
2. 底部阅读抽屉顶部控制区固定，正文独立滚动；标题区域承担拖动职责，不额外增加拖动把手行。
3. 页面与通用业务组件不得使用 `sm:` / `md:` 建立移动端专属视觉或信息结构；需要防溢出时使用与设备类型无关的自然换行、容器网格和局部滚动。
4. 375px 是最小宽度基线；在该宽度下仍必须保留完整身份、标题、状态、事实回指与操作入口，不通过隐藏弱信息制造“手机版摘要”。

### 1.8 数据源

所有页面数据来自当前工作树 `ldvh-base/` 目录下的 V4 事实源；Web API 必须限定到已配置的唯一管辖项目和实际 worktree，并保留读取范围、来源和不可用状态。页面派生视图不成为事实权威。

### 1.8.1 统一组件契约

以下组件契约是 Web 已确认的跨页面设计语言，新增页面或改造旧页面应优先复用，不得在业务组件里重新发明局部变体：

| 组件族 | 必须使用或遵守 | 边界 |
|---|---|---|
| Tab / 筛选 | `ldvh-tab-list`、`ldvh-tab-button`、`ldvh-tab-button-active`、`ldvh-tab-button-idle`、`ldvh-tab-count`；所有宽度使用同一紧凑高度 | 只表达同层筛选或视图切换；不得替代左侧主导航，不按窄屏单独改变高度 |
| 卡片网格 | `ldvh-section-grid` + `ldvh-panel`，容器宽度驱动列数 | 不使用表格替代对象扫描；不使用营销式大留白或英雄区 |
| 对象身份头部 | `类型标签 + 状态标签 + object-id`、标题、标签、更新时间（可带更新流水署名）；精确读取取得可消费 `canonical_path` 时才在右上提供复制对象路径 | 详情页和 ReadingPanel 必须同源；候选列表卡不承诺源路径，但可在状态标签旁复制稳定 object ID；状态不得漂移到右上操作区 |
| 阅读节点 | 小圆点标题、整行点击、`ChevronDown` / `ChevronUp`、Markdown 内容区 | 已定义专用阅读布局的对象不得回退到字段卡片堆叠 |
| 关联行 / 引用行 | 左侧语义图标和标题/路径/URL，右侧固定复制入口与扩展阅读入口 | 整行打开扩展阅读；复制入口 `stopPropagation()`，只复制不导航 |
| 复制按钮 | `CopyPathButton`，`Copy` 成功后短暂 `Check`，tooltip 按复制内容语义命名 | 不用“复制完整路径”覆盖对象、文档、链接、引用和提交 |
| 扩展阅读 | 桌面右侧面板，Compact 底部抽屉，顶部控制区固定，正文独立滚动 | 不维护第二套对象摘要，不作为对象列表导航 |

### 1.9 工作对象卡片通用交互

- 只有字段级直读返回 `read_status: readable` 与 `canonical_path` 的对象详情、引用和预览，才提供复制对象路径图标。候选发现卡、列表派生行和未能读取的对象不承诺也不伪造源路径；消费 Helper 精确读取结果时，仍按 05 的 `check_status` 判断其正文可消费性。
- 复制入口统一使用 `CopyPathButton`，图标为 lucide `Copy`，复制成功后短暂切换为 `Check`。
- 对象复制内容必须等于精确读取返回的 `canonical_path`。`path`、`data.path`、`target`、对象 ID 和路由定位值都不得作为缺失时的替代来源。
- 所有事实对象的候选列表 Card 在状态标签右侧提供“复制对象 ID”；它只复制稳定 `object_id`，不暗示源路径已经读取，也不替代详情、引用或预览中的“复制对象路径”。
- 复制按钮必须按复制内容语义命名：对象为“复制对象路径”，文档为“复制文档路径”，URL 为“复制链接”，普通引用为“复制引用”，提交卡片为“复制提交上下文”，提交详情为“复制提交 hash”。不得用“复制完整路径”覆盖所有场景。
- 复制按钮只使用 icon + tooltip，不在卡片内增加解释性文字。
- 复制按钮默认使用透明 ghost icon，不使用常驻边框或重底色；只有 hover、focus 或复制成功时给轻量反馈，避免在状态徽章和辅助阅读图标旁边抢视觉层级。
- plain 列表行、对象引用行和无状态背景的关联材料行中，复制图标、扩展阅读图标、进入箭头等操作 icon 必须保持同一套中性 ghost 表现；对象类型色只用于左侧类型识别、ID 或短标签，不扩散到右侧操作 icon。
- 只有当行本身已经处于明确状态色背景中，例如 WorkCase 阻塞项、Human 待确认项或明确风险行，右侧操作 icon 才允许继承该行状态色；此时同一行内复制图标和扩展阅读图标必须颜色一致。
- 进入箭头默认与复制图标同级，使用弱灰色；hover/focus 时可轻微位移并切换 accent 色，但不得常驻使用状态色抢占内容层级。
- 复制按钮点击必须 `stopPropagation()`，不得触发卡片跳转、右侧扩展阅读或选择对象。
- 当外层卡片需要点击且内部包含复制按钮时，外层不得使用 `<button>` 嵌套按钮，应使用可键盘触发的卡片容器。

### 1.10 工作对象语义设计语言

工作对象页面不是通用数据表，也不是 YAML 字段浏览器。页面设计必须先判断对象在 LDVH 工作链路中的语义位置，再决定信息层级、卡片结构和状态表达。

**当前已完善的五个基准模块：**

当前 Web 的设计语言以提交、研究、决策、火花、经验五个已经完善的模块为中心。后续修改这五个模块时，必须一起检查共同语言；改造其他页面时，应优先向这五个模块靠拢，而不是按单页重新发明卡片、标题、操作或折叠结构。

| 入口 | 路由 | 页面定位 | 必须共享的设计语言 |
|---|---|---|---|
| 提交 | `/changelog`、`/changelog/:hash` | Git commit records 证据追溯 | 筛选 tab、卡片网格、标题带、复制入口、扩展阅读入口、标准身份头部、圆点正文节点 |
| 研究 | `/objects/study`、`/objects/study/:id` | 报告阅读界面 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、关联区统一行 |
| 决策 | `/objects/adr`、`/objects/adr/:id` | 决策阅读页 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、Markdown 分段正文 |
| 火花 | `/objects/spark`、`/objects/spark/:id` | 待处理信息阅读页 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、闭环处置事实弱表达 |
| 经验 | `/objects/pitfall`、`/objects/pitfall/:id` | 可复用经验阅读页 | 对象列表卡片、状态筛选 tab、标准身份头部、圆点正文节点、非活跃原因弱表达 |

统一要求：

1. 列表页顶部切换区必须固定，使用 `ldvh-tab-list` / `ldvh-tab-button`，数字计数与文字同字体、同字号、同字重。
2. 列表主体使用 `ldvh-section-grid`，卡片允许一行多个；卡片标题必须完整展示，宽度不足时换行，不截断。
3. 候选列表卡右上角不伪造复制入口；已精确读取的卡片或预览可在右上角保留复制入口。如存在扩展阅读入口，应放在标题带、引用行或材料行右侧，复制与扩展阅读图标保持同尺寸、同中性 ghost 表达。
4. 卡片标题带使用弱背景、内圈边框和左侧语义短线；对象类型色只用于左侧识别，不扩散为大面积背景。
5. 普通对象身份时间使用统一格式：对象卡片和提交卡片底部右侧显示更新时间，并使用 `formatDateTime()` 绝对时间；详情页中的 `created_at`、`updated_at` 同样使用该格式。WorkCase 的复核、批准等事件时间必须遵守 1.3 的事件时间规则，完整显示来源中的原始时区 RFC3339，不得套用分钟级格式。
6. 详情页和右侧扩展阅读必须复用同一套身份头部和正文节点；不得出现“详情页一套、扩展阅读一套”的字段顺序、标题、折叠行为或正文样式漂移。
7. 右侧扩展阅读顶部导航栏不展示当前内容标题；内容标题只出现在正文身份区或文档正文中，顶部栏只保留前后导航、拖拽和关闭控制。
8. 主正文节点统一使用小圆点标题、整行点击折叠、`ChevronDown` / `ChevronUp` 图标和 `.ldvh-study-node-content` Markdown 阅读样式。
9. 复制内容必须服务 Human 与 AI 快速定位：已精确读取的对象复制完整 `canonical_path`，提交卡片复制完整提交上下文，提交详情复制 hash；候选卡不用导航值代替源路径。
10. 新页面或旧页面改造应先阅读 [`10-Web开发现状与设计语言基线.md`](./10-Web开发现状与设计语言基线.md)，判断目标页面和五个基准模块的关系。

**对象语义分工：**

| 对象 | 页面关注点 | 不应突出 |
|---|---|---|
| WorkCase | 当前情况、目标与范围、成功标准、当前计划与工作项、复核/批准/处置、结果与验证说明、关闭提案或终态处置 | 命令流水、推理过程、通用证明包、额外历史状态或把内部工作项提升为一级对象 |
| 工作项 | WorkCase 内部的局部目标、预期结果、依赖、当前恢复、阻塞和终值 | 一级对象导航、独立事实源、命令步骤或独立关闭判断 |
| 决策 / 踩坑经验 / 火花 | 决策、可复用踩坑经验、未计划化信息的阅读和追溯 | 强行映射成执行进度 |

**身份区：**

1. 身份区回答“这是什么对象”，不是摘要卡，也不是状态看板。
2. 标题永远是身份区第一视觉层，使用 `ldvh-page-title`；辅助数字、ID、时间、状态说明不得超过标题层级。
3. ID、路径、时间属于定位信息，使用 `ldvh-meta` / `ldvh-meta-muted`，不得做大号文本。
4. 状态徽章只表达当前页面约定的浏览分类；WorkCase 列表 Card、独立详情和右侧扩展阅读的身份头部统一显示由 `status / phase` 确定性派生的四个“进展分组”，保证进入详情前后分类不漂移。来源责任状态 `open / blocked / closed` 与精确 `phase` 仍在事实数据和详情“当前情况”中保持独立，不写回进展分组。
5. 界面不使用“活跃”、“审核中”或其它通用词覆盖 WorkCase 的责任状态、精确 phase 或进展分组，也不得把这三者合并为第二状态模型；身份头部显示进展分组不等于把它登记为来源 `status`。
6. 更新时间用于追溯，不作为独立决策信息；创建时间不进入对象身份区。若更新流水具完整署名，更新时间以提交同款弱信息行附带 Agent-ID 与 Host-Environment。

**内容结构：**

1. 每类对象都应有主阅读路径，不按 YAML 字段顺序机械堆叠。
2. WorkCase 详情的稳定阅读顺序是“当前情况 → 目标 → 成功标准 → 当前计划与工作项 → 独立方案复核 → 执行批准 → 结果与验证 → 主控自检 → 独立结果复核 → 关闭提案 → 终态处置 → 关联 → 外部网址”；`scope` 是“目标”节点内的次级字段。只按字段是否实际存在省略节点，不按状态或 Card 分组切换结构。关联区复用其它事实对象的统一标题、类型分组和目标行；关联提交由提交记录视图派生，不从 WorkCase 字段手写维护。
3. 工作项只作为 WorkCase 内部计划、恢复与结果阅读内容呈现，不拥有独立对象详情主路径。
4. 关联对象入口应作为下一层对象入口展示，避免在上层对象里展开下层对象的完整细节。
5. 核心定义类字段不使用默认折叠隐藏事实；多行内容按来源已有 Markdown 结构忠实渲染。WorkCase 直接读取 `goal`、`scope` 及其它 21 当前字段，不从标题、旧 `description` 或展示摘要重建对象正文。
6. WorkCase 详情采用渐进式披露：Human 判断和理解所需的语义阅读节点默认展开；字段问题仍在对应消费位置就地显示。YAML 数据、未解析结构和字段问题汇总等来源数据与技术诊断默认折叠，只由 Human 主动展开。折叠状态只是 Web 阅读状态，不改变 API 返回、事实可用性或 AI 经 Helper 取得信息的路径。
6. WorkCase 的结构化记录不按 YAML 成员机械堆成同权值对。稳定 ID、版本、事件时间和结论属于标题或弱元信息；工作内容、结果与处置说明属于主正文；预期、验证、反馈、边界、主控处置和恢复条件按职责使用次级语义块。颜色只表达这类阅读职责，不生成新的事实状态或判断。

**卡片和行：**

1. 卡片用于承载一个明确语义单元，例如工作项组、目标、范围、约束、任务拆解、证据材料；不得为了装饰把页面区块层层套卡片。
2. 列表行应突出可点击对象的标题；ID、更新时间和状态是辅助信息。只有已精确读取的行才可把 `canonical_path` 作为辅助定位信息。
3. 对象列表卡片只有对象标题可作为当前对象详情入口，进入时保留当前筛选 query；标题必须提供统一 hover/focus 反馈。ID、状态、正文、更新时间、卡片空白区域、内部工作项、信息框、区块标题和态势条均不触发主路由；候选列表不显示复制对象路径入口。
4. 卡片内部的下一层对象行同样只把该对象标题 + 箭头作为跳转入口；行背景、ID、状态、态势条和复制按钮都不是主路由入口。复制按钮只复制路径，不触发跳转。
5. 详情页内的关联对象入口只打开右侧扩展阅读区，不改变当前主详情页；同一个关联对象或文档入口再次点击，应关闭右侧扩展阅读区。若入口使用扩展阅读图标，图标方向必须随当前行是否已在右侧展开而变化。
6. 组标题用于表达当前来源中实际存在的信息集合，例如“当前工作项”或“成功标准”；不从数组位置、ID 或显示数量生成新的状态判断。
7. WorkCase 不保存额外过程历史集合；字段存在时按 04 的稳定阅读顺序呈现，字段不存在时不补空态或从 Git、列表摘要和旧字段重建。

**色彩和状态：**

1. 颜色表达状态和对象类型，不作为装饰性主角。
2. 颜色必须跟随当前类型的精确语义映射：Human 待确认使用紫色系，WorkCase “推进中”使用天蓝色系，“已关闭”使用低饱和蓝灰，已废弃使用中性灰，阻塞、错误和风险使用对应警示色；不使用一个“活跃色”概括不同类型。
3. 红色只用于错误、风险、失败或阻断，不用于普通关闭或退出。
4. 同一页面不应由单一色相支配；对象类型色、状态色和背景色必须互相节制。
5. 对象类型色优先用于“识别这个对象是什么”，状态色优先用于“判断这个对象处于什么状态”；操作 icon 默认属于交互层，不承担对象类型或状态表达。
6. 彩色语义 Card 的标题、正文与背景必须属于同一色相：标题保留识别强度，长正文使用该色相更深但低饱和的文字档位，元信息再弱一级；不得让高饱和标题色贯穿整段正文，也不得让通用近黑正文压过浅色背景。

**密度和响应式：**

1. 工作对象页面面向重复阅读和判断，优先信息密度、扫描效率和稳定布局，不做营销式留白或英雄区。
2. 所有宽度保留同一语义顺序和同一视觉密度，先身份，再当前关注点，再事实详情；内容可以自然换行但不能溢出。
3. 任何固定格式 UI 元素都应有稳定尺寸或响应式约束，避免加载数字、状态标签或长标题造成跳动。
