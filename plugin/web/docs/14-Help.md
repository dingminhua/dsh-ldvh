## 1. 这页是什么

给 Human 的一份**使用引导**。整页由**一个 tab 容器**组织：页头之下是常驻声明与 sticky 切换区，切换区之下是当前分区，同一时刻只呈现一个分区。

### 1.1 为什么整页都是 tab

先前是「上方两块常显概览 + 下方五个分区」——**两套组织范式挤在同一页**：

- 进页面第一眼看到的是内容，不是导航；
- 常显概览越长，切换区离得越远，tab「一次只呈现一件事」的价值被抵消；
- 分区里没有分区标题（标题信息全靠 tab 按钮），常显区反而有 h2，标题层级自相矛盾。

整页统一为一个 tab 容器后，页面上只剩**一种**组织方式：分区切换。七个分区各自回答一个问题：

| 分区 | 回答什么 | 内容来源 |
|---|---|---|
| 如何开始 | 第一次用它要做什么：先选定管辖项目，再把目标立起来（新项目与老项目的起点不同） | `specs/08` §5.4/§5.6（管辖登记入口与 Human 意图）、`specs/30` §8.3（目标确立路径）、`specs/33` §5（调研吸收进入信号） |
| 这是什么 | LDVH 是什么、怎么运作；它解决什么问题；与 AI 配合的主线是什么形态 | `specs/00` §1（问题）、§2（根方案）、§3（构成）、§3.4（七大业务系统） |
| 有哪些东西 | 七类事实对象各自「是什么 / 什么时候产生 / 你去看什么」 | 各事实类型规范的 §1 定位与字段边界 |
| 事情怎么推进 | 七大业务系统各自「它管什么 / 你怎么用 / 落到哪里 / 它不保证什么」 | `specs/03` §9.1–§9.7（职责、判据、边界）；`specs/00` §3.4 |
| 什么时候该你出面 | 五类交互入口的触发条件与你的响应契约；以及必停情形 | `specs/07` §6.1–§6.5；`specs/00` §5.7 |
| 去哪儿看 | 左侧导航里那些**不指向事实对象**的入口分别是什么、什么时候看；各类对象又分别在哪一页 | 本仓路由与各页自身职责 |
| 怎么判断可信 | 声明的三层（已证实 / 未证实 / 残留风险）、不能单独证明完成的事、值得退回去重问的情形 | `specs/00` §5.6 据实声明、§5.7 必停情形 |

**「如何开始」放第一位并作为默认落点**：它是新用户的入口。一个藏在中段、要点两次才找到的「如何开始」不算入口（Human 2026-11-03 要求新增该分区）。

**分区标题有独立一档**：分区标题走 `ldvh-region-title`（20px / 28px / 600），与页面标题（18px）、条目标题（16px）构成三级可辨层级。此前分区标题借用 `ldvh-card-title-prominent`（16px / 600），与页面标题只差 2px、与条目标题只差字重——两级标题挤在同一档，扫页时读不出「我在哪个分区」。分区标题比页面标题大一号是**有意的**：页名「帮助」在左侧导航里已经出现过，是站点里的一个标签；分区标题是读者此刻真正在读的那句话（`01` §1.5 第 1 条）。

**标签是短问句，标题是完整问句**：标签给切换区（窄屏会折行，必须短），标题给分区内容（读者落在这里，要知道自己回答哪一问）。两者不重复——标签问「有什么」，标题补「具体是哪些」。

切换按钮各带一枚**分区提示符**图标（`HELP_TAB_ICONS`：火箭、打开的书、层叠、路径、举手、罗盘、盾牌），与对象类型图标、系统图标、导航图标三族全部错开形——读者不会把分区图标误读成对象图标。

### 1.2 九类呈现件，按类型登记，每类一种壳

本页的呈现件不是「一种壳到处用」，而是**按类型登记**：每类呈现件有唯一的根元素形态、由一个组件产出，页面里同一类东西只有一种写法。

| 类型 | 标记 | 根元素 | 用在哪 |
|---|---|---|---|
| 声明条 | `notice` | `div` | 页头正下方的声明 |
| 对照表 | `compare` | `div` | 「这套系统解决什么」的三行对照 |
| 形态 | `stage` | `article` | 与 AI 配合的主线五段（纸上的五行）；「如何开始」的两条起点（并肩两格） |
| 条目 | `entry-card` | `article` | 七类对象、七大系统、五类交互入口（各一张纸上的行） |
| 行式清单 | `rows` | `ul` | 必停五条、退回去四条、入口六项 |
| 标签阵列 | `chips` | `ul` | 不能单独证明完成的七条；各类对象的入口标签 |
| 信任阶梯 | `ladder` | `div` | 声明的三层 |
| 提示条 | `hint` | `div` | 双源召回、必停之后怎么办、「还没登记项目」「立起来之后」 |
| 步骤清单 | `steps` | `ol` | 「如何开始」的两步 |

**为什么是「按类登记」而不是「全页只有一种壳」**（Human 2026-11-03 定，替掉上一轮口径）：上一轮要求「一种卡片壳 + 一种行式列表 + 一个网格基准」，那会把本页真正需要的形态判死——症状与机制本来是一一对应，用对照表才准确；三张等宽卡并排反而把这个对应拆散了；七个否定项是短句，排成长列表要占掉半屏，做成标签阵列才一屏扫得完；「如何开始」的两步有**来源已成立的先后顺序**，用有序列表才准。**要防的是同一类东西出现两套写法，不是出现多种类。**

守卫据此复算三件事：登记清单与实现一一对应、同一类型只有一处定义点、根元素标签与登记一致（行式清单与标签阵列必须是 `ul`/`li`，**步骤清单必须是 `ol`**——顺序本身就是信息，语义不留给读屏器猜）。

### 1.3 边界

- **不是规则源**。页上每一句都是对当前规范源的**通俗转述**，不产生规范效力；规则以规范源为准，事实以事实源为准（`specs/00` §3.2、§3.3）。**声明常驻页头正下方**——它是页面级限定，与分区内容无关，压在长分区末尾等人滚到底就等于没有。
- **不是事实页面**。它不读事实源、不发起任何请求、无写入口（守卫第 7 条）。页内没有一条事实对象记录，因此**不套对象卡框契约**（`01` §1.10 第 9 条针对的是「呈现一条对象记录」）；本页走 `ldvh-page-frame` 页面框架与**一条文档列**（`.ldvh-help-column`），分区内容收在 52rem 里、与页头共用同一个右缘。
- **不是营销页**。首屏是普通面板与语义排版类，不做渐变英雄区与大留白（`01` §1.8.1「不使用营销式大留白或英雄区」、§1.10「密度和响应式」第 1 条）。
- **不是七个页面的说明书**。「七大业务系统」是**规范层的过程**——它们各管一段业务过程，结论落在对象上，但系统本身不是对象，也多数不以页面形态存在（双源召回甚至不留对象）。页上讲的是「这件事由谁管、怎么用」，不是「哪个页面点哪里」。

## 2. 内容结构

### 2.1 分区内部

每个分区都是同一副骨架：

```
┌ 开篇带（淡强调底、圆角、内边距）────────────────┐
│ [■ 强调色方块] 分区标题（h2，完整问句，ldvh-region-title）│
│ 导语（一行，限宽 40rem）                            │
└──────────────────────────────────────────────┘
[分组标签] ──────────────────────────  ← 眉标压在同一条分节线上，线划到列尾
内容（纸 / 灰卡 / 步骤）
────────────────────────────────────  ← 章末出口：「下一章 …」；末章不画
```

**章首是一块有底面的开篇带**（`.ldvh-help-opener`：淡强调底 7% + 0.75rem 圆角 + `1.125rem 1.25rem` 内边距），里面是「24px 实心强调色方块 + 分区标题 + 导语」。首屏此前是三块低对比文本（页名、页面说明、声明）压在分区名上面，读者落进页面不知道自己在哪；一块有底的带子把「从这里开始读」画出来，实心方块再把眼睛钉在分区名上。方块用实心而不是淡染：10% 的淡染在这个底色上立不住，只会读成「一块更白的方块」。

**章末给一个出口**（`.ldvh-help-chapter-foot`）：一条分节线 + 「下一章」+ 下一分区的标签，点它切到下一章。此前每章读到底就是页面底，读者想知道「接下来该看什么」只能回头看切换区；给一个出口，七个分区才连成一条读得下去的路。**末章不画这一条**——没有下一章就不该出现一个空出口。

**分组标签压在同一条分节线上**（`01` §1.10 第 12 条：区块边框只作分节，只保留上边框、不补下边框）：线从标签右侧一直划到列尾。此前是「一条通栏线 + 线下 20px 一个标签」，标签悬在线与纸之间，读起来像正文的第一行；压到线上，它一眼就是「这一段的分组名」。层级由**空间与线**承担，不靠放大字号——面板内标题不得使用页面级字号（`01` §1.5 第 1 条）。

**线分两档，按「在纸外还是纸内」**：248/249/251 的页底上，`--ldvh-border`（229/231/235）画出来几乎看不见——线画了等于没画。故 **纸外的一律用 `--ldvh-text-secondary` 的 28%–30%**（落在 196 上下，看得见），**纸内的行线仍用 `--ldvh-border`**（纸自己已有边，内部只需淡分）。这条区分是有意的：外重内轻，纸才立得起来；全用同一档，要么纸没轮廓，要么纸内像表格。

**分组标签不是标题**：它是「这一组讲什么」的眉标，用 `ldvh-section-title` 渲染成一行普通文本。标题层级固定为 h1（页头）→ h2（分区）→ h3（条目标题），不跳级、不加深（守卫第 12 条）。

**导语与正文限宽 40rem**：14px 中文一行约 45 字，落在中文排版每行 30–45 字的舒适区。此前导语铺满 992px，一行五六十个汉字，读起来串行；46rem 约 52 字/行，仍偏长，故收到 40rem（守卫第 13 条把这条钉住：页面内所有 `max-w-[Nrem]` 的 N 不得大于 40）。

**主线不给编号**：主线五段形态之间没有来源已成立的先后序号（`01` §1.5 第 12 条：没有先后关系的同级集合统一使用圆点，编号只留给来源已经成立的步骤）。引导语明说「不是必须照走的流水线」，故既不给序号，也不排成流水线。**五段顺读而不同网格**：它们排进 `ldvh-section-grid` 会折成 2+2+1，末段孤零零悬在左半边——读者看到的是一个表格的残行，不是一条线。故五段改为**同一张纸上的五行**（复用 `.ldvh-help-entry`，行间一条发丝线），从上往下顺序读完，没有格子边界要跨。

**形态格不带类型图标**：一格形态的产物不止一类（老项目 = 报告 + 目标 + 子目标），十五像素的图标位塞两三个必然叠在一起；产物已由行内的入口链接逐个点名，图标在标题前只是把同一个信息再挤一遍。形态格因此只有三行：形态名（h3）→ 一句说明 → 承载对象的入口（带类型图标，`getCategoryColor` 单源）。

**步骤才给编号**：「如何开始」的两步有**来源已成立的先后关系**——项目没选定，目标就无处可落（目标与子目标长在被选中的项目下面），故用有序列表（`ol`）承载，标题带「第一步／第二步」序号，并在行首给一枚**序号徽标**（`h-6 w-6` 的实心强调色圆 + 反白数字，与正文行盒等高）让先后一眼可见。它与章首的实心方块是同一族标记（实心强调色 + 反白），页面上所有「这是一个点」的地方长成一个样子。顺序写进 markup，不只写在词句里，读屏器才念得出「第 1 项，共 2 项」。

**步骤清单不套面板边框**：它不是一张卡，是两条步骤；卡里再套卡会读成几层盒子。两步之间用一条上边框分节，与全页分节规矩一致。

**两条起点共用形态格**：新项目与老项目也是「一种形态，落在哪些对象上」，故与主线五段共用同一组件（`StageCard`），只是排法不同——起点是**并肩的两格**（`.ldvh-help-stage`，只给一条上边线、不套框，读作二选一），主线是**纸上的五行**。这是「同一类东西只有一种写法」的直接后果，而不是又一套写法。

**对象分区给七类事实对象，目标是单例**：事实对象共七类（`specs/02` §3.2 登记的 Goal、SubGoal、Spark、Report、Pitfall、Friction、Norm），其中 **Goal 是单例**（一个项目只有一个，路径即身份），它有独立页面 `/goal` 而不在对象列表值域里（`api/services/facts.ts` 的 `ACTIVE_OBJECT_TYPES` 只含可浏览的六类）。因此页面把目标单独作为一张条目卡渲染，数据来自独立的 `SINGLETON_MAP`——**不放进 `OBJECT_MAP`**：守卫第 4 条比对的是 `OBJECT_MAP` 与活跃类型值域，混入单例会让它判红（「多一类等于在讲不存在的东西」）。目标卡与六类对象卡共用同一套卡壳与文案结构。

**对象地图必须覆盖活跃事实对象类型全集**：少一类＝有一个事实对象没被解释，多一类＝在讲不存在的东西（守卫第 4 条比对 `api/services/facts.ts` 的 `ACTIVE_OBJECT_TYPES` 值域）。「提交」不是事实对象，它在「去哪儿看」分区里。2026-11-15 起不再从「导航对象族 ∪ 聚焦页可下钻类型」取并集：聚焦页目标区已撤掉子目标标题的详情下钻（改展开/收起），下钻类型集合随之缩成空，若仍按并集比对，仍在值域里的子目标会被误判成「不该解释」。

**子目标为什么仍在地图上**（Human 定案 2026-11-13，2026-11-15 续记）：2026-11-13 同批定案把**侧栏**的子目标入口撤了——它由聚焦页目标区承载；2026-11-15 又把目标区**标题的下钻**撤了，点击标题改展开/收起。两次撤的都是**进入通道**，不是这个事实类型：子目标仍是事实对象，仍有列表页与详情页（由列表卡、联邦卡与本对象地图进入），也仍需要在这个分区被解释。地图上少了它，读者就既没有侧栏入口、也没有导览说明，子目标在 Web 上无处可寻。守卫因此比对类型值域全集，而不是「有入口的那些」；值域从后端单一权威读出，不写死名单——名单写死，日后类型值域变了守卫不会跟着变。

**系统清单必须与规范源一一对应**：七大业务系统不是页面作者挑的，是 `specs/03` §9.1–§9.7 的七节（守卫第 9 条**直接读规范源**比对，不写死名单）。多一个是在讲不存在的系统，少一个是有一个系统没被解释。

**系统分区每格给四行**：它管什么（职责）、你怎么用（Human 的参与点）、落到哪里（承载它的对象，可直接打开）、它不保证什么（该系统的边界）。第四行不是客套——每条边界都是一条防自欺条款（「登记了」不等于「推进了」），与「怎么判断可信」分区是同一件事的两个落点。**双源召回是横切过程、不留独立对象**，它那格给文字说明而不是链接；**把关请示同样不落在对象上**（请示与答复是工作包生命周期上的留痕，不是事实对象），此时**整行省略**——留一行空标签只会在扫页时读成「这里本该有东西却没有」。

**入口分区末尾补一排对象入口**：左侧导航只覆盖不指向事实对象的入口，读者要拿一类对象时仍得自己认类型名。故在入口行清单之后，用**标签阵列**（`chips`）把七类对象各给一枚可直接打开的入口标签（目标走 `/goal`，其余走 `/objects/:type`）——同一套标签壳的第二次用法，与「不能单独证明完成」那排否定项共用组件，不另写第二种写法。

### 2.2 长内容的分层

七个分区各是一个**分层入口**：同一时刻只呈现一个分区，长内容不一次铺满（`specs/07` §12 第 7 条）。分区切换区是 sticky 的，固定在主滚动容器顶部（`01` §1.5「承担视图切换的顶部控制区不得随长正文滚出当前滚动容器」）。

切换分区后，分区内容的起点被带到切换区正下方——否则人在长分区里点切换，视口停在旧位置，看到的是新分区中段而不是开头。切换区在窄屏会折行变高，故按**实测高度**留出 `scroll-margin-top`，不写死高度。**分区起点已经可见时不滚**：否则刚进页面点一下切换就把页头顶掉，是无故的跳动。

**承载内容的句子一律走主色 `ldvh-body`**：此前页面正文几乎全是 `ldvh-body-muted`（次级灰 107/114/128），长文读起来发飘；声明条更用 12px `ldvh-caption` 承载页面级实质限定——违反 `01` §1.5 第 5 条（caption 只用于辅助信息，不承载主要内容），本轮提到 14px `ldvh-body`。

**次级正文是登记制，不是随手可用**：只有**系统行的边界行**（「它不保证什么」）保留次级灰。它是防自欺条款（`specs/00` §5.6），与职责不是同一量级，刻意用一条上边线把值与上面三行隔开、灰字退半步。它的根元素带 `data-voice="secondary"` 作为判定锚点；新增次级正文必须在这里显式登记，否则守卫第 13 条判红。

**定义行的值走 `ldvh-body`（主色）**：此前值用次级灰、标签也用灰，整页一个明度，眼睛没有落点。标签留 `ldvh-caption-strong`（12px 次级），值回主色，一拉开就有层级。

### 3.2 九类呈现件

**2026-11-19 版式重构后的统一口径：分组只靠「纸」与「行」。** 全页不再有任何一张张等重的卡片——十几张卡同屏时，眼睛分不出谁和谁一组，读者扫到的是一片同色的盒子。现在每个分区最多一两张**纸**（`.ldvh-help-sheet`：一条 `--ldvh-border` 细边 + 0.75rem 圆角 + `--ldvh-panel` 白面），纸上同类的东西各占**一行**（`.ldvh-help-entry`：`0.875rem 1rem` 内边距，行与行之间只有一条 `--ldvh-border/75` 发丝线，没有框）。行内的「标签 + 值」两列由 `.ldvh-help-fields` 承担，标签栏固定 `6.5rem`。

| 类型 | 壳 | 内容顺序 |
|---|---|---|
| 声明条 | `.ldvh-help-scope`：**一条上边线 + 空间，不套框**。套了框它就是首屏唯一有边的东西，读者的第一眼会落在一句免责声明上 | 信息图标（`--ldvh-accent`）+ 14px 声明（`ldvh-body`） |
| 对照表 | `.ldvh-help-sheet`；表头行 `border-b`，数据行 `.ldvh-help-entry` + `flex-wrap` | 表头（短板／典型表现／LDVH 怎么做）+ 三行；末列极浅 accent 底色提为主列，**表头与数据行同染**（色带从表头贯到末行，只在数据行染会让带子在顶上断掉）；容器 ≤ 27rem 时**整行收起表头**（三列已折成一列，表头只剩三个不知道在标什么的标签） |
| 形态 | 并列：`.ldvh-help-stage`（只给一条上边线）；顺读：`.ldvh-help-entry`（纸上的五行） | 形态名（h3）→ 一句说明 → 承载对象入口（`TypeLink`，带类型图标）。**标题前不放类型图标**——产物不止一类，十五像素的位塞两三个必然叠在一起 |
| 条目 | 一张 `.ldvh-help-sheet` 包若干 `.ldvh-help-entry`（七类对象／七大系统／五类入口各一张纸） | 图标 + 名称 + 右端去往入口 → `dl.ldvh-help-fields`（标签栏 + 值）→ 可选边界行 `.ldvh-help-limit`。**对象类型额外给图标一块 12% 类型色方块**（`.ldvh-help-entry` 抬头的 24px 圆角方块）：类型色此前只染 15px 图标本身，扫一列看不出区别；系统与入口没有类型色，图标仍是灰的 |
| 行式清单 | `.ldvh-help-sheet` + `.ldvh-help-entry` 行 | 行内容是插槽：必停行一句话、退回行一句话（琥珀圆点）、入口行「图标 + 名称 + 说明 + 去看看」 |
| 标签阵列 | `flex flex-wrap gap-2`，每项 `ldvh-chip-tag` | 七条否定项，一屏扫完；对象入口标签（类型色图标 + 类型名，可直接打开） |
| 信任阶梯 | `.ldvh-help-sheet` + `.ldvh-help-entry` 行；层标记按**形状**分级（实心／空心／虚线） | 标记 + 层级名 + 判定提示 + 说明 |
| 提示条 | `.ldvh-help-note`：**灰底小卡**（`--ldvh-border` 的 50% 底 + 0.5rem 圆角 + 内边距），**不用强调色**——强调色是「结论」与「章首」的，提示只是旁注 | 信息图标（强调色）+ 加粗小标题 + 正文 |
| 步骤清单 | `ol`，**不套边框**，两步之间一条 `border-t` 上边框分节 | 序号徽标（圆，与正文行盒等高）+ 标题（h3）→ 说明 → 该步的补充内容（提示条／分组标签 + 形态格） |

**系统卡的边界块退半步**：它是防自欺条款，与职责不是同一量级，故**在行内另起一条上边线、值退成次级灰**（`.ldvh-help-limit`），但仍**沿用同一套标签栏**——它若另起一套「标签在上、值在下」的排布，读起来就像另一张表。它是本页唯一用次级灰的正文块（登记锚点 `data-voice="secondary"`）。

**行式清单与标签阵列必须是列表**（`ul`/`li`），**步骤清单必须是有序列表**（`ol`）：前两类的每一条都是并列列表项，最后一类的顺序本身就是信息，语义不留给读屏器猜。

**纸只有一种**：`.ldvh-help-sheet` 是全页唯一的面框定义点（细边、圆角、白面、`overflow: hidden`），页面里不得再出现 `rounded-xl` / `rounded-lg` 的卡片壳（守卫第 14 条）。新增一种「一类东西」时，先问它是纸上的一行还是另一张纸，而不是再画一个盒子。

**网格只剩一处用法**：`ldvh-section-grid` 只服务「如何开始」的两条起点（两格并肩、由容器宽度决定列数，页面内不自写 `minmax(`）。主线五段**不用网格**：五段排进去会折成 2+2+1，末段悬在左半边，读起来是表格的残行。窄容器下不引断点类（`01` §1.6.1 第 3 条）：对照表用 `flex` 自然换行，标签栏用容器查询折到值上方。

**图标与文字同基线，靠容器等高而不是靠 `mt-N`**：本页各处标记容器（声明条图标、提示条图标、对照表行图标、条目抬头图标、阶梯块首标记、清单圆点、入口行图标、步骤序号徽标）的高度一律等于相邻文字的行盒高（24px = `ldvh-body` / `ldvh-card-title` 的 `leading-6`），标记在容器内居中。此前它们是「16px 容器 + `mt-N` 往下顶 1–2px」——那个数是**为某个字号试出来的**：声明条正文从 12px `ldvh-caption` 提到 14px `ldvh-body` 的那一轮，图标立刻比文字高 2px；提示条与阶梯方块同样偏高；清单圆点偏 1px。守卫第 14 条按结构识别这些容器并检查它的高度与居中方式，期望高度**从 `index.css` 的 `leading-*` 读出**（改了行高而没改容器就判红）。

**图标顶端对齐，用 `items-start` 而不是 `items-center`**：英文态标题常折成两行，若整块居中，图标会落到第二行旁边，读起来像是配错了条目。所以行是 `items-start`，**靠容器等高来定位首行**，而不是靠 `mt-N` 往下顶一个凑出来的数。

**颜色只表达状态与对象类型**：形态格行内的入口图标用承载对象的类型色（`getCategoryColor` 单源）；信任阶梯的绿／灰／琥珀表达声明状态，且**先用形状分级**（实心／空心／虚线），颜色只作补强——只靠色相区分，色觉障碍读者就丢了这一层；琥珀圆点表达「该退回去」。**不使用左侧粗边框**——`01` §1.10 第 7 条把语义左条限死在两族（决策块、项目色条），本页两类都不属，一律四边同宽，阶梯改用**块首标记**承担。

**不得使用**：渐变英雄区与装饰性光晕；视口断点类（`sm:` / `md:` / `lg:`）；任意字号（`text-[Npx]`）；单侧粗边框（`border-l-*`）；内联对象类型图标、导航图标、业务系统图标或分区图标（须经集中映射取）；第二个网格基准；页面内自写 `minmax(`；h4 及更深的标题；卡片壳（`rounded-xl` / `rounded-lg`）。

## 4. 内容纪律

1. **每句话都能指回来源**。页上的机制名（规范源、事实源、主控自查、代理审核、机械校验、双源召回、必停情形）都在规范源里有定义，页上只做通俗转述，不新增概念、不给新名字。
2. **不写已删除的系统**。原「Vibe 开发步骤」7 步里的「讨论模块」所指的**讨论业务系统已于 2026-10 由 Human 决定删除**（该职责归主控本职，见 `specs/04` 方案收敛自查条），续着写就是拿不存在的系统教人做事。旧词条与旧结构一并撤除，守卫第 2 条防止复活。
3. **不把对象类型讲成分类学**。每类对象写「它是什么 / 什么时候产生 / 你去看什么」，其中「什么时候产生」说的是**它被什么动作带出来的**，不是它属于哪一类。
4. **不承诺 Web 做不到的事**。「去哪儿看」分区里每一项都只描述当前页面实际提供的读取与呈现。
5. **中英一一对应**。帮助页是全站文案量最大的静态页，漏一个英译会在英文态直接露出 key（守卫第 3 条比对两侧词条集合）。英文文案里的引号用弯引号（`“ ”`），与中文侧的 `「 」` 对位——本仓 `settings.removeConfirm` 已有先例。
6. **系统清单不许自选**。七大业务系统是 `specs/03` §9.1–§9.7 的七节，页上只能讲这七个，且名称与规范一致（守卫第 9 条读规范源比对）。系统分区讲的是**过程与用法**，不是页面操作说明——写「你在哪个页面点哪里」是把规范层的分工讲成了产品导航。
7. **每个系统的边界都要写**。只写它做什么、不写它不保证什么，等于把「登记了」读成「推进了」。七条边界（`specs/03` §9.1–§9.7 各自的「边界」条）逐条落到「它不保证什么」那一格。
8. **分区标签不许各说各话**。七个标签统一成疑问式短句，读者一眼知道每个分区回答哪一问；标签不得写成名词短语（「对象地图」是名词，「什么时候该你出面」是问句——混排会让切换区读起来像三套命名）。
9. **呈现件不许临时起壳**。需要新的一种呈现形态时，先在 §1.2 的登记表里加一行并说明为什么现有九类装不下，再改页面；不打招呼就在页内另写一套，读起来就像几套页面拼在一起。
10. **编号只留给来源已成立的步骤**（`01` §1.5 第 12 条）。「如何开始」的两步有先后关系（先选项目，目标才立得起来），故给序号、用 `ol`；主线五段形态没有先后关系，故不给序号、用并列网格。并列集合被写成「第一步、第二步」是编造顺序，比漏写序号更糟。
11. **操作指引不许承诺做不到的事**。「如何开始」讲的每一步都要在真实路径上成立：管辖项目登记走的是 AI 入口（`specs/08` §5.4 第 1 项、§5.6 的显式提请），Web 侧本仓只有项目切换器（本页所在的 Web 应用没有登记设置页），故页上不给「在设置里登记」这类指不存在的入口的话。
12. **一句只说一件事，长文拆成短句**（Human 2026-11-19：帮助页内容按当前系统功能重写，要求简单扼要）。每个定义位最多一两句；原来「一个卡片里塞三段解释」的写法改为「一行结论 + 一行补充」。**转述不等于压缩掉依据**：句子可以短，被转述的机制名、边界与「不保证什么」一条都不能少——砍掉的应当是修辞，不是内容。

## 5. 已知边界（如实登记）

- **2026-11-19 第三轮：给页面加「质地」，让每章有起点也有落点**。上一轮之后仍然「太累」，原因不是线或色不够，是**全页只有一种质地**：正文 + 白纸，一章读到底既没有起手也没有收束，七张表格一路铺下来眼睛没有换气的地方。改法五条：① 章首改成一块**有底面的开篇带**（淡强调底 7% + 圆角 + 内边距，内含实心方块与导语）——它是全页唯一染色的大块，一章一块，页面节奏由它分段；② 提示条从「一条上边线 + 正文」改成**灰底小卡**，成为第三种质地（此前旁注和正文分不开，读者会把「切换器里没有？」当成上一步的续句）；③ 对象类型的图标落在一块 **12% 类型色方块**上——类型色此前只染 15px 图标本身，扫一列下来分不出是七类还是三类；④ 步骤序号徽标与章首方块统一为**实心强调色 + 反白**，成为同一族标记；⑤ 章末加一条出口「**下一章** + 下一分区名」，把七个分区连成一条读得下去的路（末章不画）。**新增文案只有一条**：`help.nextChapter`（中英各一）。实测 1440 / 1024 / 390 三档无横向溢出，深浅两态同一套档位；377 条前端契约测试通过。

- **2026-11-19 第二轮：视觉层级（颜色 / 线 / 章首）**。第一轮解决的是「结构」，落地后仍有一条硬伤：**结构对了，但读不出重点**——全页只有一档线（229/231/235 画在 248/249/251 的页底上，等于没画）、只有一处颜色（强调绿只出现在 13px 图标与 tab 上）、页头三块低对比文本（页名、页面说明、声明）全压在章首之上。改法八条：① **线分两档**——纸外一律 28%–30% 次级灰（看得见），纸内行线仍用 `--ldvh-border`（纸已有边，内部只需淡分）；② 章首加一枚 **24px 实心强调色方块**（淡染 10% 在页底上立不住，只会读成「一块更白的方块」）；③ **分组标签压到分节线上**，线划到列尾（此前标签悬在线与纸之间，像正文第一行）；④ **声明条去框**，只留一条上边线（套框时它是首屏唯一有边的东西，第一眼落在一句免责声明上）；⑤ 对照表的**结论列连表头一起染 10% 强调底**，色带从表头贯到末行（只染数据行，带子在顶上断掉）；⑥ 页脚提示条的线取 18%，比分区线淡一档——它是页脚，不该和「下一段开始」抢同一条线；⑦ 删掉「起点分两种」上方那条重复的分节线（两格自己已有上边线，同一处分节不必画两次）；⑧ 声明文案收短一行（中英同步，「内容随规范演化更新」这层事实一条没少）。**代价**：章的「开篇」现在靠一块纯色方块承担，若将来 `--ldvh-accent` 换色，七个分区的开篇强度会一起变——这是全局令牌的特性，不是本页可局部回退的取舍。实测 1440 / 1024 / 390 三档无横向溢出，深浅两态同一套档位；377 条前端契约测试通过。

- **2026-11-19 版式重构：把「卡片地毯」换成「一章一两张纸」**。改之前这一页的问题不是不好看，是**读不出结构**：整页十四张同款卡（圆角 + 边框 + 白面 + 内边距）同屏，所有东西等重，眼睛分不出谁和谁一组；卡片网格里每条账都在自己卡里各写一遍「它是什么／什么时候产生」，标签永远对不齐，七个答案也没法横着比；正文铺满约 964px，一行五十余汉字，读起来串行。改法六条：① 分区内容收进 **52rem 一条文档列**（`.ldvh-help-column`），与页头共用同一个右缘；② 每个分区最多两张**纸**（`.ldvh-help-sheet`），纸上同类东西各占**一行**（`.ldvh-help-entry`），行间只有一条发丝线；③ 行内**标签栏固定 6.5rem**（`.ldvh-help-fields`），七条账的标签竖成一条竖线；④ **主线五段不进网格**——排进 `ldvh-section-grid` 会折成 2+2+1，末段悬在左半边，改为一列顺读（仍不给编号，理由见 §2.1）；⑤ 信任阶梯的层标记**先按形状分级**（实心／空心／虚线），颜色只作补强；⑥ 声明条**不染底**（它是页面级限定，不是告警），只保留中性纸面 + 强调色图标。**没动的**：九类呈现件的类型集合与根元素、七类对象与七大系统的字段集合、中英词条一条没改。守卫新增第 14 条，钉住「不得再出现 `rounded-xl`/`rounded-lg` 卡片壳」「纸与标签栏只能由 `index.css` 定义」「`container-type` 必须挂在行（祖先）上而不是标签栏自己身上」。实测（Playwright）：1440 / 1024 / 390 三档均无横向溢出；390 下标签栏折到值上方、对照表整行收起表头、主线五段顺读。

- **2026-11-19 这一轮：按当前系统功能重写文案并收紧版式**。改动三处：① 全部 `help.*` 词条（中英各 181 条）重写，每句压到一行以内——上一轮把「对象地图」写成九类，实际是七类事实对象（`specs/02` §3.2：Goal、SubGoal、Spark、Report、Pitfall、Friction、Norm），「主线六段」实际是五段，两处都按事实源改正；② 「有哪些东西」分区补上**目标**（单例，独立数据源 `SINGLETON_MAP`，不进 `OBJECT_MAP`），对象分区由六张卡变七张；③ 「去哪儿看」分区末尾补一排**对象入口标签**，步骤清单加**序号徽标**，系统卡在没有落地对象时**省掉空行**。版式契约（单一 tab 容器、九类呈现件、标题层级、排版基线、正文限宽）一处未动，13 条守卫与全量 376 条前端契约测试通过。

- **窄视口实测过两次，仍有两处待补测**（2026-11-03 可读性这一轮）：本轮嵌入面板一度变为 568×1280，实测七个 tab 折成两行（4+3）、卡片降为单列、正文约 30 字/行可读；另一次更窄的布局下七个切换项折成**三行**（3+3+1），分区内容与卡片仍正常排布、边界块的虚线框未被压破。面板随后恢复 1280×720，**原型页在窄宽下的折行表现未完整实测**。本轮版式改动不触及窄屏的两处既有敏感逻辑：卡片列数仍由 `ldvh-section-grid` 按容器宽度决定（未换网格基准），切换区折行后的 `scroll-margin-top` 仍按**实测高度**动态取值（未写死高度）。**新增两处待补测**：① 分区标题提到 20px 后，窄宽下较长标题（如「什么时候该你出面」）是否折行并与切换行挤压；② 行长收窄到 40rem 后，窄屏下单行字数进一步变少，长段落是否读成「一行一句」的碎块。**这是推理不是实测。**
- **对照表在窄屏靠自然换行**：三块用 `flex` + `min-width` 而非断点类，窄屏时「典型表现」「对应机制」各占一行、缩进对齐在「短板」列宽之内。窄屏实测时要看这两行是否读得顺。
- **切换区吸顶，取决于页面够不够长**：`position: sticky` 只在「切换区被滚过视口顶」之后才吸顶。分区较短时（如「去哪儿看」），页面总高不足，切换区根本滚不出视口顶——此时它与分区内容同屏可见，本来就不需要吸顶。这不是 sticky 失效，是页面不够长；不要按「切换区没吸顶」去改样式。
- **「如何开始」默认落地但不做深链接**：页面打开即落在该分区，但分区状态只在组件内存里，刷新或另开链接都回不到同一分区。要按分区深链接需另立路由设计，不在本轮范围。
- **内容随规范演化**：本页是静态文案，规范改一次它就可能过时。它不自动跟随规范源——这正是它作为「引导」而非「规范」的代价。发现某段与规范源冲突时，先改本页，再按 `specs/09` 的受控提交流程落盘。
- **分区标题比页面标题大一号，是有意取舍**：页名「帮助」在左侧导航里已经出现过，是站点里的一个标签；分区标题是读者此刻真正在读的那句话。代价是「页面标题应当最大」的直觉被打破。若将来要求页面标题重新最大，要动的是 `ldvh-page-title` 这个**全局令牌**（影响全站），而不是本页的 `ldvh-region-title`——本页只新增令牌、不改既有档位，正是为了让这个取舍留在本页内可回退。
- **七个系统的分工仍在演化**：`specs/03` §9 的职责边界会随实际使用调整（尤其是「双源召回」与其他六者的横切关系）。本页讲的是**当前**分工，不是终局。守卫第 9 条只保证**集合与名称**与规范源一致，不保证页上对每条职责的转述与规范逐字相符——转述的准确性由人工与规范评审承担。
- **守卫是源码级的**：第 10–13 条证明的是页面的**结构**（单一 tab 容器、呈现件按类型登记每类唯一、标题层级、可读性基线），不是每张卡的内容正确性。第 11 条按**标记**与**根标签**计，不按组件名计，所以只改组件名不会把守卫打红——这是有意的：改名型变更不应当让守卫误判。第 13 条同理：它盯的是**排版档位与取用方式**（标题走哪一档、正文走主色还是次级、行长多少），不判断一句话写得好不好。
- **第 14、15 条证明的是「取用方式」，不是像素结果**：它们证明标记容器**与相邻文字行盒等高、内部居中、不做垂直微调**，不证明渲染出来的像素落在同一条线上——那是浏览器实测承担的事。本轮实测（Playwright 量真实渲染几何）：帮助页 57 处标记的「标记中心 − 文字行盒中心」**全为 0**；与文字**墨迹**中心的差落在 −0.86…−0.08px。残留的那点差是**字体墨迹本身的不对称**（不同汉字的实际墨迹上下沿不同，例：「目录」两字的墨迹中心比行盒中心低 0.86px），不是排版错位——两版本一致，不是这一轮引入的。
- **守卫是形态级的，不宣称几何等价**：容器高度写成几何等价但写法不同的 `h-[24px]`，第 14 条判红。它认的是**约定写法**（`h-6`），不做几何换算；这一点按 `12` §2 第 3 项如实登记，不宣称语义级防护。
