# 帮助页（Help）

> 范围：`/help` 静态导览页的内容结构与呈现形态——它承载什么、不承载什么，四个分区各自回答什么问题，以及版式上必须遵守的契约。
> 上位：[`specs/00-理念与构成.md`](../../specs/00-理念与构成.md)（理念、构成、Human 权利与 AI 责任、价值标准）、[`specs/07-Web 呈现与交互规范.md`](../../specs/07-Web%20呈现与交互规范.md)（呈现语义、交互入口、反过度设计红线）、[`01-全局设计约束.md`](./01-全局设计约束.md)（全局设计基线）、[`09-图标语义规范.md`](./09-图标语义规范.md)（图标语义）。
> 守卫：`plugin/web/tests/api/help-presentation-contract.test.ts`（七条：英雄区、版式硬约束、图标单源、对象地图对齐、中英词条对齐、英文引号、无硬编码文案与零请求）。

## 1. 这页是什么

给 Human 的一份**使用引导**，回答三个问题：

1. **这套系统解决什么问题**——不解决的话，后面的入口都只是名词；
2. **与 AI 配合时内容会落成什么形态**——对象类型是产物，不是分类学；
3. **AI 会在什么时候停下来找我**——哪些事不会由 AI 替你定。

### 1.1 边界

- **不是规则源**。页上每一句都是对当前规范源的**通俗转述**，不产生规范效力；规则以规范源为准，事实以事实源为准（`specs/00` §3.2、§3.3）。页脚常驻一条声明说明这件事。
- **不是事实页面**。它不读事实源、不发起任何请求、无写入口（守卫第 6 条）。页内没有一条事实对象记录，因此**不套对象卡框契约**（`01` §1.10 第 9 条针对的是「呈现一条对象记录」）；本页用 `ldvh-panel` 面板与 `ldvh-section-grid` 卡片网格（`01` §1.8.1）。
- **不是营销页**。首屏是普通面板与语义排版类，不做渐变英雄区与大留白（`01` §1.8.1「不使用营销式大留白或英雄区」、§1.10「密度和响应式」第 1 条）。

## 2. 内容结构

页面 = **一屏概览** + **四个分区**。

### 2.1 概览（常显）

| 区块 | 回答什么 | 内容来源 |
|---|---|---|
| 这套系统解决什么 | AI 靠不住 / 人接不住也留不住 / 双方互相放大误差——三类问题各对应哪一类机制 | `specs/00` §1（问题）、§2（根方案）、§3（构成） |
| 与 AI 配合的主线 | 项目内容会落成哪几种形态：目标、想法、调研、决定、执行、积累 | `specs/00` §3.4（七大业务系统）与各事实类型规范的 §1 定位；主线末尾附双源召回说明（`specs/00` §3.4） |

**主线不给编号**：这些形态之间没有来源已成立的先后序号（`01` §1.5 第 12 条：没有先后关系的同级集合统一使用圆点，编号只留给来源已经成立的步骤）。左到右只是阅读顺序；引导语明说「不是必须照走的流水线」。

### 2.2 四个分区（sticky 切换）

| 分区 | 回答什么 | 内容来源 |
|---|---|---|
| 对象地图 | 九类事实对象各自「是什么 / 什么时候产生 / 你去看什么」 | 各事实类型规范的 §1 定位与字段边界 |
| 何时停下来找你 | 五类交互入口的触发条件与你的响应契约；以及必停情形 | `specs/07` §6.1–§6.5；`specs/00` §5.7 |
| 入口地图 | 左侧导航里那些**不指向事实对象**的入口分别是什么、什么时候看 | 本仓路由与各页自身职责 |
| 怎么判断它说完了 | 声明的三层（已证实 / 未证实 / 残留风险）、不能单独证明完成的事、值得退回去重问的情形 | `specs/00` §5.6 据实声明、§5.7 必停情形 |

**对象地图必须与左侧导航的事实对象族一一对应**：少一类＝有一个入口没被解释，多一类＝在讲不存在的东西（守卫第 4 条比对 `Sidebar` 的 `/objects/:type` 集合）。「提交」不是事实对象，它在「入口地图」里。

### 2.3 长内容的分层

四个分区各是一个**分层入口**：同一时刻只呈现一个分区，长内容不一次铺满（`specs/07` §12 第 7 条）。分区切换区是 sticky 的，固定在主滚动容器顶部（`01` §1.5「承担视图切换的顶部控制区不得随长正文滚出当前滚动容器」）。

切换分区后，分区内容的起点被带到切换区正下方——否则人在长页里点切换，视口停在旧位置，看到的是新分区中段而不是开头。切换区在窄屏会折行变高，故按**实测高度**留出 `scroll-margin-top`，不写死高度。

## 3. 版式契约

| 部位 | 用什么 | 依据 |
|---|---|---|
| 页面框架 / 工具条 | `ldvh-page-frame`、`ldvh-page-toolbar` + `PageHeader`（标题 + 页面说明） | `01` §1.8.1 |
| 概览三卡、主线格、对象卡、交互入口卡、入口卡 | `ldvh-section-grid`（主线格用 `ldvh-subgrid`）——列数由容器宽度决定 | `01` §1.5、§1.6.1 第 3 条 |
| 面板外壳 | `rounded-xl border border-ldvh-border bg-ldvh-panel p-4` | `01` §1.8.1 |
| 文本层级 | `ldvh-section-title` / `ldvh-card-title` / `ldvh-caption-strong` / `ldvh-body` / `ldvh-body-muted` / `ldvh-caption` | `01` §1.4 |
| 分区切换 | `ldvh-tab-list` + `ldvh-tab-button-active` / `ldvh-tab-button-idle` | `01` §1.5 第 7 条 |
| 对象类型识别 | `ObjectTypeIcon` + `getCategoryColor`（类型色只用于识别） | `09` §3、§7.1 |
| 导航入口识别 | `NAV_ICONS`（集中映射，Sidebar 与本页共用） | `09` §8 |
| 进入主路由 | `ArrowRight` | `09` §5 |

**不得使用**：渐变英雄区与装饰性光晕；视口断点类（`sm:` / `md:` / `lg:`）；任意字号（`text-[Npx]`）；单侧粗边框（`border-l-*`，`01` §1.10「色彩和状态」第 7 条只有两族例外，均不属本页）；内联对象类型图标或导航图标。

## 4. 内容纪律

1. **每句话都能指回来源**。页上的机制名（规范源、事实源、主控自查、代理审核、机械校验、双源召回、必停情形）都在规范源里有定义，页上只做通俗转述，不新增概念、不给新名字。
2. **不写已删除的系统**。原「Vibe 开发步骤」7 步里的「讨论模块」所指的**讨论业务系统已于 2026-10 由 Human 决定删除**（该职责归主控本职，见 `specs/04` 方案收敛自查条），续着写就是拿不存在的系统教人做事。旧词条与旧结构一并撤除，守卫第 2 条防止复活。
3. **不把对象类型讲成分类学**。每类对象写「它是什么 / 什么时候产生 / 你去看什么」，其中「什么时候产生」说的是**它被什么动作带出来的**，不是它属于哪一类。
4. **不承诺 Web 做不到的事**。入口地图里每一项都只描述当前页面实际提供的读取与呈现。
5. **中英一一对应**。帮助页是全站文案量最大的静态页，漏一个英译会在英文态直接露出 key（守卫第 3 条比对两侧词条集合）。英文文案里的引号用弯引号（`“ ”`），与中文侧的 `「 」` 对位——本仓 `settings.removeConfirm` 已有先例。

## 5. 已知边界（如实登记）

- **窄屏实拍到 585px，375px 仍未实拍**：本次重设计在 1280×720 与 585×1318 两个视口下实测。585px 下概览三卡与主线六段都正确折叠为单列，标题与承载对象仍相邻。375px 未实拍——浏览器窗口最小可到 585px，键盘缩放对嵌入页不生效。补测时看两处：主线格单列时标题与承载对象是否仍相邻、切换区折行成两行后 `scroll-margin-top` 是否仍等于实测高度。
- **切换区吸顶，取决于页面够不够长**：`position: sticky` 只在「切换区被滚过视口顶」之后才吸顶。分区较短时（如入口地图），页面总高不足，切换区根本滚不出视口顶——此时它与分区内容同屏可见，本来就不需要吸顶。585px 视口下内容更高、可滚动距离也更短，实测切换区始终留在视口内（最远离顶约 180px）。这不是 sticky 失效，是页面不够长；不要按「切换区没吸顶」去改样式。
- **内容随规范演化**：本页是静态文案，规范改一次它就可能过时。它不自动跟随规范源——这正是它作为「引导」而非「规范」的代价。发现某段与规范源冲突时，先改本页，再按 `specs/09` 的受控提交流程落盘。
