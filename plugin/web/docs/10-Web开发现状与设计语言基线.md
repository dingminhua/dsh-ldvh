> 更新：2026-11-13（删除已撤除类型的阅读视角与呈现契约两节）
> 范围：`web/` 当前参考实现、页面开发文档和后续 Web 修改入口

## 1. 文档定位

本文用于把 Web 当前开发现状、页面文档职责和已经稳定的设计语言收敛到一个入口。后续修改 Web 页面时，应先按本文判断目标页面属于哪一类，再回到对应页面文档和源码实现。

本文不替代 `specs/07-Web 呈现与交互规范.md`、`specs/06-Code 实践与测试规范.md` 中适用于 Web 的测试规则、事实模型规范或 Git 文件事实源。本文只说明当前 `web/` 参考实现如何把这些规则呈现给 Human。

当前字段级读取器读取 ADR、Pitfall、Spark 和 Study 的当前正式载体；不读取 V2/V3 资产。读取不根据对象年代、缺失字段或实现版本切换结构。详情、对象预览、源路径复制和正文阅读必须先取得字段级直读，并把 `canonical_path`、`carrier`、`read_status`、读取问题、字段问题与未解析结构传到消费面。Study 定位为“外部内容调研报告”，不提供兼容双读。

## 1.1 已确认与待确认边界

当前 Web 设计沉淀采用“已确认先固化、待确认不写死”的原则。最前面第一入口已确认可见名为“聚焦 / Focus”，内部概念和源码仍使用 Cognition Center；其余入口 / tab 的最终名称、顺序和信息架构仍未完全确定，因此本文只沉淀它们必须遵守的视觉、i18n、复制、阅读面板和事实源边界，不把其余临时入口文案写成最终产品结构。

已确认并可进入实现收敛的内容：

1. App Shell 采用左侧主导航、中间主内容和右侧扩展阅读区；移动端右侧扩展阅读切换为底部阅读抽屉。
2. 对象列表使用卡片网格和统一状态筛选 tab，不回退到表格或顶部对象类型 tab。
3. 对象详情是语义阅读器，不是载体文件查看器；YAML 数据由精确读取后的事实对象字段重建，不显示源码兜底，Markdown Study 的完整阅读只进入同一份正文的扩展阅读。
5. ObjectDetail 和 ReadingPanel 必须复用同一套身份头部、节点顺序、折叠行为、关联行和复制语义。
6. 所有用户可见 UI 文案必须走 i18n；事实正文、Git message、Markdown 正文、路径、命令、ID 和 hash 不翻译。
7. 复制入口必须按对象路径、文档路径、链接、引用、提交上下文和提交 hash 区分，不使用泛化“复制完整路径”覆盖所有场景。
8. Web 只做 Human-facing 派生展示和受控轻写入，不成为第二事实源。
9. 聚焦页只读模块已经完成：待决定事项、近期动态、Spark 健康度和近期提交热点关系；待决定事项自 2026-10-19 起包含 **open Friction（待修摩擦）**三类；详细派生规则以 02 §4.1 为准。

待确认且不得写死为最终设计的内容：

1. 聚焦之后其余前置入口 / tab 的最终名称、顺序和信息架构。
2. 这些未确认入口是否最终对应当前工作、项目文件或其他更准确的产品入口。
3. 未确认入口不得反向影响已确认的聚焦页、对象页、提交页、ProjectFiles、扩展阅读、复制语义和 i18n 规则。

## 1.2 YAML 解析能力

`web/package.json` 已提供 `js-yaml`。当 Web 的 Node API 或前端确实需要解析 YAML 文本时，统一使用该依赖，不新增手写 YAML 解析器或第二个 YAML 库。

它只负责把已取得的 YAML 文本转换为程序数据；事实对象的读取边界、字段契约、可读状态和写入校验仍以现有受控读取与服务端契约为准。不得因为可以解析 YAML，就在页面侧把源码、导航路径或解析失败补造成事实字段，也不得直接改写事实载体。

## 2. 五个基准模块

当前 Web 的设计语言以五个已经完善的阅读模块为中心：

| 模块 | 路由 | 当前定位 | 作为基线的内容 |
|---|---|---|---|
| 提交 | `/changelog`、`/changelog/:hash` | Git commit records 证据追溯 | 筛选 tab、提交卡片、提交详情、复制提交上下文、右侧快速阅读 |
| 调研 | `/objects/research`、`/objects/research/:id` | 调研报告阅读界面（v5 Research，对应 v4 Study） | 调研意图、摘要、建议、唯一 Markdown 正文入口和关联资料；终态只在事实存在时显示处置（24 号薄索引 + YAML 源节点） |
| 决策 | `/objects/adr`、`/objects/adr/:id` | 决策阅读页 | 对象卡片、标准身份头部、问题/决策/范围/理由/影响节点；retired 以处置收束 |
| 火花 | `/objects/spark`、`/objects/spark/:id` | 待处理信息阅读页 | 对象卡片、标准身份头部、意图/摘要/演变节点；implemented、discarded 才显示对应终态处置；历史 routed 仅只读兼容 |
| 经验 | `/objects/pitfall`、`/objects/pitfall/:id` | 可复用经验阅读页 | 对象卡片、标准身份头部、现象/触发/范围/验证/根因/方案/规避节点；discarded 以处置收束 |

这五个模块不是孤立样板，而是后续 Web 页面继续收敛的中心。新页面或旧页面改造如涉及列表、详情、右侧扩展阅读、复制入口、关联行、节点折叠或提交证据，应优先复用这五个模块已经形成的语言。

## 4. 统一设计语言

五个基准模块共享以下语言：

1. 顶部切换区使用 `ldvh-tab-list` / `ldvh-tab-button`，滚动时固定在主滚动容器顶部。
2. 列表主体使用 `ldvh-section-grid`；卡片宽度不足时换行，不用表格或营销式大留白替代。
3. 精确可读详情、预览和已解析引用的右上可放复制入口；候选卡不复制源路径。状态、类型和标题各在自己的层级，不互相挤占。
4. 标题带使用弱背景、内圈边框、左侧语义短线、对象类型图标或提交图标和完整标题。
5. 更新时间统一在卡片底部右侧，使用 `formatDateTime()`。
6. 详情页和右侧扩展阅读复用同一身份头部、节点顺序、折叠行为和关联行。
7. 正文节点使用小圆点标题、整行点击折叠、`ChevronDown` / `ChevronUp` 和统一 Markdown 阅读样式。
8. 已精确读取且有来源路径的关联行使用左侧语义图标和标题，右侧提供复制入口与扩展阅读入口；其余关联行保留扩展阅读入口但不伪造路径。操作图标必须垂直居中。
9. 复制入口必须按内容语义命名和复制：对象复制对象路径，文档复制文档路径，URL 复制链接，普通引用复制引用，提交卡片复制提交定位上下文，提交详情复制 hash。

### 4.1 四类事实对象的共同阅读基线

Study、ADR、Spark 与 Pitfall 已经形成各类型必须继承的阅读秩序。它们不是字段数相同的模板，而是在不同事实任务下共同遵守以下分层：

1. **先身份，后判断。** 统一身份头部先说明类型、状态、稳定 ID、标题、更新时间、可用时的更新流水署名与可用复制动作；不把状态、时间或复制混入正文节点。
2. **详情按阅读问题组织。** 每个对象以少量固定语义节点承接当前最需要理解的事实，而不是逐字段铺开。节点默认展开，使用同一圆点、整行折叠和 Markdown 正文。
3. **终态是处置，不是另一套时间线。** 只有终态对象才出现 `disposition_summary`；它与对象的 `updated_at` 共同构成最后一次有效记录，不新增关闭、退出或分流时间字段，也不把处置做成强警报模块。
4. **列表只帮助定位。** 卡片保留身份、状态、标题、必要优先级和更新时间；ADR retired、Pitfall discarded、Spark terminal 才补一段弱处置正文，Study 不在列表复述报告摘要。
5. **关联在主阅读之后。** 关联区只呈现来源已有的正式关系或外部资料。可读对象先解析标题、状态与可复制路径；未解析或跨项目引用如实保留其稳定身份，不把导航信息写成新的事实判断。
6. **详情与扩展阅读同源。** ReadingPanel 复用同一身份头部和阅读布局；Study 正文是同一 Markdown carrier 的进入入口，不在主详情复制第二份全文。

各类型的专属信息契约仍必须落在这六项共同秩序中：专属派生信息只回答 Human 当前扫读问题，不能替代身份、事实正文、当前复核与处置、Human 确认或批准、终态处置或关系来源。

### 4.3 组件契约沉淀

以下组件契约属于已确认的跨页面设计语言。其余入口 / tab 的信息架构未定时，仍必须遵守这些组件契约，但不得把临时入口名称写入最终结构。

| 组件族 | 统一契约 | 不得出现 |
|---|---|---|
| Tab / 筛选 | 使用 `ldvh-tab-list`、`ldvh-tab-button`、`ldvh-tab-button-active`、`ldvh-tab-button-idle`、`ldvh-tab-count`；同层 tab 数字与文字同字体、同字号、同字重；所有宽度使用同一紧凑高度 | 单页自定义胶囊、加粗数字、营销式分段控件、顶部对象类型 tab 替代左侧导航；不得按窄屏单独放大或增高 |
| Card | 使用 `ldvh-section-grid` 和 `ldvh-panel`；标题完整换行；候选卡右上只放状态，不复制未精确读取的来源路径；更新时间固定在底部右侧；所有宽度使用同一标题入口高度 | 表格化对象列表、标题截断、候选卡伪造来源路径、右上堆叠多个强按钮、卡片内大面积装饰色；不得建立窄屏专属 Card |
| Identity Header | 顺序固定为 `类型标签 + 状态标签 + object-id`、标题、标签、更新时间（最新完整更新流水署名可紧随其后）、右上复制对象路径；详情页和右侧预览同源 | 状态漂移到右上操作区、对象详情和 ReadingPanel 两套头部、ID 做大号标题 |
| Reading Node | 小圆点标题、整行点击、`ChevronDown` / `ChevronUp`、Markdown 内容区、默认展开 | 每个对象类型自定义折叠样式、正文节点内放额外“展开/收起”文字按钮 |
| Reference Row | 左侧语义图标 + 标题/路径/URL，右侧复制入口 + 扩展阅读入口；整行打开扩展阅读，复制不触发展开 | 对象、文档、URL 各自使用不同卡片、文字按钮或操作尺寸 |
| ReadingPanel / 移动抽屉 | 顶部控制区固定，正文独立滚动；桌面右侧面板保留拖动宽度、前后导航和关闭控件，对象标题由滚动正文中的同源身份头部呈现；Compact 只切换为底部抽屉，抽屉标题区同时承担当前对象识别和高度拖动 | 右侧对象列表导航、只开不关的单向入口、移动端另做独立站或底部主导航、桌面和抽屉分别维护对象摘要 |

## 6. 复制语义

复制按钮不是泛化“复制”动作，必须让 Human 和 AI 都知道复制结果是什么。

| 场景 | Tooltip | 复制内容来源 |
|---|---|---|
| 精确可读的对象详情头部、对象引用、右侧对象预览 | 复制对象路径 | 精确读取返回的 `canonical_path`；缺失、无效或候选列表时不显示复制入口 |
| 本地 Markdown 文档、Study 正文入口 | 复制文档路径 | 文档绝对路径或规范化后的 Markdown 文件路径 |
| 外部 URL | 复制链接 | URL `ref` |
| 非对象、非文档、非 URL 的普通引用 | 复制引用 | 原始引用文本 |
| 提交卡片 | 复制提交上下文 | 面向 AI 定位的稳定多行提交上下文 |
| 提交详情 | 复制提交 hash | 完整 commit hash |
| ProjectFiles 工具页 | 复制路径 | 项目路径、文件路径或 diff 文件路径 |
| 聚焦页模块标题带 | 复制模块摘要 | 面向 AI 对话的多行文本：模块名、所选时间窗口（仅适用模块）、关键计数与条目稳定 ID；不显示或复制页面“观察时间” |

对象路径复制不得依赖可能只是对象 ID 的 `target`、列表 `path` 或导航键作为来源。`canonical_path` 只是预期位置，仍须与字段级直读的 `read_status: readable` 一起成立；否则页面显示实际读取状态、字段问题和未读取范围，而不复制路径。

## 7. 后续开发顺序

后续继续推进 Web 时，推荐按以下顺序做判断：

1. 目标是否影响五个基准模块；如果影响，先保证五个模块一起变化。
2. 目标是否影响详情页和右侧扩展阅读；如果影响，两处必须复用同一布局或同一字段组件。
3. 目标是否影响列表卡片；如果影响，先对齐调研、决策、火花、经验对象卡片和提交卡片。
4. 目标是否新增复制、图标、状态、时间或 tab；如果新增，先检查全局设计、图标语义和 i18n。
5. 目标是否改变 API、事实源读取或状态派生；如果改变，补充或说明对应测试验证。
6. 目标是否读取 Git commit records；如果读取，必须复用 `web/api/services/git.ts` 的 commit message 拆分和 Conventional Commits 解析，不在页面 API 中维护第二套 parser。
7. 目标是否改变 App Shell 高度或滚动；如果改变，必须保持根节点不滚动、主内容/侧栏导航/阅读正文各自拥有滚动，并验证侧栏滚轮不会推动文档或产生横向滚动条。

## 8. 不再采用的方向

1. 不把对象详情退回 YAML 字段平铺。
2. 不让每个对象类型各自发明卡片、节点标题、复制按钮、关联行或时间位置。
3. 不把提交页当成独立视觉系统；提交是五个基准模块之一。
4. 不在右侧扩展阅读区维护第二套对象摘要。
5. 不用“复制完整路径”作为通用文案覆盖对象、文档、链接、引用和提交这些不同动作。
