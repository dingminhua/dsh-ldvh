# 呈现收窄登记表

> 路由范围：LDVH Web 全部页面的**呈现收窄**（「某期不呈现某内容」这一类要求）
> 上位规范：[`specs/09-Code实践与测试规范.md`](../../specs/09-Code实践与测试规范.md) §5 测试基线
> 关联文档：[`10-Web开发现状与设计语言基线.md`](./10-Web开发现状与设计语言基线.md)（呈现契约本体）、[`12-契约测试与守卫设计约定.md`](./12-契约测试与守卫设计约定.md)（守卫纪律）
> 经验来源：[`Pitfall a774d7de`](../../ldvh-base/pitfalls/pitfall-a774d7de-2f70-4955-9f7f-e7c25e65265d.md)；本表由 2026-10-15「待批准关闭卡呈现与契约不一致」一案建立

## 1. 本文定位

呈现契约（`10` §5）里的**收窄类**要求——「某期**不**呈现某内容」——有一个共同弱点：**它靠「不写代码」成立，而没有任何东西会因为「写了代码」而变红**。

本文把这类要求做成**可机械对照的登记表**：每条收窄登记它的三腿，由 `tests/api/presentation-narrowing-registry.test.ts` 逐条核三腿是否仍在。

**三腿**：①**规范锚句**（逐字引自规范/契约原文）；②**实现判据入口**（承载该期判断的代码位置）；③**守卫测试**（断言该判断生效的测试）。

**第四项——须反向断言的例外**：收窄常带例外（「某形态不受本收窄约束」）。例外同样靠「写了代码」才算实现对，故每条例外须在**实现**与**守卫**两侧都留下字面并在守卫中被**反向断言**（断言该例外**未被**收窄）。

## 2. 本表**不**保证什么（如实声明，先于表格）

1. **不保证「新收窄已被登记」**。判断「某句规范文本是不是一条收窄要求」是**语义判断**，字形上不可分（同一条要求可写成「只画标记」「不再呈现正文」「正文仅于关闭期呈现」……）——机械层无法从散文里识别它。故本表的**录入是自愿的**，其完整性由 `12` §7 的复核清单承担，属**软约束**，无强制力。
2. **不保证语义级防护**。校验做的是**源码文本与文档文本的存在性断言**（`12` §3 的口径）：它证明「这三腿当前都在」，**不证明**「该期真的没有呈现该内容」。把实现改名改文案、保留语义地绕过判据，本表全绿也拦不住。
3. **不证明实例的行为**。三腿齐备不等于任何具体对象在卡面上的样子已核对。

**因此：不得据本表全绿声称「呈现收窄不会漏」或「该收窄已获机械保障」。** 它买到的是「**已知的那几条收窄不会被静默拆掉**」——一条腿被删、被判据绕过、或锚句在契约里漂走，会红。

## 3. 登记表

固定列（列序即解析序，删列或改列序即视为表结构变更，须同步改校验）：

| 收窄 | 规范锚句（逐字，无 Markdown 强调） | 规范来源 | 实现判据入口 | 守卫测试 | 须反向断言的例外 | 例外所在实现 |
|---|---|---|---|---|---|---|
| 待批准关闭期去向正文只给标记 | 去向正文只在「已关闭」期呈现 | web/docs/10-Web开发现状与设计语言基线.md | web/src/utils/workcaseCheckState.ts → workCaseDirectionTextVisible | web/tests/api/workcase-closure-narrowing-contract.test.ts → 接线：分期门控只作用于合并式渲染点 | 「待批准关闭期只给标记」约束 | web/src/components/WorkCaseResultDraft.tsx |

**锚句的取法**：取规范原文中**逐字存在**的子串（**照抄原文即可，含 `**` 强调也行**——校验在两侧都剥掉强调标记后比对，故照抄这一最自然的写法不会被拒，`docs/12` §4 的反向激励已消除；又因强调被排除在比对之外，契约只调整加粗不会让登记无谓脱钩）。锚句须是**该条收窄的载荷句**，不得取泛词（如「去向」「呈现」）——泛词在文中多处出现，删掉本行后校验仍绿，断言无判别力（该教训已在 `tests/api/workcase-closure-narrowing-contract.test.ts` 内实测过一次）。

**例外一项的取法与锚句同规格**：写该例外的**逐字载荷句**（在守卫与「例外所在实现」两侧都逐字存在的那个子串），不写描述句——描述句两侧都不逐字存在，第四腿必然恒红。其余描述写进契约或本表正文，不入单元格。

**例外所在实现**：例外被**遵循**的那处代码（收窄的**施加点**，未必等于判据入口——本次即如此：判据在共享模块，而施加点在卡组件，过度收窄正是在施加点发生的）。

**例外一项为空时写 `无`**，此时「例外所在实现」也写 `无`；写 `无` 的行不校验第四腿。

## 4. 何时须新增一行

**判据（软约束，`12` §7 复核清单承担）**：本次改动若**收窄了某期的呈现内容**（此前呈现、此后不呈现，或反之），须在本表新增一行并配齐三腿；若该收窄带例外，例外须在实现与守卫两侧留字面且被反向断言。

**明确不属本表登记对象**：块序调整、着色与分区、密度与折叠阈值、文案措辞——这些不是「不呈现」类收窄，且多数不满足「靠不写代码成立」这一弱点前提。把它们也塞进来只会让本表变成「所有呈现纪律的第二个副本」，而副本必然与契约漂移。

## 6. 变异三连记录（`12` §2，2026-10-15 实测）

**第 1 项——目标错误按真实写法注入**（每次注入后还原）：

| 注入 | 观察 | 结论 |
|---|---|---|
| 改写契约里的锚句（`去向正文只在「已关闭」期呈现` → 近义改写） | 红（第一腿） | 契约一漂移即报，符合设计 |
| 改判据入口名（追加 `RENAMED` 后缀） | **首版全绿 → 已修** | 见下「本表自身被抓出的两处」 |
| 改守卫测试名 | 红（第三腿） | 捕获 |
| 删实现侧的例外字面 | 红（第四腿） | 捕获 |
| 删掉一列 | 红（结构） | 捕获 |

**第 2 项——合法形态是否被误伤**：追加一条「例外＝`无`」的第二条收窄登记 → **全绿**（不误伤）。
途中暴露一处**反向激励**：首版要求锚句不含 `**`，于是「照抄契约原文」这一最自然的写法**被拒**（`12` §4 的判据：惩罚了诚实输入）——已改为**两侧都剥掉强调标记后比对**，照抄含 `**` 的原文现在通过，而契约只调整加粗也不再让登记无谓脱钩。

**第 3 项——语义等价改名是否逃逸**：**逃逸成立**。判据恒返 `true`（名字不动、语义反转）时本表**全绿**——本表只核三腿的存在性，不核语义。此逃逸由**行为断言**接住：`workCase-closure-narrowing-contract` 的纯函数用例实测转红（21 通过 / 1 失败）。故本表与行为断言是**分层**的，谁都不得单独声称已获保障。

**本表自身被抓出的两处（如实登记）**：
1. **子串假阴性**：第二、三腿首版用 `includes`，把 `workCaseDirectionTextVisible` 改成 `…RENAMED` 后**仍然命中**——改名逃逸。已改为**词边界匹配**（含中文字符邻接）。
2. **反向激励**：见第 2 项。两处都是**先写、后由变异抓出**，次序记在此处，以免后人以为首版即完备。

## 5. 已知边界（沿用 `12` §3 的形态/语义分离口径）

- 校验是**源码文本断言**，非行为断言：它读文件、断言标识符与字面存在。
- 语义等价改名逃逸**成立**（`12` §2 第 3 项；本表 §6 第 3 项实测）：把 `workCaseDirectionTextVisible` 改名、保留全部语义接入渲染路径，本表校验仍绿（除非登记表同步改名——而要求同步改名的正是被登记的那条纪律本身）。
- 「锚句存在」只证明**契约里仍写着那句话**，不证明**实现遵循了那句话**——两者之间由实现判据入口与守卫测试两腿承接，而这两腿仍是文本断言。
