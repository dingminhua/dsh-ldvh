# ObjectList 对象列表

> 路由：`/objects/:type`
> 源码：`web/src/pages/ObjectList.tsx`
> API：`GET /api/objects/:type`；各对象按各自契约使用 `?status=` 与 `?priority=` 等筛选参数。atus=<status>`
> 图标规范：[`09-图标语义规范.md`](./09-图标语义规范.md)

> **v5 增量基线**：v5 迁移后的类型更名（Study→Research）、联邦视图、项目色彩与字号定案见 [`11-v5Web开发增量.md`](./11-v5Web开发增量.md)；与本文冲突时以 11 号为准。

## 1. 页面目标

对象列表用于浏览单一对象类型下的事实对象，并通过该对象类型的浏览分类快速缩小范围。派生分类不得写成事实状态或生命周期。

对象类型切换由左侧主导航完成，本页不再提供顶部类型标签页。

对象列表页是主选择面，不承接详情页的右侧扩展阅读状态；进入 `/objects/:type` 时 App Shell 应主动关闭扩展阅读区。

## 2. 当前页面结构

```text
浏览筛选（使用 ObjectStatusFilter，Spark 另有 ObjectPriorityFilter）
对象卡片自适应网格（ldvh-section-grid）
  通用卡片：ID + 优先级字符徽标 + 状态徽章 + 标题 + 信号标签 + 更新时间
  对象卡片：对象身份 + 状态 + 该类型的专属正文
加载态 / 错误态 / 空态
```

## 3. 区域详细设计

### 3.1 浏览筛选

- 位于列表顶部。
- 浏览筛选及同层任务态势图例属于列表切换控制区，必须固定在主滚动容器顶部；对象卡片列表在其下方滚动。
- 浏览筛选由 `ObjectStatusFilter` 展示该类型的来源状态闭集losed` 五个进展分组及“全部”，数量读取 API 的 `progressOptions`；五个值的显示顺序固定，“全部”放在最后。
- 筛选写入 `?status=<来源状态>`；未选筛选时展示全部对象。
- 其它对象由 `ObjectStatusFilter` 根据各自状态契约展示“各状态 + 全部 + 数量”，并把选择写入 `?status=<status>`。
- 两类筛选都使用全局 tab 样式：`ldvh-tab-list`、`ldvh-tab-button`、`ldvh-tab-button-active` 和 `ldvh-tab-button-idle`，与提交记录页加载范围、type、scope 筛选保持一致。
- 数据返回前先渲染稳定的筛选占位，数字位置使用轻量加载动画，避免对象卡片先出现、顶部筛选后插入造成页面跳动。
- 无法判定分类的对象仍属于“全部”的读取范围，但不能被猜入既有分组；界面应如实保留其不可判定状态，不能用已退出显示词补造分组。
- 点击对象进入详情页时保留当前 query，使详情页返回路径与列表筛选一致。

### 3.2 对象卡片

- 使用 `ldvh-section-grid`，列数由容器宽度自动决定。
- 不使用表格视图，不使用顶部类型标签页。
- 所有对象卡片一律按 `updated` 时间倒序排列，最近发生变化的对象在最前；状态只用于筛选、徽章和卡片内容表达，不参与排序。
- 通用卡片结构：
  - 左上：对象 ID，`ldvh-meta-muted`；
  - 右上：`StatusBadge` 后紧邻“复制对象 ID”图标；列表只是候选发现，不显示或复制精确来源路径，复制值仅为稳定 `object_id`；
  - 中部：本地化标题，`ldvh-card-title`，放入轻量标题带，左侧使用状态语义短线突出，不通过放大字号突出；标题必须允许换行完整显示，不得用截断省略代替阅读；
  - 优先级字符徽标：Spark 如存在 `priority`，在 ID 后面展示 `P0` / `P1` / `P2` / `P3` 字符徽标；标题行只保留 `ObjectTypeIcon(obj.type)` 和标题。徽标使用颜色、轻量边框和 tooltip 表达优先级，不作为错误或阻塞状态；
  - 可选信号：仅当对应对象的字段契约定义该字段时展示；`priority` 只适用于 Spark，不得为其它类型杜撰 priority，也不得为任何对象杜撰 importance、category 或 tags；子目标的 `order`（28 §8 显示次序）属同一层级——它是跨条比较的扫读要素，故不在卡体判据框内呈现，而是与优先级并列作为卡头标签（类型 → 优先级 → 次序 → 修改次数），样式与该行其余标签同规格（`.ldvh-chip-sm`、12px 图标）；`order` 可缺失，缺失时保留标签、值显示为 `·` 并以 tooltip 说明，不得补隐式编号，也不得为缺失而隐藏整枚标签（否则读者无法区分「没有次序」与「忘了呈现」）；DevLog 的 `occurred_at`（29 §10.4「这件事发生的时间」）**不在卡头呈现**（2026-11-02 二次定案，见 §3.5bis）——它是排序轴与回查轴，不是逐卡必显的身份信息；条目在自己的卡面上重复给出它已经记下的时间没有新增任何可读信息；Spark 不维护 category；Pitfall 不维护 repeatability；importance 字段已由 priority 统一承载，不作为独立字段使用
  - 子目标卡的**判据面**：几何取全站统一的判据面形态——四边同宽 1px、`rounded-lg`、`px-3 py-2`，不使用左侧加粗竖线；但**色相取本类型色**（`getTypeSurfaceTint('subgoal')`，见 [`11-v5Web开发增量.md`](./11-v5Web开发增量.md) §4terdecies），不得整面复用另一个类型的颜色——两个不同类型共用一色等于让卡体替另一个类型声明身份。框内**只放一句 `criterion`**：`order` 在卡头（见上一条），`criterion_kind` 是判定口径、在详情面只以「判法」节点出现（其闭集名不上屏，见 [`11-v5Web开发增量.md`](./11-v5Web开发增量.md) §4novies），两者都不上卡面；不画圆点（圆点是并列条目之间的分隔记号，本框恒为一句）。`criterion` 为空时不渲染空框——载体不合规由详情页字段问题区如实报出。
  - 终态处置：ADR、Pitfall 与 Spark 不复用泛化的“非活跃原因”字段。它们在各自终态卡片中只读取 `disposition_summary`，用弱圆点与小号正文承载，不另造“退出理由”“关闭时间”“处置时间”标签；缺失时如实显示处置缺失提示，仍不得压过标题、状态和更新时间。
  - 正式 `relations` 由所有五类对象 Card 统一呈现：同一稳定目标只呈现一次，即使来源以多个 relation key 关联它；使用对象语义图标、完整标题和关联状态图标；悬停显示文字：待处理的 Spark、Pitfall draft 使用待处理图标（**带圈问号 `CircleHelp`**；五族行末图标的集中登记见 [`09-图标语义规范.md`](./09-图标语义规范.md) §4.1）；推进中的对象使用推进图标；其余可读的活跃对象使用活跃图标；所有可读终态关联也保留，已关闭使用勾选图标，已废弃使用灰色废弃图标。已废弃关联整行进一步使用中性 slate 灰色弱化对象图标、标题、状态图标和 hover/focus 反馈，但仍保持可读、可进入和完整标题。关联严格按“活跃 → 推进中 → 待处理 → 已关闭 → 已废弃”排序；不可用关联保留在这些状态之后并显示“关联信息不可用”。不设“关联”标题、类型分组标题、对象 ID 或复制按钮，不折叠或截断。它不是链接、URL、材料或引用列表，也不据此推断分流、依赖、承接责任或终态处置。仅当前项目内精确读取成功的目标可点击并打开扩展阅读；跨项目、缺失、不可读或结构无效的关联明确显示“关联信息不可用”，不猜标题或静默遗漏。**唯一例外是子目标卡「名下的工作」区**（见 [`11-v5Web开发增量.md`](./11-v5Web开发增量.md) §4quinquies）：该区按类型**分块**且每类各有独立展示预算（先展固定条数、其余可展开），故允许折叠；**「不设类型分组标题」对该区同样成立**——它的块不带层名，行由行首类型图标自描述。行式与区域形态仍复用本节的统一关联行，不自建第二套。
  - Pitfall 状态筛选使用 `draft / active / discarded`，分别显示“待确认 / 活跃 / 已废弃”；`discarded` 与其终态处置说明均使用中性灰，红色只保留给 Pitfall 类型识别。Pitfall 卡片不提供 promote、discard 或批量审核控件，也不展示 `tags` 或冗余解决态。
  - 底部：只展示更新时间，使用 `formatDateTime()`，格式为 `YYYY-MM-DD HH:mm`，样式为弱化元信息 `ldvh-meta-muted`；更新时间行使用 `mt-auto` 贴近卡片下边距，避免不同标题行数或中部内容高度导致时间上浮；对象列表以更新时间排序，创建时间留在详情页身份区展示。
- 复制对象 ID 只复制，不触发导航。只有详情或引用行完成精确读取并取得可消费 `canonical_path` 后，才可另行显示复制对象路径入口。
- hover 时边框变为 `border-ldvh-accent/40`，标题变 accent 色。
- 卡片标题不得超过全局 `ldvh-card-title` 字号；标题强调优先使用轻量背景、位置、留白、状态语义短线和 hover 反馈。

### 3.3 ADR 卡片

ADR 是已经形成、并应在适用边界内执行的当前决策。列表卡片只帮助用户定位当前决策，不在卡片内展开决策影响范围。

- ADR 状态筛选只认 `active / retired`。`active` 是当前有效决策；`retired` 表示不再作为当前决策入口，中文显示为”已废弃”并使用中性灰。
- ADR 卡片使用通用卡片结构：ID、状态、完整标题、更新时间；`retired` 时在标题之后以弱处置正文展示 `disposition_summary`。
- ADR 标题就是最好的摘要；除 retired 的处置正文与通用正式关联区外，卡片不展示 `decision_question`、`decision`、`applicability`、`rationale`、`consequences`或未采纳备选摘要。
- ADR 卡片标题必须允许换行完整显示，避免用截断标题替代决策识别。
- ADR 卡片不展示 `related_rules` chip，也不展示 `superseded_by`、`proposed`、`accepted`、`rejected`、`superseded`、`alternatives` 或 `affects` 等旧生命周期和旧字段信息。

### 3.5 Spark 卡片

Spark 是“待处理信息”卡片，列表态用于快速定位每条火花，并在已经形成终态处置时提示闭环事实；待处理卡片不展开意图、摘要、演变或长正文。

- Spark 卡片保留通用头部、标题、优先级字符徽标、状态和更新时间。
- Spark 卡片不使用通用非活跃原因块；卡片中部只由 Spark 闭环状态驱动。
- Spark 卡片中部状态内容必须使用与 Pitfall 归档原因一致的弱说明表达：弱圆点、小号标签、小号正文，无彩色外框、无大面积状态底色、无 section 标题级强调。
- `open` 时，卡片中部不展示 `intent`、`summary` 或 `evolution`；这些内容留在详情页按阅读节点展开。
- `implemented` 与 `discarded` 时，卡片中部展示 `disposition_summary`。`implemented`（已关闭）使用低饱和蓝灰，`discarded`（已废弃）使用中性灰；状态徽章说明终态类别，正文说明实际处置；不在卡片中显示承接目标、额外终态时间或旧的 `resolved_to` / `resolved_at` / `discard_reason` 投影。历史 `routed` 仅保留直接只读查看，不是当前列表状态。
- 实际存在 `relations` 时，Spark 与其它四类对象一样使用 §3.2 的通用正式关联区；它不表示链接或分流。
- Spark 卡片内部信息区域只用于阅读，不响应主路由跳转；只有卡片标题进入 Spark 详情页，ID、状态、正文、更新时间和卡片空白区域均不触发导航。

### 3.5bis DevLog 卡片

DevLog（29 号）是**已发生工作的结论条目**：它记录「这件事我做过了、结论是什么、边界
到哪里」，与「待处理」类对象（Spark）不是同一件事。列表
卡只帮读者定位一条结论，不展开依据。

- 卡头与其它类型同序：类型 → 优先级（本类型不适用）→ 修改次数。
  **发生时间不在卡头**（2026-11-02 二次定案）：`occurred_at` 由「按 `occurred_at`
  排序的条目清单」承担回查职责（29 §12.1「时间线回查」），29 §10.4 已同步订正——
  单个条目不必在自己的卡面上重复给出它已经记下的时间。`DevLogOccurredBadge`
  随该决定一并退场（它只有一个消费方，留着就是无人消费的壳）。
- **卡体正文读 `summary`，不读 `title`**：29 §8 明文标题是 ≤40 字的定位短标题、
  不承载结论；`summary` 才是「当前语义快照」（结论 + 当前适用边界 + 已确认不成立
  的情形）。长结论用 `SummaryText`（阈值 420）折叠，不得用截断标题代替阅读。
- `summary` 为空时不渲染空框，显示「结论缺失」提示——载体不合规由详情页字段问题区
  如实报出，列表不得替它编一句话。
- 承载 `summary` 的那一块按**本类型色**上色：几何取全站统一的判据面形态
  （四边同宽 1px、8px 圆角、8/12 内距），色相取 `getTypeSurfaceTint('devlog')`
  （青绿 `#2c9e43` 与卡头 chip 同源）。正文色必须经 `SummaryText` 的 `bodyStyle`
  传入——Markdown 渲染出的 `<p>` 由 `github-markdown-css` 着色、不继承外层 `color`，
  只给外层设色会得到「彩色面 + 近黑正文」的分家形态（2026-11-02 实测）。
  取舍理由见 [`11-v5Web开发增量.md`](./11-v5Web开发增量.md) §4terdecies。
- 终态（`absorbed` / `superseded` / `dropped`）不换卡体形态：三者都仍是「一条结论」，
  差别在状态徽章与详情页的承接/推翻边说明，卡面不另造终态处置块。
- 与子目标卡一样，正式 `relations` 走 §3.2 的统一关联区（承接边 `absorbed-into`
  的 commit 形态已在关联侧支持）。
- `refs`（内容关联）走**同一块**统一关联区（2026-11-02 采用面扩展，29 §8/§11/§12.3bis、
  02 §7.1/§8.2）：条目侧登记自己与哪些事实对象有内容依据／输入／相关，与对象侧指向
  条目的 `refs` 是**两侧各自声明**、互不复制反向边；生命周期关系仍走 `relations`。
  关联行的呈现形态因此与 Spark 卡完全一致——这正是「关联事实对象的处理参考
  spark」的落点。

### 3.5ter 规范卡片

Norm（27 号）是**一个工程方向的成体系规则体系**：四段固定正文（方向定位与适用范围／
核心规则体系／约束与反模式／验证与遵从性检查）构成一个方向的长效规范。

- **活跃规范卡不承载任何卡体内容**（Human 定案 2026-11-02）：只剩卡头（类型 / 标题 /
  状态 / 修改次数）与标题。与 ADR 卡同形——`NormCardContent` 活跃态返回 `null`，只有
  retired 才有卡体（退出理由 `retirement_reason`，闭集同 22 号形态，走 `TerminalFactPanel`）。
- **撤除的两样东西及各自理由**（不是同一条）：① 方向键块（`direction_key` + 紫壳 chip）
  ——方向键是唯一性公式与索引的**机器作用域**，不是列表里挑选条目的依据，标题与正文首段
  才是「这份规范管哪个方向」的答案；② 类型说明行（「事实规范——一个工程方向的成体系
  规则体系（27 §1）」）——它是**类型定义的复述**，卡头 chip 已写「规范」，重说一遍违反
  `docs/10` §5.5「同类信息只有一处行式」。后者能存活至今只因它与方向键同处一壳，被误当
  作「这个块的说明」。
- 由此 `DECISION_CARD_SHELL_CLASS.violet`、`DECISION_TITLE_HUE_CLASS.violet`、
  `DECISION_VIOLET_CODE_CHIP_HUE_CLASS`、`TYPE_DESCRIPTION_LOCALES` 全部退场（详见
  [`11-v5Web开发增量.md`](./11-v5Web开发增量.md) §4undecies）。
- 状态筛选只认 `active / retired`；`retired` 卡为中性灰并显示退出理由。

### 3.6 Spark 创建边界

Spark 列表页保持只读；Web 不提供 Spark 创建、直接捕获、写入或由表单生成 Spark 的入口。Spark 的对象化、既有对象查重和受控创建只由 AI 按 20 与 31 的规则调用 Helper 完成；Web 只呈现当前事实源中的结果。

### 3.7 空态、加载态、错误态

- 加载态：居中旋转动画。
- 错误态：`common.loadFailed` + 错误信息。
- 空态**分两句**（Human 定案 2026-11-02），判据是 `statusTotal`（服务端按**未应用状态
  筛选**的池子计数）而非 `items.length`：
  - `statusTotal === 0` → `objectList.noObjects`（「还没有{type}对象」）：这个类型本来就
    没有任何对象，下一步是去建；
  - 否则 → `objectList.noObjectsUnderFilter`（「当前筛选条件下没有{type}对象」）：对象有，
    是状态筛选/搜索把它们挡掉了，下一步是放宽筛选。

  用 `items.length` 判会把「筛选后为空」误报成「本来没有」。`{type}` 必须经
  `getTypeLabel(type, locale)` 本地化——不得直塞原始类型键（`norm` / `devlog` 之类），
  那会在中文界面里露出英文键名。两句都不得拼 raw 中文句子。
- **「该事实类型尚未接入」不再作为空态出现**：对象目录缺失已按零对象处理（判据与实测
  见 [`11-v5Web开发增量.md`](./11-v5Web开发增量.md) §4duodecies）。`type_not_integrated`
  这个覆盖状态仍在前端契约里（三个筛选器按它显示 `—`、覆盖警示条按它工作），只是后台
  不再因「目录不存在」产出它。

### 3.8 五个基准模块中的对象列表基线

研究、决策、火花、经验四个对象列表已经进入五个基准模块，应作为非工作主线对象卡片的统一基线。提交列表不属于工作对象列表，但其卡片网格、标题带和底部更新时间必须与这四类对象列表保持同一视觉语言。

- 四类对象都使用同一外层卡片框架：浅边框、`ldvh-panel` 背景、`p-4`、`gap-3`、hover/focus 轻微 accent 边框反馈。
- 顶部区域统一为左侧对象 ID、右侧状态徽章；候选卡不伪造或复制来源路径，也不得在右侧操作区加入强视觉按钮。
- 标题带统一使用弱背景、内圈边框、左侧语义短线、对象类型图标、完整标题和右侧进入箭头；标题使用 `ldvh-card-title`，必须允许换行完整显示。
- 更新时间统一放在卡片底部右侧，使用 `formatDateTime()` 和 `ldvh-meta-muted`；列表排序统一按 `updated` 倒序，最近发生变化的对象在最前。
- 研究、决策、火花和经验在列表态只展示对象定位所需信息与通用正式关联区，不展开长正文；ADR 的 `retired`、Pitfall 的 `discarded` 与 Spark 的 `implemented` / `discarded` 才展示终态 `disposition_summary`，并使用弱说明表达，不升级为强状态模块。
- 终态处置在决策、经验和火花中保持一致：弱圆点、小号正文、无额外标签、无醒目外框、大面积状态底色或标题级强调。
- 四类对象必须继续使用同一 `ObjectStatusFilter` tab 视觉；状态数量数字使用 `ldvh-tab-count`，不得在单个对象页局部改大、改粗或拉开间距。

## 4. 交互

| 操作 | 行为 |
|---|---|
| 点击左侧导航类型 | 切换到对应 `/objects/:type` |
| 点击浏览筛选 | 更新 `status` query；按 query 重新读取列表 |
| 点击对象卡片外层空白、标题带、ID、状态徽章或更新时间 | 跳转到当前对象详情页，保留当前 query，并把当前列表 URL 记录为详情页返回来源 |
| 点击任意对象 Card 的正式关联行 | 在右侧扩展阅读打开对应对象，不改变当前列表路由 |
| 点击卡片内部信息框、区块标题、态势条或普通信息区域 | 不触发路由跳转，不表现为独立可点控件 |
| 从详情页返回对象列表 | 主内容回到 `/objects/:type`，并主动关闭右侧扩展阅读区 |
| 切换语言 | 状态、标题和空态文案同步切换 |

## 5. 实现约束

1. 不恢复顶部对象类型标签页；类型导航已经统一到左侧侧栏。
2. 不把列表改成表格；当前事实对象用卡片扫描。
3. 不展示 raw ISO 时间，统一使用 `formatDateTime()`。
4. 不在列表卡片里复述完整详情，只展示当前已确定的分组专属内容。
   - `closure_confirmation` 的结论语义块固定显示“关闭提案”，标题已提供提议身份，因此右侧只显示“目标达成 / 部分达成 / 未达成 / 取消”（英文“Achieved / Partial / Not achieved / Cancel”）的紧凑分类标签，不重复“提议结论 / Proposed conclusion”前缀；整体统一使用中性提案图标和琥珀色提案色调，不把提案分类表现成既成状态。`closed` 的总体语义块固定显示“终态处置”，读取 `closure_outcome` 选择语义色与图标，但 Card 不再重复显示“完成”等第二状态标签。
5. 候选对象卡片不得用对象 ID、导航 target 或空 `path` 冒充来源路径；精确读取成功后再在详情或引用消费点提供复制入口。
6. 执行项不作为一级导航 tab，也不拥有独立详情路由。
7. 对象卡片只有标题是当前对象详情入口，并提供统一 hover/focus 反馈；ID、状态、正文、更新时间和卡片空白区域均不触发导航。正式关联行是唯一可单独响应的内部控件，并只打开扩展阅读；内部工作项不拥有独立详情路由。

## 6. API 数据结构

对象列表 API 只向 Card 交付当组实际消费的最小字段。所有当前事实类型在 Helper 已确认的管辖 worktree 内由 Web 直接读取正式载体；页面字段缺失或类型不符保留为逐字段问题，额外、旧或无法归类的结构保留在 `unparsed_structures`，不经过 Core 全量校验、Python machine 或第二份 Schema。列表使用同一字段级读取结果投影 Card，并保留 `read_status`、读取问题、字段问题与未解析结构供范围提示。

列表顶层返回字段级直读的范围与集合问题：`coverage_status` 与 `collection_issues`。对象卡携带自己的 `read_status`、`read_issues`、`field_issues` 与 `unparsed_structures`；集合问题保留准确路径、原因和消息，不以旧 machine 的 `invalid / not_found` 分类替代。页面必须保留已形成的可消费 Card，独立展示集合问题与未完成范围；不设置列表级“观察时间”或“重新读取”控件。筛选或导航发生时照常发起新的列表请求，不能复用旧 payload。读取失败时页面必须保留实际失败原因，不得回退其它读取路径或显示伪零值。
