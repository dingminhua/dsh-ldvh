# 图标语义规范

> 路由范围：LDVH Web 全部页面
> 图标库：`lucide-react`
> 上位规范：[`specs/08-Web 呈现与交互规范.md`](../../specs/08-Web%20呈现与交互规范.md)、[`specs/21-WorkCase-工作项.md`](../../specs/21-WorkCase-工作项.md)
> 关联文档：[`01-全局设计约束.md`](./01-全局设计约束.md)、[`03-ObjectList.md`](./03-ObjectList.md)、[`04-ObjectDetail.md`](./04-ObjectDetail.md)

## 1. 目标

图标用于帮助 Human 快速识别对象类型、状态、集合语义和操作入口。图标不是装饰，不应因为局部视觉效果随意替换。

本文解决四类图标的边界：

1. 对象类型图标：回答“这是什么对象”；
2. 状态图标：回答“工作项当前处于什么状态”；
3. 操作图标：回答“点这里会做什么”；
4. 分区提示符：回答“这里是一个阅读分区或分组”。

## 2. 基本规则

1. 同一对象类型在导航、列表、详情、引用卡片和右侧扩展阅读区中必须使用同一个对象类型图标。
2. 同一操作在所有页面中必须使用同一个操作图标，不随对象类型改变。
3. 状态图标只表达状态，不替代对象类型图标。
4. 对象身份标题必须使用对象类型图标；包括 WorkCase 的列表卡片标题、详情页标题和引用行标题。工作项使用工作项图标，但不得被表达为一级对象身份。
5. 页面大区块、状态分组和工作项状态标题如果只是阅读分区，不承担对象身份识别，统一使用小圆点，不额外引入语义图标。
6. 业务页面不得直接导入对象类型标准图标表达对象身份，必须通过 `ObjectTypeIcon`、`CollectionTitleIcon` 或 `OBJECT_TYPE_ICONS` 映射取得。
7. plain 行中的右侧操作图标默认是中性 ghost；类型色只用于左侧类型识别、ID 或短标签。
8. 复制是稳定工具动作，默认和 hover 都保持中性 ghost；tooltip 必须按对象路径、文档路径、链接、引用、提交上下文或提交 hash 区分；扩展阅读、进入箭头等导航/阅读动作可在行 hover、当前打开或明确选中时继承所在分组/状态色。
9. 如果现有 lucide 图标不能准确表达对象类型，应新增本地语义封装或设计自定义图标，不用相近但语义错误的图标凑合。

## 3. 对象类型图标

对象类型图标只用于识别对象类型。禁止用对象类型图标表达状态。

| 对象类型 | 标准图标 | 用途 | 备注 |
|---|---|---|---|
| 项目认知中心 | `LayoutDashboard` | 主导航、页面入口 | 认知中心入口图标；2026-07-30 按 Human 决定换回 `LayoutDashboard`（见 02 §0.1）；导航可见名 label 为「聚焦 / Focus」 |
| WorkCase | `Shovel` | 工作导航、工作引用、WorkCase 详情身份识别 | 表达动手开挖、推进工作的行动语义；不得用 `MapPinned`、`GitBranch` 或静态人员图标 |
| 工作项 | `ListTodo` | WorkCase 内部工作项行 | 表达局部工作单元；不得作为一级对象类型图标 |
| ADR | `FileSignature` | 决策导航和决策引用 | 表达已记录的决策 |
| Pitfall | `Lightbulb` | 踩坑经验导航和踩坑经验引用 | 表达可复用踩坑经验，不得用 `Bug` 避免误解为缺陷列表 |
| Spark | `Sparkles` | 火花导航和引用 | 表达未定型工作信号被接住时的火花；不得回退为笔、便签或灯泡，避免和创建动作、普通记录或踩坑经验混淆 |
| Git 提交记录 | `GitHubSilhouette` | 提交记录入口 | 以 GitHub 剪影表达 Git 历史入口，不表达工作对象 |
| Git 提交引用 | `GitCommit` | 提交条目和提交引用 | 表达单次 commit，不表达导航入口 |

### 3.1 工作项图标说明

工作项只作为 WorkCase 内部工作单元展示，不是独立事实对象。当前采用 lucide 原生图标表达这一稳定语义：

| 图标 | 语义 |
|---|---|
| `ListTodo` | WorkCase 内部工作项；只识别局部工作单元，不表示一级事实对象 |

`ExecutionFlowStatus` 可在工作项行中表达当前状态，但对象引用、对象入口和类型标签不得把工作项提升为一级事实对象。

## 4. 状态图标

状态图标由 `ExecutionFlowStatus` 统一表达，用于 WorkCase `work_items` 的当前状态。

| 状态 | 当前图标 | 中文语义 |
|---|---|---|
| pending | `CircleDashed` | 待执行 |
| in_progress | `CirclePlay` | 进行中 |
| blocked | `Hourglass` | 已阻塞；具体原因读取该工作项的 `blocking_summary` |
| completed | `CheckCircle2` | 已完成 |
| cancelled | `CircleX` | 已取消 |

状态图标可使用状态色和弱背景；对象类型图标不使用状态语义。

## 5. 操作图标

操作图标只表达动作。它们默认不承担对象类型或状态表达。

| 操作 | 标准图标 | 规则 |
|---|---|---|
| 复制对象 ID / 对象路径 / 文档路径 / 链接 / 引用 | `Copy`，成功后 `Check` | 统一通过 `CopyPathButton`；点击必须 `stopPropagation()`；列表 Card 的 Copy 只复制稳定 object ID |
| 打开右侧扩展阅读 | `ChevronRight` | 未打开时统一向右，表达内容进入右侧阅读区 |
| 关闭当前扩展阅读 | `ChevronLeft` | 当前行已在右侧展开时统一向左，表达从右侧收回 |
| 进入详情主路由 | `ArrowRight` | 只用于主路由入口；默认弱灰，hover 轻微右移 |
| 展开/收起集合 | `ChevronDown` / `ChevronRight` | 只表达折叠状态，不表达对象类型 |
| 外部链接 | `ExternalLink` | 只用于外部 URL |

plain 行和状态色背景行中，`Copy`、右侧扩展阅读方向箭头、`ArrowRight` 默认同级弱灰；状态表达交给左侧状态图标、行背景和状态条。状态色背景行 hover 时，右侧扩展阅读方向箭头和 `ArrowRight` 可切到该行背景对应的状态色；`Copy` 只有自身 hover 时才变色。右侧扩展阅读方向箭头与 `Copy` 并列时保持同一 28px 操作容器；Chevron 图形可使用 16px，以抵消线形箭头的视觉偏小。

## 6. 标题图标与分区圆点

标题前的视觉符号分为两类：对象身份图标和分区圆点。不要混用。

| 场景 | 标准表达 | 示例 |
|---|---|---|
| 对象标题 | `ObjectTypeIcon(type)` | WorkCase 卡片标题、WorkCase 详情标题、WorkCase 引用行标题 |
| 对象引用行 | `ObjectTypeIcon(type)` | 决策 / 火花 / 踩坑经验 / WorkCase 引用 |
| 阅读大区块 | 小圆点 | 目标、成功标准、结果与验证、终态处置 |
| Card 语义区标题 | `14px` 语义图标 | WorkCase 卡片中的“目标”“当前情况” |
| 工作项区域标题 | 标题文字或当前状态图标 | WorkCase Card 使用状态图标；详情内嵌折叠标题不重复放置图标或圆点 |
| 工作项状态 | `ExecutionFlowStatus` 状态图标 | 工作项行左侧的待执行、进行中、已阻塞、已完成、已取消状态 |

如果 lucide 图标对某个对象类型过于抽象，应先在 `SemanticIcon.tsx` 新增本地语义封装；必要时可使用短文字徽标，例如 ADR，但仍必须通过统一组件输出，不在页面里临时拼写。

## 7. 颜色规则

1. 对象类型图标按所在层级决定颜色：对象卡片标题和详情页主标题使用对象类型色；状态色行或状态色分组内的对象图标继承标题文字颜色，不单独使用对象类型色或 `ldvh-accent`；plain 引用行可使用对象类型色。
2. 状态图标使用状态色，例如待执行 sky、进行中 emerald、已阻塞 amber、已完成 zinc、已取消 neutral。工作项状态只能来自 `pending / in_progress / blocked / completed / cancelled`。
3. 操作图标默认使用 `text-ldvh-text-secondary/70` 或等价弱灰。
4. 当前行处于状态色背景时，左侧状态图标、行背景和态势条承担状态表达；对象类型图标不得再叠加另一种彩色。
5. 右侧操作图标默认保持中性弱灰；复制图标只有自身 hover 时切到该行背景对应的状态色。
6. 类型色和状态色冲突时，优先保持状态判断清晰；对象类型可弱化为继承文字色或弱标签。

## 8. 实现建议

图标映射集中在 `web/src/components/SemanticIcon.tsx`，页面不得自行散落对象类型和集合标题图标选择。

```typescript
export const OBJECT_TYPE_ICONS = {
  workcase: Shovel,
  adr: FileSignature,
  pitfall: Lightbulb,
  spark: Sparkles,
  study: FileSearchCornerIcon,  // 项目自定义 SVG 图标，见 SemanticIcon.tsx
  changelog: GitHubSilhouette,
};
```

语义组件：

1. `ObjectTypeIcon`：按对象类型返回标准图标；
2. `CollectionTitleIcon`：只用于确有集合身份识别需要的入口；普通页面分区优先使用小圆点。

操作图标暂由 `CopyPathButton`、`ReferenceCard` 和页面内按钮承接；后续如继续扩展操作种类，再抽 `ActionIconButton`。

## 9. 当前待收敛项

1. 核心对象入口已接入集中映射：Sidebar、项目认知中心收件箱、ObjectList、ObjectDetail、ReferenceCard、ReadingPanel。
2. 后续如继续扩展操作种类，可抽 `ActionIconButton`，进一步收敛复制、扩展阅读、进入详情和外部链接的尺寸与 hover。
3. 如果后续认为 `ListTodo` 与 LDVH 工作项语义仍不够贴合，再新增本地自定义工作项图标；在此之前不得回退到状态图标或通用层级图标。
4. 项目画像类入口不属于当前对象类型、导航入口或图标语义；管辖项目配置如需展示，应按管辖配置自身语义另行设计，不复用项目画像图标或对象类型。
