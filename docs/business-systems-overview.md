> 性质：**讨论工作稿（非规范、非候选、非事实对象）**——本会话（2026-09-07）多轮收敛的成果，作为 00 §3.1 规范修订候选的唯一底稿。未走 01 §11/§12 流程前，规范源原文（specs/00-理念与构成.md §3.1 八维）仍是唯一权威。
> 依据：specs/00-理念与构成.md（§3.1 八维定义 / §3.5 四种价值交付方式）+ docs/team-control-foundation-draft.md（v5，Human 终审通过）+ docs/eight-dimension-host-mapping-draft.md（§1–§8 各维定案）+ 四份外部调研（dsh-mnemon / dsh-solo-thinking / dsh-deep-research / dsh-workflow）+ 本会话 3 次子代理并行分析（内部结构 ×2 / 宿主能力 ×1，其中 1 次跑偏不采信仅作佐证）。

## 0. 一句话结构

> **LDVH 工作模型 = 3 个基础系统（读/写/编排）× 4 个业务系统（记忆/调研/讨论/遵守）× 开放制度集合（复核、沉淀……）× WC 工作模式（Gate1→Gate2）**

基础系统回答"怎么跑"，业务系统回答"做什么"，制度回答"怎么保证做对"，WC 模式回答"怎么收口"。

## 1. 基础系统（3 个，封闭集合）

机械能力，零业务语义，被所有业务系统调用。

| # | 系统 | 定义 | 外部参考 | 内容 |
|---|---|---|---|---|
| 1 | **读** | 信息拉取——取得当前工作所需且来源明确的信息 | LDVH 自建 | 规范层 L0–L4 + 事实层 F0–F4 渐进披露；引导注入 |
| 2 | **写** | 受控落盘——把已经明确去向的内容受控写入，并核对实际结果 | LDVH 自建 | 落盘器（原子写 + SHA-256 指纹门 + 回读）+ Git Gate |
| 3 | **编排** | 子代理全生命周期管理——怎么把代理跑起来、管住、收回 | dsh-workflow（11 条不变量）+ 底座 v5 | **= 团队控制底座 v5 §1.1–§1.7 全部内容**：spawn 纪律 / 信道 A·B·C / 漂移防护 / L1–L4 中断恢复 / 结果回收 / 成本三闸门 / 并发分区 |

**编排的宿主 API 面**（0.1.2-rc.1 已核验）：`startContinuable + toolFilter`（受控物化）/ `sendMessage`（双向通信）/ `interrupt`（parked 语义中断）/ `listChildren / listDescendants / drainContinuable*`（送达对账）/ `tools.guard`（执行期拒绝）/ `jobs`（后台任务）。

**命名裁定（Human 2026-09-07）**：读/写/**编排**，不用"执行"——执行被两件事撕扯（"怎么把代理跑起来"的机械面 vs "怎么完成工作包"的业务面），"编排"永久解决此歧义。

## 2. 业务系统（4 个，当前集合）

业务能力，直接产生决策/行动/结论，各有唯一外部锚点。

| # | 系统 | 一句话定义 | 外部参考 |
|---|---|---|---|
| 1 | **记忆** | 存储经验不沉没——接收多入口候选，五路分流决定去留，idle 自动维护 | dsh-mnemon（三层控制平面） |
| 2 | **调研** | 深度挖掘——对着一个未知点挖到 EIG 边际增益为零，产出三态证据 | dsh-deep-research（EIG + confirmed/uncertain/gaps） |
| 3 | **讨论** | 广度扩散与收敛——多 AI 分支围绕目标对话，结构化分歧，judge 选定 | dsh-solo-thinking（思考树 + Handoff） |
| 4 | **遵守** | 规则在场——识别并落实适用的规则、事实、决定和授权 | LDVH 自建（七锚点 + ADR 枚举 + 网关） |

### 2.1 记忆系统（唯一跨维聚合的业务系统）

记忆横跨原八维中的四个维——这是它不能被折叠进任何单维的原因：

| 记忆系统的环节 | 来自哪个维 | 功能 |
|---|---|---|
| **存储** | 写维 | 事实对象（ADR/Pitfall/Study YAML）+ 热记忆中间档的持久化 |
| **检索** | 读维 | F0–F4 渐进披露读取 |
| **路由** | 沉淀维 | 五路分流：Pitfall / Spark / 规范流程 / Goal-Charter 修订 / 不对象化 |
| **维护** | 反思维 | idle 自动审查（容量触发压缩 / 归档 / 更新） |

### 2.2 反思引擎（记忆系统的维护子机制，Human 2026-09-07 定案）

**反思并入记忆，作为沉淀过程中的思考内容**。其完整设计：

```
反思引擎（隔离检查）
  ├─ 触发：idle（空闲）/ 容量（记忆满）/ 摩擦信号（执行现场供给）
  ├─ 动作：隔离上下文（fork worker，不污染主对话）对照
  │        Goal/Charter（参考信号）+ 审查记忆内容健康
  ├─ 产出：流水记录——只记录，不中断、不纠偏、不行动
  └─ 后续：人和主控读到流水 → 判断是否采纳
              ├─ 采纳 → 走沉淀分流落位（Pitfall/Spark/Charter 修订）
              └─ 不采纳 → 流水保留（或过期清理）
```

**关键裁定（Human 2026-09-07）**：反思对目标要求的检查是**隔离**的（独立视角，64.5% 自检盲区对策），但**只记录流水**——反思提供的是**独立证据，不是控制信号**；采信权在人和主控手里（00 §4 Human 决定权 + 00 §5 单一主控最终负责）。反思没有中断效力——它是哨兵，不是刹车。

**需补建的两个输入接口**（无则反思只剩 mnemon 的 idle+容量触发）：
1. 参考信号输入（主控读维/遵守维的 Goal/Charter 对照结果）
2. 摩擦信号登记（执行/讨论现场的卡壳/重复错误/Stop Condition）

### 2.3 调研与讨论为何分立（Human 2026-09-07 裁定）

调研是**深度挖掘**，讨论是**广度扩散与收敛**——混在一起收不住：

| | 调研 | 讨论 |
|---|---|---|
| 收敛判据 | EIG 边际信息增益 = 0（信息论，单维度） | Goal/Charter 锚点对照（多维度） |
| 产出 | confirmed/uncertain/gaps 三态证据链 | 正反方论点 + 最终决定 |
| 分支关系 | 可串行深挖（一个方向挖到底） | 必须并行多视角（不同方向同时跑） |

## 3. 制度（开放集合）

贯穿纪律，不独立产出，随治理需要增长。

**判定标准**：贯穿所有系统 + 不独立产出 + 约束全体。

**当前已知**：

| 制度 | 内容 |
|---|---|
| **复核** | 独立 Session 检查 + 双层完成声明（机械 + 独立都过才算完成）+ 写后回读 |
| **沉淀** | 去留纪律（多入口 + 五路分流）+ 容量纪律（不静默截断） |

**开放集合裁定（Human 2026-09-07）**：制度可能有很多，00 只定义类别的判定标准，具体清单由下位规范与实施逐步登记——安全纪律、审计纪律、成本纪律、可见性纪律都可能长成制度。**不写死**。

## 4. WC 工作模式（04 行动模板领域）

**WC 生命周期（Gate1 批准 → 执行循环 → 复核 → Gate2 关闭 → 交还）不是系统，是模式**——每个业务系统被批准的工作都按这个模式走生命周期，由编排承载运行。

- 业务系统决定"做什么"
- 编排提供"怎么跑"
- WC 模式约束"怎么收口"

| 复核 | 制度·复核 | 降格：系统→纪律 |
| 反思 | 业务·记忆的维护子机制（反思引擎） | 降格：系统→子机制 |
| 沉淀 | 制度·沉淀（去留纪律）+ 业务·记忆的路由面 | 拆成两半 |

**八维全部有归宿，无遗漏、无重复。**
