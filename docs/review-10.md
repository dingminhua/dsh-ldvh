## 4. 10 与 07/08 在设置页上的分工判定

**问题 1：同一件事（设置页安装管辖项目）在三份规范是否各写一遍？**
- **07**（`07 §5.4/§5.6/§5.7`）：定义管辖登记的**领域语义**——登记载体位置/`schema_version`/`projects[]` Schema、判定方式、原子写入与冲突拒绝、取消登记的写入机制。即「登记是什么、怎么写、怎么判定」。
- **08**（`08 §6` 管辖项目安装事务）：定义**宿主侧安装事务的机械形态**——设置页「安装」按钮触发「登记 + 创建/校验 `ldvh-base/` + 安装/更新 Git Hook」三必需步骤、「检查」只读巡检、「更新」修复可修复态、「取消管辖」自动卸载 Hook 但保留 `ldvh-base/`、启动巡检节奏。即「Host 怎么把登记落地的安装事务」。
- **10**（`10 §6.5`）：定义**Web 交互契约**——呈现登记对象/项目路径/就绪状态/分项诊断、把「安装」呈现为不可选、把「检查/更新/取消」按 08 行为呈现、写入/移除经 07 §5.4/§5.7 与 08 §6 流程并分项回读确认。

**判定**：三份规范**不是各写一遍同一件事**，而是「领域语义（07）→ 宿主事务（08）→ Web 呈现（10）」的清晰分层。10 以「Web 不自行解析或直写登记载体、事实源或 Hook」「写入与移除经 07 §5.4/§5.7 和 08 §6 定义的受控流程」**显式让出权威**。唯一需关注的是 F1：`10:144` 对安装事务步骤的**重述**与 `08 §6` 平行，属冗余描述而非冲突性重定义；权威归属清楚（08 §6 为事务权威、07 §5.4/§5.7 为登记权威、10 仅为呈现权威），不构成「第二规则源」。

**问题 3：10 引用的 07/08 章节号是否仍存在且相符？**
