## 七、03 §6.1：change_log 署名的机械闸门缺失

**事实（Human 发现并提出，2026-09-12）**：`ldvh-base/` 中出现**无 `provider`/`model` 的 `change_log` 流水**。

**根因（两层）**：
1. 候选形成者以**一次性脚本直调 writer**（`sessionSignature: null`）绕过工具面；
2. **工具层 update 路径系统性丢失署名**：五个事实类型（spark/adr/friction/pitfall/research）的 `signatureFor()` 返回**未加品牌的普通对象**，而 writer 只接受品牌载体，未品牌者被解析为 `null` → 静默写为无署名流水；envelope 仍按「路由读取成功」报告无 gap。**create 路径正确、update 路径错误**，五个模块一致。

**已修复**：① 以 `shellAuthoritativeSignature()` 正规通道为受影响对象补记署名流水（原无署名条目保留，`change_log` 只追加）；② 五个 `signatureFor()` 改为在源头返回品牌载体，并移除调用点重复包装（`authoritativeSignature()` 非幂等）；③ 新增回归用例，以撤销修复验证其确实失败。

**仍缺的机械闸门（未处置，待 Human 定）**：`resolveAuthoritativeSignature()` 的既定语义是**安全降级**——非品牌载体解析为 `null`，流水写成无署名，而**没有任何机械层报告该缺失**。`03 §6.1` 只规定署名「由 Code 托管」，**从未规定「署名缺失必须拒绝写入」**，故本项缺口在规范侧亦无载体。改为显式报告或拒绝写入属**实质修改**（`01 §12.1`），须独立审核后另议。

**核验**：`grep -n 'resolveAuthoritativeSignature' plugin/lib/signature-channel.js`——降级语义；抽样核对全库对象流水署名覆盖。

**同形不同源的既有缺口**：`ldvh-base/goal.md` 的 4 条流水**全部无署名**，其时间早于 writer 工具化，且 `plugin/lib/` 下**无 goal writer**（25 号无受控写入实现）。属独立实现缺口，未随本项处置。
