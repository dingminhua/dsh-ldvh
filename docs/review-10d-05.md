## 3. 问题清单（分级 + 引文行号 + 复现）

### F1【高·规范-实现不一致 + 内部欠指定】outcome 闭集不含任何"成功"取值；主接入面实现使用闭集外 `completed` 且未被登记

- **普通话**：05 说响应结果分类的闭集是五个（partial/unavailable/rejected/invalid_request/执行错误）——这五个全是"没成"或"出问题"的分类，**没有一个是"成功了"**。可规范又要求每次响应都带回结果分类。于是完全成功的调用按规范字面无值可填。实现只能自己发明：DSH 工具面用 `completed`（也是闭集外的），Web 面等 `ok`（同样闭集外）。05 只把 Web 的 `ok` 登记为已知偏离，没发现自家主接入面的 `completed` 同样越集。
- **规范侧引文**：
  - 05:111（§5.3）：「本文 §8 的结果分类闭集为 partial／unavailable／rejected／invalid_request／执行错误，不含 `ok`」——明称**闭集**且仅五值；
  - 05:137（§6.2）：「每次调用的 `outcome` **仅使用** §8 的 `partial`、`unavailable`、`rejected`、`invalid_request` 或执行错误分类」；
  - 05:167（§8 表第 1 行）：「回显服务发现或实际调用的标识和**结果分类**」——每次响应必须携带；
  - 05:105（§5.2 第 5 项）：「各接入面不得改变共同响应的字段语义、`outcome` 分类与 `scope` 边界」。
- **实现侧证据**：`plugin/lib/ldvh-tools.js` 成功路径全部 `envelope(..., "completed", ...)`（行 124、139、150、161、174、187、196、204、211、222、233、243、288、297、310、321、336、377）；全部 writer 批次同样使用 `"completed"`（如 `spark-tools.js:126/250/308`）；Web 面 `plugin/web/api/services/governanceScope.ts:208/340` 判 `response.outcome !== 'ok'`——**两个接入面互不兼容且都越出 05 自称的闭集**。
