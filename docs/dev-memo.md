5. 管辖：独立工作区 dogfood（方案 A），不沿用旧 poker_hud_projects 配置。
6. **不再借用第三方技术**：所有问题内部自己解决；第三方只吸收原理，运行时零依赖。
7. **DSH 宿主能力 = 自家能力**：要用透，需深入研究查漏（见 `docs/dsh-platform-facts.md`）。
8. **MCP 出口**：LDVH 可以「提供」MCP server 作为对外服务接口；DSH 经 `ctx.mcpClient` 原生消费（提供≠借用）。（暂不计入当前设计目标，见 #11。）
9. 开发备忘记录在 `docs/` 目录（本文件及配套备忘）。
11. **范围纪律（Human 定，2026-08-24）：先只做好 DSH 效果，非 DSH 不考虑**——多环境策略、MCP 出口、跨产品 Hook 适配、Skill 在非 DSH 环境的形态等**全部暂缓、不计入当前设计目标**（避免想太多）；D3 开源属性不变（开源≠多环境，是代码开放与插件市场契约）。
12. **开源协议对齐（Human 定，2026-08-24）：DSH 用什么协议，我们就用什么协议**——已核实 DSH 本体为 MIT（本地证据：`dsh-plugin-desktop` 2.0.2 与 @deepseek-ai 核心包 dsh/dsh-agent/dsh-tools/dsh-subagent/dsh-workflow 等 package.json license 全部 MIT）；dsh-ldvh 现有 LICENSE 即 MIT（v4 决策 D3 已就位），**协议已对齐，无需变更**。开源的本意 = 让其他人去做移植（DSH 之外的平台移植由社区完成），同协议降低移植门槛。
10. **证据的目标函数 = 防 AI 自欺，不是外部可验证**（Human 定，2026-08-24）：
    - v4 把「防自欺锚点」与「外部审计证据」混在一起并向外倾斜，是过度合规的重要来源（[11][21]）。
    - 三类分账：**防自欺锚点**（写后回读/指纹 CAS/机械预检/Git Gate 终闸/独立复核/单调令牌/判断分层/预检落实记录）→ 保留；**决策输入**（Human Gate 提请的依据/风险/选项）→ 保留；**外部审计证据**（验证选择记录簿记/逐动作署名流水/会话轨迹回放与可比性审计/change_log 完整流水/冗余元数据）→ 砍或降级到防自欺所需最小形态。
    - 判据：每项机制必须回答「防的是 AI 用哪种具体方式骗过自己」；答不出的审计向机制不引入。
    - 连带改写：§8 验证与交还 =「防自欺机械锚点 + 交还」；03 溯源重建收窄为最小回指；HV3/V5 按防自欺与决策输入重读；「过程透明」是防自欺的透明，不是审计透明。

## 3. 五维重构（Human 定法，取代移交文档 §3 映射表）

| 维 | 内容 | 对治的 §1 根缺陷 | 关键机制 |
|---|---|---|---|
| **读** | 渐进读取 | AI 上下文依赖 | 规则引导 → F0 → F1/F2 → F3/F4；补预热层 + 效果验证 |
| **写** | 受控写入 | AI 无连续状态 | 受控创建/更新 + 回读 + 审计；局部补丁减摩擦 |
| **遵守** | 遵守记录 + ADR + Pitfall | 前说后忘、重复犯错 | 预检落实：决策边界遵从、踩坑规避、约束必须改变行动方案 |
| **思考** | 自发辩证机制 | AI 概率性输出 | 判断分层（相关/适用/授权/完成）+ 独立复核/多视角对抗 |
| **执行** | 完成 WC 的流程 | Human 进展断续 | Gate1 冻结 → 执行循环 → 复核 → Gate2 关闭 → 交还 |

- **Git Hook = 最后的把关**：不进五维，是横在五维之上的**机械守护层**（终闸），对应骨架 §4。
- 渐进式读取的诚实评估：机制成立（F0–F4 机械完备、v4.1.0 实测全量可读），**成功未证**（[48][32] 无因果结论；[35] 摩擦高；[37] 行业共识=会话级预热优先）。v5 定案：保留骨架 + 补预热层 + 漏读/误报/成本对照验证。

## 4. 记忆-反思-交互封装（设计主线）

**记忆（读维）**：三层注入——
- 公共必读层（active ADR 决策边界常驻摘要 + 当前 open WorkCase 状态 + Gate/Stop 边界）→ `ctx.systemPrompt.section`，会话冷启动；
- 类型触发层（Pitfall 按症状/技术栈分发；相关事实卡候选）→ 占位 user message 注入（内部实现），会话启动 + `agent/pre-step`；
- 按需层（Study/事实全文）→ Helper F0–F4 渐进。
- 预算与红线：`ctx.tokenMeter` + CJK 感知 + L0 容量上限；注入卡带来源标签+指纹；概率召回只做候选、永不进事实写入。

**反思（思考维）**：四段闭环——
触发（行动单元交还/turn-end/goal 轮末/故障后）→ 辩证执行（subagent 独立复核 / subagent_fork 上下文继承 / ralph 全新视角 / workflow 多视角对抗）→ 使用证据（22/23 预检落实记录升格：没改变行动的积累=死积累）→ 受控回流（反思结论经 Helper 写成 Pitfall/ADR/Study/Spark）。
- 效用审计：HV4 判据 + 周期价值审计（六维度）+ 日落机制（没用的积累退役）→ 自我进步 = 事实库净效用增长可观察。

**对话交互封装（执行维·三通道宿主化）**：
- 规则引导 → `systemPrompt.section` + `pre-step` 模板提示；
- 决策提请 → `ctx.userQuestions` 结构化选项；授权 → `ctx.authorization`；计划审查 → `dsh-plan-mode`；
- 交还 → 两层输出契约（人类可读简洁正文 + 机器可读 Output Envelope）；
- 验收提交 → Isolated Session 验收条（worktree claims + 建议 Commit Message）；
- 反馈 → `message-feedback`（Human 反馈进反思输入）；命令 → slash 命令（dsh-command-*）；呈现 → 四层阅读器 + deliverables 引用尾。

**总闭环**：读（预热）→ 遵守（预检落实=使用证据）→ 执行（WC 流程+交互封装）→ 思考（辩证反思）→ 写（受控回流）→ 审计（HV4 可见+日落）→ 回到读（预热更准）。

## 7. v5 核心定调（Human 定，2026-08-24）

「引入新技术 + 深度绑定环境机制，解决 v4 存在的问题」——认可，并精确化为两句话：

1. **引入新技术（问题驱动）**：每个吸收项必须回答「补哪一维的哪个根、对治 §1 哪个缺陷」；四根支柱 + 49 Study 吸收清单挂五维账（docs/study-absorption.md）。
2. **系统性裁剪（减法）**：v4 问题有一半是「只增不减」造成（23 条 Stop、18 项协议、7 规范穿越、证据过重）——靠裁剪解决；新技术让裁剪可行（宿主机制替代自建流程）。
   - 两句合起来 = 「同样的治理效果，更低的摩擦」。

三条红线（深度绑定不越界）：
- 绑定机械层与交互层，**不绑定语义权威层**（宿主机制是机械承载，不是第二规则源/事实源）；
- **AI 面向的语义路由/引导文本必须单一权威来源、逐字节一致、不复制规则正文、不成为第二规则源**——载体可变：DSH 深度绑定下薄 Skill 三职责（身份告知/规则引导/模板路由）分别由插件 systemPrompt.section / pre-step 事件 / ldvh_call 工具承接，**Skill 未必存在**（Human 定，2026-08-24）；若保留 Skill 形态（如非 DSH 环境）同样受此不变式约束；
- 受控写入唯一经 Helper、Git Gate 终闸不变（宿主 fs 观察策略只是辅助防线）。
