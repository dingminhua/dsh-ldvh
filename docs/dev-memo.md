18. **管辖项目安装与权限降级（Human 定，2026-09-01）**：候选目录必须是实际 Git 根；设置页“安装”不可选地完成登记、创建或校验 `ldvh-base/`、安装或更新当前 Git common-dir 的 commit-msg Hook，任一步失败均不得显示就绪。“卸载”只卸载 LDVH 托管 Hook，保留登记和 `ldvh-base/`；“取消管辖”自动卸载 Hook 并移除登记，但保留 `ldvh-base/` 与全部事实对象；“检查”只读检查全部分项，DSH 每次启动自动检查所有登记项目 Hook 版本，不自动更新。DSH 现有 `ctx.approval.request()` 只适用于带 Agent/call id/open turn 的工具调用，设置页空闲按钮不能复用；Host 先尝试按 OS 用户权限自动完成，权限失败时 fail-closed，并提供统一 LDVH CLI 的 macOS/Windows 正确命令与 DSH Terminal 打开入口作为降级，执行后仍须回到设置页检查。

## 3. 八维工作模型（Human 定法，取代移交文档 §3 映射表）

| 维 | 内容（00 §3.1 根定义） | 对治的 §1 根缺陷 | 关键机制 |
|---|---|---|---|
| **读** | 取得当前工作所需且来源明确的信息 | AI 上下文依赖 | 规则引导 → F0 → F1/F2 → F3/F4；补预热层 + 效果验证 |
| **写** | 将已经决定需要落位的内容受控写入，并核对实际结果 | AI 无连续状态 + Human 灵感无处安放 | 受控创建/更新 + 回读 + 审计；局部补丁减摩擦；临时想法入档 |
| **遵守** | 识别并落实适用的规则、事实、决定和授权 | Human 经验无法积累 | 预检落实：决定变规则、教训变约束，约束必须改变行动方案 |
| **审议** | 把 Human 意图经扩散和约束收敛为方案 | Human 规划模糊 | 方案扩散与约束收敛；计划审查（dsh-plan-mode）+ 结构化决策提请 |
| **复核** | 依据已经确定的目标、方案和成功标准，检查实际工作和结果 | AI 概率性输出 | 相关/适用/授权/完成四层判断 + 独立复核/多视角对抗（审当前） |
| **执行** | 由主控组织行动并形成实际结果 | Human 进展断续 | 计划批准冻结 → 执行循环 → 复核 → Human 关闭 → 交还 |
| **反思** | 从目标、判断、行动、结果、摩擦和反馈中形成候选认识 | 持续积累（HV4） | 触发 → 多视角复盘（含交还复盘）→ 使用证据 |
| **沉淀** | 判断哪些认识和结果值得跨行动保留，以及应进入什么稳定位置 | 经验沉淀与复用（HV4/V8） | 受控回流（经 Helper 写成 Pitfall/ADR/Study/Spark）→ 效用审计 + 日落 |

## 4. 记忆-反思-交互封装（设计主线）

**记忆（读维）**：三层注入——
- 公共必读层（active ADR 决策边界常驻摘要 + 当前 open WorkCase 状态 + Gate/Stop 边界）→ `ctx.systemPrompt.section`，会话冷启动；
- 类型触发层（Pitfall 按症状/技术栈分发；相关事实卡候选）→ 占位 user message 注入（内部实现），会话启动 + `agent/pre-step`；
- 按需层（Study/事实全文）→ Helper F0–F4 渐进。
- 预算与红线：`ctx.tokenMeter` + CJK 感知 + L0 容量上限；注入卡带来源标签+指纹；概率召回只做候选、永不进事实写入。

**反思（复核/反思/沉淀维）**：四段闭环——
触发（行动单元交还/turn-end/goal 轮末/故障后）→ 辩证执行（subagent 独立复核 / subagent_fork 上下文继承 / ralph 全新视角 / workflow 多视角对抗）→ 使用证据（22/23 预检落实记录升格：没改变行动的积累=死积累）→ 受控回流（反思结论经 Helper 写成 Pitfall/ADR/Study/Spark）。
- 效用审计：HV4 判据 + 周期价值审计（八维度）+ 日落机制（没用的积累退役）→ 自我进步 = 事实库净效用增长可观察。

**对话交互封装（执行维·三通道宿主化）**：
- 规则引导 → `systemPrompt.section` + `pre-step` 模板提示；
- 决策提请 → `ctx.userQuestions` 结构化选项；授权 → `ctx.authorization`；计划审查 → `dsh-plan-mode`；
- 交还 → 两层输出契约（人类可读简洁正文 + 机器可读 Output Envelope）；
- 验收提交 → Isolated Session 验收条（worktree claims + 建议 Commit Message）；
- 反馈 → `message-feedback`（Human 反馈进反思输入）；命令 → slash 命令（dsh-command-*）；呈现 → 四层阅读器 + deliverables 引用尾。

**总闭环**：读（预热）→ 遵守（预检落实=使用证据）→ 执行（WC 流程+交互封装）→ 反思（辩证执行）→ 写（受控回流）→ 审计（HV4 可见+日落）→ 回到读（预热更准）。
