## 1. 类型定位与价值

Goal 解决项目目标缺少稳定承载的问题：项目「为什么存在、要实现什么、走到哪里算成」若只存在于 README、对话记忆或散落文档，则每次授权、每轮规划、每个会话都无法对照同一个锚——方向漂移无从暴露（00 §1 痛点 1「规划模糊、来去不可答」），HV5 演进脉络缺第一环（「长期意图」无载体）。Goal 以单例冻结锚承载项目目标：目标陈述表达为什么与要什么，G-SC 成功标准锚点表达走到哪里算成，为全部前向工作提供统一引用顶点。

主要支撑：V3 边界识别（Gate 1 授权引用链顶——说不清服务哪条 G-SC 即暴露偏离）、V5 据实判断（G-SC 判定分层）；HV1 决策提请清晰可决（授权提请必含目标锚定）、HV5 项目演进脉络可循（goal 修订史 + change_log 是演进链第一环）。

为什么普通文件或既有类型不能无损承载：README 是公共门面不是事实对象（无受控写入、无 change_log、无 Gate 1 引用契约）；Initiative 是月级分组容器（承载「这一章」而非「整本书为什么写」）；Spark 是悬置层（目标已定，不是悬而未决）。Goal 是唯一被 Gate 1 引用链、蓝图投影、讨论三件套三处结构性消费的锚。

Goal 是**单例类型**：一个管辖项目在任一时点至多一个当前 Goal 对象。单例不使用多例身份机械（见 §3），这是本类型与 20–24 其余类型最重要的形态差异。

## 2. 对象边界

**构成**：Goal = 一个目标陈述（为什么 + 要实现什么）+ 若干 G-SC 成功标准锚点（走到哪里算成）+ status。三者共同构成项目目标的当前完整语义；缺 G-SC 的 Goal 是合法中间态（初始化对话可只落陈述，G-SC 延后精化）。

**单例约束**：项目内 Goal 至多一个。由载体路径唯一性机械保障（`ldvh-base/goal.md` 只能存在一份），不设基数规则、不设第二个 Goal 对象形态；受控创建入口在 goal.md 已存在时拒绝创建（fail-closed），不存在「打开第二个 Goal」的路径。

**查重**：单例使查重退化为存在性检查——创建前检查 goal.md 是否已存在。不存在多 Goal 间的语义查重问题。

**明确不属于本类型**：阶段聚焦（归 BLUEPRINT 手写区与 active Initiative 投影）；项目价值约束（Charter 语义，归规范源项目级 spec，裁定见锚点 §5.4）；使命宣言式永不可判定文本（G-SC 必须可判定——永不可判定的表述应留在 README，不进 Goal）；多项目共享目标（工作对象边界：单项目单 worktree，07 §6）。

## 3. 身份与载体

| 项 | 定案 |
|---|---|
| `fact_type_key` | `goal-fact-type`（唯一类型定义来源即本规范） |
| 载体 | 平铺单文件：YAML frontmatter（机器权威）+ markdown 正文（家族统一约定，24 号同形态） |
| 权威位置 | `ldvh-base/goal.md`——**路径即身份**：不分配 `object_uid`、无类型子目录、无文件名编码 |
| 单例三免 | 免 `object_uid`（03 §6.1 单例豁免，见下）、免 F0–F2 候选召回（消费点直读）、免目录基数校验（文件系统天然单例） |

`object_uid` 豁免依据：03 §6.1 定义其为「事实对象唯一身份」，服务多例对象的引用消歧；Goal 无消歧需求（引用目标恒为该路径），强加 UID 只制造冗余机械。本节即该豁免的类型来源声明。公共字段实际采用：`fact_type_key`、`title`、`status`、`created_at`、`change_log`（首修后必有）；**不采用** `urls`（目标陈述不依赖外部来源）、`relations`（Goal 是链顶，无上游可指；下游引用由 Initiative 的 `serves` 建立，方向不可逆）。

**创建与变更权**：创建与任何修改都必须经 Human 决定（修订属 00 §4.2 级根决定事项——项目目标的变更改变一切下游锚定）；AI 只能提议修订（C1 提案对象模式），无直接写入路径。`created_at` 与 change_log 托管规则照公共契约。

## 4. 字段契约

frontmatter 闭集（全部必填，除标注外创建时一次落定）：

| 字段 | 类型 | 语义 | 约束 |
|---|---|---|---|
| `goal_key` | string | 固定值 `project-goal` | 唯一合法值；机械校验 |
| `title` | string | 目标陈述收紧后的短标题 | ≤ 40 字；不承载 G-SC 内容 |
| `status` | string | 闭集 `active` / `achieved` | 初态必为 `active`；`achieved`=项目收官判定，见 §5 |
| `created_at` | RFC3339 | Code 受控创建时填写 | AI 不得填写 |
| `change_log` | array | 每次实际修改恰好追加一条 | `at`/署名 Code 托管；AI 只提供一句话语义摘要；**每条必含修订理由**（见下） |

正文两块固定 H2：

```
# 项目目标
## 目标陈述        ← 为什么 + 要实现什么；一段话；写给未来会话与新读者
## 成功标准        ← G-SC 条目列表；每条一行：`G-SC-n <可判定的达成条件>`
```

G-SC 不定字数上限（成功标准 1–8 条为宜，超过说明目标应拆 Initiative）；`G-SC-n` 编号**创建后冻结永不换号**（被 WC→Initiative 引用链历史性依赖，锚点稳定性公理）；某条 G-SC 作废时原位标记 `（已作废：<理由>）` 不删除不重排，后续新增编号顺延。

change_log 修订理由的最低形态：`summary` 必须能独立回答「改了什么 + 为什么改」；goal 修订属罕见事件（预期季度级零次至一次），每条理由都是 HV5 演进链的实体节点。

## 5. 状态与生命周期

状态闭集仅两值：`active`（项目存续期常态）→ `achieved`（全部 G-SC 判定达成且 Human 决定收官）。无第三个状态——**不设 `abandoned`**：项目放弃 = 项目退役（管辖取消），goal.md 随 `ldvh-base/` 保留为历史档案（决策 #30 取消管辖保留事实对象），无需独立状态承载。

- `active → achieved`：Human Gate（终局判定是根决定）；前提是全部 G-SC 达成判定成立（每条锚定其名下 Initiative/WC 的关闭证据，AI 汇总提议，Human 判定）；翻转后文件冻结为历史档案。
- **不存在的转换**：goal 不退役、不 superseded、不重开。项目目标被根本推翻 = 受控修订（大改 change_log），不是状态转换。

**G-SC 精化次序**（初始化对话定案，锚点 §5.10）：创建时允许只落目标陈述（G-SC 空缺是合法中间态）；首次精化由 AI 在该项目的早期会话提议草案、Human 逐条确认后经受控更新补入——这是唯一允许的「无 G-SC → 有 G-SC」变更，走普通受控更新（change_log 留痕），不设独立 Gate 形态。

## 6. 来源与证据

目标陈述与 G-SC 是 Human 意图的结构化表达，**来源是 Human 决定本身**（初始化对话或修订对话中的确认记录），不适用外部证据锚定；本类型无 `urls`、无逐字摘录、无溯源锚点要求（与 24 号的最大差异——Goal 不调查外部世界，只承载内部意图）。

G-SC 的「可判定性」由 AI 语义审核（提议时逐条自检：这条标准能被证据判定吗？判定材料是什么——名下 Initiative/WC 的关闭记录？）与 Human 确认共同保障；机械层不判断语义可判定性，只校验存在性与格式。

`achieved` 判定的证据形态：逐条 G-SC → 锚定的 Initiative 关闭记录 / WC 关闭记录链（由引用链反查机械可得），AI 汇总提议、Human 终判。

## 7. 关系契约

**不使用 `relations` 字段**（类型来源声明不采用，03 §7.2 允许）。理由：Goal 是引用链顶点，唯一合法边是「下游指上来」——Initiative 的 `serves: G-SC-n`；Goal 自身无上游、无平级。反向投影（某 G-SC 名下有哪些 Initiative/WC）由机械反查 `serves` 得到，不需要 Goal 侧存储。

## 8. 召回与消费

单例三免的第三免：**不走 F0–F2 候选召回**。消费点全部直读（消费方知道路径）：

| 消费点 | 时机 | 消费内容 |
|---|---|---|
| systemPrompt 注入（引导段 +1 项） | 每会话 | 目标陈述 + active 专项列表一行摘要；goal 缺失时注入「项目未初始化」提醒 |
| Gate 1 授权提请 | 每次 WC 授权 | 必含「本 WC 服务哪个 Initiative 的哪条 G-SC」（经 Initiative 引用链顶可达 goal） |
| 蓝图「当前目标」区块 | 每次蓝图渲染 | 目标陈述投影 + G-SC 达成概览 |
| 讨论系统依据装配 | 每次扩散前 | 目标服务性检查（12 号 §5 已定义引用） |
| G-SC 精化提议 | 早期会话 | 全文直读 |

**Enforcement**（锚点 §5.10 定案）：goal.md 缺失时 **Gate 1 无法受理**（授权无锚可引，架构性 fail-closed，无需额外规则）；一切读操作（调研/讨论/Spark/Research/事实源浏览）不拦——探索与调研正是形成目标的过程。goal.md 存在但 G-SC 空缺时 WC 可正常走（Gate 1 引 goal 本体），注入段提示「G-SC 待精化」。

## 9. 受控操作

- **创建**：仅经「项目初始化对话」路径（触发句「帮我进行项目初始化」；Web 横幅指路；锚点 §5.10 对话流程）。机械检查：goal.md 不存在（否则拒绝——单例 fail-closed）、`goal_key=project-goal`、title 非空、status=active、`目标陈述` H2 存在且非空。创建后回读。**安装表单不是创建路径**（裁定 12：表单方案作废）。
- **更新**（陈述精化、G-SC 补入/增改、作废标记）：03 §9.5 受控更新；CAS 以完整文件为单位；每次恰好一条 change_log（含理由）；**必须先经 Human 确认**（修订提议由 AI 生成，Human 明确同意后执行——C1 模式）。
- **goal 修订级联**（C2 链式扩展，锚点 §5.10 四约束）：修订落盘后机械扫描 `serves` 受影响 G-SC 的 active Initiative，逐个标记 `goal-changed 待核对` 并生成待办；核对（调整/关闭/保持，各留各自 change_log）后其名下 active WC 标记待核对，按 21 号 C2 语义局部重批。**只到 active 对象**（closed 是历史，锚定的是当时的 goal）；Spark 豁免；每跳是标记非动作；Goal 侧不为级联存储任何下游状态。
- **状态翻转**（achieved）：Human Gate；AI 汇总逐条 G-SC 证据链提议，Human 判定；翻转即冻结。
- **删除**：不存在删除操作。项目退役时 goal.md 随 `ldvh-base/` 保留（07 §5.7 取消管辖语义）。

**升级路径**（存量管辖项目无 goal.md）：「更新修复」入口扩展 goal 检测（发现缺失时提示初始化对话路径）；首次 AI 会话检测缺失时主动引导。Web 横幅持续显示直至补齐。

## 10. 类型特有验证与类型退出

| 验证对象 | 时机 | 成立条件 | 入口 | 可证明范围 |
|---|---|---|---|---|
| 单例存在性 | 消费点读取时 | goal.md 至多一份；存在即解析成功 | 机械（路径检查） | 当次载体存在性与可解析性 |
| G-SC 锚点稳定性 | 更新时 | 既有 G-SC-n 编号不被改写、不重排、不删除（只可原位作废） | 机械 + AI 核对 | 编号连续性与历史引用安全 |
| 修订授权 | 每次更新 | change_log 对应一次 Human 确认记录（会话/Gate 载体） | AI 语义审核 | 当次修订的授权事实 |
| achieved 证据链 | 状态翻转前 | 每条 G-SC 有可回读的 Initiative/WC 关闭证据 | 机械反查 + AI 汇总 + Human 终判 | 各 G-SC 达成判定的证据覆盖 |
| 级联标记正确性 | 修订后 | 受影响 active Initiative 全部被标记、无遗漏 | 机械（serves 反查） | 当次扫描的引用链完整性 |

**类型退出**：若 Human 决定取消 Goal 类型（如并入其他承载），须按 03 §10 处理：goal.md 内容迁出、全部引用消费点（Gate 1/引导段/蓝图/讨论装配）同步改造、Initiative `serves` 语义重定义。退出属 00 §4.2 根决定。
