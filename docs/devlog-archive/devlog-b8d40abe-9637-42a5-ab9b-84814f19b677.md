# 宿主契约差分机制落地：三通道取数与两次真实漏判修正

## 背景

Spark 76ee7b7b（建立上游 DSH 能力变化的吸收与同步机制）2026-11-02 重核为四要件 1/4：基线登记点已建，但契约差分靠人工、三态无机械判据、落地时机无规范条文。Human 明确需求形态：「每次上游更新，只告知 AI，AI 就知道怎么跟进」。本轮先立新 Norm `host-upgrade-followup`（norm-0e0436c1，七步 runbook），经工单路由询问 Human 选「直接执行」，随后落地 runbook 第 3–4 步的机械件。

## 做法

- 调研发现上游仓内已提交三张**生成物**（均有 CI 新鲜度门禁，不会与源码漂移）：`api-catalog.ts`（SERVICE_API/EVENT_API/TYPE_API 三表）、`slot-catalog.ts`（CLIENT_SLOT_API）、upgrade-guide 目录（官方破坏性变更自述）。差分不需解析 asar、不需通读源码。
- 新增 `lib/host-contract-catalog.js`（括号深度解析器 + FIELD_LAYERS 字段分层，字符串/注释感知，畸形输入 fail-closed）、`lib/host-version.js`（DSH 版本序比较器，alpha<rc、正式版>预发布）、`scripts/host-contract-diff.mjs`（三通道差分 + 三态初值 + 消费面匹配）、`lib/host-consumption.json`（机器可读消费面清单：14 服务 / 10 事件 / 4 槽位 / 2 值服务 / 5 客户端服务 / 4 非契约锚点，逐项带 callSites）。
- 测试四件：解析器单测（内联 fixture，11 项）、清单一致性测试（双向核对 + callSites 精确核对，6 项）、版本序单测（6 项）、回归锚点测试（锚定两段人工已登记区间与三次已知破坏，8 项）。
- 全部断言经变异检验确证检测力：代码新增未登记消费点 / 清单登记死键 / callSites 填错 / 回填 bug 形态 / 消费面成员资格删除，五类变异全部被抓。

## 实测

- 锚 A（rc.5→0.2.2-rc.1）：服务 98→107、槽位 103→109 与 norm a1b559a6 人工登记数字吻合；schedule 服务 methods 契约变更报破坏初值；schedule-agent-tools / fs-observation-policy-default-off 强匹配；四个在用槽位契约字段零变更（与 norm 登记一致）。
- 锚 B（0.2.0-rc.2→0.2.1-alpha.1）：invariants 删除报破坏初值；subagent-activations 强匹配 subagents；区间 guide 总数 22（最新 tree 口径）。
- 全量套件 3184 pass / 0 fail；eslint 与 test-lint 对新增文件零发现。
- **两次真实漏判在开发中被机制自身暴露并修正**：① 消费面清单漏登 `subagents`（经 `agent?.ctx?.get?.("subagents")` 可选链取得，按 receiver 名匹配的提取正则抓不到——正是 spark 记录的第二次破坏 subagent-activations 的消费面）；② upgrade-guide 回填陷阱：subagent-activations guide 在 dsh-v0.2.1-alpha.1 tag 当时不存在（0 份），由上游事后回填到后续 tree（22 份）——按 `git diff base..target` 新增文件判区间会完全漏掉该已知破坏。修正为从克隆内最高版本 tag tree 读取、按版本号筛 (基线,目标] 区间，并立回归锚防退化。

## 结论与边界

上游 DSH 契约面可从仓内生成物（api-catalog.ts/slot-catalog.ts/upgrade-guide）机械差分，host-contract-diff.mjs 已落地并经回归锚点验证（rc.5→0.2.2-rc.1 服务 98→107、槽位 103→109 与人工登记吻合；三次已知破坏全部命中）。边界：三态是初值不是结论，最终归类须 AI 读 guide 后提请、Human 落定；值服务（dshHomePath 等）与客户端服务（slots/locale 等）无仓内生成物目录、差分不可判；非契约 CSS 锚点不可判；槽位表契约字段/噪音字段分层与 guide 单复数归一是实测校准的启发式，上游 catalog 格式变更时解析器 fail-closed 报不可判定。本轮修正两次真实漏判：① 消费面清单漏登 subagents 服务（可选链 ctx?.get?. 形态绕过提取正则，一致性测试改 receiver-agnostic 提取后抓到并补登）；② upgrade-guide 事后回填陷阱（subagent-activations guide 在 alpha.1 tag 当时不存在、由上游回填到后续 tree，按 git diff 新增文件判区间会漏——改为从最高版本 tag tree 读、按版本号筛区间，并立回归锚）。

未验证范围：差分器只在 macOS 本机克隆上实跑过；`agent/request` 事件在锚 A 区间被删（非消费面、正确报无关）未做语义复核；锚 B 的 guide 总数 22 依赖上游不再向 alpha.1 目录回填（若回填，锚点数字须人工核实后更新，测试注释已写明）。
