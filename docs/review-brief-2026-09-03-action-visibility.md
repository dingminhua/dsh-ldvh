## 2. 为什么审（审核依据）

- **01 §12.1 强制触发**：本候选新增可强制执行规则（§5.7 可见性契约）、新验证行、新 Human Gate 增量项——属较高风险档，必须在 Human 终审前完成独立对抗审核并修复真实发现。风险分级可调整范围深度，不能取消触发。
- **01 §12.2 独立性**：审核执行体不得参与候选形成（候选由本会话主控 kimi-k3 形成；审核须在隔离上下文执行；同模型时须披露独立性边界）。
- **01 §12.3 十维全覆盖**：价值判据对齐／职责边界与单一权威／反过度设计／技术可实现性与能力真实性／身份编号引用格式／防自欺与不能单独证明的边界／内部一致性与反例检验／草案-修复-决定-提交闭环／审核自身风险匹配／中文语义清晰与术语一致。跳过维度必须给理由。

## 3. 背景（为什么这么改）

00 §3 承诺「过程信息保持透明……方便而准确地核对」，00 §7.1 规定「AI 自述不得作为事件已经发生的依据」。实证缺口：引导注入真实发生（会话 JSONL request/header 中存在 `ldvh:minimal-guidance` 段）但对话流无任何痕迹，Human 无法方便核对，曾以「为什么没有上下文注入」发问。另：会话内管辖标记（绿标）的实现已由 Human 定案（2026-09），但从未登记进规范源——本候选首次入规，含承载面注册。

## 5. 反例攻击方向（候选形成者已知的薄弱区，供攻方参考，不限于此）

会话压缩/rewind 后指纹与标记的对应；子代理委派链上父子判定时点不同步；`unavailable→governed` 迁移在 unavailable 行动语义下的标记呈现；多步回合中「当回合」的歧义；一回合内注入与注册多事件合并；管辖态一回合内两次迁移；「事件事实」术语的定义模糊性；10 §7 改题后他处交叉引用完整性。

## 7. 审核后的接续工作流（你在流程中的位置）

```
候选形成 ✅ → 独立对抗审核（本步）→ 主控核对发现并修复 → Human 终审 → 应用到 specs → 受控提交
```

1. **修复**（主控执行，可继续委派你）：真实发现逐条修复；未修复项必须说明原因、影响与残留风险，不得静默忽略。修复若改变根语义/职责/可强制规则，由审核执行体复审受影响维度（01 §12.4）。
2. **Human 终审**：展示候选、审核报告、修复记录与差异；Human 决定后更新登记引用。
3. **应用与提交**：按候选第 3/4 节逐处修改 specs/08、specs/10；受控提交遵循 06 提交契约（提交前 `ldvh_precheck_git_commit` 机械预检；提交签名 LDVH-Provider/LDVH-Model 按会话权威记录末条事件逐字注入，零清理）。本候选不涉及 00 §4.3 受保护文档五类（08/10 不在受保护清单）。
4. **实现批次（不在本工作流）**：标记扩展、子代理标记、中途迁移标记、状态查询面增强归后续 Code 批次；候选第 6 节已登记实现影响（含 child.js 注释被 A2 定案取代）。
