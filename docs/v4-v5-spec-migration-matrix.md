# v4 → v5 规范迁移矩阵

> 性质：规范建设备忘与迁移控制清单，非规范、非事实对象。
> 目标：在开始正式 Code 前，逐项核对 v4 规范职责、v5 承接位置、保留/重建/取消决定与未决 Human Gate，避免整份复制、遗漏既有教训或把实现存在误写成 v5 能力成立。
> 当前边界：v5 规范体系完成并经 Human 确认前不开始正式 Code；`pre-push` 不纳入当前 v5 核心；WorkCase Gate 1/Gate 2 作为专业术语保留；采用 v5 用户目录登记方案；受保护文档 Merge 契约由 06 承接。

## 1. 迁移纪律

1. v4 是迁移输入，不是 v5 当前定义来源；每项语义必须进入对应 v5 规范后才取得 v5 规范身份。
2. 迁移以职责和问题为单位，不以文件整体复制为单位；先判断保留、重建、合并、取消或推迟，再形成 v5 正文。
3. `00` 提供 v5 上位设计基线；01–10、20–24、30–38 在规范建设完成并经 Human 确认前按设计草案处理，不从文件存在、提交或 v4 `active` 推导代码能力成立。
4. 术语表只登记规范名称、机器表示和唯一定义来源，不复制来源正文，也不成为平行规则点。
5. WorkCase Gate 1/Gate 2 只作为 WorkCase 专业节点：Gate 1 处理计划与执行授权基线，Gate 2 处理复核后的结果与关闭提案；二者承接 00 Human Gate，不建立全局第三套授权语义。
6. v4 已撤回或判定过度设计的机制不得静默恢复；尤其不恢复两阶段 Git 提交、全局事实快照事务、逐动作过程审计和默认全量流程。
7. 每项迁移结论应说明：对治的根缺陷、支持的 V/HV、不能单独证明什么、宿主能力是否已核验、需要哪些 Human 决策。

## 5. 首批迁移边界：术语表、WorkCase 21、WorkCase 34

### 5.1 术语表

首批至少登记以下词汇，并把定义指向 00、21、34 或其它唯一来源：

- Human Gate、Stop Conditions、Git Gate；
- WorkCase、Controller、Reviewer、独立复核；
- Gate 1、Gate 2；
- execution authorization、execution approval；
- 当前计划、工作项、检查点、结果复核、关闭提案、剩余责任；
- partial、cancelled、not-achieved；
- 设计草案、设计基线、当前规则源成员。

尚未建立 21/34 前，Gate 1/Gate 2 可以登记为“待 21/34 定义”，不能先在术语表写完整规则正文。

### 5.2 WorkCase 21

必须保留：

1. WorkCase 是可独立关闭的项目工作责任，不是聊天计划、命令清单、实时监控或过程日志。
2. Gate 1 是当前计划和完整执行授权基线的 Human 决定；Gate 2 是经复核结果和完整关闭提案的 Human 决定。
3. 正常路径只设置这两个 WorkCase Human Gate；Gate 1 与 Gate 2 之间不得因模板切换或执行者切换重复请求同一授权。
4. 授权包必须显式限定目标、对象、范围、风险、禁止项与副作用，不能从“执行计划”推导 push、发布、外部消息或其它未列明行动。
5. 结果、关闭分类、验证范围和剩余责任必须据实收敛；对象存在、字段存在、测试通过或 Git commit 不单独证明 WorkCase 完成。
6. 关闭后只保留有查重、结果理解、责任去向和后续决策价值的内容，不保留完整过程流水。

必须重新设计：

- DSH AgentTeams/continuable subagent 下的 attempt 单调令牌与中断恢复；
- 快通道与小工作准入，防止 wc-39 式误建；
- partial/cancelled/not-achieved 的终态和剩余责任承接；
- 独立审核失败时的保证披露与 Human 决策，不复制 v4 多轮补丁。

### 5.3 WorkCase 34

必须保留：

1. 只适用于已完成 Gate 1 且可精确回读当前授权包的 WorkCase。
2. 执行过程中消费冻结授权基线，不重复索取同一授权，也不询问扩权；超界事项取消、缩小或安全收敛后进入结果链。
3. 真实检查点才写回；不得先实施后补造 `in_progress`，也不为极小同一检查点工作制造虚假中间状态。
4. Controller 自检、独立结果复核、反馈处置、关闭提案形成后才能进入 Gate 2。
5. 不能创建真正独立 Reviewer 时，必须披露保证差距；不能谎报独立审核。
6. 34 只组织行动，不重复定义 21 的字段、phase、状态机和关闭条件。

待 21 决定后再定：

- DSH 原生计划审查、授权流、AgentTeams、goal rounds、Isolated Session 验收如何映射 Gate 1/Gate 2；
- 中断恢复和 attempt 令牌由 21、34、08、09 分别承担哪些语义和实现职责；
- Gate 2 与宿主验收条的字段映射。
