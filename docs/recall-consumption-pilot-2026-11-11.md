# 召回消费侧试点记录（2026-11-11）

**试点目的**：不看召回「准不准」，只看召回有没有改变行动。按 `34 §8.3` 的三项判据（有指向、有改变、可回指）逐条判定，不用事后归因代替证据。

**试点方法**：选真实回合，记录当次注入的全部材料（候选与索引），逐条判定是否改变了行动的路径、前置条件、是否继续或是否提请；只记录，不预先改代码或规范。发现缺陷后另立修复，修复本身也作为试点观察对象。

**样本与边界**：本记录覆盖两个真实回合（A 纯读取、B 有候选），另参考九步取证的整体读数。样本小，不能外推；适用判断是语义判断（`34 §14` 不证明判断正确）；未观察其他会话、外部用户流量与宿主全部注入分支。

## 案例 A：纯读取回合（2026-11-11 18:24，指令「试点」）

### 召回交付

- 词法候选：**0 条**（`34 §6` 判为纯读取／纯查询，不进入词法候选召回）。
- L0 索引：3 条 ADR、3 条事实规范、经验按需行。
- 经验按需行原文：`本项目当前无 active 经验（0 条）`。

### 逐条判断

| 材料 | 判定 | 依据 |
|---|---|---|
| ADR「每次回复先称呼老丁」 | **适用** | 改变回复开头（程序性要素） |
| ADR「只推 dev」 | 不适用 | 本回合无提交 |
| ADR「状态禁令作用域及决定记录的承载位置」 | 不适用 | 本回合不设状态禁令 |
| Norm「上游更新跟进规程」 | 不适用 | 本回合不跟进上游 |
| Norm「发布门槛」 | 不适用 | 本回合不发布 |
| Norm「本地开发工作流」 | 暂不适用 | 本回合无提交；后续修复提交时适用 |
| 经验按需行「0 条」 | **与事实不符** | 见下 |

### 动作改变

1. **有指向**：经验按需行的计数是一个具体行动要素——它决定「本项目有没有经验可召回」。
2. **有改变**：该行报「0 条」，而 `ldvh_pitfall_list` 报 68 条 active。我没有按索引写成「无经验」，而是转去枚举核对；动作从「记录结论」变成「核对并修复」。
3. **可回指**：`34 §8.4` 第 1 项要求总数真实，`34 §12` 三态要求「本类为空」与「未枚举」可分辨；「0 条」违反二者，故必须核对。

这是本次试点唯一一次由召回材料触发的**实质性**动作改变，但触发原因是索引错误，不是候选相关。

### 缺陷与修复

- **根因**：`baselineOnlyForAction` 曾从常驻段枚举里查找 `pitfall` 段，再以 `?? 0` 兜底。2026-11-11 经验改为按需后，常驻段只剩 `adr`／`norm`（`L0_SEGMENT_ORDER`），找不到 `pitfall` 段只表示「经验不在常驻枚举」，不代表「本项目没有经验」；`?? 0` 把「未枚举」说成了「本类为空」。
- **修复**：新增 `countActivePitfalls(facts)`，全量路径与基线路径共用同一计数口径；基线路径事实源不可读时给 `null`（读不到 ≠ 没有）。
- **回归用例**：`buildRecallInjection：纯读取回合的经验总数须与全量路径一致（2026-11-11 缺陷回归）`，同时钉「真实总数」与「两条路径不漂移」。
- **验证**：`node --test plugin/test/recall-injection.test.mjs` 89/89 通过；全量测试 3173 项、3153 通过、0 失败。
- **边界**：修复先在测试与直接调用中验证；2026-11-11 19:36 宿主重启后，`ldvh_inspect_loaded_modules` 报 `stale: 0`，运行实例已加载修复模块。但本回合指令「重启了」有词法候选、走全量路径（该路径修复前即报 68 条），**不能区分基线路径是否已修**；基线路径的线上输出仍待一次纯读取回合观测。

## 汇总与结论

| 回合 | 词法候选 | 改变程序性要素 | 改变实质性判断 |
|---|---|---|---|
| A 纯读取「试点」 | 0 | ADR「称呼老丁」 | 索引错误触发的核对与修复（非候选） |
| B 有候选「继续推进」 | 12 规范 + 5 事实 | 03 §7.2；ADR「只推 dev」 | 0 |

**结论**：

1. **真正稳定起作用的是常驻索引／基线层**（ADR、事实规范），不是词法候选层；词法候选在两次样本中只影响程序性要素。
2. **索引会错，而且错了会被消费**：这次正是靠「0 条」与工具读数的冲突发现并修复了一个真实缺陷。反过来说，索引必须可核对，不能把「索引说什么」当成「事实是什么」（`34 §13`）。
3. **短指令下候选层结构性为空**：`34 §6` 会把「试点」「继续」这类纯操作指令判为纯读取／纯查询，词法候选不进入；要测候选层，必须用「指令本身含任务描述」的真实回合。
4. **试点不能证明因果**：两次样本只说明「这次没有观察到候选改变实质性判断」，不能证明「候选永远不会改变判断」；也不证明「候选质量差」——样本里多数是泛词命中，属预期噪声。

**下一步建议**：

- 若要继续试点，选一次内容型真实任务（用户指令本身含任务、对象、动作），再按本记录格式记一次；否则按收口处理。
- 本记录可作为 SG 评估包「消费侧材料」的补充：它给出了「候选是否改变行动」的首个逐条可回读样本，同时暴露并修复了一个索引计数缺陷。
