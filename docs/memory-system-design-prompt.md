## 一、LDVH 是什么

LDVH（LD Vibe Harness）是深度绑定 DSH（一个类 Claude Code 的 Agent 宿主平台，支持插件、子代理、工具注册、事件钩子）的 AI 协作治理框架，目标是让长程 Vibe Coding（人主导方向、AI 长程执行的开发模式）稳定、可控、高效。

它的立论基于三个对协作的认知假设，你的设计必须与其一致：

1. **AI 不可靠**：输出是概率性推理，会出错、漂移、遗忘——只能靠外部制度、机械检查、多视角复核约束和补偿；
2. **人有短板**：规划模糊、灵感流失、进展断续、经验离散——只能靠外部稳定承载接续与复用；
3. **配合有错位**：人接不住 AI 的笃定，AI 猜不准人的意图——只能靠有效沟通与事前防患让偏差及时止损。

LDVH 由"读、写、编排"三个技术支撑和"记忆、调研、讨论、遵守"四个业务系统构成。**四大业务系统各自独立规范文档（Human 决定 2026-09-10）：调研已有 11 号、讨论已有 12 号，记忆系统规范为独立新规范（规范号立项时按 01 §11 定），本文档是其设计定稿。**

**战略动机（Human 2026-09-10 定）**：LDVH 已有 git（事实源），若用户另行安装其他记忆系统，内容会重复。因此 LDVH 记忆系统必须**独占记忆职责**——两层合起来完整覆盖记忆需求，让用户不需要第二个记忆系统。

## 二、LDVH 已有的基础设施（设计必须建立在其上）

### 2.1 事实源（已建成，运行中）

LDVH 把"跨行动稳定承载的项目事实"放在 git 仓库目录 `ldvh-base/` 下，目前有六类事实对象：

| 类型 | 目录/文件 | 语义 |
|---|---|---|
| Spark 火花 | `sparks/` | 悬而未决的议题与评估输入 |
| WorkCase 工作案 | `workcases/` | 含执行计划与验收的任务 |
| ADR 决定 | `adrs/` | 已拍板的架构/取舍决定 |
| Pitfall 失败经验 | `pitfalls/` | 踩过的坑与教训 |
| Research 调研 | `researches/` | 外部对象深度调研产物（三态证据+引用闭环） |
| Goal 目标 | `goal.md` | 项目目标与子目标 |

每个对象 = 一个 Markdown 文件：frontmatter 薄索引层（机器消费：三态证据索引、关系边、状态、指纹）+ 固定 H2 结构的阅读层。关键机制：

- **受控读写**：写入经工具层 CAS（内容指纹比对防覆盖）、写后强制精确回读、部分字段由 Code 托管；
- **分层召回 F0-F4**：类型目录存在性 → F1 最小卡片投影 → F2 候选发现（确定性字段过滤+有界摘录）→ F3 全文展开 → F4 按溯源锚点回查外部来源；
- **关系边**：对象间 `inspired-by`/`informs`/`updates` 等有向关系；
- **溯源锚点**：每个发现单元末尾一行 `溯源：<URL>（<锚点位置>）`——事实源存"可回查的判断"，不存原文镜像。

### 2.2 Git Gate（已建成）

commit-msg 钩子机械校验每次提交（message 契约、受保护文档、受控字段），失败阻止提交。**LDVH 一切事实变更都走 git，闸门在 git 生命周期上。**

### 2.3 规范源与 Helper（已建成）

`specs/` 是 LDVH 自身规则体系（00-12、20、24、25 已建，26 预留）。Helper 是确定性执行层：AI 发请求、Helper 机械执行。**DSH 宿主提供**：Session 生命周期、子代理（独立上下文、工具白名单、persona）、动态工具注册、事件钩子、问询通道。**无独立服务器、无独立数据库进程、无 cron 定时设施。**

### 2.4 记忆系统职责定义（已定，不可更改）

- **职责**：留存和取回项目的经验认识；从目标、判断、行动、结果、摩擦和反馈中形成候选认识，接收多入口候选并按沉淀制度分流决定去留，空闲时自动维护记忆健康；
- **判据**：留存的内容有消费对象、适用边界和明确去向；候选认识可回指实际行动和证据；偶发现象与可复用模式可区分；
- **边界**：记忆留存不自动产生规则或授权；对象数量、页面呈现和单次复用不证明效用。

## 三、外部调研证据（六个项目已深研，直接站在其上）

### A. dsh-mnemon 0.5.6（DSH 生态最成熟记忆平面）

三层记忆：Runtime 热记忆（memories.json 真值，投影 MEMORY.md 10KiB / USER.md 4KiB 字节预算）/ Documents 受管文档（index.json 元数据真相源，单文档 2MiB）/ Memory Spaces 持久层（九 provider 可换、能力诚实矩阵、四型关系边）。**记录机制三路**：主控工具随手记 + **空闲评审代理**（对话检查点后保守回顾——只有真人明确断言够格，推断偏好/AI 断言/可重新发现的事实不记，默认不变更）+ 容量代理（满了只整理不新增）。**热到持久溢出写原文非摘要**。闸门：准入（只能操作本轮实际看到的）、forget 三重门槛（自主 worker 白名单硬性剔除）、压缩 CAS。**快照进消息流、协议进系统提示**（防缓存失效）。USER.md 画像永不出本机。记忆条目带 source 来源三值：user/agent/external。MEMORY.md 记项目/环境/决定/惯例/工具怪癖/可复用教训。

### B. dsh-agent-memory（DSH 原生轻量记忆）

六类（fact/preference/decision/lesson/todo/note）+ scope（user/project 两字段）+ importance 1-3 + TTL + accessCount 记账。storageDomain 单 JSON 存储。零依赖启发式检索（CJK 单字+双字分词、评分=base×importance×recency×access、Jaccard≥0.7 近重复合并）。pre-step 事件驱动注入 top-3。**错误计数到阈值自动提示写 lesson（提示不自动写，闸门在 AI 手里）**。容量 400 条、importance-3 淘汰保护。

### C. dsh-noema（跨工具记忆导入中枢）

外部 Rust MCP server + SQLite。无类型分类（text+tags+实体+三元组）、六型关系边多跳召回、SHA-256 内容键账本去重（跨 10 工具导入）、状态机 active→reviewed→rejected。

### D. dsh-sgme（独立记忆引擎）

L0 原始层 append-only → 自动蒸馏管线（去重/合并/矛盾检测）→ 14 维 dimension 记忆（TTL/time_velocity/priority）。BM25+向量+RRF 融合检索。supersession 归档。中文优先（jieba）。

### E. Letta Code（业界头部，与 LDVH 最同构）

MemFS：本地文件系统是服务端 memory blocks 的 git 投影（**LDVH 相反：文件即真值**）。目录即召回层级（/system 常驻系统提示、非 /system 渐进披露）。**Context Constitution（CC0 宪法）**：四治理维度（管什么/顺序/粒度/多久）、**记录与索引分野（可检索的不存为记忆）**、四失败模式（忘写回/囤积/塞系统提示/加载无关 skills）。**git hook 双闸门**：pre-commit 校验记忆 frontmatter（read_only 受保护字段 Agent 不可增删改、编辑白名单只有 description）、post-commit 镜像。约束配置 .memfs.config.json（深度 2/单文件 20K/核心 64K 字符）。fail-closed 沙箱（子代理记忆隔离，无沙箱宁可抛错）。三类上下文管理子代理：Recall/Reflection/Defragmentation。

### F. Mem0（业界通用层）

全自动 LLM 流水线：FACT_RETRIEVAL 提取 → 四操作决策（ADD/UPDATE/DELETE/NONE）→ 向量+图。**图记忆实测整体增益仅 ~2%**；91% p95 延迟降/90% token 省的分层效率证据。内容倾向是 C 端个人生活记忆，非工程记忆。

### G. 横向结论

检索技术光谱：启发式 → 全文+图 → BM25+向量 → 向量+图——**上向量的全是引擎/服务端形态，插件级千条量级全在启发式端**；量化（embedding 压缩）六项目零使用（规模差 3-4 个数量级）。记录自动化光谱：mnemon（AI 主动+最严纪律）→ agent-memory（AI 主动+事件提示）→ Letta（Agent 自主+宪法）→ noema（状态机审核）→ sgme/Mem0（全自动流水线，无人工闸门）。

## 四、设计红线（你的方案必须逐条通过）

1. **Human 决定权**：跨界动作（晋升/删除公共记忆）走 Human Gate；记忆留存不自动产生规则或授权；
2. **单一主控 AI 最终负责**：子代理委派不转移责任；
3. **防自欺**：机械结果与语义判断互不替代；
4. **文件即真值**：不引入服务端投影层、不建第二权威；
5. **深度绑定 DSH 原生机制**：不引独立引擎/服务进程/存储后端；
6. **反过度设计（YAGNI）**：普通文件可无损承载的摘要不对象化；
7. **不跟风**：向量/图是可选项非标配（图增益 ~2% 实证）；
8. **效用不可冒充**：必须有消费对象、适用边界、明确去向。

## 五、本地层与信息分界设计定稿（Human 拍板，2026-09-10——**这部分是对抗审查对象，不是重新设计对象**）

### 5.1 两层架构

- **本地层**：存 `$DSH_HOME/storages`（DSH 原生 storageDomain），跨项目共享、不进项目 git、轻治理。回答"这个人/这台环境怎么工作"；
- **git 层**：`ldvh-base/` 事实源 + 完整治理（受控写入/Git Gate/类型准入）。回答"这个项目怎么做出来的"。

### 5.2 信息分诊：一根主轴 + 三道门 + 默认方向（"什么进 git、什么不进"的判据体系，核心设计）

**主轴（受众判据）**："这条信息错了或丢了，伤害的是谁？"

- 伤害**项目**（误导未来任何人/任何 AI 的行动）→ 进 git——所以要举证、要 Human 拍板、错了要走退休流程；
- 只伤害**自己**（我被误导，删掉重记即可）→ 留本地——所以无举证义务、随手删；
- **谁都不伤害**（可重新发现）→ 不记。

**三道门（信息分诊决策树）**：

```
候选信息
  │
  ├─ 门 0：不记门（先过，防垃圾）
  │    · 可从会话历史/文件/git 重新发现？ → 不记（Letta 记录与索引分野）
  │    · AI 自己的断言、推断出的偏好？   → 不记（mnemon 评审纪律）
  │    · 单会话临时状态？               → 不记（Human 拍板：状态不记，
  │                                      接续靠 DSH 会话历史 + Output Envelope）
  │
  ├─ 门 1：git 门（受众 = 项目）
  │    问：它错了会误导项目的未来参与者吗？
  │    · 是 + 证据可回指 → 进 git，按性质路由：
  │        坑→Pitfall ｜ 决定→ADR ｜ 外部结论→Research ｜ 议题→Spark ｜ 任务→WorkCase
  │        触发：即时检测（记录时发现）或攒熟提议（buffer+命中次数）
  │        闸门：Human 拍板，晋升写原文
  │    · 是 + 证据还不够 → 先落 buffer（本地），攒证据，走攒熟路径
  │
  └─ 门 2：本地门（受众 = 自己/本机）
       · 工作偏好             → preference
       · 环境/机器/工具事实    → fact
       · 跨项目个人模式       → pattern
       · 未成熟的项目观察     → buffer（晋升候选池）
       · 其余                 → note
```

**默认方向（不对称裁决规则）**：不确定时，先落本地。本地→git 有晋升通道随时可补；git 错了要走退休流程、公共代价已发生。宁可漏进 git，不可错进 git——与"受控写入宁可拒绝不可静默降级"同一姿态。

**灰色地带裁决**：

| 场景 | 裁决 |
|---|---|
| 工具怪癖（两侧都像） | 问受众：坑到团队（环境无关的 bug）→ git Pitfall；只坑本机（版本/配置）→ 本地 fact |
| 个人模式中出现项目信号 | 观察期落 buffer（project scope），反复验证后攒熟提议 |
| 用户随口说的项目事实 | 受众是项目 → 即时检测当场提议进 git，不先落本地多一跳 |
| 小教训小技巧 | 不新增类：环境无关且坑团队的即时升 Pitfall（Pitfall 不必都是重大事故）；只影响本机的落 fact |

**git 层 V1 不新建对象类型**（Human 拍板 2026-09-10）：buffer 成熟的候选认识按性质路由到既有六类（坑→Pitfall、外部结论→Research、决定→ADR、悬置→Spark）——这正是 02 §9"按沉淀制度分流决定去留"的原义。实践中发现"正面可复用模式"确无家可归时再议新类型（YAGNI）。

### 5.3 晋升通道（三路触发，统一概念）

| 触发 | 机制 | 先例 |
|---|---|---|
| **即时检测**（路径 A） | 主控记录/对话中发现内容够格（有证据、项目相关、跨会话有效）→ 当场提示"建议记录为事实对象"→ Human 拍板 → 直接入 git（不落 buffer） | mnemon 读时判断的升级 |
| **攒熟提议**（路径 B） | buffer 条目 confidence 高 + 被反复命中 + source 可回指 → 空闲评审时提议 | noema reviewed 态 / sgme 蒸馏 |
| **摩擦检测** | 同一错误/摩擦出现 N 次 → 提示主控"该记 lesson 了"（提示不自动写，闸门在 AI 手里） | agent-memory 错误计数 |

晋升**写原文非摘要**。晋升后本地条目**留影子**（追加 `promoted` 指向 git 对象 uid），影子不参与召回。反向无仪式：本地记忆错误直接删，无审计负担。**Human 拍板双入口**（Human 拍板 2026-09-10）：Web 确认卡（主面，见 5.11）+ 会话内问询通道（即时提议即时决，DSH 问询机制）——主面不等于唯一面。

### 5.4 双路召回

git 侧（F0-F4 分层）与本地侧（启发式+scope 过滤）各自独立、各自预算；(a) 注入顺序 git 优先（预算冲突时 git 先占坑）；(b) 冲突裁决 git 赢。热集常驻（按 type×scope 挑选）+ pre-step 动态召回（当前用户消息作 query 检索 top-N）。**本地侧每次召回注入附命中依据**（匹配字段与分值——noema 的 explain 审计工具先例），与 git 侧 F2 候选发现的"命中依据"对称（防自欺）。**记忆协议文本进系统提示、易变内容进消息流**（防缓存失效）。

### 5.5 本地层条目结构

```yaml
---
id: mem_a1b2c3d4e5f60789
type: buffer              # preference | pattern | fact | buffer | note
title: 一句话标题
tags: []                  # 可选，小写
scope: project            # global | project（两字段，scope=project 时 project 必填）
project: dsh-ldvh
confidence: medium         # high | medium | low——晋升成熟度信号
importance: 2              # 1-3；=3 受容量淘汰保护
source: 2026-09-10 会话·一句话上下文   # 必填弱形式回指
origin: user               # user（用户明说）| agent（AI 观察）——用户明说天然更够格晋升
created: ISO8601
updated: ISO8601
expires: 可选 TTL
locked: false               # 人手动锁定后 AI 只读不可改删（容量淘汰也跳过）——Letta read_only 先例，Human 决定权的本地层落地
promoted: <git object_uid> # 晋升后追加，影子不参与召回
---
正文 Markdown，≤2000 字符
```

运行时系统记账（不进 frontmatter）：accessedAt/accessCount——召回命中时更新，效用审计信号。

### 5.6 记录触发（三路）

1. **主控随手记**（对话中，工具直写，写入过 Helper 格式校验：必填/闭集/非空/source 必填，fail loud 只管格式不判语义）。**随手记的标准第二动作——写入前四操作比对**：先查已有条目，判断新内容是新增/修正/矛盾/重复（Mem0 四操作决策的人工闸门版——它用独立 LLM 自动做，我们让主控顺带做，无新增闸门）；**矛盾时提示"替换还是并存"**（sgme 矛盾检测先例——提示不自动改；preference 类最需要：偏好变更不应矛盾共存）；
2. **空闲评审代理**（对话检查点结束后保守回顾：默认不变更、每次至多一条变更、只认真人明确断言——mnemon REVIEW_PERSONA 先例；与 git 层"空闲自动维护记忆健康"共用同一空闲钩子）；
3. **容量维护代理**（满了只整理不新增：压缩/归档/TTL 淘汰）。

### 5.7 本地层无举证义务（Human 决定）

**本地信息不用保留、不用举证**：不保留原始对话（不采纳 sgme 式 L0 归档）、source 保持弱形式回指即可、删除无审计负担。**举证是 git 层的职责**（Research 溯源锚点、Pitfall 证据链）——不对称治理：本地层宽进轻出，git 层严进严出。

### 5.8 治理参数与检索

容量上限 400 条、importance-3 保护、Jaccard≥0.7 合并、TTL 过期（**按类默认衰减率**：preference/fact 180 天、pattern/note 90 天、buffer 30 天——sgme time_velocity 的简化版，条目可显式覆盖）。检索零依赖启发式（tokenize+jaccard+加权评分，CJK 处理参照 agent-memory）+ scope 过滤（当前项目条目+global 兜底）。**不上向量**（远期最轻升级路径 sqlite-vec）、**永远不上量化**。

### 5.9 明确不采纳

投影层/服务端真值（文件即真值）、Agent 级记忆主体（LDVH 主体是项目）、独立服务进程、自动提取流水线（Mem0/sgme 式无人工闸门，与"AI 不可靠"根判断相反）、本地原始对话归档（见 5.7）、**容量判据（mnemon 式"热层满了才溢出"——把分界权交给字节数是被动的，受众判据是主动的）**、跨会话接续状态记忆（选 C：靠 DSH 会话历史 + Output Envelope 交还结构承载，本地层五类不含状态类）。**V2 待议**：SHA-256 内容键幂等（Jaccard≥0.7 已覆盖近似重复，仅会话重放场景有增量价值）、记忆互链 related_to 字段（量级小时收益有限，Letta 索引链接先例）。

### 5.10 完整性承诺（独占记忆职责）

两级门设计使 LDVH 记忆系统覆盖全部记忆需求的信息流——任何候选信息都有去处（git 六类对象 / 本地五类 / 不记），用户装了 LDVH 不需要 mnemon 或 agent-memory 等第二个记忆系统：

| 用户原本装 mnemon 的理由 | LDVH 对应 |
|---|---|
| USER.md 记用户偏好 | 本地 preference（且多 origin 语义） |
| MEMORY.md 记工作记忆 | 本地 fact/buffer + git 层 |
| Documents 记项目文档 | git 层事实对象（带完整治理） |
| Memory Spaces 持久库 | git 层（clone 即继承，不需要 provider 矩阵） |

LDVH 不提供的（向量/图/九后端）恰是这个量级工程记忆被六项目证明不需要的——**覆盖是完整的，多余是恰好的**。

### 5.11 管理面与待拍板

**管理面双通道（Human 决定 2026-09-10）**：**Web UI 是人的主管理面**（对齐 10 号规范四层阅读器与授权流交互入口；LDVH 插件 Web 端已有 ObjectList/ObjectDetail/CognitionCenter 基础）——记忆列表页（type/scope/importance 过滤、accessCount 冷热、TTL 预警）、记忆详情页（命中依据 + locked 开关）、**晋升确认卡**（原条目+溯源+拟落类型+确认/拒绝——Human 拍板的 UI 化）、审计视图（四失败模式体检+摩擦检测历史）、对话内轻交互（回合尾记忆活动条，mnemon turnBar 先例）、远期关系图（三类节点：事实对象/类型目录/标签，确定性布局）。**工具面是 AI 的面**（主控随手记/召回/评审/比对）。**Web 写操作与 AI 工具写操作过同一道 Helper 格式校验**（单一闸门不因入口分叉；mnemon 独立写通道+认证先例）。

**存储形态已定**（Human 确认 2026-09-10）：A. storageDomain 单 key 聚合（agent-memory 先例）——Web 成为人的主面后，"一条目一 key 人友好"的理由消失（人不直接碰存储）。

**V1 参数（Human 批准默认值 2026-09-10）**：
- V1 最小集：三页（记忆列表/详情/晋升确认）+ 三命令（记/查/删）；
- 摩擦检测阈值：同一错误 3 次触发提示（可配）；
- 空闲评审代理：默认开启、可关闭。

### 5.12 git 层关系图（Web 呈现扩展项，Human 方向确认 2026-09-10）

**判断：git 层比本地层更需要关系图。** 理由：①关系是 git 层的语义骨架——事实对象本来就靠关系组织（"这个决定基于哪个调研、推翻了哪个旧决定、起源于哪个火花"），关系链就是项目演进史；②HV5（项目演进脉络可循）的直接可视化承载；③审计刚需——讨论"改这个决定影响谁"时需要看对象的辐射面；④量级恰好（几十个对象画图清晰，对比本地层 400 条记忆的图嘈杂）。

**LDVH 的图几乎免费（与 mnemon 的本质差异）**：mnemon 的边要靠 AI 在对话中主动调 link 工具一条条建（带准入纪律）；LDVH git 层的关系边是**受控写入的内建产物**——每个事实对象创建时 frontmatter 的 `relations` 就声明好了（`inspired-by`/`informs`/`updates`/`superseded-by` 等闭集，Git Gate 校验合法性）。**数据全在，图只差渲染，零建边成本**；关系导航的双向查询（反查谁指向我/正向我指向谁）已在 F2 候选发现规划内。

**设计草案**（待 10 号 Web 呈现规范扩展时立项）：
- 三类节点：对象节点（六类事实对象，按类型着色）/ 类型目录节点（容器，可选显示）/ 标签节点（serves_sg、tags 聚合视角）——直接映射 mnemon 的三类节点设计；
- 两个视图：**全景图**（挂 Federation 页或新页——整个 ldvh-base 的对象关系网，演进脉络一屏看）+ **邻域图**（挂 ObjectDetail 页——单对象一跳邻域，"基于什么、影响什么"，讨论与审计用）；
- 布局：确定性哈希布局（mnemon 先例——同一数据每次渲染位置一致，两次渲染的差异=数据真实变化，可对比演进）。

**本地层明确不做图**：关系稀疏（无受控关系字段，轻治理设计使然）、量级不值、收益密度低。

### 5.13 git 层新类型候选：Friction 摩擦账本（Human 批准 2026-09-10）

**语义定位（普适改进账本）**：记录"应该修但还没修"的系统性阻碍——与 Pitfall 的分界是**改进导向 vs 规避导向**："CI 每次要 8 分钟"不是教训（避不开），是待修的账。命名依据：02 §9 规范原文用词即"摩擦"（六入口之一，类型名直接对应规范原文，如 Research 对应"调研"）；行业实践为 DevRel 领域的 friction log；Scrum 的 Impediment（障碍）记为备选参考；Technical Debt 不采用（特指权宜之计的债务，语义有偏）。

**归因判据（摩擦记到谁的仓库）**：

| 归因对象 | 记录位置 | 账本性质 | 消费端 |
|---|---|---|---|
| LDVH 框架自身（规范/Git Gate/工具/流程——**无论发生在哪个项目**，含将来 SG-4 项目里遇到的框架摩擦） | LDVH 仓库 `frictions/` | 框架迭代账本 | 规范修订判断（01 §11）输入、SG-3 dogfood 度量 |
| 项目自身（该项目 CI/构建/依赖/流程的摩擦） | **该项目自己的 ldvh-base** | 项目改进账本 | 该项目迭代决策 |
| 项目业务上的坑 | 不是 Friction——走 Pitfall | 教训（规避导向） | 防再踩 |

**三层闭环（与相邻类型的分工）**：账本层（Friction open→resolved）→ 决定层（攒够触发 Spark 议题或直接 ADR，走讨论系统）→ 教训层（修复过程中踩的新坑走 Pitfall）。Friction resolved 时以 `informs` 关系边指向解药（修订 commit/ADR/WorkCase）——闭环可追溯。

**入账三条件（防过度红线，全中才记）**：重复出现 + 可归因 + 修了会更好。单次卡顿（可重新发现/偶发）与情绪化抱怨过门 0 不记。

**最小字段**：title / status: open | resolved | deferred / phenomenon（现象，非结论）/ attribution（归因指向，可空）/ impact: light | medium | heavy / serves_sg（框架摩擦挂 SG-3）/ relations（resolved 时 informs 解药）。

**出生路径（全部复用已定机制，零新增触发器）**：空闲评审代理捕捉 → 轻微/不确定先进本地 buffer 攒 → 重复出现 N 次（摩擦检测，阈值 3）或重大即显 → 即时检测提议 → Human 拍板（双入口）→ 受控创建进对应仓库。**Friction 类型不是 buffer 的晋升落点**（晋升落点仍是既有六类——本节与 5.2 的"V1 不新建类型"不冲突：Friction 是独立的框架/项目改进通道）。

**消费端价值**：① 规范与工具迭代的证据输入（攒到什么程度触发修订，有账可依）；② SG-3 度量（摩擦数与解决率 = dogfood 质量的机械验证）；③ SG-4 对外价值交付（用 LDVH 的项目自动获得可追溯的改进机制，摩擦解决曲线即 HV4"积累效用直观可见"的证据）；④ 反过度设计的反向信号（部分摩擦指向设计过度，是简化的输入）。

**立项路径**：独立类型规范（新类型号，走 01 §11 规范新建判断），**可先行于记忆系统规范落地**（最简版空闲评审直接提议创建即可，不依赖本地层）；v4 的 problem-ledger 实践（docs/v4-problem-ledger.md）为历史佐证与迁移输入。

### 5.14 git 层设计决定与遗留处置（Human 拍板 2026-09-10）

**三个已拍板**：

1. **立项顺序——记忆系统规范与 22（WorkCase）/23（Pitfall）类型规范并行起草、互为输入**：晋升路由的三个落点（21 WorkCase / 22 ADR / 23 Pitfall）中 22/23 规范未建，buffer 晋升的目标契约暂空——并行起草使"什么内容会流进来"（记忆侧）与"准入契约是什么"（类型侧）同时成形，避免单向等待；21 号（WorkCase）按既有排期不因此提前。
2. **预检式召回集中放记忆系统规范**：做决定前自动查相关 ADR（防矛盾决定）、动手前查 Pitfall（防重蹈覆辙）、调研前查 Research（防重复调研）——触发规则统一由记忆规范定义（记忆系统是**主动防线**而非被动仓库），各业务规范只引用不重复定义。
3. **沉淀制度作为记忆系统规范的一章**：02 §9 "按沉淀制度分流决定去留"的展开落记忆规范内（四系统各自独立规范的既定结构下，沉淀制度是记忆系统的核心机制，不另立独立制度文档）。

**三个转开放问题（交对抗审查出方案，倾向供参考）**：

- 晋升格式转换规则（buffer 条目 → 目标类型结构补全：谁补、怎么补——倾向主控在提议时补全）；
- git 对象效用信号（倾向：Git 提交 message 引用 object_uid 作为消费信号，Git Gate 机械可统计）;
- 影子与退休对象的联动（superseded 链上影子指针是否跟随更新）。
