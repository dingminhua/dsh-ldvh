## 1. 判据、普查方法与计数更正

### 1.1 采用的判据（`specs/01` §7.2 逐字）

> **判据**：一句正文如果**随实现或其它载体的现状变化而需要修改**，它是状态，不得留在正文；如果它在现状变化后**仍然成立**（义务、条件、边界、禁止项），它是规则，应当留在正文。

> **状态的去向**：现状信息由机械扫描或 Code 取得，不由规范承载；确需向读者提示现状时，以**条件式要求**的形式表达（「在 X 具备之前，不得……并须披露未兑现范围」），把事实判断的责任交还给读取时的观察，而非固定在正文里。

三档禁止项（§7.2）：1 实现状态（「已实现／尚未实现／未接入／已由某提交落地」，以及实现所在的文件、函数或批次说明）；2 下位文档的存在状态；3 过程与进度（当前处理到哪一步、待办事项、已完成的轮次或批次）。

### 1.2 普查方法

对 `specs/08-DSH环境接入与插件发布规范.md`（275 行）逐行判定，检索面覆盖两类模式：

- 版本对照与核验标记类：`核验`／`两版`／`零 diff`／`零变化`／`零变更`／`字节级一致`／`逐字相同`／`完全一致`／`0.1.`／`0.2.`；
- 过程、待办与能力缺失类：`此前`／`本次`／`曾经`／`仍待`／`待补`／`尚未`／`未消费`／`未接入`／`已接入`／`已实现`／`不提供`／`无 … API`／`无 … 服务`／`如实`／`实测`。

命中的每一行按 §1.1 判据逐一核算，**不因带日期戳与否、也不因是否为括注而预先归类**。
