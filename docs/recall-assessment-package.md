## 3. 未检查范围与遗漏截断

### 3.1 三态披露（已修）

2026-11-11 提交 `567a924a` 修复三处披露失真：

- **未列清单用切片冒充集合差**：事实侧交付前经分节重排，`slice` 把已返回对象算进「未列出」。实测 7 条已返回事实中有 5 条同时出现在 unchecked。改为按 path 真差集后重叠归零，两侧 kept+unchecked 与命中总数自洽。
- **分节外条目只给数不给类型**：`unassigned`（实测 13 条 = devlog 8 + subgoal 5）此前不披露，现按类型列出。
- **devlog 越界进候选**：29 §12.1 早已写明不进自动注入，排除名单只含 spark。实测同一次召回 112 条命中含 8 条 devlog，均未交付却计入分母。

### 3.2 当前未检查范围（据实）

- 本包未检查：其他项目的事实源、外部用户的真实使用流量、宿主侧注入实现的所有分支。
- 评测集仍只代表本项目真实原话的有限样本，不等于全部使用场景。
- 行动取证历史快照（2026-11-11）扫描 200 个含注入会话；本次复跑受当前可取得的本机会话目录限制，只得到 27 个含注入会话、70 个注入回合。两次取证的会话与回合分母不同，不能直接作趋势比较。

- 终态对象按类型规范不进入默认候选；这属于设计边界，但仍须将状态过滤与枚举不全、预算截断分别披露。

## 4. 适用判断

**已补**（2026-11-11）：可回读记录见 `docs/recall-precheck-record-2026-11-11.md`，按 03 §7.2 公共格式对当次动作逐条判定。

此前本项只能声明「该能力尚无可回读产出」；该历史状态已由记录补上，不能继续作为当前状态描述。现有记录提供：逐条判定、判定依据，以及不适用的理由。

**这份记录最有信息量的部分不是哪些被判定适用，而是十条规范被判定「不适用」**：32／36／35／05／30／27／24／33／26 等进入候选，仅因当次问句含「根据」「文档」「给出」等泛词，与之对应的动作（建单、销账、形成经验、改 CLI 结构、改 Goal、做调研）本轮一个都没发生。这正是 `pitfall-06d08683`「以词频区分泛词与主题词在专门语料失效」的现场实例——若不逐条判定，「命中」就会被当成「相关」。

**边界**：该记录只证明「作出并记录了一次适用判断」，不证明判断正确（34 §14「不证明适用判断正确」），也不证明此后每回合都会这样判断。要成为持续能力须接入实际流程，属机制改动，需先按 00 §5.1 说清服务哪项价值、以什么证据核对。

## 5. 行动落实

取证脚本：`plugin/scripts/recall-action-evidence.mjs`。数据源：真实会话日志的注入块与其后的事件。该脚本产出结构性回指证据，不判定因果，也不单独裁定是否满足 34 §8.3 的语义判据。

### 5.1 历史快照（2026-11-11）

历史 DevLog `devlog-aa2fae2f` 记录扫描 200 个含注入会话、629 个注入回合、3069 条候选；注入后工具调用 607/629（96.5%），参数回指 51/629（8.1%，131 次），write 档 15/629（2.4%），reasoning 提及候选 124/629（19.7%），动手但未提及候选 483/629（76.8%）。更早评估稿曾记录 627 回合；629 是在修正日志解析漏项后的历史终值。它们都属于当时语料快照。

### 5.2 当前可取得会话快照（2026-11-12）

以 `--limit-sessions 200` 重跑，脚本扫描到 27 个含注入会话、70 个注入回合、377 条候选；275 个目录无会话日志（子代理/空目录），非读取失败；真读取失败 0、不可解析行 0。

| 指标 | 本次读数 |
|---|---:|
| 注入后发生工具调用 | 64/70（91.4%） |
| 调用参数回指到候选 | 9/70（12.9%），20 次回指 |
| 出现 Gate 类动作 | 6/70（8.6%） |
| write / read / relay（按回合最强档） | 1 / 3 / 5 |
| reasoning 提及候选 | 22/70（31.4%） |
| 动手但未提及候选 | 44/70（62.9%） |

本次样本与历史 629 回合不相同；本机日志目录可见范围、当前数据集与历史扫描范围不同，不能把百分比变化解释为行为改善或退化。

### 5.3 证据解释

「回指」不等于「落实」——读一下文件和据此改写对象是两件事。write 档只证明受控写入/审批参数承载了候选标识；它不证明候选导致决定改变。read 档是精读前置，relay 档只是转述，均不能单独算作落实。是否满足“有指向、有改变、有可回指依据”仍须逐回合语义判读。

## 6. 材料进入判断的位置

判据：被注入候选的标识（uid 或非通用标题前缀）是否出现在该回合 AI 的 reasoning 中。

历史 629 回合快照为：有 reasoning 609/629，reasoning 提及候选 124/629（19.7%），动手但未提及候选 483/629（76.8%）。

本次 70 回合快照为：有 reasoning 68/70，reasoning 提及候选 22/70（31.4%），动手但未提及候选 44/70（62.9%）。这两个读数不能直接比较行为变化，因为分母和可取得日志集合不同。

在任一快照中，“动手但未提及候选”只能说明材料没有进入可观察的判断位置；它支持 34 §8.3 的“有指向”尚未得到结构性证据，不等于机械证明候选没有被使用。

## 7. 结论与边界

### 7.1 结论

**双源召回当前能稳定交付候选，但现有证据仍不足以证明它普遍改变了行动。**

本次复核支持三点：

1. 候选质量：固定评测集本次为整体精确率 6.2%、any-of 命中 18/21、all-of 命中 6/21、对象级命中 26/45；这说明“有进展即命中”与“完整覆盖”差异很大。
2. 消费侧结构证据：当前可取得 70 回合中，write 档 1 回合；历史 629 回合快照为 15 回合。两者不可合并为趋势，但都不能被解释为因果证明。
3. 判断位置：本次 70 回合中 44 回合动手但未提及候选；历史 629 回合中为 483 回合。该指标支持“材料进入判断的位置仍缺结构性证据”，不等于证明模型绝未使用候选。

按 00 §2.6 与 34 §8.3，召回职责的“实际改变行动”目前**尚未被现有证据普遍证明**；这是一项证据结论，不是对所有回合的机械判定。

### 7.2 该价值冲突已由 Human 裁定并落入规范（2026-11-12）

提高精确率（价值二）与保持召回宽度（价值一）在本系统里直接对立：

| 侧 | 主张 | 负担与风险 |
|---|---|---|
| 提高精确率 | 减少噪声，让关键约束不被稀释（§1.4「过载时关键约束被稀释」） | 门槛抬高会漏掉本该召回的条目，伤价值一 |
| 保持宽度 | 召回系统归在价值一，宁多勿漏 | 每回合注入整屏噪声，抬高上下文成本 |

**Human 的裁定（2026-11-12）**：预算受限时**优先精确率**，但**同一决策**要求候选交付同时保留消费方法与详情入口。该裁定已写入 `specs/34-双源召回系统规范.md` §8.2（候选选择优先次序 + 四项必保项）与 §14（对应四行验证），并已在实现中落地：

1. 事实候选行带完整 `object_uid`、规范候选行带 `spec_key` 并标明「L4 全文入口」（`34 §8.2` 第 2、4 项）；
2. 用法行判据从「预算档位」改为「是否真的交付了候选」——有候选必有用法、零候选不占字节（第 3 项）；
3. 渲染层裁掉候选时，完整度降级为 `partial`，不再出现「complete + 已裁去 N 条」的自相矛盾（§12）；
4. 预算与条数上限数值、来源排除范围、评测阈值**均未改变**。

**该裁定不证明价值冲突已消解**：它只固定了取舍方向与必保项；精确率本身仍由 §2.1 的读数承担，未因本次改动而变化（复跑仍为整体 6.3%、any-of 18/21、all-of 6/21、对象级 26/45）。

### 7.3 未验证范围

- 适用判断已有一次可回读产出，但仅证明判断被作出并记录，不证明判断正确，也不证明此后每回合持续执行。
- 因果未验：write 档只证明候选标识出现在写入或审批参数里，**不证明该候选改变了决策**——也可能是其它原因促成同一动作。语义判读属 AI/Human 核对，脚本不越界。
- 样本边界：32 条固定用例和两次会话取证都来自本项目，不等于其他项目或外部用户流量。
- 取证分母边界：2026-11-11 历史快照与 2026-11-12 当前快照的会话集合和回合数不同，不支持行为趋势结论。
- 时间边界：会话日志跨多个实现状态，包含 `567a924a` 等披露修复前后的材料；本包不把读数变化归因于某一实现改动。
- 精确率与召回宽度的取舍方向已由 Human 于 2026-11-12 裁定并落入 `34 §8.2`／§14（见 §7.2）；**但取舍方向已定不等于精确率已改善**——本次改动只改交付形态与消费方法，未改候选选择序列，复跑读数持平。
- 本次未改变注入预算、条数上限、来源排除范围与评测阈值；这些仍受 `10 §9.1` 第 2 项与 `34 §15.1` 第 5 项的 Human Gate 约束。
- 用法行与稳定引用的**实际效用**尚未验证：本次只证明它们出现在交付面（有守卫用例），不证明 AI 因此改变判断。

### 7.4 新增负担与以什么核对（00 §5.1 第 4 问）

**新增负担**：取证脚本需扫会话日志（628 个目录、单会话最大 18MB 多帧 zstd），单次运行约数分钟；评测集需人工逐条标注并持续维护（已有 4 条结构守卫防标注腐烂）。

**主要风险**：把「回指」误读成「落实」——本包已并列披露历史快照的 76.8% 与本次快照的 62.9%，但这两组分母不同，且语义层面的因果仍不可机械证明。

**以什么证据核对**：后续若改动召回，用同一脚本与同一评测集重测 §5／§6 的三条读数是否移动；读数不动即改动无效。
