## 4. §6 是否越界（明确判定）

**判定：§6 整体遵守「只规定实现纪律、不替它们定义接口或行为」的声明，但存在 2 处轻度越界/张力，不构成系统性越界。**

逐项：
1. **规范解析实现**（L108）：仅规定单一入口 + 测试，精确引 01 §6/§10.3，不改语义——**不越界** ✓
2. **LDVH CLI 操作契约**（L110）：以 09 自有措辞重述 05 边界，未引 05 章节，措辞与 05 §5.2 第 3 项不完全一致——**轻度越界/存疑 S3**（与「不替它们定义接口或行为」有张力；但方向一致，未创设新语义）。
3. **Git Gate 共享**（L112）：规定同一入口，并明确「具体路径由实现登记，不由 09 替 06 预定」——**守界** ✓
4. **管辖登记共享**（L114）：测试派生清单以压缩形式复列 07 契约覆盖项，但声明「具体用例清单随 07 契约维护，不在 09 建立第二份字段或算法定义」——**守界但有负载消费张力（P1）**，未定义 07 语义本身。
5. **机械签名**（L116）：重申 06 §6.1 取值纪律（06 已指派 08/09 实现验证），属授权内——**不越界** ✓；但对 03 `change_log` 署名补位「所需的 provider/model」，而 03 仅规定「署名由 Code 托管」未定义署名结构，且 03 §6.1 明言「09 均不取得字段定义权」——**轻度越界/存疑**（对 03 字段署名作结构补位，超出其授予 09 的「机械实现与测试」授权，但风险低、且与 06 trailer 同构）。
6. **Output Envelope**（L118）：明确「Envelope 最低语义由 00 §7.4 定义，09 不定义其形状」，08/10 定义宿主/呈现，且 08 §7.7 明确委派 09 单一生成——**守界** ✓

**结论**：§6 的边界声明基本被正文遵守；两处轻度张力（05 转述、03 署名补位）建议收紧措辞或显式标注「此处置仅复列来源契约、不另立定义」，即可完全消弭。
