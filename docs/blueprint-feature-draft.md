# 蓝图功能设计草案 v1（需求记录 + 初步想法）

> 性质：**讨论工作稿（非规范、非候选、非事实对象）**——2026-09-07 Human 提出"蓝图"真实需求（"工作蓝图每次都存在你的记忆里，我没法看到"），主控初步设计记录于此。待后续正式裁决后升格为规范候选或直接实施。
> 需求发现者：Human（2026-09-07，工作模型重构完成后的蓝图梳理对话中）
> 对应价值：HV5 项目演进脉络可循（主）、HV1/HV2/HV4（辅）

## 1. 需求陈述（Human 原话 + 场景）

**原话**：
> "你看现在就存在一个真实的需求，也就是工作蓝图这个，每次都存在你的记忆里，我没法看到"

**场景**：主控刚完成工作模型重构（4 个 commit），向 Human 汇报了完整蓝图——但这个蓝图只存在于对话上下文和 AI 记忆里。Human 下次打开项目，看不到这个蓝图；换个会话，AI 要靠翻历史才能重建。

**本质**：LDVH 帮 AI 解决了"经验不沉没"，但还没帮 **Human** 解决"规划不模糊"——00 §1 第 2 条痛点：

> "长期规划与演进，逐渐模糊。项目往往起步于一个大致的方向……项目是怎么走到今天的，接下来要往哪里去，都答不上来。缺的，是让'从哪里来、到哪里去'**随时可答**的承载。"

## 2. v4 的经验教训

v4 用 `docs/v5-handoff.md` 做跨会话移交——有作用但有三个缺陷：

| 缺陷 | 表现 | 蓝图功能要怎么改 |
|---|---|---|
| **一次性** | 写完就不再更新，很快过时 | 活文档——每个重大节点后持续更新 |
| **AI 专属视角** | 写给 AI 接手用的，不是给 Human 看的 | Human 第一——你随时可看，不是 AI 的交接备忘 |
| **无固定结构** | 内容随写的人自由发挥 | 固定六区块结构，读的人不用猜 |

## 3. 初步设计

### 3.1 蓝图是什么

**一个固定位置、固定结构、受控更新的活文档**——Human 随时可看的项目状态总览。

```
位置：仓库根 BLUEPRINT.md（Human 最容易找到的位置）
形态：Markdown（初期）/ Web 页面（最终形态，随阶段 4a）
更新：主控起草 + 受控提交（Git Gate 管，现在就能用）
```

### 3.2 六区块固定结构

```markdown
# [项目名] 蓝图

## 当前目标          ← 引用 Goal 对象（有则引用，无则 Human 手写）
## 当前阶段          ← 四阶段之一 + 一句话说明
## 已完成            ← 重大节点列表（引事实对象/commit，不凭记忆编）
## 进行中            ← 正在做的事（含状态和负责人）
## 下一步            ← 按优先级排序（含依赖关系）
## 悬而未决          ← 待 Human 决定的事集中可见
```

### 3.3 三个纪律（防蓝图腐化）

| 纪律 | 内容 | 防什么 |
|---|---|---|
| **更新时机** | 每个重大节点后（规范提交/阶段完成/Human 决定），不是定期空转 | 防过时——蓝图的价值在于反映"当前" |
| **更新方式** | 主控起草 → Git Gate 受控提交，不是随便改 | 防漂移——蓝图是正式产物，不是便签 |
| **内容来源** | 从事实源/Goal/提交记录投影，不凭 AI 记忆编 | 防虚构——蓝图是投影，不是第二事实源 |

### 3.4 与新工作模型的关系

蓝图是**记忆系统的产物**：

```
记忆系统（存储 + 检索 + 路由 + 维护）
  └─ 蓝图 = 记忆系统的一种特殊产物
       ├─ 存储在仓库根（Human 最容易找到）
       ├─ 从事实源/Goal/提交记录投影（不是第二事实源）
       ├─ 每次重大节点受控更新（活文档）
       └─ Web 呈现为项目首页（最终形态，阶段 4a）
```

### 3.5 对应价值

| 价值 | 蓝图怎么兑现 |
|---|---|
| **HV5 项目演进脉络可循** | 蓝图本体——"从哪里来、到哪里去"随时可答 |
| **HV1 决策提请清晰可决** | "悬而未决"部分——待你决定的事集中可见 |
| **HV2 授权执行受控可续** | "进行中"部分——你离开再回来，看一眼就知道进展 |
| **HV4 积累效用直观可见** | "已完成"部分——做了什么、积累了什么 |

## 6. 与已有规范的关系

- **不违反 00 §3.3**（事实源）：蓝图从事实源投影，不是第二事实源——"未经受控写入的信息，不因被记录、返回或呈现而自动成为稳定事实"
- **不违反 03**（事实模型）：蓝图不是事实对象（不进 ldvh-base/ 类型系统），是 Human 可读的项目状态文档
- **关联 10**（Web 呈现）：最终形态由 10 承接（Web 首页投影）
- **关联记忆系统**（02 §9）：蓝图的更新维护归记忆系统（每次重大节点是记忆的"维护事件"）
