## 0. 总则（四条，先于一切子问题）

1. **主控即队长**：LDVH 不设独立「队长」角色——单一主控 AI 最终负责（specs/00 §5），委派不转责。一切 spawn 的实体都是主控的**手段**，不是平级责任主体。主控必须保住 judge 位（MAD 研究结论：judge 能力是天花板——八维表 §4.2 发现二，原始综述见附录 A #16）。
2. **信息四层定位**（修 F-01；v4 拆层——原「运行态」一分为二，Human 追问「WC 本身有状态、每个事实对象都有状态」触发）：
   - **事实**（ADR/Pitfall/决定/结论）——唯一权威是事实源 YAML 文件，只经写维落盘器写入；
   - **事实对象内嵌状态机**——权威在事实源：状态是 YAML 的 status 字段本身，跃迁=受控写入（签名+时间戳+change_log 留痕）。状态机是**事实的一部分**（内嵌特写层，非并列独立层），不是运行态。**三层细化（Human 2026-09-06 细节澄清，v4 实证 E 主题 067/073）**：
     - **状态语义分两类**：**效力状态**（ADR active/retired、Pitfall active/discarded、Spark 各态——回答「这条还有没有效」）与**进度状态**（**仅 WC 有**——回答「执行到哪了」；其他事实对象没有「执行中」这个状态）；
     - **WC 是双层状态机**：WC 级生命周期（draft→accepted→open→closed，Gate1/Gate2 夹住）≠ item 级生命周期（工作项自己的状态，v4 E 主题 067 item 生命周期拦截的治理对象）——两级不同物，不可混写；
     - **呈现目的**：WC 执行过程与生命周期变化的**呈现**，服务 Human 了解工作进度（HV 价值）——呈现走 Web 信息呈现通道消费状态机与事件流投影，底座只保证两者可供消费；「状态变化的可见」与「状态跃迁的受控写入」是两件事（v4 E 主题 073「执行状态可观察」的分层）。
     - 实证规模：157 份 WC 全部带状态机+判据逐条核对+closure_outcome（盘点时点 2026-09-06，八维表附录 B #26；问题账 2026-08-24 记 152 份，两数均为观察时点值非矛盾）；
   - **活动态**（attempt 令牌值、成员忙闲、任务派发关系）——权威在运行时（编排引擎），审计投影=会话事件流：可丢弃、可重建、**绝不作为事实来源**（LDVH 不引入 AgentTeams 式「状态目录当真相源」——study F2/F5 的不吸收结论维持）；
   - **交付物**（实体间 Handoff/任务书/结论）——是通信内容不是事实；「像事实」的交付物只能作为**候选**走写维（验证环+Human 门+落盘器）。
   - **状态两层归属规则**：宿主 goals 服务只能承载**活动态**编排镜像；WC 生命周期若用 goals 辅助编排，是**镜像非权威**——同步冲突时以事实源 WC YAML 为准（镜像可从 WC YAML 重建，反向不可）。
3. **指针过信道，内容少过信道**（修 F-02）：实体间传递的是**机械生成的元数据 + 锚点指针 + 结构化交付物**三类，**不是主控自由撰写的摘要**。需要原文时给锚点（文件+段落），接收方自读。机械生成 = 从事实对象 YAML 既有字段直读（F0 枚举模式：title/status/trigger_signal 是既存字段，非总结）；主控撰写的只有任务书（Handoff 六段，属交付物语义，必带锚点，可核对）。
4. **一切「AI 必须不」的纪律先定档**（修 F-07）：四档——**状态机断言**（纯函数写入前拒绝）/ **能力白名单**（成员上下文不装该工具）/ **宿主网关**（pre-execute 拦截，宿主能力）/ **persona 自律**（仅提示词，如实标注「自律级」）。写方案时必须声明档位。**档位诚实性规则（修 N-01）**：凡依赖未实测宿主机制的档位，必须标注「待实测」并降一档表述——不得拿类比（如 mnemon worker 是 mnemon 自建白名单）充当宿主已验证能力。

## 1. 六个子问题 × 底座方案 v2

### 1.1 spawn 纪律

**组织原则（两模真正共用的，修 F-04）**：
- ①一切 spawn 经主控之手——**能力白名单档（待实测）**：意图是成员上下文不注册任何 spawn 类工具。候选实现=宿主 `registerContinuableSetup`（**未实测**——八维表 Group G 标注「未试过的正道」；mnemon worker 白名单是 mnemon 自建机制，非该 API 的已验证行为——若实测语义是「启动时执行 setup 函数」而无法介入工具注册，则此档退化为宿主网关档或 persona 档）。实测项登记遗留表；
- ②上限机械拒绝——**状态机档**：深度/分支/节点数写入前纯函数校验（solo-thinking DEFAULT_LIMITS 模式，具体数值 LDVH 落规范时定）；
- ③Human 手动点名 spawn：**绕过 dormant/staged 流程直接物化**，但仍受上限机械约束（修 B-09——「优先」指流程豁免，不是上限豁免）。

**spawn 形态（两模各自独立，如实分写，修 F-04）**：

| | 审议模（发散讨论） | 执行模（工作包分活） |
|---|---|---|
| 物化时机 | **先物化再选**：2–4 个 dormant 分支出生（各带方向专属 Handoff），选定才唤醒 | **先批准再物化**：任务 DAG staged，工作包 Gate1（Human Gate）批准才 spawn 成员 |
| 出生态 | dormant（不唤醒不跑） | active（批准即运行） |
| 终态 | returned（封存）/ 废弃 | 任务 terminal（结果经主控收货） |
| 依据 | solo-thinking 生命周期 | AgentTeams approval=required 语义（思想层，不搬状态机） |

### 1.2 信息传递（三信道 + 一禁令）

- **信道 A｜继承锚（指针包，修 F-02/N-03）**：随实体出生注入，内容三样——①**指针**：Goal/Charter 文件路径+版本号+关键段落锚；②**机械生成的 ADR 枚举**：从事实对象 YAML 字段直读（F0 模式，非主控摘要）；③本支任务书（Handoff 六段）。**上限 ≤4000 字符**（修 B-04），超出只留指针。接收方核对纪律：**摘要有疑义必须按锚回原文**，锚点不可解析=报告漂移信号。**存在性前提（修 N-03）**：Goal/Charter YAML 尚未对象化时，①退化为「不存在」的如实报告（不说「无约束」，说「对象未建」）；②的机械枚举只含 YAML 已有字段——字段不全则枚举如实少字段，不补写。此时信道 A 实际内容=任务书+目标路径声明（内容由主控 spawn 时注入并标注「Goal 对象未建，此为临时声明」）。
- **信道 B｜任务书/上报（执行链）**：任务对象承载（目标/验收/范围/依赖/判据锚点）。修正 F-05：任务书**不含形成过程叙述，但必含判据锚点**（Charter/ADR 条款+版本+路径）——成员不知「条款怎么来的」，但随时可按锚查 F3/F4 原文与形成史；Charter 修订时向活跃实体广播 notice（带 diff 指针，非全文）。
- **信道 C｜结论封存（returned）**：子实体终态交付物，只读不可编辑，修正走新轮次。**整合产物的归类（修 F-09）**：主控对封存物的整合结果=新候选对象，按沉淀维五路分流表分流（事实候选走写维 / 经验走 Pitfall / 仅会话中间态则丢弃）——原 returned 永远只读。
- **禁令**：实体间交付物**永不直接落事实源**（红线「Handoff 不作事实交换协议」的正面表述）。跨实体的「事实」只以两种形态存在：指针（接收方自读事实源）或候选（走写维）。

### 1.3 漂移防护

- **出生锚**：信道 A 指针包随出生注入——Goal/Charter 锚点在身，成员自己读原文。
- **结构化分歧**：审议分支分歧必须结构化（正方引 Charter 条款 A、反方引条款 B——引条款=引锚点，不是引记忆）。MAD tit-for-tat 结论。
- **judge 对照——事件驱动，非定时（修 B-07）**：主控在每个成员 returned/任务 terminal 时**即触发**对照 Goal/Charter 核验（不是「定期」空话——每收一货核一次，机械可数）。
- **刷新规则**：Goal/Charter 修订→新实体出生即带新版锚点（版本随出生锁定）；存量实体不追溯改写，但收 notice（带 diff 指针），下一轮自行消化。

### 1.4 中断恢复（四层）

- **L1 实体级**：瞬态锁回滚（状态机档）——带锁操作回合结束未完成即回滚到操作前（solo-thinking recoverIncompleteOperation 同构）。
- **L2 任务级**：attempt fencing——转派/重试先撤旧令牌→中断旧成员→等安静→新令牌；旧令牌迟到更新机械拒收；冷恢复兜底（idle 持开放任务→新 attempt）。
- **L3 副作用级**：**三分类（修 B-05）**——可重入（读/幂等写）→重试或换道；不可重入（非幂等写/外部副作用）→**绝不重试**，从 receipt 定位后人工裁决或缩小范围；**撤销+重做**（已发生副作用需回退）→≠重试：显式回滚到 receipt 前状态+重走流程生成新 receipt，回滚本身须留审计记录。
- **L4 主控级——过渡态（修 F-03/N-04；v4 收窄+R4-2 重写）**：goals 服务承载**活动态编排镜像**（任务轮次、attempt 协调），**不承载 WC 生命周期权威**（权威在事实源 WC YAML——§0.2 状态两层归属规则）。两类镜像须分清（修 R4-2 对象滑动）：**活动态镜像**（goals 里的编排态）——丢失**可容忍**，但重建源是**会话事件流**（非 WC YAML——任务轮次/attempt 值不在 WC YAML 里），goalRoundDriver 内存态恢复未验时为有损回退（事件流+事实侧水位+L2 fencing 兜底）；**WC 生命周期镜像**（goals 若缓存 WC 状态的副本）——丢失**无所谓**，可从 WC YAML 随时重灌。**未经实测验证**（study-absorption 遗留核对项；且八维表 §6.4 第 1 点明确「goals 与 WC 的 Gate1→executing→Gate2 同构度需进一步评估」——同构度假设在执行维映射中同样未裁，本底座不做越前认定）。显式要求：goals 缺 recoverIncompleteOperation 同构品（瞬态锁回滚）则活动态镜像层 L4 必塌，需自建。必塌场景分两组（修 R4-2 归类矛盾）——**活动态层（可容忍，丢失后按上述重建/回退）**：主控进程级中断留半成品编排态 / 主控 Session 重建（goalRoundDriver 内存态能否恢复未验）；**事实侧（不可容忍——非 L4 范畴，由写维落盘器最小版收口，回扣 §2 依赖排序）**：写维落盘中途断电（revision 锁只能拒收不能回滚）。落字为「过渡态：待实现期验证 goalRoundDriver race-fenced 同构度；若 goals 无法承载，L4 需独立恢复机制」。

### 1.5 结果回收

- **收货权在主控**：成员的「做完了」只是声明。主控核对证据、整合、必要时交独立复核。**独立复核主体（修 B-08）**：复核维定案已定——独立优先=新 Session 子代理（64.5% 自检盲区实测封顶自评价值），沿用不另起炉灶。
- **迟到拒收**：旧 attempt 更新机械丢弃。
- **封存交付**：复核结论与终态交付物只读；轮次留档审计链。
- **诚实边界**：不假设上报必达（成员可能完成但忘记上报——AgentTeams 实测）——主控以证据收货（文件/测试/Gate），不轻信声明（specs/00 §7 防自欺的团队版）。

### 1.6 成本控制（三闸门 + 分级）

- **成立闸——分两档（修 F-06）**：计划**触及 00 §4 根决定清单**（新增事实对象类型/规范修订/受保护路径/授权边界）→ Human Gate 硬闸；**不触及**→ 主控自决成立+事后抽审。**抽审标准待决**（修 B-06：抽审谁做/抽多少/对照什么——登记为底座遗留问题，不强行定）。
- **唤醒闸**：dormant 分支不选定不唤醒。
- **轮次闸**：goals maxGoalRounds 硬限（机械），超出即 blocked 交还 Human。
- **已知缺口（修 F-10）**：token 计量暂为提醒级（宿主无 API），与底座「机械优先」定位不一致——显式登记为缺口，与读维预算自建议题合并，待自建计量落地后升硬限。

### 1.7 并发与多工作包（新增，修 B-01/B-02/N-02）

- **写入权分区（分对象，修 N-02）**：
  - **受管写入**（单点在主控）：LDVH 工作树、事实源 YAML、Git 操作（commit/push）、受保护路径——成员产物要进这些位置必须经**主控收货通道**（代码/文档类产物由主控核证据后 commit；**事实类**候选另走写维流程=验证环+Human 门+落盘器——写维管道是事实对象专用，不绑代码交付，与 §1.6 成立闸轻重分级一致）；
  - **瞬态工作产物**（成员可写，不在此分区管辖）：成员执行命令产生的文件系统副作用（测试输出/coverage/构建产物/日志）——**归 L3 副作用级处理**（可重入/不可重入/撤销重做三分类），不构成「写入权」问题；产物持久化进仓库仍走主控收货通道；
  - **成员私有区**（scratch/，gitignore）：成员草稿、中间态、被丢弃的尝试；
  - 区分的意义：成员能跑 `pnpm test`（瞬态副作用）≠ 成员能写事实源（受管写入）——两个维度不混淆。
- **底座 V1 单工作包原子**：一次只编排一个工作包（多工作包并存=串行排队）。多包并行的隔离/路由规则留待执行用法段裁决——显式不装作已解决。
- **dormant 清理（修 B-03）**：审议树 end 时，未唤醒的 dormant 分支即废弃——物理 Session 归档删除，方向描述以事件流留档（防只增不减，HV4）；无半衰期机制。

## 2. 底座 → 两用法映射（展开条件已定，修 F-11；v4 补依赖排序）

**展开规则**：本底座经 Human 终审通过后，审议用法映射与执行用法映射由主控分别起草，各自再过一轮轻量审核（独立子代理）+ Human 终审——两道门，不是底座过审即全部放行。

**依赖排序（v4 新增）**：执行用法映射依赖**写维落盘器最小版先行**——WC 生命周期权威在事实源（§0.2 状态两层归属），状态跃迁=受控写入，没有落盘器则 WC 状态机转不起来（跃迁无处受控落盘）。审议用法映射无此依赖（思考树走信道 A/C，不涉事实跃迁）。**实现顺序：落盘器最小版 → 执行用法 → 审议用法可并行**。
