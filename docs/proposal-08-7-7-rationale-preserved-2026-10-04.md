## 1. 被移出的正文原文（逐字保存）

以下是 `specs/08` §7.7 在 2026-10-04 改动**之前**的原文中，被删除的那一段（**逐字**）：

> 核验结论（2026-09-10，源码双版对照）：宿主两版均无交还产物专用存储入口，且 0.1.5 存在两处升级陷阱（session-persistence 服务直调接口整体移除换 handle 所有权式；存储事件对白名单外类型默认拒绝，ignorable:true 为唯一逃生口）。

**核验时点**：2026-09-10；**方法**：源码双版对照（`DSH 0.1.2-rc.1` 与 `0.1.5-alpha.1`）。

## 2. 该段承载的技术理由（逐项）

destate §3.10 的改法说明指出该段是「宿主能力现状与版本对照」，但同时是下列正文结论的**技术依据**。逐项拆解：

### 2.1 「不进项目事实源目录」

正文保留的判据是：「不进项目事实源目录（判据：事实对象=项目转移时跟目录走、他人接手可共享的内容，handovers 不具备）」。
该判据是**自足**的（以事实源的定义为据），不依赖被移出的核验结论。故删段不影响此项成立。

### 2.2 「不写宿主会话事件流、不依赖 session-persistence API」

**此项的技术理由来自被移出的核验结论**，共两条：

1. **宿主无交还产物专用存储入口**——故 LDVH 不能把 Output Envelope 的持久化托付给宿主某个现成入口，只能自持久化。
2. **`0.1.5` 的两处升级陷阱**：
   - `session-persistence` 服务**直调接口整体移除**，改为 handle 所有权式；
   - **存储事件对白名单外类型默认拒绝**，`ignorable:true` 为唯一逃生口。

⇒ 这两条共同构成「**不依赖 session-persistence API**」的实证依据：该 API 的接口形态在版本间发生过破坏性变更，且对自定义类型的默认策略是拒绝。依赖它会使 Output Envelope 的持久化随时可能因宿主升级而失效。

### 2.3 与正文保留部分的关系

`specs/08` §7.7 正文**保留**了定案与其边界（「由 LDVH 自持久化于本地存储区…不进项目事实源目录…不写宿主会话事件流、不依赖 session-persistence API」）。被移出的只是**支撑该定案的技术事实**，定案本身未变。

**故**：删段后正文的规范性内容**未减少**；减少的是「为何如此」的实证说明，其可查性由本文档承载。
