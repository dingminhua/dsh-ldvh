# 闲时辅助「经验积累」任务与材料供给错配——方案提案

> 状态：**提案**，未经 Human Gate；本文为供独立复核的方案收敛产物。
> 作者：主控 AI（本会话）；日期：2026-10-16。
> 事实源：`~/.dsh/ldvh/idle-checkpoint-runs.json`、`~/.dsh/ldvh/pending-queue.jsonl`、`plugin/lib/*.js`、`specs/*.md`。

## 1. 问题陈述

闲时辅助的「经验积累」（`experience-capture`，specs/36 §10）任务**产出率低、失败理由高度同质**。

### 1.1 实测数据（截至 2026-10-16T16:42Z）

runlog 共 50 条（环形上限 50），其中 `experience-capture`（EC）终局 **18 次**：

| EC 结局 | 次数 | 占比 |
|---|---|---|
| `landed` + `candidate-created`（真产出） | 2 | 11% |
| `landed` + `action=none`（正常完成，无候选） | 8 | 44% |
| `rejected`（未取得结论，入待处置队列） | 8 | 44% |

两条真实产出：`2abbbc2f-507f-4861-beb8-06053f93b8d3`（2026-10-16T06:17Z）、`c4b28410-bd5e-46bf-ada9-1ef91a9e22a0`（2026-10-16T16:42Z）。

`pending-queue.jsonl` 中 EC 共 **23 条**（含历史），**100% 为同一错误码** `discovery/quote_not_in_window`。

### 1.2 与摩擦发现（FD）的关系

同一次派发内 FD 与 EC 的联合分布（21 组）：

| FD | EC | 次数 |
|---|---|---|
| landed | landed | 10 |
| rejected | rejected | 6 |
| landed | rejected | 4 |
| rejected | landed | 1 |

同结局率 76%。但 EC 被拒的 8 次中，**2 次 FD 正常 landed** —— 说明按任务独立收口**确实生效**，不是「互相干扰」。

## 2. 根因

**EC 的判断对象（四前提齐备的失败机制）在时间上横跨多轮，而它获得的材料只是「自上次运行以来新增」的轮次（通常 1–3 轮）；逐字引证又被要求落在这份材料内（`verifyQuotation`，friction-window.js:289）。**

两项要求存在**结构性冲突**：

- 四前提：失败已发生 → 根因已查明 → 解决已采用 → 验证已观察。四项按时间序分布，天然跨轮。
- 材料：`windowFrom(afterTurn)` 只按 `entry.turn > floor` 过滤（friction-window.js:199），即「本轮新增」。
- 引证：`validateCaptureVerdict` 在材料非空时强制 `verifyQuotation(quote, windowText)`（experience-capture-contract.js:192-193）。

故一个真正齐备的经验，其证据**在构造上不可能**全部落在一个新增窗口内。执行体只能引用它真正看到的片段，而这些片段多在新窗口之外（实测引文多含「我上一轮」「我前三轮」），必被拒。

**附带事实**：EC 与 FD 共用同一份 `windowText`（aux-task-registry.js:268）。该材料对 FD（单轮可判）适配，对 EC（跨轮才能判）偏窄。git 记录显示 EC 由 `da114e8`（2026-10-14）接入，与 FD 同构接线。

## 3. 提案：经验积累独立成代理 + 材料形态改为「最近 N 轮」

### 3.1 主张

1. **EC 独立成一个执行体（不与 FD 共用）**——两者材料需求粒度不同，共用只能取交集。
2. **EC 的材料形态由「自上次运行以来新增」改为「最近 N 轮」**——放宽**时间跨度**，但保持**体量有界**。
3. **保持零上下文 spawn + 逐字引证核对不变**——材料变宽，核对规则不变，§11 机械性保住。
4. **重复由 23 §6.2 查重兜底**——`draft` 已纳入查重范围，重复发现不产生重复对象。

### 3.2 为什么不是「每次给全部」

**已被实测证否。** 源码注释记录：fork 全量 seed 在约 1.1 万事件会话达 **37–46 万字符，执行体以 error/max-tokens 失败**（friction-discovery-provider.js:23）。

而「每次给全部」的规模上界：环形缓冲 200 轮 × 每轮 2000 字符 = **400,000 字符**，与已失败量级相同。且 36 §7.1 明文：「执行体输入随会话增长**单调扩大**、成本不可持续」。

### 3.3 为什么 EC 可以放宽而 FD 不可以

| | FD（摩擦） | EC（经验） |
|---|---|---|
| 重复看见的后果 | `occurrence.count` 被灌水（度量失真） | 仅查重命中（无害） |
| 兜底机制 | 水位切分（唯一防线） | **23 §6.2 查重**（第二道防线） |

36 §11 对「只算新增」的必要性论证，其理由是：**「同一现象会因被反复看见而被反复计入第 2 项，使 `occurrence.count` 度量的是被观察次数而非发生次数」**。该理由**只对 FD 成立**（EC 不做计数递增）。

### 3.4 参数 N

建议初值 **20 轮**（约 4 万字符）。理由：经验故事通常横跨数轮而非数十轮；久远内容应已在当时的窗口中处理过。按 36 §17「条件式要求…数值属实现侧承接」，N 应由实现侧承接并可按实测调整，规范不内嵌具体值。

## 4. 需修订的规范条款

| 条款 | 现状 | 拟改 |
|---|---|---|
| 36 §10 | EC 作为闲时辅助任务之一，与 FD 同次派发 | EC 独立成执行体（或至少独立材料） |
| 36 §11 | 观察对象 = 「自上次运行以来新增的会话内容」 | 对 EC 另定材料范围（最近 N 轮），FD 不变 |
| 36 §7.1 | 禁止全量交付 | 不变（本提案不违反） |
| 23 §6.2 | 查重含 `draft` | 不变（本提案的兜底前提） |

## 5. 未验证与风险

1. **N 的取值未经验证**：20 轮是估计值，未实测。需落地后观察产出率。
2. **「最近 N 轮」仍在 §11 的「只算新增」定义之外**：须修订 §11 正文，属 36 §19.1 第 3 项（Human Gate）。
3. **EC 独立成代理会增加派发成本**：多一个子代理。未量化。
4. **§6.1「安静期」触发时机未动**：本提案不解决「回合刚结束即触发」的问题（该问题已被 §6.1 的安静期判据覆盖）。
5. **成功样本仅 2 条**：样本量小，「当前形态勉强可用」还是「基本失效」的判定证据不足。
6. **未验证**：独立成代理后 EC 的实际产出率是否提升，无实测。
7. **本提案未主张**：EC 的失败已由本提案消除；仅主张根因定位与修订方向。

## 6. 需独立复核的具体问题

1. 根因定位是否成立？（「材料跨度 vs 引证要求」的冲突是否真的是结构性、而非可通过其它方式绕开）
2. 「最近 N 轮」是否真的不破坏 §11 的机械性？（切分依据是否仍是纯位置规则）
3. 是否遗漏了更简单的解法？（例如：主控标记、双向引证、材料按需展开）
4. 「EC 独立成代理」是否必要？能否在共用代理下只给 EC 不同材料？
5. 有无规范依据被误读或过度解读之处？
