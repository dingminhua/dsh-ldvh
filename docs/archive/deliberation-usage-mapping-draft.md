## 0. 审议用法一句话

**审议 = 在底座的隔离与锚定之上跑一棵「讨论树」**：主控当 judge，把发散问题拆给 2–4 个独立 Session 分支，各分支出生即带三件套锚（信道 A），结构化分歧、结论封存回传（信道 C），全程不落任何受控载体（除草案工作稿）。

## 1. 审议维定案 → 底座条目映射

| 审议维定案（八维表 §4.4 五条） | 底座条目（v5） | 映射方式 |
|---|---|---|
| 1. 漏斗形态（扩散→收敛→审查→执行） | §1.1 审议模 spawn（dormant 2–4 物化→选定唤醒） | 扩散=dormant 可选集物化；收敛=选定唤醒+讨论；审查=judge 对照+Human Gate；执行=交执行用法（另一文档） |
| 2. AI 间讨论（多实体围绕目标对话收敛） | §1.2 信道 A/C + 思考树拓扑 | 树形=视角关系显式化；讨论走 Handoff 六段交付物（目标/结论/证据/风险/未解/下一步），不走原始对话同步 |
| 3. 审议上下文三件套（Goal/Charter/已激活 ADR） | §1.2 信道 A 指针包 | Goal/Charter=指针（路径+版本+段落锚）；已激活 ADR=机械枚举（F0 模式字段直读）；出生注入不可变 |
| 4. 错误记忆防护（否决标记排除理由） | §1.2 信道 C 封存 + §1.5 封存交付 | 被否决方向：returned 封存只读+排除理由一行（MAD-M2 毒化的机械对策）；最终文档只写推荐方案+排除理由 |
| 5. 与执行维同构（差异在权限态） | §1.7 写入权三分 | 审议期：分支只可写 scratch/（**非受控临时区**——gitignore、不属事实源/工作树/受保护路径任何一类）；不碰事实源、不 commit——「审议期讨论不落任何受控载体（除草案）」的机械落点 |

**底座直接消费、审议侧零新增的**：主控即队长（judge 位）、四档纪律制、写入权分区、成本三闸门（审议树物化=成立闸轻档：不触及根决定清单，主控自决+事后抽审——**抽审标准待决**，底座遗留 1）。

## 2. 一次审议的完整生命周期（时序）

```
触发：Human 提出议题 / 主控识别「值得多视角」的决策点
  │
  ├─ S0 准备：主控确认三件套在场——**硬前置，任一缺失不进入 S1**（机制硬前置：讨论
  │    开始前必须到场）：缺 Goal/Charter→主控先走写维补建对象；缺 ADR 枚举→补枚举
  │    （接线后机械直读）。补建完成才开议；「临时声明」仅是补建完成前的标记，不构成
  │    开议豁免（底座 §1.2 存在性前提的审议侧落点）
  │
  ├─ S1 扩散：thinking_suggest 等价动作——2–4 个方向物化（dormant，各带方向专属 Handoff）
  │    纪律：宁缺勿凑（solo-thinking 0.1.19 模式）；上限纯函数拒绝（底座组织原则②）
  │
  ├─ S2 选定：Human 或主控 judge 选定唤醒哪几支（唤醒闸——dormant 不选定不跑）
  │
  ├─ S3 讨论：被唤醒分支独立工作；结构化分歧=persona+Charter 条款锚（正方引条款 A、
  │    反方引条款 B——引锚点非引记忆）；跨分支同步只走 checkpoint 语义（Current State
  │    发布，不唤醒兄弟）。**轮次耗尽（D-2，默认 ≤3 轮）未收敛→显式报僵局**，僵局出口
  │    三选一：①上抛 Human 终裁（僵局触及根决定清单时必走此路）；②主控收回、缩小议题
  │    后回 S1 小规模再物化（≤2 支，一次为限）；③封存「当前无足够锚点收敛」结论交还
  │    Human（如实报告，不硬凑方案）
  │
  ├─ S4 judge 对照（事件驱动——每支 returned 即触发，底座 §1.3）：主控对照 Goal/Charter
  │    核验各支结论；漂移信号（锚点不可解析/结论无锚）→ 该支结论不入收敛
  │
  ├─ S5 收敛：主控整合（整合产物=新候选，按沉淀维五路分流——事实候选走写维，
  │    其余按去向）；被否决方向：封存+排除理由
  │
  ├─ S6 审查（事件驱动——由 S4/S5 的 returned 触发，非定时）：收敛产物按风险分级
  │    分流——触及根决定清单→Human Gate；不触及→主控自决+事后抽审（**抽审标准仍待决**，
  │    底座遗留 1，未定案）
  │
  └─ S7 终态：审议树 end——未唤醒 dormant 即废弃（物理 Session 归档删除，
       方向描述事件流留档，HV4 防只增不减）；封存结论供复核/执行引用
```

## 4. 审议侧待裁点（本轮轻量审核+Human 终审时定）

| # | 待裁点 | 候选与倾向 |
|---|---|---|
| D-1 | 分支 persona 与工具面设计：审议分支该给什么工具？ | 倾向 mnemon worker 模式——读类工具+事实读取 F 层+报告；**零写工具**（审议分支只产交付物不落盘）；不装 spawn 类工具（白名单档） |
| D-2 | 讨论轮次上限 | 倾向每支 ≤3 轮即必须收敛或显式报僵局（防无锚漫谈）；机械计数控 |
| D-3 | 分支数量默认值 | 物化 2–4（宁缺勿凑）；**Human 是否可手动指定第 5 支**——倾向可（手动点名=流程豁免非上限豁免，底座已定）。**交叉澄清**：手动第 5 支豁免与 S3 僵局出口②的「≤2 支·一次为限」不冲突——前者是正常流程的 Human 点名权限，后者是僵局处理路径的全流程硬限（整个审议流程只触发一次缩小路径）；若 Human 已手动点名在先，僵局时仍可走出口②，但该次触发视为该硬限的一次消耗 |
| D-4 | 审议产物与 ADR 的关系 | 讨论收敛出「决定」时：走写维起草 ADR 候选（验证环+Human 门），不是自动变 ADR——质量门纪律（遵守维定案 4） |

## 5. 红线自检

- 不依赖 solo-thinking 运行（编排代码 LDVH 自建；事件溯源+乐观锁为**吸收的工程件形态**——LDVH 自己实现同样机制，非运行依赖；其状态机与 MARKER 不搬）✅
- Handoff/交付物不作事实交换协议（交付物不落事实源；judge 在 S4 可**引用**交付物作核验依据——引用≠事实化，核验后的结论走写维落盘才转事实）✅
- MARKER 不用（指令走 tool calling）✅
- AgentTeams 状态机不搬（本草案无涉）✅
