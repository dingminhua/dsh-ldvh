## 0. 执行用法一句话

**执行 = 在底座上跑一个工作包（WC）的生命周期**：Gate1 冻结批准 → 任务 DAG 派活（成员执行）→ 主控逐件收货（证据收货）→ 关键跃迁受控落盘（落盘器）→ 复核 → Gate2 关闭 → 交还。主控全程是唯一责任人，成员只是手段。

## 1. 执行维五点未决逐点收口（八维表 §6.4）

### 点 1：工作包层是否用宿主 goals 服务承载生命周期 → **已由底座解决一半，剩余收口如下**

底座 v5 已定：goals 只承载**活动态镜像**（任务轮次、attempt 协调），WC 生命周期权威在事实源 WC YAML（状态两层归属规则）。

**剩余两点的裁决提案**：
- **镜像同步时机**：单向懒同步——主控在每次受控写入 WC YAML 后，下次编排决策点读 WC YAML 刷新镜像（不需要实时同步；镜像永远可从 WC YAML 重灌）。
- **失效检测**：主控发现镜像与 WC YAML 不一致时，**以 WC YAML 为准并重建镜像**（机械规则，无仲裁空间）；无需失效告警机制（不一致本身无危害，因为镜像非权威）。

### 点 2：中断恢复默认策略 → **底座 L1–L4 框架直接适用，WC 语境映射**

| 底座层 | WC 语境 |
|---|---|
| L1 实体级（瞬态锁回滚） | 成员回合中断：其持锁任务操作回滚到操作前，任务回 ready 池 |
| L2 任务级（attempt fencing+冷恢复） | 成员失联：撤 attempt→安静→重派新 attempt；迟到结果拒收 |
| L3 副作用级（三分类） | 可重入（测试/构建）→重试；不可重入（外部副作用）→绝不重试，人工裁决；撤销+重做→显式回滚+新 receipt |
| L4 主控级（活动态镜像） | 主控中断：镜像丢失可从 WC YAML+事件流重建（底座已定；goalRoundDriver 实测=遗留 3） |

**WC 特有补充**：Gate1/Gate2 之间的 WC 处于 open 态时，任何中断恢复都以「不越过当前 Gate」为界——恢复动作不得隐含新的授权（v4 E 主题 034 Gate1 授权完整性的中断版）。

**E1 物化阶段与 Gate1 审批前后的中断归属（审核 F5 采纳；E1/E2 等阶段术语定义见 §3 生命周期）**：
- **Gate1 审批前中断**：无恢复问题——WC 在 draft 态无受控写入、无成员物化，重开即续（L4 活动态镜像丢失可从 WC YAML 重灌）。
- **E1 物化中中断**（DAG 已建、部分成员已物化）：归 **L2 任务级**——未派发任务的成员按 dormant 废弃处理（等同审议树 end 清理）；已派发任务按 attempt fencing 常规处理；WC 状态仍在 open 前态，无事实侧跃迁需回滚。
- **Gate1 审批后**：即点 2 主表覆盖的 E2 执行循环场景。

## 2. 底座遗留 8/9 项裁决提案（本草案核心新增）

### 遗留 8：跨层同步触发（任务 terminal → WC item/results 受控写入）

**裁决提案**：
- **谁触发**：**主控收货时触发**——成员任务 terminal 只是活动态事件；主控核对证据收货后，由主控发起对 WC item 状态/results 的受控写入（落盘器）。成员永不直接写 WC YAML（Git 与事实落盘单点主控，底座已定）。
- **收货判据分级**（审核 F6 采纳）：证据充分的判据**锚定 WC YAML 的 success_criterion_definitions**——主控逐条对照该 item 关联的判据项；判据项类型不同则核对动作不同（代码类=测试通过+文件落盘；文档类=结构完整+主控确认；Gate 类=Human 签批），但**判据本身永远来自 WC 判据定义，主控不自造标准**。
- **轻重分级**：WC 级跃迁（draft→accepted / open→closed）=**Human Gate**（Gate1/Gate2 本来就是 Human 决定点，root 决定清单内）；item 级状态更新与 results 追加=**主控自决轻档**（收货即写，不逐条问 Human——否则每个 item 都弹卡，不可用）。**例外协调（审核 N2 采纳）**：含 Gate 类判据的 item，其状态跃迁以 **Human 签批为准**——判据分级覆盖轻重分级的默认轻档（判据本身来自 WC 定义，主控不自造标准亦不自行放行）。
- **时序**：收货→受控写入→镜像刷新（点 1 的懒同步），三步顺序固定。
- **task↔item 对应**（审核 F8 采纳）：task terminal 为**触发表面**，收货内容按证据归属到 item/results——一 task 可对应多 item（聚合交付）或一 item 拆多 task（细化执行），映射关系在任务书派发时声明。

### 遗留 9：item 级更新频率分级

**裁决提案**：双层频率制——
- **item 状态机跃迁**（pending→in_progress→done/failed）：受控落盘（低频，item 数量级）；此为权威记录。
- **item 内细粒度进度**（「正在跑第 3 个测试」「覆盖率 72%」）：走**事件流呈现**（高频，Web 通道消费）——不落盘、不进 WC YAML。
- 判据：**凡改变「下一步该做什么」的信息落盘；只改变「现在做到哪了」的观感信息走呈现**。呈现服务 Human 了解进度（底座 §0.2 呈现目的），落盘服务事实回溯。

## 3. 一次工作包的完整生命周期（时序）

```
Gate1：Human 审批 WC（goal/scope/判据冻结；staged 计划批准=底座成立闸）
  │
  ├─ E1 物化：任务 DAG（成员 staged→批准物化）；成员出生带信道 A 指针包
  │    （Goal/Charter 锚+ADR 枚举+任务书；任务书判据锚指 WC success_criterion_definitions）
  │
  ├─ E2 执行循环：就绪任务派发（attempt 令牌）；成员执行（工具面=白名单档 guard）；
  │    细粒度进度→事件流；L1–L3 恢复兜底
  │
  ├─ E3 收货（每任务 terminal 触发）：主控核对证据（声明不算数）；
  │    item 状态/results 受控写入（遗留 8 提案）；judge 对照 Goal（底座事件驱动）。
  │    **复核分级**：item 级复核=主控收货时证据核对（轻——每个任务都做，机械证据）；
  │    WC 级复核=全部判据收齐后独立复核（重——复核维定案：新 Session 子代理，
  │    按判据逐条核，不含形成过程）
  │
  ├─ E4 WC 级复核：双层完成声明——机械层（测试/Gate）+独立复核（E3 的 item 级
  │    复核不豁免此步）；复核结论封存轮次留档；复核发现缺口→回 E2 追加任务
  │    （converge 循环，修复后复验——不改判据本身）
  │
  ├─ E5 交还：判据逐条核对结果汇总；若有未决→goals blocked+结构化交还文档（点 4 提案）
  │
  └─ Gate2：Human 验收关闭（closure_outcome 分类）；WC→closed 受控落盘
```
