## 0. 为什么不用优先级

优先级要求人对每个对象表态，且一旦写入就需长期维护；同时 AI 自评重要度触及 00 §7 防自欺边界。

本清单改用两个属性排序：

| 属性 | 含义 | 提取方式 |
|---|---|---|
| **可执行性** | 该 Spark 是否必须等 Human 表态才能推进 | 读 `scope_boundary`：停止条件是否要求「Human 裁定／决定／终审」 |
| **被指向数** | 有多少其他对象在 `relations` 或正文中指向它 | 机械反查 `object_uid` 在 `ldvh-base/` 与 `docs/` 中的出现次数 + `relations` 入边 |

分档规则：

```
第一档：可自主推进 + 有指向        ← 立刻做
第二档：可自主推进 + 无指向        ← 随时可做
第三档：需 Human 表态 + 有指向     ← 牵动别处，值得优先催裁定
第四档：需 Human 表态 + 无指向     ← 最后再看
```

### 0.1 本属性的边界（重要）

**「被指向数」衡量的是顺序，不是价值。二者可以完全脱钩。**

- **指向多但不重要**：一条技术性事项挡着若干琐事，解锁了也只是清理杂务。
- **重要但指向为零**：`LDVH 记忆系统` 指向数为 **0**，却是 SG-3 下的核心方向——尚未到可被引用的阶段。若以指向数当重要性判据，它会被误判为不重要。

**同时须区分指向的性质**：`relations` 入边中，`merged-into` / `split-into` 记录的是**历史收拢动作**（旧议题被拆并进来），**不等于现时有人依赖它**。两类指向在计数时未加区分——这是本表的一个已知粗粒度，使用时须回看原文确认性质。

**因此本清单不主张「被指向多 = 重要」。** 它只用于识别「不挡在别人后面 / 挡着别人」这一顺序信息。「值不值得做」是价值判断，按 00 §4 属 Human 决定权范围，不由本表回答，也不由任何字段回答。

## 1. 第一档：立刻可做（1 条）

### Norm 与 WorkCase 承载层补建

- **被指向数**：2 处正文点名 + 3 条 `relations` 入边（1 merged-into + 2 split-into）
- **指向性质**：3 条入边的源全部是 `discarded` 的 Spark，记录的是「旧议题被拆出/并入此处」的**历史收拢**，**不表示现时有对象依赖它**。故此数说明的是它由多个议题汇聚而来，不是"最多人在等它"
- **停止条件**：Norm 与 WorkCase 均可受控创建、可召回、Git Gate 覆盖
- **硬证据**：`ldvh-base/workcases/` 与 `ldvh-base/norms/` 均为 **0 个对象**。承载层未建，这两类事实**一个都创建不了**（**2026-09-13 修正**：当时两目录均**不存在**，非「为空」；目录已补建，但 writer 与 Git Gate 断言仍缺席，故「一个都创建不了」的结论**不变**）
- **排第一的真实依据**：不是被指向数，而是**目录无对象**——它证明「悬置 → 执行」这条通道不通。23 条 Spark 至今没有任何 WorkCase 承接，直接原因就在这里

**即：它排第一是因为"通道不通"，不是因为"最重要"。这两个结论不等价**（见 §0.1）。

## 5. 与 SG 的关系（说明为何 serves 不产生区分度）

23 条中 17 条挂 SG-1（规范体系）。经逐条判读，**这没有错标**——它们确实都是 SG-1 下的独立议题。问题在于 SG-1 粒度太粗，一条子目标下挂了 17 个彼此无关的议题。

**因此本清单不按 SG 分档，而按可执行性与被指向数分档。**

## 6. 自认未验证范围

1. **需 Human 属性为文本判读**：依据 `scope_boundary` 中的「Human 裁定／决定／终审」措辞。已逐条复核标为「可自主」的 10 条确认无隐性 Human 依赖，但措辞的语义判断是 AI 判断，非机械校验。
2. **被指向数**为 `object_uid` 字符串反查，可能漏计未写 UID 的语义引用；且未区分指向性质（历史收拢 vs 现时依赖，见 §0.1），为已知粗粒度。
3. **未评估工作量**：第一档被识别为「不挡在别人后面」，不代表它能在短时间内完成——其停止条件（可受控创建 + 可召回 + Git Gate 覆盖）本身是较大的工程范围。
4. 本清单是**某一时刻的快照**；Spark 状态变化后需重新生成。
5. 本清单**不构成授权**：第一档「立刻可做」指不依赖 Human 方向裁定，不替代 00 §4 的受保护范围判断与 Gate 授权。
