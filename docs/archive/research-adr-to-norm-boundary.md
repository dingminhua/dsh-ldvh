# 调研：ADR 与「事实规范」的边界及 ADR→规范 的转向

> **性质**：**调研**，非候选。Human 于 2026-09-11 指示「这个问题专门搞个调研」。
> **问题**：ADR 是短小的决定，规范是系列的、专项的；ADR 之后可能会转向规范——这个转向如何界定与承载？
> **基准**：`f6efdad`。工作区干净。
> **方法**：以 `specs/22-ADR-决策.md`、`specs/00-理念与构成.md`、`specs/03-事实模型基础规范.md`、`specs/21-WorkCase-工作项.md` 原文为依据，逐条摘引并附行号。

## 一、Human 的判据（本调研的起点）

> 「ADR 是短小的决定，规范是系列的专项的，ADR 之后可能会转向规范」

拆成两条可检验的判据：

| 判据 | 内容 |
|---|---|
| **J1 粒度** | ADR 承载**单条**决定；规范承载**系列**的、**专项**的规则集合 |
| **J2 时序** | ADR 可能**前置于**规范，之后转向规范 |

## 二、22 号规范**已经承认**这一转向（原文证据）

### 2.1 承认识别：ADR 与规范源是两类承载

`22 §6.3`（第 99 行）明确把「已被完整承接进规范源的可强制执行规则的决策」列为**不属于 ADR 类型**：

> 已被完整承接进规范源的可强制执行规则的决策（**规则本身由规范源承载，ADR 可作为决策来源被引用但不再承担约束**）。

`22 §15` 红线（第 275 行）：

> 6. **不把 ADR 变成规则源**——决策被承接为可强制执行规则时由规范源承载（00 §3.3），ADR 保持记录身份。

**→ 即：22 号已经预设了「决策 → 规范」的承接关系，并承认 ADR 在此之后**不再承担约束**。**

### 2.2 但**没有**承载这一转向的机制 ← **这是缺口**

| 检查项 | 实际 | 行号 |
|---|---|---|
| `retirement_reason` 闭集 | `superseded` / `outdated` / `out-of-scope` —— **无「已转入规范」一项** | `22:127` |
| `superseded-by` 目标约束 | 「必须带 `superseded-by` 关系指向替代它的 **ADR**（该新 ADR 须已存在可解析）」—— **只能是 ADR** | `22:162` |
| 状态闭集 | 仅 `active` / `retired` 两值，「无第三个状态」 | `22:149` |
| 终态不重开 | 「决策要再变更时创建新 ADR」 | `22:170` |

**→ 冲突**：22 号**承认**「决策可被承接进规范源」，但其**状态机、终态理由闭集与关系闭集都无法表达这一事件**：

- 若该决策被完整承接后应 `retired` → **用哪个 `retirement_reason`？** 三个值都不准确（它既不是被新 ADR 替代，也不是环境变化失效，也不是范围不再属于本项目——它**被更完整的承载取代了**）
- 若想留一条「我转到哪份规范了」的链接 → **`superseded-by` 只能指向 ADR**，指向规范会被判为不可解析
- 若不 retired、保持 `active` → 则 ADR **继续承担约束**，与 §6.3「不再承担约束」**直接矛盾**，且造成**双重约束**（ADR 与规范同时约束同一事项）

**现状实证**：本仓库 `ldvh-base/adrs/` 仅 1 个实例，**无 retired 实例**——所以这个缺口**尚未被真实使用暴露**，是**潜在**而非已发生的问题。

## 三、与 00 的关系：00 支持什么、不支持什么

| 00 条文 | 内容 | 对本问题的作用 |
|---|---|---|
| §3.3:132 | 「事实规范承载管辖项目的规则，**以事实对象形态承载于事实源**」 | **支持**：事实规范与 ADR 同住事实源、同为事实对象 → 转向是**同域内的载体切换**，不是跨域搬迁 |
| §3.3:132 | 「规范源是可强制执行规则的来源，由元规范与事实规范两级承载」 | 规范源**只有两级** → 项目规范属**事实规范**，不构成第三级 |
| §3.2:128 | 「事实对象可以承载规范（事实规范），但事实不能反向创造或放松规则」 | **支持**：ADR（事实对象）的决策**可以**转为规范内容，但**不得反向放松** |
| §3.3:132 | 「AI 不得自行新增、改写或扩张可强制执行规则」 | **约束**：转向使规则取得约束力 → 必须经受控程序，不得由 AI 自动完成 |
| §3.6:152 | 「两级规范共用同一套受控建立程序」 | **约束**：转向的建立程序不得另设一套 |

**→ 00 不禁止、且其 §3.2/§3.3 在语义上支持该转向；但 00 未定义转向的机械形态。**

## 五、三种可能的界定（供裁定，非建议）

### 界定 A：**并列承载**（ADR 保持约束，规范并存）
- ADR 不 retired，规范另行建立
- ❌ **问题**：双重约束、双重权威，违反 `00 §3.6`「不构成第二套权威」

### 界定 B：**接管承载**（规范接管约束，ADR 转记录）
- 规范完整承载该规则后，ADR `retired`
- ✅ 与 `22 §6.3`「ADR 可作为决策来源被引用但**不再承担约束**」字面一致
- ⚠️ **需补**：`retirement_reason` 需有对应取值（如新增「已承接进规范」），或复用 `superseded` 但放宽 `superseded-by` 的目标域
- ⚠️ **需定**：「完整承载」的判据是什么（谁判、依什么核对）

### 界定 C：**部分承载**（ADR 保留未被承接的部分）
- 规范只承接了决策的一部分
- ⚠️ 粒度判据复杂，易造成「两条都管一半」的模糊地带

## 六、本调研识别的关键设计问题（不详答，属设计任务）

1. **转向的触发条件**：ADR 何时「应」转为规范？依 J1（粒度），可设想判据为「该决定的规则内容已从单条扩展为系列/专项」；但**判据需 Human 定**。
2. **转向的方向性**：`22 §6.3` 只写了「ADR → 规范源」。**反向**（规范缩回为单条 ADR）是否可能？未定义。
3. **链接的承载**：是否需要一条「该 ADR 的规则已由某规范承载」的指针？若要，**不能走 `relations`**（21 号先例：目标须可解析为事实对象 `object_uid`，而**元规范不是事实对象**）。可能的形态是普通标量字段（如 `norm_absorbed_by: <spec_key>`）。
4. **与 `norm_source` 的对称性**：事实规范侧已设计 `norm_source` 指向元规范成员。若 ADR 侧也需指向规范，**两者是否应统一形态**？
5. **约束力的交接时点**：转向过程中，何时 ADR 约束失效、规范约束生效？**是否存在两者皆有效的窗口**？（若存在，即双重约束）
6. **是否触及 00 §4.2**：若「转向」需要新的终态理由或新关系类型 → 属「改写可强制执行规则」或「重排事实模型」，**须 Human 决定**。

## 附录 B：前提更正 —— ADR 文本的时间语境（Human 纠正，2026-09-11）

> 本附录修正 §五/§六 的分析前提。Human 指出：**ADR 相关条文写作时，「元规范/事实规范」的说法尚不存在**。主控已用 git 史机械验证，**成立**。

**且当时的术语是单一「规范源」**：

- `53a8df1` 版 `00 §3.3` 首句：「规范源是可强制执行规则的**唯一内容来源**……」
- 现版 `00 §3.3` 首句：「规范源是可强制执行规则的来源，**由元规范与事实规范两级承载**……」

**→ 即：ADR 条文中的「规范源」指当时那个**未分级的单一概念**，而非今天的「元规范」或「事实规范」。**

### B.3 因此正确的读法

| 命题 | 成立性 |
|---|---|
| 「ADR ≠ 元规范」 | ✅ **成立**。ADR 是项目侧事实对象；元规范是 LDVH 自身机制规范，二者层级不同 |
| 「ADR = 事实规范」 | ❌ **不成立**（原 §二的分析前提有误）。按 Human 定义，**事实规范 = 成体系的规范**；ADR = **临时的、单条的决定** |
| 「ADR 的效力与规范同级」 | ✅ 成立（`22:23`「视同违背规范源」），但**同级指的是约束力性质，不是承载类型** |

**关键区分（Human 定义）**：

| | 事实规范 | ADR |
|---|---|---|
| 形态 | **成体系**的规范（系列的、专项的） | **单条**决定 |
| 性质 | 稳定规范 | **临时**决定 |
| 与元规范的关系 | 层级不同（项目 vs LDVH 自身） | 层级不同 |

### B.4 对 §二～§五 的更正

- §二识别的**机制缺口仍然成立**（`retirement_reason` 闭集无「转入规范」、`superseded-by` 只指向 ADR）——但**理由变了**：
  - 原分析：ADR 转入规范是「记录升格为规范」
  - **更正后**：ADR 转入事实规范是「**临时的单条决定**被**成体系的事实规范**取代」——**粒度与体系性的跃迁**，不是效力层级的跃迁
- §五的三种界定（A/B/C）**仍然适用**，但应改按「临时单条 → 成体系」的语义重新表述。

### B.5 撤回主控上一轮的推论

主控上一轮曾提出「事实规范本身即规范 → `00 §3.6`『不得放松元规范』还拦得住什么」。**该推论基于错误前提**（把 ADR 等同于事实规范）。**更正后**：

- 事实规范与元规范**层级不同**（项目侧 vs LDVH 自身），`00 §3.6`「事实规范不得放松元规范」**仍有明确对象**，不存在「拦不住」的问题。
- 因此主控上一轮提出的「机械落点是空的」**属误判**，予以撤回。

### B.6 残留不确定

- 「事实规范 = 成体系的规范」是 **Human 的定义**，**尚未写入任何规范文本**。是否需将其正式化（写入 00 或新规范），属待定。
- 「成体系」的**判据**（几个规则算成体系？如何机械或半机械判定？）**未定义** —— 这是新设计必须回答的问题。
