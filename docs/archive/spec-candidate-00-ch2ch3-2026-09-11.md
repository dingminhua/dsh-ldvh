#### 1.1.2 「等」为何必须保留（Human 2026-09-11 指示）

Human 指示：「**要有个等**」。**该指示有规范依据，且审核发现 7 的判断不成立**：

| | |
|---|---|
| **审核发现 7 的理由** | 「九项功能已**全部列举**，『等』无开放项可修饰，属冗余助词」 |
| **该理由的缺陷** | 它假定功能是**封闭集合**。但 Human 已明确：功能会增（系统数亦会变）；`§3.1:113` 制度定义本身即写「**开放集合**」 |
| **「等」的实际功能** | **标记功能为开放集合**——与**六系统的封闭承诺**形成对照 |

**关键区分（本句的立法意图）**：

| 平面 | 集合性质 | 「等」 |
|---|---|---|
| **六大业务系统** | **封闭**——`§3.1:111`「新增、删除业务系统…均须修改本规范，并按第四章取得 Human 决定」 | **无「等」** ✅ |
| **功能** | **开放**——可在下位规范细化与增补 | **有「等」** ✅ |

**→ 故本句「六大业务系统……提供……等功能兑现价值」中，「等」不仅不冗余，反而是唯一标记"功能开放、系统封闭"这一区分的语法手段。删除它会使功能被读作封闭集合，与 §3.1:111 只约束系统、不约束功能的设计相冲突。**

**处置**：**恢复「等」**；审核发现 7 **不予采纳**，其理由已在此说明。

#### 1.1.3 「功能」术语的最小界定（回应审核重要4）

审核指出：§2:77 的「功能」与 `00:239`「不因机制已设计、对象已积累或**功能已呈现**而推定成立」存在语义张力。

**处置**：在 §2:77 句内加**最小界定**（不作分类名、不新增术语定义）：

> - 以调研、讨论、工作执行、规则遵守、目标与蓝图、记忆与反思六大业务系统提供规划目标、校准蓝图、存取记忆、吸收调查、收敛讨论、执行工单、落实规则、沉淀事实、反思摩擦等功能兑现价值（**此处"功能"指业务系统对用户兑现的价值面，与 §6.3 所称「功能已呈现」的实现状态无关**）。

**理由**：`00:239` 禁的是「以**实现已存在**推定价值成立」；`§2:77` 讲的是「系统**提供什么**」。加括注**一次性切断误读**，且**不新增规范术语**（避免 v3 前身被推翻的"新平面"错误）。

> **待审核判断**：该括注是否为最小充分？抑或应改为改词（如「作用」）？
