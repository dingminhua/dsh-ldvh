## 1. 价值判断

Helper 的目标是让 AI 在确实需要 LDVH 已定义的确定性读取、机械检查或受控操作时，经一个可回指的 DSH 工具入口取得当次结果、范围、来源与缺口；它不是把普通求解、语义判断或 Human 决定改造成服务调用。

本文主要承接 00 的以下价值：

- **V1 快速定位**：公开操作声明和能力发现让 AI 定位当前已定义、已实现或当次可用的服务入口；服务目录本身不证明行动适用或允许。
- **V2 充分理解**：共同响应保留来源、作用范围、已完成与未完成范围，使读取结果能回到规则、事实或实际观察。
- **V3 边界识别**：区分公开声明、实现存在、当次可调用、机械结果、AI 语义判断与 Human 决定，不把它们互相替代。
- **V4 稳定推进**：同一工具面为既有行动模板的复用提供稳定入口，能力不可用或结果不完整时如实交还或按来源分流；模板复用依据的记录与证明由 04 承担，Helper 本身不证明复用已发生。
- **V5 据实判断**：响应不超出当次输入、实际观察与来源已定义的机械检查范围；工具成功不单独证明事实、授权、验证、完成或价值。
- **V6/V7**：机器可读范围、来源、缺口和继续入口与人类可读交还保持一致，帮助后续 AI 或 Human 据实接续。
- **HV2/HV3**：需要受控写入或授权匹配时，Helper 只执行来源已封闭定义的确定性部分，并保留实际变化与回读结果供核对。
- **V8/HV4/HV5**：持续积累、净效用与长期脉络的判定由 02 反思/沉淀维、03 事实模型、06 溯源和 10 呈现承接；Helper 作为读取、发现与受控变更回读的高保真管道，以保留来源标记和变更定位的方式支撑复用与演进脉络，但管道本身不单独宣称积累或效用成立。

Helper 存在、工具注册成功、操作被发现、请求返回或载体被写入，都不单独证明以上价值成立。价值须由真实使用、回读、风险匹配验证和后续交还共同核对。

## 3. 职责边界

### 3.1 本文负责

1. Helper 作为 DSH 原生工具直通服务的共同定位（形态见 §4）；
2. Helper 自治范围内领域公开操作的稳定身份、声明形状、may_change_state 标记与发现语义；
3. 最小共同请求和响应的语义、响应状态分类（partial/unavailable/rejected/invalid_request/执行错误）、来源与范围保留和缺口交还；
4. Helper 承载规范读取 L0–L4、事实召回 F0–F4、行动模板读取和事实预热时的共同传输与 envelope 契约；
5. 受控状态变更调用的共同传输边界：来源规则、当前范围、授权、实际变化与回读不可互相省略；
6. 共同反过度设计红线、验证边界、Human Gate 与 Stop Conditions 的承接。

### 3.2 本文不负责

1. 规范、附件、事实类型、事实字段、关系、状态、召回时机、证据充分性或领域操作的参数/结果 Schema；这些由 01、03、20–24 和各自来源承担；
2. 行动模板的触发、适用、风险路由、预检落实记录、步骤、完成门禁或降级；这些由 04、30–38 承担；
3. Git 提交候选机械预检、Git Gate、事实载体、提交消息或 trailer；这些由 06 承担；
4. 工作对象的管辖判定、插件装载、工具的实际注册、引导注入、Host 事件或 Hook 部署；这些由 07/08 承担；
5. Code 模块、工具 schema、缓存、索引、并发、日志、测试、错误栈或 Web 呈现；这些由 09/10 承担；
6. AI 对相关、适用、证据充分、行动允许或完成的语义判断，以及 Human 的取舍、授权、验收决定。

领域来源是操作语义的唯一权威；05 是 Helper 服务入口和共同 envelope 的权威；08 是 DSH 接入的权威；09 只能执行已经由来源封闭定义的机械规则。实现、缓存、工具描述、测试与 Web 不得反向创造第二规则源。

## 4. DSH 原生工具直通

### 4.1 服务形态

LDVH Helper 操作注册为 DSH 的原生工具，AI 经该工具直接调用。当前范围不要求另建 CLI、HTTP 网关、MCP server、RPC 中间层或把宿主工具再包装为文本命令；若未来需要其它传输形态，必须由相应环境或对外接口来源按 00 的范围纪律另行定义。

DSH 已可观察的 `ctx.tools.register` 是工具注册缝；这只证明宿主具备注册能力，不证明任何 LDVH 操作已经实现、装载、可用或通过验证。实际工具名称、输入 schema、注册时机、权限/沙箱配置、呈现和错误映射由 08/09 根据 DSH 当前版本核验并定义。

### 4.2 直通边界

1. 每个公开领域操作必须有唯一、稳定的 `operation_key`，但 `operation_key` 不等于 DSH 工具名称、文件路径、模块名、路由 URL 或权限；
2. 操作可以是只读或可能改变状态；“可能改变状态”只描述副作用风险，不证明请求已获授权或实际发生变化；
3. Helper 只承载来源已封闭定义的解析、定位、过滤、指纹、机械校验等确定性机制的调用，不自行定义 CAS、原子发布或提交语义（这些归 03/06）；不得自行推断领域语义、补造输入、扩张授权或替 Human 作决定；
4. 普通只读检查、普通求解和不依赖 LDVH 能力的业务编辑不因 05 存在而强制调用 Helper；具体来源将某操作列为不可替代前置条件时，其局部效力来自该来源。

## 5. 公开操作声明与能力发现

### 5.1 领域操作声明

05 定义公开操作的声明形状（本表）；承担某项领域操作语义的当前来源按此形状声明其公开操作，供能力发现定位。同一来源没有公开操作时不创建空表，声明的格式位置由该来源自行安排，05 只约束本表的字段与取值闭集，不强制其它规范的文件结构。

| operation_key | summary | effect | arguments_contract | result_contract |
|---|---|---|---|---|
| `<小写 ASCII kebab-case，全局唯一>` | `<操作提供什么服务，不声明可用或完成>` | `<read 或 may_change_state>` | `<本来源或其授权附件的唯一输入章节>` | `<本来源或其授权附件的唯一结果章节>` |

`operation_key` 只稳定识别服务行为，不能从名称推导适用、授权、实现、验证或完成。`arguments_contract` 和 `result_contract` 必须以 `<spec_key 或 attachment_key>::<精确标题文本>` 回指同一当前来源或其已授权附件中的唯一章节。解析失败、重复 key、来源未生效、输入/结果章节缺失或与声明不符时，必须暂停发现并按 00 §7.2 暂停调用。

05 只定义声明形状，不登记 01、03、04、06 或其它来源具体操作的字段。领域来源中的示例、内部函数、工具注册、测试、缓存或草案表格都不是公开声明。

### 5.2 能力发现

Helper 必须提供一个只读的能力发现入口，返回当前规则源可定位的公开操作及其来源、effect、所需输入类别、实现观察和未完成范围。发现至少区分：

- **已声明**：当前来源存在符合 §5.1 的操作声明；
- **已实现**：当前实际环境可定位对应实现；
- **当次可调用**：声明、实现、必要输入、工作对象、能力、来源要求与来源要求的授权范围均在当前请求范围内成立；
- **部分可调用**：独立子范围中可调用与不可调用范围可区分；
- **不可用**：没有实现、必要输入/能力/来源/授权前提缺失或零个请求子范围可调用。

以上是能力发现的 `availability` 描述，不是调用结果分类；发现入口可枚举全体操作或针对单一操作检查。每次调用的 `outcome` 仅使用 §7 的 `partial`、`unavailable`、`rejected`、`invalid_request` 或执行错误分类，两者不得混用。

未提供完整领域输入时，能力发现只能报告已声明/已实现与需要补充的输入，不能把未知写成不可用或可调用。当次可调用只证明 Helper 可以尝试按服务契约处理请求，不证明领域适用、Human 授权、技术验证或上层完成。

操作目录不是行动许可白名单：操作不存在、未实现、不可用或请求无效，只说明 Helper 无法按该操作承接请求；不自动禁止适用规则允许的普通求解或其它能力。反之，来源明确要求某操作且它不可用时，按该来源暂停、缩小或分流。

## 6. 最小共同请求语义

每次 Helper 调用都应由 DSH 工具输入承载以下最小语义；实际工具 schema 只登记当次操作确有需要的字段，不为对齐表格填充无关字段：

| 内容 | 用途与边界 |
|---|---|
| `operation_key` | 识别已声明的领域操作；服务级能力发现可不针对单一领域操作。 |
| `work_object_locators` | 需要项目或对象专属信息时提供原始定位符；不得由 Helper 以缓存、同名路径或默认工作区猜测未提供的对象。 |
| `arguments` | 由领域来源定义的结构化输入；自由文本不得绕过领域 Schema、来源条件或授权边界。 |
| `observed_context` | 操作确有需要的当次可观察环境、能力或签名输入；必须说明来源，不能成为稳定事实或替代回读。 |
| `authorization_reference` | 仅在领域来源要求授权时引用已存在的 Human 决定及其作用范围；不证明技术结果或自动扩权。 |

`responsibility_key` 是规范/附件读取操作的领域 `arguments` 字段，取值即目标 `spec_key` 或 `attachment_key`，与 01 §7 同义。01 定义 L0–L4 的读取层级、标题/行号定位与具体读取参数；05 只保证请求和响应不会改写该语义，不新增或重定义读取参数。

v5 不设 CLI 响应投影档位；共同请求字段是否裁剪、响应聚合或诊断档位是否需要，由 08/09 按 DSH 工具 schema 与实际消费定义，05 只定义其共同语义。

请求缺少必需输入、范围无法唯一定位、来源冲突或输入无法按操作契约解析时，Helper 必须在执行任何领域副作用前返回具体缺口或无效请求；不得静默从历史会话、缓存、猜测、环境变量或未声明的默认值补齐。

## 7. 最小共同响应语义

每次 Helper 响应必须同时提供机器可读结果和可供交还的摘要；两者不得矛盾。下表定义共同语义要求，最小字段闭集只在有实际实现与独立消费需要时由 05 授权附件或 09 登记。共同响应至少表达：

| 内容 | 要求与边界 |
|---|---|
| `operation_key` 与服务结果 | 回显服务发现或实际调用的标识和结果分类；无效标识的回显不使其成为公开操作。 |
| `result` | 仅由领域来源定义的结果；没有领域结果时明确为空，不在共同层伪造领域字段。 |
| `scope` | 明确请求、已完成和未完成的对象、页、检查或动作范围；“已完成”只表示本次服务处理范围，不表示上层任务完成。 |
| `sources` | 保留实际使用的规则、事实、Human 决定、配置、观察或实现依据及其可定位信息；不由 05 建立权威优先级。 |
| `gaps` 与未验证范围 | 明确缺失的输入、能力、来源、覆盖、实现或验证，而不是用空数组、工具成功或已完成子范围代表整体完成或验证通过。 |
| `changes` 与回读定位 | 可能变更状态的操作只报告实际发生的变化、实际定位与来源要求的回读；零写入、拒绝或失败不得伪称变化。 |
| `verification` | 只报告当次实际执行的机械检查、范围和结果；不把检查存在或通过写成领域语义、Human 决定、价值或整体完成。 |
| `follow_up` | 给出可继续读取、分页、回读、修复、分流或 Human 决定入口；没有可信入口时如实为空。 |

`partial`、`unavailable`、`rejected`、`invalid_request` 与执行错误必须可区分：

- `partial`：已实际完成独立子范围，但仍有明确未完成或未验证范围；
- `unavailable`：当前来源、实现、能力、环境、输入或授权前提不足，未能按请求范围提供服务；
- `rejected`：已形成足够输入，但来源已定义的机械条件、CAS、范围或权限检查拒绝操作；
- `invalid_request`：请求形状或共同/领域输入不能解析或不符合契约，领域副作用为零；
- 执行错误：服务开始后发生未由领域契约吸收的错误，必须报告实际已发生副作用与残留范围，不得暗示可无条件重试。

上述分类是 Helper 服务响应状态，区别于 03 §8.8 事实域的 `partial_scope` 交还形状；后者是否进入共同 envelope 字段闭集由 05 授权附件按 01 §9.2 登记，服务状态与领域结果不互相替代。

具体响应字段闭集、枚举、分页 cursor、编码与 DSH 工具 schema 只在有实际实现和独立消费需要时，通过 05 授权附件或 09 定义；在此之前不得用虚构的全局 DTO、日志、版本协议或错误码表填充本文。

## 8. 读取、预热与事实操作协作

### 8.1 规范和模板读取

Helper 在承载由 01 定义的规范读取领域操作（`read-specification-candidates` 与 `read-specification-content`）时，不改变其 L0–L2 与 L3/L4 分工，保留 01 定义的 `responsibility_key`、`heading_path`、`start_line`、`end_line` 与未展开范围；承载由 04 声明的模板候选与模板内容读取时，保留 04 定义的 `template_key` 与 `definition_ref` 定位，不把 01 的行号/标题路径套用到模板读取。二者都不让工具自动展开全部依据或把候选写成适用。

### 8.2 事实召回和预热

Helper 仅承载由 03 定义的 F0–F4 事实读取、草案、创建、更新、回读和完整性审计等领域操作的传输，不在 05 中自行定义或扩张其领域契约。F0–F2 候选、预热卡、分页结果或概率提示不得被写成 F3/F4 已读、事实适用、行动允许或事实声明。

在 03 的事实消费进入条件、具体类型来源的召回时机和 08 的宿主注入边界均成立时，Helper 可以交付带来源与指纹的候选、卡片或恢复入口。预热在传输与注入时的实质行为约束严格遵守 03 §7.2 的限制，Helper 仅提供传输载体；超预算、分页、不可用和未展开范围必须据实返回 partial/unavailable。

### 8.3 受控状态变更

可能变更状态的操作只能在领域来源已定义操作、实际范围、机械条件与授权要求均满足时执行。05 不自行定义事实创建、更新、删除或提交语义；这些语义分别由 03 和 06 定义，05 仅提供 `may_change_state` 标记和共同传输支持。

状态变更响应中的成功只证明实际服务结果和来源要求的回读/检查范围。若写后精确回读、已触发的完整性审计或其它来源要求未完成、partial、unavailable 或残留无法排除，必须停止受影响的后续写入、提交和成功声明，按 00 §7.2 与领域来源交还。

## 9. 反过度设计红线

1. 不要求每次普通求解、读文件、编辑或工具调用先经过能力发现、完整 envelope、事实召回、授权匹配或 Human Gate；只在实际来源和风险要求时调用相应机制。
2. 不以 Helper 建立全局事务、统一状态机、全量审计日志、跨环境消息总线、固定错误码宇宙或外部 API 网关。
3. 不把共同请求/响应字段扩张成领域字段仓库；具体字段只留在实际领域来源的 `arguments`/`result`。
4. 不把 DSH 工具注册、实现文件存在、schema 校验、返回成功、缓存命中或页面呈现当作规则适用、授权、验证、完成或价值成立。
5. 不把能力发现、公开操作目录或工具权限当作 AI 行动的许可白名单，也不以未匹配操作阻断普通求解。
6. 不要求 Helper 自动保存会话轨迹、推理过程或逐动作簿记；防自欺只保留来源要求的实际范围、变化、回读和机械检查锚点。

## 10. 验证与证据边界

| 验证对象 | 成立条件 | 可证明范围 | 不能单独证明 |
|---|---|---|---|
| 操作声明 | `operation_key`、effect 与输入/结果章节可唯一回指当前来源 | 公开服务身份与领域契约定位 | 已实现、当次可调用、适用或授权 |
| 工具注册 | DSH 当前环境已实际注册目标工具 | 当前宿主工具面可发现 | 操作领域语义、能力有效或完成 |
| 能力发现 | 来源、实现和当次前提按实际观察报告 | 当次发现范围与缺口 | 领域适用、Human 授权、技术验证 |
| 只读响应 | 读取范围、来源和未完成范围如实返回 | 当次读取/候选/披露范围 | 语义相关、适用、全文均已读取 |
| 状态变更响应 | 来源定义的前提、实际变化、回读与已触发检查均已完成 | 当次实际变化和机械结果 | 自然语言事实、Git 提交、Human 决定、上层完成或价值 |
| partial/unavailable 交还 | 已完成、未完成、未验证和残留范围可区分 | 当次服务所及与不及的明确边界 | 不存在风险、可无条件恢复 |

05 不建立价值审计报告或外部过程证明。Helper 共同响应是单次服务调用的机器可读结果，只交还当次已证实、未证实与残留风险；它是主控形成 00 §7.4 Output Envelope 的输入之一，不替代主控交还。共同响应附带的人类可读摘要必须与机器结果一致。

上表“成立条件”是机制的设计意图，其中“工具注册”“能力发现”的机械可判定性依赖 08/09 按 DSH 当前版本核验 DSH 工具 schema（具体协议名称由 08 核验登记）后成立；核验通过前，对应“成立条件”只代表来源要求，不当作已实现事实。每项机制必须能回答“防的是 AI 用哪种具体方式骗过自己”（dev-memo 决策 #10），答不出的不引入：

| 机制 | 对治根缺陷 | 防 AI 骗过自己的具体方式 |
|---|---|
| 能力发现与当次可用性 | 上下文依赖 | 防止 AI 在输入不全、实现缺失或环境未接入时，把“操作存在”脑补成“可调用可用”，或用缺失输入/能力去盲调用 |
| 共同请求/响应 envelope 与 gaps | 概率性输出 | 防止 AI 用空数组、局部成功、`{ok:true}` 或已完成子范围冒充整体完成或验证通过 |
| 受控状态变更与写后回读 | 概率性输出 | 防止 AI 把“写入接口返回成功”当成“载体已正确落盘且当前”，绕过精确回读与来源要求的完整性审计 |
| partial/unavailable 交还 | 无连续状态 | 防止 AI 把“没做完/没查到”吞成“已覆盖”或“无风险”，掩盖残留与未验证范围 |

## 11. Human Gate 与 Stop Conditions

本文不新增统一 Human Gate。以下事项按 00 §4.2 提请 Human：

1. 新增、删除、改名或重排 Helper 服务规范、公共服务形态或领域公开操作的编号/职责边界；
2. 改变 DSH 工具直通的效力边界、共同 envelope 的语义边界，或把新传输形态纳入当前范围；
3. 改变受控状态变更的授权、回读、机械拒绝或实际变化表达边界；
4. 领域来源与 05/08/09 的职责冲突且无法以来源回指收敛；
5. 修改 00 §4.3 所列受保护文档。

以下条目是 00 §7.2 在 Helper 服务域的具体化，不新增停止触发类型。出现以下任一情况，按 00 §7.2 暂停受影响的服务调用、状态变更或结果声明：操作来源缺失/冲突或无法唯一定位；请求范围、必需输入、实际能力或授权无法确认；准备把候选、注册、工具成功或部分结果写成适用、授权、完成或价值；已触发的回读、审计、验证或 Human Gate 未完成；当次请求实际超出来源已声明的操作前提或机械条件。暂停期间可做不越界的来源定位、只读核对、验证、修复和分流准备；恢复条件必须对应触发原因。

## 12. 起草验证清单

05 草案在进入 Human 审阅前至少检查：

1. 身份块、编号、`spec_key` 与 01 §6.1 一致，且不设生命周期 `status`；
2. DSH 原生工具直通是当前唯一服务形态，没有偷渡 CLI/HTTP/MCP/中间层要求；
3. 公开操作身份、能力发现和共同 envelope 不抢占 01/03/04/06 的领域语义；
4. L0–L4、F0–F4、模板读取、预热、partial/unavailable 和回读的来源指向与 01/03/04 一致；
5. 受控变更不以工具成功、声明存在或服务结果取代授权、回读、审计、验证或完成；
6. 能力发现不成为行动许可白名单，低风险普通求解不被默认升级为完整服务流程；
7. 共同响应可交还来源、范围、缺口和残留风险，但不建立外部审计账本或全局 DTO；
8. DSH 实际能力、计划中的实现和未验证能力清楚区分；DSH 工具 schema（具体协议名称由 08 核验登记）对共同请求/响应结构化字段的承载能力须由 08/09 按 DSH 当前版本核验，核验通过前字段级直通语义属于未验证范围，不得在实现中声明当次可调用；
9. 每项公共机制能说明服务的 V/HV 范围、机械证据、未验证范围与摩擦风险。
