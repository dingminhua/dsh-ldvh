# Report-报告



## 1. 价值判断

报告解决「已收敛的认识缺少跨行动稳定承载」的问题：一轮工作产生的调研发现、阶段性总结或独立审核结论，若只停留在会话、普通文档（`docs/`）或过时备忘，后续行动无法区分证据与推断、无法回指来源、无法判断结论当前性，导致重复调研、误用过时结论与把推断写成事实。通过统一身份、单文件载体（薄索引+报告正文）、三态证据与来源锚点、停止判据，使后续行动能够定位、核对、承接与追溯已收敛结论，减少重复劳动与依据漂移。**`docs/` 里的文档不因存在而取得事实效力**：它们可由 Human 择机要求 AI 汇总成报告（本条即该汇总的落点），一经形成报告即进入事实源与召回面。本规范主要服务核心价值三（经验与摩擦自动积累，00 §1.3）：三态证据（已证实／未证实／缺口）与来源闭环把一轮工作的认识固化为可回指、可复核、可复用的判据资产，使后续行动能区分证据与推断、定位原始来源，而不必重跑；兼服务核心价值二（任务高效准确完成，00 §1.2）：来源闭环提供收敛判据，使取证能在证据耗尽时以可验证信号停止，未证实范围与缺口显式可见。本文不以全量价值声明替代主要影响判断。

本规范只承载报告产物的事实模型；取证执行与进度由 33 承接，独立方案比较不迁入本类型、由方案收敛工作（主控本职，04 §6.1）与既有承载按 Human 决定另行处置，采纳决定由 22 承接，经验沉淀由 23 与 20 承接。三类来源形态的分工：调研型面向外部对象、要求外部 HTTP(S) 来源；总结型面向内部过程与阶段工作、内部来源以逐字摘录进正文承载；审核型承载一次独立审核或独立复核的完整结论报告，并沿用原 29 §6.4 的四项准入门槛（DevLog 类型已于 2026-11-14 撤除，该门槛随之迁入本条，见 §6）。证据充分性与来源真实性由 AI 依据本文核对，不由对象存在或机械通过证明。

身份可解析、载体通过机械校验、引用回指存在或关系声明成立，只证明当次载体与检查范围，不能单独证明来源真实、证据充分、结论当前、已获授权或工作完成。

## 3. 职责边界

### 3.1 本文负责

1. `report` 的类型语义、对象粒度、三种来源形态（`report_form`）的准入与排除边界；
2. 报告的当前权威载体（平铺单文件结构）、机器权威入口、frontmatter 字段闭集与按形态分叉的正文固定结构（含调研型专属的探索型可选 H2 与固定 H3）；
3. 三态证据（关键发现索引/uncertain/gaps）、来源锚点（外部与内部两种形态）与停止判据的结构和不变量；
4. 报告的状态闭集、生命周期转换与终态处置；
5. 报告的关系 key、召回时机与消费边界；
6. 报告类型特有的验证对象与类型退出条件。

### 3.2 本文不负责

1. 调研执行流程，包括入口澄清、检索方法、证据闭环过程与三层收敛、三态分拣，由 33 承接；
2. 调研问题是否成立、采纳哪种结论、是否据此行动以及相应授权，由 00 §3、22、21 与实际行动承接；
3. 外部来源真实性抽查、外部内容抓取、全文镜像、引用格式美化与真伪评分；
4. 内部方案、设计、架构的比较与取舍（v4 `technical_assessment`）——其迁移与落位归主控方案收敛本职（04 §6.1）与 22 号；**审核型报告（`report_form=audit`）的承载本身由本文负责**，其审核活动的执行过程、独立性判定与结论正确性不由本文负责（由 04 承接）；
5. 其它事实类型的语义、状态与 Schema；
6. LDVH CLI 请求/响应 envelope、Code 实现与测试、受控提交契约与 Git Gate、Web 呈现，分别由 05、06、09、07 承接；
7. 把调研结论直接写成规则、决定、授权或完成结论。

### 3.3 相邻规范分工与唯一权威

03 §9.4 是调研吸收系统职责的唯一权威；33 是调研流程规则的唯一权威；02 是事实公共模型与受控读写的唯一权威；20–23 与 25–27 是相邻事实类型的唯一权威；05 是 LDVH CLI 服务入口的唯一权威；06 是 Code 实现的唯一权威；09 是受控提交契约与 Git Gate 的唯一权威；07 是 Web 呈现的唯一权威；04 是检查机制（含审核活动的独立性与结论正确性）的唯一权威。本文只定义报告产物对象的类型语义，Code 只能执行本文与相邻规范已明确为机械规则的部分，不得由实现、测试、缓存或 Web 反向创造第二权威。

## 4. 适用范围

### 4.1 适用对象与场景

本规范适用于：

1. 管辖项目中已收敛并终止的一轮报告产物（按 `report_form` 为调研型／总结型／审核型之一）；
2. Human、AI、LDVH CLI、Code 与 Web 对该类型对象的共同消费边界。

本规范用于报告的准入、创建、定位、引用、验证、召回、更新与处置，以及三态证据与来源锚点对判断依据的核对和承接。

### 4.2 明确排除与证明边界

外部对象指技术、工具、项目或实践；独立方案比较（v4 `technical_assessment`）不迁入本类型，其承载由方案收敛工作（04 §6.1）与 22 号处置。进行中的工作保持在当次会话上下文，采纳决定由 22 承接，失败经验由 23 承接，议题由 20 承接。临时搜索结果、裸链接清单、聊天摘要、运行日志、一次性笔记和普通目录下的备忘不自动成为事实对象。

**`docs/` 下的文档不构成报告，也不被事实对象引用**：它们可以由 Human 择机要求 AI 汇总成报告（此时内容须**逐字摘录进报告正文**，`docs/` 路径不得作为来源定位——见 §10.2），汇总前不取得事实效力、不进入召回面。事实对象之间只相互引用，不引用 `docs/` 下的文档（09 §5.3 第 5 项、Human 2026-11-14 决定）。

对象符合本文结构或通过机械校验，只证明当次载体和字段范围，不单独证明来源真实、证据充分、结论当前、已获授权或已完成。

## 5. 类型定位与价值

### 事实类型声明

| fact_type_key | summary | definition_ref |
|---|---|---|
| `report` | 已收敛并终止的一轮认识产物（外部调研、内部阶段性总结或独立审核的完整结论），形成可回指的来源锚点与三态证据，按 `report_form` 分为调研／总结／审核三种来源形态 | `report-fact-type::5. 类型定位与价值` |

报告是调研吸收业务系统（00 §2.6、03 §9.4、33）的产物类型：主控围绕一个已收敛的问题搜集成因并形成判断，直到停止判据成立，再经受控创建对象化。进行中的搜索、阅读、实验与工作过程不产生对象；只有已终止、问题明确、来源可回指且结论具有跨行动引用或复读价值的一轮产物才形成报告。

### 三种来源形态（`report_form`）

三种形态共用一个类型、一套身份与状态、一张载体，差异只在**来源面**、**必填字段**与**正文骨架**：

| `report_form` | 来源面 | 回答什么 | 关键必填 |
|---|---|---|---|
| `research`（调研型） | 外部对象：技术、工具、项目、实践 | 「这个东西是什么、怎么用、边界在哪」，并给出对本项目的帮助与启发 | `urls` 必填（外部 HTTP(S) 来源证明）、`research_question`、`research_purpose`、三态 |
| `summary`（总结型） | 内部过程：已完成的工作阶段、既有载体、运行记录 | 「这一阶段做成了什么、结论是什么、遗留什么」 | 正文证据摘录段 + 内部来源锚点（§10.2）；`research_question` 可缺省 |
| `audit`（审核型） | 一次独立审核或独立复核活动 | 「这次审核发现了什么、未覆盖什么、保证边界是什么」 | 四项准入门槛（§6.3）+ 内部来源锚点（§10.2） |

**形态由创建时一轮产物的实际来源面决定**，一经创建不可变更（变更形态即「另一类认识」，须新建对象并把旧对象按 §9 处置），由 `report_form` 字段机械固化。不单设子类型字段，避免字段与正文结构形成第二权威。

### 调研型的两种子阶段（仅 `report_form=research`）

- **明确方向型调研（directed）**：调研问题与对象边界在启动时已明确，无需先行的调查阶段，直接进入证据搜集与分析；
- **探索型调研（exploratory）**：对象、问题或范围在启动时不明确，先进行调查阶段（检索、试运行、范围澄清）形成调查正文，再进入分析阶段产出最终结论。

两种子阶段都是一轮调研的产物，共用同一对象边界、字段契约、三态证据、来源锚点与状态语义；差异只体现在调查阶段是否先行，且该差异只由同一单文件正文内的 `调查阶段` H2 承载（探索型该 H2 必在、明确方向型必无），不产生第二个 md 文件。子阶段由创建时一轮调研的实际形态决定，并经正文 `调查阶段` H2 的存在性机械固化（探索型必在、明确方向型必无），不单设 stage 字段，避免字段与正文结构形成第二权威。**子阶段只属调研型**：总结型与审核型禁含 `调查阶段` H2（见 §7 正文骨架）。

### 与 v4 Study 的迁移边界

报告与 v4 Study 的关系以语义收窄重定：v4 `report_kind=external_research` 对象（28 份）与 docs/ 既有调研备忘迁入本类型的调研型；v4 `technical_assessment`（内部方案比较）不迁入本类型（由方案收敛工作处置）；v4 `internal_audit`（内部审计）的**完整结论报告**自本条起由审核型承载——该项是 Human 2026-11-14 的决定带来的承载位变化，此前该内容按 02 §6.4 落判据 9「不承载」；v4 Study 类型名废弃、不设单独类型规范，v4 归属只作迁移输入。报告与相邻类型的分工以对象与问题为本：调研型面向外部对象的"是什么、怎么用、边界在哪"；总结型面向内部过程的阶段结论；审核型面向一次审核活动的完整结论；独立方案比较属方案收敛工作（主控本职，04 §6.1）的产物范围，不因 v4 中同属 Study 文件而与报告混同。

普通文件或会话无法无损承载报告的身份、状态、单文件内固定 H2/H3 结构、三态结构与来源锚点的机器消费，这是本类型独立对象化的准入门槛。

## 6. 对象边界

一个报告对象承载**一轮已收敛并终止的认识产物** + 一个问题陈述 + 证据与来源锚点 + 一个正文单文件（frontmatter 薄索引 + 按形态分叉的固定 H2 正文）。三形态共用下列**公共准入条件**（6.0），各自再叠加形态专属条件（6.1–6.3）。

### 6.0 公共准入条件（三形态均须同时满足）

1. **已收敛并终止**：有据实的停止依据（`stopping_reason`），不是进行中的搜索、阅读、实验或工作过程；
2. **一个问题**：能够用一句 `title` 之外的 `research_question` 或其等价表述界定「这一轮回答了什么」；一个对象不承载多个不统属的问题（必须拆分）；
3. **证据可回指**：已形成关键发现单元（声明 + 浓缩观察 + 价值判断 + 来源锚点），锚点能重新定位到实际来源；
4. **有现实承接价值**：结论具有跨行动引用、复读或后续承接的现实价值；
5. **查重已完成**：已召回相邻报告与既有事实类型、规范和普通文档，没有可无损更新或自然承载的位置；
6. **不属排除面**（见本节末）。

### 6.1 调研型专属条件（`report_form=research`）

1. 调研对象是**外部**技术、工具、项目或实践，可被至少一项长期可复核的**外部 HTTP(S) 资料**定位；
2. 问题属于「是什么、怎么用、边界在哪」，能够用一句 `research_question` 明确表述；探索型允许调查阶段先收敛问题与范围，收敛后的最终问题仍须单句可表述；
3. 已形成三态索引（`confirmed_statements`／`uncertain`／`gaps`）；
4. 每个关键发现单元的锚点回指 `urls[].ref`（§10.1）；
5. v4 `external_research` 对象与 docs/ 既有调研备忘作为迁移输入，逐份重新满足本节全部条件，不得批量导入或按旧 shape 赋予当前性。

### 6.2 总结型专属条件（`report_form=summary`）

1. 对象是**内部过程**：已完成的工作阶段、既有载体状态或运行记录，不调查外部世界；
2. 正文必须含**逐字摘录的证据段**——内部来源的内容以摘录形式进入正文，不以指针代替（§10.2）；
3. 内部来源锚点符合 §10.2 的形态与纪律（**禁止以 `docs/` 路径作定位**）；
4. 总结的范围与停止点可界定：写明本总结覆盖哪一段工作、起止依据是什么。

### 6.3 审核型专属条件（`report_form=audit`）——四项准入门槛

本节承接原 29 号 §6.4 的四项准入条件（DevLog 类型于 2026-11-14 撤除，该门槛随之迁入本条，**不是新建门槛**）：

1. **报告正文完整可得**：既有三方结论（对象恰当性／方案可行性／scope 清晰度）、或复核的判据七要素、或规范变更独立审核的七维结论（01 §12.3），连同证据性发现、未覆盖范围与保证边界均**实际在正文内**。**只保留概要而完整正文已不可得的，不构成准入**——此时建出的对象证明不了审核做过什么。该情形如实登记为缺口（按 04 §8 保留为 `gaps` 并在交还中披露），不建对象。
2. **粒度是「一次审核 = 一条」**：以被审事项为单位，一份报告一个对象，不按发现逐条拆分；同一次审核的多轮共享一份报告、一个对象，轮次记账随当次交还正文呈现。
3. **对象是被审候选的结论，不是审核流程**：对象承载「这次审核发现了什么、未覆盖什么、保证边界是什么」；审核的开销、轮次、工具调用与执行流水不构成本类型；后者归当次交还正文与会话记录。
4. **来源交代写在正文「被审对象与背景」段**：须写明被审对象的标识（规范载体与节号或候选指纹）、该报告属于哪一轴与审核者来源形态。**这不是可解析指针**（§10.2），源报告删除后仍可被 Human 复核其出处。

**两轴的形式权威不同，不得互相援引**（01 §12.2 明文禁止跨轴借用）：审核轴（建前审核、规范变更的独立审核）来源形态按 01 §12.2 的审核轴要求；复核轴按其自身要求。本类型只承载两端产物，不重新定义两轴。

### 6.4 查重规则

同一问题与同一来源面指同一对象；补充资料或刷新观察且主要结论不变的**更新原对象**；问题实质变化、或来源面发生足以改变结论的重大变化时**新建对象**，旧对象按 §9 处置。

### 6.5 不得形成报告的内容

进行中的调研或工作；独立方案、设计或架构比较（v4 `technical_assessment`，不迁入本类型，属方案收敛本职）；决定（22）；失败经验（23）；议题（20）；规范约束（27）；含执行计划或验收的任务（由主控在当次行动中承接，不对象化）；临时搜索结果、裸链接清单、聊天摘要、运行日志与一次性笔记；`docs/` 或普通目录下的备忘本身（可被汇总成报告，但备忘不是报告）；一个对象承载多个不统属同一问题的内容。普通文件能够无损承载且不需要身份、状态与来源锚点的摘要，不创建报告。

## 7. 身份与载体

`fact_type_key` 固定为 `report`。对象身份与公共字段语义按 02 §7.1 承接。

正文结构的公共契约（H1 恰好一个且由 Code 从标题生成、正文自 H2 起）按 02 §7.3 承接；本节只定义本类型的 H2 骨架，不重述该层。

载体是**一个平铺单文件**（一对象一文件承载；02 §7.2 点 2 允许类型定义载体格式、目录与文件承载方式）：对象文件为事实源根目录（`ldvh-base/`）下 `reports/` 类型目录中的 `reports/report-<uid>.md`，其中 `<uid>` 为 `object_uid` 的规范文本表示（编码规则由 05/06 承接）；文件头为 YAML frontmatter（02 §7.1 公共字段与本文 §8 专属字段），其后为 markdown 正文。事实对象使用 frontmatter 而非规范的 ```yaml 代码块身份块，是有意的形态区分：规范的代码块身份块是文档自描述内容、读者需要看到；事实对象的 frontmatter 是机器索引层、对读者隐藏是设计意图（markdown 预览器不渲染 frontmatter 即符合预期）。事实源根目录与工作树整体布局、路径安全和符号链接规则由 06 承接，02 不建立第二套检查器。旧对象标识（v4 `object_id`）只作迁移输入，不进入 canonical 对象、关系目标或 CAS 身份（02 §7.2）。

该单文件是对象唯一当前权威载体（02 §7.2 点 1）与机器权威入口：F1/F2 卡片、索引、Web 视图与 LDVH CLI 响应均以它为入口，且均为派生结果。

frontmatter 的规范阅读序如下（Human 决定；展示层约定，字段闭集不变，本条只定顺序、不构成书写强制）：`title`、`status`、`report_form`、`research_question`、`research_purpose`、`stopping_reason`、`confirmed_statements`、`uncertain`、`gaps`、`clarification_log`、`implications`、`retirement_reason`、`retired_at`、`urls`、`relations`、`object_uid`、`fact_type_key`、`created_at`、`change_log`——语义块在前（标题与状态为扫读入口，研究三要素继之，三态证据与澄清启发随之，退出语义次之），引用（urls/relations）与身份（uid/类型/创建时间）居后，流水（`change_log`）沉底。该顺序是**展示层约定而非语义，也不约束写入**——YAML 映射本身无序，写入方按任意顺序书写均合规，消费方不得依赖字段顺序；任何呈现 frontmatter 的表面（阅读布局、文档、工具展示）可按此序排序呈现，读取端不因顺序校验或拒绝消费；未在列表中的条件字段按其逻辑位跳过。

`content_fingerprint` 绑定该文件的规范化内容：文件任何变化都改变指纹，读取、更新与回读以整个文件为边界；算法、编码与共同响应字段由 05/06 承接（02 §7.1），02 不建立第二套检查器。

正文 H2 骨架**按 `report_form` 三分叉**，互不通用（形态与骨架的一致性是机械校验项，§13）：

- **调研型（`research`）**：下表 7 个 H2（其中 `调查阶段` 为探索型专属可选）；
- **总结型（`summary`）**：`范围与目的`／`工作与结论`／`证据摘录`／`遗留与下一步`（4 个，顺序固定）；
- **审核型（`audit`）**：`被审对象与背景`／`审核结论`／`证据性发现`／`未覆盖范围与保证边界`／`后续处置`（5 个，顺序固定）。

以下为**调研型**的 7 个固定 H2（总结型与审核型见本节末两表），按顺序各出现且只出现一次，其中 **`调查阶段` 为探索型专属的可选 H2**（明确方向型禁在、探索型必在）：

| 固定 H2 | 出现条件 | 必须承载的阅读单元 | 不得退化为 |
|---|---|---|---|
| `研究问题` | 必在 | 展开 `research_question` 与 `research_purpose`：调研的外部对象、要回答的问题、支撑的项目判断；探索型说明与调查阶段的收敛关系 | 只重述标题、搜索关键词或 Human 原话 |
| `输入与边界` | 必在 | 实际读取的外部来源如何分工（每项 `urls` 的用途或限制）、观察时点与版本、分析方法（静态分析、文档阅读、试运行等）、不覆盖范围与来源冲突；探索型说明分析如何承接调查阶段 | 只复制 URL 列表，或用无法重新定位的模糊说明代替来源 |
| `调查阶段` | 探索型必在、明确方向型禁在 | 调查阶段的完整正文，内含四个固定 H3（见下表）；无 frontmatter 语义、不承载任何字段 | 复制"研究问题"、搜索关键词或流水账 |
| `关键发现` | 必在 | 一个或多个可独立讨论的发现单元（每个 H3 一单元）：声明 + 浓缩观察事实（2-5 行，从来源提取的机制/数据/行为描述，可含关键细节）+ **对 LDVH/管辖项目的价值判断**（同源性/模式/边界/吸收与否）；每单元末尾一行溯源锚点（格式：`溯源：<urls 内的 ref>（<锚点>）`），供需要时回查原文 | 一段压缩结论、纯摘录堆砌（观察不成形）、无判断只有描述、把推断写成已证实、缺溯源锚点 |
| `未证实与缺口` | 必在 | 逐项展开 `uncertain` 与 `gaps`：疑点与原因、缺口描述与优先级、对判断的阻塞范围 | 堆砌免责声明或省略真实缺口 |
| `建议` | 必在 | 一个或多个具体建议或取舍，说明适用条件、风险或不成立边界。每个建议必须具体到可被 ADR 或相应事实类型直接承接：至少说明目标对象类型、预期目标、验收条件和创建/更新判断；如认为无需对象化，必须写明判断依据和后续监测条件。建议不是决定——采纳与否由 22/主控方案收敛（04 §6.1）与 Human 裁决 | 为填满模板虚构每一类建议、把建议伪装成已决定行动、或只写"待决定"占位 |
| `后续分流` | 必在 | 每项建议/未决问题的后续承载方向，或为何无需对象化；每个分流项必须包含判断标准：什么信号出现时应该创建/更新哪个对象类型，以及什么条件下可以继续无需对象化 | 只写"后续再看"、无条件地创建 Spark、或暗示下游对象已经建立 |

`调查阶段` H2 内部必须按顺序各出现且只出现一次以下非空 H3：

| 固定 H3 | 必须承载的阅读单元 | 不得退化为 |
|---|---|---|
| `调查问题与范围` | 展开调查阶段要澄清的问题、对象范围与优先级，以及向 `research_question` 收敛的过程 | 复制"调研问题"段、搜索关键词或流水账 |
| `调查方法与来源` | 调查阶段实际读取的外部来源如何分工（每项 `urls` 的用途或限制）、观察时点与版本、调查方法（检索、试运行、实验等）、不覆盖范围与来源冲突 | 只复制 URL 列表，或用无法重新定位的模糊说明代替来源 |
| `调查发现` | 展开调查阶段形成的初步三态发现：已核实条目、疑点与空白及其依据；与 frontmatter 的最终三态一致或如实标注差异 | 一段压缩结论、无摘录的断言、把推断写成发现 |
| `调查停止与交接` | 说明调查阶段停止的依据（与 30 收敛判据对齐）、未覆盖范围、向分析阶段交接的未决项 | 占位语或无依据的停止声明 |

子阶段由 `调查阶段` H2 的存在性机械固化：正文含该 H2 即探索型，不含即明确方向型；不设 stage 字段，H2 存在性是子阶段的唯一权威。

#### 总结型（`report_form=summary`）固定 H2

按顺序各出现且只出现一次，四个均必在，**禁含 `调查阶段` H2**：

| 固定 H2 | 必须承载的阅读单元 | 不得退化为 |
|---|---|---|
| `范围与目的` | 本总结覆盖哪一段工作、起止依据是什么、为回答什么问题而写 | 只写「本阶段工作总结」这类空话 |
| `工作与结论` | 这一阶段实际做成了什么、形成的结论是什么、依据哪些载体或运行记录 | 罗列动作清单而无结论、把计划写成已完成 |
| `证据摘录` | 支撑上述结论的内部来源内容**逐字摘录**，每条附内部来源锚点（§10.2），并注明该内容支持哪条结论 | 只写「见某某文档」而无摘录、把 docs 路径当定位 |
| `遗留与下一步` | 未完成、未证实、待决的事项，以及后续承接方向与判断信号 | 只写「继续推进」、把遗留写成已解决 |

#### 审核型（`report_form=audit`）固定 H2

按顺序各出现且只出现一次，五个均必在，**禁含 `调查阶段` H2**：

| 固定 H2 | 必须承载的阅读单元 | 不得退化为 |
|---|---|---|
| `被审对象与背景` | 被审对象的标识（规范载体与节号或候选指纹）、该报告属于哪一轴、审核者来源形态（§6.3 第 4 项） | 只写「本次审核了某方案」而无标识 |
| `审核结论` | 该候选是否可进入下一步的整体判断，及其依据的结论要点 | 只给结论不给依据、或只罗列发现而无整体判断 |
| `证据性发现` | 逐条发现：现象 + 证据 + 影响判定，附内部来源锚点（§10.2） | 无证据的断言、把猜测写成发现 |
| `未覆盖范围与保证边界` | 本次审核没查什么、查到的能保证到什么程度、哪些结论不成立 | 用「已全面审核」类措辞掩盖未覆盖 |
| `后续处置` | 各发现的处置方向与责任归属（修复／接受／升级），以及复审触发条件 | 只写「待处理」、把处置伪装成已完成 |

**审核型的四项准入门槛见 §6.3**；本表只定义正文骨架，不重复门槛判据。**只保留概要而完整正文不可得的，不构成本形态的合法对象**（§6.3 第 1 项），该情形如实登记为缺口，不建对象。

frontmatter 是三态与引用的机器权威，任何正文只可展开、不得改变或弱化 frontmatter 语义；`调查阶段` 正文不得承载本文或 02 §7.1 之外的字段，也不得以调查过程的叙述冒充最终三态。

## 8. 字段契约

公共字段使用绑定如下，公共语义按 02 §7.1 承接，本文只声明采用范围：`object_uid` 必填、`fact_type_key` 必填、`title` 必填、`created_at` 必填、`status` 必填（状态语义见 §9）、**`urls` 条件必填（仅 `report_form=research` 时必填且至少一项，作外部来源证明；`summary`／`audit` 两类禁填——内部来源不走 `urls`，见 §10.2）**、`relations` 条件（§11）、`change_log` 条件（对允许受控修改的对象，首次修改后必有，按 02 §7.1 承载；本文的报告允许受控修改）。

**`urls` 为何改条件必填**：02 §7.1 明文 `urls`「只承载具有长期消费价值的外部 HTTP(S) 资料；不得用本机路径、日志、会话或 Git 定位符替代」。总结型与审核型的来源是项目内部过程，没有外部 HTTP(S) 资料可填；若仍要求 `urls` 必填，唯一后果是迫使写作者把本机路径塞进 `urls`，那正是 02 §7.1 禁止的语义误用。故按形态分叉，而非放宽 `urls` 的语义。

`urls` 成员使用 `{ ref, title, summary }`：`ref` 是绝对 HTTP(S) URL 且必填并全局唯一于本对象；`title` 与 `summary` 条件出现，其中 `summary` 说明该资料对本次调研支持什么、未支持什么或具有什么限制；被溯源锚点引用的 `urls` 项必须提供 `title` 以便识别资料。

类型专属字段定义如下，`field_path` 为 frontmatter 中实际路径。设计原则：**frontmatter 是薄索引层，正文是研究主体**——frontmatter 只承载机器索引（声明列表、状态、关系、流水），证据的完整叙述（观察事实、价值判断、溯源锚点）在正文"关键发现"段承载；frontmatter 目标行数与正文相比应显著少于一比一。

| field_key | field_path | JSON 类型 | meaning | not_meaning | constraints |
|---|---|---|---|---|---|
| `report-form` | `report_form` | string | 本报告的来源形态：`research`（对外部对象取证）／`summary`（对内部过程的阶段性总结）／`audit`（一次独立审核或独立复核的完整结论报告） | 不是子阶段（子阶段只属调研型、由 `调查阶段` H2 承载）、不是优先级或分类标签；不表示质量或权威程度 | **必填**；闭集三值；创建后**不可变更**（变更形态即另一类认识，须新建对象并按 §9 处置旧对象）；决定正文骨架与哪些字段必填（§8 不变量 12）；**存量兼容**：既有对象缺该字段时读路径按 `research` 判、写路径仅在新设或显式变更时必填（迁移批次完成时转为全量必填，见 §8.2） |
| `research-question` | `research_question` | string | 本调研实际回答的一个以外部对象为主体、可独立复读的问题（探索型为调查收敛后的最终问题） | 不是 Human 原话、搜索关键词、执行目标或决定问题 | **条件必填**（仅 `report_form=research` 时必填非空；`summary`／`audit` 可缺省）；本字段是问题的唯一权威文本，正文"研究问题"段必须逐字包含本字段原文（不变量 10，机械校验），除此之外可展开；实质变化时新建对象 |
| `research-purpose` | `research_purpose` | string | 本次调研将支撑的当前项目判断（选型、接入、取舍、风险识别等）及为何需要这轮调研 | 不表示已经决定、已获授权或结论已采纳 | **条件必填**（仅 `report_form=research` 时必填非空）；与 `research_question` 分工 |
| `stopping-reason` | `stopping_reason` | string | 本轮调研的停止原因 | 不表示证据充分、结论正确或调研成功 | 必填；闭集 `sufficient`/`no-gain`/`round-cap`；与三态一致性见本条不变量 |

| `research-clarification-log` | `clarification_log` | array | 已经改变调研问题、对象边界或证据解读的实质澄清记录 | 不是聊天日志 | 条件；成员必填 `question`、`answer`、`answered_by`（闭集 `human`/`external`/`ai`） |
| `research-implications` | `implications` | array | 调研结论对管辖项目的帮助与启发：每个 confirmed 发现对 `research_purpose` 所述项目判断的支持、限制或修正 | 不表示已采纳、已决定或已授权行动 | 条件；成员必填 `finding_ref`（逐字等于某条 `confirmed_statements[]` 成员）、`implication` |
| `serves` | `serves` | string | 本报告服务于哪一条 SubGoal——目标锚定的登记位 | 不表示该报告确实推进了该子目标、不表示锚定正确、不构成达成证据 | 可选；取值须为 canonical UUIDv4 并解析到同项目内 `active` 或 `achieved` 的 SubGoal 对象（28 §12.3）；创建与更新时机械校验解析，解析失败零写入拒绝；仅在「新设」或「取值变更」时重解析；缺失时该报告在目标层不可见，呈现层须说明「未锚定」（24 §8.1） |
| `retirement-reason` | `retirement_reason` | string | 退出当前调研入口的原因语义标签 | 不表示对象删除或来源失效 | `status=retired` 时必填；闭集 `outdated`（外部资料过时/失效）/`superseded`（被新调研更新）/`out-of-scope`（调研范围不再相关）/`rejected`（本对象自始为工具端到端验证等非业务承载）；`status=active` 时禁填 |
| `retired-at` | `retired_at` | string | 对象进入 retired 状态的精确时间戳 | 不表示创建时间或最后修改时间 | `status=retired` 时必填；ISO 8601 格式；由 Code 托管，AI 不得提供或覆盖；`status=active` 时禁填 |

字段间不变量：

1. 三态至少一项成立：`confirmed_statements`、`uncertain`、`gaps` 三者至少出现其一，不出现时整体省略；
2. 溯源锚点不变量：正文"关键发现"段每个发现单元必须以一行 `溯源：<ref>（<锚点>）` 结尾，`<ref>` 逐字等于某条 `urls[].ref`——证据不悬空，但摘录本身留在来源处不复制进对象（需要核对时按锚点回查）；
3. 停止一致性：`stopping_reason=sufficient` 时 `confirmed_statements` 必填非空且不存在阻塞 `research_purpose` 结论的 `high` 优先级缺口；`stopping_reason=round-cap` 时必须在 `gaps` 或正文"后续分流"中声明未覆盖范围；
4. 生命周期约束：`status=retired` 时禁止新增或实质修改发现单元，只允许配套更正或退出说明的更新——**该许可的受控入口是 §13 的「终态事实更正」**（`correct`）：正文与 §13 白名单五项可改，`status`/`retirement_reason`/`retired_at`/`urls`/`research_purpose`/`stopping_reason` 与子阶段逐字继承；「实质修改发现单元」仍被禁止——更正只能修正错述，不变量 7 要求声明与正文 H3 标题逐字对应，改一条须两层同改；
5. 未知字段处理：frontmatter 出现本文与 02 §7.1 之外字段时，该对象不得作为报告消费，直到完成字段准入或修正；
6. 载体一致性：`调查阶段` H2 存在性与子阶段一致（探索型必在、明确方向型禁在），frontmatter 只在文件头部，`调查阶段` H3 正文不承载字段、不得改变或弱化 frontmatter 语义；
7. 索引一致不变量：每条 `confirmed_statements[]` 成员必须逐字等于正文某个发现单元的声明句——索引不悬空，每条机器索引都能在正文定位到完整叙述；
8. 启发锚定不变量：每条 `implications[].finding_ref` 必须逐字等于某条 `confirmed_statements[]` 成员——启发不悬空，每条项目含义都锚定到具体已证实发现。
9. 退出完整性不变量：`status=retired` 时 frontmatter 必填 `retirement_reason`（闭集）且 `retired_at`（ISO 8601）由 Code 托管；`retirement_reason=superseded` 时 frontmatter `relations[]` 必含一条 `updates` 关系指向可解析的替代报告；`status=active` 时 frontmatter 禁填 `retirement_reason` 与 `retired_at`；不变量违规时该对象不得作为当前报告消费（24 §15）。
10. 问题原文不变量：正文"研究问题"段必须逐字包含 frontmatter `research_question` 的完整原文——frontmatter 是问题的唯一权威文本，正文只可在原文之外展开背景、对象与边界，不得改写、删减或换述问题本身；创建与更新时机械校验（24 §13），违规拒绝写入。目的：frontmatter（机器索引层）与正文（研究主体）各自服务不同读取面，同一问题在两处出现时必须由机械校验锁死为同一文本，防止两处各自演化形成第二事实源。

11. 目标锚定不变量：`serves` 出现时必须解析到同项目内 `active` 或 `achieved` 的 SubGoal 对象；解析失败拒绝写入（02 §7.1 关联引用型形态的机械口径）。本字段只登记「本调研声称服务于哪条子目标」，**不证明该调研确实推进了它**——后者只能由子目标的达成证据与 Human 判断检验（28 §6.3）。目标与子目标侧不存储反向边，「哪些调研服务于这条子目标」由机械反查本字段得到（25 §11、28 §8.1）。

12. 形态一致性不变量：`report_form` 的值与正文骨架、必填字段面必须一致——`research` ⇒ 正文含调研型 7 个 H2（探索型还须含 `调查阶段` 及其 4 个 H3）且 `urls`、`research_question`、`research_purpose` 必填；`summary` ⇒ 正文含总结型 4 个 H2 且禁含 `调查阶段`、`urls` 禁填；`audit` ⇒ 正文含审核型 5 个 H2 且禁含 `调查阶段`、`urls` 禁填、并满足 §6.3 四项准入。违反任一项时拒绝写入（§13）。

### 8.1 目标锚定的采用面与存量兼容

**采用面**：`serves` 与 Spark（20 号）采用同一字段名与同一解析口径（28 §12.3），指向 SubGoal 的 `object_uid`；本类型不另立字段名，也不改变该字段在其它类型中的语义。原另一采用方 DevLog（29 号）已于 2026-11-14 撤除，采用面据此收窄，既有报告对象的 `serves` 不受影响。

**存量兼容**：本字段为可选字段。既有报告对象不含 `serves` 时**不因此失效**，也不要求迁移——其 `status`、`urls`、三态字段与引用闭环的效力均不变。缺失只影响目标层的可反查性。

**缺失时的呈现义务**：无 `serves` 的报告在 Web 呈现与召回结果中须显式标注「未锚定」，使读者能区分「已挂到子目标」与「尚未挂」；不得因收录而默示其已锚定（07 §承接呈现，本节只声明义务的存在与不满足的边界）。

**不构成质量背书**：本字段存在、且能解析，只证明「该调研声称服务于某条子目标」这一登记事实；不证明调研充分、结论正确或该子目标确实被推进——这些属 §15 验证与本类型价值成立的范围，不由本字段承担。

### 8.2 `report_form` 的存量兼容与过渡条款

本类型由 `research`（Research-调研报告）改名并扩展为统一报告类型，既有 50 份对象**不含** `report_form`。过渡规则如下，**读路径与写路径分别适用**：

**读路径（立即生效，无过渡期）**：既有对象缺 `report_form` 时**一律按 `research` 判**——其正文骨架校验按调研型 7 个 H2 进行，其 `urls`／`research_question`／`research_purpose` 按调研型必填面校验。理由：这批对象在成文时即按外部对象调研写成，其实际形态就是调研型；按 `research` 判不是猜测，是据实认定。

**写路径（有过渡期）**：
- **新建**：`report_form` **必填**，无例外；
- **更新既有对象**：允许不带 `report_form`（视为不变更），此时按读路径的认定校验；一旦显式携带，取值必须与读路径认定一致（即既有对象若显式写 `report_form`，只能是 `research`——它们确实是调研型；要改为其它形态须新建对象）；
- **迁移批次**：把既有 50 份对象的 `fact_type_key` 与 `report_form` 一次性补齐（同时迁移目录与文件名），逐份补 `change_log` 摘要并写后回读。

**过渡期的结束条件（本条在迁移批次完成时删除）**：迁移批次经受控提交落盘、且 50 份对象均已携带显式 `report_form: research`、且冒烟验证通过（至少一次报告创建/更新与一次跨类型引用解析成功）——三者同时成立即「迁移批次完成」。在此之前，本节是读路径的合法依据；成立之后，`report_form` 对全部对象无条件必填，本节删除。

**与 02 号过渡条款的对应**：02 §6.4 同批登记了「存量 `fact_type_key: research` 在迁移批次完成前视同 `report`」的过渡规则，两处指同一个「迁移批次完成」判据，不得各自解释。**为何需要两处**：`fact_type_key` 的值域归 02 §7.1 管、`report_form` 的必填面归本条管，二者是两个不同字段的两条不同规则，不能合成一条。

## 9. 状态与生命周期

状态闭集为 `active` 与 `retired`，初始状态只能是 `active`，唯一合法转换是 `active → retired`，`retired` 不复开。

| status | 语义 | 必须成立 |
|---|---|---|
| `active` | 在所述来源、观察时点、停止与限制范围内可作为当前调研入口 | 只能是新建初态；全部核心字段、三态证据、引用闭环与正文成立；不证明外部事实仍当前、来源真实或结论已采纳 |
| `retired` | 不再作为当前调研入口，包括资料失效、外部对象版本变化、被新调研更新、范围不再相关或本对象自始即为工具面端到端验证等非业务承载 | 唯一转换是 `active → retired`；转换时 frontmatter 必填 `retirement_reason`（闭集 `outdated`/`superseded`/`out-of-scope`/`rejected`）与 `retired_at`（ISO8601，Code 托管），且当 `retirement_reason=superseded` 时 frontmatter 的 `relations[]` 必含一条 `updates` 关系指向替代对象；`change_log` 末条摘要必须说明退出依据；正文`建议`段最后一条必须显式回答"本对象在何种条件下仍可被回查"以保证"研究→执行"承接不断裂；不要求或自动建立其他替代关系 |

不设进行中状态：进行中的调研是运行状态（02 §4.2），不进入事实源，终止后才经受控创建成为对象。未形成对象的调研取消不入档；已对象化后的撤销属删除边界，不属状态。重新做同一来源面的报告时新建对象，旧对象按生命周期处置为 `retired`，不以 `supersedes` 关系表达替代。

更正、更新、状态转换与删除是不同动作（02 §11）：错字、来源定位、摘录改写错误或同问题同边界的证据补充属更正或更新，不改变状态；`active → retired` 是状态转换，必须说明依据；删除不能用代替 `retired`（02 §11）。内容、关系或状态变化必须使用当前指纹绑定的完整更新入口，写后精确回读整个对象文件（02 §10）。

## 10. 来源、证据与来源锚点

**来源形态按 `report_form` 分叉，两套形态互不替代**：调研型用外部来源（§10.1），总结型与审核型用内部来源（§10.2）。**判据是来源面的性质，不是写作者的偏好**——对外部世界的取证只能用 §10.1，对内部过程的取证只能用 §10.2。两套形态的共同纪律：来源回指只回答"内容从哪里观察"，不单独证明内容正确、证据充分、当前适用或已获授权；**不得以 AI 自述、记忆或二手转述冒充来源回指**。

### 10.1 外部来源锚点（`report_form=research` 专用）

来源只承载外部长期可复核资料：经 `urls` 以绝对 HTTP(S) URL 表达，允许文献、代码仓库、官方文档、规范原文等。`urls` 的语义边界由 02 §7.1 唯一持有，本文不复述、不扩张。

溯源锚点格式：每个发现单元末尾一行 `溯源：<ref>（<锚点>）`，`<ref>` 逐字等于某条 `urls[].ref`，`<锚点>` 为来源内可重新定位的位置（章节标题、文件路径与行号、API 名称、commit 等）。外部来源的摘录原文可不复制进对象——需要核对时按锚点回查来源（F4 展开）。

### 10.2 内部来源锚点（`report_form=summary`／`audit` 专用）

**内部来源不是指针，是摘录。** 对内部过程、既有载体与运行记录的取证，其内容必须**逐字摘录进报告正文**（总结型的 `证据摘录` H2、审核型的 `证据性发现` H2），每条摘录后缀一行内部来源锚点，指明该摘录取自何处。

**内部来源锚点格式**：`来源：<kind>（<locator>）`

| `kind` | 闭集语义 | `locator` 形态与纪律 |
|---|---|---|
| `commit` | 该内容来自某次提交（含该提交下的文件历史版本） | 40 位小写十六进制 commit 哈希；**首选形态**——哈希永久可解析，且不随工作树文件移动而失效 |
| `object` | 该内容来自另一个事实对象 | 该对象 `object_uid` 的规范文本；**事实对象只相互引用**，这是唯一被允许的「引用其它事实对象」通道 |
| `session` | 该内容来自某次会话 | 会话标识（由宿主提供）；**不作长期权威**，仅用于当次与近期回查 |
| `run-record` | 该内容来自某次运行记录（测试输出、构建日志、诊断结果） | 记录标识或可复现命令 + 时间点 |

**禁止事项（机械可判）**：

1. **禁止以 `docs/` 路径作为 `locator`**——`docs/` 下的文档不是事实对象、不取得事实效力；要引用其内容须把内容**逐字摘录进正文**，`docs/` 路径只可作为辅助文字说明出现在摘录旁，**不得**充当 `locator`。这与 09 §5.3 第 5 项同向，并比它更严格：09 禁的是"以 `docs/` 为权威依据"，本条禁的是"以 `docs/` 路径作来源定位"。
2. **禁止以本机绝对路径、会话内临时路径作为 `locator`**（同 02 §7.1 对 `urls` 的纪律）。
3. **禁止把内部来源填进 `urls`**——`urls` 只承载外部 HTTP(S) 资料（02 §7.1），塞入本机路径属语义误用；`summary`／`audit` 两类直接禁填 `urls`（§8）。
4. **禁止虚构 `locator`**：写了 `commit` 就必须真存在该提交、写了 `object` 就必须能解析到该对象。机械层校验 `commit` 的 40 位 hex 形态与 `object` 的可解析性；**不校验** `session`／`run-record` 的真实性——那属 AI 据实声明范围（00 §4.6）。

**为何 `commit` 优先**：`docs/` 档案可能被清理、文件可能被移动，而 commit 哈希由 Git 历史永久保证。以 commit 定位既满足「内容可追溯」，又不产生对 `docs/` 路径的依赖——这是 Human「事实对象不能引用 docs 下的文档」与「内容须可追溯」两条要求的同时满足方式。**如实边界**：commit 定位的是「该时刻的文件内容」，不是「该内容永远可用」；仓库被删除或历史被重写时该锚点失效，这一风险不由本规范消除。

### 10.3 三态证据的承载与获得判据


三态证据的承载分工：`confirmed_statements` 是正文发现单元的机器索引（声明句列表）；发现单元的完整证据——浓缩观察事实、价值判断、溯源锚点——在正文"关键发现"段承载；`uncertain` 与 `gaps` 因条目短小且无叙述展开需求，仍以 frontmatter 字段承载。三态获得判据如下：

- **已证实（关键发现单元）**：对同一声明有可回指的来源支持（外部按 §10.1、内部按 §10.2）、经核对没有实质冲突，且发现单元附有效溯源锚点；发现单元必须含独立的价值判断（对 LDVH/管辖项目意味着什么），纯描述无判断不构成合格发现。有来源但存在实质冲突或不可复核的观察，归入 `uncertain`。
- **未证实（`uncertain`）**：存在疑点或冲突证据待裁决、证据不足、不可复核、超出能力或时间范围的观察，记录 `issue` 与 `reason`；不得以"未知"冒充已证实。
- **缺口（`gaps`）**：已知未能取得的信息空白，按对 `research_purpose` 所支撑判断的阻塞程度取优先级，必要时用 `blocked_scope` 说明阻塞范围。


机械层校验来源锚点的存在性、格式与回指一致性（外部型回指 `urls[].ref`，内部型校验 `kind` 闭集与 `locator` 形态）；观察事实是否忠实于来源、价值判断是否成立、锚点处内容是否仍一致，属 AI 语义审核与 F4 展开范围，机械结果与语义判断互不替代。

`clarification_log` 记录已经改变调研问题、对象边界或证据解读的实质澄清；未改变方向的问答、寒暄与复述不记录，防止该字段退化为聊天日志。

## 11. 关系契约

报告使用 02 §8.2 的公共关系形状，允许的 `relation_key` 闭集如下：

| `relation_key` | 方向 | 语义 | 允许的目标类型 | 约束 |
|---|---|---|---|---|
| `inspired-by` | 报告 → 目标 | 本报告由该对象承载的议题、工作或问题驱动（**「报告关联发起它的 Spark」即用此边**） | `spark`、`adr` | 每个对象至多一条指向同一来源类型；允许指向多个不同的来源对象；不证明议题仍开放或问题未解决 |
| `informs` | 报告 → 目标 | 本报告的结论或边界应影响该对象的判断或执行 | `adr`、`spark` | 不表示已采纳、已承接或行动已开始；每条关系独立声明，不合并 |
| `updates` | 报告 → 目标（同类型） | 本对象是对同一来源面的更早报告的更新 | `report` | 每对象至多一条；目标必须可解析且不等于自身；不自动处置目标状态，旧对象 `retired` 按 §9 单独执行 |

禁止的关系 key：`supersedes`（重新调研通过新建对象与旧对象生命周期处置表达，不用关系替代处置）；`depends-on`（报告不依赖其它对象的当前状态）。v4 Study 遗产对象不作为合法关系目标（v4 Study 类型已废弃且无 canonical 身份；如需精确引用 v4 遗产对象，通过迁移记录的 object_uid 历史信息回指，不建立关系声明）。

本文不采用关系级 `evidence_locator`：关系的依据由对象自身引用闭环与正文承载，不建立关系级证据定位，证据闭环唯一定义在 §10，避免第二证据权威。关系条目的公共形状、变更流水与失效报告按 02 §8.2 承接。

**本类型 `informs` 的特指语义（与 26 号同名不同义）**：本类型的 `informs` 是**前瞻性影响声明**——「本调研的结论应当被该对象在判断或执行时考虑」，目标对象的状态与行动尚未因该边改变。`26` 号 Friction 亦使用 `informs` 键，两表同为「源→目标」同形边，但**因果流向与时态**不同：本条的因果是「调研 → 影响目标」，26 的因果是「目标（解药）→ 已解决该账」，本条指尚未发生的影响，26 指已经发生的解决。两者不得互相替代或互相推断；按 02 §8.2 第 3 项，关系 key 的闭集与语义由各类型来源分别定义，02 不建立通用关系家族。

## 12. 召回与消费

召回时机：当前目标需要外部对象的事实输入（该技术、工具、项目或实践"是什么、怎么用、边界在哪"），或当前输入精确引用 `research_question`、外部对象名或 `research_purpose` 时，进入报告候选发现（召回通用边界按 02 §9.2 承接）。

F1 卡片只投影最小权威字段：`object_uid`、`fact_type_key`、`title`、`status`、`report_form`、`research_question`、`research_purpose`、`stopping_reason`、`created_at`；不投影三态内容、发现单元、溯源锚点或子阶段，不在卡片层解释结论当前性。

F2 候选发现只按确定性字段过滤：默认状态范围 `status=active`，`retired` 只在精确引用、调研历史或来源追溯时进入候选；允许按类型、状态、稳定引用、关系或本文允许字段（`title`、`research_question`、`research_purpose`）命中，候选卡返回 F1 字段、命中依据与有界确定性摘录（`title` 或 `research_question` 的定长片段）；关系导航**不设本类型专属的检索操作**，两个只读方向由通用关系机制承载：**反向**（已知目标对象反查哪些报告声明了指向它的关系）走 02 §9.1 的 F2 关系命中——以目标 `object_uid` 为查询指称、并以 `types=[research]` 收窄类型（该维度按完整 `object_uid` 整值命中，短标识与类型短名不参与），命中理由逐项标注命中的 `relation_key`／`relation_target`；**正向**（从已知报告沿 `inspired-by`/`informs`/`updates` 边取得直接目标）属 F4 派生：仅在查询为纯指称时触发，按本类型判据表「关系展开」行（02 §12.4）与 §11 关系闭集跟随对象上实际存在的边、一条边一跳、不递归，结果单独归类、不占 F2 名额，超出上限时按 `dropped` 如实披露。两者只形成候选与关系边结果，不自动改变对象状态、时效或结论当前性，均为通用关系机制的派生结果，不写回对象。

F3 完整展开发生在三态证据、引用闭环或边界结论影响当前判断时：读取当前权威载体（单文件）全文，完成已实现机械校验（frontmatter 闭集、状态、`调查阶段` H2 存在性与子阶段一致、引用闭环回指一致、关系 key 与目标解析），再作适用与边界判断。

F4 来源展开发生在需要核对具体观察、版本或观察时点时：按溯源锚点的 `ref` 与锚点位置读取实际来源并核对观察事实是否仍一致；来源已变化时按变化收紧声明或触发更新/新建（F4 通用边界按 02 §9.1 承接）。

消费边界：`confirmed_statements` 声明可被引用，`uncertain` 与 `gaps` 不得写成已证实；发现单元必须可经溯源锚点回查来源，锚点存在不证明来源真实或证据充分；`retired` 对象不作为当前证据输入，除非完成 F4 复核并按结果收紧声明；上下文压缩后，已在本轮引用且仍影响判断的报告必须重新回读 F3 的三态、停止与边界。报告结论不自动产生规则、决定、授权或完成结论，进入 ADR、Spark 或规范由相应来源另行准入；调研证据被吸收不自动使报告终态。

## 13. 受控操作

创建按 02 §10.4 承接；类型特有的机械校验为：**`report_form` 必填且取值属闭集三值**、**形态与正文骨架一致（不变量 12）**、必填条件字段按形态分叉（§8）、闭集取值、三态至少一项、每条 `confirmed_statements[]` 成员在正文有逐字对应发现单元、每个发现单元末尾有合法来源锚点（调研型回指 `urls[].ref`；总结型／审核型按 §10.2 的 `kind` 闭集与 `locator` 形态）、正文"研究问题"段逐字包含 `research_question` 原文（不变量 10，仅调研型适用）、正文 H2 顺序与唯一（调研型：明确方向型六个 H2／探索型七个 H2 且`调查阶段`内四个 H3 顺序与唯一；总结型四个 H2；审核型五个 H2）、`serves` 出现时的格式与目标解析（不变量 11）、**审核型另须满足 §6.3 四项准入**（正文完整可得、一次审核一条、对象是结论不是流程、来源交代在背景段）。

更新与更正按 02 §10.5 承接（通用发布不变量——完整 after、恰好一条 change_log、写后回读——见该节；**可更正到什么范围由本条下方的终态事实更正条目定义**，02 §10.5 本身不承载任何类型的终态更正正文规则）；类型特有约束：CAS 以完整文件为单位（指纹绑定整个文件），提交完整 after；frontmatter 的三态字段如因调查发现变化须同步更新（frontmatter 是三态的机器权威，`调查阶段` 正文不得有独立于 frontmatter 的证据状态）。`serves` 仅在「新设」或「取值变更」时重新解析目标（不变量 11），未变更时不重复解析。子阶段不可变：更新不得添加或删除 `调查阶段` H2。**形态不可变**：更新不得改变 `report_form`（变更形态即另一类认识，须新建对象并按 §9 处置旧对象）。

**终态事实更正**（`correct`）：§8 第 4 项早已允许「`retired` 时……只允许配套更正或退出说明的更新」，但此前**没有任何通道承载它**——`status` 由磁盘继承，于是 `retired` 对象的任何一次更新都会命中「`retired → retired` 不可再次进入」而一律被拒，该许可只是一句话。本入口是它的承载。**入口只对 `status = retired` 开放**：`active` 的内容修正走普通更新；把内容更新路由到本入口即「把内容更新伪装成事实更正」的反向越界。**必须 Human 授权**：调用方须提供非空 `human_authorization`，其文本逐字落入 `change_log`；缺授权即拒绝。**如实声明边界**：该字段是自报，机械层只保证「授权记录被提交」，**不证明** Human 真的同意过。**可写范围是白名单**（本类型不能像 22 号 ADR 那样「完全不接收 frontmatter」——§8 的索引-正文不变量要求两层同改，只改正文无法完成一次合法更正）：`confirmed_statements`／`uncertain`／`gaps`／`implications`／`research_question` 五项，其余键一律拒绝。**逐字继承**：`status`／`retirement_reason`／`retired_at`／`urls`／`research_purpose`／`stopping_reason` 与子阶段。**`stopping_reason` 为何不在白名单**：它是「为什么停在这个轮次」的**判断**，改动它属判断变更而非事实更正，且没有任何机械判据能区分「更正一个写错的停止理由」与「把结论改成另一个结论」，故明文排除。**§8 不变量的拒绝属预期行为，不是缺口**：不变量 3（`sufficient` ⇒ `confirmed_statements` 非空）会拒绝「更正后清空全部声明」——替换单条不触发，只有删空全部才触发，而删空全部本就不是错述更正；不变量 7（声明与关键发现 H3 标题逐字对应）与不变量 10（研究问题段逐字包含 `research_question`）都是**两层同改**的要求，白名单纳入对应字段后即可满足，不构成阻断。**无写入变更即拒绝**：正文与白名单字段均未变时拒绝为 no-op，不追加声称更正过的条目（02 §10.5 不记录 no-op）。**机械拒绝的越权动作**：终态字段（`correction_terminal_field_immutable`）、判断字段（`correction_judgment_field_immutable`）、白名单外字段（`correction_field_not_permitted`）、非终态对象（`correction_requires_retired`）、缺授权（`human_authorization_required`）、陈旧指纹（`cas_conflict`）。写后精确回读。**本条机械保证范围**：只证明「该次写入带 Human 授权、只改白名单字段与正文、终态与判断字段逐字未变、`change_log` 恰好 +1」；**不证明**更正内容正确或缺陷已实质消除——那属 AI 语义审核与 Human 阅读（04 §6）。**残留（如实登记）**：`urls` 的源头写错（如链接本身记错）不在本入口范围，仍无通道。

状态转换 `active → retired` 经受控更新完成：after 含新状态、`retirement_reason`（闭集）与 Code 托管填写的 `retired_at`，当 `retirement_reason=superseded` 时同时携带一条 `updates` 关系指向可解析的替代报告；`change_summary` 必须据实说明退出依据；正文`建议`段最后一条必须显式回答"本对象在何种条件下仍可被回查"以保证"研究→执行"承接不断裂（与 §9 退出完整性不变量对齐）；不允许普通编辑 direct writing canonical 载体。多对象边界：新调研创建与旧对象 `retired` 是两个单对象操作，不声明原子性；`relations` 随对象创建写入（02 §10.6）。

迁移边界：v4 `report_kind=external_research`（28 份）对象与 docs/ 既有调研备忘是迁移输入，须逐份重满足本文 §6 准入并补全三态证据与引用闭环后，经受控创建按实际子阶段进入 `researches/` 类型目录（单文件：探索型含 `调查阶段` H2，明确方向型不含）；v4 frontmatter 中本文不承载的字段（如 `abstract`、`recommendation_summary`）在迁移创建时删除，不进入 canonical frontmatter，如需保留迁移历史可在 `change_log` 摘要中说明；v4 `technical_assessment` 与 `internal_audit` 不迁入本类型（前者不设产物类型，按主控方案收敛本职分流处置，04 §6.1；后者的完整结论报告不设持久事实对象承载——**本文此前称其「由检查机制规范的独立复核结论封存通道承载」，该通道并不存在**：04 号全文无「封存」一节，本句与「审核详情不入任何事实对象」的一般纪律共同构成了「审计报告在全部事实类型中无承载位」的成因，经 Human 决定改判并据实更正于此；2026-11-14 DevLog 类型撤除后该结论进一步坐实：此类内容按 02 §6.4 落判据 9「不承载」）；v4 Study 类型名废弃、不设单独类型规范；legacy `object_id` 只作迁移输入，不进入 canonical 对象、关系目标或 CAS 身份（02 §7.1、§7.2）。删除边界按 02 §11 承接。

## 14. 类型特有验证与类型退出

类型特有验证对象为三态一致性、溯源锚点完整性、单文件载体结构与正文结构：机械层验证三态与 `stopping_reason` 的闭集与存在性、`confirmed_statements` 与正文发现单元的逐字对应、正文"研究问题"段逐字包含 `research_question` 原文（不变量 10）、溯源锚点格式与 `ref` 回指、`relations` 的 key 与目标类型闭集、`调查阶段` H2 存在性与子阶段一致、正文 H2（及探索型 H3）的顺序与唯一性；逐字摘录是否真实、来源是否仍当前、缺口优先级是否阻塞 `research_purpose` 判断、三态归类是否据实、子阶段判定是否据实，属 AI 语义审核与独立复核范围，机械结果与语义判断互不替代（02 §8.1）。

**终态事实更正边界**（§13 的 `correct`）：对象为 `retired`；带非空 Human 授权与变更摘要；提交正文与落盘正文不同（no-op 拒绝）；**终态与判断字段逐字未变**——`status`/`retirement_reason`/`retired_at`/`urls`/`research_purpose`/`stopping_reason` 与 CAS 基线逐字段一致；frontmatter 写入限于 §13 白名单五项，其余键按专属失败码拒绝；正文固定 H2/H3 结构与索引-正文一致性（不变量 7、10）仍须通过；`change_log` 恰好 +1 且带授权文本。**可证明范围**：只证明该次写入的形状与不变性；更正内容的正确性属 AI 语义审核与 Human 阅读。

类型退出：报告停止新增、合并、替代或取消时，必须按 02 §11 与 09 处置唯一定义来源、全部对象文件、字段登记、引用消费方与仍适用内容，并保留仍需回看调研历史的 `retired` 档案；不能只删除本文、目录、Schema 或 Web 入口，也不能用文件删除代替完整退出。

## 16. Human Gate

本规范不新增 00 之外的 Human Gate。

### 16.1 领域增量事项

以下事项是 00 §3.2 在报告领域的具体化：

1. 删除报告对象或退出报告类型；
2. 调研来源涉及需要 Human 授权的访问边界（私密、付费、许可、受限仓库或敏感领域）；
3. 引用闭环需要保留受版权限制的逐字长摘录或受限引用时的取舍；
4. 来源冲突无法裁决、或证据缺口阻塞 `research_purpose` 所支撑判断仍需引用时的高影响取舍；
5. 从 v4 或旧材料迁移报告的批量方式及其准入标准的决策，以及 v4 `technical_assessment` 不迁入后的承载处置、`internal_audit` 不设持久承载后的去向与 v4 Study 类型名废弃的决定；
6. **对 `retired` 报告的终态事实更正**（§13 的 `correct`）：每次更正都须 Human 明确授权，授权文本逐字落入 `change_log`。这是 §16「本规范不新增 00 之外的 Human Gate」的一处领域细化——它不新增关卡类型，而是把 00 §3.2 的既有授权要求落到一个此前没有入口的动作上；**如实声明**：机械层只校验授权记录被提交，不证明 Human 真的同意过。

### 16.2 决定边界

Human 决定只证明决定及其作用范围，不替代本文 §15 的来源验证、三态结构检查、引用闭环核对或对象回读；Human 确认来源充分或风险可接受，不能把 `uncertain` 或 `gaps` 变成已证实，也不能把调研结论变成规则、决定或授权。

## 17. 必停情形

本规范不新增根停止类型。

### 17.1 领域触发与影响范围

出现以下任一情况时，按 00 §4.7 暂停最小受影响范围：

1. 将进行中的工作写成报告对象，或 `stopping_reason` 无据实依据、与三态结果不符；
2. 来源面与形态不符：调研型的对象非外部、无法被外部资料定位，或问题不属于"是什么、怎么用、边界在哪"且无法单句明确；总结型／审核型以外部资料为主体取证（应改判为调研型）；或形态与正文骨架不一致（不变量 12）；
3. 来源锚点断裂：发现单元缺来源锚点、调研型锚点 `ref` 无法回指 `urls`、内部型锚点 `kind` 不在闭集或 `locator` 缺失／以 `docs/` 路径充当定位、锚点位置无法重新定位、观察事实凭记忆填写而非实际读取；**总结型／审核型未把内部来源内容逐字摘录进正文、只留指针**（§10.2）；
4. 三态缺失或矛盾：无任何三态证据、条件字段用 `null`/空值占位、`sufficient` 却无 `confirmed_statements`、`round-cap` 却未声明未覆盖范围；
5. 载体结构违规：探索型缺 `调查阶段` H2、明确方向型出现 `调查阶段` H2、`调查阶段` 内 H3 缺失或顺序错误、更新试图添加或删除 `调查阶段` H2；
6. 状态、关系或生命周期处置越出本文闭集，或用关系冒充目标处置、用删除代替 `retired`；
7. 声称已核对未实际 F4 展开的来源，把 `uncertain`/`gaps` 写成已证实，或将 `retired` 对象作为当前证据输入；
8. 创建/更新后尚未精确回读整个对象文件、或适用完整性审计未完成，却准备继续写入、提交或声明成功；
9. 发现本文与 00/02/03、30、相邻类型来源或 Human 已定决策冲突；
10. **审核型只保留概要而完整正文不可得**却仍准备创建对象（§6.3 第 1 项）——该情形应如实登记为缺口，不建对象；
11. **试图在更新中变更 `report_form`**（形态不可变，须新建对象并按 §9 处置旧对象）。

### 17.2 暂停期间允许动作

暂停期间只允许不越过停止边界的来源定位、对象回读、证据补取、摘录核对、修复与分流准备，不得继续受影响对象写入、关系变更、提交或成功声明。

### 17.3 恢复与再次触发

恢复条件必须与触发原因逐项对应（补齐来源与摘录、修复三态归类、修复单文件载体的正文 H2/H3 结构、满足停止判据、完成回读），恢复只覆盖当前依据支持的范围；同一停止条件恢复后再次触发时，不得再次自行恢复，必须按 00 §4.7 的恢复与再次触发进入 Human Gate。

## 18. 反过度设计红线

1. 不把进行中的搜索、链接收集或会话过程对象化；只有已终止并形成三态证据的产物才创建报告；
2. 不为单次网页阅读、零星 URL 或普通文档可无损承载的摘要创建报告对象；
3. 不建立三态之外的第二证据形态、独立引用数据库、来源全文镜像或抓取缓存作为事实权威，`调查阶段` 正文不得成为第二证据权威；
4. 不要求每次读取报告都重读全部外部来源或自动联网复核；F4 只按需展开影响判断的必要来源；
5. 不把引用闭环扩张为版权全文抄录、网页存档或外部资料镜像；摘录以最小足以支撑声明为限；
6. 不为调研增加过程日志、轮次或预算流水、搜索历史字段；`clarification_log` 只收改变方向的实质澄清，`调查阶段` 正文不承载逐轮过程日志；
7. 不把关系存在、引用回指或机械通过冒充来源真实、证据充分、结论当前或工作完成；
8. 不因 v4 已存在 28 份 `external_research` 就批量迁移或按旧 shape 赋予当前性，逐份重满足本文准入；不把 v4 `technical_assessment` 迁入报告（属方案收敛本职）；
9. 不为子阶段单设 stage 字段，`调查阶段` H2 的存在性是子阶段唯一机械表达，避免字段与正文结构形成第二权威。
