## 1. 价值判断

本规范解决经验认识缺少受众归属判据与沉淀纪律的持续问题：候选认识什么都记会沦为垃圾场、什么都不记则重蹈 AI 无连续状态的覆辙；个人偏好混入项目事实源会污染未来任何参与者的判断，项目教训沉没在个人记忆里则随人员流失而散尽；有记忆不用是死库、本地观察成熟后无路进 git 是断头路、装了第二个记忆系统则内容重复且权威漂移。通过受众分诊与默认方向、三道门分流、双路召回与预检式召回编排、三路晋升通道与不对称治理，使每条候选认识都有受众判据、明确去向与消费对象，使已留存的记忆在后续行动中被实际召回、比对与晋升，减少重复犯错、重复调研、重复争论与权威漂移的负担。

本规范主要兑现 V6 工作接续与 V8 持续积累——分层留存与双路召回使后续会话恢复状态依据、相似事项复用既有经验与结论；同时支撑 V4 稳定推进、V5 据实判断与 V7 清晰沟通——预检式召回使决定前查 ADR、动手前查 Pitfall 成为义务触发，召回命中依据使判断可回指，晋升提议使待决对象清楚可决；Human 价值主要兑现 HV4 积累效用直观可见与 HV5 项目演进脉络可循——晋升留痕与效用审计使积累的消费端可见、影子与关系边使认识的形成链可循，并支撑 HV1 决策提请清晰可决、HV2 授权执行受控可续与 HV3 入档闭环节点可验——晋升确认卡使拍板对象与依据清楚，locked 保护和越权机械拒绝使本地层写入受控，晋升、淘汰与状态翻转节点可回读核对。

本规范只定义记忆与反思系统自身的分诊、召回、晋升、维护与反思机制；git 事实类型语义由 20–27 承接，受控写入路径由 03/06 承接，宿主事件与子代理接入由 08 与 02 §8 承接，Web 管理面细节由 10 承接，LDVH CLI 操作声明形状由 05 承接。

条目数量、召回命中次数、晋升数量、页面呈现或单次复用，均不能单独证明记忆内容正确、适用或有长期价值；效用须由真实消费、跨行动接续与后续工作效果共同核对。

### 1.1 系统定位与价值

本系统是 LDVH 六大业务系统之一的**记忆与反思系统**，对应 00 §3.1 工作模型「业务系统」登记名**「记忆与反思」**（system_key 见 §1 业务系统声明）。其稳定身份为：留存和取回项目的经验认识，从目标、判断、行动、结果、摩擦和反馈中形成候选认识并按沉淀环节分流决定去留的业务过程承载；反思为其一机制，检查既有认识与经验是否仍然适用。

解决的持续业务问题：AI 的无连续状态（00 §1 缺陷 3）与人的经验离散（00 §1 痛点 4）使已确认的事实、做过的决定、踩过的坑、得出的结论随对话结束散尽——下次同样取舍重新争论、同样岔路重新选错、同样结论重新调研。记忆与反思系统把"候选认识的分诊、留存、召回、晋升与健康维护"作为稳定可复用的业务过程承接，使其他五个业务系统（调研、讨论、工单执行、规则遵守、目标与蓝图）都能以受维护的记忆为输入与去处。

服务的消费方与价值：
- **消费方**：主控（随手记、召回消费、比对、晋升提议、反思执行）、空闲维护代理（宿主闲置辅助任务，见 §10）、规则遵守系统（预检式召回的触发消费方）、其余五个业务系统（沉淀去处的分流消费方）、Human（晋升拍板、锁定、管理面操作与效用核对）。
- **价值（V）**：主要兑现 V6/V8，支撑 V4/V5/V7（见本节第一段）。
- **Human 价值（HV）**：主要兑现 HV4/HV5，支撑 HV1/HV2/HV3（见本节第一段）。

本系统的价值不等于系统自身成立；门类齐全、条目积累或晋升发生，均不单独证明分诊正确、内容适用或效用成立，价值由后续实际使用核对（沿用 00 §6 与 04 §1 的边界）。

### 1.2 记忆受众归属（这条信息伤害谁）

记忆系统服务于**受众判定**：每条候选认识的第一判据是"它错了或丢了，伤害的是谁"。这是本系统与相邻系统的根本分界，也是双层架构的立法依据。

| 受众 | 伤害形态 | 承载层 | 治理强度 |
|---|---|---|---|
| **项目**（误导未来任何人/任何 AI 的行动） | 错误内容污染共享判断 | git 层（`ldvh-base/`） | 严进严出：举证、Human 拍板、错了走退休流程 |
| **自己/本机**（我被误导，删掉重记即可） | 只误导本地消费者 | 本地层（DSH storageDomain） | 宽进轻出：无举证义务、随手删 |
| **谁都不伤害**（可重新发现） | 无 | 不记 | 门 0 拦截 |

受众归属的判定主体与防滑移：受众由主控依据当次可观察依据判定，不得因记录省事而把"只伤害自己"的内容推入 git 层，也不得因举证麻烦而把"伤害项目"的内容压回本地层。判定无法确认时按 §5.6 默认方向处理；连"是否该记"都无依据时，不记并在交还中说明。受众判定的机械辅助（候选设计，见附录 A.4）不替代主控语义判断。

**自举场景的双重身份**：当管辖项目即 LDVH 自身开发仓库时，"这个项目怎么做出来的"（git 层）与"LDVH 机制该怎么改进"（也是 git 层，但目标类型不同——改进账本走 Friction/ADR）在物理上重叠。此时受众主轴仍然成立：框架自身的工作偏好（如"起草规范先查 01 §7"）若已被规范明文规定，则它是规范内容不是记忆（可重新发现，门 0 拦截）；若尚未成文而是个人工作习惯，则按其伤害对象分层。规范已定义的规则不因被记忆而获得第二次规范效力。

## 3. 职责边界

### 3.1 本文负责

本文负责：

1. 记忆受众判据（受众主轴）与双层架构（git 层/本地层）的领域定义；
2. 信息分诊三道门（不记门/git 门/本地门）与默认方向、灰色地带裁决；
3. 沉淀去留纪律与分流路由（00 §3.1 沉淀环节的展开；含 git 层性质路由表与灵感→Spark 的根指定路由）；
4. 记录触发（三路）与主控随手记的四操作比对；
5. 双路召回的编排原则：git 侧对 F0–F4 的消费方式、本地侧启发式检索、注入顺序与预算冲突裁决、命中依据义务；
6. 预检式召回的统一触发编排（与 04 §7.2 预检落实记录"已召回"区的衔接方式；类型侧召回原则回指 22/23/24，不重复定义）；
7. 晋升通道（三路触发、Human 拍板双入口、格式转换候选规则、影子语义候选规则）；
8. 本地层轻治理契约：载体与存储形态、条目结构、类型闭集、scope/origin、治理参数（容量/TTL/合并/淘汰保护）、无举证义务、locked 保护；
9. 空闲维护的调度纪律与宿主闲置任务对齐（空闲评审代理、容量维护代理、记忆健康体检、效用审计最小形态候选）；
10. 反思机制的触发条件与修订意见的承载边界；
11. 完整性承诺（独占记忆职责）的边界声明与双入口管理面的原则（细节回指 10/05）。

### 3.2 本文不负责

本文不定义：git 事实类型的对象边界、字段契约、状态与生命周期（由 20–27 各类型规范承接）；事实对象进入事实源的具体受控写入路径、CAS、提交契约与 Git Gate（由 03/06 承接）；LDVH CLI 的请求/响应 envelope、公开操作注册与宿主接入（由 05 承接）；DSH 事件钩子的具体事件名、可用性与子代理 spawn/恢复（由 08 与 02 §8 承接）；Web 管理页的视觉、交互与呈现细节（由 10 承接）；跨会话接续状态的承载（由 DSH 会话历史与 Output Envelope 承载，本地层类型闭集不含状态类——Human 决定 2026-09-10）；上下文压缩、上下文预算与 token 管理（宿主机制，不是记忆系统的职责）；调研、讨论等兄弟系统的自身流程（由 30/31 承接，本文只定义沉淀衔接与召回衔接）；Memory 的 Code 实现与测试（由 09 承接）。

### 3.3 相邻规范分工与唯一权威

00 §3.1 与 02 §14 是记忆与反思系统根职责、判据与边界的唯一权威；03 与 20–27 是 git 层类型语义与受控写入的唯一权威；04 是业务系统公共机制（五机制、风险路由、预检落实记录格式、降级）的唯一权威；05 是 CLI 操作声明形状的唯一权威；06 是提交契约与 Git Gate 的唯一权威；08 是宿主事件接入的唯一权威；10 是 Web 呈现的唯一权威；22 §12 是 ADR 义务召回原则的唯一权威、23 是 Pitfall 执行前预检的唯一权威、24 与 30 是调研查重的唯一权威——本文只编排触发时机与预检落实记录衔接，不重复定义各类型的召回原则。本文是记忆与反思系统专属流程与领域条件（受众分诊、本地层契约、晋升通道、空闲维护纪律、反思触发）的唯一权威；Code、Web、缓存或工具输出不得反向创造第二权威。

### 3.4 职责根边界与回指

00 §3.1 登记名「记忆与反思」职责原文：**"留存和取回项目的经验认识，从目标、判断、行动、结果、摩擦和反馈中形成候选认识；沉淀环节由本系统承接，承接对话中的灵感与经验，并以事实对象承载其产物；沉淀的去留纪律与分流路由亦由本系统承接，其中灵感按方向与未决问题归入 Spark 事实对象；反思同为本系统的一个机制。"** 02 §14 判据原文：留存的内容有消费对象、适用边界和明确去向；候选认识可回指实际行动和证据；偶发现象与可复用模式可区分；反思产出的修订意见可回指其依据。本文不改写上述根定义；六入口（目标、判断、行动、结果、摩擦、反馈）是候选认识的来源闭集表述，其展开见 §6.1。

**本地层的根职责依据（重要登记，审核重点之一）**：00 §3.1 与 02 §14 的字面职责聚焦"**项目**的经验认识"；本文承载的本地层（跨项目个人工作记忆，受众=自己/本机）的权威依据是 Human 决定 2026-09-10 的两层架构与独占记忆职责战略（`docs/memory-system-design-prompt.md` §5.1/§5.10），其根方案挂点是 00 §3.1"沉淀的去留纪律与分流路由亦由本系统承接"——本地层是分流路由的一个落点（门 2），不是对根职责原文的扩写。若对抗审核或 Human 认为本地层需要根方案层面的职责修订（例如在 00 §3.1 显式登记个人工作记忆职责），该子域按规则候选处理（01 §11 程序 + 00 §4.2 Human Gate），在此之前本文按分流路由落点承载本地层。

**不改根定义的边界声明**：本系统不产生规则或授权——记忆留存不自动产生规范效力、事实、授权或完成结论（00 §3.1/§3.2；记忆条目与事实对象都不因被记录而取得规范效力）；已被规范明文规定的内容是规范内容不是记忆（门 0 可重新发现拦截）；反思结论不自动生效，须经相应规范或事实承载与 Human 决定（02 §14 边界原文）。对象数量、页面呈现和单次复用不证明效用（02 §14 边界原文）。

## 4. 适用范围

### 4.1 适用对象

本规范适用于：

1. 主控对候选认识的分诊、记录、召回消费、比对、晋升提议与反思执行；
2. 空闲维护代理（宿主闲置辅助任务）对记忆的保守评审、容量维护与健康体检；
3. Human 对本地层的锁定、晋升确认与管理面操作；
4. Code 对本地层格式校验、容量维护与检索的机械执行。

### 4.2 适用场景

本规范用于：对话中六入口候选认识的分诊与记录；行动前预检式召回的触发与执行；本地观察的攒熟与晋升；记忆容量与健康的空闲维护；既有认识的反思与修订提议；git 层七类事实对象与本地层五类条目的召回消费。git 层操作要求当前项目受 LDVH 管辖（07）；本地层操作不要求项目受管辖——本地层跨项目共享，其载体不在项目仓库内。

### 4.3 明确排除与证明边界

本规范不适用于：单会话临时状态（门 0 拦截，接续由 DSH 会话历史与 Output Envelope 承载）；上下文压缩与 token 预算管理（宿主机制）；规范或事实规范的建立与修改（01/27 程序，记忆不创设规范效力）；调研执行与讨论收敛（30/31）；未受管辖项目的 git 层操作。门类齐全、条目已写或晋升已发生，只能证明相应机械与过程范围，不单独证明受众判定正确、内容适用、验证通过、行动获准或价值成立。

## 5. 记忆分层与受众分诊（过程机制衔接章之一）

本章与 §6–§11 共同承载过程机制；十项之 5 的锚点章为 §8，归属关系见 §8 开头。本章承接 00 §3.1"沉淀的去留纪律与分流路由"与 02 §16 沉淀机制的领域展开。

### 5.1 双层架构

| 层 | 载体 | 回答的问题 | 治理 | 受众 |
|---|---|---|---|---|
| **git 层** | `ldvh-base/` 事实源（管辖项目仓库内） | 这个项目怎么做出来的 | 严进严出：类型准入、受控写入、Git Gate、Human 拍板、退休流程 | 项目 |
| **本地层** | DSH storageDomain（`$DSH_HOME/storages`，不进项目 git） | 这个人/这台环境怎么工作 | 宽进轻出：格式校验、无举证义务、随手删、TTL 衰减 | 自己/本机 |

两层互不替代：git 层不收纳个人偏好（受众判据不过），本地层不承载项目结论（证据与治理强度不够）。存储形态为 storageDomain 单 key 聚合（Human 确认 2026-09-10）；Web 成为人的主管理面后，人不直接触碰存储，故不采用一条目一 key。本地层的宿主接入由 08 承接，本文只定义契约。

### 5.2 受众主轴

见 §1.2。受众主轴是分诊的第一判据，先于一切类型判断。

### 5.3 门 0：不记门（先过，防垃圾）

候选信息命中任一条即不记：

1. **可重新发现**：可从会话历史、文件、git 或规范源重新取得的内容（Letta 记录与索引分野先例——可检索的不存为记忆）；
2. **AI 自身断言或推断**：AI 的断言、AI 推断出的用户偏好，未经 Human 明示（mnemon 评审纪律先例——只有真人明确断言够格）；
3. **单会话临时状态**：接续靠 DSH 会话历史与 Output Envelope（Human 决定 2026-09-10——状态不记）。

### 5.4 门 1：git 门（受众 = 项目）

判问：它错了会误导项目的未来参与者吗？是且证据可回指 → 进 git，按性质路由：

| 候选性质 | git 落点 | 落点规范 | 额外程序 |
|---|---|---|---|
| 方向与未决问题（灵感） | Spark | 20 | **根指定路由（00 §3.1 原文）**；Human 确认后受控创建 |
| 踩过的坑（失败机制与规避） | Pitfall | 23 | 已验证才够格；Human 确认 |
| 已拍板的取舍决定 | ADR | 22 | Human 决定；active 后具持续约束力 |
| 外部对象深度调研结论 | Research | 24 | 经 30 调研系统产出，非随手可建 |
| 已批准工单与授权执行 | WorkCase | 21 | 经工单执行系统 |
| 待修的系统性阻碍 | Friction | 26 | 入账三条件（26 §7）；其出生路径的触发器归本系统空闲评审（26 §3.2 指向本文） |
| 项目方向规则体系 | Norm | 27 | **Human 决定（27 的 create 须 Human）**；成体系判据按 27 §5 |
| 项目目标锚 | Goal | 25 | 单例冻结锚，修订走 25 的级联程序 |

证据还不够的候选 → 先落本地层 buffer 攒证据（门 2 第 4 类），走 §8.5 攒熟路径。git 层 V1 不新建对象类型（Human 决定 2026-09-10）：正面可复用模式确无家可归时，按 01 §11 程序另议新类型，本规范不预留空位。

### 5.5 门 2：本地门（受众 = 自己/本机）

| 内容 | 本地类型 |
|---|---|
| 工作偏好 | preference |
| 环境/机器/工具事实 | fact |
| 跨项目个人模式 | pattern |
| 未成熟的项目观察（晋升候选池） | buffer（scope=project） |
| 其余 | note |

### 5.6 默认方向与灰色地带

**默认方向（不对称裁决）**：受众不确定时，先落本地。本地→git 有晋升通道随时可补；git 错了要走退休流程、公共代价已发生。宁可漏进 git，不可错进 git——与受控写入 fail-closed 同一姿态。该默认只裁决"记在哪"，不豁免门 0（不该记的不因不确定而获得本地去处）。

| 灰色场景 | 裁决 |
|---|---|
| 工具怪癖（两侧都像） | 问受众：环境无关且坑团队 → git Pitfall；只坑本机（版本/配置）→ 本地 fact |
| 个人模式中出现项目信号 | 观察期落 buffer（scope=project），反复验证后攒熟提议 |
| 用户随口说的项目事实 | 受众是项目 → 即时检测当场提议进 git（§8.5 路径 A），不先落本地多一跳 |
| 小教训小技巧 | 不新增类型：环境无关且坑团队的即时升 Pitfall（Pitfall 不必是重大事故）；只影响本机的落 fact |
| 已被规范明文的规则 | 门 0 第 1 条拦截（可重新发现）；记忆不重复承载规范内容 |

## 6. 进入与退出契约

### 6.1 进入信号

1. 六入口出现候选认识：目标（Goal 变化/新意图）、判断（当次取舍有跨行动价值）、行动（做法值得复用或规避）、结果（验证结论）、摩擦（26 入账三条件成立或重复体验）、反馈（Human 明示的偏好/纠正/验收意见）；
2. 预检式召回触发清单（§8.4）命中当前行动场景；
3. 主控或 Human 主动要求记忆操作（记录/查询/管理面）；
4. 空闲触发点到达且维护预算成立（§10）；
5. 反思触发条件成立（§11.1）。

### 6.2 适用条件

1. 分诊判定可完成：受众归属明确，或默认方向可适用；
2. 门 0 三条已核对且未命中（命中即不记，交还说明）；
3. git 层操作：项目受管辖（07）且目标类型的写入程序可满足（含 Human Gate 可达）；
4. 本地层操作：storageDomain 载体可用且格式契约可满足；
5. 召回消费：召回入口（git 侧 F0–F4 / 本地侧检索）可用且预算明确。

### 6.3 排除条件（反例）

以下场景不由本系统承接：单会话状态记录（→DSH 会话历史/Output Envelope）；上下文压缩（→宿主）；规范内容记忆化（→门 0/§1.2 自举场景）；调研证据搜集（→30，其结论的沉淀衔接见 §15.1）；方案收敛讨论（→31）；目标确立（→34/25 程序，但确立过程中的候选认识分流归本系统）。

### 6.4 不确定处理

受众不明 → 默认落本地（§5.6）；是否可重新发现不确定 → 按会话历史与文件可查性判断，仍不确定 → 落 buffer（低代价可淘汰）；晋升证据不足 → 退回攒熟（B 路径）；目标类型字段无法补全 → 提议 fail loud，不得留占位符；本地载体不可用 → 按 04 §8 降级路径。

### 6.5 当次作用范围

当次记忆动作覆盖的条目/对象集合、召回范围（过滤条件与预算）、维护范围（单次任务的对象数上限）与时间范围；作用范围在交还中如实呈现，不扩大到未操作范围。

### 6.6 退出与转交条件

1. 当次动作完成收口：写入已回读 / 召回已交付（含 partial 如实标注）/ 晋升已确认或已退回 / 维护任务已收口或已 fail-closed 入队 / 反思意见已交还；
2. 候选认识有明确去向：git 对象、本地条目、不记（附判定依据）或转交其它系统（如证据不足的调研需求 → 30）；
3. 触发 Human Gate 尚未回应时（晋升确认、锁定解锁）→ 暂停受影响条目并交还（00 §4.2）。

## 7. 输入与前置条件

### 7.1 必需输入

1. 当次会话上下文中的候选内容及其来源定位（哪个对话回合/哪个对象事件——本地层 source 弱回指的素材）；
2. 写入时：目标层的载体可用性与格式契约（本地层 Helper 格式校验 / git 层受控入口）；
3. 晋升时：目标类型的必填字段契约（20–27）与 Human 拍板入口可达性；
4. 召回时：当前任务的过滤条件（scope/类型/关键词）与预算。

### 7.2 可选输入

已有条目集合（四操作比对）、命中历史（攒熟判定的 confidence 与反复命中证据）、Human 明示偏好（origin=user 天然更够格晋升）、F0 恢复边界（会话启动体检的基线）。

### 7.3 来源

对话流（主控观察/Human 明说）、事实对象生命周期事件（retired/discarded/superseded 等触发反思）、宿主事件（空闲触发点，08 承接）、Web 管理面（Human 操作）、预检落实记录（召回结论的承载）。

### 7.4 缺失和冲突处理

载体不可用 → 04 §8 降级（缩小范围/暂停交还），不得静默丢弃或声称已记；候选证据不足 → buffer 攒熟；两条目矛盾 → 四操作比对提示"替换还是并存"，不自动改（§8.2）；影子断链 → partial 交还并登记（§8.6）。

## 8. 记录、召回与晋升（过程机制锚点章）

**十项之 5 归属标注**：本项"过程机制与分支"由本章（锚点）与 §5（分诊）、§9（本地层契约）、§10（空闲维护）、§11（反思）共同承载——§5 定去向判据，本章定记录与取回的机制与分支，§9–§11 定两层各自的契约与后台机制。

### 8.1 记录触发（三路）

| 触发 | 机制 | 先例依据 |
|---|---|---|
| **主控随手记** | 对话中发现候选 → 当场分诊 → 工具直写（git 层则走即时检测提议，见 §8.5 路径 A） | mnemon 主控工具随手记 |
| **空闲评审代理** | 对话检查点结束后保守回顾，产出提案不直接写 git | mnemon 空闲评审（§10.2） |
| **容量维护代理** | 容量满时只整理不新增（压缩/归档/TTL 淘汰） | mnemon 容量代理（§10.3） |

### 8.2 主控随手记与四操作比对

随手记的标准第二动作——**写入前四操作比对**：先查既有条目集合，判定新内容是新增/修正/矛盾/重复（Mem0 四操作决策的人工闸门版：它用独立 LLM 自动做，LDVH 由主控顺带做，无新增闸门）；**矛盾时必须提示"替换还是并存"**，不自动改（sgme 矛盾检测先例；preference 类最需要——偏好变更不应矛盾共存）。随手记写入过 Helper 格式校验（必填/闭集/非空/source 必填，fail loud 只管格式不判语义）。git 层写入不经随手记通道——必须走 §8.5 晋升（含即时检测）并经 Human 拍板。

### 8.3 双路召回

- **git 侧**：消费 03 §8 的 F0–F4 分层召回，不另建检索机制；召回时机、默认候选状态与展开范围按各类型规范（22 §12 义务召回原则、23 执行前预检、24/30 调研查重、26 §9 攒账查重）；
- **本地侧**：零依赖启发式检索（tokenize + Jaccard + 加权评分 base×importance×recency×access，CJK 单字+双字分词参照 agent-memory 先例）+ scope 过滤（当前项目条目 + global 兜底）；
- **注入顺序与预算**：两路各自独立、各自预算；预算冲突时 git 优先占坑；内容冲突时 git 赢（本地层是弱权威）；
- **命中依据义务**：本地侧每次召回注入附命中依据（匹配字段与分值），与 git 侧 F2 候选发现的命中依据对称（防自欺——noema explain 先例）；
- **热集与动态召回**：热集常驻（按 type×scope 挑选）+ pre-step 动态召回（当前用户消息作 query 检索 top-N）；记忆协议文本进系统提示、易变内容进消息流（防缓存失效）。

### 8.4 预检式召回编排（主动防线）

记忆系统是主动防线而非被动仓库。本节统一编排"什么时机必须召回什么"，与 04 §7.2 预检落实记录的"已召回"区衔接；各类型的召回原则回指其类型规范，本文不重复定义：

| 行动场景 | 必须召回 | 原则来源 |
|---|---|---|
| 方案/决定形成前 | 相关 active ADR（防矛盾决定） | 22 §12 义务召回原则 |
| 执行/写入/提交前 | 触及失败机制域的 active Pitfall（防重蹈覆辙） | 23 |
| 发起调研前 | 既有 Research（防重复调研） | 24/30 |
| 摩擦检测周期 | open+deferred Friction 账本查重 | 26 |
| 沉淀/晋升提议前 | 目标类型既有对象（防重复入档） | 20–27 各自的查重条款 |

触发成立而召回入口不可用时，按 00 §7.2 与 04 §12.1 第 6 项处理（预检缺失不得进入受控执行）；未触发的场景在预检落实记录中标记"未触发"，不得把未遍历写成已核对。

### 8.5 晋升通道（本地 → git）

| 触发路径 | 机制 | 先例 |
|---|---|---|
| **A 即时检测** | 主控在对话中发现内容够格（有证据、项目相关、跨会话有效）→ 当场提议"建议记录为事实对象"→ Human 拍板 → 直接入 git（不落 buffer） | mnemon 读时判断的升级 |
| **B 攒熟提议** | buffer 条目 confidence 高 + 被反复命中 + source 可回指 → 空闲评审时提议 | noema reviewed 态 / sgme 蒸馏 |
| **C 摩擦检测** | 同一错误/摩擦出现 N 次（默认 3，可配）→ 提示主控"该记了"（**提示不自动写，闸门在 AI 手里**） | agent-memory 错误计数 |

晋升**写原文非摘要**；晋升后本地条目**留影子**（§8.6）。**Human 拍板双入口**（Human 决定 2026-09-10）：Web 确认卡（主面——原条目 + 溯源 + 拟落类型 + 确认/拒绝，10 承接）+ 会话内问询通道（即时提议即时决，DSH 问询机制）；主面不等于唯一面。反向无仪式：本地记忆错误直接删，无审计负担（§9.6）。

### 8.6 晋升格式转换与影子（候选设计，待审核确认）

- **格式转换**：主控在提议时按目标类型规范补全必填字段全集（从 buffer 条目与当次上下文取材）；**缺项即提议 fail loud**，不得留占位符、不得由 Code 静默补默认值；
- **影子语义**：本地条目晋升后追加 `promoted: <object_uid>`；影子**不参与召回**；影子存 uid 不存状态——消费侧解析发现对象已退休/断链时按 partial 交还并登记修订信号，影子本身不自动更新（最保守设计；"superseded 链上影子是否联动更新"登记为开放问题，见附录 A.5）。

### 8.7 失败分流

随手记格式校验失败 → fail loud 修复后重写，不得静默降级；晋升缺项 → 拒绝提议退回攒熟；召回超预算 → 分页/partial，不静默截断；本地载体不可用 → 04 §8 降级序列（缩小范围→暂停交还）；空闲任务校验失败 → fail-closed 入队（§10.6）。

### 8.8 停止位置

本系统流程的停止位置：分诊受众无法判定且连"是否该记"都无依据（§6.4）；晋升证据不足；影子断链且消费需要其当前状态；Human Gate 未回应（晋升确认/解锁）；本地载体写入无法回读。领域停止条件全集见 §19。

## 9. 本地层契约（过程机制衔接章之二）

### 9.1 载体与条目结构

载体：DSH storageDomain（跨项目共享、不进项目 git、不随项目 clone 而去）。条目 = frontmatter 索引 + 正文 Markdown（≤2000 字符）。运行时记账 accessedAt/accessCount 不进 frontmatter（召回命中时更新，效用审计信号）。

条目 frontmatter 字段（闭集）：

| 字段 | 取值/约束 | 语义 |
|---|---|---|
| id | 机械生成，全局唯一 | 条目身份 |
| type | preference / pattern / fact / buffer / note（五类闭集） | §9.2 |
| title | 一句话 | 人可扫读 |
| tags | 可选，小写 | 辅助过滤 |
| scope | global / project（scope=project 时 project 必填） | 受众的本地面 |
| confidence | high / medium / low | 晋升成熟度信号 |
| importance | 1–3；=3 受容量淘汰保护 | 淘汰保护 |
| source | 必填，弱形式回指（如"2026-09-10 会话·一句话上下文"） | 溯源下限 |
| origin | user（用户明说）/ agent（AI 观察） | 用户明说天然更够格晋升 |
| created / updated | ISO8601 | 时间 |
| expires | 可选 TTL | 衰减 |
| locked | 布尔；true 时 AI 只读不可改删（容量淘汰也跳过） | **Human 决定权的本地层落地（Letta read_only 先例）** |
| promoted | 晋升后追加，git object_uid | 影子（§8.6） |

### 9.2 类型五类语义

preference 工作偏好（怎样协作）；fact 环境/机器/工具事实；pattern 跨项目个人模式；buffer 未成熟的项目观察（晋升候选池，scope=project）；note 其余。**不含状态类**——跨会话接续状态由 DSH 会话历史 + Output Envelope 承载（Human 决定 2026-09-10）。

### 9.3 治理参数（默认值，变更走 §18 Human Gate）

| 参数 | 默认值 |
|---|---|
| 容量上限 | 400 条 |
| 近重复合并 | Jaccard ≥ 0.7 |
| TTL 默认衰减率 | preference/fact 180 天；pattern/note 90 天；buffer 30 天（条目可显式覆盖；sgme time_velocity 的简化版） |
| 淘汰保护 | importance = 3 与 locked 跳过 |
| 摩擦检测阈值 | 同一错误 3 次触发提示（可配） |

### 9.4 检索与召回契约

见 §8.3 本地侧。**不上向量**（远期最轻升级路径 sqlite-vec 为非承诺的候选方向，不是规范义务）、**永远不上量化**——插件级千条量级的工程记忆被六项目调研证明不需要（检索技术光谱：上向量的全是引擎/服务端形态）。

### 9.5 无举证义务与不对称治理

本地信息不用保留、不用举证：不保留原始对话（不采纳 sgme 式 L0 归档）、source 保持弱形式回指即可、删除无审计负担。**举证是 git 层的职责**（Research 溯源锚点、Pitfall 证据链）——不对称治理：本地层宽进轻出，git 层严进严出（Human 决定 2026-09-10）。

### 9.6 locked 保护

locked 条目 AI 只读不可改删、容量淘汰跳过；锁定与解锁均须 Human（§18）。锁定是 Human 对本地内容的决定权落地，不使条目取得规范效力或事实地位。

## 10. 空闲维护与记忆健康（过程机制衔接章之三）

### 10.1 宿主闲置任务对齐（根纪律）

空闲评审代理、容量维护代理与记忆健康体检均属**宿主闲置发起的辅助任务**：没有主控，不能自行执行暂停与恢复判断；其机械校验必须自带失败处置——任一校验不可用、未通过或写入未能完整回读时，一律 fail-closed：停止该次任务、保留已发生副作用并如实登记、不继续、不自行重试、不把部分写入当完成；停止原因与残留范围进入待处置队列（跨会话留存、下一主控接管或 Human 查阅时必然可见），未完成核查前受影响对象不得被当作稳定记忆消费（00 §7.2 宿主闲置纪律全文适用）。

### 10.2 空闲触发表达（候选设计，待审核确认）

DSH 无 cron 与独立定时设施，"空闲"表达为**宿主事件锚点**（具体事件可用性由 08 承接，属实现现状按读取时观察取得）：

1. **会话检查点事件**（对话回合稳定点后的钩子）——空闲评审与容量维护的主触发；
2. **会话启动**（恢复边界检查的扩展时机）——记忆健康体检与待处置队列清点的触发。

三任务（评审/容量/体检）共用触发点、按预算轮换：评审优先、容量次之、体检周期性（如每 N 次触发一次）。任一触发点的任务预算用尽时顺延至下一触发点，不堆积执行。

### 10.3 空闲评审代理（保守纪律）

对话检查点结束后保守回顾：**默认不变更**、**每次至多一条变更提议**、**只认真人明确断言**（推断偏好/AI 断言/可重新发现的事实不记——门 0 纪律复用）；产出仅提案（晋升提议/修正提议/摩擦入账提议），git 层写入必须再经 Human 拍板（§8.5），本地层修正走四操作比对提示。与 git 层"空闲时自动维护记忆健康"（02 §14）共用同一空闲钩子。

### 10.4 容量维护代理

容量满时只整理不新增：压缩、归档、TTL 淘汰、Jaccard 合并；importance-3 与 locked 跳过（§9.3）。

### 10.5 记忆健康体检与效用审计（最小形态候选，待审核确认）

**四失败模式体检**（Letta Context Constitution 失败模式的移植）：

| 失败模式 | 体检信号 |
|---|---|
| 忘写回（该记没记） | 分诊判"该记"却查无条目/对象；摩擦重复计数上升 |
| 囤积（不该记记了） | 门 0 拦截率下降；buffer 长期不晋升；低 access 死条目占比 |
| 塞系统提示（注入过载） | 召回预算超限频发；无关命中进入热集 |
| 加载无关（召回失准） | 命中依据审计发现低相关命中占比高 |

**效用审计最小形态**：输入 = 本地 accessCount/accessedAt 冷热 + 晋升记录（谁晋升、git 对象 uid）+ git 对象消费信号（候选：Git 提交 message 引用 object_uid 作为消费信号、Git Gate 机械可统计——实现属 06 扩展，当前未建，登记为开放问题见附录 A.5）；产出 = 体检结论 + 冷热清单 + 晋升-消费对照，随空闲周期进入 Web 审计视图（10 承接）或交还附件；频率 = 空闲周期触发，规范实质修订或类型退出后强制一次。**审计产出不证明价值成立**，只提供可观察证据（00 §6.3 价值纪律：尚无充分证据支撑的价值声明必须保留缺口）。

### 10.6 条件式要求（镜像 02 §16）

本系统空闲维护机制须按本章执行；**在其候选识别、调度与 fail-closed 纪律实际具备之前**，不得据本文主张空闲维护已运行、记忆健康已被自动维护或效用审计已产出，HV4 效用亦不得据此声明改善。机制是否已实际具备属实现现状，按 01 §7.2 由读取时的观察取得，本条不陈述其当前状态。

## 11. 反思机制（过程机制衔接章之四）

### 11.1 反思触发

1. **事实对象生命周期事件**：对象 retired/discarded/superseded 时，检查引用它的本地条目与影子是否需要修订（断链信号）；
2. **规范实质修订**：受影响认识（与修订规范相关的 preference/fact/pattern 条目与知识类对象）的复核；
3. **Human 要求**：直接发起的复盘；
4. **空闲周期体检**：四失败模式发现相关信号时（§10.5）。

### 11.2 修订意见的承载与边界

反思产出**修订意见**而非变更本身：意见必须可回指依据（触发事件、受影响对象、复核证据）；git 层对象的修订走各类型规范的受控更新程序（CAS + 按类型要求的 Human 决定），本地层条目的修订走四操作比对（矛盾提示替换/并存）；修订通道不可用（locked/类型规范缺位/证据不足）时暂停受影响消费并交还（§19 第 7 条）。反思结论不自动生效（02 §14 边界原文）。

## 12. 结论承载与回写

### 12.1 git 层承载

本系统以七类事实对象（20–27）按 §5.4 性质路由承载项目侧结论；是否写入由各类型规范的准入与 03/06 的受控写入程序决定，晋升提议经 §8.5 三路触发与 Human 拍板后由受控创建入口落盘并精确回读。本规范不定义各类型的字段与状态机。

### 12.2 本地层承载

本地层以条目自身承载结论（frontmatter + 正文，§9.1）；写入过 Helper 格式校验并写后回读；晋升后条目转为影子（promoted 指针，不参与召回）。

### 12.3 回读要求

本地层每次写入必须写后回读（防自欺锚点）；晋升的 git 对象经受控创建后精确回读（03/06 程序）；召回交付附命中依据（§8.3）。

### 12.4 不承载结论的显式说明

分诊判定本身、召回交付本身、体检报告本身不产生结论对象——它们分别以交还说明、召回响应（含 partial/unavailable 边界）与审计视图承载；不为本系统另建"记忆结论"事实类型。

## 13. 风险路由与预检要求

### 13.1 默认风险层：快通道

本系统默认风险层为**快通道**（04 §6.1 第 1 层）。理由：常规动作（随手记、召回、读取、单条维护）低风险、高度确定、动作模式固定且机械闸门完备（格式校验 fail loud、locked 只读、git 写入必经受控入口 + Human Gate、越权动作被机械拒绝——HV2 判据）；本地层轻治理设计本身即按低风险定位。**审核重点登记：本系统是首个声明快通道默认的业务系统规范（30/31 均为标准路径），其适用与排除条件的完备性须由对抗审核确认（附录 A.2）。**

### 13.2 最低预检覆盖（04 §6.2 三段判断的具体化）

1. **生效**：本地层载体可用（storageDomain 可写）且当前治理/会话状态已知；git 层操作时项目受管辖；
2. **适用**：门 0 已核对未命中；受众判定完成或默认方向适用；type 在闭集内；scope 正确；
3. **行动允许**：记录在主控责任范围内且不产生规则/授权；locked 条目只读；格式契约满足。

已成立的事实召回时机仍必须按相应来源完成所需召回（§8.4 触发清单）——快通道不豁免召回义务。

### 13.3 升级触发（环节级，04 §6.3 对应）

以下环节必须从快通道升为标准路径（该环节前置的不落档环节不回溯失效）：晋升提议与任何 git 受控写入；批量操作（淘汰/合并/TTL 清理超过单条、跨 scope 迁移）；locked 涉及环节；治理参数变更；记忆相关规范修改；空闲任务产出需 Human 决定的提议。凡产出带明确取舍倾向的结论（推荐方案、定案建议）即属定论而非探索，须按标准路径完成预检（04 §6.3 判据原文适用）。

### 13.4 降级路径

引用 04 §8 全部条款：缩小范围→风险重分类（须登记依据）→切换系统或技术→暂停交还；能力不足分流不是风险降低证明；不得以降级为由跳过已触发的召回义务或把 partial 表达为完成。

## 14. 交还

记忆活动的交至少包含：当次记忆活动摘要（记录了什么/召回了什么及命中依据/提议了什么晋升/执行了什么维护）；已验证范围（回读成功的写入、附依据的召回）与未验证范围（partial、未触发标记、载体不可用）；残留风险（影子断链、矛盾未决、buffer 积压）；待 Human 决定事项（晋升确认、解锁、参数变更）；继续入口（过滤条件、分页游标、待处置队列位置）。交还沿用 00 §7.4 结构与 04 §5.5 三层评测（流程完成层/验证通过层/交还承接层），不混用。

## 15. 与相邻系统及能力的边界

### 15.1 与相邻业务系统的分工

- **调研（30）**：调研前查 Research 防重复（§8.4）；调研结论的沉淀去处在调研系统自身结论承载（30 §13）与本系统 §5.4 路由的交集上以类型规范为准；本系统不执行调研。
- **讨论（31）**：讨论的四路分流中进入沉淀方向的产物按 §5.4 路由；本系统不执行方案收敛。
- **工单执行（32）**：工单结论回写后的沉淀衔接同 §5.4；本系统不执行工单。
- **规则遵守（33）**：预检式召回的触发清单（§8.4）为遵守预检供给"已召回"区内容（04 §7.2 格式）；遵守判定本身归规则遵守系统。
- **目标与蓝图（34）**：Goal 的确立与修订走 34/25 程序；修订触发的反思归本系统（§11.1）。
- **Friction（26）**：Friction 的出生路径触发器（空闲评审捕捉、摩擦检测阈值）由本系统 §8.1/§10.3 承载（26 §3.2 指向本文）；账本本身的契约归 26。

### 15.2 与能力承载的分工

读 = git 侧 F0–F4（03）+ 本地侧启发式检索（§8.3）；写 = git 层受控写入（03/05/06）+ 本地层 Helper 格式校验写入（05 承载入口形状）；编排 = 空闲触发调度与维护代理的宿主机制（02 §8/08）。本系统不建第二套读写通道。

### 15.3 与制度的分工

主控自查：随手记的四操作比对与晋升提议的依据核对是主控自查在本系统的落点；独立复核：晋升提议与规范级变更按 01 §12 对抗审核；机械校验：格式校验、locked 拒绝、容量参数、命中依据附随由 Code 承载（09）。

### 15.4 与相近概念的区分

- **记忆 ≠ 事实源**：事实源是项目稳定信息的当前内容承载（03）；记忆系统是其上层的分诊、召回编排与维护机制——git 层记忆条目即事实对象，但"记忆系统"不等于"事实源"。
- **记忆 ≠ DSH 会话历史**：会话历史是宿主的对话留痕；记忆是经分诊判定值得跨行动保留且已落稳定载体的内容；单会话状态不记（门 0）。
- **记忆 ≠ Output Envelope**：Envelope 是交还语义的结构（00 §7.4）；其内容需要跨行动保留的部分经本系统分诊落位。
- **记忆 ≠ 上下文管理**：上下文压缩/预算/预热是宿主机制（03 §8 事实预热条款的边界适用）；本系统只供给带来源与命中依据的候选。
- **本地层记忆 ≠ git 事实对象**：受众、治理强度、举证义务、容量与生命周期全部不同（§5.1）；影子是单向指针，不构成双向同步。

## 16. 完整性承诺与管理面（系统扩展，04 §9.3 扩展规则 2）

本章为系统扩展，不挤占十项必填结构。

### 16.1 独占记忆职责承诺（Human 决定 2026-09-10）

两级门设计使本系统覆盖全部记忆需求的信息流——任何候选信息都有去处（git 七类 / 本地五类 / 不记），用户安装 LDVH 后不需要第二个记忆系统：USER.md 式画像 → 本地 preference（且多 origin 语义）；项目工作记忆 → 本地 fact/buffer + git 层；项目文档 → git 层事实对象（完整治理）；持久库 → git 层（clone 即继承）。本系统不提供的（向量/图/多后端）恰是这个量级工程记忆被调研证明不需要的。**该承诺的验证属实现现状**：在双路召回、晋升闭环与空闲维护实际具备并经 dogfood 验证前，不得据本节声明独占已成立（§10.6 条件式要求适用）。

### 16.2 管理面双通道（Human 决定 2026-09-10）

Web UI 是人的主管理面（记忆列表/详情/晋升确认三页与审计视图，10 承接——对齐其四层阅读器与授权流）；工具面是 AI 的面（记/查/删及晋升提议，05 承载入口形状）。**Web 写操作与 AI 工具写操作过同一道 Helper 格式校验**——单一闸门不因入口分叉。对话内轻交互（回合尾记忆活动提示）与 git 层关系图为 10 号扩展项（方向已确认：三类节点/两视图/确定性哈希布局），本规范只登记方向，不在本文展开。

### 16.3 V1 最小集与 dogfood（Human 批准默认值 2026-09-10）

V1 最小集：三页（记忆列表/详情/晋升确认）+ 三命令（记/查/删）；摩擦检测阈值 3 次（可配）；空闲评审代理默认开启、可关闭。dogfood 验收标准（候选，待 Human 确认）：LDVH 自身仓库为第一个用户——真实开发会话中发生≥1 次完整晋升闭环（buffer/即时 → 提议 → Human 拍板 → 受控创建 → 影子登记 → 后续召回消费）、四失败模式体检至少跑通一轮且产出可读报告、待处置队列对一次注入的失败任务完成 fail-closed 演示。验收前 §16.1 承诺保持缺口状态。

## 17. 验证与证据边界

| 验证对象 | 验证时机 | 成立条件 | 可接受依据 | 验证入口 | 可证明范围 | 未满足时的处理 |
|---|---|---|---|---|---|---|
| 受众分诊判定 | 每次记录/晋升提议前 | 三道门核对完成、受众归属明确或默认方向如实适用 | 分诊结论与主轴回指 | 主控语义判断（机械辅助为候选扩展，附录 A.4） | 当次条目/提议的去向判定 | 错入 git 的候选走对象退休流程；错留本地的可删——判定错误不因后续流程完备而追认 |
| 本地层写入 | 每次写入 | 字段闭集合法、必填齐备、source 非空、写后回读一致 | Helper 格式校验结果 + 回读内容 | 机械校验 + 回读 | 当次条目格式与载体一致 | fail loud 修复后重写；不得静默降级或丢弃 |
| 四操作比对 | 本地层写入前 | 既有条目集合已查询、操作判定（新增/修正/矛盾/重复）完成 | 比对结论随写入留存 | 主控自查 | 当次写入与既有集合的关系 | 矛盾未提示即写入按反逃避信号处理（04 §5.3） |
| 双路召回 | 每次召回交付 | 命中依据附随、预算内、partial/unavailable 如实标注 | 召回响应（匹配字段与分值） | 召回响应核对 | 当次候选范围与未检查范围 | 超预算分页或 partial，不静默截断 |
| 预检式召回触发 | 受控执行前 | 触发清单命中场景的召回已完成，或如实标记未触发 | 预检落实记录已召回区（04 §7.2） | 记录回读核对 | 当次预检的召回完成范围 | 未触发补标记或补召回；入口不可用按 00 §7.2 暂停 |
| 晋升 | 提议与执行时 | 三路触发条件成立、目标类型必填字段全集补全、Human 拍板取得 | 提议对象 + 确认记录 + 受控创建回读 | 受控入口机械校验 + 回读 | 当次晋升成立与影子登记 | 证据不足退回攒熟；缺项 fail loud 拒绝提议 |
| 空闲维护任务 | 每次任务 | fail-closed 纪律执行、停止原因入队、不自行重试 | 待处置队列登记 | 队列回读 | 当次任务范围与残留 | 停止 + 登记；受影响对象在核查前不作稳定记忆消费 |
| 容量淘汰与合并 | 维护执行时 | 参数合规、importance-3 与 locked 跳过、Jaccard 阈值满足 | 淘汰/合并记录 | 机械校验 | 当次清理范围 | 越界动作机械拒绝并登记 |
| 反思修订意见 | 反思产出时 | 可回指触发事件与受影响对象、修订通道合规 | 意见及其依据 | 主控自查 + 类型规范受控更新校验 | 当次意见及其依据范围 | 通道不可用时暂停受影响消费并交还 |

机械结果与语义判断互不替代；本章不能单独证明受众判定正确、记忆内容适用、效用成立或独占承诺兑现（§16.1/§16.3 缺口纪律）。本章不建立价值审计报告或过程留痕工件（04 §13 红线 4）。

## 18. Human Gate

本文不新增 00 之外的根级 Human Gate 类型；以下为 00 §4.2 在记忆领域的增量事项（领域具体化）：

1. **晋升确认**：本地候选（buffer 攒熟/即时检测）→ git 受控对象的每次晋升须 Human 拍板（双入口：Web 确认卡主面 + 会话问询通道；路径 A/B/C 触发的提议均须确认）；
2. **locked 锁定与解锁**：锁定为 Human 动作，解锁须 Human（locked 条目 AI 只读）；
3. **类型闭集与治理参数变更**：本地层五类闭集的增删、容量/TTL/阈值/衰减率默认值的变更；
4. **架构级边界变更**：引入并存的其他记忆系统、本地层承载形态（storageDomain 之外）变更、双层架构调整；
5. **重大清理处置**：效用审计产出的大规模清理建议（超过单次维护预算的批量删除/归档）的执行决定；
6. 规范、类型规范与事实对象修订中按其自身来源要求须 Human 决定的事项（如 Norm 创建、ADR 决定、Goal 修订），本节只回指不重复登记。

Human 决定只证明决定及其作用范围，不替代受众判定、格式校验、回读结果或效用核对；晋升经 Human 确认不证明晋升内容正确或有长期价值。

## 19. Stop Conditions

本文不新增根停止类型；以下为 00 §7.2 在记忆领域的增量触发（出现任一情况时，暂停受影响的最小条目、提议、召回交付或维护任务范围）：

1. 晋升证据不足（source 不可回指、confidence 不足、验证缺失）却准备提议 → 暂停晋升，退回攒熟路径；
2. 影子指向的 git 对象已退休/断链且当前消费需要其状态 → 按 partial 交还并登记修订信号，不静默跳过；
3. 受众判定无法确认且连"是否该记"都无依据 → 不记并在交还中说明，不得按名称相似强行归类；
4. 本地载体不可用或写入无法完整回读 → fail loud 停止该次记录，按 04 §8 降级交还，不得静默丢弃或声称已记；
5. 空闲任务任一校验不可用、未通过或写入未完整回读 → fail-closed：停止、登记待处置队列、不自行重试、不把部分写入当完成（00 §7.2 宿主闲置纪律）；
6. 预检式召回触发成立但召回入口不可用 → 按 00 §7.2 暂停受影响的受控执行（预检缺失不得进入受控执行）；
7. 反思发现既有认识可能失效但修订通道不可用（locked/类型规范缺位/证据不足）→ 暂停受影响范围的记忆消费，交还修订提议。

暂停期间允许不越过停止边界的来源定位、事实核对、证据收集与分流准备。恢复与触发原因对应且只覆盖当前依据支持的范围；同一停止条件恢复后再次触发时按 00 §7.3 进入 Human Gate。

## 20. 反过度设计红线

1. 不建投影层或服务端真值——文件即真值：本地 storageDomain 即载体，git `ldvh-base/` 即真值；不引入 MemFS 式服务端投影；
2. 不引入独立服务进程、存储后端或运行时依赖——深度绑定 DSH 原生 storageDomain 与事件机制（00 §3.4 零运行时依赖）；
3. 不上向量检索与量化（V1）；sqlite-vec 为远期非承诺的候选升级路径，不是规范义务；图记忆实测增益（~2%）不支持其标配化；
4. 不上无人工闸门的自动提取流水线——git 层一切写入经 Human 拍板，本地层随手记经主控四操作比对；Mem0/sgme 式全自动 ADD/UPDATE/DELETE 与"AI 不可靠"根判断相反；
5. 不本地归档原始对话、不为本地层建举证链——举证是 git 层职责（不对称治理，§9.5）；
6. 不为本地层建关系图或关系字段（V1）——本地层关系稀疏、量级不值；关系是 git 层的语义骨架（frontmatter relations 受控写入的内建产物）；
7. 不新增 git 对象类型承载"正面可复用模式"——确无家可归时按 01 §11 程序另议，不预留空位（04 §13 红线 8 同向）；
8. 不把条目数量、召回命中次数、晋升数量或 accessCount 单独写成效用证明——效用须有消费对照与可观察效用（00 §6 HV4 判据）；
9. 不复制 03 的 F0–F4/受控写入、04 的五机制/风险层/预检格式、05 的 envelope、06 的提交契约、08 的事件接入、10 的呈现细节、22–27 的类型契约——一律回指（04 §13 红线 7）；
10. 不把记忆条目、影子或体检报告写成规则、授权或完成结论的来源——记忆留存不自动产生规则或授权（00 §3.1 根边界）；
11. 不为记忆活动建独立审计账本或过程留痕工件——防自欺锚点为格式校验结果、写后回读、预检落实记录（04 §7.2）、change_log（git 层）与待处置队列（空闲任务）；
12. 不把容量判据（"满了才溢出"）当作分界权——受众判据是主动的，字节数只是维护信号（mnemon 反例的规避）。

### A.1 本地层的根职责张力（最高优先审核项）

### A.2 首个快通道默认系统

30/31 均为标准路径；35 选快通道的正当性依赖"常规动作低风险高确定 + 机械闸门完备"的判断。审核点：适用/排除条件是否覆盖"记忆污染项目判断"这一慢生效风险（错记一条 preference 的伤害是渐进的，快通道的最低预检是否足以拦截）；C 路径摩擦检测的误报与阈值合理性。

### A.3 设计文档遗留的三个对抗审查项

晋升影子与 git 权威漂移（影子不自动更新的最保守设计是否够用）；scope 过滤的失败场景（global 条目在多项目间的内容串扰）；三路触发的相互干扰与重复记录（即时检测与攒熟提议的竞争条件——同一内容两路同时触发时的幂等性，当前设计靠 Jaccard≥0.7 合并兜底）。

### A.4 信息分诊门的机械可实现性（设计文档第六节第 4 项）

门 0 三条中仅部分信号可机械辅助（单会话状态检测、会话历史可查性、规范源文本命中）；受众主轴全语义判断。候选方案：把门 0 做成主控可执行检查清单 + Helper 机械预检（可机械部分），语义部分留主控。未决：是否值得为机械部分扩 Helper 操作（YAGNI 权衡）。

### A.5 三个未闭合的实现侧设计（登记为缺口，不冒充已决）

1. **git 对象效用信号**：候选为 Git 提交 message 引用 object_uid 作消费信号、Git Gate 机械统计——需 06 扩展，当前未建；
2. **影子与退休对象联动**：superseded 链上影子指针是否跟随更新——本文取最保守（不联动、消费时发现断链按 partial 交还）；
3. **空闲触发事件可用性**：DSH 当前是否提供会话检查点事件与启动事件属实现现状（08 承接）；未具备前 §10 整章按条件式要求处理。

### A.6 dogfood 验收标准的候选性

§16.3 的验收标准（晋升闭环一次 + 体检一轮 + fail-closed 演示一次）为本文起草的候选，未经 Human 确认；V1 最小集与默认参数（三页三命令、阈值 3、评审默认开启）为 Human 已批（2026-09-10），两者状态不同，不得混同。
