# ADR-决策

## 1. 价值判断

ADR 解决已定决策随对话消散、以及决策缺乏持续约束力的问题：一个架构取舍当时为什么这么定、认真考虑过什么备选、为何落选、接受了什么后果、边界在哪——这些内容若只存在于会话记录或散落文档，后续每一次方案工作都无法对照同一份决策依据，重复争论已定之事、无意间违背既有决策、或在故障调查时找不到「当时否过什么」（00 §1 痛点 4「历史经验与教训，无法积累」）——后果段在案与否，正是故障追责时「已知成本」与「设计盲区」的分界线。**ADR 是对 AI 具有持续约束力的法定效力决定（Human 决定）：一经生效，AI 在一切相关环节必须贯彻——设计遵守、实现遵守、写入遵守、提交遵守；违背 active ADR 的行动视同违背规范源。** ADR 以知识层对象承载法定决定：回溯记录、前瞻约束——行动前预检与方案收敛时被义务召回并核对，决策本身不再被重新裁决。普通文件不能无损承载：无受控写入、无状态闭集（active/retired 无从机械判定）、无方案收敛的引用契约（违背淘汰须记录「哪条 ADR」）。Spark 是方向的容器（决定未结晶前住在方向主线里）；Research 是外部证据的调查（支撑决策但不承载决定）；Pitfall 是教训规避（「别这么做」不是「为什么这么定」）。本规范主要服务核心价值一（项目可厘清，00 §1.1）：ADR 把「当时为什么这么定、考虑过什么备选、为何落选、接受了什么后果、边界在哪」固化为可回指的唯一决策载体，使同一个取舍依据在后续每一轮方案收敛中被定位到同一处，而不是凭记忆重建；兼服务核心价值二（任务高效准确完成，00 §1.2）：方案收敛淘汰与遵守预检以「哪条 ADR 的 decision/scope」为可回指依据，使违背已定决策在方案阶段即被发现。本文不以全量价值声明替代主要影响判断。

ADR 对象存在、处于 active 或形成决策谱系，均不能单独证明决策正确、仍然适用或被实际遵守——决策的价值须在后续装配、预检与故障调查的真实消费中核对。ADR 不承载「接下来做什么」（裁定 6：前向规划属前向层），不替代 Human 决定权（决策的作出与废除始终是 Human 权限，ADR 只承载已定决策的记录）。

4. Human 作出或废除决策的过程（00 §3 承载——ADR 记录已定决策，不产生决策）；
5. Web 呈现的视觉与交互细节（10 号承载）。

### 3.3 相邻规范分工与唯一权威

02 是公共字段、关系与受控读写契约的唯一权威；09 是受控提交契约与 Git Gate 的唯一权威；06 是 Code 实现的唯一权威；23/24 分别是 Pitfall/Research 类型语义的唯一权威。本文只定义 ADR 类型自身的边界、字段、状态、关系与消费点，不复制相邻规范的规则。

## 4. 适用范围

### 4.1 适用对象与场景

1. 管辖项目中的多例 ADR 对象（`ldvh-base/adrs/`）；
2. ADR 的决策记录、备选理由、适用范围与证据引用。

本规范用于 ADR 的创建（主控方案收敛分流到已定决策、Human 直接裁定后记录）、查重、勘误级更新、终态流转（废弃/被替代）与消费（方案收敛装配、遵守预检、审议上下文、故障调查）。

### 4.2 明确排除与证明边界

明确排除：未定方案（走 Spark 悬置，决策形成前不该有 ADR）；执行计划（由主控在当次行动中承接，不对象化）；外部证据调查（走 Research）；教训与规避（走 Pitfall）；对话中的临时取舍（重要性不足以对象化的留在会话记录）。ADR 对象存在或状态为 active，不能单独证明决策正确、适用、被遵守或已被消费——这些须由装配、预检与故障调查的真实使用核对。

## 5. 类型定位与价值

ADR 是知识层的法定效力类型：承载对 AI 具有持续约束力的已定决定，供前瞻约束与回溯审查。三层分工中它与 Pitfall、Research 同层——「回溯记录、前瞻约束」，不承载「接下来做什么」（裁定 6）。

- **与 Spark 的差异**：Spark 是方向主线（宽入口，一切的起点），ADR 是方向中结晶出的法定决定（窄出口）——同一个主题，方向住在 Spark，结晶出的每条可独立贯彻的必须提取为 ADR；
- **与 Research 的差异**：Research 调查外部世界形成证据，ADR 用证据（可能含 Research）作出并记录决定；
- **与 Pitfall 的差异**：Pitfall 承载「什么会出错、怎么规避」，ADR 承载「为什么这么定、否过什么」。

按 02 §6.2 准入六问：跨行动保留——决策基线必须跨会话稳定，否则每次方案工作重新裁决已定之事；独立身份与状态——决策有 active/retired 与替代谱系，需要独立生命周期；普通文件不能无损承载——无受控写入、无状态闭集、无装配引用契约；消费价值服务 AI（装配/预检）与 Human（Web 决策库浏览、演进脉络追溯）双轨；维护成本——低频类型（v4 实证仅 2 例，业界 ADR 同为月级低频），净值为正；类型定义来源——本规范。

## 6. 对象边界

### 6.1 什么构成一个对象

一个 ADR 对象 = **一条可独立贯彻的法定效力决定**：决策陈述（decision）+ 适用范围（scope）+ 决策背景（正文）+ 备选与理由（正文）+ 已接受后果（正文）+ 证据引用（可选）。判据：决策必须可独立召回、**可独立检查遵从性**（任一相关行动能对照本条回答「守没守」——这是法定效力落地的粒度基础）、可独立违背（装配淘汰时能指向「哪条 ADR」）、可独立终态（被替代时单独 retired）。**粒度判据（Human 决定）**：对同一主题的多个松散决定，宁可拆成多条 ADR 也不打包一条——打包的决定集合无法逐条贯彻检查，等于没有效力。

### 6.2 查重

创建前必须查重：对照既有 active ADR 的 title/decision 语义比对（AI 语义判断，02 §9.2 不建立相似度自动裁决）。同主题决策已存在且仍然适用时，不新建（重复记录制造伪谱系）；已存在但决策实质变化时，走替代路径（新 ADR + 旧 retired），不改写既有 ADR 的决策语义。查重结论必须记录在创建提案中。

### 6.3 明确不属于本类型

开发计划与计划确认（意图与时序，由主控在当次行动中承接；**「计划被确认了」改变的是意图不改变规则**——计划变更无「违背」语义，无法逐环节检查遵从性，进 ADR 即稀释法定效力）；需求文档与方向叙事（方向主线由 Spark 承载）；未定方案（决策形成前不该有 ADR）；外部证据调查（走 Research）；教训与规避（走 Pitfall）；对话中的临时取舍（重要性不足以对象化的留在会话记录）；同一决策的表述精化（勘误级更新，非新对象）；同一讨论的多个独立决定（各自成对象，不捆成一个）；已被完整承接进规范源的可强制执行规则的决策（规则本身由规范源承载，ADR 可作为决策来源被引用但不再承担约束）。

## 8. 字段契约

frontmatter 闭集（分析性长文本一律住正文，frontmatter 只留薄索引——24 号定型原则：机器可验证性不得以牺牲分析空间为代价）：

| 字段 | 类型 | 必填性 | 语义 | 约束 |
|---|---|---|---|---|
| `fact_type_key` | string | 必填 | `adr` | 唯一合法值（02 §7.1 值域） |
| `object_uid` | UUIDv4 | 必填 | Code 生成 | 创建时落定，永不改变 |
| `title` | string | 必填 | 决策短标题 | ≤ 30 字；供候选定位与 Human 扫读 |
| `status` | string | 必填 | `active` / `retired` | 初态必为 `active` |
| `decision` | string | 必填 | 决定陈述 | 单句（句终符 。？！至多一个且若存在必须结尾，同 20 号 question 机械校验）；与正文字段分工见 §15.1（差异只报告不阻断） |
| `scope` | string | 必填 | 适用范围陈述 | 与正文字段分工见 §15.1（差异只报告不阻断）；何时适用/不适用由正文展开 |
| `trigger_signal` | string | 条件 | 重新审视信号 | 存在真实重审前提时写（如「当 X 出现时重审本决策」：版本发布、SG-4 落地、依赖变更）；无真实信号时省略（02 §7.1 条件字段——不得以占位文本伪造）；供遵守预检消费 |
| `urls` | array | 条件 | 支撑决策的外部 HTTP(S) 证据 | 出现时非空；`urls` 非空 ⇒ 正文「证据」段必填 |
| `relations` | array | 条件 | `superseded-by` / `absorbed-into`（见 §9、§11） | 仅终态 `superseded`（`superseded-by`）或 `absorbed`（`absorbed-into`）时可出现 |
| `retirement_reason` | string | 条件 | 终态原因 | 闭集：`superseded` / `absorbed` / `outdated` / `out-of-scope` / `abolished`；retired 必填、active 禁现 |
| `retired_at` | RFC3339 | 条件 | Code 填写 | retired 必填、active 禁现 |
| `created_at` | RFC3339 | 必填 | Code 填写 | AI 不得填写 |
| `change_log` | array | 条件 | 变更流水 | 首修后必有；每次恰好一条 |

不设 `context`、`alternatives`、`evidence` 等 frontmatter 字段——决策背景、备选与理由、后果叙述、证据叙述是分析主体，住正文（frontmatter 薄索引 + 正文主体）；`trigger_signal` 例外：它是短句信号而非分析叙述，条件出现。

正文固定结构（H1「# 标题」由 Code 从 title 生成、位于围栏后首行且恰好一个，正文自 H2 起；此处不直书 H1 字面以免与身份 H1 重复）：

```
## 决策背景        ← 为什么需要这个决策：问题与约束（必填）
## 决定            ← decision 的展开说明（必填；不要求逐字复现，02 §7.1）
## 备选与理由      ← 认真考虑过的每个备选 + 落选原因（必填）
## 后果            ← 已接受的正负后果、限制、风险与后续义务（必填，可短：一句话如实，「无已知重大后果」是合法陈述）
## 适用范围        ← scope 的展开：何时适用、何时不适用（必填；不要求逐字复现，02 §7.1）
## 证据            ← 支撑决策的内部引用（research 对象 uid）与外部来源（可选；urls 非空时必填）
```

字段间不变量：`decision` 单句可读（机械校验同 20 号 question 模式）；`disposition` 类终态字段随状态约束（§9）；`relations` 与 `retirement_reason`/`retired_at` 的出现条件互斥绑定（§9.2）；未知字段不进入 canonical 对象，不得以空字段或占位代替判断。

## 9. 状态与生命周期

状态闭集两值：`active`（决策现行有效）→ `retired`（决策不再作为现行依据）。无第三个状态——决策被替代、被规范承接、过时、范围失效或被废除都是 retired 的原因差异，由 `retirement_reason` 承载。

### 9.1 状态语义与成立条件

| `status` | 语义 | 必须成立 |
|---|---|---|
| `active` | 决策现行有效，参与装配与预检 | `retirement_reason`、`retired_at`、`relations` 均不得出现 |
| `retired` | 决策不再作为现行依据；保留为历史基线，不进入普通未处置候选。**`abolished` 时退出的只是「这条记录留在决策基线里」这件事**：该决策作出时所依据的前提没有变化，当时的适用范围判断也未被推翻（这是历史判断，**不表示退休后仍作为现行依据被检索或消费**），其内容所生的既有约束由 §10 所指明的承载继续承担，不因本对象退休而宣告自始无效 | `retirement_reason` 与 `retired_at` 必填；`retirement_reason=superseded` 时 `relations` 必含恰好一条 `superseded-by`；`retirement_reason=absorbed` 时 `relations` 必含恰好一条 `absorbed-into`；`outdated` / `out-of-scope` / `abolished` 时 `relations` 禁止出现 |

### 9.2 状态转换

正常转换只有 `active → retired`（Human Gate：废除已定决策是 Human 决定权的领域具体化）。理由闭集：

- `superseded`：被新决策替代——必须带 `superseded-by` 关系指向替代它的 ADR（该新 ADR 须已存在可解析）；
- `absorbed`：决策内容已被某方向的 Norm 完整承接——必须带 `absorbed-into` 关系指向承接它的 Norm（该 Norm 须已存在可解析）；本 ADR 退出约束、转为历史依据，其规则不再由本对象承担；
- `outdated`：环境或前提变化使决策失效（无单一替代者）；
- `out-of-scope`：决策的适用范围整体不再属于本项目；
- `abolished`：Human 决定不再保留这条决策记录——既没有被新决策替代，内容也没有被某方向 Norm 承接，使它失效的前提变化同样没有发生，被废除的只是「把这条记录留在决策基线里」这件事本身；本对象退出装配与预检消费，**其已产生的影响保留**：既有规范条文、实现行为与事实源中既有对象对它的引用都不因本对象的退休而改变。既有引用若只作溯源或沿革（说明某对象源自该决策、或记载其历史影响），**不构成 §17 第 6 项所称「引用 retired 决策为现行依据」**；但任何仍以本对象的 decision/scope 条文作为现行规则来源的引用，**不因 `retirement_reason=abolished` 而豁免**——该现行依据必须落在 §10 指明的承载上并改指该承载，否则按 §17 第 6 项处理。

`superseded` 与 `absorbed` 的区别是**去向的性质**而非有无去向：前者被另一条决策推翻（决策→决策），后者被规则体系成熟吸收（决策→规范）。两者都要求恰好一个可解析的去向，因此「退休必带去向」在两种情形下都由关系键承载，`outdated` / `out-of-scope` / `abolished` 因无单一去向而禁止带关系。

`abolished` 与 `outdated`、`out-of-scope` 的区别是**没有任何前提或边界发生变化**：该决策作出时所依据的前提没有变化，当时的适用范围判断也未被推翻（与 §9.1 同一口径的历史判断），故它既不指向承接对象，也不说明某个前提变了；它只指明「Human 不再保留这条记录」这一决定本身及其作用范围。

`abolished` 的适用边界（否定式判据）：**不得用它撤下仍在独立承担约束、且没有其它承载继续承担该约束的决策**。是否「另有承载」以 §10 的据实说明为准；说明中列不出任何继续承担该约束的既有承载时，该决策不属于 `abolished` 的适用对象——其内容仍须由某条 active 决策或某方向 Norm 承担（走 `superseded` / `absorbed`），确实已随前提变化而失效的走 `outdated`，适用范围已整体移出项目的走 `out-of-scope`。本条界线不新增机械门禁：`abolished` 与这三者的分界只能由 Human 决定与 AI 据实说明判定，机械层只校验闭集、字段与关系形态。

终态不重开。决策要再变更时创建新 ADR；错误的终态记录按**本条 §13 的「终态事实更正」**修正，不伪装成状态转换（该动作的通用纪律见 02 §10.5，但**可更正到什么范围由本类型自己的 §13 条目定义**——02 §10.5 只承载 CAS 更新与更正的共用发布不变量，不承载任何类型的终态更正正文规则）。决策语义的任何实质修订 = 新 ADR + 旧 ADR retired（superseded）——ADR 不原地改写决策（决策记录的可信度依赖「当时的决定不被事后篡改」）。**决策向规范的迁移不是实质修订**：`absorbed` 要求 decision 与 scope 逐字不变，改变的是承载其约束力的对象，不是决定本身；一旦迁移时决策内容也要变，仍走新 ADR + 旧 ADR retired（superseded）。

### 9.3 勘误级更新

正文错别字、引用路径修正、表述澄清（不改变决策语义与适用范围判断）走 02 §10.5 受控更新，change_log 留痕并注明勘误性质。判断标准：更新后的 decision/scope 逐字段不变（机械可比对）——变了就不是勘误，走替代路径。

机械比对只覆盖 decision/scope 两个字段，正文其余段落（决策背景、备选与理由、后果、适用范围展开、证据）的语义不变性是 AI 审核义务而非机械保证：勘误提交方必须确认更新不改变任何段的实质语义；存疑时一律走替代路径（新 ADR + 旧 retired），不得以「字段未变」为由放行实质性改写。

**本入口只对 `active` 开放**（`active → active`）。`retired` 对象的正文更正**不走本入口，走 §13 的「终态事实更正」**——两者不是同一动作的两种叫法，差别在可改范围与前置：勘误级更新接收完整 `frontmatter_after`（故必须机械证明 decision/scope 未变，靠 §14.1 的勘误边界校验），而终态事实更正**结构性不接收任何 frontmatter 输入**（decision/scope 无路可达，不靠校验拦）。把终态更正路由到本入口，等于要求调用方先提交一份必须与基线逐字相同的 decision/scope——那不但做不到「修正错述」，还会让调用方以为字段可写；反之把 `active` 的内容更新路由到 §13 入口，则是把内容更新伪装成事实更正，两条都是越界。

## 10. 来源与证据

决策来源是 Human 决定本身（主控方案收敛的分流结果、直接裁定的记录），不适用外部证据锚定决策的「正确性」——证据支撑决策，不证明决策。`urls` 的来源回指语义（可回读、可追溯、只承载长期消费价值的外部 HTTP(S) 资料）遵循 02 §8.1 的公共边界，本文不另建第二套来源规则；内部证据以 Research 对象 uid 在正文「证据」段引用（自然语言交代「哪个调研的什么结论支撑了本决策」），不建立结构化关系（02 §8.2 第 4 条：反向引用由 Research 侧 informs 关系承载，ADR 不复制）。

`retired` 的 `retirement_reason` 必须能据实说明废止/替代的依据：superseded 指明替代者与变化实质；absorbed 指明承接它的 Norm 方向与被承接的内容范围；outdated/out-of-scope 说明哪个前提变化了；abolished 指明 Human 在什么作用范围内决定不再保留该记录，以及已产生的影响由哪些既有承载继续承担。**「既有承载」的判定对象是「该约束是否仍被遵守」，不是「它是否已被写成某条规范」**：既有规范条文的相应表述、被既有校验/测试或宿主机制固定的实现行为、仍在生效的制度安排，都是合法的承载——它们须**可被持续核对或持续执行**，仅「此刻恰好在遵守」而没有任何持续机制的行动不单独构成承载；说明只需让读者能核对该约束靠什么继续兑现、下一次改动为什么不会让它无声消失，不要求逐项列出文件、函数或命令。反过来，**列不出任何继续承担该约束的承载时，该决策不属于 `abolished`**（§9.2 的否定式判据）。证据以自然语言描述，不得用路径、命令或日志位置代替说明。

## 11. 关系契约

`relations` 只使用 02 §8.2 公共形状。本类型关系闭集：

| `relation_key` | 方向 | 目标类型 | 基数 | 语义 | 约束 |
|---|---|---|---|---|---|
| `superseded-by` | 本 ADR（旧）→ 替代它的 ADR（新） | ADR | 1 | 本决策被目标 ADR 的决策替代 | 仅 `retired + retirement_reason=superseded` 时出现；目标必须存在且可解析（状态不限——链式替代后目标可能也已 retired） |
| `absorbed-into` | 本 ADR（已迁移）→ 承接它的 Norm | Norm | 1 | 本决策的规则内容已被目标 Norm 完整承接 | 仅 `retired + retirement_reason=absorbed` 时出现；目标必须存在且可解析（状态不限——规则可能后继被同方向的 active Norm 取代）；写后不得反向修改目标 Norm |

两个键的**基数各自恰为 1**，且因理由互斥（`superseded` / `absorbed`）二者不会同时出现——一条 ADR 的 `relations` 总计恰一条。

不设 `inspired-by`/`informs`（那是 Research 侧的跨类型键）；不建正向键（`supersedes` / `absorbs`），两个方向键均为旧→新的单向，终态校验按目标 `fact_type_key` 精确读取目标载体（`adrs` 或 `norms`），不做目录扫描；不建普通关联键——决策与调研/工作的关联由对侧承载或正文自然语言交代，确有公共消费价值时由 03 提升公共契约再议。**`absorbed-into` 的边只存在于 ADR 侧**：Norm 不建立指回 ADR 的反向结构化关系（27 号），反向导航由 Code/Web 派生索引承担（02 §8.2 第 4 条），不构成第二权威。关系变更必须使用对象当前指纹绑定的完整更新入口，写后精确回读。

## 12. 召回与消费

**义务召回原则（法定效力的消费侧落地）**：相关行动开始前，AI 必须召回并核对相关 active ADR——这是义务而非「需要时查阅」（Human 决定）。设计、实现、写入、提交各环节触及既有决策域时未召回核对，视同违背本规范；新方案违背 active ADR 时在方案收敛被淘汰，行动方案违背时被遵守预检拦截。

| 消费点 | 时机 | 消费内容 |
|---|---|---|
| 方案收敛依据装配 | 每次方案收敛装配前（主控本职，04 §6.1） | 相关 active ADR 的 decision + scope——决策一致性依据：方案违背即淘汰，淘汰须记录违背的具体条目（哪条 ADR） |
| 遵守预检（义务） | 行动涉及既有决策域时（34 号双源召回系统规范） | decision + scope + trigger_signal（若声明）——识别当前行动是否触及/违背已定决策；声明了重审信号的 ADR 顺带核对前提是否已变化 |
| 审议上下文 | 方案工作的备选评估时 | title + 备选与理由——「历史上否过什么、为什么」 |
| 故障调查 | 事后追溯时 | 决策背景 + 备选与理由 + 后果——当时的取舍依据，以及出问题处是「当初已接受的已知成本」还是「设计盲区」（后果段在案与否即是分界线） |
| Web 决策库呈现 | Web 呈现（07 号；细则见 `plugin/web/docs/10`） | active ADR 列表与决策谱系投影 |

召回分层（02 §9.1）：F1 枚举 active ADR 计数（title + status）；F2 按类型、状态、稳定引用、命中词的候选卡；F3/F4 按需展开。默认候选只含 active——**当前决策基线就是 active 集本身**，链式替代（A1→A2→A3）下消费者无须遍历链找「最新」：F1 召回的 active ADR 即现行决策，谱系链只服务历史追溯与演进脉络。retired 不进入普通候选，只在精确引用或追溯历史基线时展开。AI 展开候选后必须重新比较当前主题与决策状态——ADR 被召回不等于决策适用，装配时的相关性判断是 AI 语义工作（02 §9.2）。

## 13. 受控操作

- **创建**：AI 产出提案对象（含查重结论与「备选是否经多视角考虑、依据是否装配且可回指、取舍是否逐项有据、未决问题与残留是否有显式去向」四项自查内容，取自 04 §6.1 方案收敛自查），经 §16 第 1 项的 Human Gate 取得确认后，经受控创建入口落盘——典型入口是主控方案收敛的分流（04 §6.1；已定决策→ADR），Human 直接裁定后记录是第二入口。**查重结论是创建的必含输入**（§14.1「查重已执行」）：未记录查重结论者不得提请，机械层对此只校验「有没有记录」，查重的语义比对仍属 AI（02 §9.2 禁止机械相似度裁决）。机械校验：字段闭集合法、decision 单句、title ≤ 30 字、urls 形状、载体结构（H2 固定序 + urls 非空时「证据」段必在）、正文与字段一致性的差异报告（decision/scope 与正文段的差异**只报告不阻断**，02 §7.1、Human 2026-11-10 取消逐字义务）。创建后精确回读。
- **勘误级更新**：02 §10.5 受控更新；CAS 以完整文件为单位；每次恰好一条 change_log（注明勘误性质）；decision/scope 逐字段不变（机械比对，变了拒绝——走替代路径）。
- **终态流转（retired）**：§16 第 2 项的 Human Gate；AI 先精确读取 F3，核对 retirement_reason 与证据；superseded 时校验替代者 ADR 存在可解析，absorbed 时校验承接它的 Norm 存在可解析；**outdated / out-of-scope / abolished 无去向要求**——不得带 relations，且理由须据实可述（§10）并在说明中交代前提变化或被废除记录的影响承载；Code 检查闭集、字段、关系、CAS 与回读。**§10 的据实说明落在本次流转的 `change_log.summary` 上**：Code 原样保留；该流水仍是一条语义摘要（不复制完整正文或完整 diff，02 §7.1 的公共字段语义不变），篇幅随据实交代承载所需，不设一句话上限。**该段说明须在取得确认时呈报给 Human 全文**（连同 retirement_reason 与关系目标）——§10「承载列得出列不出」是语义判定，归 Human；机械层只保证 Human 看到了它，不判断其成立与否。
- **终态事实更正**（`correct`；Human 决定建立）：**非状态转换**，是 §9.2「错误的终态记录按事实更正修正」这一承诺的受控入口。触发形态：`retired` 记录的**正文**本身有缺陷（错述、超限引用、与事实不符的叙述），而 `status` 与 `retirement_reason`/`relations`/`retired_at` 所载的判定不变。**入口只对 `status = retired` 开放**：`active` 的内容修正走 §9.3 勘误级更新，把内容更新路由到本入口即「把内容更新伪装成事实更正」的反向越界（§9.3 末段）。**必须 Human 授权**：调用方须提供非空 `human_authorization`，其文本**逐字**落入 `change_log`（更正与其它受控更新同权限，02 §10.5）；缺授权即拒绝，不得以「格式治理」名义批量绕过。**如实声明边界**：该字段是自报，机械层只保证「授权记录被提交」，**不证明** Human 真的同意过。**无字段写入能力**：入口**不接收 `frontmatter_after`，也不接收 `frontmatter_removals`**——`decision`/`scope`/`status`/`retirement_reason`/`relations`/`retired_at` 逐字继承落盘对象，`change_log` 追加**恰好一条**，摘要沿用「事实更正（非状态转换）——」前缀。这是**结构性保证而非校验结果**：入口没有可承载字段值的参数，故「改写决策」不是被拒绝，而是无路可达（§9.2「ADR 不原地改写决策」）。**正文可改范围**：固定 H2 骨架与载体内聚仍然适用——「决定」段须逐字保留 `decision`、「适用范围」段须逐字保留 `scope`，故这两段的逐字行不可动；可更正的是决策背景、备选与理由、后果、证据等叙述段。**无写入变更即拒绝**：提交正文与落盘正文相同（含仅尾随空行差异）时拒绝为 no-op，不追加声称更正过的条目（02 §10.5 不记录 no-op）。**入参的两种等价形态**：`body_markdown_after` 的规范形态是从 `## 决策背景` 起的正文片段（H1 由 title 生成）；若调用方把精确读取返回的 `body`（含 `# <title>` 那一行）原样回传，Code 在拼装前剥掉**与 title 逐字相同的那一个前置 H1**，再走同一套结构校验——两种形态等价，不会拼出双 H1。剥除只对「与 title 逐字相同」的行生效；title 不同则不动，交由结构校验如实报错（不静默改写一段本该被拒绝的输入）。**机械拒绝的越权动作**：任何 frontmatter 改动（无通道）、非终态对象（`correction_requires_retired`）、缺 Human 授权（`human_authorization_required`）、缺变更摘要（`change_summary_required`）、陈旧指纹（`cas_conflict`）。写后精确回读。**本条机械保证范围**：只证明「该次写入带 Human 授权、只改正文、终态字段逐字未变、恰好一条 change_log」；**不证明**更正内容正确、更正确有必要或正文缺陷已实质消除——那属 AI 语义审核与 Human 阅读（04 §6）。**残留（如实登记）**：本入口只覆盖**正文**；`superseded-by`/`absorbed-into` 的**目标写错**属「改终态判定」，不由本入口承载，目前无通道，须另行裁定。
- **删除**：不存在删除操作。retired ADR 随 `ldvh-base/adrs/` 保留为历史基线。

## 14. 类型特有验证与类型退出

### 14.1 类型特有验证

- 查重结果记录：创建提案必含查重结论（同主题已存在 → 不新建，走更新或替代）；
- **正文与字段分工**：frontmatter 字段是索引与摘要、正文是展开，**不要求逐字一致**（02 §7.1、Human 2026-11-10 取消「载体内聚」义务）；差异由读回与诊断层如实报告，不阻断写入。
- 证据段条件：`urls` 非空 ⇒ 正文「证据」段存在（二元可判定：frontmatter 数组长度 > 0 与 H2 存在性）；
- 勘误边界：更新的 decision/scope 与 CAS 基线逐字段一致（防语义变更伪装勘误）；正文其余段的语义不变性是 AI 审核义务（§9.3），不在机械层；
- 终态完整性：retired 必有 reason + retired_at；superseded 必有且恰有一条 superseded-by 且目标可解析，absorbed 必有且恰有一条 absorbed-into 且目标可解析；`outdated` / `out-of-scope` / `abolished` 无去向要求——不得带关系，理由的据实性由 §10 承担（语义判断，不在机械层）；
- 状态-关系不变量：active 不得带终态字段与关系；`outdated` / `out-of-scope` / `abolished` 的 retired 不得带关系；每一条关系键都须与其理由对应（superseded→superseded-by、absorbed→absorbed-into），交叉错配拒绝；
- 终态事实更正边界（§13 的 `correct`）：对象为 `retired`；带非空 `human_authorization` 与 `change_summary`；提交正文与落盘正文不同（no-op 拒绝）；**终态字段逐字未变**——`decision`/`scope`/`status`/`retirement_reason`/`relations`/`retired_at` 与 CAS 基线逐字段一致，且 `frontmatter_after`/`frontmatter_removals` 两参数**不被入口接收**（结构性不可达，不是「校验后拒绝」）；正文固定 H2 骨架与载体内聚仍须通过（故「决定」段与「适用范围」段的逐字行不可改）；`change_log` 恰好 +1 且带授权文本。

### 14.2 存量对象迁移

无 v5 存量。v4 仓库的 2 个 ADR 实例按「v4 存量不迁移」（Human决定）保留在 v4 历史归档，不进入 v5 事实源消费；其决策若仍适用，在 v5 以新 ADR 重新记录。

### 14.3 类型退出

若 Human 决定取消 ADR 类型，须按 02 §11 处理：处理仍适用决策的转移承接、入向/出向关系与稳定引用，登记变化（01 §8.1）与受影响引用同步，走受控提交。退出属 00 §3.2 根决定。

## 15. 验证与证据边界

| 验证对象 | 成立条件 | 验证入口 | 未满足时的处理 |
|---|---|---|---|
| 载体结构 | 创建、更新或精确读取时核对（依据当前载体与本文 §8）：H1 恰好一个且与 title 一致、正文自 H2 起、H2 固定序完整、各段非空。仅证明当次载体结构合法性 | 机械（结构解析） | 拒绝创建/更新；修复后重走 |
| 正文与字段一致性 | 创建与更新时对照 frontmatter 与正文：**仅报告差异、不阻断写入**（02 §7.1、Human 2026-11-10 取消逐字义务）。仅证明当次可对照观察，不证明内容正确 | 机械（差异报告） | 如实呈现差异；不拒绝 |
| 勘误边界 | 更新时（仅 `active` 勘误级更新）核对（依据更新前后 frontmatter 对照）：decision/scope 与 CAS 基线逐字段一致。仅证明当次更新的勘误性质；**不覆盖**终态更正（见下行） | 机械（字段比对） | 拒绝；语义变更走替代路径 |
| 终态事实更正边界 | 每次 `correct` 写入前核对（依据对象全文 + 写入前后 frontmatter 比对 + `change_log` 条数）：对象为 `retired`；带非空 Human 授权与变更摘要；提交正文与落盘正文不同；终态字段逐字未变。仅证明该次写入只改正文、`status`/`decision`/`scope`/`retirement_reason`/`relations`/`retired_at` 逐字未变、`change_log` 恰好 +1 且带授权文本；**不证明**更正内容正确、更正确有必要或缺陷已实质消除 | 机械（状态检查、必填项、正文比对、CAS、写后回读 + 逐字字段比对） | 拒绝且零写入；正文缺陷须实质消除后重走 |
| 查重已执行 | 创建时核对（依据提案记录）：创建提案含查重结论。仅证明当次查重范围 | AI 语义审核；机械只校验「查重结论非空」 | 补查重后重走创建 |
| 创建与终态的确认已取得（§16.2） | 每次 `create` 与「`active → retired`」写入前核对（依据受控入口返回的信封）：经 `ctx.userQuestions.ask` 取得明确的肯定答复；无答题器／询问失败／未作选择时零写入。仅证明「写入前取得过肯定答复」，**不证明呈报内容曾被看到（§16.2：呈报在对话正文，弹窗只留标题，无机械判据）**、不证明答复者理解呈报内容、不证明决策质量、不产生事后可核的确认凭据 | 机械（宿主询问入口 + fail-closed 路径） | 拒绝且零写入；补走确认后重试 |
| 终态完整性 | 终态流转时核对（依据对象全文与目标读取结果）：reason/retired_at 齐备；superseded / absorbed 时对应关系键齐备且目标可解析；outdated / out-of-scope / abolished 时不带关系。仅证明当次终态机械范围 | 机械（字段+关系校验） | 拒绝流转；补齐后重走 |
| 决策语义质量 | 创建与终态时核对（依据 §16.2 的呈报内容与 Human 的答复）：decision 可判定、备选与理由据实、scope 边界明确。仅证明当次决策记录质量 | AI 语义审核 + Human 终审 | 拒绝或退回修订 |

机械结果与语义判断互不替代。本章不能单独证明决策正确、适用或被遵守——这些由消费点的真实使用核对；未实现与不可用范围保留为 gaps。

## 16. Human Gate

本文不新增 00 之外的 Human Gate。领域增量事项（00 §3.2 在 ADR 领域的具体化）：

1. ADR 的创建（决策的记录成立——含讨论分流与直接裁定两入口的记录确认）；
2. ADR 的终态决定（retired——废除已定决策）；
3. ADR 类型本身的取消或合并。

### 16.1 决定边界

Human 决定只证明决定及其作用范围，不替代查重判断、载体校验、装配相关性判断或终态机械校验。本文成为当前规则源成员时的 01 §8.1 登记与受影响引用同步，按 01 §8.1 的登记义务随本次规范新建一并执行。

### 16.2 确认的承载与呈报

**承载范围（条件式）**：第 1 项（创建）与第 2 项（终态决定）的确认，须由宿主询问入口（`10 §5.5`：`ctx.userQuestions.ask`）取得——无答题器、询问失败或未作选择时一律拒绝并如实报告。**第 3 项（ADR 类型本身的取消或合并）当前没有受控实现入口，本节不为它声明承载**：该动作一旦提上日程，须先建立入口再谈承载，不得据本节主张其已获机械保障。

**呈报内容**：取得确认时须向 Human 呈报下列内容——创建：查重结论、`decision`、`scope`；终态决定：拟转状态与 `retirement_reason`、关系目标（若声明）、以及 §10 要求的据实说明全文（该说明落在本次流转的 `change_log.summary` 上，§13）。

**呈报内容的承载位置（Human 2026-11-13 决定）**：上列内容须由主控在**调用受控写入之前写进对话正文**，不得依赖提请弹窗携带。「所有经过 ldvh 业务的提请，都要求内容简洁，title 字数在 200 字内，没有其它细节信息」——故弹窗只承担「这是什么动作、点哪个键」，其 `question` 不再承载呈报正文，也不再携带 `detail`。**这是本条据实声明的边界**（`00 §4.6`）：机械层只证明「写入前取得过一次明确的肯定答复」，**不再证明 Human 看到过完整呈报**；呈报是否已在对话正文中给出，属主控自律与 §15 语义核对范围，无机械判据。该缺口不得以「弹窗简化」为理由隐去。

**保证边界（如实声明）**：本项只证明「写入前取得过明确的肯定答复、未取得即零写入」；**不证明**答复者理解了呈报内容、不证明决策质量，也不产生可事后核对「谁确认过」的凭据——答复本身由宿主记录在会话侧，本类型不新增确认凭据字段。**在宿主询问入口对本类型实际具备之前，不得主张本项已获机械保障**，须按 `00 §4.6` 如实披露未兑现范围；该前提是否成立按 `01 §7.2` 由读取时的观察取得，本节不陈述其当前状态。**已知代价**：该承载按工具声明，故同一工具的 `correct` 与 `active → active` 勘误更新同样失去执行期的墙钟上限。

## 17. 必停情形

本文不新增根停止类型。领域触发与最小影响范围：

1. 创建时发现同主题 active ADR 已存在（重复决策谱系风险）——未完成查重结论前不创建；
2. decision 为空或不可读、scope 缺失；
3. 准备以更新改写 decision/scope 语义（勘误边界违例）；
4. 终态流转存在 retirement_reason 缺口，或 superseded / absorbed 的去向缺口（不带对应关系键），或 superseded-by / absorbed-into 目标不可解析；
5. AI 未经 Human 确认直接创建、流转或**做终态事实更正**（授权缺失）；
6. 装配/预检消费时 ADR 状态与引用不一致（引用了 retired 决策为现行依据；仅溯源或沿革性引用除外，见 §9.2）；
7. 拟更正的正文缺陷落在「决定」段或「适用范围」段的逐字行上（载体内聚不允许改动 `decision`/`scope` 的权威文本）：这不是可更正的错述，而是**决策语义变更**——须走新 ADR + 旧 retired（`superseded`），不得以更正名义改写；同理，拟借更正改动 `retirement_reason` / `relations` / `retired_at` 时一律停止，该入口无此通道（§13 已登记该残留）。

暂停期间只允许不越过停止边界的证据补取、引用修复、授权补走与条件核实。恢复须与触发原因逐项对应；同一停止条件恢复后再次触发的，按 00 §4.7 的恢复与再次触发进入 Human Gate。

## 18. 反过度设计红线

1. 不设 `context`/`alternatives` frontmatter 字段——分析主体住正文，frontmatter 只留薄索引（`trigger_signal` 是短句信号非分析叙述，条件字段不违本线）；
2. 不设 `priority`、`tags`、`confidence` 类装饰字段——决策的重要性由消费点引用体现；
3. 不建 `supersedes` / `absorbs` 正向键 + 目录扫描校验——`superseded-by` 与 `absorbed-into` 均为旧→新的单向，终态校验按目标 `fact_type_key` 直读对应载体，只查本对象与目标；
4. 不为「决策微调」开第二个更新通道——勘误级（逐字段不变）与替代（新对象）两路覆盖全部**变更语义**；§13 的「终态事实更正」**不是第三个更新通道**：按 02 §11，事实更正与内容更新是不同动作，它不承载任何变更语义（decision/scope 结构性不可达、不新增不删除字段），只修正已落盘记录中的错述，故不落入本线所禁的「为微调开第二通道」（本线与 §13 的关系在建立该入口时一并写明，避免读者以为红线被破）；
5. 不建决策族谱索引或时间线投影——谱系由 superseded-by 链、absorbed-into 边与 Web 派生呈现承载，不写回对象；反查 Norm 承接了哪些 ADR 同样由派生索引承担，不在 Norm 侧加反向字段；
6. 不把 ADR 变成规则源——决策被承接为可强制执行规则时由规范源承载（00 §3.2），ADR 保持记录身份，`absorbed` 是这一让渡关系的记录方式而非把 ADR 升格为规范；
