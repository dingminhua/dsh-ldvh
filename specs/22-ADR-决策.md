# ADR-决策

## 1. 价值判断

ADR 解决已定决策随对话消散、以及决策缺乏持续约束力的问题：一个架构取舍当时为什么这么定、认真考虑过什么备选、为何落选、接受了什么后果、边界在哪——这些内容若只存在于会话记录或散落文档，后续每一次方案工作都无法对照同一份决策依据，重复争论已定之事、无意间违背既有决策、或在故障调查时找不到「当时否过什么」（00 §1 痛点 4「历史经验与教训，无法积累」）——后果段在案与否，正是故障追责时「已知成本」与「设计盲区」的分界线。**ADR 是对 AI 具有持续约束力的法定效力决定（Human 决定 2026-09-10）：一经生效，AI 在一切相关环节必须贯彻——设计遵守、实现遵守、写入遵守、提交遵守；违背 active ADR 的行动视同违背规范源。** ADR 以知识层对象承载法定决定：回溯记录、前瞻约束——行动前预检与讨论装配时被义务召回并核对，决策本身不再被重新裁决。普通文件不能无损承载：无受控写入、无状态闭集（active/retired 无从机械判定）、无讨论装配的引用契约（违背淘汰须记录「哪条 ADR」）。Spark 是方向的容器（决定未结晶前住在方向主线里）；Research 是外部证据的调查（支撑决策但不承载决定）；Pitfall 是教训规避（「别这么做」不是「为什么这么定」）。

主要支撑 V3 边界识别（方案违背已定决策在讨论装配即被淘汰）、V5 据实判断（决策依据可回指——装配淘汰与预检拦截都以「哪条 ADR 的 decision/scope」为可回指依据，而非笼统的「历史上有过决定」）、V6 工作接续（跨会话恢复决策基线）与 V8 持续积累（相似取舍直接复用既有决策与备选分析）；HV3 入档闭环节点可验（决策创建与终态可回读）与 HV5 项目演进脉络可循（决策谱系：什么替代了什么、为什么）。

ADR 对象存在、处于 active 或形成决策谱系，均不能单独证明决策正确、仍然适用或被实际遵守——决策的价值须在后续装配、预检与故障调查的真实消费中核对。ADR 不承载「接下来做什么」（裁定 6：前向规划属前向层），不替代 Human 决定权（决策的作出与废除始终是 Human 权限，ADR 只承载已定决策的记录）。

4. Human 作出或废除决策的过程（00 §4 承载——ADR 记录已定决策，不产生决策）；
5. Web 呈现的视觉与交互细节（10 号承载）。

### 3.3 相邻规范分工与唯一权威

## 4. 适用范围

### 4.1 适用对象

1. 管辖项目中的多例 ADR 对象（`ldvh-base/adrs/`）；
2. ADR 的决策记录、备选理由、适用范围与证据引用。

### 4.2 适用场景

本规范用于 ADR 的创建（讨论收敛分流到已定决策、Human 直接裁定后记录）、查重、勘误级更新、终态流转（废弃/被替代）与消费（讨论装配、遵守预检、审议上下文、故障调查）。

### 4.3 明确排除与证明边界

明确排除：未定方案（走 Spark 悬置，决策形成前不该有 ADR）；执行计划（走 WorkCase）；外部证据调查（走 Research）；教训与规避（走 Pitfall）；对话中的临时取舍（重要性不足以对象化的留在会话记录）。ADR 对象存在或状态为 active，不能单独证明决策正确、适用、被遵守或已被消费——这些须由装配、预检与故障调查的真实使用核对。

## 5. 类型定位与价值

ADR 是知识层的法定效力类型：承载对 AI 具有持续约束力的已定决定，供前瞻约束与回溯审查。三层分工中它与 Pitfall、Research 同层——「回溯记录、前瞻约束」，不承载「接下来做什么」（裁定 6）。

- **与 Spark 的差异**：Spark 是方向主线（宽入口，一切的起点），ADR 是方向中结晶出的法定决定（窄出口）——同一个主题，方向住在 Spark，结晶出的每条可独立贯彻的必须提取为 ADR；
- **与 Research 的差异**：Research 调查外部世界形成证据，ADR 用证据（可能含 Research）作出并记录决定；
- **与 Pitfall 的差异**：Pitfall 承载「什么会出错、怎么规避」，ADR 承载「为什么这么定、否过什么」。

按 03 §5.2 准入六问：跨行动保留——决策基线必须跨会话稳定，否则每次方案工作重新裁决已定之事；独立身份与状态——决策有 active/retired 与替代谱系，需要独立生命周期；普通文件不能无损承载——无受控写入、无状态闭集、无装配引用契约；消费价值服务 AI（装配/预检）与 Human（Web 决策库浏览、HV5 演进脉络）双轨；维护成本——低频类型（v4 实证仅 2 例，业界 ADR 同为月级低频），净值为正；类型定义来源——本规范。

## 6. 对象边界

### 6.1 什么构成一个对象

一个 ADR 对象 = **一条可独立贯彻的法定效力决定**：决策陈述（decision）+ 适用范围（scope）+ 决策背景（正文）+ 备选与理由（正文）+ 已接受后果（正文）+ 证据引用（可选）。判据：决策必须可独立召回、**可独立检查遵从性**（任一相关行动能对照本条回答「守没守」——这是法定效力落地的粒度基础）、可独立违背（装配淘汰时能指向「哪条 ADR」）、可独立终态（被替代时单独 retired）。**粒度判据（Human 决定 2026-09-10）**：对同一主题的多个松散决定，宁可拆成多条 ADR 也不打包一条——打包的决定集合无法逐条贯彻检查，等于没有效力。

### 6.2 查重

创建前必须查重：对照既有 active ADR 的 title/decision 语义比对（AI 语义判断，03 §8.2 不建立相似度自动裁决）。同主题决策已存在且仍然适用时，不新建（重复记录制造伪谱系）；已存在但决策实质变化时，走替代路径（新 ADR + 旧 retired），不改写既有 ADR 的决策语义。查重结论必须记录在创建提案中。

### 6.3 明确不属于本类型

开发计划与计划确认（意图与时序，走 WorkCase；**「计划被确认了」改变的是意图不改变规则**——计划变更无「违背」语义，无法逐环节检查遵从性，进 ADR 即稀释法定效力）；需求文档与方向叙事（方向主线由 Spark 承载）；未定方案（决策形成前不该有 ADR）；外部证据调查（走 Research）；教训与规避（走 Pitfall）；对话中的临时取舍（重要性不足以对象化的留在会话记录）；同一决策的表述精化（勘误级更新，非新对象）；同一讨论的多个独立决定（各自成对象，不捆成一个）；已被完整承接进规范源的可强制执行规则的决策（规则本身由规范源承载，ADR 可作为决策来源被引用但不再承担约束）。

## 8. 字段契约

frontmatter 闭集（分析性长文本一律住正文，frontmatter 只留薄索引——24 号定型原则：机器可验证性不得以牺牲分析空间为代价）：

| 字段 | 类型 | 必填性 | 语义 | 约束 |
|---|---|---|---|---|
| `fact_type_key` | string | 必填 | `adr` | 唯一合法值（03 §6.1 值域） |
| `object_uid` | UUIDv4 | 必填 | Code 生成 | 创建时落定，永不改变 |
| `title` | string | 必填 | 决策短标题 | ≤ 30 字；供候选定位与 Human 扫读 |
| `status` | string | 必填 | `active` / `retired` | 初态必为 `active` |
| `decision` | string | 必填 | 决定陈述 | 单句（句终符 。？！至多一个且若存在必须结尾，同 20 号 question 机械校验）；正文「决定」段逐字包含 |
| `scope` | string | 必填 | 适用范围陈述 | 正文「适用范围」段逐字包含；何时适用/不适用由正文展开 |
| `trigger_signal` | string | 条件 | 重新审视信号 | 存在真实重审前提时写（如「当 X 出现时重审本决策」：版本发布、SG-4 落地、依赖变更）；无真实信号时省略（03 §6.1 条件字段——不得以占位文本伪造）；供遵守预检消费 |
| `urls` | array | 条件 | 支撑决策的外部 HTTP(S) 证据 | 出现时非空；`urls` 非空 ⇒ 正文「证据」段必填 |
| `relations` | array | 条件 | `superseded-by`（见 §9） | 仅终态 superseded 时可出现 |
| `retirement_reason` | string | 条件 | 终态原因 | 闭集：`superseded` / `outdated` / `out-of-scope`；retired 必填、active 禁现 |
| `retired_at` | RFC3339 | 条件 | Code 填写 | retired 必填、active 禁现 |
| `created_at` | RFC3339 | 必填 | Code 填写 | AI 不得填写 |
| `change_log` | array | 条件 | 变更流水 | 首修后必有；每次恰好一条 |

不设 `context`、`alternatives`、`evidence` 等 frontmatter 字段——决策背景、备选与理由、后果叙述、证据叙述是分析主体，住正文（frontmatter 薄索引 + 正文主体）；`trigger_signal` 例外：它是短句信号而非分析叙述，条件出现。

正文固定结构（H1「# 标题」由 Code 从 title 生成、位于围栏后首行且恰好一个，正文自 H2 起；此处不直书 H1 字面以免与身份 H1 重复）：

```
## 决策背景        ← 为什么需要这个决策：问题与约束（必填）
## 决定            ← decision 逐字 + 展开说明（必填）
## 备选与理由      ← 认真考虑过的每个备选 + 落选原因（必填）
## 后果            ← 已接受的正负后果、限制、风险与后续义务（必填，可短：一句话如实，「无已知重大后果」是合法陈述）
## 适用范围        ← scope 逐字 + 展开：何时适用、何时不适用（必填）
## 证据            ← 支撑决策的内部引用（research 对象 uid）与外部来源（可选；urls 非空时必填）
```

字段间不变量：`decision` 单句可读（机械校验同 20 号 question 模式）；`disposition` 类终态字段随状态约束（§9）；`relations` 与 `retirement_reason`/`retired_at` 的出现条件互斥绑定（§9.2）；未知字段不进入 canonical 对象，不得以空字段或占位代替判断。

## 9. 状态与生命周期

状态闭集两值：`active`（决策现行有效）→ `retired`（决策不再适用）。无第三个状态——决策被替代、过时或范围失效都是 retired 的原因差异，由 `retirement_reason` 承载。

### 9.1 状态语义与成立条件

| `status` | 语义 | 必须成立 |
|---|---|---|
| `active` | 决策现行有效，参与装配与预检 | `retirement_reason`、`retired_at`、`relations` 均不得出现 |
| `retired` | 决策不再适用；保留为历史基线，不进入普通未处置候选 | `retirement_reason` 与 `retired_at` 必填；`retirement_reason=superseded` 时 `relations` 必含恰好一条 `superseded-by`；其他理由时 `relations` 禁止出现 |

### 9.2 状态转换

正常转换只有 `active → retired`（Human Gate：废除已定决策是 Human 决定权的领域具体化）。理由闭集：

- `superseded`：被新决策替代——必须带 `superseded-by` 关系指向替代它的 ADR（该新 ADR 须已存在可解析）；
- `outdated`：环境或前提变化使决策失效（无单一替代者）；
- `out-of-scope`：决策的适用范围整体不再属于本项目。

终态不重开。决策要再变更时创建新 ADR；错误的终态记录按 05 的事实更正规则修正，不伪装成状态转换。决策语义的任何实质修订 = 新 ADR + 旧 ADR retired（superseded）——ADR 不原地改写决策（决策记录的可信度依赖「当时的决定不被事后篡改」）。

### 9.3 勘误级更新

正文错别字、引用路径修正、表述澄清（不改变决策语义与适用范围判断）走 03 §9.5 受控更新，change_log 留痕并注明勘误性质。判断标准：更新后的 decision/scope 逐字段不变（机械可比对）——变了就不是勘误，走替代路径。

机械比对只覆盖 decision/scope 两个字段，正文其余段落（决策背景、备选与理由、后果、适用范围展开、证据）的语义不变性是 AI 审核义务而非机械保证：勘误提交方必须确认更新不改变任何段的实质语义；存疑时一律走替代路径（新 ADR + 旧 retired），不得以「字段未变」为由放行实质性改写。

## 10. 来源与证据

决策来源是 Human 决定本身（讨论收敛的分流结果、直接裁定的记录），不适用外部证据锚定决策的「正确性」——证据支撑决策，不证明决策。`urls` 的来源回指语义（可回读、可追溯、只承载长期消费价值的外部 HTTP(S) 资料）遵循 06 §5 的公共边界，本文不另建第二套来源规则；内部证据以 Research 对象 uid 在正文「证据」段引用（自然语言交代「哪个调研的什么结论支撑了本决策」），不建立结构化关系（03 §7.2 第 4 条：反向引用由 Research 侧 informs 关系承载，ADR 不复制）。

`retired` 的 `retirement_reason` 必须能据实说明废止/替代的依据：superseded 指明替代者与变化实质；outdated/out-of-scope 说明哪个前提变化了。证据以自然语言描述，不得用路径、命令或日志位置代替说明。

## 11. 关系契约

`relations` 只使用 03 §7.2 公共形状。本类型关系闭集：

| `relation_key` | 方向 | 目标类型 | 基数 | 语义 | 约束 |
|---|---|---|---|---|---|
| `superseded-by` | 本 ADR（旧）→ 替代它的 ADR（新） | ADR | 1 | 本决策被目标 ADR 的决策替代 | 仅 `retired + retirement_reason=superseded` 时出现；目标必须存在且可解析（状态不限——链式替代后目标可能也已 retired） |

不设 `inspired-by`/`informs`（那是 Research 侧的跨类型键）；不建正向 supersedes 键（旧→新的单一方向使终态校验只查本对象，无须目录扫描）；不建普通关联键——决策与调研/工作的关联由对侧承载或正文自然语言交代，确有公共消费价值时由 03 提升公共契约再议。关系变更必须使用对象当前指纹绑定的完整更新入口，写后精确回读。

## 12. 召回与消费

**义务召回原则（法定效力的消费侧落地）**：相关行动开始前，AI 必须召回并核对相关 active ADR——这是义务而非「需要时查阅」（Human 决定 2026-09-10）。设计、实现、写入、提交各环节触及既有决策域时未召回核对，视同违背本规范；新方案违背 active ADR 时在讨论装配被淘汰，行动方案违背时被遵守预检拦截。

| 消费点 | 时机 | 消费内容 |
|---|---|---|
| 讨论系统依据装配 | 每次扩散前（31 §7.1） | 相关 active ADR 的 decision + scope——决策一致性依据：方案违背即淘汰，淘汰须记录违背的具体条目（哪条 ADR） |
| 遵守预检（义务） | 行动涉及既有决策域时（02 §12） | decision + scope + trigger_signal（若声明）——识别当前行动是否触及/违背已定决策；声明了重审信号的 ADR 顺带核对前提是否已变化 |
| 审议上下文 | 方案工作的备选评估时 | title + 备选与理由——「历史上否过什么、为什么」 |
| 故障调查 | 事后追溯时 | 决策背景 + 备选与理由 + 后果——当时的取舍依据，以及出问题处是「当初已接受的已知成本」还是「设计盲区」（后果段在案与否即是分界线） |
| Web 决策库呈现 | 蓝图渲染（10 号） | active ADR 列表与决策谱系投影 |

召回分层（03 §8）：F1 枚举 active ADR 计数（title + status）；F2 按类型、状态、稳定引用、命中词的候选卡；F3/F4 按需展开。默认候选只含 active——**当前决策基线就是 active 集本身**，链式替代（A1→A2→A3）下消费者无须遍历链找「最新」：F1 召回的 active ADR 即现行决策，谱系链只服务历史追溯与 HV5 演进脉络。retired 不进入普通候选，只在精确引用或追溯历史基线时展开。AI 展开候选后必须重新比较当前主题与决策状态——ADR 被召回不等于决策适用，装配时的相关性判断是 AI 语义工作（03 §8.2）。

## 13. 受控操作

- **创建**：AI 产出提案对象（含查重结论与完整四要素），Human 确认后经受控创建入口落盘——典型入口是讨论收敛的四路分流（31 §10.1 已定决策→ADR），Human 直接裁定后记录是第二入口。机械校验：字段闭集合法、decision 单句、title ≤ 30 字、urls 形状、载体结构（H2 固定序 + urls 非空时「证据」段必在）、载体内聚（decision/scope 逐字）。创建后精确回读。
- **勘误级更新**：03 §9.5 受控更新；CAS 以完整文件为单位；每次恰好一条 change_log（注明勘误性质）；decision/scope 逐字段不变（机械比对，变了拒绝——走替代路径）。
- **终态流转（retired）**：Human Gate；AI 先精确读取 F3，核对 retirement_reason 与证据；superseded 时校验替代者 ADR 存在可解析；Code 检查闭集、字段、关系、CAS 与回读。
- **删除**：不存在删除操作。retired ADR 随 `ldvh-base/adrs/` 保留为历史基线。

## 14. 类型特有验证与类型退出

### 14.1 类型特有验证

- 查重结果记录：创建提案必含查重结论（同主题已存在 → 不新建，走更新或替代）；
- 载体内聚：decision/scope 在正文对应段逐字出现（frontmatter 是唯一权威文本，正文只展开）；
- 证据段条件：`urls` 非空 ⇒ 正文「证据」段存在（二元可判定：frontmatter 数组长度 > 0 与 H2 存在性）；
- 勘误边界：更新的 decision/scope 与 CAS 基线逐字段一致（防语义变更伪装勘误）；正文其余段的语义不变性是 AI 审核义务（§9.3），不在机械层；
- 终态完整性：retired 必有 reason + retired_at；superseded 必有且恰有一条 superseded-by 且目标可解析；
- 状态-关系不变量：active 不得带终态字段与关系；非 superseded 的 retired 不得带关系。

### 14.2 存量对象迁移

无 v5 存量。v4 仓库的 2 个 ADR 实例按「v4 存量不迁移」（Human 2026-09-09 决定）保留在 v4 历史归档，不进入 v5 事实源消费；其决策若仍适用，在 v5 以新 ADR 重新记录。

### 14.3 类型退出

若 Human 决定取消 ADR 类型，须按 03 §10 处理：处理仍适用决策的转移承接、入向/出向关系与稳定引用，登记变化（01 §8.2）与受影响引用同步，走受控提交。退出属 00 §4.2 根决定。

## 15. 验证与证据边界

| 验证对象 | 验证时机 | 成立条件 | 可接受依据 | 验证入口 | 可证明范围 | 未满足时的处理 |
|---|---|---|---|---|---|---|
| 载体结构 | 创建、更新或精确读取时 | H1 恰好一个且与 title 一致、正文自 H2 起、H2 固定序完整、各段非空 | 当前载体与本文 §8 | 机械（结构解析） | 当次载体结构合法性 | 拒绝创建/更新；修复后重走 |
| 载体内聚 | 创建与更新时 | decision/scope 在正文对应段逐字出现 | frontmatter 与正文对照 | 机械（逐字比对） | 索引与主体一致性 | 拒绝；补齐后重走 |
| 勘误边界 | 更新时 | decision/scope 与 CAS 基线逐字段一致 | 更新前后 frontmatter 对照 | 机械（字段比对） | 当次更新的勘误性质 | 拒绝；语义变更走替代路径 |
| 查重已执行 | 创建时 | 创建提案含查重结论 | 提案记录 | AI 语义审核 | 当次查重范围 | 补查重后重走创建 |
| 终态完整性 | 终态流转时 | reason/retired_at/superseded-by 齐备且目标可解析 | 对象全文与目标读取结果 | 机械（字段+关系校验） | 当次终态机械范围 | 拒绝流转；补齐后重走 |
| 决策语义质量 | 创建与终态时 | decision 可判定、备选与理由据实、scope 边界明确 | Human 确认记录 | AI 语义审核 + Human 终审 | 当次决策记录质量 | 拒绝或退回修订 |

机械结果与语义判断互不替代。本章不能单独证明决策正确、适用或被遵守——这些由消费点的真实使用核对；未实现与不可用范围保留为 gaps。

## 16. Human Gate

本文不新增 00 之外的 Human Gate。领域增量事项（00 §4.2 在 ADR 领域的具体化）：

1. ADR 的创建（决策的记录成立——含讨论分流与直接裁定两入口的记录确认）；
2. ADR 的终态决定（retired——废除已定决策）；
3. ADR 类型本身的取消或合并。

### 16.1 决定边界

Human 决定只证明决定及其作用范围，不替代查重判断、载体校验、装配相关性判断或终态机械校验。本文成为当前规则源成员时的 01 §8.1 登记与受影响引用同步，按 01 §8.2 的登记变化义务随本次规范新建一并执行。

## 17. Stop Conditions

本文不新增根停止类型。领域触发与最小影响范围：

1. 创建时发现同主题 active ADR 已存在（重复决策谱系风险）——未完成查重结论前不创建；
2. decision 为空或不可读、scope 缺失；
3. 准备以更新改写 decision/scope 语义（勘误边界违例）；
4. 终态流转存在 retirement_reason/目标缺口，或 superseded-by 目标不可解析；
5. AI 未经 Human 确认直接创建或流转（授权缺失）；
6. 装配/预检消费时 ADR 状态与引用不一致（引用了 retired 决策为现行依据）。

暂停期间只允许不越过停止边界的证据补取、引用修复、授权补走与条件核实。恢复须与触发原因逐项对应；同一停止条件恢复后再次触发的，按 00 §7.3 进入 Human Gate。

## 18. 反过度设计红线

1. 不设 `context`/`alternatives` frontmatter 字段——分析主体住正文，frontmatter 只留薄索引（`trigger_signal` 是短句信号非分析叙述，条件字段不违本线）；
2. 不设 `priority`、`tags`、`confidence` 类装饰字段——决策的重要性由消费点引用体现；
3. 不建 `supersedes` 正向键 + 目录扫描校验——单一 `superseded-by` 方向让终态校验只查本对象；
4. 不为「决策微调」开第二个更新通道——勘误级（逐字段不变）与替代（新对象）两路覆盖全部变更语义；
5. 不建决策族谱索引或时间线投影——谱系由 superseded-by 链与 Web 派生呈现承载，不写回对象；
6. 不把 ADR 变成规则源——决策被承接为可强制执行规则时由规范源承载（00 §3.3），ADR 保持记录身份。
