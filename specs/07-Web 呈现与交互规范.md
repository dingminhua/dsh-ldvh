# Web 呈现与交互规范


## 1. 价值判断

Web 呈现与交互解决 Human 难以直接观察 LDVH 状态、依据、授权和积累的问题，通过统一阅读层级与交互入口，使信息可定位、可回应、可回读，减少黑盒感、误操作和跨页面理解负担。

结构化问询与计划审查主要支撑 HV1 决策提请清晰可决；授权流和执行状态呈现主要支撑 HV2 授权执行受控可续；节点回读主要支撑 HV3 入档闭环节点可验；卡片网格、语义详情与扩展阅读主要支撑 HV4 积累效用直观可见与 HV5 项目演进脉络可循。V 轨价值由 AI 侧规范承接，Web 只呈现其可观察结果。

本规范只定义 Human 呈现语义与交互契约；机械拒绝、领域数据、宿主接入和 Code 实现由事实源与事实模型基础规范、业务系统基础规范、检查机制规范、LDVH CLI 确定性服务规范、管辖范围规范、DSH 环境接入与插件发布规范、Code 实践与测试规范与实际运行环境承接。

页面呈现、工具成功、组件加载或 Human 操作，只能证明当次呈现与交互范围，不能单独证明事实成立、授权覆盖、技术验证、工作完成或价值兑现。

**会话项目跟随的价值登记（2026-10-29）**：§7 的跟随各条按下述五项交还（`00 §6.3`）。**回应第 1 章的哪个问题**：Human 四项短板中的「眼前进展与任务，难以接续」——该短板要求「回来就能接着干」；多项目并行时，若 Web 呈现的项目与当前会话无关，人回到某个会话就得先确认「现在看到的是不是这个项目的」，接续的起点从内容退化为核对指向。**落实第 2 章的哪项根方案**：`00 §2` 的「以 DSH 宿主原生机制与能力为基线、以 LDVH 只作补充、完善与利用为原则」与「以 DSH 原生插件为交付形态，承载……Web 信息呈现……」——呈现的改指由既有交付形态、按既有管辖判定职责的结果发起，不新增判定职责、不新增业务系统、不新增事实类型。**预期影响哪些 V/HV**：主要支撑 HV4 积累效用直观可见与 HV5 项目演进脉络可循，取二者判据的**前提面**（读到的对象确属当前会话所属项目，而非别项目的同名对象；脉络不因呈现错位而混读），而非二者判据本身（实际复用与效用、关系可识别仍须各自证据）；V 轨不直接承接（Web 只呈现可观察结果，与本节同口径）。**新增什么负担与风险**：① 跟随会改指呈现，若沿用原项目的页内位置会把人带进「该对象不存在」的死路，故跨项目落回默认呈现的要求不得缺席；② 跟随与 Human 手动选择可能冲突，其优先边界与文档重新载入的情形**只在 §7 一处承载**，本段不复述，以免两处漂移；③ 判据不可得时的处置完整展开归 §8，本段只登记该风险的存在，不复述其规则；④ 工作树级指向不属跟随范围，同项目内呈现的仍可能是另一工作树的内容，该边界须由本文与消费侧各自如实声明，不得以项目级跟随冒充工作树级精确。**准备以什么证据核对**：① 规范侧——§9「会话项目跟随」行的成立条件逐条核对；② 机械侧——在「会话所属项目未变化时不换页」「变化时改指跟随目标且不沿用原项目的页内位置」「判据不可得时不猜项目」「会话所属项目不在登记列表内时不生效」四态各自具备可重跑的用例覆盖之前，不得声称本机制已获机械保障；③ 制度侧——本修订的独立审核结论与 Human 的决定记录须绑定同一内容形态，未留痕即不得主张审核与决定已完成。**尚无充分证据支撑的部分保留为缺口**：Human 是否因此减少手切、多项目切换是否真的不再混乱，在取得实际使用证据前不作推定；工作树级跟随是否需要另立规则，在取得「呈现的项目正确而工作树不符造成实际误读」的使用证据前不纳入本文。

**关系显示规则的价值登记（2026-09-28）**：呈现契约中新增的「认知中心热力图的关系显示规则」一表（现由 `plugin/web/docs/10-Web开发现状与设计语言基线.md` §5 承载）按下述五项交还（`00 §6.3`）。**回应第 1 章的哪个问题**：Human 四项短板中的「长期规划与演进逐渐模糊」——派生视图若把「已终结的目标」过滤掉，Human 看到的是一片干净但**不完整**的图，等于把「这条残留交出去之后怎么样了」这一问从视野里删掉；而不完整比不呈现更危险，因为它不像缺失。**落实第 2 章的哪项根方案**：`00 §2` 的「宿主原生机制承载编排与注入」＋「元规范承载规则」——显示判据此前只存在于实现，本表把它落成可回查的规则，并指明唯一权威仍是定义该关系的规范（`21 §12`），显示层不得自行放宽或收紧形态。**预期影响哪些 V/HV**：主要支撑 HV5 项目演进脉络可循（演进脉络里「已终结的去向」也是脉络的一部分，不得静默消失）、HV4 积累效用直观可见；V 轨不直接承接（Web 只呈现可观察结果，V 轨由 AI 侧规范承接——与本节同口径）。**新增什么负担与风险**：① 每新增一个关系键即须在本表补一行——未登记即意味着该键的显示判定没有可回查的规范源，在其补入本表之前不得主张该键的显示形态成立（已登记的缺口见 `plugin/web/docs/10` §5）；② 显示期与写入期两个判据并存于同一关系键，读者可能误读为两处权威——本表以「唯一权威仍是 `21 §12`、显示层只选择呈现范围」显式拆分。**准备以什么证据核对**：① 机械侧——在本表的每一行都具备可重跑的关系显示用例覆盖之前，不得声称该行已获机械保障；② 对应侧——本表每行须与实现中的唯一对应点逐行相符，行与实现不一致时以本表与 `21 §12` 为准并须修正实现，不得反过来据实现放宽本表；③ 制度侧——该收窄的决策依据（原判定允许指向 WorkCase 且状态不限，与 `21 §12` 互斥）已登记在该表「为什么目标接受终态而写入期只接受 `open`」段。**尚无充分证据支撑的部分保留为缺口**：其余七个关系键的显示条件仍未获规范登记；本表的效用（Human 是否真能据此更新演进认知）在取得实际使用证据前不作推定。

## 3. 职责边界

### 3.1 本文负责

1. 四层阅读器的呈现语义与切换契约（字段级直读 / 卡片网格 / 语义详情 / 扩展阅读）（§5），含呈现契约的归属与效力边界（§5.5）；
2. 交互入口的触发条件与 Human 响应契约（结构化问询 / 计划审查 / 授权流 / 验收交还）（§6）；
3. 管辖项目登记与取消登记的 Web 交互契约（经管辖范围规范 §5.4/§5.7 受控登记流程承载，Web 不自行解析或直写登记载体）（§6.5）；
4. 管辖项目在 Web 中的切换呈现规则与会话项目跟随规则（§7）；
5. Web 呈现边缘条件的识别与处理方式（登记文件缺失、项目未管辖、授权范围不清、交还未通过等场景下的 UI 行为）（§8）。

### 3.3 相邻规范分工与唯一权威

事实源与事实模型基础规范是事实与状态语义的唯一权威，LDVH CLI 确定性服务规范是 LDVH CLI 响应的唯一权威，受控提交与机械守护规范是提交与溯源语义的唯一权威，管辖范围规范是管辖判定的唯一权威，DSH 环境接入与插件发布规范是宿主接入的唯一权威，Code 实践与测试规范是 Code 实现的唯一权威；07 只定义呈现语义与交互契约，不改变任何领域语义，不成为第二规则源。

### 3.4 本文只承载要求，不承载实现状态

本文正文只承载**要求**——在某条件成立时应当或不应当做什么，以及呈现语义与交互契约（呈现什么、何时呈现、如何派生、状态如何表达）。**不得承载任何「当前如何」的事实陈述**：实现状态（某项机制是否已实现、已由何提交落地、实现所在的文件、组件、函数、常量或测试）、下位文档的存在状态与过程进度。

**判据**：本节不另立判据——某处正文是状态还是规则，一律按 `01 §7.2` 的判据（断言 vs 规定，载体无关）判定。**本节的范围限于本文正文**（`specs/07`）；其余载体的状态禁令与该判据的作用域见 `01 §7.2`。

**状态的去向**：**实现与状态由下位设计文档（`plugin/web/docs/`）承载**，不由本文承载。具体的呈现接线——由哪个组件、哪处常量、哪份测试钉住——属实现接线，其登记与维护归下位设计文档；本文只定义可被验收的呈现要求。

确需向读者提示现状时，以**条件式要求**表达（「在 X 具备之前，不得主张 Y 已生效／已完成，并须如实披露未兑现范围」），把事实判断的责任交还给读取时的观察。

**相邻形态（不受本款禁止）**：条件式要求、假设与反例、对读者的处置指引——这三类是义务而非事实陈述，应当保留。

**本款与 §3.3 的分工**：§3.3 约束**职责**边界（07 不越权定义领域语义，不成为第二规则源）；本款约束**内容形态**（07 不承载实现状态）。二者互不替代——缺前者会使 07 变成第二规则源，缺后者会使 07 变成实现台账。

## 5. 四层阅读器

四层阅读器承载 Human 对 LDVH 项目信息的呈现消费。四层**互不替代、不互锁**：Human 可随时切换至任一或同时展开多层，不要求从低层向高层递进。

### 5.1 字段级直读

- 呈现事实对象的核心字段（名称、状态、指纹、时间戳、来源引用）
- 面向快速定位与核对：Human 可一眼确认某条记录是否存在、状态如何
- 不渲染关联关系或语义解释

### 5.2 卡片网格

- 以卡片形态呈现事实对象摘要（标题、状态标签、单行摘要、关联计数）
- 支持按类型、状态、维度、时间等条件筛选与排序
- 面向浏览与概览：Human 在卡片间扫描，定位感兴趣的对象

### 5.3 语义详情

- 完整呈现单条事实对象的所有字段与关联引用，含来源回指
- 显示该对象的变更历史（摘要形态，不要求完整 diff）
- 面向深度核查：Human 逐条审阅内容、判断适用性与完整性

**已登记的窄例外（Human 授权 2026-09-28）**：WorkCase 终态（`status = closed`）对象的 `result.residual` 不上屏——见 `plugin/web/docs/10` §5「「已关闭」为何不再呈现残留」。这是本条首句「完整呈现所有字段」的**一处明确例外**，由 Human 直接授权（原话：「在关闭页面就不应该有残留信息了，要删除掉，规范里也要明确一下」；追问后答「1，要删」，确认详情页同）。**该例外不扩张**：只作用于 WorkCase 终态对象的 `result.residual` 这**一个字段**与这**一种状态**，不得据以将其它类型、其它字段或其它状态下的呈现收窄解释为合法。**该例外的适用范围（2026-09-29 修订）**：条件豁免段已于该日删除（见 `plugin/web/docs/10` §5），故**全部** WorkCase 终态对象**一律**适用本例外——不再区分形态或去向正文是否自足（此前「不满足前提者如实保留」那一侧已随该段一并取消）。

### 5.4 扩展阅读

- 跨对象关联呈现：按话题、决策链、问题-方案-结果线索串联多条事实
- 呈现事实的积累效用与复用情况（HV4/HV5 的承载面）
- 面向脉络探索：Human 沿关联追踪项目演进路径

### 5.5 呈现契约的归属

本文只定义**呈现语义与交互契约的顶层约定**，不承载具体规则。四层阅读器（§5.1–§5.4）与交互入口（§6）定义「呈现什么、何时呈现、面向什么判断」；**具体规则——各类对象的呈现细节、派生判据、卡体构成、行式与形态纪律——归 Web 专属设计文档**。

**归属（Human 指示 2026-10-09）**：WorkCase 的呈现契约（三态直读、派生分组与筛选档位、执行期阶段与变更流水、四组卡体块构成与次序、去向分区与逐项标记、块序与单一来源纪律、合并徽标与取消理由块、统一关联行、热力图关系显示规则等）整体由 **`plugin/web/docs/10-Web开发现状与设计语言基线.md`** 承载，本文不再复述。

**下位设计文档的目录与命名**（本款是**规定性要求**，不是现状登记）：

- 全部 Web 专属设计文档一律位于 **`plugin/web/docs/`**，不散落到其它目录；
- 文件名形如 **`NN-<短名>.md`**：`NN` 为两位十进制序号，短名表达该文档职责（中文或小写 kebab-case）；同一序号不得重复；
- **序号一经分配不得改号、不得复用**——改号会使既有引用静默指错（本仓已发生过同类事故：规范改号后 21 号 15 处引用仍指旧号位而无人察觉）。文档作废时**保留其序号**，或留一个指向继承者的文件，或明确登记该序号不再使用；
- **每份文档首部须声明自己的范围与上位依据**（`> 范围：…` 与 `> 上位：…`），使读者无需外部索引即可判断它管什么、受谁约束；

## 6. 交互入口

交互入口承载 Human Gate 与交还流程。每个入口定义触发条件与 Human 响应契约，并在 Web 中呈现对应面板。

### 6.1 结构化问询

- **触发条件**：AI 需要 Human 判断、选择或补充信息，问题已组织为带选项、影响与风险的结构化形式
- **Human 响应契约**：呈现代选项与自由输入，响应须含对象、范围与处理结论

### 6.2 计划审查

- **触发条件**：AI 呈交候选计划，等待 Human 审查或批准；Gate 1 / Gate 2 的授权语义以 21 的文本为准；该语义属 WorkCase 类型语义（21 §3.3），不属目标规划与火花记录业务系统（30/31 号位）的职责，故本节的触发依据以 21 现行文本为准
- **Human 响应契约**：呈现计划依据、范围、步骤与风险，**Gate 1 批准时另须呈现建前独立审核结论（21 §10.1 第五提请要素；其持久承载为对象 `pre_reviews` 字段，见 21 §8/§14）**，Human 批准/拒绝/要求修改。**待批准执行期的建前审核标记**：`draft` 对象须让 Human 一眼看出**这份候选审没审**。形态为**同一派生组内的文字后缀**而非新增派生组——已取得通过审核结论者显示原词「待批准执行」，未取得者显示「待批准执行 · 待审核」；二者**配色相同**（它们是同一分组内的完成度标记，不是语义相反的两个状态，故不适用「语义相反须显著不同色」的纪律）。判据取自对象字段 `pre_reviews`、**不得**改用运行期状态；后缀**只在一处拼接**（徽标的 statusLabel 入口），防口径漂移。`draft` 卡另须与「执行中」卡同形显示变更流水，作为「有没有动静」的佐证（判据与形态细则见 `plugin/web/docs/10` §4.2.1）

### 6.3 授权流

- **触发条件**：AI 需要 Human 授权才能执行或继续某项受控操作
- **Human 响应契约**：呈现授权对象、范围、边界与执行状态，Human 授予/拒绝/限制，越权动作被机械拒绝

### 6.4 验收交还

- **触发条件**：AI 完成当前工作，呈交验收结果
- **Human 响应契约**：呈现 00 §5.8 Output Envelope 的 Human 可读视图与验证证据，Human 验收/退回/要求补充；Web 不重新定义 Envelope，也不把呈现或验收写成技术验证

### 6.5 登记管理

- **触发条件**：Human 在 Web 中发起项目登记或取消登记（对应管辖范围规范 §5.4/§5.7 的 Web 入口）
- **Human 响应契约**：呈现登记对象、项目路径、综合就绪状态与分项诊断。**安装事务的步骤、状态闭集与失败处置由 DSH 环境接入与插件发布规范 §6 定义，本文不复述**；本文只定义其**呈现与交互约束**：(a) 用户选择的目录由 Host 确认为实际 Git 根后方可提交安装；(b) 未就绪项须分项呈现原因而非合并为单一结论；(c) 可修复与不可修复状态须在交互上可区分，前者提供修复入口、后者只呈现原因；(d) 写入与移除经管辖范围规范 §5.4/§5.7 和 DSH 环境接入与插件发布规范 §6 定义的受控流程并分项回读确认，**Web 不自行解析或直写**登记载体、事实源或 Hook

## 7. 管辖登记与项目切换

管辖范围规范 §5 登记的管辖项目在 Web 中可切换呈现。本节含两类规则：**手动切换**（下列前四条）与**会话项目跟随**（其后各条）。跟随不是手动切换：它不由 Human 在页面内发起，也不改变任何登记内容。规则如下：

- 管辖项目的列出由管辖范围规范定义的唯一管辖判定职责读取 Human 已定案的登记载体，Web 不自行解析候选路径或 Schema；
- Human 在 Web 中切换当前呈现的管辖项目，切换后四层阅读器与交互入口均指向目标项目的事实源；
- 切换只作用于 Web 呈现层，不改变当前会话工作目录，不触发 LDVH CLI 或 Git 操作；
- 本节的**手动切换**沿用管辖范围规范 §7 消费方表所列 Web 的消费方式；跟随对该判定结果的使用另见下文跟随条，不并入本条。

**本节用词**（三个对象可以互不相等，规则出现其一时不得混用）：**会话所属项目**指唯一管辖判定职责就当前会话给出的管辖项目——判定以路径为输入（管辖范围规范 §5.3）；会话到路径的取得不由本文定义，其服务身份见 LDVH CLI 确定性服务规范对 `resolve-governance-scope` 的声明（解析当前会话工作目录的管辖状态），Web 也不得据此自行解析路径。**当前呈现项目**指 Web 本次呈现其内容来源的项目。**跟随目标**指会话所属项目且位于登记列表内时的那个项目。**呈现指向**指当前呈现项目被选定的结果，即本次呈现取自哪个项目。**页内位置**指 Web 呈现所在文档内的浏览位置（含当前路径与已阅读到的位置）；**页内筛选**指该文档内已施加的筛选与展开状态；二者只在同一项目、同一文档内有意义。**默认呈现**指一个项目的入口位置，不指默认进入某一阅读层（四层互不递进，见 §5）。**文档存续期间**指一次文档载入到下一次文档载入之间：期间内的页内路由与列表刷新不属重新载入，页内位置与页内筛选存续；**文档重新载入**指呈现所在文档再次取得内容的载入（iframe 重载或浏览器刷新同型），此时页内状态随旧文档消亡，是否保留见下文跟随条。**此前跟随结果**指同一文档存续期间内上一次跟随所确定的呈现指向，无跟随结果时不存在比较基准。

会话项目跟随的规则如下：

- Human 打开或切换会话时，当前呈现项目跟随该会话的会话所属项目；跟随判据取自管辖范围规范定义的唯一管辖判定职责，Web 不自行解析候选路径、不自行读取登记载体、也不自行判定管辖状态。本条按该判定结果决定**呈现指向**，与管辖范围规范 §7 Web 行所定「决定功能呈现与隐藏」是同一判定结果的不同用法：本文不据此主张管辖范围规范 §7 已涵盖呈现指向，也不代为改写该表的表述——是否在该行补入这一用法属管辖范围规范的职责，须由 Human 决定；判定语义本身不因本条而改变；
- 跟随只决定项目级的呈现指向：工作树级的呈现选择不属跟随范围，本文不定义之，跟随也不保证呈现内容取自会话所在工作树；跟随的呈现层效力范围与本节切换条相同，另不改变登记的默认项目；
- 文档存续期间内，改变呈现指向的判据是**会话所属项目相对此前跟随结果发生变化**，而不是与当前呈现项目不一致：会话所属项目未变而 Human 已手动切换到别的项目时，跟随不把人拉回——跟随不与人争夺呈现；判不出会话所属项目时不改指，保持当前呈现（处置见 §8）；
- 同一项目的不同会话之间切换时呈现指向不变、页面不重新载入，页内位置与页内筛选因此原样保留；
- 文档重新载入后呈现指向以跟随目标为准；跟随不承诺页内位置与页内筛选跨载入存续——二者是否恢复由重新载入的方式决定，不属本节规则，也不得据此要求保留；未恢复时落回该项目的默认呈现即为合格呈现；
- 会话所属项目不在登记列表内时不存在跟随目标，跟随不生效，呈现按 §8 相应行处置；
- 跨项目改变呈现指向时落回跟随目标的默认呈现：原项目的页内位置与页内筛选不保留——对象标识在项目内有效，沿用原项目的页内位置只会指向不存在的内容；
- 跨项目汇总呈现的视图（联邦视图）不享有跟随豁免：呈现指向的改指对它同样生效，它与其他单项目视图一样按本节判据被替换或保留；但跟随不改变该视图自身的数据范围——其内容始终覆盖登记列表内的全部管辖项目，与呈现时的当前呈现项目无关；
- 跟随不改变任何事实的读取范围——它改变的只是呈现指向。

## 8. Web 边缘条件处理

以下条件处理仅影响 Web UI 呈现行为，本身不新增 Human Gate 触发条件或必停情形；Human Gate 以 `00 §4.2` 为准，必停情形以 `00 §5.7` 为准，本文领域增量见 §10–§11。

| 条件类型 | 具体条件 | 处理方式 |
|----------|----------|----------|
| 登记文件缺失 | 管辖范围规范登记文件尚未创建 | 显示“尚未初始化”并提供受控安装入口；不可读、权限不足或 Schema 无效时显示 `unavailable`，不得伪装为“未管辖” |
| 项目未管辖 | 当前项目不在登记列表 | 隐藏 LDVH 功能，提示登记入口 |
| 授权范围不清 | 授权对象/范围/边界不明确 | 显示授权不可用状态，提示 Human 补充范围 |
| 交还未通过 | 验收交还条件不满足 | 退回至 AI 补充或修正 |
| 切换失败 | 目标项目登记文件损坏 | 保留当前项目呈现，提示问题 |
| 跟随判据不可得 | 取不到当前会话的会话所属项目（判定入口不可达、判定尚未完成，或判定结果为 `not_governed`／`unavailable`） | 不存在跟随目标，跟随不生效，保持 Web 自身的项目选择与当前呈现；不据缺失猜测项目，也不清空已有选择。跟随是呈现增强，不是页面可用性的前置条件。**本行只处置会话级跟随判据的缺位，不改变本表其余各行的处置**：登记载体缺失或不可读按「登记文件缺失」行处置，当前呈现项目不在登记列表按「项目未管辖」行处置，不得以「跟随判据不可得」为由继续呈现已不在登记列表内项目的内容 |

登记载体损坏、不可唯一解析等触及管辖范围规范 §10 停止边界的条件，其暂停语义以管辖范围规范 §10 与 00 §5.7 为准；Web 层仅按本节表格呈现对应状态（“尚未初始化”、`unavailable`、保留当前呈现并提示），不自行处置，也不把呈现写成暂停已执行。

| 验证对象 | 验证时机 | 成立条件 | 可接受依据 | 验证入口 | 可证明范围 | 未满足时的处理 |

| 关键节点可回读 | Human 核对节点时 | 受控创建、状态变更、关闭节点在语义详情或扩展阅读可核对 | 语义详情与扩展阅读 | 节点回读核对 | 当次可回读范围；不证明节点语义正确 | 不可回读时如实披露缺口 |
| 价值声明可观察 | 声称 HV4/HV5 时 | 页面可呈现相应复用与演进依据 | 卡片网格与扩展阅读 | 呈现依据核对 | 只证明页面可呈现相应依据；不单独证明 HV4/HV5 已成立 | 无依据时降低声明并记录缺口 |
| Output Envelope 呈现 | 每次验收交还时 | 机器可读结果与 Human 可读视图两层表达一致 | 00 §5.8 结果与 Human 可读视图 | 一致性核对 | 当次呈现一致性；不证明技术完成 | 不一致时退回修正，不交付矛盾呈现 |

机械结果与语义判断互不替代。页面呈现、组件加载或 Human 操作只能证明各自呈现范围；本章不能单独证明事实成立、授权覆盖、技术验证或 V/HV 价值成立，未执行和不可用范围保留为 gaps。

## 10. Human Gate

本文不新增 00 之外的 Human Gate。

### 10.1 领域增量事项

以下事项是 00 §4.2 在 Web 呈现与交互领域的具体化：

1. 改变四层阅读器的层级定义、切换契约或交互入口的触发条件与响应契约；
2. 改变管辖项目切换、会话项目跟随或 Web 边缘条件的处理语义。

受保护文档修改按 00 §4.3 执行，此处仅回指，不构成本文领域增量。

### 10.2 决定边界

Human 决定只证明决定及其作用范围，不替代呈现一致性核对、触发条件核对或节点回读核对。

## 11. 必停情形

本规范不新增根停止类型。

### 11.1 领域触发与影响范围

出现以下任一情况时，按 00 §5.7 暂停受影响的最小呈现、交互或完成声明范围：

1. 呈现所依据的来源（登记载体、事实源、Output Envelope）缺失、不可读或相互不一致；
2. 准备把页面呈现、组件加载或 Human 操作写成技术验证、授权成立或整体完成；
3. 交互入口的触发条件或响应契约无法确认。

### 11.2 暂停期间允许动作

暂停期间只允许不越过停止边界的规则定位、只读核对、呈现比对、修复与分流准备，不得继续受影响交互或完成声明。

### 11.3 恢复与再次触发

恢复须与触发原因对应，且只覆盖当前依据支持的范围；同一停止条件恢复后再次触发时按 00 §5.7 进入 Human Gate。

## 12. 反过度设计红线

1. 不要求四层阅读器互锁或从低层向高层递进；
2. 不指定 UI 框架、组件库或预设组件形态——只定义呈现语义与交互契约；
3. 不绕过管辖范围规范的登记制度在 Web 侧自行解析管辖项目列表或候选路径；
4. 不在 Web 中直接改写规范或写入事实——均经受控提交与机械守护规范的机械预检与 Git Gate 流程、以及 LDVH CLI 确定性服务规范流程；
5. 不在已授权范围内重复提请 Human Gate 或把已授权操作再次转为问询；
6. 不为状态切换、加载或列表更新加入装饰性动画、过场或音效；必要的加载与进行中反馈只用于表明实际进行中的操作，不用于营造效果；
7. 不在单一视图中堆积与当前判断无关的信息，不以信息密度代替可用性；长列表与长文本须有分页、折叠或分层入口，不一次铺满；
8. 不用颜色、图标或动效单独承载状态语义；状态须有可读文本与可区分形态，使色觉差异或静音环境下仍可判断。
