## 1. 价值判断

管辖登记制度把“哪些项目受 LDVH 管辖”从 AI 的记忆与环境猜测改为固定载体上的可回读判定，使受控操作、机械检查与呈现以同一判定结果为门禁输入。本文主要承接 00 的以下价值：

- **V1 快速定位**：工作对象涉及的 Git 根、事实源路径（`ldvh-base/`，受管载体边界见 06）与规范路径（`specs/`，由 01 定义）均有明确来源，管辖判定引用的登记载体位置固定可回指。
- **V3 边界识别**：当前项目是否受管辖可依据登记载体判定；非管辖项目不进入受控操作，登记载体缺失或损坏时暂停而不是猜测。
- **V6 工作接续**：登记载体保留项目登记状态，新会话可读取登记列表恢复管辖判定结果。
- **HV2 授权执行受控可续**：管辖判定结果作为 Helper 操作与 Git Gate 的机械门禁输入，未登记项目被拒绝受控操作。

登记文件存在、判定成功、路径解析或文件写入，均不单独证明以上价值成立；价值由实际使用、回读核对与后续验证共同核对。

## 3. 职责边界

### 3.1 本文负责

1. 管辖登记制度：登记方向、登记载体语义、判定方式、登记入口与取消登记（§5）；
2. 工作对象边界：Git 根目录、事实源路径与规范路径的定位语义（§6）；
3. 管辖判定语义：只读登记载体的判定规则与前置条件（§5）；
4. 消费方消费管辖判定结果的语义接口（§7）。

### 3.2 本文不负责

1. 登记文件的具体字段 Schema、文件名与格式——精确载体定案前留空，定案后回写本文或以授权附件登记；
2. Helper 传输 envelope——归 05；受管载体与受控提交——归 06；
3. Git Hook 部署、插件装载与环境接入——归 08；Code 实现与测试——归 09；Web 交互细节——归 10；
4. AI 对当前行动是否适用管辖判定的语义判断，与 Human 的授权、验收决定。

01 是规范路径与当前规则源的权威，06 是事实源与受管载体的权威，05 是传输 envelope 的权威；07 只定义登记制度、判定语义与工作对象边界，不另建第二登记权威。

## 4. 适用范围

本规范适用于 LDVH 对管辖项目的登记、取消登记、管辖判定与工作对象定位，以及 Helper、Git Gate、Skill 与 Web 消费管辖判定结果的语义边界。普通项目操作、非 LDVH 受控流程不因本规范存在而强制经过管辖判定；本规范不适用于登记文件的具体 Schema、Helper 传输、Git Hook 部署、Code 实现或 Web 交互细节。项目已登记、判定成功或路径可解析，只证明当次判定的机械范围，不单独证明行动适用、授权成立或价值兑现。

## 5. 管辖登记制度

### 5.1 用户目录登记方向

v5 采用用户目录下的登记目录制度（候选名 `dsh-ldvh`，精确目录名经 Human Gate 定案），不再使用 v4 的项目外独立配置和向上遍历。精确路径、目录名在不同系统上的解析、文件名、Schema、权限、迁移与兼容规则在实现该能力时经 Human Gate 定案；定案前不得把候选路径写成已经成立的固定位置。

### 5.2 登记载体

登记文件夹内包含一个登记文件，记录所有 LDVH 管辖项目的列表；具体文件名与格式由实施定案后回写本文或以授权附件登记，本文不定死。

### 5.3 判定方式

1. 每次判定时，只读该登记文件；
2. 判断当前项目是否在登记列表中；
3. 不做向上遍历（废弃 v4 向上查找 `LDVH-GOVERNED-PROJECTS.yaml` 的做法）。

### 5.4 登记入口

1. **AI 入口**：用户在项目目录内对 AI 表达把当前项目设为 LDVH 管辖的意图时，Helper 先只读登记文件确认当前项目不在列表中，再写入登记文件；写入应使用原子操作防并发竞态，写入权限与原子机制按 08 §6 执行（08 核验、09 实现）；
2. **Web 入口**：通过 Web 界面管理登记列表，交互细节归 10。

### 5.5 前置条件

1. 登记对象必须是 Git 项目（存在 `.git` 目录）；
2. 非 Git 项目不允许登记。

### 5.6 创建与呈现

精确载体定案后，Helper 才可按来源规定受控创建用户目录登记载体；创建前读取当前状态，写入使用原子或版本守卫机制并回读。实际路径由 Web 和 AI 登记响应如实呈现，不得在定案或创建前展示为已成立。

### 5.7 取消登记

1. **AI 入口**：用户明确要求取消时，Helper 从登记文件中移除对应项目并回读确认；
2. **Web 入口**：通过 Web 界面操作移除。

## 6. 工作对象

工作对象成立的前提是项目已登记且为 Git 项目（§5.5）。

1. **定义**：工作对象 = 当前项目 Git 根目录 + 事实源路径（`ldvh-base/`）+ 规范路径（`specs/`）；
2. **登记载体边界**：用户目录登记载体位于项目 Git Working Tree 之外，不属于项目事实源、受管事实载体或 Git Gate 候选；它是项目外受控配置载体，语义由 07 定义，写入权限与原子机制按 08 §6 沙箱分层与文件观察策略执行——用户目录属跨工作区路径，其写入授权路径由 08 核验登记，核验与登记完成前 AI 登记入口不得声明可用；
3. **边界**：工作对象不跨越多个项目（单项目单 worktree）；多项目聚合归未来规范（v4 多项目聚合做法废弃）。

## 7. 管辖判定消费方

| 消费方 | 消费方式（语义接口，不描述具体 UI/传输细节） |
|---|---|
| Helper | 在执行 LDVH 操作前调用管辖判定，未管辖时拒绝操作 |
| Git Gate | 在 Git Hook 事件中检查管辖状态，未管辖时阻断提交 |
| Skill | 是否保留由 08 §5.6 宿主接入定案；保留时执行前检查当前项目是否在管辖列表 |
| Web | 参照管辖判定结果决定功能呈现与隐藏 |

消费方按判定结果执行是消费方自身规范的承接义务；本表只定义语义接口，不证明任一消费方已经实现。

机械拒绝语义：非 Git 项目拒绝登记；项目未登记时拒绝受管操作；已登记时不重复写入。权限层的机械拒绝与停止层的暂停互不替代（00 §7.2）。

## 8. 验证与证据边界

| 验证对象 | 验证时机 | 成立条件 | 可接受依据 | 验证入口 | 可证明范围 | 未满足时的处理 |
|---|---|---|---|---|---|---|
| 登记载体存在性 | 管辖判定或登记操作前 | 定案载体存在且可唯一解析 | 文件系统与 Human 定案记录 | 载体定位检查 | 载体存在与可解析；不证明项目清单语义正确或授权成立 | 暂停受影响判定与操作并按 00 §7.2 交还 |
| 登记内容有效性 | 登记或取消登记时 | 项目路径格式有效，登记项目实际存在且含 `.git` | 登记文件与项目目录观察 | 登记校验 | 当次登记条目的机械有效范围；不证明项目应否受管辖 | 格式无效时拒绝登记；发现孤立记录（幽灵登记）时标记并提示 Human |
| 判定结果一致性 | 每次管辖判定后 | 多次判定结果一致且可回指同一登记状态 | 判定响应与登记文件 | 判定结果核对 | 当次判定范围；不证明行动适用或授权 | 结果不一致时暂停受影响操作并重新判定 |
| 登记写入 | 登记或取消登记后 | 原子写入完成且回读一致 | 写入结果与回读 | 写后回读核对 | 当次实际登记变化；不证明管辖正当性或 Human 决定 | 回读不一致时暂停并修复，不宣称登记完成 |
| 消费方行为 | 消费方执行受控操作时 | 消费方按判定结果执行拒绝或放行 | 各消费方的执行记录 | 消费方规范域验证 | 当次消费执行；不证明判定语义或整体完成 | 未按判定执行时由消费方规范域暂停受影响操作 |

机械结果与语义判断互不替代。登记存在、判定成功或消费方放行只能证明各自机械范围；本章不能单独证明登记正当、行动适用、授权覆盖或 V/HV 价值成立，未执行和不可用范围保留为 gaps。

## 9. Human Gate

本文不新增 00 之外的 Human Gate。以下事项按 00 §4.2 提请 Human 对准确候选及作用范围作出明确决定：

1. 登记载体精确路径、目录名、文件名、Schema、权限与迁移方案的首次定案；
2. 改变登记方向、判定方式或工作对象边界（含恢复向上遍历或跨项目聚合）；
3. 是否移除幽灵登记。

受保护文档修改按 00 §4.3 执行，此处仅回指，不构成本文领域增量。

Human 决定只证明决定及其作用范围，不替代登记校验、判定结果核对或写后回读。

## 10. Stop Conditions

本规范不新增根停止类型。出现以下任一情况时，按 00 §7.2 暂停受影响的登记、判定或受控操作：

1. 登记载体损坏、不可唯一解析或无法受控读取；
2. 登记载体无法受控创建或权限不足；
3. 判定范围不清或多次判定结果不一致；
4. 准备在未登记或非 Git 项目上执行受管操作。

暂停期间只允许不越过停止边界的规则定位、只读核对与修复准备。恢复须与触发原因对应；同一停止条件恢复后再次触发时按 00 §7.3 进入 Human Gate。

## 11. 反过度设计红线

1. 不以任何形式向上遍历查找登记文件（废弃 v4 做法）；
2. 不把工作对象扩展到跨多个项目或多 worktree 聚合；
3. 不在本文硬编码登记文件名、格式或系统特定路径；
4. 不在登记或判定前省略 `.git` 目录存在性检查；
5. 不为管辖判定建立第二登记表、缓存权威或独立状态账本。
