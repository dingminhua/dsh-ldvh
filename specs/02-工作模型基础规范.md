# 工作模型基础规范


## 1. 价值判断

工作模型把 00 的根方案展开为 AI 可执行的职责框架，使主控与协助者能用同一组职责语言组织行动、复核结果和恢复工作，减少职责混淆、重复流程与接管时的上下文重建负担。

读、编排与遵守主要支撑 V1–V3、V5 和 HV1–HV2；记忆、调研与复核主要支撑 V4–V5、V7 和 HV1–HV3；写、记忆与沉淀主要支撑 V6、V8 和 HV3–HV5。工作模型是全部管辖行动的职责框架，分组映射的并集覆盖 00 §6 全部价值；主要影响判断体现在各系统与价值的对应关系，而非排除某项价值。

本规范只定义工作模型职责、协同和恢复框架；事实、既有行动结构、服务、实现、Human 授权与具体领域价值由相邻规范和实际行动承接。该映射只说明预期价值贡献，不表示单一系统独占某项价值。

系统、技术或流程存在，或者一次执行成功，均不能单独证明价值成立；价值只能在实际工作、结果、证据和 Human 使用中按 00 §6 核对。

## 2. 规范依据

本文直接依据：

1. `ldvh-root`：00 §2 的根方案、§3.1 的工作模型、§3.4 的技术保障、§4 的 Human 决定权、§5 的 AI 责任、§6 的双轨价值和 §7 的防自欺、Stop Conditions 与交还；
2. `specification-model-foundation`：01 §6 的身份块契约、§7 的共同章节结构、§9 的当前规则源条件、§10 的 L0–L4 读取层级与 §12 的独立对抗审核。

本文不依赖额外外部语法或行业标准定义工作模型语义。

03–10、20–27 与 30–35 是机制和领域承接对象，不是本文的规范依据。开发备忘、研究和实现只作设计输入，不取得规范效力；机制指向须在相应来源成立后回核，未兑现前不证明系统机制已经实现。发生冲突或权威关系无法确认时，按 00 §7.2 暂停受影响范围并完成对齐。

## 3. 职责边界

### 3.1 本文负责

本规范负责：

1. 承接 00 §3.1 工作模型根定义，具体化每项能力承载、业务系统与制度的职责、判据、机制指向与边界；
2. 定义共同框架：最小充分机制、单一主控与协助者协作、技术选择原则、稳定事实与运行状态区分、横向机械保障；
3. 定义协同与四层判断的描述边界；
4. 定义暂停、接管、恢复与交还在工作模型框架下的承接边界。

身份块声明七维全集，是因为正文实质承担全部系统的领域定义责任；它不表示规范文件自身替代主控执行工作模型。

### 3.2 本文不负责

本规范不重新定义能力承载、业务系统或制度的数量、名称或根职责，不定义事实字段、事实类型状态机、业务系统规范步骤、LDVH CLI 协议、Git 提交契约、DSH 接入实现或 Web 呈现。

### 3.3 相邻规范分工与唯一权威

00 是工作模型根定义的唯一权威；03 是事实公共模型与受控读写的唯一权威；04 是业务系统规范共同结构的唯一权威；05–10 及事实类型、具体业务系统规范只在各自职责内承接机制。本规范只定义工作模型职责框架，不复制相邻规范的字段、步骤、协议或实现。

## 4. 适用范围

### 4.1 适用对象

本规范适用于：

1. LDVH 管辖行动中的主控与协助者；
2. 下位规范对其机制所支持系统或制度的声明。

### 4.2 适用场景

本规范用于工作模型职责的识别、组合、执行、复核、恢复与交还。普通讨论只有在实际进入相应行动职责时才受具体系统要求约束。

### 4.3 明确排除与证明边界

本规范不适用于脱离具体行动的流程仪式设计，也不替代事实、既有行动结构、服务或实现规范。系统声明和适用范围成立本身不产生授权、事实、流程或完成结论。

## 5. 共同框架

### 5.1 工作模型不是分层流程

一个行动可以同时触及多个系统，也可以在推进中返回此前系统；主控只激活目标和风险实际需要的最小充分机制。能力承载、业务系统与制度不是三类事实类型、状态机、LDVH CLI 确定性服务、审核仪式或过程日志。

### 5.2 单一主控与协助者

本节只承接 00 §5.1、§5.3 的单一主控、协助者责任及其不可转移边界，不重新定义。工作模型框架只增加：全部系统职责均在该责任结构内展开，系统划分、委派、并行与复核不分割主控的整体责任。

### 5.3 技术选择原则

执行形态由主控按目标、依赖、风险、专业性、上下文隔离和恢复需要选择。直接执行、可续子代理、隔离或继承视角、多视角思考、团队调度和工作流等只是候选协助形态，不产生授权、事实或完成结论；具体名称、能力与 DSH 接入由 08 核验和承接。

### 5.4 稳定事实与运行状态

宿主任务、成员、attempt、Session、Thinking 分支、临时 Goal、消息、工具事件、服务响应和 Web 投影等属于运行状态，不自动进入事实源；本列举不是闭集，具体宿主形态由 08 定义。Output Envelope 是 00 定义的交还语义，其 Web、文件或工具载体属于实现层运行状态，两者不得混同。需要跨行动保留的内容先由记忆与反思系统的沉淀环节判断去向，再按 03 的准入与受控写入要求落位；稳定事实是否对象化以 03 的准入为准。

### 5.5 横向机械保障

Git Gate、权限、沙箱、文件观察、运行时不变量和宿主事件等是横向机械支撑；宿主事件能力由 08 核验，不属于单一系统。机械层只执行来源已定义的确定性检查，不替代主控判断、Human 决定或完成判断。

## 6. 读（能力承载）

- **职责**：取得当前工作所需且来源明确的规范、事实、状态和能力信息，控制上下文负担。
- **判据**：实际使用的信息可回指来源；候选、片段、完整来源、已读和未读范围可区分。
- **机制指向**：规范分层读取、事实分层召回、LDVH CLI 读取、宿主引导与预算，以及 Web 呈现的 Human 阅读入口；具体契约分别由 01、03、05、08、10 承接。
- **边界**：读取成功不证明理解、适用、授权或完成。

## 7. 写（能力承载）

- **职责**：把已经明确去向的内容通过来源允许的受控入口写入，并核对实际结果。
- **判据**：范围、身份、授权、当前基线、实际变化、回读和未验证范围可区分。
- **机制指向**：事实域受控写入与 CAS、LDVH CLI 受控操作、事实源与 Git 溯源、Code 实现与测试；具体契约分别由 03、05、06、09 承接。
- **边界**：写不决定是否值得沉淀；工具成功和 commit 不证明事实语义或上层完成。

## 8. 编排（能力承载）

- **职责**：调度子代理执行委派的工作，管理其通信、漂移防护、中断恢复、结果回收与成本控制；编排承载工作包运行，主控对工作包的业务结果承担整体责任。
- **判据**：委派有明确任务与验收边界；子代理产物被主控核对和整合；中断后有恢复路径；成本受闸门约束。
- **机制指向**：可续子代理、任务调度、通信信道、守护网关、成本控制与恢复机制；具体契约由 08 承接，工作包生命周期模式由 04 承接。
- **边界**：编排是能力承载，不独立产生业务结论；子代理完成不等于主控完成。

## 9. 记忆与反思（业务系统）

- **职责**：留存和取回项目的经验认识；从目标、判断、行动、结果、摩擦和反馈中形成候选认识，接收多入口候选并按其沉淀环节分流决定去留，空闲时自动维护记忆健康。沉淀环节承接对话中的灵感与经验，并以事实对象承载其产物，方向与未决问题归入 Spark；反思为本系统的一个机制，检查既有认识与经验是否仍然适用。
- **判据**：留存的内容有消费对象、适用边界和明确去向；候选认识可回指实际行动和证据；偶发现象与可复用模式可区分；反思产出的修订意见可回指其依据。
- **机制指向**：事实分层召回、事实类型准入、空闲自动维护与效用审计、沉淀分流路由与反思触发；具体契约分别由 03 与事实类型规范、05、10 承接。
- **边界**：记忆留存不自动产生规则或授权；对象数量、页面呈现和单次复用不证明效用；反思结论不自动生效，须经相应规范或事实承载与 Human 决定。

## 10. 调研（业务系统）

- **职责**：围绕不掌握的问题搜集证据，直到不再产生新的确认认识，产出已证实、未证实与缺口三态证据。
- **判据**：调研问题明确；证据可回指来源；已证实、未证实与缺口范围可区分；停止条件可判定。
- **机制指向**：外部检索、事实证据链、三态证据结构与停止判据；具体契约由 03 与事实类型规范、05、08 承接。
- **边界**：调研产出事实证据，不自动产生行动授权或完成结论；调研结论进入事实源须满足 03 准入。

## 11. 讨论（业务系统）

- **职责**：把 Human 意图经必要信息读取、多视角扩散和规范、事实、价值、能力、成本、风险约束，收敛为可执行或可交 Human 决定的方案，由主控选定。
- **判据**：问题、场景、反例、替代方案、排除范围和未解决取舍清楚；采纳和排除有依据。
- **机制指向**：结构化问询与计划审查、隔离或新鲜视角、并行多视角及既有行动结构；宿主承载和业务系统规范的行动结构契约分别由 08、04 承接。
- **边界**：讨论不自动产生行动授权，不以扩散扩大当前目标。

## 12. 工作执行（业务系统）

- **职责**：执行已批准的工作，以 WorkCase 承载其结论；工作包生命周期（批准→执行→复核→关闭→交还）在业务面上由本系统承接。
- **判据**：执行对象已获批准且授权边界清楚；实际进展、结果与残留范围可回读；中断后有恢复路径。
- **机制指向**：工作包生命周期、WorkCase 类型契约、attempt 令牌与冷恢复；具体契约由 21 号类型规范、04 与具体业务系统规范、08 承接。
- **边界**：执行不自我授权，不以"已批准"扩张授权范围；子代理完成不等于主控完成；执行完成不自动等于复核通过或整体完成。

## 13. 规则遵守（业务系统）

- **职责**：识别并落实当前适用的规则、事实、决定和授权，使约束实际改变行动。
- **判据**：适用条件、授权、禁止动作和未验证范围可回指；应暂停或缩小处实际执行。
- **机制指向**：规范源、事实来源、预检结论机械承载、既有行动结构、Human 决定与宿主权限；具体契约分别由 01、03 与事实类型规范、04 与具体业务系统规范、00 §4、08 承接。
- **边界**：事实、经验和预检记录不成为规则源；低风险行动不自动全量召回或触发 Human Gate。遵守成立（含预检落实记录完成）不等于行动完成。

## 14. 目标与蓝图（业务系统）

- **职责**：把 Human 的长期意图确立为可回指、可核对的项目目标，并校准项目蓝图使其与目标、结构和进展一致；以 Goal 事实对象承载其结论。
- **判据**：目标陈述可判定且有明确引用顶点；子目标可观测；蓝图内容与目标、结构、进展的偏离可识别并能回指依据。
- **机制指向**：目标确立与修订级联、子目标锚点、蓝图校准与空闲触发调度；具体契约由 25 号类型规范、10、08 承接。
- **边界**：目标与蓝图不自动产生行动授权或完成结论；Goal 对象存在或状态为 active 不证明目标正确或子目标充分；蓝图呈现不构成机械校验。

## 15. 复核与校验（制度）

主控自查、独立复核与机械校验三种形态合称工作制度（00 §3.1）：主控自查由主控核对自己发起的工作及其实际结果；独立复核由独立于实施者的视角对照实际工作和结果；机械校验按规范已定义的确定性内容验证实际结果并由机械保障承载执行。

- **职责**：依据已确定的目标、方案、授权和成功标准，通过上述形态对照实际工作、结果、证据和完成声明，检查其是否成立。
- **判据**：对象、基线、方法、覆盖、未覆盖、发现和保证边界清楚；发现得到处置。
- **机制指向**：业务系统规范的完成门禁、事实证据边界、LDVH CLI 与 Code 的机械结果，以及独立、继承、新鲜或对抗执行体；最终核对与整合由主控承担（00 §5.1、§5.3）；具体契约由 04、03 与事实类型规范、05、09 承接。
- **边界**：多视角、独立性、专业性、对抗性和新鲜视角语义互不替代，但不要求同时全部启用；按风险选择最小充分视角。协助者复核结论仍由主控最终核对与整合；复核或校验通过不自动等于整体完成或授权扩张。机械校验仅在存在规范已定义的确定性内容时适用，不替代主控判断。

## 16. 沉淀与反思（记忆与反思系统的机制）

- **职责**：沉淀判断哪些认识和结果值得跨行动保留、应进入什么稳定位置；反思检查既有认识与经验是否仍然适用。
- **判据**：保留内容具有消费对象、适用边界和明确稳定去向；进入事实源时，须满足 03 的准入与受控写入要求。无独立消费价值的内容不对象化；事实或既有行动结构的退出分别按 03、04 的领域规则处理。反思产出的修订意见可回指其依据。
- **机制指向**：事实类型、受控写入传输、既有行动结构改进、Git 溯源与 Web 效用呈现、空闲触发的沉淀与反思调度；具体契约由 03 与事实类型规范、05、04 与具体业务系统规范、06、10 承接。
- **边界**：沉淀与反思是记忆与反思系统内的机制，不是制度，不独立于该系统产生结论；对象数量、页面呈现和单次复用不证明效用；HV4 效用审计仍是能力缺口，本文不提前定义。

## 17. 协同与四层判断

相关、适用、授权覆盖和完成分别核对：读与讨论提供相关性输入，遵守识别适用要求并核对既有 Human 授权的覆盖范围，写把明确去向的结果受控落位，编排形成结果，复核检查完成声明，记忆处理后续认识和去向。四层只是工作模型协同的描述工具，不构成新的权威框架；主控负责相应语义判断。业务系统规范对步骤完成、验证通过与交还承接的具体评测由 04 定义；本节不预设具体业务系统规范的章节号、术语或结构，两者互不替代。

各系统可以并行、回跳或按需跳过未触发职责；主控按目标与风险选择最小充分协同，不把任何示例顺序固化为流程。

## 18. 暂停、接管与恢复

接管不变量以 00 §5.3 为准，暂停和恢复以 00 §7.2、§7.3 为准，本节不重复其内容。工作模型框架只增加：协助者不得自行升格为主控；新主控继续前，须向 Human 披露更替原因、时点、接管范围与继续入口；既有 Human 决定的作用范围须重新核对后方可复用。attempt、锁、冷恢复和宿主事件所需的术语、接入与实现由 08/09 按各自来源另行定义，02 不预设其语义。

## 19. 交还（含 Output Envelope）

交还与撤回承接 00 §7.4。每次交还必须同时提供 Human 可读正文和机器可读 Output Envelope，两者表达同一结果且不得矛盾；Output Envelope 至少表达 00 §7.4 要求的交还要素。具体共同语义、字段闭集和传输形状由 05 承接，02 不预设其结构。

Output Envelope 的最低交还语义由 00 §7.4 定义，不得由下位改变；LDVH CLI 服务输入契约由 05 承接，具体结构与 DSH 宿主承载由 08 定义，Code 生成实现与一致性测试由 09 承接，Human 呈现格式由 10 承接，四者互不替代。相应结构或承载尚未实现、不可用或无法验证时，不得把仅有 Human 可读正文称为已完成交还；应按 00 §7.2 暂停交还完成声明，明确披露缺少 Envelope 的未兑现范围并进入允许的修复或分流。不得自填 Envelope 冒充机制已经实现。已证实范围必须有回读、机械校验或独立复核记录支持。

## 21. Human Gate

本规范不新增 00 之外的 Human Gate。

### 21.1 领域增量事项

以下事项是 00 §4.2 在工作模型领域的具体化：

1. 改变能力承载、业务系统或制度的数量、名称、顺序、根职责或效力边界；
2. 改变单一主控与协助者在工作模型框架中的责任关系；
3. 改变暂停、接管、恢复或交还在工作模型框架中的承接边界；
4. 下位机制选择触及来源已定义的 Human 保留事项。

### 21.2 决定边界

Human 决定只证明决定及其作用范围，不替代工作模型语义审核、接管状态核对、能力验证或交还一致性检查。

## 22. Stop Conditions

本规范不新增根停止类型。

### 22.1 领域触发与影响范围

出现以下任一情况时，按 00 §7.2 暂停最小受影响范围：

1. 规则、事实、授权或能力边界无法确认；
2. 接管所需状态不完整；
3. 系统机制不可用却准备扩大声明；
4. 应落实的约束没有实际改变行动。

### 22.2 暂停期间允许动作

暂停期间只允许不越过停止边界的来源定位、状态回读、能力核验、修复与分流准备，不得继续执行受影响系统职责或扩大状态、授权和完成声明。

### 22.3 恢复与再次触发

恢复须与触发原因对应，且只覆盖当前依据支持的范围；同一停止条件恢复后再次触发时按 00 §7.3 进入 Human Gate。

## 23. 反过度设计红线

1. 不把工作模型固化为分层步骤、固定流程、事实类型或强制工具；
2. 不因行动触及多个系统就默认建立工作项、团队、全量召回、完整审核或 Human Gate；
3. 不为证明协作保存完整消息、思考链、运行日志或第二状态账本；
4. 不在本文复制事实字段、既有行动结构步骤、LDVH CLI envelope、状态机、API 或宿主事件实现；
5. 不把技术形态、对象数量、页面展示或单次复用冒充系统价值；
6. 不为尚未成立的未来能力预设锁、调度器、恢复协议或跨环境兼容层。
