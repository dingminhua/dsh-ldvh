# 规范关系与层级表

```yaml
ldvh_attachment:
  attachment_key: "specification-relation-definitions"
  attachment_id: "01.Att.03"
  title: "规范关系与层级表"
  canonical_path: "specs/attachments/01.Att.03-规范关系与层级表.md"
  positioning: "承载规范关系、授权一致性、L0–L4 读取层级与术语来源分类表"
```

本附件由 `specification-model-foundation` §8.3 与 §10 授权，只展开父规范已定义的关系、读取层级和来源分类结构，不建立独立规则、Human Gate 或 Stop Conditions。

## 1. 关系字段总表

| 字段 | 承载位置 | 类型 | 目标 | 基数与核心约束 |
|---|---|---|---|---|
| `basis` | 根规范或普通规范身份块 | array[string] | 直接必要的上位规范 | 根规范固定为空；普通规范成员唯一，不得含自身或 `parent_spec` |
| `parent_spec` | 根规范或普通规范身份块 | string | 唯一直接结构父规范 | 根规范固定空字符串；普通规范与 `relation` 同时为空字符串或同时非空 |
| `relation` | 根规范或普通规范身份块 | string | 对 `parent_spec` 的关系 | 根规范固定空字符串；普通规范非空时当前闭集仅 `refines` |
| `authorized_attachments` | 普通规范身份块 | array[string] | 被当前规范授权的附件 | 成员唯一；每个附件只能被一个父规范授权 |
| `supersedes` | 普通规范或附件身份块 | array[string] | 被实质替代的同类旧职责 | 可选、非空、成员唯一；正文说明旧规则处置 |
| `related_specs` | 根规范或普通规范身份块 | array[string] | 非结构关联规范 | 成员唯一；不产生依据、归属、授权、替代或效力 |

## 2. 关系语义

| 关系 | 含义 | 必须同时成立 | 不用于 |
|---|---|---|---|
| 规范依据（Normative Basis） | 指向理解、判断或维护当前规范所必需的直接上位规范 | 目标为同一当前来源视图中的规范；正文实际依赖该来源 | 编号相邻、Code 实现、测试覆盖、下游消费者或“可能相关” |
| 结构归属（Structural Parent Relationship） | `refines` 表示子规范具体化唯一父规范的部分职责而不替代父规范 | `parent_spec` 与 `relation` 成对；父目标存在；图无环 | 自动替代 `basis`、继承全部规则或构造表面层级 |
| 附件授权（Attachment Authorization） | 父规范确认附件的唯一归属和结构化承载边界 | 父规范身份登记附件，正文定义承载对象；附件身份与路径一致 | 允许附件扩张父规范、建立独立规则或自我授权 |
| 替代关系（Supersession） | 新职责承接旧职责全部或主要责任，使旧职责退出当前规则源 | 使用新 key；目标可追溯；正文逐项说明保留、转移、改写和退出 | 同一职责改名、改号、移动或普通修订 |
| 非结构关联（Related Specification） | 两个规范存在需提示的非结构关联 | 目标存在且正文能说明关联用途 | 继承、授权、替代、依据或自动适用 |
| 其它正文引用 | 链接或来源回指只表达所在语句明示的关系 | 引用可定位且上下文不夸大 | 暗示正式关系、规则效力或 Human 决定 |

## 3. 关系与授权一致性检查

| 检查对象 | 成立条件 | 失败边界 |
|---|---|---|
| 目标存在 | 每个关系 key 在同一当前来源视图中精确定位为允许类型 | 不从其它 checkout、HEAD、缓存或模糊名称补回 |
| 自引用 | `basis`、`supersedes`、`related_specs` 不含自身；`parent_spec` 不指向自身 | 任一自引用都拒绝该关系 |
| 父关系配对 | 根规范两字段均为空字符串；普通规范两字段同时为空字符串或同时非空 | 缺一、不匹配或未知关系值时拒绝 |
| 父关系类型 | `parent_spec` 指向当前成立的规范，不指向附件；结构父图无环；父正文能定位被具体化的职责边界 | 不能用附件、循环或无父职责授权制造表面归属 |
| 依据与父关系 | `basis` 仅指向当前成立的规范；依赖图无环；同一目标不同时作为 `basis` 与 `parent_spec` | 草案、附件、循环依赖或双重关系均不成立 |
| 附件唯一父权 | 每个附件恰被一个当前父规范登记且父正文逐项说明承载对象与边界；父列表每个 key 恰对应一个实际附件 | 孤儿、悬挂授权、多父授权或附件扩张父规则均不成立 |
| 附件编号 | `attachment_id` 的父编号、文件名前缀与父规范当前 `spec_id` 一致 | 不因 key 正确而忽略编号或路径冲突 |
| 替代处置 | `supersedes` 同类目标可追溯；替代图无环；旧职责不与替代者同时成为当前成员；正文说明旧规则去向 | 只有字段、互相替代或新旧并存不构成完整替代 |
| 列表一致性 | 成员类型正确、唯一并保持声明顺序 | 不以排序或去重后的结果掩盖原始错误 |

关系检查通过只证明已检查图和字段范围，不证明相关规则对当前事项适用，也不证明被替代职责已完成退出。

## 4. L0–L4 渐进式披露层级

| 层级 | 名称 | 承载内容 | 直接用途 | 不能单独证明 |
|---|---|---|---|---|
| L0 | 发现层（Discovery） | 载体类型、稳定 key、当前编号、标题和路径 | 发现、去重与精确定位 | 与当前事项相关、规则适用、授权或当前规则源全部条件成立 |
| L1 | 概览层（Overview） | L0 + 规范 `positioning`、`scope`；附件 `positioning` | 不全文读取时初筛职责 | 正文最终适用范围、完整约束或规则效力 |
| L2 | 关系层（Relationships） | L1 + `basis`、`parent_spec`、`relation`、`authorized_attachments`、`supersedes`、`related_specs`、`dimensions` 与章节目录 | 建立来源、结构、授权、替代和关联上下文 | 上位规则自动适用，或未展开章节不存在 |
| L3 | 规则切片层（Rule Slice） | 按精确 H2 或 H2/H3 `heading_path` 返回的当前原始 Markdown、1-based 行号与来源 | 用最小可复核片段支持局部判断 | 已包含全部语义依赖、规则适用或 Human Gate 已满足 |
| L4 | 全文层（Full Source） | 目标文件完整当前内容；附件同时保留父规范授权上下文 | 完整回读、审核、冲突处理与高影响变更 | Code 已实现、环境已接入、验证通过、授权成立或行动完成 |

层级只表示披露深度，不是建设状态、生命周期、风险等级、Human Gate 结果或验证结果。消费方可直接请求任何足够层级，不要求依次经过 L0–L4；信息不足时必须继续展开或披露缺口。L3 的 `heading_path` 必须在单一载体内精确唯一，重复或歧义标题拒绝读取，不选择首个匹配。每次返回必须绑定同一规则源快照及内容指纹，区分 `completed`、`not_completed` 和资格 `gaps`；附件与父规范不能来自不同快照。

## 5. 来源分类取值说明

本节只为 `ldvh-bilingual-terminology` 已定义的术语来源字段提供结构化取值与一致性检查；术语来源分类的语义权威仍在该术语附件及其父规范，不由本附件另建第二定义。

| 来源分类 | 机器值 | 成立要求 | 最小来源记录 | 禁止表述 |
|---|---|---|---|---|
| 行业标准术语 | `industry-standard` | 有标准组织、正式规范或等价一手权威来源，且 LDVH 没有扩大或改变原义 | 可核验一手来源、标准编号或正式发布物 | 无直接来源却称“行业标准”“最佳实践”或“通用模型” |
| 常见描述性表达 | `common-descriptive` | 相关领域存在自然、可检索且含义相近的真实用法，但不存在或未采用统一标准定义 | 可复核的公开来源或检索依据 | 把常见用法包装成统一行业术语 |
| LDVH 特定术语 | `ldvh-specific` | 现有行业或普通表达不足，LDVH 确有独立稳定概念需要命名 | LDVH 唯一定义职责标识符与精确章节 | 隐去内部定义性质，或仅凭内部简称创造外部通用概念 |

来源分类不改变术语的规范效力。术语是否进入双语附件、由谁定义及机器表示为何值，仍以父规范与 `ldvh-bilingual-terminology` 的当前内容为准；外部来源只支持来源声明，不成为 LDVH 根语义的上位依据。
