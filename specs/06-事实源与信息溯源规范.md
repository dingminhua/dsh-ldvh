## 1. 价值判断

本文只服务“事实可溯源 + 受控提交”这两个目标，不另行宣称其它价值：

- **V1 快速定位**：以管辖项目 Working Tree 当前文件为事实唯一承载位置，事实可回指文件路径与提交历史。
- **V5 据实判断**：受控提交要求 message 与 diff 逐条对应，阻断“声明多、实际少”的自欺路径（v4 教训 #10）。
- **V6 工作接续**：Git 历史与署名 trailer 使后续会话、执行者能沿提交链恢复事实变化、来源与授权。
- **V8 持续积累**：规则源成员登记使规范源文件的生效与退出可追溯，维持积累边界清晰。
- **HV2 授权执行受控可续**：Git Gate 终闸在真实提交事件中机械阻断未通过检查的受控提交。

载体存在、Git 命令成功、文件写入或检查通过，均不单独证明价值成立；价值由实际提交、回读核对与后续使用共同验证。

## 4. 事实源与溯源

### 4.1 事实源载体

事实源以管辖项目实际 Git Working Tree 的当前文件为唯一有效承载形态，满足 00 §5.2 的两项要求：有 Git 可溯源、有组织可消费。事实位于符合适用来源规则的文件路径下，以文件当前内容为可读取的事实状态。

### 4.2 Working Tree / Index / HEAD 三层语义

1. **Working Tree**：当前默认读取视图。AI 与 Human 读取的事实为 Working Tree 的当前内容，是事实源的主体；
2. **Index（暂存区）**：待提交候选。Index 内容在提交前不构成事实源的有效版本，只作为受控提交的中间状态；
3. **HEAD/history**：历史锚点。已提交的提交链是事实变化的溯源记录，不替代 Working Tree 作为当前事实的权威位置。

### 4.3 稳定事实与未提交内容

03 已定义“稳定事实”的成立条件，06 不重定义。未提交内容不排除稳定事实：03 的受控写入、回读与完整性审计在 Working Tree 上执行，其结果在受控提交前即构成事实对象的当前状态，不因尚未提交而丧失事实效力。

### 4.4 溯源

1. 有 Git 就能溯源：`git log`、`git blame`、`git diff`、`git cat-file` 等常规 Git 命令可追溯提交历史、变更内容与署名 trailer，不要求额外工具或机制；
2. Git 提交是工作树快照级溯源锚点，与对象级 `change_log`（归 03）互补、互不替代：06 只承接提交链层面溯源，不建立对象级流水。

## 5. 受控提交契约

### 5.1 适用场景

受控提交契约适用于**受控提交候选**——提交内容含受管载体（`ldvh-base/` 事实对象）、规范源文件、规则源成员变更等按来源规则须经受控流程的提交。契约不要求每次普通求解、普通编辑或非受管文件修改先经过 precheck 或 Git Gate；低风险日常变更按普通提交执行。

### 5.2 message 契约

每个受控提交的 message 必须满足以下格式：

**Header**（一行）：`<type>: <简短描述>`。`type` 为小写 ASCII 单词（如 `docs`、`specs`、`feat`、`fix`），**不设 scope**（决策 #15）；过渡期沿用 v4 Git Gate 的 `type(scope)` 双段格式，至 v5 Git Gate 重建时切换。

**Body**（空一行后开始）：必须包含恰好一个唯一 `关键变更:` 小标题，其下以 `- ` 列表逐项列出每次实际变更。**每个 `- ` 列表项必须与本次提交的 diff 逐条对应**——不得列出 diff 中不存在的变更项，也不得遗漏 diff 中实际存在的变更项（防自欺核心规则，v4 教训 #10）。

**Trailer**（空一行后开始，三行，逐行写入）：

```
LDVH-Product-Name: deepseek-harness
LDVH-Model-Name: <模型名称>
Human-Gate: <Human 授权事实>
```

`LDVH-Product-Name` 固定为 `deepseek-harness`。`LDVH-Model-Name` 填写当次执行使用的模型标识。`Human-Gate` 引用 Human 对本次提交的授权事实（如 WorkCase 编号或 Human 明确授权语句）；未取得 Human 明确授权的受控提交不得进入 Git Gate。

### 5.3 precheck-git-commit 公开操作

`precheck-git-commit` 是 Helper 公开操作：**语义归 06、传输归 05**。

**性质**：只读机械检查。操作以受控提交候选的 message 文本与当前 Index diff 为输入，执行以下确定性检查：

1. Header 格式合规（按 §5.2 或过渡期规则）；
2. Body 含唯一 `关键变更:` 小标题；
3. 每个 `- ` 列表项与 diff 逐条对应（机械可判定部分：列表项与 diff 变更可匹配，无空列表项，无 diff 不存在的变更项）；
4. Trailer 三行完整（LDVH-Product-Name / LDVH-Model-Name / Human-Gate）。

**三值结果**：

| 结果 | 含义 |
|---|---|
| `passed` | 全部机械检查通过 |
| `failed` | 至少一项未通过，返回具体未通过项 |
| `unverifiable` | 输入不足以完成检查（如 Index 为空、message 不可解析），返回具体缺口 |

precheck 只执行来源已封闭定义的机械规则，不判断语义适用、授权范围或 Human 是否应同意；precheck 不替代 Git Gate 事件检查。

### 5.4 Git Gate（commit-msg）事件检查

Git Gate 是 00 §3.3 定义的机械守护终闸，在真实 Git 提交事件（commit-msg hook）中触发，提交前不可绕过。

- **同一 validator**：precheck 与 Git Gate 调用同一份确定性检查实现，只允许入口输入、响应形式与实际作用不同——precheck 返回结构化结果供 AI 消费，Git Gate 在提交时阻断或放行；
- **非 passed 即阻断**：阻断后不得使用 `--no-verify` 绕过，须修正后重新提交；
- **快照一致性**：Git Gate 通过时 stderr 输出 `LDVH Git Gate (commit-msg) passed` 与 `snapshot_identity`；AI 提交后核对 `snapshot_identity` 与 precheck 返回一致，确认双入口作用于同一提交候选。

## 6. 规则源成员

1. **生效** = 文件存在（`specs/` 下、路径与 01 §6.1 一致）+ 编号登记在册 + 提交经 Human 同意（创建或修改经 Human Gate 授权且 Git Gate 通过）。规范不设生命周期 `status`（01 §5.2）；三者成立即当前规则源成员，不依赖额外状态声明。
2. **退出** = 从 01 §6.1 编号终表移出对应登记项，记录退出原因、时间与取代来源（如有）；文件可保留，但已移出登记表的不再作为当前规则源成员生效。
3. 01 §6.1 编号终表是成员身份的权威清单；06 只承接其生效与退出语义，不另建第二登记表。

## 7. 验证与证据边界

| 验证对象 | 成立条件 | 可证明范围 | 不能单独证明 |
|---|---|---|---|
| 事实源载体 | Working Tree 当前文件符合 00 §5.2 两项要求 | 载体存在、路径稳定、Git 可跟踪 | 内容正确、授权成立、完成成立 |
| message 机械合规 | §5.2 格式检查全部通过 | header/body/trailer 机械格式正确 | 变更语义准确、Human 授权 |
| precheck 结果 | 检查依输入执行并返回三值结果 | 当次候选的机械检查范围与结果 | 适用、授权、Human 同意 |
| Git Gate 阻断 | 事件检查非 passed 且提交被实际拒绝 | 当次提交被真实拦截 | 修正已满足、绕过不存在 |
| 成员生效 | 文件存在 + 登记在册 + 提交经 Human 同意 | 规范在规则源中的成员身份 | 内容正确、适用、价值成立 |

## 8. Human Gate 与 Stop Conditions

本文不新增统一 Human Gate。以下事项按 00 §5.4 提请 Human：改变事实源载体定义（Working Tree 之外的承载形态）；改变受控提交契约的 message 格式、trailer 字段或 precheck 机械检查规则；改变规则源成员的生效条件或退出方式。

以下条目是 00 §5.5.1 在事实源域的具体化，**不新增停止触发类型**：precheck 返回 `failed`/`unverifiable` 且未修正；Git Gate 阻断后准备使用 `--no-verify` 绕过；message 与 diff 逐条对应无法确认；提交后 `snapshot_identity` 与预检不一致；规则源成员登记与 01 §6.1 登记表不一致；准备以普通提交替代受控提交流程。暂停期间可做规则定位、message 修复、Index 核对与预检重试；恢复条件必须对应触发原因。

## 9. 反过度设计红线

1. 不要求每次普通求解/编辑先过 precheck 或 Git Gate；
2. 不以 06 建立全局事务、全量审计日志或外部证明链，Git 历史即溯源记录；
3. 不重复定义事实校验层（归 03）；提交链调用 03 已定义实现的同一实现；
4. 不写入版本发布契约、时间表示（时间由 Code 托管填 RFC 3339）、来源枚举（归 05 `sources` 响应字段）；
5. 不复制事实对象身份清单（UUIDv7 等，归 03）；
6. 不写入 commit 的创建/暂存/回读步骤（归 04）。
