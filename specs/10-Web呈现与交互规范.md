## 1. 价值判断

Web 呈现与交互面向 Human，是 Human 侧价值交付的统一呈现面，HV1–HV5 的判据均须在 Web 中可观察、可回读或可回应，故全组列为主要影响；其中 HV2 的机械拒绝判据由 08/09 承接，本文只承担其呈现与交互面。V 轨价值由 AI 侧规范承接，本文不直接映射。本文主要承接 00 §6.2 的 HV 组价值：

- **HV1 决策提请清晰可决**：结构化问询与计划审查使提请对象、依据、选项与风险清晰可决（判据见 00 §6.2：提请含对象、依据、选项、影响与风险）。
- **HV2 授权执行受控可续**：授权流使授权范围、边界与执行状态在 Web 中可追溯；越权动作的机械拒绝由执行端（08/09）承担，Web 呈现越权状态并限制交互入口。
- **HV3 入档闭环节点可验**：四层阅读器使受控创建、状态变更、关闭等关键节点可回读核对。
- **HV4 积累效用直观可见**：卡片网格与扩展阅读使积累与实际复用效用直观可见。
- **HV5 项目演进脉络可循**：语义详情与扩展阅读使演进脉络可循，未记录范围如实可见。

页面呈现、工具成功或组件加载不单独证明以上价值成立。

## 3. 职责边界

### 3.1 本文负责

1. 四层阅读器的呈现语义与切换契约（字段级直读 / 卡片网格 / 语义详情 / 扩展阅读）（§5）；
2. 交互入口的触发条件与 Human 响应契约（结构化问询 / 计划审查 / 授权流 / 验收交还）（§6）；
3. 管辖项目登记与取消登记的 Web 交互契约（经 07 §5.4/§5.7 受控登记流程承载，Web 不自行解析或直写登记载体）（§6.5）；
4. 管辖项目在 Web 中的切换呈现规则（§7）；
5. Web 呈现边缘条件的识别与处理方式（登记文件缺失、项目未管辖、授权范围不清、交还未通过等场景下的 UI 行为）（§8）。

3. 事实源定义、受控提交契约、Git Gate——归 06；
4. 管辖登记 Schema、判定逻辑——归 07；
5. 插件 manifest、工具注册缝、引导面注入、事件时机——归 08；

05–09 各自是其领域语义的唯一权威；10 只定义呈现语义与交互契约，不改变任何领域语义，不成为第二规则源。

## 4. 适用范围

本规范适用于 DSH Web GUI 中 LDVH 项目信息的呈现（四层阅读器）与 Human 交互（结构化问询、计划审查、授权流、验收交还），以及管辖项目切换与 Web 边缘条件的呈现行为。面向 AI 的受控读取与写入不因本规范存在而改变；本规范不定义 Helper 服务契约、事实模型、行动模板、环境接入或 Code 实现。页面呈现、组件加载或交互完成，只证明当次呈现范围，不单独证明事实成立、授权覆盖、技术验证或价值兑现。

## 5. 四层阅读器

四层阅读器承载 Human 对 LDVH 项目信息的呈现消费。四层**互不替代、不互锁**：Human 可随时切换至任一或同时展开多层，不要求从低层向高层递进。

### 5.1 字段级直读

- 呈现事实对象的核心字段（名称、状态、指纹、时间戳、来源引用）
- 面向快速定位与核对：Human 可一眼确认某条记录是否存在、状态如何
- 不渲染关联关系或语义解释

### 5.2 卡片网格

- 以卡片形态呈现事实对象摘要（标题、状态标签、单行摘要、关联计数）
- 支持按类型、状态、维度、时间等条件筛选与排序
- 面向浏览与概览：Human 在卡片间扫描，定位感兴趣的对象

### 5.3 语义详情

- 完整呈现单条事实对象的所有字段与关联引用，含来源回指
- 显示该对象的变更历史（摘要形态，不要求完整 diff）
- 面向深度核查：Human 逐条审阅内容、判断适用性与完整性

### 5.4 扩展阅读

- 跨对象关联呈现：按话题、决策链、问题-方案-结果线索串联多条事实
- 呈现事实的积累效用与复用情况（HV4/HV5 的承载面）
- 面向脉络探索：Human 沿关联追踪项目演进路径

## 6. 交互入口

交互入口承载 Human Gate 与交还流程。每个入口定义触发条件与 Human 响应契约，并在 Web 中呈现对应面板。

### 6.1 结构化问询

- **触发条件**：AI 需要 Human 判断、选择或补充信息，问题已组织为带选项、影响与风险的结构化形式
- **Human 响应契约**：呈现代选项与自由输入，响应须含对象、范围与处理结论

### 6.2 计划审查

- **触发条件**：AI 呈交候选计划，等待 Human 审查或批准；Gate 1 / Gate 2 仅为 WorkCase provisional 术语，在 21/34 定稿前不作为本节触发依据
- **Human 响应契约**：呈现计划依据、范围、步骤与风险，Human 批准/拒绝/要求修改

### 6.3 授权流

- **触发条件**：AI 需要 Human 授权才能执行或继续某项受控操作
- **Human 响应契约**：呈现授权对象、范围、边界与执行状态，Human 授予/拒绝/限制，越权动作被机械拒绝

### 6.4 验收交还

- **触发条件**：AI 完成当前工作，呈交验收结果
- **Human 响应契约**：呈现 00 §7.4 Output Envelope 的 Human 可读视图与验证证据，Human 验收/退回/要求补充；Web 不重新定义 Envelope，也不把呈现或验收写成技术验证

### 6.5 登记管理

- **触发条件**：Human 在 Web 中发起项目登记或取消登记（对应 07 §5.4/§5.7 的 Web 入口）
- **Human 响应契约**：呈现登记对象、项目路径与登记状态；写入与移除经 07 §5.4/§5.7 定义的受控登记流程并回读确认，Web 不自行解析或直写登记载体

## 7. 管辖登记与项目切换

07 §5 登记的管辖项目在 Web 中可切换呈现，规则如下：

- Web 通过 07 定义的唯一管辖判定职责读取 Human 已定案的登记载体，列出管辖项目；Web 不自行解析候选路径或 Schema；
- Human 在 Web 中切换当前呈现的管辖项目，切换后四层阅读器与交互入口均指向目标项目的事实源；
- 切换只作用于 Web 呈现层，不改变当前会话工作目录，不触发 Helper 或 Git 操作；
- 管辖判定消费方式沿用 07 §7 消费方表。

## 8. Web 边缘条件处理

以下条件处理仅影响 Web UI 呈现行为，本身不新增 Human Gate 触发条件或 Stop Conditions；Human Gate 以 00 §4.2 为准，Stop Conditions 以 00 §7.2、恢复以 §7.3 为准，本文领域增量见 §10–§11。

| 条件类型 | 具体条件 | 处理方式 |
|----------|----------|----------|
| 登记文件缺失 | 07 登记文件不存在或不可读 | 显示"未管辖"，LDVH 功能隐藏 |
| 项目未管辖 | 当前项目不在登记列表 | 隐藏 LDVH 功能，提示登记入口 |
| 授权范围不清 | 授权对象/范围/边界不明确 | 显示授权不可用状态，提示 Human 补充范围 |
| 交还未通过 | 验收交还条件不满足 | 退回至 AI 补充或修正 |
| 切换失败 | 目标项目登记文件损坏 | 保留当前项目呈现，提示问题 |

登记载体损坏、不可唯一解析等触及 07 §10 停止边界的条件，其暂停语义以 07 §10 与 00 §7.2 为准；Web 层仅按本节表格呈现对应状态（"未管辖"、保留当前呈现并提示），不自行处置，也不把呈现写成暂停已执行。

## 9. 验证与证据边界

| 验证对象 | 验证时机 | 成立条件 | 可接受依据 | 验证入口 | 可证明范围 | 未满足时的处理 |
|---|---|---|---|---|---|---|
| 四层阅读器呈现 | 每次呈现或层间切换时 | 各层按 §5 语义呈现，层间切换不丢失已加载数据 | 各层渲染结果 | 呈现核对 | 当次呈现范围；不证明内容正确、事实成立或价值兑现 | 呈现异常时暂停受影响视图并修复 |
| 交互入口触发 | 交互面板出现时 | 面板出现时机与 §6 触发条件一致 | 各交互面板观察（含 §6.1–§6.5） | 触发条件核对 | 当次触发一致性；不证明提请内容正确或 Human 已回应 | 时机不一致时修正触发，不伪造面板 |
| 管辖项目切换 | 每次切换后 | 呈现目标项目的事实源，切换不改变会话工作目录 | 07 登记载体与目标项目观察 | 切换结果核对 | 当次呈现指向；不证明目标项目状态正确 | 切换失败时保留当前呈现并提示 |
| 授权范围可追溯 | 授权流面板呈现时 | 授权边界与实际执行范围一致呈现 | 授权流面板与执行状态 | 授权呈现核对 | 当次呈现一致性；不证明授权成立或越权被拒 | 范围不清时显示授权不可用并提示补充 |
| 关键节点可回读 | Human 核对节点时 | 受控创建、状态变更、关闭节点在语义详情或扩展阅读可核对 | 语义详情与扩展阅读 | 节点回读核对 | 当次可回读范围；不证明节点语义正确 | 不可回读时如实披露缺口 |
| 价值声明可观察 | 声称 HV4/HV5 时 | 页面可呈现相应复用与演进依据 | 卡片网格与扩展阅读 | 呈现依据核对 | 只证明页面可呈现相应依据；不单独证明 HV4/HV5 已成立 | 无依据时降低声明并记录缺口 |
| Output Envelope 呈现 | 每次验收交还时 | 机器可读结果与 Human 可读视图两层表达一致 | 00 §7.4 结果与 Human 可读视图 | 一致性核对 | 当次呈现一致性；不证明技术完成 | 不一致时退回修正，不交付矛盾呈现 |

机械结果与语义判断互不替代。页面呈现、组件加载或 Human 操作只能证明各自呈现范围；本章不能单独证明事实成立、授权覆盖、技术验证或 V/HV 价值成立，未执行和不可用范围保留为 gaps。

## 10. Human Gate

本文不新增 00 之外的 Human Gate。以下事项按 00 §4.2 提请 Human 对准确候选及作用范围作出明确决定：

1. 改变四层阅读器的层级定义、切换契约或交互入口的触发条件与响应契约；
2. 改变管辖项目切换或 Web 边缘条件的处理语义。

受保护文档修改按 00 §4.3 执行，此处仅回指，不构成本文领域增量。

Human 决定只证明决定及其作用范围，不替代呈现一致性核对、触发条件核对或节点回读核对。

## 11. Stop Conditions

本规范不新增根停止类型。出现以下任一情况时，按 00 §7.2 暂停受影响的呈现、交互或完成声明：

1. 呈现所依据的来源（登记载体、事实源、Output Envelope）缺失、不可读或相互不一致；
2. 准备把页面呈现、组件加载或 Human 操作写成技术验证、授权成立或整体完成；
3. 交互入口的触发条件或响应契约无法确认。

暂停期间只允许不越过停止边界的规则定位、只读核对与修复准备。恢复须与触发原因对应；同一停止条件恢复后再次触发时按 00 §7.3 进入 Human Gate。

## 12. 反过度设计红线

1. 不要求四层阅读器互锁或从低层向高层递进；
2. 不指定 UI 框架、组件库或预设组件形态——只定义呈现语义与交互契约；
3. 不绕过 07 登记制度在 Web 侧自行解析管辖项目列表或候选路径；
4. 不在 Web 中直接改写规范或写入事实——均经 06 受控提交与 05 Helper 流程；
5. 不在已授权范围内重复提请 Human Gate 或把已授权操作再次转为问询。
